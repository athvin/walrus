# PR 20.1 — Implement TryFrom for the pgoutput wire-byte conversions

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test,sqlx · **Test packages:** common,pg-sink

> **Phase:** 20 — Rust conversions · **Crates touched:** `common`, `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 19.6 · **Unlocks:** PR 20.2

The token `TryFrom` appears **0 times** in all 189 Rust files. walrus *consumes* the trait 10 times
(`.try_into()` in `pgoutput/reader.rs` and `replication.rs`, `i32::try_from` in `pg-to-arrow`) but
never **implements** it: every fallible conversion walrus owns is hand-rolled. `ReplicaIdentity`
carries `from_wire(u8) -> Result<Self, Error>` (9 references repo-wide), the Update/Delete
old-tuple tag is an inline `b'K' | b'O'` match written out twice at
`crates/pg-sink/src/pgoutput/mod.rs:320` and `:343`, and the `#[repr(i32)] ExitCode` contract is
one-way — you can turn a variant into a number but not a number back into a variant. None of the
three is reachable through `.try_into()?`, and none can satisfy a `T: TryFrom<u8>` bound. This PR
lands the three `TryFrom` impls, deletes `from_wire`, and moves every caller and sibling test onto
the standard idiom.

## Why — learning objectives

- **`TryFrom` / `TryInto`** — the blanket impl, the associated `Error` type, and why you implement
  `TryFrom` and never `TryInto`.
- **pgoutput wire tags** — `relreplident` (`'d'`/`'n'`/`'f'`/`'i'`) and the Update/Delete old-tuple
  submessage tag (`'K'`/`'O'`), plus the `#[repr(i32)] ExitCode` public contract.

**In scope**

- `impl TryFrom<u8> for ReplicaIdentity` in `crates/common/src/pg_shape.rs`, with
  `type Error = crate::Error` and the *same* `Error::Internal("unknown relreplident byte …")`
  message the current `from_wire` produces — the wording is what an operator greps for.
- **Delete `ReplicaIdentity::from_wire`.** It is not deprecated, not kept as a thin wrapper: the
  probe is `from_wire` going 9 → 0. Move `crates/common/src/pg_shape_test.rs`'s
  `replica_identity_from_wire_char` onto `ReplicaIdentity::try_from(b'd')` /
  `b'd'.try_into()`, and rename it to say `try_from`.
- `impl TryFrom<u8> for OldTupleKind` in `crates/pg-sink/src/pgoutput/mod.rs`, with
  `type Error = DecodeError`, mapping anything but `b'K'`/`b'O'` to
  `DecodeError::BadTupleFormat { byte }`.
- Rewrite the Delete `'D'` arm (`:343`) as `OldTupleKind::try_from(reader.byte1()?)?` and restructure
  the Update `'U'` arm (`:320`) so its `'N'` case stays a special case and the `'K'`/`'O'` cases go
  through `try_from` once instead of two copy-pasted blocks.
- Keep the Relation `'R'` arm's error re-wrap: `ReplicaIdentity::try_from(ident_byte)` still
  `.map_err(|_| DecodeError::BadReplicaIdentity { byte: ident_byte })?`, because `common::Error` must
  not leak into `DecodeError`'s taxonomy.
- `impl TryFrom<i32> for ExitCode` in `crates/common/src/error.rs`, with a concrete
  `UnknownExitCode(i32)` error, making the `#[repr(i32)]` contract round-trippable — and a sibling
  test in `crates/common/src/error_test.rs` asserting
  `ExitCode::try_from(e.exit_code() as i32) == Ok(e.exit_code())` for every variant, so a renumbering
  becomes a test failure rather than a silent runbook break.

**Explicitly deferred** (do *not* build these here)

- **No `TryFrom<i64> for UtcTimestamp`.** A bare `i64` is ambiguous between the Postgres epoch and
  the Unix epoch, so `UtcTimestamp::from_pg_micros` (`crates/common/src/sink_meta.rs:74`) keeps its
  domain name **on purpose** — a `.try_into()` there would silently invite Unix micros. Record that
  reason in `from_pg_micros`'s doc comment as part of this PR.
- **Do not touch `crates/pg-sink/src/ddl.rs:39` `from_tuple`.** It takes two arguments; a tuple
  `TryFrom` would be strictly worse than the named constructor.
- No string parsing. `FromStr` and the `type Err = String` cleanup are PR 20.2.
- No `.sql` file, no `.sqlx` offline-cache entry, and **no lint promotion** — this ticket changes
  code, not `Cargo.toml`.

## Hints & gotchas

- `TryInto` has a **blanket impl** over `TryFrom`. Writing `impl TryInto<…> for …` is the classic
  mistake the rule warns about — it makes the conversion unusable from a `T: TryFrom<U>` bound.
  Implement `TryFrom` only; `.try_into()` at the call site then just works.
- `common::Error` does **not** derive `PartialEq`, so `assert_eq!` on
  `ReplicaIdentity::try_from(b'x')` will not compile. Use `.is_err()` for the reject cases (exactly
  what `pg_shape_test.rs:30-31` already does) and `assert_eq!(…try_from(b'd').unwrap(), …)` for the
  accept cases. `UnknownExitCode`, being new, *should* derive `PartialEq, Eq` so the round-trip test
  can `assert_eq!` on the `Err` arm.
- Sibling test files (`pg_shape_test.rs`, `error_test.rs`) are **Go-style siblings** wired by
  `#[cfg(test)] #[path = "…_test.rs"] mod tests;` — not inline `mod tests {}`. `clippy.toml` re-allows
  `unwrap`/`expect` there; production code is still under `unwrap_used = "deny"` /
  `expect_used = "deny"`, so the impl bodies must stay `unwrap`-free.
- `Message` is `#[non_exhaustive]`, but `OldTupleKind` is not — adding the `TryFrom` impl changes no
  variant, so no downstream match arm moves. Keep it that way.
- `ExitCode`'s numbers are a documented public contract (`crates/common/src/error.rs:105-107`:
  "never renumber an existing code, only append new ones"). Write the `TryFrom<i32>` arms as
  **literal numbers**, not `as` casts over a variant list — the whole point is that the test fails
  loudly if someone renumbers.
- `clippy::all` and `warnings` are already `deny` at the workspace root and every member declares
  `[lints] workspace = true`. Expect clippy to have opinions about the new impls (e.g. it may want
  `Self` rather than the enum name inside them) — fix them, don't `#[allow]` them.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache: there is no Docker on this
  machine to regenerate it, and CI runs `cargo sqlx prepare --check --workspace`.
- No new dependency is needed. `thiserror` is already a `common` dependency; anything else would
  have to clear `cargo deny` (advisories, the 8-license allow-list, bans) for no gain here.
