# PR 20.2 — Give every FromStr a concrete error type and parse UtcTimestamp through FromStr

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 20 — Rust conversions · **Crates touched:** `common`, `control`, `pg-sink`,
> `pg-to-arrow`, `loader` · **Est. size:** M ·
> **Depends on:** PR 20.1 · **Unlocks:** PR 20.3

Production has **5 `FromStr` impls and 4 of them declare `type Err = String`** — `ManifestKind`,
`ManifestStatus` (`crates/control/src/manifest.rs:43`, `:76`), `ReloadFlavor`, `ReloadStatus`
(`crates/control/src/reload.rs:44`, `:81`) — exactly what the rule forbids. Only `Lsn` gets it right,
with the concrete `LsnParseError` at `crates/common/src/lsn.rs:37`. The stringly failure is then
laundered straight into `ControlError::Decode(String)` at `crates/control/src/manifest.rs:193` and
`:198`, so no caller can ever match on *which* column held *which* bad value. Separately
`UtcTimestamp` exposes the bespoke `parse_rfc3339` (21 references repo-wide) with no `FromStr` and no
`Display`, even though its own `Deserialize` impl already funnels through it. After this PR the
`type Err = String` count is 0, the `parse_rfc3339` count is 0, and every one of these types is
reached the standard way: `"…".parse::<T>()`.

## Why — learning objectives

- **`FromStr` with a concrete `Err`** — the `.parse::<T>()` idiom, and pairing `FromStr` with
  `Display` so the round-trip is testable in one assertion.
- **walrus control-plane text enums** — `file_manifest.kind`/`status`, `table_reload.flavor`/`status`,
  and the UTC-`Z`-only RFC-3339 wire contract every walrus-stamped datetime obeys.

## Read first

- [`conv-fromstr-parsing`](../../../.claude/skills/rust-skills/rules/conv-fromstr-parsing.md) — take
  two notes from it verbatim: "use a concrete `Err` type, not `String`, so callers can pattern-match
  on parse failures", and "`FromStr` pairs naturally with `Display`". The third note (use `From<&str>`
  for *infallible* conversions) is why nothing here becomes a `From`.
- `crates/common/src/lsn.rs:36-42, 66-90` — `LsnParseError` and `impl FromStr for Lsn`. This is the
  in-repo model the four control enums must be brought up to: a `thiserror` type carrying the
  offending `input` plus a `reason`.
- `crates/control/src/manifest.rs:30-53` (`ManifestKind::as_str` + `FromStr`), `:63-83`
  (`ManifestStatus`), and `:186-205` — the `claim_ready` row mapper where both `.parse()` results are
  flattened by `.map_err(ControlError::Decode)`.
- `crates/control/src/reload.rs:24-93` — `ReloadFlavor` / `ReloadStatus`, their `as_str()` writers, and
  the `#[derive(sqlx::Type)] #[sqlx(rename_all = …)]` attributes that *also* encode the same strings.
- `crates/control/src/db.rs:36-40` — `ControlError::Decode(String)`, documented as "a text column held
  a value outside its enum's known set … a data-integrity bug — terminal, never transient".
- `crates/common/src/sink_meta.rs:52-68` (`parse_rfc3339`), `:90-103` (the hand-written `Serialize` /
  `Deserialize`), and the module header's "every datetime is UTC RFC-3339 with a `Z` suffix"
  cross-service contract (architecture.md §1.4).
- `crates/control/src/manifest_test.rs` and `crates/control/src/reload_test.rs` — both already assert
  `assert_eq!(s.parse::<T>(), Ok(v))`, which constrains the new error type's derives (see Hints).

## Scope

**In scope**

- Add one concrete parse error to `crates/control/src/db.rs`, next to `ControlError`, modelled on
  `LsnParseError`:
  `pub struct ParseEnumError { pub column: &'static str, pub input: String }` with
  `#[derive(Debug, thiserror::Error, PartialEq, Eq)]`. Re-export it from `crates/control/src/lib.rs`
  alongside `ControlError`.
- Switch all four control enums from `type Err = String` to `type Err = ParseEnumError`, naming the
  column each one guards (`"file_manifest.kind"`, `"file_manifest.status"`,
  `"table_reload.flavor"`, `"table_reload.status"`).
- Change `ControlError::Decode(String)` to `Decode(#[from] ParseEnumError)` so the source chain is
  preserved instead of being `.to_string()`-flattened. Keep the variant's `#[error("control-plane
  decode: {0}")]` text and its `is_terminal()` classification (`crates/control/src/db.rs:52`)
  unchanged.
- Simplify `crates/control/src/manifest.rs:193` / `:198` to plain `r.kind.parse()?` / `r.status.parse()?`
  now that `#[from]` exists.
- `impl FromStr for UtcTimestamp` in `crates/common/src/sink_meta.rs` with a concrete
  `TimestampParseError` (two variants: the non-`Z` rejection and the malformed-RFC-3339 case), plus
  `impl Display for UtcTimestamp` that renders the inner `jiff::Timestamp`. Point `Serialize` at that
  `Display`, and `Deserialize` at `s.parse::<UtcTimestamp>()`.
- **Delete `parse_rfc3339`** and move all 20 remaining call sites (tests, benches, integration tests
  across `pg-to-arrow`, `pg-sink`, `loader`, `common`) to `"2026-07-04T12:00:00Z".parse::<UtcTimestamp>()`.
- Add a `From<TimestampParseError> for common::Error` mapping to `Error::Internal(…)`, so any future
  `common::Result` caller keeps the exact operator-facing wording the old function produced.
- Sibling tests: a `Display` ⇄ `FromStr` round-trip for `UtcTimestamp`, and a `ParseEnumError`
  assertion that the *column name* and the *offending input* both survive into
  `ControlError::Decode`.

**Explicitly deferred** (do *not* build these here)

- **No `FromStr` for `common::sink_meta::Op` / `Kind`.** Their string form is a serde-only wire
  contract (`#[serde(rename = "i")]`, architecture.md §1.4), not a control-DB text column; a parser
  there would create a second source of truth for the same bytes.
- **No `Dsn` newtype** for `crates/pg-sink/src/replication.rs:537 parse_dsn` — it returns a 4-tuple,
  and turning that into a parsed type is `type-newtype-validated` in Phase 18, not this ticket.
- No change to any `as_str()` writer. Every persisted string stays byte-identical, so **no `.sql` file
  and no `.sqlx` offline-cache entry is touched**.
- No new `TryFrom` impls (PR 20.1) and no lint promotion (PR 20.3).

## Hints & gotchas

- `crates/control/src/manifest_test.rs` and `reload_test.rs` already assert
  `assert_eq!(s.parse::<T>(), Ok(v))`. That requires `Result<T, ParseEnumError>: PartialEq + Debug`,
  so `ParseEnumError` **must** derive `Debug, PartialEq, Eq` — otherwise those existing tests stop
  compiling and you will be tempted to rewrite them. Derive, don't rewrite.
- `#[from]` on `ControlError::Decode` also generates `impl From<ParseEnumError> for ControlError`.
  Check no *other* `From` into `ControlError` now conflicts, and remember `#[from]` implies
  `#[source]` — that is the point, the chain is what `.to_string()` was destroying.
- `ReloadFlavor` / `ReloadStatus` also carry `#[derive(sqlx::Type)]` with `rename_all`. That derive is
  a **third** encoding of the same strings alongside `as_str()` and `FromStr`; do not touch it, and
  keep `reload_test.rs`'s comment about the three staying in sync.
- `jiff::Timestamp`'s parse error is not `PartialEq`, so store it as a `String` `reason` inside
  `TimestampParseError::Malformed` (exactly how `LsnParseError` keeps a `&'static str` reason) rather
  than as a `#[source]` — that is what lets the whole error derive `PartialEq, Eq`.
- Adding `Display` to `UtcTimestamp` makes `.to_string()` available *everywhere*; make sure
  `Serialize` routes through it so the JSON and the `Display` form can never drift. The
  `sink_meta_test.rs` assertions on `"1999-12-31T23:59:59Z"` and the `ends_with("Z\"")` check are your
  proof.
- `parse_rfc3339` call sites live in **benches** (`crates/pg-to-arrow/benches/batch.rs`,
  `crates/loader/benches/append.rs`) and integration `tests/` as well as sibling `*_test.rs` files.
  Benches are `harness = false` and carry file-level `unwrap` allows; `cargo clippy --all-targets`
  compiles them, so a missed call site fails CI, not just `cargo test`.
- Unit tests here are **Go-style sibling files** (`db_test.rs`, `manifest_test.rs`,
  `sink_meta_test.rs`) wired by `#[cfg(test)] #[path = "…"] mod tests;` — never add an inline
  `mod tests {}`.
- `unwrap`/`expect` are `deny` in production (`clippy.toml` re-allows them only under `cfg(test)` and
  in `tests/`), and `clippy::all` + `warnings` are already `deny` workspace-wide. The new `from_str`
  bodies must propagate, not unwrap.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it, and CI runs `cargo sqlx prepare --check --workspace`. Keeping every
  `as_str()` writer byte-identical is what makes that safe.
- No new dependency: `thiserror` is already a dependency of both `common` and `control`. Anything new
  would have to clear `cargo deny` (advisories, the 8-license allow-list, bans).
