# PR 20.2 — Preserve typed control parse failures and parse UtcTimestamp through FromStr

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test,sqlx · **Test packages:** common,control,loader,pg-sink,pg-to-arrow

> **Phase:** 20 — Rust conversions · **Crates touched:** `common`, `control`, `pg-sink`,
> `pg-to-arrow`, `loader` · **Est. size:** M ·
> **Depends on:** PR 20.1 · **Unlocks:** PR 20.3

Production has **5 `FromStr` impls and 0 `type Err = String` declarations**. PR 18.5 already moved
all four control enums — `ManifestKind`, `ManifestStatus`, `ReloadFlavor`, and `ReloadStatus` — onto
the shared `control::ParseEnumError` in `crates/control/src/parse.rs`; it is already re-exported from
`control::lib`. The remaining control-plane defect is at the next boundary: `claim_ready` converts
that typed error to text twice, and `ControlError::Decode(String)` discards its fields and source
chain. This PR refines the existing error's vocabulary label into the exact control-DB column and
preserves the error through `ControlError::Decode`.

Separately, `UtcTimestamp` already implements `Display` (PR 19.3), but still exposes the bespoke
`parse_rfc3339` instead of `FromStr`. The token has **22 references** under `crates/` and `tests/`:
the declaration, `Deserialize`, and **20 callers**. After this PR the `type Err = String` count stays
0, the production `FromStr` count moves 5 → 6, `parse_rfc3339` moves 22 → 0, and callers use the
standard `"…".parse::<UtcTimestamp>()` entrypoint without changing the UTC-`Z` wire contract.

## Why — learning objectives

- **`FromStr` with a concrete `Err`** — the `.parse::<T>()` idiom and why an associated error stays
  structured through the next error boundary instead of being flattened with `.to_string()`.
- **`FromStr` paired with existing `Display`** — one standard parser and one standard renderer for
  `UtcTimestamp`, with serde routed through the same pair.
- **walrus text boundaries** — the four checked control-DB columns and the UTC-`Z`-only RFC-3339
  contract shared by the sink and loader.

#[derive(Debug, Clone, PartialEq, Eq, thiserror::Error)]
#[error("unknown {column} value {input:?}")]
pub struct ParseEnumError {
    /// Exact checked control-DB column, e.g. `file_manifest.kind`.
    pub column: &'static str,
    /// Rejected text, preserved verbatim.
    pub input: String,
}

impl ParseEnumError {
    #[must_use]
    pub fn new(column: &'static str, input: &str) -> Self {
        Self {
            column,
            input: input.to_string(),
        }
    }
}

```rust
// crates/common/src/sink_meta.rs — Display already exists and remains unchanged.
#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum TimestampParseError {
    #[error("timestamp {input:?} must be UTC with a 'Z' suffix, not a numeric offset")]
    NotUtcZ { input: String },
    #[error("invalid RFC-3339 timestamp {input:?}: {reason}")]
    Malformed { input: String, reason: String },
}

impl std::str::FromStr for UtcTimestamp {
    type Err = TimestampParseError;

    fn from_str(s: &str) -> std::result::Result<Self, Self::Err> {
        if !(s.ends_with('Z') || s.ends_with('z')) {
            return Err(TimestampParseError::NotUtcZ {
                input: s.to_string(),
            });
        }
        let timestamp = s.parse::<jiff::Timestamp>().map_err(|error| {
            TimestampParseError::Malformed {
                input: s.to_string(),
                reason: error.to_string(),
            }
        })?;
        Ok(Self(timestamp))
    }
}

impl Serialize for UtcTimestamp {
    fn serialize<S: Serializer>(&self, serializer: S) -> std::result::Result<S::Ok, S::Error> {
        serializer.collect_str(self)
    }
}

impl<'de> Deserialize<'de> for UtcTimestamp {
    fn deserialize<D: Deserializer<'de>>(deserializer: D) -> std::result::Result<Self, D::Error> {
        let input: String = Deserialize::deserialize(deserializer)?;
        input.parse().map_err(serde::de::Error::custom)
    }
}
```

## Hints & gotchas

- PR 18.5 deliberately stopped at the enum boundary and flattened into `Decode(String)`. This task
  owns the next step: preserve that already-concrete error via `#[from]`; do not reimplement PR 18.5.
- The `expected` → `column` refinement is intentional. These four enums are the Rust boundary for
  four specific checked DB columns, so exact `table.column` data is more actionable than a prose
  vocabulary label and remains valid at direct parse call sites.
- `#[from]` also marks the `ParseEnumError` payload as a source. Test the payload fields, not only
  the composed display string.
- `crates/pg-sink/src/exit_test.rs` directly constructs `ControlError::Decode` twice. Those fixtures
  must use `ParseEnumError`; otherwise the variant change fails outside the control crate.
- `jiff::Timestamp`'s parse error is not `PartialEq`, so store its rendered reason as `String` rather
  than as a source. That permits precise `TimestampParseError` equality assertions.
- Preserve the current suffix-first validation order. In particular, `"not a timestamp"` remains a
  `NotUtcZ` failure because it lacks `Z`; this task standardizes the entrypoint, not error precedence.
- `UtcTimestamp` already implements `Display`; adding another impl is a conflict. Change
  `Serialize` from `collect_str(&self.0)` to `collect_str(self)` so the existing impl becomes the
  single rendering hook.
- The 20 callers include benches and integration tests. `cargo clippy --all-targets` compiles the
  benches, so every one must move even though most use test-only `unwrap` allowances.
- Sibling tests remain Go-style `*_test.rs` modules. Do not add inline `mod tests {}` blocks.
- No new dependency is needed: `thiserror` already belongs to `common` and `control`.
