# PR 20.3 — Record why AsMut has no write target and deny needless_pass_by_ref_mut instead

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 20 — Rust conversions · **Crates touched:** `pg-sink` · **Est. size:** S ·
> **Depends on:** PR 20.2 · **Unlocks:** PR 21.1

Zero `AsRef<…>` / `AsMut<…>` trait bounds exist anywhere in walrus's Rust — **0 matches across
`crates` and `tests`**; every `.as_ref()` / `.as_mut()` hit is the inherent `Option` / `Box` / `Arc`
method. All **8** `&mut` container parameters in production either need the concrete container's own
API — `String::push_str` (`crates/common/src/sink_meta.rs:201`), `Vec::push`
(`crates/loader/src/plan.rs:132`/`:133`), `Vec` len/remove (`crates/pg-sink/src/reload_signal.rs:222`),
`BytesMut::split_to` (`crates/pg-sink/src/replication.rs:480`) — or are **already** the `&mut [T]`
slice form the rule advocates (`crates/pg-to-arrow/src/batch.rs:367`/`:399`/`:428`). walrus has no
fixed-length byte-fill target, which is the only shape `impl AsMut<[u8]>` serves: the wire builders in
`replication.rs` all *grow* a `Vec<u8>`, and the pgoutput `Reader` is read-only over `&'a [u8]`. So
this PR writes the deviation down as an ADR, pins the absence with a guard, and lands the
mutable-borrow gate walrus actually lacks — `clippy::needless_pass_by_ref_mut`, which today reports
exactly **1** site: `crates/pg-sink/src/reload_export.rs:282 async fn await_echo(&mut self, …)`, which
never mutates `self`.

## Why — learning objectives

- **`AsRef` / `AsMut` as generic borrowed-input bounds** — and when a concrete `&mut T` is the correct
  API, i.e. writing the deviation down instead of cargo-culting the rule.
- **walrus's mutable-borrow surface** — the pgoutput frame reader (`BytesMut::split_to`), the Arrow
  builder slices, and the reload echo-wait loop.

  **"When Not to Use"** section first, not the "Good" example. Its own first bullet ("if the function
  only ever receives `&mut SomeConcreteType`, keep the concrete type") is the load-bearing sentence
  for this ticket, and its third ("don't use `AsMut` as a substitute for a trait that captures domain
  semantics") is why nothing here is retrofitted.
- `crates/pg-sink/src/reload_export.rs:81-99` (`struct ChunkExporter` — `client`, `waiters`, `pool`
  are all shared-borrow APIs) and `:270-329` (`await_echo`, the whole body: `waiters.subscribe(&self)`,
  `client.batch_execute(&self)`, `pool.acquire(&self)` — not one `&mut` use).
- `crates/pg-sink/src/reload_export.rs:334-340` — `export_next_chunk(&mut self)`, the only caller.
  It keeps its `&mut self`; a `&mut` receiver reborrows as `&` for the call, so nothing else moves.
- `Cargo.toml:15-21` — `[workspace.lints.clippy]` and the comment explaining that lints outside
  `clippy::all` need no `priority` juggling. Copy that comment style.
- `rust-toolchain.toml` — `channel = "1.95.0"`, pinned exactly so "a new stable release can never turn
  a fresh clippy lint into a CI failure". That pin is what makes denying a *nursery* lint safe.
- `docs/implementation/notes/commit-visibility-race.md` — the house ADR format (a decision blockquote
  up top, then the evidence). Your new note follows it.
- The five concrete-container sites you must **not** change:
  `crates/common/src/sink_meta.rs:201`, `crates/loader/src/plan.rs:132`,
  `crates/pg-sink/src/reload_signal.rs:222`, `crates/pg-sink/src/replication.rs:480`, and the
  already-sliced `crates/pg-to-arrow/src/batch.rs:367`.

## Scope

**The conflict, and how to resolve it** — read this before touching anything.

The rule asks for `impl AsMut<[u8]>` write targets. walrus's measured mutable-borrow surface (8
parameters) contains **no fixed-length byte sink**: 5 parameters need `push`/`split_to` on the
concrete container, and 3 are already `&mut [T]`. Per CONTEXT §3 this is archetype **D** — a
documented deviation, not a revert and not a retrofit. Concretely: **do NOT** put `AsMut` on
`crates/common/src/sink_meta.rs:201` or `crates/loader/src/plan.rs:132`. The rule's own "When Not to
Use" forbids it, and `AsMut<String>` / `AsMut<Vec<T>>` widen nothing — they accept exactly the one
type the concrete signature already accepts, at the cost of a generic instantiation. What lands
instead is the ADR, an absence guard, and the mutable-borrow gate walrus genuinely lacks.

**In scope**

- `docs/implementation/notes/asmut-write-targets.md` — the ADR. It must (a) state the decision in a
  blockquote in the house style, (b) tabulate all **8** measured `&mut` container parameters with
  their `file:line` and the concrete-container method each one needs, (c) name the one shape
  `impl AsMut<[u8]>` actually serves (a fixed-length byte fill) and show walrus has none — the
  `replication.rs` wire builders grow a `Vec<u8>`, the pgoutput `Reader` is read-only over `&'a [u8]`,
  (d) record that `clippy::needless_pass_by_ref_mut` is denied in its place and why that is the gate
  the codebase was actually missing, and (e) note that the `1.95.0` pin in `rust-toolchain.toml` is
  what makes denying a single **nursery** lint deterministic.
- `Cargo.toml` — add `needless_pass_by_ref_mut = "deny"` to `[workspace.lints.clippy]`, with a
  one-line comment in the style of the existing `unwrap_used` / `expect_used` note recording that it
  is nursery (so outside `clippy::all`, so no `priority`) and linking the ADR.
- `crates/pg-sink/src/reload_export.rs:282` — `async fn await_echo(&mut self, chunk_no: i64)` becomes
  `async fn await_echo(&self, chunk_no: i64)`. The lint's site count goes 1 → 0.
- `crates/pg-sink/src/reload_export_test.rs` — a compile-time guard pinning the shared receiver, so a
  later refactor cannot silently widen it back to `&mut self`.
- `crates/pg-sink/tests/asmut_absence.rs` — the absence guard: a `#[test]` that walks `crates/**/*.rs`
  and asserts **zero** `AsMut<` bounds, failing with a message that points at the ADR.

**Explicitly deferred** (do *not* build these here)

- **No `impl AsRef<…>` parameters.** The read-only counterpart is `api-impl-asref` in Phase 13 and
  this ticket must not pre-empt it. That is also why the compiled guard pins only the `AsMut<` half:
  denying `AsRef<` would set a trap for PR 13.x. The `As(Ref|Mut)<` grep stays the *measurement* (both
  are 0 today); only `AsMut<` is *enforced*.
- **No other nursery lint promotion.** One nursery lint, one measured site, one green run.
- No new dependency, so no `cargo deny` surface change. No `.sql` file and no `.sqlx` cache entry.

## Hints & gotchas

- The guard file would match **itself** if it contained the literal `AsMut` + `<` sequence. Build the
  needle at runtime (two concatenated halves) — otherwise the test fails the moment you write it, and
  the "fix" of excluding its own path by name is brittle.
- Scope the compiled guard to `AsMut<` only. Phase 13's `api-impl-asref` will legitimately introduce
  `AsRef` bounds; a guard that denies both would make that PR delete this one. The
  `As(Ref|Mut)<` grep stays in the DoD as a *measurement*, not as the enforced assertion.
- `clippy::needless_pass_by_ref_mut` is a **nursery** lint. Denying it is safe here only because
  `rust-toolchain.toml` pins `channel = "1.95.0"` exactly (not `"stable"`), so a future toolchain
  cannot widen the lint under you. Say that in the ADR; it is the whole justification.
- Nursery lints are not members of `clippy::all`, so you do **not** need `priority = -1` on `all` —
  the same reasoning the `unwrap_used` / `expect_used` comment at `Cargo.toml:17-19` already records.
  Keep that comment style.
- Narrowing a receiver from `&mut self` to `&self` is source-compatible for the caller (a `&mut`
  reborrows as `&`), but it is **not** compatible with a caller that holds another `&mut` borrow of
  the same value across the call. There is exactly one caller —
  `export_next_chunk` at `crates/pg-sink/src/reload_export.rs:337` — so check that line and nothing
  else. Do not "helpfully" narrow `export_next_chunk` too; it mutates `self.chunk_no` / `self.cursor`.
- `await_echo` is private and `async`. The receiver guard therefore has to live in the **sibling**
  `crates/pg-sink/src/reload_export_test.rs` (`#[cfg(test)] #[path = …] mod tests;` — never an inline
  `mod tests {}`), where `use super::*` reaches it. The `Fn(&ChunkExporter, i64) -> Fut` bound is the
  cheapest way to assert the receiver without constructing a `ChunkExporter` (which needs a live
  Postgres connection).
- `clippy::all` and `warnings` are already `deny` workspace-wide and every member declares
  `[lints] workspace = true`, so the new lint takes effect everywhere with no per-crate edit — and it
  applies to `--all-targets`, i.e. tests and benches too. Expect it to fire somewhere unexpected; if
  it does, fix the receiver, and only fall back to an item-level `#[allow(...)]` with a one-line
  reason when the `&mut` is genuinely required by a trait signature.
- `unwrap`/`expect` are `deny` in production; `clippy.toml` re-allows them under `cfg(test)` and in
  integration `tests/`, so the new guard test may use them freely.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it.
- No new dependency: the guard is `std::fs` only. Anything else (a walkdir crate) would have to clear
  `cargo deny` — advisories, the 8-license allow-list, bans — for a 20-line recursive walk.
