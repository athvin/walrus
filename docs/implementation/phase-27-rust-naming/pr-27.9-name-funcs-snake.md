# PR 27.9 — Deny `non_snake_case` explicitly and add the naming guard script

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 27 — Rust naming conventions · **Crates touched:** none — workspace `Cargo.toml`,
> `scripts/`, `justfile`, CI · **Est. size:** M · **Depends on:** PR 27.8 · **Unlocks:** PR 27.10

walrus is already fully conformant with this rule: **zero** function or method names contain an
uppercase letter, all **124** `mod` declarations are snake_case, and all **189** `.rs` filenames
match `^[a-z0-9_]+\.rs$`. What is missing is anything that *names* the rule. `[workspace.lints.rust]`
carries a single line — `warnings = "deny"` (`Cargo.toml:12-13`) — so `non_snake_case` is enforced
only as a side effect of that blanket, and it disappears the moment someone relaxes it. And rustc
cannot see file names at all: `apply_loop.rs` could be renamed `applyLoop.rs` tomorrow and every
gate would stay green. This PR pins `non_snake_case = "deny"` by name and lands
`scripts/check-naming.sh` — the shared guard harness that PRs 27.10, 27.12, 27.14, 27.15 and 27.16
each extend with one more check — wired into the `fmt · clippy · test` CI job next to `cargo fmt`.

## Why — learning objectives

- **rustc's `nonstandard_style` lint group and lint-as-policy** — `non_snake_case`,
  `non_camel_case_types` and `non_upper_case_globals` are *rustc* lints (warn-by-default), not
  clippy ones, so they belong in `[workspace.lints.rust]`. Naming a lint that a blanket already
  covers is documentation the compiler enforces: it states the intent and survives the blanket
  being loosened.
- **Keeping a repo convention machine-checked rather than review-checked** — the interesting half
  of this rule lives *outside* the token stream (file names, and later Cargo `name =` fields and
  type-parameter shapes). A 60-line bash guard in the cheapest CI job catches what no lint can.

## Skeleton

```toml
# Cargo.toml — [workspace.lints.rust]
warnings = "deny"
# `nonstandard_style` is policy, not a side effect of the blanket above. Naming the lint keeps it
# alive if `warnings` is ever relaxed, and documents the convention where a reader looks for it.
# The half rustc CANNOT see — .rs FILE names — is guarded by scripts/check-naming.sh (PR 27.9).
non_snake_case = "deny"
```

```bash
#!/usr/bin/env bash
# check-naming.sh — Phase 27's machine-checked naming conventions (PR 27.9+).
#
# rustc's `nonstandard_style` group owns the *identifiers* (see [workspace.lints.rust] in
# Cargo.toml). What rustc cannot see is everything outside the token stream: .rs FILE names, Cargo
# `name =` fields, the shape of type-parameter lists. This script covers those, and re-states the
# rustc-owned checks as belt-and-braces so a stray `#[allow(non_snake_case)]` still shows up here.
#
#   bash scripts/check-naming.sh     (or: just naming)
#
# Each check is one function that reports what it inspected and calls `fail` per violation. Later
# PRs (27.10, 27.12, 27.14, 27.15, 27.16) append one function and one dispatch line at the bottom.
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"

ROOTS=(crates tests) # the two walrus source trees
failures=0

fail() { printf '  FAIL  %s\n' "$*"; failures=$((failures + 1)); }
note() { printf '  ..    %s\n' "$*"; }

# --- funcs_snake (PR 27.9) -------------------------------------------------
# Functions, methods and modules are snake_case; every .rs filename is [a-z0-9_]+.rs.
funcs_snake() {
  echo "== funcs_snake =="
  local bad_idents bad_files n_files n_mods

  # `|| true`: grep exits 1 on "no matches", which is the PASS case, and `set -e` would kill us.
  bad_idents=$(grep -rnE '\b(fn|mod) +[a-z_0-9]*[A-Z]' --include='*.rs' "${ROOTS[@]}" || true)
  # TODO: same shape — find every *.rs, take `basename`, keep only what does NOT match
  #       ^[a-z0-9_]+\.rs$ , and remember the trailing `|| true`.
  bad_files=""

  n_files=$(find "${ROOTS[@]}" -name '*.rs' | wc -l | tr -d ' ')
  n_mods=$(grep -rhE '^\s*(pub(\([a-z]+\))? )?mod [A-Za-z_0-9]+' --include='*.rs' "${ROOTS[@]}" | wc -l | tr -d ' ')
  note "$n_files .rs files, $n_mods mod declarations inspected"

  [[ -z "$bad_idents" ]] || fail "non-snake_case fn/mod name:"$'\n'"$bad_idents"
  [[ -z "$bad_files"  ]] || fail "non-snake_case .rs filename:"$'\n'"$bad_files"
}

funcs_snake
# (27.10) types_camel; (27.12) consts_screaming; (27.14) no_get_prefix;
# (27.15) type_params;  (27.16) crate_no_rs  — appended here, one per PR.

if ((failures > 0)); then
  echo "check-naming: FAIL ($failures)"
  exit 1
fi
echo "check-naming: PASS"
```

## Hints & gotchas

- `set -e` + `grep` is the classic bash trap: `grep` exits **1** when it finds nothing, which here is
  the *success* case. Every grep in the script needs `|| true` (or must be tested with `if !`), or a
  clean tree will fail the gate. Same for `grep -c` inside `$( )`.
- Use `grep -rh` (no line numbers) when counting and `grep -rn` when reporting, and quote the array
  expansion as `"${ROOTS[@]}"` — unquoted it word-splits and `set -u` will not save you.
- The regex must not trip on the ecosystem: `dyn Fn(..)`, `impl FnMut`, `FnOnce` all start with a
  capital `F` and are **not** matched by `\b(fn|mod) ` (lowercase `fn` followed by a space). Do not
  loosen it to `[Ff]n`.
- Sibling test files are `foo_test.rs` — already `[a-z0-9_]+\.rs`. Do **not** exclude `*_test.rs`
  from the filename check; the convention applies to them too.
- Keep the check functions independent and side-effect free (no `exit` inside them, only `fail`), or
  the five PRs that append to this script will each have to restructure it. The `failures` counter
  plus a single `exit` at the bottom is what makes them additive.
- `non_snake_case` is a **rustc** lint, so it goes in `[workspace.lints.rust]`, not
  `[workspace.lints.clippy]`. `warnings = "deny"` already covers it, so adding it needs no
  `priority` field and cannot conflict.
- CI's `changes` filter already lists `scripts/**` and `.github/**` (`ci.yml:40-51`), so a
  script-only PR still runs `gates`. No filter edit is needed.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache (no Docker locally to
  regenerate it), and add no dependency — anything new must clear `cargo deny`.
