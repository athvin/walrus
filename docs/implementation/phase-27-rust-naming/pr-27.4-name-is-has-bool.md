At clean task predecessor `040d7d0c04a1506365a0ec1d246e8dcf11a28ca7`, the exact production
probe finds **13** unprefixed bool-returning definitions, not the originally authored 11. The six
rename targets still exist with the same behavior: `same_duck_type`, `over_ceiling`, two distinct

The target surface also evolved without invalidating the rename. PR 13.2 commit `d333ec4` gave
`over_ceiling` its reasoned `#[must_use = "…"]`; PR 17.4 commit `d02d1a7` changed its ceiling to
`NonZeroU64` and its body to compare against `ceiling_bytes.get()`; PR 21.1 commit `02da833` made it
`const`; and PR 26.3 commit `72daa7e` added a happy-path check before the spill heap, bringing the
method to exactly **nine callers** (memory production 1, memory sibling tests 6, streamed-txn
production 2). `Heartbeat::degraded` already has bare `#[must_use]`. This PR changes names only:
those signatures, bodies, attributes, and all observable behavior stay byte-for-byte equivalent.

Renaming the six definitions removes six lines from the unprefixed census, so the final count is
exactly **7**. Separately, the tree has **five** `sqlx::Type<Postgres>::compatible` definitions —
`Lsn`, `ManifestId`, `EpochNo`, `SchemaVersionNo`, and `ReloadId`. Their spelling is fixed by the
trait and is intentionally excluded from both the 13-line baseline and seven-line final census.

## Why — learning objectives

- **Predicate naming versus bool-returning commands** — `is_` names a state/property query.
  `AtomicPhase::transition`, epoch `advance`, and `Backpressure::tick` mutate state and return
  whether/what transition occurred; the bool return alone does not make them predicates.
- **`clippy::wrong_self_convention` and borrowed `is_` receivers** — the renamed methods already use
  `&self` or `&mut self`. The e2e child-process probes need `&mut self` for `Child::try_wait`, and a
  borrowed mutable receiver still satisfies the convention.
- **The sink's memory ceiling and heartbeat round trip** — `over_ceiling` drives shedding, while
  `degraded` reports an outstanding heartbeat that has missed its round-trip deadline without
  gating readiness. Naming changes must not disturb either correctness path.

## Hints & gotchas

- **There are three degraded predicates after the rename.** `BeatState::is_degraded` (private) and
  `Heartbeat::is_degraded` (public) are the two targets; `HealthState::is_degraded` is a different
  type and already conforms. In `health.set_degraded(heartbeat.is_degraded(now))`, only the
  argument method changes; the setter and health field do not.
- **`over_ceiling` accumulated three independent API contracts.** Keep PR 13.2's reasoned
  `#[must_use]`, PR 17.4's `NonZeroU64::get()`, and PR 21.1's `const fn`. Its current nine-call
  surface includes PR 26.3's early check and loop condition; missing either changes the algorithm.
- `loader_running` currently has **zero** callers. Rename its public definition but do not invent a
  use. `sink_running` has exactly one call, in `tests/e2e/tests/keepalive.rs`.
- `transition`, `advance`, and `tick` deliberately survive because each mutates. Their return values
  report a transition/publish result; `is_*` would lie about side effects.
- `extract<T>(...) -> Vec<T>` is still a regex false positive: the matched `-> bool` belongs to its
  `impl FnMut(&T) -> bool` parameter, not the function return.
- `clippy::wrong_self_convention` accepts the e2e probes' borrowed `&mut self`; do not change them to
  `&self` because `Child::try_wait` needs mutable access, and do not add a lint allow.
- Unit tests remain sibling files (`memory.rs` → `memory_test.rs`, `heartbeat.rs` →
  `heartbeat_test.rs`). `heartbeat_liveness.rs` is a separate integration test.
- Do not touch any `.sql` file or committed `.sqlx` cache. Add no dependency.
