# PR 27.4 — Prefix the predicate methods with `is_`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 27 — Rust naming conventions · **Crates touched:** `loader`, `pg-sink`, `e2e` ·
> **Est. size:** S · **Depends on:** PR 27.3 · **Unlocks:** PR 27.5

**30** production functions already use an `is_` / `has_` / `can_` / `should_` prefix, so the
convention is established here — but **11** bool-returning definitions still do not, and six of them
are genuine violations sitting next to a conformant sibling. `same_duck_type`
(`crates/loader/src/ddl.rs:78`) lives six lines above `is_lossless_widen` (`:84`); `over_ceiling`
(`crates/pg-sink/src/memory.rs:60`) sits between the plain accessors `total()` and `ceiling()`;
`degraded` appears **twice** (`crates/pg-sink/src/heartbeat.rs:165` and `:243`) while
`crates/pg-sink/src/health.rs:89` already spells the same concept `is_degraded`; and the e2e harness
exposes `loader_running` / `sink_running`. This PR prefixes those six, leaves the five justified
survivors alone, and changes no behaviour at all.

## Why — learning objectives

- **Predicate naming, and `clippy::wrong_self_convention`'s receiver rules for `is_`** — clippy wants
  `is_*` on `&self` (or on `self` when the type is `Copy`). `HealthState::is_degraded(&self)` is the
  in-tree shape to copy; the e2e harness's `&mut self` receivers are the interesting edge.
- **The sink's memory ceiling / backpressure and the heartbeat round-trip health signal** —
  `over_ceiling` is what drives `ShedAction` and `spill_if_over_ceiling`; `degraded` is the
  *non-gating* signal that an outstanding beat has not come back inside `roundtrip_deadline`. Reading
  those two paths is how you learn why both are predicates and not commands.

**Explicitly deferred** (do *not* build these here)

- No behaviour change and no new predicates — do not add `is_empty`, do not invert a condition, do
  not turn `over_ceiling`'s `>` into `>=`.
- The `#[must_use]` sweep over these predicates belongs to the `api-` phase. A bool-returning method
  whose result is dropped is a real bug class, but not this ticket's.
- `spill_if_over_ceiling` (`crates/pg-sink/src/stream_txn.rs:190`, `:195`) is a *method name
  containing* the old word, not a predicate. Leave it spelled as it is — it is an `async fn`
  returning `Result<()>`, and `if_` reads correctly.

**Conflict — resolve it explicitly, do not apply the rule blindly.**
`fn compatible(ty: &PgTypeInfo) -> bool` appears at `crates/common/src/lsn.rs:131` and
`crates/common/src/ids.rs:47`. It **cannot** be renamed: it is a required method of
`sqlx::Type<Postgres>`, and its name is fixed by the trait. The probe below therefore *excludes*
`compatible` in its `grep -vE` filter rather than pretending the tree is conformant there. Say so in
the PR body; do not add an `#[allow]` and do not invent a wrapper.

## Hints & gotchas

- **`degraded` is renamed at two layers, and a third already exists.** `BeatState::degraded`
  (private) and `Heartbeat::degraded` (public) both become `is_degraded`; `HealthState::is_degraded`
  in `health.rs` is a *different type* and already conforms. There is no ambiguity — but read
  `consume.rs:83` carefully, because the line `health.set_degraded(heartbeat.degraded(now))` mentions
  two of the three. Only the argument changes.
- `set_degraded` is a **setter**, not a predicate — it returns `()`. This rule does not touch it, and
  the `set_` prefix is not what the `name-no-get-prefix` ticket (PR 27.14) is about either.
- `tick(&mut self, ..) -> bool` deliberately survives. It *mutates* and returns whether the
  transition fired; `is_tick()` would be a lie. Say that in the PR body rather than renaming it.
- `extract<T>(v, pred) -> Vec<T>` survives for a duller reason: the probe's regex matches the
  `-> bool` inside `impl FnMut(&T) -> bool`, not the function's return type. It is a false positive,
  and calling that out is part of the DoD.
- `clippy::wrong_self_convention` (in `clippy::all`, denied workspace-wide) will start applying to
  these once they are `is_*`: it wants `&self`/`&mut self`, or `self` only for `Copy` types. All six
  already satisfy it, so no lint should fire — but if one does, the fix is the receiver, not an
  `#[allow]`.
- `tests/e2e` is feature-gated and its lib carries a file-level `unwrap`/`expect` allow, but it is a
  workspace member with `[lints] workspace = true` — `cargo clippy --all-targets --all-features`
  compiles it, so a missed caller in `tests/e2e/tests/keepalive.rs` *will* fail CI.
- Unit tests are **sibling files** (`memory.rs` → `memory_test.rs`, `heartbeat.rs` →
  `heartbeat_test.rs`), never inline `mod tests {}`. `crates/pg-sink/tests/heartbeat_liveness.rs` is
  a separate integration test — do not confuse the two.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache (no Docker locally to
  regenerate it). Add no dependency — anything new must clear `cargo deny`.
