# PR 27.12 — Deny `non_upper_case_globals` explicitly and guard const naming

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 27 — Rust naming conventions · **Crates touched:** none — workspace `Cargo.toml`,
> `scripts/` · **Est. size:** S · **Depends on:** PR 27.11 · **Unlocks:** PR 27.13

**132** `const`/`static` items live in production code — 131 `const`s (82 free-standing, 49
associated consts inside `impl`/`mod` blocks) and exactly **1** `static`, `HANDLE: OnceLock<…>` at
`crates/common/src/metrics.rs:132` — and every single one is SCREAMING_SNAKE_CASE: measured **0
violations**. Nothing in `Cargo.toml` or `clippy.toml` names `non_upper_case_globals`; like its two
siblings it rides on the blanket `warnings = "deny"` at `Cargo.toml:13`. This PR pins the lint by
name — completing the `nonstandard_style` trio started in PRs 27.9 and 27.10 — and appends the third
check, `consts_screaming`, to `scripts/check-naming.sh`, so the 132-item scan runs on every push
instead of being a number in a commit message.

## Why — learning objectives

- **Compile-time globals vs runtime bindings** — a `const` is inlined at every use site and a
  `static` has one address and program-wide lifetime; neither is a `let`. SCREAMING_SNAKE_CASE is
  the visual marker that a name is *not* a local, which is why the convention is compiler-enforced
  rather than a style preference.
- **walrus's Postgres OID tables as compile-time constants** — `crates/common/src/oids.rs` is ~40
  `pub const <TYPE>: u32 = <oid>;` lines (`BOOL = 16`, `NUMERIC`, the range/multirange families,
  the Tier-3 text carriers). They are `const`, not a lookup map, so every `match col.type_oid`
  in `pg-to-arrow` and `loader` compiles to a jump table. `crates/pg-to-arrow/src/oids.rs` is a
  one-line `pub use common::oids::*;` re-export (PR 8.3) — a single source of truth, two paths.

```bash
# scripts/check-naming.sh — appended below types_camel().

# --- consts_screaming (PR 27.12) -------------------------------------------
# `const` and `static` items are SCREAMING_SNAKE_CASE. Covers free-standing items, associated
# consts inside impl/mod blocks (49 of the 132), and the single `static` in the tree.
consts_screaming() {
  echo "== consts_screaming =="
  local decls bad n
  decls=$(grep -rnE '^\s*(pub(\([a-z]+\))? )?(const|static) [A-Za-z_][A-Za-z_0-9]*:' \
            --include='*.rs' --exclude='*_test.rs' crates/*/src tests/e2e/src || true)
  n=$(printf '%s\n' "$decls" | grep -c . || true)
  note "$n const/static items inspected"

  # TODO: keep only the offenders — anything NOT matching `(const|static) [A-Z][A-Z_0-9]*:`.
  #       Shape: printf '%s\n' "$decls" | grep -vE '(const|static) [A-Z][A-Z_0-9]*:' || true
  bad=""

  [[ -z "$bad" ]] || fail "non-SCREAMING_SNAKE_CASE const/static:"$'\n'"$bad"
}
```

## Hints & gotchas

- The regex anchor is `^\s*`, not `^` — dropping the `\s*` silently loses the **49** associated
  consts inside `impl`/`mod` blocks (`Lsn::ZERO` at `crates/common/src/lsn.rs:23`, the seven
  `telemetry::fields::*` keys, the metrics name tables) and the count would read 82 instead of 132.
  The DoD number is the check that you got this right.
- The trailing `:` in the pattern matters: it anchors on the type ascription and keeps `const fn …`
  declarations out of the match. Without it, every `const fn` in the tree becomes a false positive.
- `grep` exits **1** when it finds nothing, which is the PASS case — every pipeline here needs
  `|| true`, including the `grep -c` inside `$( )`. The harness runs under `set -euo pipefail`.
- `non_upper_case_globals` is a **rustc** lint, so `[workspace.lints.rust]`, not `.clippy`. It is
  already implied by `warnings = "deny"`, so no `priority` field is needed and nothing conflicts.
- Constants in acronym form are correct by definition here — `SINK_WAL_STATUS`, `INT4MULTIRANGE`,
  `TIMESTAMPTZ` are all fine. PR 27.13's acronym rule deliberately excludes SCREAMING_SNAKE names;
  do not "fix" them.
- Keep `consts_screaming` side-effect free (call `fail`, never `exit`) — PRs 27.14, 27.15 and 27.16
  append to the same dispatch block and rely on the single exit at the bottom.
- Unit tests here are sibling `foo_test.rs` files, and `*_test.rs` is excluded from this scan on
  purpose: test-local constants are still covered by rustc under `--all-targets`, so the script only
  needs the production count.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache (no Docker locally to
  regenerate it), and add no dependency — anything new must clear `cargo deny`.
