# PR 27.1 — Record PR 13.4 as owner of the LoaderError conversion

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** superseded by PR 13.4
>
> **Gates:** fmt,clippy,test · **Test packages:** loader

> **Phase:** 27 — Rust naming conventions · **Crates touched:** none (docs evidence only) ·
> **Est. size:** S · **Depends on:** PR 26.4 · **Unlocks:** PR 27.2

The original audit expected `LoaderError::as_common(&self) -> common::Error`, two `as_common`
references, and seven production `as_*` methods. That tree no longer exists. PR 13.4 commit
`e2ada0dfb42dc15a0b155f8d385d477ff73b4f5d` already removed the method and its caller under the
sole `Walrus-Task: 13.4` trailer. It moved the match body byte-for-byte into the stronger standard
conversion `impl From<&LoaderError> for common::Error`, then routed the exit-code seam through
`common::Error::from`. PR 19.2 later centralized terminal classification behind `FailureClass`, but
kept that conversion as the exact exit-code mapping seam.

At baseline `ae87a92a3b06afa5fd54fe0713c4d8d0cc65648e`, `as_common` has **0** source/test hits and
production contains exactly **5 textual `fn as_*` definition sites**. All five are free: two return
borrowed `&str`s, two project primitives from `Copy` newtypes, and one macro definition maps `Copy`
enums to `&'static str` literals. Renaming the removed method to `to_common` would therefore undo the
standard conversion PR 13.4 already owns. This task records the historical ownership, the current
residual census, and the condition that would make this naming rule actionable again.

## Why — learning objectives

- **Prefer the standard conversion already in place.** The rule correctly rejects an allocating
  `as_*`, but `From<&LoaderError>` is a stronger final API than the originally proposed `to_common`:
  it preserves the borrowed receiver, participates in blanket `Into`, and names no ad-hoc adapter.
- **Audit definition sites by cost and ownership.** `as_*` is honest for a borrowed return or a
  primitive projection from a `Copy` wrapper. A macro definition counts once in the textual census
  even when it generates the same free method for several enums.
- **Preserve terminal classification while refactoring APIs.** PR 13.4 moved every mapping arm
  unchanged; PR 19.2 changed only which trait exposes `exit_code`. The current
  `LoaderError -> common::Error -> ExitCode` behavior remains the contract.

## Hints & gotchas

- **Do not implement the obsolete rename.** `to_common(&self) -> common::Error` would satisfy the
  prefix rule in isolation but regress the standard `From<&LoaderError>` API PR 13.4 intentionally
  installed.
- **`From<&LoaderError>` is exact.** Do not change it to `From<LoaderError>`: `main` retains the
  error for logging, and the match clones/formats only what the owned `common::Error` requires.
- **The exit-code caller moved after PR 13.4.** PR 19.2 made `exit_code` a `FailureClass` method and
  changed `main` back to `e.exit_code()`. That is not a reversal: the override still routes through
  `common::Error::from(self)` and preserves all prior codes.
- **Count textual definitions, then inspect macro callers.** The `string_enum!` `fn as_str` line is
  one production definition site that generates four current enum methods. All four enum inputs are
  `Copy`, and every arm returns a static literal.
- **A by-value receiver is not automatically expensive.** `Ratio` and `Lsn` are `Copy` transparent
  wrappers whose `as_*` methods project an `f64`/`u64`; they allocate nothing. Conversely, any
  future borrowed receiver returning a new owned/computed value would violate this rule.
- Do not add a test merely to create a red/green transcript. The owning conversion and exit-code
  tests already exist; the evidence note plus exact absence/census probes is the honest completion.
- Do not touch SQL, `.sqlx`, manifests, lockfiles, workflows, scripts, source, or tests. This task is
  a documentation-only ownership record.
