# PR 27.1 — Rename the allocating `LoaderError::as_common` to `to_common`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** loader

> **Phase:** 27 — Rust naming conventions · **Crates touched:** `loader` · **Est. size:** S ·
> **Depends on:** PR 26.4 · **Unlocks:** PR 27.2

walrus has **7** `as_`-prefixed methods in production and six of them honour the std cost contract
exactly: `Lsn::as_u64` (`crates/common/src/lsn.rs:31`) and `Tier::as_int`
(`crates/common/src/type_descriptor.rs:24`) unwrap a `Copy` primitive, and four
`as_str(self) -> &'static str` methods on `Copy` control-plane enums (e.g. `ManifestKind::as_str`,
`crates/control/src/manifest.rs:32`) hand back a `&'static str`. The seventh —
`LoaderError::as_common(&self) -> common::Error` at `crates/loader/src/error.rs:39` — **allocates on
every arm**: 6 `format!` calls plus 2 `String::clone`s, returning an owned `common::Error` rather
than a reference. It is the only `as_` in the tree that is not free. This PR renames it to
`to_common`, so the loader's terminal-error → `ExitCode` seam advertises its real cost, and leaves
the six free ones untouched.

## Why — learning objectives

- **The std `as_`/`to_`/`into_` cost contract** — the *return type*, not the receiver, decides which
  prefix is honest: `&self -> &U` is `as_`, `&self -> U` (allocating/computing) is `to_`, and
  `self -> U` is `into_`.
- **The loader's terminal-error → `common::ExitCode` mapping seam** — `LoaderError` is the loader's
  crate-local taxonomy; `common::Error` is the shared one that owns the `#[repr(i32)]` exit-code
  contract, and this one method is the bridge between them.

impl LoaderError {
    /// The classified terminal error `main` surfaces as an exit code.
    ///
    /// `to_`, not `as_`: this **allocates** — every arm either `format!`s a message or clones an
    /// owned `String` — and yields an owned [`common::Error`], never a borrow of `self`.
    pub fn to_common(&self) -> common::Error {
        match self {
            LoaderError::Config(e) => todo!("common::Error::Config(e.0.clone())"),
            LoaderError::Control(e) => todo!("common::Error::ControlDb(e.to_string())"),
            LoaderError::Duck(m) => todo!("common::Error::Internal(format!(\"duckdb: {m}\"))"),
            LoaderError::ObjectStore(m) => todo!("common::Error::ObjectStore(m.clone())"),
            LoaderError::LeaseContended { table, owner } => todo!(),
            LoaderError::CorruptCheckpoint { table } => todo!(),
            LoaderError::Quarantine { table, reason } => todo!(),
            LoaderError::EpochBumped { from, to } => todo!(),
            LoaderError::Internal(m) => todo!(),
        }
    }

    pub fn exit_code(&self) -> common::ExitCode {
        self.to_common().exit_code()
    }
}

## Hints & gotchas

- **The receiver is a red herring.** `Tier::as_int(self)` takes `self` *by value* and is still a
  correct `as_`, because `Tier` is `Copy` and the return is a `u8`. Conversely `as_common(&self)`
  borrows and is still wrong, because the return is an owned, freshly-allocated value. Judge the
  return type.
- `clippy::wrong_self_convention` is already in `clippy::all` (denied workspace-wide since PR 7.7).
  It permits `as_*` on a by-value `self` for `Copy` types, which is why the six survivors are silent
  today — and it will stay silent for `to_common(&self)`. Do not expect the lint to do this PR's job
  for you; it does not check allocation.
- Do **not** "improve" the arms while you are in there. `Config(e) => common::Error::Config(e.0.clone())`
  looks like a clone you could remove, but `&self` means you cannot move out of it; changing that is
  a receiver change and belongs to a different ticket.
- `unwrap`/`expect` are denied in production by `[workspace.lints.clippy]`, and `clippy::all` +
  `warnings` are already `deny`. Nothing here needs either.
- Unit tests in walrus are **sibling files** (`src/foo.rs` → `src/foo_test.rs`), never inline
  `mod tests {}`. `crates/loader/src/error.rs` has no sibling test today and does not need one for a
  pure rename — the existing `crates/loader/tests/bootstrap.rs` exit-code assertion is the regression
  net.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. Add no dependency; anything new must clear `cargo deny`.
