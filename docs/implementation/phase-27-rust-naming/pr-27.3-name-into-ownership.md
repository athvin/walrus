# PR 27.3 — Rename `BatchBuilder::finish` to `into_record_batch` to signal the move

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 27 — Rust naming conventions · **Crates touched:** `pg-to-arrow`, `pg-sink`
> (`loader` benches) · **Est. size:** M · **Depends on:** PR 27.2 · **Unlocks:** PR 27.4

Production has exactly **one** `into_`-prefixed method: `SnapshotConn::into_stream`
(`crates/pg-sink/src/snapshot.rs:87`), whose doc comment says "Consumes the connection" because the
name already told you. Meanwhile `BatchBuilder::finish(mut self) -> Result<RecordBatch, Error>`
(`crates/pg-to-arrow/src/batch.rs:193`) consumes `self` while wearing arrow-rs's `finish` name — and
arrow's own `ArrayBuilder::finish` takes `&mut self`. Same word, opposite ownership. That mismatch is
exactly why the single production caller has to write
`std::mem::replace(&mut self.builder, BatchBuilder::new(&self.rel.relation)?)` at
`crates/pg-sink/src/batch.rs:166` before it can call `finish`: the surrounding `seal(&mut self)` only
has a mutable borrow, and the by-value receiver is invisible from the call. Renaming it to
`into_record_batch` makes the move a caller-visible fact.

## Why — learning objectives

- **`self` vs `&mut self` receivers, and why `into_` is the caller-visible move marker** — a method
  taking `self` ends the receiver's life. Rust will tell you at the *use-after-move*, which may be
  far from the call; the name tells you at the call.
- **How the sink seals one Arrow `RecordBatch` per micro-batch at a commit boundary** —
  `TableBatcher::seal` refuses to split an open transaction, swaps in a fresh `BatchBuilder`, turns
  the old one into a `RecordBatch`, and resets the row/byte/LSN counters. The `mem::replace` is the
  physical shape of "the builder is spent".

## Scope

**In scope**

- Rename `BatchBuilder::finish(mut self) -> Result<RecordBatch, Error>` to
  `into_record_batch(mut self) -> Result<RecordBatch, Error>` in `crates/pg-to-arrow/src/batch.rs`.
  Keep the `mut self` receiver, the `Result`, and the body exactly as they are.
- Update **every** call site in the workspace (enumerated below — production, sibling tests,
  integration tests, and benches; `cargo clippy --all-targets` compiles all of them).
- Extend the doc comment to record *why* this differs from arrow's `finish`: walrus takes the
  builder by value, arrow takes `&mut`.

**Explicitly deferred** (do *not* build these here)

- Do **not** change the receiver to `&mut self` "to match arrow". That would require reusing the
  `Vec<Box<dyn ArrayBuilder>>` across batches and re-establishing the schema invariants after each
  flush — a real refactor, out of scope, and it would delete the very lesson this ticket teaches.
- Do **not** touch `WrittenObject` → `NewManifestFile` (`crates/pg-sink/src/manifest.rs:38`). It
  clones 3 `String`s and looks like an `into_` candidate, but all three `record_ready` call sites
  still need `obj` afterwards; consuming it needs a wider refactor.
- Do **not** rename `ParsedRange::elem_data_type(self, ..)` — it takes an argument, so it is not a
  pure `T -> U` conversion.
- No `#[must_use]`, no `From`/`Into` impl, no error-type change.

**Conflict — resolve it explicitly, do not apply the rule blindly.** arrow-rs spells this operation
`finish`, so at first read the rename looks like fighting the ecosystem. It is not: **arrow's
`ArrayBuilder::finish` takes `&mut self` and leaves the builder reusable; walrus's takes `mut self`
and destroys it.** The names must differ *precisely because* the semantics differ — and
`batch.rs:196-198` calls arrow's `finish` twice inside the very method being renamed, so after this
PR the file contains both spellings side by side, which is the point. Write that reasoning into the
doc comment so the next reader does not "fix" it back.

## Hints & gotchas

- **The compiler will not find every call site for you unless you build every target.** `cargo test
  -p pg-to-arrow` misses `crates/loader/benches/append.rs:101` and the two `pg-sink` integration
  tests. Use `cargo clippy --all-targets --all-features -- -D warnings` as the search: it compiles
  lib, bins, tests, examples and benches.
- There are **two** unrelated `finish` families in these files. arrow's `ArrayBuilder::finish` /
  `StringBuilder::finish` (`&mut self`) and criterion's `BenchmarkGroup::finish` (`g.finish()` in
  every bench) both keep their names. Grep for `bb.finish()` / `b.finish()` on a `BatchBuilder`, not
  for the bare word.
- `TableBatcher::seal` must keep the `mem::replace`. It is not a workaround to delete — it is the
  correct way to move a value out of a `&mut self` field, and `BatchBuilder::new(&self.rel.relation)?`
  is what re-arms the batcher for the next micro-batch.
- Do not rename `seal` itself. It is a verb with side effects (it resets six counters and returns a
  `SealedBatch`), not a `T -> U` conversion.
- `unwrap`/`expect` are denied in production by `[workspace.lints.clippy]`; `clippy.toml` re-allows
  them under `#[cfg(test)]` and in integration `tests/`, and the benches carry a file-level allow —
  so the `.into_record_batch().unwrap()` you write in tests and benches is fine, but never in `src`.
- Unit tests are **sibling files** (`batch.rs` → `batch_test.rs`), wired via
  `#[cfg(test)] #[path = "..."] mod tests;`. Do not add an inline `mod tests {}`.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache (no Docker locally to
  regenerate it). Add no dependency — anything new must clear `cargo deny`.
