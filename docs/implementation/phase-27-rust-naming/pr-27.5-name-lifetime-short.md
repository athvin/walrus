# PR 27.5 — Record PR 9.6 as owner of SQLx encoder lifetime elision

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** superseded by PR 9.6
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 27 — Rust naming conventions · **Crates touched:** none (docs evidence only) ·
> **Est. size:** S · **Depends on:** PR 27.4 · **Unlocks:** PR 27.6

The original audit expected two `impl<'q> Encode<'q, Postgres>` definitions and no explicit
`elidable_lifetime_names` policy. That tree no longer exists. PR 9.6 commit
`1e7cc0617cda6924dae4501e8f7f90d3c5cfcf63` already changed `ManifestId` and `Lsn` to
`impl Encode<'_, Postgres>` and added the workspace lint under its sole `Walrus-Task: 9.6`
trailer. Repeating those edits would overwrite historical ownership rather than teach a new naming
lesson.

At clean task predecessor `943808232acbba112fa809bfde308ec4495f2934`, `common` has **0**
`impl<'q>` definitions, exactly **5** anonymous SQLx encoders (`ManifestId`, `EpochNo`,
`SchemaVersionNo`, `ReloadId`, and `Lsn`), and exactly **5** named
`impl<'r> Decode<'r, Postgres>` definitions for the same types. The decoder name remains meaningful:
`'r` relates the trait parameter to `PgValueRef<'r>` in the method signature. Cargo's root
`[workspace.lints.clippy]` contains exactly one `elidable_lifetime_names = "deny"`. PR 13.3 and PR
18.1 added the three later newtypes in the already-correct anonymous-encode/named-decode form, so
the current five-type census is evidence that PR 9.6's policy continues to own this seam.

This task records that historical ownership, the exact current census, and the condition that would
make the naming rule actionable again. It changes no Rust, test, lint configuration, SQL, or Cargo
artifact.

## Why — learning objectives

- **A lifetime name should communicate a relationship.** `Encode<'_, Postgres>` acknowledges the
  trait lifetime without asking a reader to track an identifier used nowhere else. In contrast,
  `Decode<'r, Postgres>` uses `'r` in `PgValueRef<'r>` and therefore keeps the conventional short
  name.
- **Distinguish rule applicability from implementation ownership.** `name-lifetime-short` validates
  the same two original sites that `own-lifetime-elision` already changed. A later curriculum task
  records the earlier owner instead of manufacturing duplicate source work.
- **Use later callers as policy evidence.** PR 13.3's `EpochNo` and PR 18.1's
  `SchemaVersionNo`/`ReloadId` copied the anonymous encoder shape while retaining meaningful decoder
  lifetimes, demonstrating that the lint guards new hand-written SQLx impls.

## Hints & gotchas

- **Do not reimplement the obsolete diff.** PR 9.6 already owns the two source edits and lint
  policy. Changing them again would either be empty or disturb a working ownership seam.
- **`'_` is an anonymous lifetime, not the absence of one.** The SQLx `Encode` trait still has its
  lifetime parameter; the impl simply declines to invent a name that carries no relationship.
- **The decoders are deliberately different.** In `impl<'r> Decode<'r, Postgres>`, the same `'r`
  appears in `PgValueRef<'r>`. Keep it: it tells the reader which borrowed Postgres value the trait
  implementation decodes.
- **Count all five current newtypes, not only PR 9.6's historical two.** PR 13.3 and PR 18.1 copied
  the policy correctly. Their additions are later ownership evidence, not missing PR 27.5 code.
- **The lint already exists exactly once.** Do not add a duplicate, move it, change group priority,
  or enable all nursery/pedantic lints. The existing comment documents why a named deny is needed.
- Do not create an intended-red test just to manufacture a red/green transcript. PR 9.6's diff,
  current source census, explicit lint, and existing common tests are the honest proof.
- Do not touch Rust, tests, Cargo files, SQL, `.sqlx`, lockfiles, workflows, scripts, the roadmap
  index, or design docs. The implementation PR creates one evidence note and nothing else.
