# PR 27.13 — Turn on aggressive acronym casing in clippy.toml

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** loader

> **Phase:** 27 — Rust naming conventions · **Crates touched:** *(workspace config — `clippy.toml`,
> root `Cargo.toml`)* · **Est. size:** S ·
> **Depends on:** PR 27.12 · **Unlocks:** PR 27.14

Not one identifier in walrus spells an acronym in caps. A line-anchored scan of every
`struct`/`enum`/`trait`/`type` declaration for two consecutive capitals returns **0 hits**: the tree
writes `DdlEvent` / `DdlRow` / `DdlConsumer` / `DdlError`, `Lsn` (213 uses) and `LsnParseError`,
`UtcTimestamp` (35 uses), `PgColumn` / `PgRelation`, `CtidRangePlan`, `SinkMeta`, and
`WrittenObject { s3_uri, .. }` — acronyms as *words*, every time. `clippy::upper_case_acronyms` is
already denied transitively (it lives in `clippy::style` ⊂ `clippy::all = "deny"`,
`Cargo.toml:16`), but its default mode only fires on a *fully* capitalised identifier: a future
`HTTPResponse` or `JSONParser` sails straight through. This PR flips
`upper-case-acronyms-aggressive = true` in `clippy.toml` — a knob that exists **only** in that file,
not in `[workspace.lints]` — and names `upper_case_acronyms = "deny"` explicitly so the policy is
written down rather than inherited. Nothing is renamed; the tree is already conformant. The PR
closes the door behind it.

## Why — learning objectives

- **Configuring clippy via `clippy.toml` vs `[workspace.lints]`** — `[workspace.lints.clippy]` sets a
  lint's *level* (allow/warn/deny); `clippy.toml` sets a lint's *behaviour*. Some knobs
  (`upper-case-acronyms-aggressive`, `allow-unwrap-in-tests`) exist only in the latter, so "denied"
  and "denied strictly" are two separate edits — this PR makes both.
- **Reading walrus type names: Ddl / Lsn / Pg / Toast as words, not initialisms** — the tree's
  vocabulary is already the rule's "Good" column. Knowing *why* `DdlCaptureMissing` beats
  `DDLCaptureMissing` (word boundaries survive) is what lets you review the next name in seconds.

- Extend `scripts/check-naming.sh --self-test` with an isolated temporary crate containing a private

  there, and require the expected `upper_case_acronyms` diagnostic without editing a member crate.

**The conflict this ticket must resolve (do not apply the rule blindly)**

Aggressive mode does not just look for runs of capitals — it rebuilds the identifier with clippy's
internal `correct_ident` and fires when the rebuilt form differs. That is a wider net, and
`S3Access` (`crates/loader/src/duck.rs:375`) is the one production name that could plausibly land in
it. **Keep the config knob.** If clippy flags `S3Access`, add a scoped
`#[allow(clippy::upper_case_acronyms)]` on that item with a one-line comment saying S3 is a product
name (Simple Storage Service *3*), not a run of initials — the same reasoning that keeps
`Base64Encoder` legal in the rule's own "Mixed Cases" section. Renaming it to `S3access`/`S3Access`
variants, or dropping the aggressive knob to keep the build quiet, are both wrong answers. Run
clippy and record the actual result in the PR body either way.

**Explicitly deferred** (do *not* build these here)

- **Renames nothing.** The measured violation count is 0; this PR is pure enforcement.
- SCREAMING_SNAKE constants are untouched — `INT2`/`TIMESTAMPTZ`/`UUID` in
  `crates/loader/src/duck.rs:9-10` and the OID tables in `crates/common/src/oids.rs` are acronyms in
  a context where all-caps is *correct by definition*, and the lint does not look at consts anyway.
- No new check in `scripts/check-naming.sh` (PRs 27.14/27.15/27.16 each append one). Here the
  compiler gate is strictly stronger than a grep, so a script check would be redundant weight.

## Hints & gotchas

- **A typo in `clippy.toml` is a hard error, not a warning.** An unknown key makes clippy abort with
  `error: error reading Clippy's configuration file: unknown field ...` before it lints anything.
  That is your fastest feedback loop — run `cargo clippy` once immediately after the edit.
- **The key is kebab-case, the lint is snake_case.** `upper-case-acronyms-aggressive` in
  `clippy.toml`; `upper_case_acronyms` in `[workspace.lints.clippy]`. Mixing them up produces the
  unknown-field error above.
- **`upper_case_acronyms` skips items that are exported from the crate.** Its intent is
  crate-internal hygiene, so a `pub struct HTTPThing` re-exported from `lib.rs` may lint clean while
  a private one right beside it fails. Verify this yourself before you write "the gate catches
  everything" anywhere — put your scratch struct in a *private* position, and mention the limitation
  in the PR body. It is also the reason Phase 27 keeps the grep-based `scripts/check-naming.sh`
  (PRs 27.9/27.10) alongside the lint rather than replacing it.
- **Default vs aggressive, precisely.** The default mode fires only when the whole identifier is
  uppercase and longer than two characters (two-letter idents like `Io`/`Id` are deliberately
  exempt). Aggressive mode additionally fires whenever the identifier differs from clippy's corrected
  spelling. For `S3Access` the corrected form comes out as `S3Access` — a single-capital fragment
  followed by a digit stays glued — so the expectation is silence. **Expectation is not evidence:**
  run clippy and paste the real output.
- **Don't trust a naive adjacent-caps grep.** `grep -rE '(struct|enum|type) [A-Z][A-Z]'` without the
  `^\s*` anchor matches *prose* in doc comments — e.g. `/// Map a Postgres type OID to a DuckDB
  column type` at `crates/loader/src/duck.rs:383` scores a hit on "type OID". Anchor at line start
  (as the probe above does) or you will chase phantoms.
- `clippy::all` and `warnings` are already `deny` workspace-wide, and every member declares
  `[lints] workspace = true` — you do not need to touch any member manifest.
- `unwrap`/`expect` are denied in production; nothing here needs either. No new dependency, so
  `cargo deny` has nothing new to clear.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it.
- Unit tests in walrus are **sibling files** (`src/foo.rs` → `src/foo_test.rs`), never inline
  `mod tests {}`. This PR adds no Rust test file; the script's isolated Clippy fixture is the
  negative proof.
