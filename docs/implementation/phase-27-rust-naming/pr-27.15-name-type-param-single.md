# PR 27.15 — Guard generic parameters to the conventional short names

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 27 — Rust naming conventions · **Crates touched:** *(none — `scripts/check-naming.sh`
> only)* · **Est. size:** S ·
> **Depends on:** PR 27.14 · **Unlocks:** PR 27.16

walrus uses generics sparingly and conventionally. There are **13** generic declaration sites in
production, and every declared type parameter is a short, recognisable letter:
`lease_guarded_export<R, RFut, E>` (`crates/pg-sink/src/reload.rs:64`),
`retry_transient<T, F, Fut>` (`crates/pg-sink/src/bootstrap.rs:148`),
`write_parquet<W: std::io::Write + Send>` (`crates/pg-to-arrow/src/parquet.rs:24`),
`append_num<B, T>` (`crates/pg-to-arrow/src/batch.rs:715`), `trait ArrowNumBuilder<T>` (`:747`),
`struct_field<'a, T: ArrayBuilder>` (`:568`), `extract<T>`
(`crates/pg-sink/src/reload_signal.rs:222`), `pub type Result<T>`
(`crates/common/src/error.rs:13`), and serde's `serialize<S: Serializer>` /
`deserialize<D: Deserializer<'de>>` on `Tier`, `SinkMeta` and `Lsn`. Not one `ElementType`, not one
lowercase `<t>`. Every `impl<…>` header in the tree declares **lifetimes only**. And nothing
enforces any of it — rustc has no lint for parameter-name length, and clippy has none either. This
PR appends a `type_params` check to `scripts/check-naming.sh` that extracts *declared* parameters
and rejects anything that is not `^[A-Z][A-Za-z]{0,3}$`, with `Fut`/`RFut` documented as the
accepted future-type convention. Nothing is renamed.

## Why — learning objectives

- **Type-parameter naming conventions (T/E/K/V/F/Fut) and where clauses** — the single letter is a
  *vocabulary*, not laziness: `E` says "error", `F` says "the function", `Fut` says "the future that
  `F` returns". The complexity belongs in the `where` clause, which is exactly how
  `retry_transient<T, F, Fut> where F: FnMut() -> Fut, Fut: Future<Output = Result<T, Error>>` reads.
- **walrus's two generic seams: the retry-with-deadline helper and the lease-guarded export** — both
  exist to make an async policy testable *without a database*: the effect is injected as a closure,
  so the retry/cancel contract is a unit test. Understanding why those two functions (and almost
  nothing else) are generic tells you where the seams of this codebase are.

## Read first

- [`name-type-param-single`](../../../.claude/skills/rust-skills/rules/name-type-param-single.md) —
  take the **Standard Type Parameter Names** table (T/E/K/V/I/O/R/S/A/F) and the **Trait Bounds**
  section: short parameters, bounds in a `where` clause. Note what the rule does *not* say — it never
  demands a rename of a 3-letter parameter that reads as a word.
- `scripts/check-naming.sh` — **read it in full first.** PR 27.9 created it; 27.10, 27.12 and 27.14
  each appended one check. Mirror the shape they established (helper name, `ok`/`FAIL` output,
  exit convention). This is the fifth check, not a new script.
- `crates/pg-sink/src/reload.rs:60-95` — `lease_guarded_export<R, RFut, E>`, the widest generic
  signature in the tree. `R` is the renewer, `RFut` the future it returns, `E` the export future.
  Read the `where` clause and the `tokio::select!` body together; the names only make sense as a set.
- `crates/pg-sink/src/bootstrap.rs:144-171` — `retry_transient<T, F, Fut>`. The `F`/`Fut` pairing is
  the canonical Rust idiom for "async closure" before async closures existed; `T` is the success
  value that flows back out.
- `crates/pg-to-arrow/src/parquet.rs:24` and `crates/pg-to-arrow/src/batch.rs:715,745-760` —
  `W` for a writer (`std::io::Write`), and `append_num<B, T>` over the `ArrowNumBuilder<T>` bridge
  trait plus the `num_builder!` macro that implements it. That macro is where the guard's sharpest
  edge lives (see **Hints**).
- `crates/common/src/type_descriptor.rs:33-42` — `serialize<S: Serializer>` and
  `deserialize<D: Deserializer<'de>>` on `Tier`. `S` and `D` are serde's own vocabulary, and `D` is
  the parameter the naive one-line probe cannot see.

## Scope

**In scope**

- Append a `type_params` check to `scripts/check-naming.sh` that:
  - extracts type parameters from **declaration** positions only — the `<…>` immediately after
    `impl`, and the `<…>` after a `fn` / `struct` / `enum` / `trait` / `type` name;
  - strips lifetimes (`'a`, `'de`, `'q`, `'r`) and trait bounds (everything from the first `:`);
  - fails on any surviving name that does not match `^[A-Z][A-Za-z]{0,3}$`;
  - prints the sorted set it inspected, so the PR body can paste it as evidence.
- Handle nested angle brackets in bounds — `<D: Deserializer<'de>>` and
  `<T: Into<Cow<'a, str>>>` must both yield exactly one parameter. A check that silently drops them
  is a check that will silently miss `ElementType: Into<Foo>` later.
- Write the `Fut` / `RFut` carve-out into the script as a comment: a 3-4 character parameter that
  names a *future* is the accepted convention here, which is precisely why the bound is
  `{0,3}` and not `{0}`.

**Explicitly deferred** (do *not* build these here)

- **Renames nothing.** `RFut` stays `RFut` — it is not "R + Fut2", it is "the future `R` returns",
  and it is the clearest available name for that. Do not rename it to `Fut2` or `G`.
- No new generics are introduced. If a signature looks like it *wants* to be generic, that is a
  different ticket.
- The `where`-clause reformatting the rule also suggests is left to rustfmt defaults — walrus does
  not carry a `rustfmt.toml` override for it and this PR does not add one.
- Const generics (`<const N: usize>`) are not modelled: the tree has none. Note the gap in the
  script's comment rather than writing speculative parsing for it.
- Depends on PR 27.9 having created `scripts/check-naming.sh`. If it is absent, land 27.9 first.

## Skeleton

Helper naming below is a placeholder — **mirror `scripts/check-naming.sh`'s existing style.** What
must survive is the extraction scope (declarations, not applications) and the accepted pattern.

```bash
# scripts/check-naming.sh — appended after the no_get_prefix check.

# --- type_params (PR 27.15) ---------------------------------------------------------------------
# Generic parameters are short conventional letters: T (type), E (error), F (function), Fut (the
# future F returns), R/RFut (the renewer and its future), S/D (serde's Serializer/Deserializer),
# W (writer), B (builder). Accepted pattern: ^[A-Z][A-Za-z]{0,3}$ — the {0,3} tail exists so `Fut`
# and `RFut` pass; anything longer is a word pretending to be a parameter (`ElementType`).
#
# Scope is DECLARATIONS only:
#   * the `<..>` immediately after `impl`  (walrus: lifetimes only today)
#   * the `<..>` after a fn / struct / enum / trait / type NAME
# Applications are NOT declarations — `impl Type<Postgres> for ManifestId`, `Result<T, Error>` and
# the macro body `impl ArrowNumBuilder<$t> for $b` must never be scanned, or the check reports
# `Postgres` / `$t` as violations.
#
# Not modelled: const generics (`<const N: usize>`) — the tree has none. Extend here if that changes.
check_type_params() {
  local params
  params=$(
    grep -rhoE '\b(impl|fn|struct|enum|trait|type)[[:space:]]+([A-Za-z_0-9]+[[:space:]]*)?<' \
      --include='*.rs' crates/*/src tests/e2e/src >/dev/null 2>&1 || true
    # NOTE: a one-line grep CANNOT balance nested `<>`. Extract the declaration header, then let
    # awk/sed walk the angle-bracket depth so `<D: Deserializer<'de>>` yields exactly `D`.
    todo_extract_declared_params
  )
  local bad
  bad=$(printf '%s\n' "$params" | grep -vE '^[A-Z][A-Za-z]{0,3}$' | grep -c . || true)
  if [ "$bad" -ne 0 ]; then
    echo "FAIL type_params: generic parameter(s) longer than 4 chars or not UpperCamel:"
    printf '%s\n' "$params" | grep -vE '^[A-Z][A-Za-z]{0,3}$'
    echo "     use T/E/K/V/F/Fut (.claude/skills/rust-skills/rules/name-type-param-single.md)"
    return 1
  fi
  echo "  ok type_params: $(printf '%s\n' "$params" | sort -u | tr '\n' ' ')"
  return 0
}
```

`todo_extract_declared_params` is the actual work of this PR: a small `awk` (or `sed` + `tr`) pass
that, for each declaration header, consumes characters tracking `<`/`>` depth, emits the depth-1
comma-separated items, then drops anything starting with `'` and truncates each item at the first
`:`. Ten lines of `awk`, and the DoD below tells you the exact set it must produce.

## Hints & gotchas

- **Regex cannot balance angle brackets — stop trying.** `<D: Deserializer<'de>>` and
  `<W: std::io::Write + Send>` defeat any single `grep -oE`. Extract the header, then walk the string
  counting `<` and `>` depth in `awk`. This is the whole difficulty of the ticket and the reason it
  is a script rather than a one-line grep in CI.
- **Declaration vs application is the other half.** `impl Type<Postgres> for ManifestId` declares
  nothing — the `impl`'s own parameters are the `<…>` *immediately after the `impl` keyword*, and in
  walrus every one of those contains only lifetimes (`impl<'de>` ×3, `impl<'r>` ×2, `impl<'q>` ×2,
  `impl<'a>` ×2). Anchor on `impl<` with no space, not on `impl` followed by anything.
- **The `num_builder!` macro will bite you.** `crates/pg-to-arrow/src/batch.rs:750-760` contains
  `impl ArrowNumBuilder<$t> for $b` inside a `macro_rules!` body. A sloppy extractor reports `$t` as
  a violating parameter. It is an *argument* inside a macro template, not a declaration — the
  `impl<` anchor above already excludes it, which is a good way to confirm your anchor is right.
- **PR 27.5 may have changed two of those `impl<'q>` headers to `impl Encode<'_, Postgres>`.** If
  you are working after it merged, the lifetime-only impl count is different; the type-parameter set
  is not. Do not hard-code impl-header counts into the check — only the parameter set is asserted.
- **`grep -c` returns exit 1 on no match, which `set -euo pipefail` turns into a script abort.**
  Every grep in the check needs `|| true`. A guard that fails on a clean tree is worse than no guard.
- **Keep the check name literally `type_params`.** The probe in this task file and the roadmap
  greps for that exact string; renaming it to `check_generics` silently breaks the evidence trail.
- `Fut` and `RFut` are the reason the pattern is `{0,3}` rather than `{0}`. If you tighten it to a
  single letter to feel pure, the tree fails its own guard on day one — the rule's own "Descriptive
  only when many parameters need clarity" line covers exactly this case.
- `unwrap`/`expect` are denied in production, and `clippy::all` + `warnings` are already `deny` —
  irrelevant to a shell script, but relevant to the fact that this PR must add **no** Rust.
- Unit tests in walrus are **sibling files** (`src/foo.rs` → `src/foo_test.rs`), never inline
  `mod tests {}`. This PR adds neither; the paste-and-revert checks in the DoD are the proof.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. No new dependency, so nothing new for `cargo deny`.
