# PR 27.16 — Guard crate and binary names against `-rs` / `-rust` suffixes

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 27 — Rust naming conventions · **Crates touched:** *(none — `scripts/check-naming.sh`
> only)* · **Est. size:** S ·
> **Depends on:** PR 27.15 · **Unlocks:** PR 28.1

All **14** `name =` entries across the six member manifests are clean: packages `common`, `control`,
`loader`, `pg-sink`, `pg-to-arrow`, `e2e`; libs `loader` and `pg_sink`; binaries `walrus-loader` and
`walrus-pg-sink`; benches `transform`, `append`, `decode`, `batch`. Zero `-rs` suffixes, zero
`-rust` suffixes, zero `rust-` prefixes. That is a deliberate choice, written down in
`docs/architecture.md` § "Proposed Rust workspace layout": *"The workspace is already named
`walrus`, so member crates drop the redundant prefix"*, and the `walrus-` on the two binaries is
*"the cluster-level service/image name, not the crate name"*. The risk is not the present tree — it
is the next member. `Cargo.toml:3` says so out loud: the workspace *"grows one crate at a time,
following the DAG in docs/implementation/README.md"*. This PR appends a `crate_no_rs` check to
`scripts/check-naming.sh` so the fifteenth `name =` entry is checked by CI rather than by whoever
happens to review it. Nothing is renamed.

## Why — learning objectives

- **Cargo package vs lib vs bin `name` fields and how they differ in one manifest** —
  `crates/pg-sink/Cargo.toml` carries three of them: `[package] name = "pg-sink"` (what `-p` and
  `path =` see), `[lib] name = "pg_sink"` (what `use pg_sink::…` sees — hyphens are illegal in Rust
  identifiers), and `[[bin]] name = "walrus-pg-sink"` (the binary on disk and in the container
  image). Three names, three audiences, one file.
- **The walrus workspace DAG: common → pg-to-arrow/control → pg-sink/loader → e2e** — `common` is a
  leaf, `control` and `pg-to-arrow` each depend only on it, the two binary crates sit on top, and
  `tests/e2e` drives them as black boxes. Knowing the DAG is knowing where a new crate can legally
  be inserted — and it is precisely at that moment that the naming guard earns its keep.

## Read first

  bad/good table and, more importantly, the **When Context Is Needed** and **Exceptions** sections:
  `windows-sys` is fine because `sys` is a platform, not a language. That distinction is what your
  check's comment has to encode so the next person does not "fix" a legitimate name.
- `scripts/check-naming.sh` — **read it in full first.** PR 27.9 created it; 27.10, 27.12, 27.14 and
  27.15 each appended one check. This is the sixth and last check of Phase 27; mirror the shape
  those five established rather than inventing a new one.
- `Cargo.toml:1-3` — the virtual workspace manifest. Note there is **no** `[package]` and therefore
  no root `name =` to check; the scan is over member manifests only. Read the trailing comment on
  `:3` — it is the reason this ticket exists.
- `crates/pg-sink/Cargo.toml:1-13` — the three-name manifest (`pg-sink` / `pg_sink` /
  `walrus-pg-sink`). Compare with `crates/loader/Cargo.toml:1-13`, where the package and lib names
  are both `loader` because there is no hyphen to translate.
- `tests/e2e/Cargo.toml:1-14` — `name = "e2e"`, `publish = false`, and the comment explaining that
  the crate drives both binaries over the compose stack. It lives under `tests/`, not `crates/`, so
  a glob that only walks `crates/*/Cargo.toml` misses it — and it is the member most likely to
  attract a `-rs`-style suffix, being the odd one out.
- `crates/loader/Cargo.toml:48-55` and `crates/pg-to-arrow/Cargo.toml:38-41` — the `[[bench]]`
  entries (`transform`, `append`, `batch`, `decode`). They carry **no `path`**, so the `name` maps
  directly to `benches/<name>.rs`; renaming one breaks the build. The negative control therefore
  uses isolated manifest fixtures.
- `docs/architecture.md` § "Proposed Rust workspace layout (for when coding starts)" — the paragraph
  after the tree is the written-down rationale for every one of these 14 names.

## Skeleton

Helper naming is a placeholder — **mirror `scripts/check-naming.sh`'s existing style.** What must
survive is the glob, the anchored pattern, and the inspected-count reporting.

```bash
# scripts/check-naming.sh — appended after the type_params check.

# --- crate_no_rs (PR 27.16) ---------------------------------------------------------------------
# No `-rs` / `-rust` suffix and no `rust-` prefix on any Cargo `name`. The workspace is already
# called walrus and everything in it is obviously Rust, so the suffix is pure noise
# (docs/architecture.md § "Proposed Rust workspace layout").
#
# Scans PACKAGE, LIB, BIN, BENCH and EXAMPLE names — one manifest can hold several:
#   crates/pg-sink/Cargo.toml -> package "pg-sink", lib "pg_sink", bin "walrus-pg-sink".
# `pg_sink` is NOT a violation: a lib name cannot contain a hyphen (it is a Rust identifier), so the
# underscore is the mandatory translation of the package's hyphen — hence the `_rs"` anchor on the
# closing quote rather than a bare `_rs` substring.
# `walrus-` on the two bins is the cluster service/image name, not a language tag: also fine.
# tests/ is included on purpose — the `e2e` member lives at tests/e2e/Cargo.toml.
check_crate_no_rs() {
  local names bad
  names=$(grep -hE '^name = "' crates/*/Cargo.toml tests/*/Cargo.toml || true)
  bad=$(printf '%s\n' "$names" | grep -E '^name = "(rust-.*|.*(-rs|-rust|_rs))"$' || true)
  if [ -n "$bad" ]; then
    echo "FAIL crate_no_rs: crate/target name(s) tagged with the language:"
    printf '%s\n' "$bad"
    echo "     drop the suffix (.claude/skills/rust-skills/rules/name-crate-no-rs.md)"
    return 1
  fi
  echo "  ok crate_no_rs: $(printf '%s\n' "$names" | grep -c .) name entries, 0 -rs/-rust suffixes"
  return 0
}
```

## Hints & gotchas

- **`tests/` is not under `crates/`.** The `e2e` member lives at `tests/e2e/Cargo.toml`. A glob of
  `crates/*/Cargo.toml` alone inspects 12 names, not 14 — which is exactly why the DoD asserts the
  count rather than just "exits 0". A guard that silently stops looking is worse than no guard.
- **Anchor the pattern on the closing quote.** `_rs` as a bare substring matches nothing today but
  would match a future `common_rspec`-style name; `-rs"$` / `_rs"$` is the honest test for a
  *suffix*. Likewise `rust-` must be anchored to the start of the value (`"rust-`), or you flag any
  name containing the word.
- **Do not flag `pg_sink`.** `[lib] name` becomes a Rust identifier, and identifiers cannot contain
  hyphens — cargo requires the underscore form. If your check reports it, your pattern is looking
  for underscores rather than for the `_rs` suffix.
- **Bench names have no `path`.** `[[bench]] name = "transform"` resolves to
  `crates/loader/benches/transform.rs`; the committed self-test must therefore use isolated
  manifest fixtures rather than renaming any real target.
- **`grep` exits `1` on no match**, and under `set -euo pipefail` that aborts the script — on the
  *clean* tree, which is the success case. Terminate every grep in the check with `|| true`, as the
  skeleton does.
- **Resist the urge to also check the workspace root.** `Cargo.toml` is a virtual manifest: no
  `[package]`, no `name`. Adding it to the glob costs nothing but reporting `15` would be wrong, and
  the count is the DoD's evidence.
- **This closes Phase 27.** `scripts/check-naming.sh` now carries six checks (funcs/mods/filenames,
  `types_camel`, `consts_screaming`, `no_get_prefix`, `type_params`, `crate_no_rs`). Read the whole
  file once after your edit — if it has drifted into six different styles, a short tidy-up here is
  worth more than in any later phase.
- `unwrap`/`expect` are denied in production and `clippy::all` + `warnings` are already `deny` —
  irrelevant to a shell script, but a reminder that this PR must add **no** Rust. Unit tests in
  walrus are sibling files (`src/foo.rs` → `src/foo_test.rs`), never inline `mod tests {}`; this PR
  adds neither.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. No new dependency, so nothing new for `cargo deny` to clear.
