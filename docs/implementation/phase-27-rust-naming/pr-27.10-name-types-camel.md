# PR 27.10 — Deny `non_camel_case_types` explicitly and guard type names

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 27 — Rust naming conventions · **Crates touched:** none — workspace `Cargo.toml`,
> `scripts/` · **Est. size:** S · **Depends on:** PR 27.9 · **Unlocks:** PR 27.11

All **147** production type declarations — every `struct`, `enum`, `trait`, `type` alias and `union`
under `crates/*/src` and `tests/e2e/src` — are UpperCamelCase, and not one of them contains an
underscore or starts with a lowercase letter: measured **0 violations**. As with `non_snake_case`
one PR ago, the lint that says so is reachable today only through the blanket
`warnings = "deny"` at `Cargo.toml:13` and is never named. This PR pins
`non_camel_case_types = "deny"` in `[workspace.lints.rust]` and appends a second check,
`types_camel`, to the `scripts/check-naming.sh` harness PR 27.9 created — so the count stays visible
(the script prints "147 type declarations inspected") rather than being an unstated assumption.

## Why — learning objectives

- **Item-kind naming conventions and where rustc enforces them** — `non_camel_case_types` covers
  `struct`, `enum`, `trait`, type aliases, *and* generic type parameters; `non_snake_case` covers
  values and modules; `non_upper_case_globals` covers `const`/`static`. Three lints, one group
  (`nonstandard_style`), all rustc rather than clippy — which is why they live in
  `[workspace.lints.rust]`.
- **The walrus type vocabulary** — `PgRelation`/`PgColumn` (the decoder → Arrow seam),
  `ManifestKind`/`ManifestStatus` (the control-plane work queue), `Lsn` (the ordering newtype),
  `SinkMeta`. Acronyms are written as words — `Pg`, `Lsn`, `Ddl`, `Utc` — never `PG`, `LSN`, `DDL`.

## Skeleton

```toml
# Cargo.toml — [workspace.lints.rust], joining `warnings` and `non_snake_case`.
# The other half of `nonstandard_style`: type-level names. Same reasoning as non_snake_case (PR 27.9)
# — named so the convention survives anyone relaxing the blanket `warnings = "deny"`.
non_camel_case_types = "deny"
```

```bash
# scripts/check-naming.sh — appended below funcs_snake().

# --- types_camel (PR 27.10) ------------------------------------------------
# struct / enum / trait / type-alias / union names are UpperCamelCase: a capital first letter and
# no underscore. rustc's non_camel_case_types owns this too; restated here so the *count* is
# visible and a stray `#[allow(non_camel_case_types)]` cannot hide.
types_camel() {
  echo "== types_camel =="
  local decls bad n
  decls=$(grep -rnE '^\s*(pub(\([a-z]+\))? )?(struct|enum|trait|type|union) [A-Za-z_0-9]+' \
            --include='*.rs' --exclude='*_test.rs' crates/*/src tests/e2e/src || true)
  n=$(printf '%s\n' "$decls" | grep -c . || true)
  note "$n type declarations inspected"

  # TODO: keep only the offenders — a declaration whose name starts lowercase OR holds an `_`.
  #       Shape: printf '%s\n' "$decls" | grep -E '<the bad-name pattern>' || true
  bad=""

  [[ -z "$bad" ]] || fail "non-UpperCamelCase type name:"$'\n'"$bad"
}
```

## Hints & gotchas

- `grep` exits **1** on "no matches", which is the PASS case here — every pipeline needs a trailing
  `|| true`, and so does `grep -c` inside `$( )`. The harness runs under `set -euo pipefail`.
- Associated types inside `impl`/`trait` blocks (`type Item = &'a PgColumn;`, `type Err = String;`,
  `type IntoIter = Iter<'a>;`) match the same `^\s*type ` pattern and are counted among the 147.
  That is fine — they are UpperCamelCase too — but do **not** try to exclude them with an
  indentation anchor; you would also drop nested `struct`s.
- Do not confuse the `type` keyword with the `type_oid` / `type_modifier` fields on `PgColumn`: the
  pattern requires a space after `type`, so `pub type_oid: u32,` is not matched. Keep the space.
- `crates/*/src` deliberately excludes `crates/*/tests/` and `benches/`. Test and bench targets are
  still covered by rustc, because `[lints] workspace = true` plus `--all-targets` denies
  `non_camel_case_types` there as well; the script only needs the production count to stay honest.
- `non_camel_case_types` is a **rustc** lint, so `[workspace.lints.rust]`, not `.clippy`. It is
  already implied by `warnings = "deny"`, so no `priority` juggling and no risk of conflict.
- Keep `types_camel` side-effect free (call `fail`, never `exit`) — PRs 27.12, 27.14, 27.15 and
  27.16 append three more checks to the same dispatch block and rely on the single exit at the end.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache (no Docker locally to
  regenerate it), and add no dependency — anything new must clear `cargo deny`.
