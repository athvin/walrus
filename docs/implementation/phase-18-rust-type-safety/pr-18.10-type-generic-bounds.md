# PR 18.10 — Lock in generic-bound hygiene with workspace lints

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 18 — Rust type safety · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 18.9 · **Unlocks:** PR 18.11

Bound placement in walrus is already disciplined, and that is exactly why this ticket is a **gate,
not a cleanup**. Production has a handful of generic functions and exactly **three `where` clauses**
— `crates/pg-sink/src/reload.rs:70`, `crates/pg-sink/src/bootstrap.rs:149`,
`crates/pg-to-arrow/src/batch.rs:722` — and every multi-bound signature already uses one, while the
single-bound signatures (`S: Serializer`, `T: ArrayBuilder`, `W: io::Write + Send`) stay inline. No
struct carries a bound. Nothing *keeps* it that way: none of the bound-hygiene lints appear in
`[workspace.lints]`, and the pedantic/nursery sweep already shows one of them firing — a full
`--all-targets --all-features` run of `common`, `control`, `pg-to-arrow` and `pg-sink` reports
`clippy::elidable_lifetime_names` at **exactly two sites**, both on the newtypes' sqlx impls
(`crates/common/src/ids.rs:52`, `crates/common/src/lsn.rs:138`). After this PR the four lints are
denied workspace-wide and those two `impl<'q>` heads read `impl Encode<'_, Postgres>`.

## Why — learning objectives

- **`where` clauses vs inline bounds, and where a bound belongs** — struct vs impl vs fn — plus
  lifetime elision in `impl` headers: a named lifetime used exactly once is noise.
- **Why walrus keeps its generics shallow** — the `pgoutput` decode and loader transform are sync
  and pure, the Arrow builders are `dyn`-dispatched, and the two real generic seams are test seams.

## Read first

- [`type-generic-bounds`](../../../.claude/skills/rust-skills/rules/type-generic-bounds.md) — take
  the **Bound Placement** table and "start with no bounds, add as needed". The
  "Conditional Trait Implementation" section is the one to remember for PR 18.11, where a derived
  `Clone` on `DuckTable<K>` will silently add a `K: Clone` bound you do not want.
- `Cargo.toml:10-21` — `[workspace.lints.rust]` / `[workspace.lints.clippy]` and the comment
  explaining why `unwrap_used`/`expect_used` need no `priority` juggling: they are `restriction`
  lints, outside the `clippy::all` group. The same reasoning applies to three of the four lints here.
- `crates/common/src/ids.rs:37-66` and `crates/common/src/lsn.rs:120-155` — the two `sqlx_support`
  modules. Compare `impl<'q> Encode<'q, Postgres>` (the lifetime appears **once**) with
  `impl<'r> Decode<'r, Postgres>` (it appears again in `PgValueRef<'r>`) — only the first is elidable.
- `crates/pg-sink/src/reload.rs:64-77`, `crates/pg-sink/src/bootstrap.rs:148-156`,
  `crates/pg-to-arrow/src/batch.rs:715-724` — the three `where` clauses this PR is protecting.
- `crates/pg-to-arrow/src/parquet.rs:24` and `crates/pg-to-arrow/src/batch.rs:568` — the inline
  single-bound signatures that stay inline.

## Scope

**In scope**

- Four new entries in `[workspace.lints.clippy]`, one per line, each `= "deny"`:
  `type_repetition_in_bounds`, `trait_duplication_in_bounds`, `multiple_bound_locations`,
  `elidable_lifetime_names`.
- The two `elidable_lifetime_names` sites fixed: `impl<'q> Encode<'q, Postgres> for ManifestId`
  (`ids.rs:52`) and `impl<'q> Encode<'q, Postgres> for Lsn` (`lsn.rs:138`) become
  `impl Encode<'_, Postgres> for …`.
- A one-line comment above the block recording *why* these four (bound hygiene is currently perfect
  and unenforced) so a future reader does not delete them as cargo-cult.

**Explicitly deferred** (do *not* build these here)

- The inline-bound signatures stay inline. `fn serialize<S: Serializer>` /
  `fn deserialize<D: Deserializer<'de>>` (`lsn.rs:105/112`, `sink_meta.rs:92/99`,
  `type_descriptor.rs:34/40`), `fn struct_field<'a, T: ArrayBuilder>` (`batch.rs:568`),
  `fn write_parquet<W: std::io::Write + Send>` (`parquet.rs:24`) and
  `fn extract<T>(…, impl FnMut(&T) -> bool)` (`reload_signal.rs:222`) are single-bound and
  idiomatic — **do not churn them into `where` clauses.** The rule asks for `where` when bounds are
  *complex*, and none of these are.
- `impl<'r> Decode<'r, Postgres>` (`ids.rs:61`, `lsn.rs:149`), `impl<'de> Deserialize<'de>`
  (`lsn.rs:110`, `sink_meta.rs:98`, `type_descriptor.rs:39`), `impl<'a> SourcePreflight<'a>`
  (`preflight.rs:129`) and `impl<'a> Reader<'a>` (`pgoutput/reader.rs:15`) all use their lifetime
  more than once and are **not** elidable. Do not "simplify" them.
- No new generic code, no new trait, no bound added or removed anywhere. This PR only deletes two
  lifetime names and adds four lines of policy.
- `clippy::pedantic` / `clippy::nursery` are **not** enabled wholesale. CONTEXT records 51 distinct
  pedantic/nursery lints firing at 1192 sites across the tree; turning the groups on is a different
  (much larger) ticket. Pick these four by name.

```rust
// crates/common/src/ids.rs:52 — `'q` was named once and used once
mod sqlx_support {
    use super::ManifestId;
    use sqlx::postgres::{PgArgumentBuffer, PgTypeInfo, PgValueRef};
    use sqlx::{Decode, Encode, Postgres, Type};

    impl Encode<'_, Postgres> for ManifestId {
        fn encode_by_ref(
            &self,
            buf: &mut PgArgumentBuffer,
        ) -> Result<sqlx::encode::IsNull, sqlx::error::BoxDynError> {
            <i64 as Encode<Postgres>>::encode_by_ref(&self.0, buf)
        }
    }

    // UNCHANGED: `'r` appears twice (the trait and `PgValueRef<'r>`), so it must stay named.
    impl<'r> Decode<'r, Postgres> for ManifestId {
        fn decode(value: PgValueRef<'r>) -> Result<Self, sqlx::error::BoxDynError> {
            Ok(ManifestId(<i64 as Decode<Postgres>>::decode(value)?))
        }
    }
}
```

```rust
// crates/common/src/lsn.rs:138 — identical change, the pg_lsn encoder
impl Encode<'_, Postgres> for Lsn {
    fn encode_by_ref(
        &self,
        buf: &mut PgArgumentBuffer,
    ) -> Result<sqlx::encode::IsNull, sqlx::error::BoxDynError> {
        // pg_lsn's binary wire format is an 8-byte big-endian integer — identical to int8.
        <i64 as Encode<Postgres>>::encode_by_ref(&(self.as_u64() as i64), buf)
    }
}
```

## Hints & gotchas

- **Verify the sweep on the two crates this PR could not cheaply check.** The two-site count was
  measured across `common`, `control`, `pg-to-arrow` and `pg-sink`; `loader` and `tests/e2e` were
  skipped because they build bundled DuckDB (~20 min cold). Run the full
  `cargo clippy --all-targets --all-features -- -D warnings` once before you open the PR — if a
  third site appears in `loader`, fix it the same way rather than downgrading the lint.
- **`-A warnings` will not let you preview a lint.** `cargo clippy -- -A warnings -W clippy::x`
  silently reports nothing, because the `warnings` group allow beats the specific `-W`. Use
  `cargo clippy -- --cap-lints warn -W clippy::x` to see the sites without `deny(warnings)` aborting
  the build at the first crate.
- **`multiple_bound_locations` is already inside `clippy::all`**, which walrus denies — verified by
  running `clippy-driver` with no extra flags on a `fn f<T: Clone>(t: T) where T: Debug`. Listing it
  changes nothing today; it is there so the policy reads as one block. Do not claim it as a new
  enforcement in the PR body.
- `elidable_lifetime_names` is **not** the same lint as `needless_lifetimes` — it targets the
  *name*, not the parameter. `impl Encode<'_, Postgres>` still has the lifetime; it just stops
  naming it. If clippy suggests removing the lifetime entirely, you are reading a different lint.
- Cargo's `[lints]` table needs `priority` only when a group and a member of that group disagree.
  All four entries here are `"deny"` and `all` is `"deny"`, so there is no conflict — mirror the
  existing `unwrap_used` / `expect_used` style exactly.
- `[workspace.lints]` only takes effect in a member that declares `[lints] workspace = true`. All
  six members already do; do not add it again.
- Unit tests are **sibling files** (`ids_test.rs`, `lsn_test.rs`) — this PR adds no test, because the
  lint *is* the test. Say that in the PR body so a reviewer does not ask for one.
- No `.sql` file and no `.sqlx` cache entry changes here — and they must not change, because there
  is no Docker on this machine to regenerate the offline cache.
