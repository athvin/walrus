# PR 18.8 — Replace the batcher's empty-string and `Lsn::ZERO` sentinels with `Option`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 18 — Rust type safety · **Crates touched:** `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 18.7 · **Unlocks:** PR 18.9

`TableBatcher` uses an **empty `String` as its "no batch id assigned yet" sentinel**: the field is
declared `batch_id: String` (`crates/pg-sink/src/batch.rs:75`), initialised to `String::new()`
(`:97`), tested with `if self.batch_id.is_empty()` (`:104`) and reset to `String::new()` on seal
(`:181`). Nothing in the type says an empty id is special, so the *only* thing standing between a
mis-ordered call and a Parquet file whose every row carries `"batch_id": ""` in its provenance JSON
is that one `is_empty()` check. The same 25-line struct is internally inconsistent about the
pattern, which makes the point better than any argument: `first_commit_lsn: Option<Lsn>` (`:69`)
sits **directly above** `last_commit_lsn: Lsn` (`:70`), whose "unset" value is the `Lsn::ZERO`
sentinel (`:95`, `:172`, `:179`) — and `Lsn::ZERO` is also a *legitimate* WAL position elsewhere in
the crate. After this PR the three "not yet known" fields are all `Option`, the seal path matches on
them explicitly, and a batch that somehow reached `seal()` without bounds is a `BatchError` instead
of a silently zero-bounded manifest entry.

## Why — learning objectives

- **`Option<T>` vs sentinel values** — and the fact that `Option<Lsn>` is the same size as `Lsn`
  only when a niche exists: `Lsn` wraps a plain `u64` with no niche, so `Option<Lsn>` is 16 bytes,
  not 8. Know the cost you are paying and why it is irrelevant for three fields on one struct.
- **How the sink assigns a batch id** — the id is minted when the first row opens a batch and is
  stamped onto every row's `SinkMeta` at commit, which is what lets the loader join a
  `<table>_raw` row back to its manifest entry.

**In scope**

- `batch_id: Option<String>`, initialised `None`; `push()` mints it with
  `get_or_insert_with(|| format!(…))` — the same shape `first_commit_lsn.get_or_insert(..)` already
  uses two fields up. The `is_empty()` test disappears.
- `last_commit_lsn: Option<Lsn>`, initialised `None`, set to `Some(commit_lsn)` in `on_commit()`,
  reset to `None` in `seal()`.
- `seal()` destructures all three optionals explicitly (`let (Some(id), Some(start), Some(end)) = …
  else { return Err(..) }`) after the existing `OpenTransaction` / `Empty` guards, so
  `SealedBatch.lsn_start` / `.lsn_end` can only ever be real commit LSNs.
- One new `BatchError` variant for "committed rows exist but the batch has no assigned id or
  bounds" — an internal-inconsistency error, documented as unreachable through the public API and
  proved reachable-and-handled by a sibling test that clears the private field.
- `on_commit()` takes the id once (`self.batch_id.clone().ok_or(..)?`) before the row loop rather
  than reading `self.batch_id` inside it. The existing source-shape assertion is updated from
  `meta.batch_id.clone_from(&self.batch_id);` to `meta.batch_id.clone_from(&batch_id);`; its
  byte-identity behavior stays unchanged.
- New `batch_test.rs` cases: a fresh batcher has `batch_id == None` and `last_commit_lsn == None`;
  after `seal()` all three are `None` again; and clearing `batch_id` before `seal()` yields the new
  `BatchError`, not a `SealedBatch`.

**Explicitly deferred** (do *not* build these here)

- **Conflict — `SinkMeta` is a cross-service JSON wire contract**
  (`crates/common/src/sink_meta.rs:1-12` spells this out: "the sink and loader must agree
  byte-for-byte"). Do **not** make
  `SinkMeta::batch_id` or `SinkMeta::commit_lsn` an `Option`. The rule's advice to model absence as
  `Option` stops at the serialization boundary here — an `Option<String>` would change the emitted
  JSON and break the loader's promotion of `$.commit_lsn` into a typed `<table>_raw` column.
- The five `batch_id: String::new()` placeholder constructions at `consume.rs:547`,
  `snapshot.rs:225`, `reload_export.rs:454` and `stream_txn.rs:259`/`:409` stay exactly as they are.
  They build a `SinkMeta` whose id the batcher overwrites at `on_commit`; they are wire-contract
  values, not batcher state.
- The 15 other production `Lsn::ZERO` uses (`slot.rs:75/80/105/110`, `replication.rs:103-104`,
  `consume.rs:96/543`, `snapshot.rs:221`, `reload_export.rs:450`, `epoch.rs:91`, and the loader's
  `phase_a.rs`/`apply_loop.rs`/`compaction.rs` sites) are untouched. Several are genuine "start of
  WAL" values rather than null markers, and separating those is a different judgement call.
- `SealedBatch` gains no `batch_id` field, and its `lsn_start`/`lsn_end` stay non-optional `Lsn` —
  a sealed batch by definition has bounds.

## Skeleton

```rust
// crates/pg-sink/src/batch.rs — the fields
pub struct TableBatcher {
    // …rel / triggers / clock / builder / pending / counters unchanged…
    /// Commit LSN of the batch's first / last committed txn. `None` until the first `on_commit`.
    /// Both are `Option` on purpose: `Lsn::ZERO` is a *legitimate* WAL position elsewhere in this
    /// crate (`replication.rs:103`, `slot.rs:75`), so it cannot double as "unset" here.
    first_commit_lsn: Option<Lsn>,
    last_commit_lsn: Option<Lsn>,
    opened_at: Option<Instant>,
    /// The file id shared by every row of this batch (minted when it opens; the manifest, PR 2.25,
    /// keys on it). `None` until the first row is pushed.
    batch_id: Option<String>,
}
```

```rust
// crates/pg-sink/src/batch.rs:103 — mint on first push, no is_empty() probe
pub fn push(&mut self, meta: SinkMeta, values: &[TupleValue]) {
    self.batch_id.get_or_insert_with(|| {
        format!("{}.{}-{}", meta.source_schema, meta.source_table, meta.lsn)
    });
    self.pending_bytes += estimate_row_bytes(values);
    self.pending.push((meta, values.to_vec()));
}
```

```rust
// crates/pg-sink/src/batch.rs:121 — the id is taken once, explicitly
pub fn on_commit(&mut self, commit_lsn: Lsn, commit_ts: UtcTimestamp) -> Result<(), BatchError> {
    if self.pending.is_empty() {
        return Ok(()); // a commit with no rows for this table
    }
    // Non-empty `pending` means `push` ran, which means the id was minted. Say so in the type
    // rather than trusting it: an unassigned id here would stamp every row with a dead reference.
    let batch_id = self.batch_id.clone().ok_or(BatchError::Unassigned)?;
    if self.opened_at.is_none() {
        self.opened_at = Some(self.clock.now());
    }
    self.first_commit_lsn.get_or_insert(commit_lsn);
    self.last_commit_lsn = Some(commit_lsn);
    for (mut meta, values) in std::mem::take(&mut self.pending) {
        todo!("stamp commit_lsn / commit_ts / batch_id.clone(), append_row, bump committed_rows")
    }
    self.committed_bytes += std::mem::take(&mut self.pending_bytes);
    Ok(())
}
```

```rust
// crates/pg-sink/src/batch.rs:158 — no sentinel can survive the seal
pub fn seal(&mut self) -> Result<SealedBatch, BatchError> {
    if self.has_open_txn() {
        return Err(BatchError::OpenTransaction);
    }
    if self.committed_rows == 0 {
        return Err(BatchError::Empty);
    }
    // The three "not yet known" fields must all be known by now. Previously `lsn_start` fell back
    // to `Lsn::ZERO`, which the manifest and the loader's transform window would have believed.
    let (Some(_batch_id), Some(lsn_start), Some(lsn_end)) =
        (self.batch_id.as_deref(), self.first_commit_lsn, self.last_commit_lsn)
    else {
        return Err(BatchError::Unassigned);
    };
    let builder = std::mem::replace(&mut self.builder, BatchBuilder::new(&self.rel.relation)?);
    let sealed = SealedBatch {
        record_batch: builder.finish()?,
        schema: self.rel.relation.schema.clone(),
        table: self.rel.relation.name.clone(),
        schema_version: self.rel.schema_version,
        lsn_start,
        lsn_end,
        row_count: self.committed_rows,
    };
    todo!("reset: counters to 0, first/last_commit_lsn and opened_at and batch_id to None");
    Ok(sealed)
}
```

```rust
// crates/pg-sink/src/batch.rs:233 — the new variant
#[derive(Debug, thiserror::Error)]
pub enum BatchError {
    #[error("cannot seal mid-transaction (would split a committed txn tail)")]
    OpenTransaction,
    #[error("nothing to seal (empty batch)")]
    Empty,
    /// Committed rows exist but the batch id or its commit-LSN bounds were never assigned.
    /// Unreachable through the public API (`push` mints the id, `on_commit` records the bounds);
    /// it exists so the old `""` / `Lsn::ZERO` fallbacks cannot be reintroduced by accident.
    #[error("batch has committed rows but no assigned batch id / commit-LSN bounds")]
    Unassigned,
    #[error(transparent)]
    Arrow(#[from] pg_to_arrow::Error),
}
```

```rust
// crates/pg-sink/src/batch_test.rs — sibling file, so private fields are in scope
#[test]
fn sealing_without_an_assigned_batch_id_is_an_error_not_an_empty_id() {
    let mut b = TableBatcher::new(
        cached(),
        triggers(u64::MAX, u64::MAX, Duration::from_secs(3600)),
        Arc::new(SystemClock),
    )
    .unwrap();
    assert_eq!(b.batch_id, None, "no id before the first row");
    assert_eq!(b.last_commit_lsn, None, "no upper bound before the first commit");
    b.push(meta("0/10"), &row("1"));
    b.on_commit("0/30".parse().unwrap(), UtcTimestamp::now()).unwrap();
    b.batch_id = None; // the state the old `String::new()` sentinel made representable
    assert!(matches!(b.seal(), Err(BatchError::Unassigned)));
}
```

## Hints & gotchas

- **The borrow checker will push back on `on_commit`.** `self.batch_id.as_ref()` holds an immutable
  borrow of `self` while the loop needs `&mut self.builder`. Clone the `String` once *before* the
  loop (`self.batch_id.clone().ok_or(..)?`) — the per-row `meta.batch_id = …` clone stays exactly as
  it is today. Do not try to be clever with `take()`; the id must survive until `seal()`.
- **`Option<Lsn>` is 16 bytes, not 8.** `Lsn` is `pub struct Lsn(u64)` (`crates/common/src/lsn.rs:19`)
  — every bit pattern is valid, so there is no niche for `None` to occupy. Three optional fields on
  one per-table struct is free in practice; do not let anyone talk you into `NonZeroU64`, which
  would reintroduce exactly the "zero is special" claim this PR deletes.
- `let … else` needs the `else` block to diverge. `return Err(..)` is the shape you want; the tuple
  destructure in `seal()` must bind `lsn_start`/`lsn_end` by value (`Lsn` is `Copy`) while
  `batch_id` is borrowed via `as_deref()` so the field is still assignable in the reset below.
- **Do not touch `.sql` or the `.sqlx` offline cache** — there is no Docker on this machine to
  regenerate it. Nothing in this PR reaches SQL, and it must stay that way.
- `unwrap`/`expect` are denied in production by `[workspace.lints.clippy]`; `clippy.toml` re-allows
  them under `#[cfg(test)]`, which is why the sibling test above may keep using `.unwrap()`.
- Unit tests are **sibling files**, and that is load-bearing here: `batch_test.rs` is included as
  `mod tests` inside `crate::batch`, so it can set `b.batch_id = None` to reach the defensive error
  branch. An integration test under `crates/pg-sink/tests/` could not.
- Quote both `grep -c` numbers in the PR body — they are this ticket's mechanical probe.
