# PR 18.4 — Derive Debug on every public type and deny missing_debug_implementations

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 18 — Rust type safety · **Crates touched:** `common`, `control`, `loader`, `pg-sink`,
> `pg-to-arrow` · **Est. size:** L · **Depends on:** PR 18.3 · **Unlocks:** PR 18.5

The `Display` half of this rule is already right: walrus has exactly **two** hand-written `Display`
impls — `Lsn` (`lsn.rs:89`) and `ManifestId` (`ids.rs:14`) — neither derived, neither delegating to
`{:?}`. The `Debug` half is not. **25 public production types have neither `#[derive(Debug)]` nor a
manual `impl Debug`**, and they are not obscure ones: `TableDb`, `TransformSql`, `TableBatcher`,
`ReplicationStream`, `ParquetSink`, `BatchBuilder`, `SchemaDiff`, `StreamDemux`. That means a
`tracing` field cannot print them, `assert_eq!` cannot report them, and `dbg!()` on a failing sink
path is a compile error. Nothing in `Cargo.toml` prevents the 26th. This PR closes all 25, adds
`missing_debug_implementations = "deny"` to `[workspace.lints.rust]`, and makes the gate the thing
that keeps it closed.

## Why — learning objectives

- **`#[derive(Debug)]` vs a hand-written `Debug`, `finish_non_exhaustive`, and API guideline
  C-DEBUG** — derive is the default; a hand-written
  `f.debug_struct("X").field(…).finish_non_exhaustive()` is the escape hatch when a member has no
  `Debug` of its own, and the `..` it prints is an honest signal that fields were withheld.
- **Which loader/sink handles are opaque resources that must not dump their contents into a log** —
  a `duckdb::Connection`, an `Arc<dyn ObjectStore>` or a `Vec<Box<dyn ArrayBuilder>>` holding a
  half-built Arrow batch has no useful textual form; naming the handle and eliding the payload is
  the correct `Debug`, not a bigger one.

## Read first

- [`type-display-vs-debug`](../../../.claude/skills/rust-skills/rules/type-display-vs-debug.md) —
  take the guidelines table and, above all, the two bullets *"Never derive `Display`"* and
  *"`#[derive(Debug)]` on every public type (API Guidelines C-DEBUG)"*. The "Bad" block's second
  mistake (implementing `Display` by calling `{:?}`) is the thing this PR must not accidentally
  introduce while adding `Debug` everywhere.
- `Cargo.toml:11-20` — the `[workspace.lints.rust]` / `[workspace.lints.clippy]` blocks and the
  comment explaining that they only bite once a member declares `[lints] workspace = true`. All six
  members do, including `tests/e2e` (`tests/e2e/Cargo.toml:16-17`).
- `crates/common/src/lsn.rs:96-100` — the tree's precedent for a **hand-written** `Debug`
  (`Lsn({:016X})`), and why it exists: the derived form would print the raw decimal `u64`.
- `crates/loader/src/duck.rs:31-41` — `TableDb { conn: duckdb::Connection, parquet_cols: RefCell<…>
  }`. The doc on `parquet_cols` explains what the cache holds; a `Debug` that prints the map size is
  useful, one that prints every column list is noise.
- `crates/pg-sink/src/batch.rs:22` (`pub trait Clock: Send + Sync`) and `:57-76` (`TableBatcher`) —
  `Arc<dyn Clock>` is the member with no `Debug`, and the trait must **not** gain a `Debug`
  supertrait to paper over it.
- `crates/pg-to-arrow/src/batch.rs:72-83` — `BatchBuilder { builders: Vec<Box<dyn ArrayBuilder>>,
  … }`. Same situation, plus `rows` and `meta_const`, which *are* worth printing.
- `crates/loader/src/ddl.rs:26-100` — `SchemaVersion`, `CommentTarget`, `AdditiveChange`,
  `DestructiveChange`, `SchemaDiff`. Four of the 25 live here and all four are plain data: a bare
  `#[derive(Debug)]` is the whole fix.

## Skeleton

```toml
# Cargo.toml — the gate. This is the half of the PR that keeps the other half true.

[workspace.lints.rust]
warnings = "deny"
# API guideline C-DEBUG: every public type is printable in a log, a panic message and a test
# assertion. 25 types were missing it as of PR 18.4; the deny is what stops the 26th.
missing_debug_implementations = "deny"
```

```rust
// crates/loader/src/duck.rs — a resource handle: name it, elide the payload.

/// Owns one table's `.duckdb` connection (mirror `<table>` + CDC log `<table>_raw`).
pub struct TableDb {
    conn: duckdb::Connection,
    parquet_cols: RefCell<HashMap<i64, Arc<Vec<String>>>>,
}

impl std::fmt::Debug for TableDb {
    /// The live connection has no useful textual form and the column cache can be hundreds of
    /// strings; print the handle's identity plus the one number an operator would want.
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        f.debug_struct("TableDb")
            .field("cached_schema_versions", &self.parquet_cols.borrow().len())
            .finish_non_exhaustive()
    }
}
```

```rust
// crates/pg-sink/src/batch.rs — `Arc<dyn Clock>` has no Debug and must not gain one.

impl std::fmt::Debug for TableBatcher {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        f.debug_struct("TableBatcher")
            .field("table", &self.rel.relation.table)
            .field("committed_rows", &self.committed_rows)
            .field("committed_bytes", &self.committed_bytes)
            .field("pending", &self.pending.len())
            .field("first_commit_lsn", &self.first_commit_lsn)
            .field("last_commit_lsn", &self.last_commit_lsn)
            .field("batch_id", &self.batch_id)
            // `clock: Arc<dyn Clock>` and `builder: BatchBuilder` are deliberately withheld.
            .finish_non_exhaustive()
    }
}
```

## Hints & gotchas

- **Order matters.** `TableCtx` and `OwnedTable` hold a `TableDb`; `ReloadController` and
  `ChunkExporter` hold a `ParquetSink`. Give the leaf types `Debug` first, then the containers can
  simply derive. Doing it top-down produces confusing "doesn't implement Debug" chains.
- **Derive first, hand-write only on a compiler error.** Several members you might assume are opaque
  are in fact `Debug` (`sqlx::PgPool`, `tokio::net::TcpStream`, `BytesMut`, `PathBuf`,
  `std::process::Child`). Let `cargo build` tell you; do not pre-emptively hand-write 25 impls.
- The members known to have **no** `Debug` are `Arc<dyn Clock>` (`batch.rs:22` — hits `TableBatcher`,
  `BatchRouter`, `StreamDemux`, `Backfill`) and `Box<dyn ArrayBuilder>` (`BatchBuilder`). Check
  `duckdb::Connection` and `tokio_postgres::Client` by compiling rather than by guessing.
- `finish_non_exhaustive()` prints a trailing `..` — that is the *point*. Use it whenever you skip a
  field, and never use plain `finish()` on a struct whose fields you elided; that would lie.
- `missing_debug_implementations` is a **rustc** lint (`[workspace.lints.rust]`), not a clippy one.
  Putting it under `[workspace.lints.clippy]` silently does nothing.
- The lint fires on public items **reachable from the crate root**. `loader` and `pg-sink` are
  lib + bin; their `pub` items in `lib.rs`'s module tree are all in scope. If a type is genuinely
  crate-internal, the right fix is `pub(crate)`, not an `#[allow]` — but do that only where it is
  obviously correct, and never as a way to dodge the lint.
- `tests/e2e` also declares `[lints] workspace = true`, so `Harness` (`tests/e2e/src/lib.rs:26`) is
  in scope even though it is not under `crates/`. `cargo clippy --all-targets` covers it.
- Do **not** implement `Display` by forwarding to `Debug` anywhere — the rule's own "Bad" block calls
  that out, and a reviewer will reject it.
- `unwrap()`/`expect()` are `deny` in production; `clippy.toml` re-allows them under `#[cfg(test)]`,
  so the new sibling test cases may use `.unwrap()`.
- Tests are **Go-style sibling files**: append to the existing `duck_test.rs` / `batch_test.rs`,
  wired by the `#[cfg(test)] #[path = "…_test.rs"] mod tests;` line at the bottom of each module.
  Never add an inline `mod tests {}`.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it, and nothing here needs it.
