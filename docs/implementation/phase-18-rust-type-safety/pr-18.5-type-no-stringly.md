# PR 18.5 — Replace the four stringly-typed FromStr error types in control

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** control

> **Phase:** 18 — Rust type safety · **Crates touched:** `control` · **Est. size:** M ·
> **Depends on:** PR 18.4 · **Unlocks:** PR 18.6

walrus already models its persisted control-table text columns as enums — `ManifestKind`,
`ManifestStatus`, `ReloadFlavor`, `ReloadStatus`, each with an `as_str`/`FromStr` pair — so the
**success** path is fully typed. The **failure** path is not: all four impls declare
`type Err = String` (`manifest.rs:43`, `manifest.rs:76`, `reload.rs:44`, `reload.rs:81`) and build it
with `format!("unknown manifest kind: {other}")`. A caller who wants to know *what* was rejected, or
*which* enum rejected it, can only re-parse an English sentence — and `claim_ready` immediately
folds that sentence into `ControlError::Decode(String)` (`manifest.rs:193`, `:198`), so the offending
byte sequence is gone forever. This PR replaces all four with one `thiserror` struct that carries the
input and the expected vocabulary **as data**, and leaves the four enums' happy paths untouched.

## Why — learning objectives

- **`FromStr`'s associated error type, and a `thiserror` struct that carries the offending input** —
  `type Err` is a real part of the API surface; making it a `String` throws away everything the
  parser knew at the moment it said no.
- **How walrus persists control-plane enums as text columns and parses them back at the DB
  boundary** — `kind`/`status`/`flavor` are `text` with SQL `CHECK` constraints; the enum is the
  second line of defence, and a rejection there means a data-integrity bug, which is why it maps to
  the *terminal* `ControlError::Decode`.

- [`type-no-stringly`](../../../.claude/skills/rust-skills/rules/type-no-stringly.md) — the section
  that matters here is **"Parsing at Boundaries"**: note `type Err = ParseError;` and
  `Err(ParseError::UnknownPriority(s.to_string()))` — the rejected input is a *field*, not a
  sentence. The "Bad" block (a `&str` parameter matched with a `panic!` default) is already absent
  from walrus; do not go looking for it.
- `crates/control/src/manifest.rs:30-54` — `ManifestKind::as_str` and its `FromStr`. This is the
  shape all four share; `:51` is the `format!` this PR deletes.
- `crates/control/src/manifest.rs:56-85` — `ManifestStatus`, the same pattern with two variants.
- `crates/control/src/reload.rs:33-53` and `:67-93` — `ReloadFlavor` and `ReloadStatus`. Note both
  also derive `sqlx::Type` with `#[sqlx(rename_all = …)]`, which is a **separate** decoding path;
  this PR must not disturb it.
- `crates/control/src/manifest.rs:186-203` — `claim_ready`'s row mapping, the only production caller:
  `r.kind.parse().map_err(ControlError::Decode)?`. That `map_err` is the line that has to change.
- `crates/control/src/db.rs:36-41` — `ControlError::Decode(String)` and the doc explaining why it is
  terminal. Read the whole enum: this is the taxonomy the new type plugs into, not replaces.
- `crates/control/src/manifest_test.rs:8-43` and `crates/control/src/reload_test.rs:4-29` — the
  existing round-trip cases. They use `assert_eq!(s.parse::<ManifestKind>(), Ok(k))`, which requires
  the new `Err` type to be `PartialEq + Debug`.
- `crates/common/src/lsn.rs:36-42` — `LsnParseError { input: String, reason: &'static str }`, the
  in-tree precedent for exactly this shape. Copy its structure and its `#[error("…")]` style.

**In scope**

- A new `crates/control/src/parse.rs` defining one shared error:

  ```rust
  #[derive(Debug, Clone, PartialEq, Eq, thiserror::Error)]
  #[error("invalid {expected}: {input:?}")]
  pub struct ParseEnumError {
      /// The enum that rejected the value, e.g. `"manifest kind"`.
      pub expected: &'static str,
      /// The exact text read out of the control table.
      pub input: String,
  }
  ```

- Re-export it from `crates/control/src/lib.rs` alongside the other flat type exports.
- Point all four `FromStr` impls at it: `type Err = ParseEnumError;` and
  `other => Err(ParseEnumError::new("manifest kind", other))`.
- Update the one production call site (`manifest.rs:193`, `:198`) to
  `.map_err(|e| ControlError::Decode(e.to_string()))?` so the settled `Decode(String)` taxonomy
  stays intact while the message comes from the typed error's unambiguous `Display` form.
- New sibling cases in `crates/control/src/manifest_test.rs` asserting the rejected input survives
  **as a field** — `err.input == "snapshottt"`, `err.expected == "manifest kind"` — not merely
  inside the `Display` string. Plus a `parse_test.rs` for the `Display` rendering.
- Extend `reload_test.rs`'s two negative cases (`"superseded"`, `"rebuild"`) the same way.

**Explicitly deferred** (do *not* build these here)

- The 26 remaining string-literal match arms in production are legitimate **wire decoders** — the
  pgoutput replica-identity bytes in `crates/common/src/pg_shape.rs` and the interval-unit vocabulary
  in `crates/pg-to-arrow/src/tier2.rs`. They already parse *into* enums and are untouched.
- No new `ControlError` variant. `Decode(String)` stays exactly as it is (`db.rs:39-40`), including
  its place in the `is_terminal` match.
- No change to `ReloadFlavor`/`ReloadStatus`'s `sqlx::Type` derives or their `#[sqlx(rename_all)]`
  attributes — that decoding path is independent of `FromStr` and out of scope.
- No `#[from]` conversion from `ParseEnumError` into `ControlError`. An explicit closure at the two
  call sites preserves the existing `Decode(String)` boundary and avoids widening the error
  taxonomy.

**Conflict to resolve explicitly** — the walrus error taxonomy is **settled**: `common::Error` with
`is_terminal()`/`is_transient()`/`exit_code()` and an exhaustive no-`_`-arm match, plus
`loader::ConfigError(pub String)` (`crates/loader/src/config.rs:114-116`). This ticket must **not**
retype `Error::Config(String)`, must **not** retype `ConfigError`, and must **not** turn
`ControlError::Decode(String)` into a structured variant. **Only the four `FromStr::Err` associated
types change.** If the implementer finds themselves editing `crates/common/src/error.rs`, they have
left the scope of this PR.

## Hints & gotchas

- **`PartialEq` on the error is load-bearing.** `manifest_test.rs:16` writes
  `assert_eq!(s.parse::<ManifestKind>(), Ok(k))`; `Result<T, E>: PartialEq` needs `E: PartialEq`, and
  `assert_eq!` needs `E: Debug`. Derive both or the existing tests stop compiling.
- Use `{input:?}` (not `{input}`) in the `#[error("…")]` attribute. An empty string, a trailing
  space, or an embedded newline read out of a text column is invisible otherwise — and those are
  exactly the values that reach this path.
- `expected: &'static str` beats an enum-of-enums here: the four call sites each pass one literal,
  and a `&'static str` keeps `ParseEnumError` `Clone` and cheap. Do not over-model it.
- Three **integration** tests parse `ManifestKind` too — `crates/loader/tests/reload_rebuild.rs:116`,
  `snapshot_boundary.rs:110`, `reload_resync.rs:101` — all with `.unwrap()`. They keep compiling
  because the new `Err` derives `Debug`; check them before you push.
- `ReloadFlavor`/`ReloadStatus` decode from Postgres through `sqlx::Type`, **not** through `FromStr`
  (`reload.rs:26-27`, `:57-58`). Their `FromStr` is used only by tests today, which is precisely why
  this change is safe — but it also means you must not "simplify" by deleting them.
- `thiserror` is already a `control` dependency (`crates/control/Cargo.toml`). No `cargo deny` run is
  needed because no new dependency is introduced.
- `ControlError::Decode(String)` is deliberately left stringly. Widening it is a separate decision
  about the error taxonomy that Phase 10 owns; doing it here would blow this PR's review budget and
  collide with the settled `common::Error` contract.
- `unwrap()`/`expect()` are `deny` in production; `clippy.toml` re-allows them under `#[cfg(test)]`,
  so `unwrap_err()` in the sibling tests is fine.
- Tests are **Go-style sibling files**: `parse.rs` needs its own
  `#[cfg(test)] #[path = "parse_test.rs"] mod tests;` at the bottom, and `parse_test.rs` starts with
  `use super::*;`. Never add an inline `mod tests {}`.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. The four enums' `as_str()` writers are unchanged, so the persisted text
  is unchanged too.
