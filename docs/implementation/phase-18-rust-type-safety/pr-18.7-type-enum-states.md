# PR 18.7 — Model the loader health lifecycle as one enum instead of two independent bools

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** loader,pg-sink

> **Phase:** 18 — Rust type safety · **Crates touched:** `loader`, `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 18.6 · **Unlocks:** PR 18.8

`LoaderState` encodes a three-state lifecycle in **two independent `AtomicBool`s** — `ready`
(`crates/loader/src/health.rs:22`) and `quarantined` (`:26`). Two bools are four representable
combinations, and one of them — `!ready && quarantined` — means nothing at all, yet
`crates/loader/tests/reload_rebuild.rs:484` actually constructs it. The invariant that ties the two
together is not in the type; it is spelled out by hand in `is_ready()` (`health.rs:48`,
`self.ready.load(..) && !self.is_quarantined()`), and every future reader has to re-derive it.
pg-sink's side is half-done in the other direction: `Phase` **is** an enum (`pg-sink/src/health.rs:27`)
but it is stored as a raw `AtomicU8` behind hand-maintained `PHASE_BOOTSTRAPPING` / `PHASE_READY`
consts (`:22-23`) and decoded with a lossy `_ => Phase::Bootstrapping` wildcard (`:77`) — a
mis-stored byte silently reads back as "still bootstrapping". After this PR both crates hold exactly
one enum in exactly one atomic, the decode is exhaustive, and the invalid combination is
unrepresentable rather than merely untested.

## Why — learning objectives

- **Making invalid states unrepresentable** — one enum in one atomic, with the `u8` round-trip
  confined to a private wrapper whose only writer takes an enum.
- **The loader quarantine latch** — why `/startup` must stay satisfied after a quarantine while
  `/ready` degrades, and why the latch has exactly one exit (the PR 6.7 reload rebuild).

**In scope**

- `loader`: a `#[repr(u8)] pub enum LoaderPhase { Bootstrapping = 0, Ready = 1, Quarantined = 2 }`
  with an exhaustive `TryFrom<u8>`, stored in one private `AtomicPhase(AtomicU8)` field on
  `LoaderState`. Both `AtomicBool` fields go away.
- `is_started()`, `is_ready()` and `is_quarantined()` become exhaustive `matches!` over the loaded
  phase — the hand-spelled `ready && !quarantined` conjunction disappears.
- The three mutators become transitions: `mark_ready()` → `Ready`; `quarantine()` → `Quarantined`
  (from any phase — a quarantine implies bootstrap finished, which is exactly why `/startup` stays
  satisfied); `clear_quarantine()` is a `Quarantined → Ready` compare-and-swap that is a **no-op**
  from any other phase.
- `pg-sink`: delete `PHASE_BOOTSTRAPPING` / `PHASE_READY`, put `#[repr(u8)]` + explicit
  discriminants on the existing `Phase`, add the exhaustive `TryFrom<u8>`, and store it through the
  same private `AtomicPhase` wrapper. `phase()` keeps its `-> Phase` signature and loses its
  wildcard arm.
- Sibling-file tests in both crates: a `TryFrom` round-trip for every variant, and an out-of-range
  byte (`7`) that is an `Err`, not a silently-`Bootstrapping` `Ok`.

**Explicitly deferred** (do *not* build these here)

- **The `/ready` JSON body shape is an operational contract and does not change.**
  `ReadyBody { ready, degraded }` (`crates/pg-sink/src/health.rs:104-108`) keeps its two booleans;
  only the *internal* state representation is enum-shaped. Same for every probe's status code.
- **Conflict — do NOT fold pg-sink's other three `AtomicBool`s into the phase enum.** `terminating`,
  `degraded` and `live` (`crates/pg-sink/src/health.rs:37-39`) are genuinely orthogonal axes, not
  lifecycle states: `health.rs:1-10` documents that liveness must stay independent of readiness and
  lag, and that `degraded` is *reported, not gating*. Collapsing them into one enum would multiply
  the variants and recreate the exact self-healing hazard that module doc warns about. The rule says
  "enums for **mutually exclusive** states" — these are not mutually exclusive, so they stay bools.
- No shared `common::AtomicPhase` extraction. The two enums have different state sets (three vs two)
  and different transition rules; a shared wrapper would be generality with one and a half users.
- `last_poll_completed_at: Mutex<Option<Instant>>` (`loader/src/health.rs:28`) is untouched — it is
  a progress timestamp, not a lifecycle state, and it is already an `Option`.
- No public-API change: `LoaderState` / `HealthState` keep every existing method name and signature,
  so `phase_a.rs`, `main.rs`, `apply_loop.rs` and the loader integration tests need **no** edits.

// crates/loader/src/health.rs
use std::sync::atomic::{AtomicU8, Ordering};

/// The loader's health lifecycle — exactly one of three states.
///
/// `Quarantined` **implies bootstrap finished**: its only producer is a failed lossy DDL cast in
/// the apply loop (`phase_a.rs:179`), which cannot run before `mark_ready()`. That implication is
/// why `/startup` stays satisfied while `/ready` degrades — previously an invariant spelled out by
/// hand in `is_ready()`, now a property of the type.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
#[repr(u8)]
pub enum LoaderPhase {
    #[default]
    Bootstrapping = 0,
    Ready = 1,
    /// Latched by a failed lossy DDL cast (PR 3.9). Exactly one exit: a single-table-reload
    /// rebuild (PR 6.7) replaces the data, so the failed cast no longer applies.
    Quarantined = 2,
}

    /// `/startup` gate — satisfied by `Ready` **and** by `Quarantined` (bootstrap did complete).
    pub fn is_started(&self) -> bool {
        matches!(
            self.phase.load(),
            LoaderPhase::Ready | LoaderPhase::Quarantined
        )
    }

    /// `/ready` — the conjunction is gone; readiness is now a single variant.
    pub fn is_ready(&self) -> bool {
        matches!(self.phase.load(), LoaderPhase::Ready)

    pub fn is_quarantined(&self) -> bool {

## Hints & gotchas

- **`crates/loader/tests/reload_rebuild.rs:484` calls `quarantine()` on a state that was never
  marked ready**, then asserts `!is_ready() || !is_started()` at `:485` and `!is_quarantined()` at
  `:499` after the rebuild. Under the enum, `quarantine()` from `Bootstrapping` lands on
  `Quarantined` (so `is_started()` becomes `true` where it used to be `false`) — the `||` assertion
  still passes because `is_ready()` is false. Re-read that test before you change the transition
  rules; it is the one place the old impossible state was reachable.
- **`clear_quarantine()` must not be a plain `store(Ready)`.** `phase_a.rs:285` calls it in the
  reload-rebuild path; a bare store would promote a loader that had *not* finished bootstrap to
  `Ready` and put a half-open pod into rotation. Use `compare_exchange`.
- `#[derive(Default)]` on `LoaderState` still works if `AtomicPhase` derives `Default` (`AtomicU8`
  is `Default` at 0) **and** `LoaderPhase::Bootstrapping` carries `#[default]` — keep the
  discriminant of the default variant at `0` so the two agree. `LoaderState::new()` is unchanged.
- `Ordering::SeqCst` everywhere, exactly as today. This is a probe path read a few times a second;
  do not "optimise" it to `Relaxed` in the same PR — that is an unrelated memory-model argument.
- **`unwrap()`/`expect()` are denied in production** (`[workspace.lints.clippy]`). `AtomicPhase::load`
  must use `unwrap_or_else` with a logging closure, not `unwrap`. Log at `error!` with the offending
  byte as a structured field, per the `tracing` convention — never `println!`.
- `#[repr(u8)]` on a fieldless enum lets you write `phase as u8`. That cast is the one place in this
  PR where `as` is correct; keep it inside `AtomicPhase` so no caller ever sees a raw byte.
- Unit tests are **sibling files** (`health_test.rs`, wired by `#[cfg(test)] #[path = …] mod tests;`
  at the bottom of each `health.rs`) — add cases there, do not create an inline `mod tests {}`.
- `cargo test -p loader` builds bundled DuckDB (~20 min cold, ~3 min cached), and several loader
  integration tests need `docker compose up --wait` for control-pg. The unit tests you are adding
  need neither — run `cargo test -p loader --lib health` first for a fast loop.
- No `.sql` file and no `.sqlx` cache entry changes here.
