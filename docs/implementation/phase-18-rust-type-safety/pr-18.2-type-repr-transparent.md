# PR 18.2 — Make the transparent newtypes actually repr(transparent) and assert their layout

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 18 — Rust type safety · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 18.1 · **Unlocks:** PR 18.3

There is **zero** `#[repr(transparent)]` anywhere in `crates/` or `tests/` — the only `repr` in the
whole tree is `#[repr(i32)]` on `ExitCode` (`crates/common/src/error.rs:109`). Yet
`crates/common/src/ids.rs:34` documents `ManifestId`'s Postgres support as "the transparent-newtype
trick", and both `Lsn` (`lsn.rs:19`) and `ManifestId` (`ids.rs:12`) hand-forward `Encode`/`Decode`
straight to their inner primitive on a layout assumption nothing in the source actually states. This
PR turns that unstated assumption into a compiler-checked one: six newtypes gain
`#[repr(transparent)]` plus a `const _: () = assert!(…)` that fails **at compile time** if anyone
ever adds a second field. It is a small PR whose entire value is that the next person cannot quietly
break the sqlx delegation.

## Why — learning objectives

- **`#[repr(transparent)]` layout guarantees and const-assert compile-time checks** — the attribute
  promises identical size, alignment and ABI to the single non-ZST field; `const _: () =
  assert!(size_of::<T>() == size_of::<Inner>())` turns "I believe this" into "the build fails
  otherwise".
- **Why the sink and loader can bind an `Lsn` straight into a Postgres `pg_lsn`/`int8` column** —
  `lsn.rs:138-154` reuses `i64`'s encoder verbatim because a `pg_lsn` wire value *is* an 8-byte
  big-endian integer. That shortcut is only sound while `Lsn` is a one-field wrapper.

## Read first

- [`type-repr-transparent`](../../../.claude/skills/rust-skills/rules/type-repr-transparent.md) —
  take the "What repr(transparent) Guarantees" block (`size_of` / `align_of` / ABI) and the
  when-to-use table row **"Pure Rust newtypes: optional (doesn't hurt)"**. Ignore the FFI examples:
  walrus has no `extern "C"` and no raw pointers, so this ticket is a layout *guarantee*, not a wire
  change.
- `crates/common/src/lsn.rs:13-34` — `pub struct Lsn(u64)` and its `ZERO`/`new`/`as_u64` accessors.
- `crates/common/src/lsn.rs:118-155` — the `sqlx_support` module. Read `encode_by_ref` at `:138-147`:
  it encodes `&(self.as_u64() as i64)` through `i64`'s encoder. That is the delegation the layout
  guarantee protects.
- `crates/common/src/ids.rs:11-12` and `:32-36` — `ManifestId(pub i64)` and the doc comment that
  already *calls* it "the transparent-newtype trick" without the attribute backing it up.
- `crates/common/src/sink_meta.rs:41-47` — `UtcTimestamp(jiff::Timestamp)`. Note the inner type is
  **not** a primitive; the assertion compares against `size_of::<jiff::Timestamp>()`, so it stays
  correct even if a `jiff` bump changes that size.
- `crates/common/src/error.rs:105-120` — `#[repr(i32)] pub enum ExitCode`, the tree's only existing
  `repr`, and the doc comment style used to explain *why* a repr is load-bearing. Match that tone.
- PR 18.1's `EpochNo` / `SchemaVersionNo` / `ReloadId` in `crates/common/src/ids.rs` — this PR
  covers them too, which is why it lands second.

## Scope

**In scope**

- Add `#[repr(transparent)]` to exactly six types, all in `common`:
  `Lsn` (`lsn.rs:19`), `ManifestId` (`ids.rs:12`), `UtcTimestamp` (`sink_meta.rs:47`), and the three
  PR-18.1 ids `EpochNo`, `SchemaVersionNo`, `ReloadId`.
- Under each, a compile-time layout assertion: `const _: () = assert!(size_of::<T>() ==
  size_of::<Inner>() && align_of::<T>() == align_of::<Inner>());`
- A short doc line per attribute saying *what it buys here* — for `Lsn`/`ManifestId` it is the sqlx
  `Encode`/`Decode` delegation; for `UtcTimestamp` it is that the wrapper costs nothing over
  `jiff::Timestamp`.
- Update `ids.rs:32-36`'s doc so "the transparent-newtype trick" now points at the attribute.
- One sibling test per module (`lsn_test.rs`, `ids_test.rs`, `sink_meta_test.rs`) asserting the same
  sizes at runtime, so a reader who greps the tests sees the invariant spelled out.

**Explicitly deferred** (do *not* build these here)

- walrus has **no `extern "C"` and no FFI**, so nothing about the wire format, the Parquet layout or
  the Postgres protocol changes. This is a layout/ABI guarantee plus a compile-time size assertion,
  full stop. Do not introduce an `ffi` module to "justify" it.
- `loader::config::ConfigError(pub String)` (`crates/loader/src/config.rs:116`) is a **message
  wrapper**, not a value newtype — it exists to name an error, not to stand in for a `String` at a
  boundary. Deliberately left alone.
- No `NonZero*` conversions (that belongs to `num-nonzero`, Phase 17) and no `PhantomData`
  (PR 18.11).
- No new `Deref`, `AsRef` or `Borrow` impls — PR 18.12 specifically guards against them.

## Skeleton

```rust
// crates/common/src/lsn.rs

/// A Postgres Log Sequence Number as a single `u64`.
///
/// Canonical text form is **uppercase, zero-padded 16-hex** ([`Display`](fmt::Display)), chosen so
/// lexical order equals numeric order. `Ord` derives from the inner `u64`, so it *is* numeric
/// order.
///
/// `#[repr(transparent)]`: the `sqlx` support below encodes an `Lsn` through `i64`'s encoder
/// verbatim (a `pg_lsn` wire value *is* an 8-byte big-endian integer). That delegation is only
/// sound while this type is exactly one `u64` wide, which the assertion under this item enforces.
#[repr(transparent)]
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct Lsn(u64);

// Fails the BUILD, not a test, if a second field is ever added to `Lsn`.
const _: () = assert!(
    size_of::<Lsn>() == size_of::<u64>() && align_of::<Lsn>() == align_of::<u64>(),
    "Lsn must stay layout-identical to u64 — sqlx Encode/Decode delegate to i64"
);
```

// crates/common/src/sink_meta.rs

/// A UTC instant rendered as RFC-3339 with a `Z` suffix — walrus's only legal datetime form.
///
/// `#[repr(transparent)]`: the wrapper exists purely to forbid a non-UTC datetime at the type
/// level, so it must cost exactly nothing over the inner [`jiff::Timestamp`].
#[repr(transparent)]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]

// Compare against the INNER type, never a hard-coded 16 — a `jiff` bump must not break the build
// for a reason that has nothing to do with walrus.
const _: () = assert!(
    size_of::<UtcTimestamp>() == size_of::<jiff::Timestamp>()
        && align_of::<UtcTimestamp>() == align_of::<jiff::Timestamp>()
);

## Hints & gotchas

- `size_of` and `align_of` have been in the **prelude** since Rust 1.80; walrus's MSRV is 1.95
  (`Cargo.toml:8`), so no `use std::mem::…` import is needed and adding one is dead weight.
- `assert!` is usable in a `const` item since Rust 1.57 — `const _: () = assert!(…)` is the
  idiomatic static assertion and needs **no** new dependency. Do **not** add `static_assertions`; a
  new dep would have to clear `cargo deny`'s advisories + 8-license allow-list for a one-line macro.
- `#[repr(transparent)]` rejects a struct with more than one non-zero-sized field (E0690). That is
  the *first* half of the guard; the const assert is the second, and catches the subtler case where
  someone adds a zero-sized marker and then changes it.
- Attribute order matters for readability, not semantics: put `#[repr(transparent)]` **above**
  `#[derive(…)]` so the layout promise is the first thing a reader sees. `rustfmt` will not reorder
  them.
- `Lsn`'s field is private (`Lsn(u64)`), `ManifestId`'s is public (`ManifestId(pub i64)`).
  `repr(transparent)` is orthogonal to visibility — do not "harmonise" them here.
- `UtcTimestamp` wraps a foreign type. `#[repr(transparent)]` on it promises *this* wrapper is free;
  it promises nothing about `jiff::Timestamp`'s own internals, and the doc comment should say so.
- Do not claim a niche optimisation in the comments: `u64` and `i64` have no niche, so
  `size_of::<Option<Lsn>>()` is **16**, not 8. Asserting otherwise will fail.
- `clippy::all` + `warnings` are already `deny` workspace-wide and `common` declares
  `[lints] workspace = true`. `clippy::assertions_on_constants` is a `restriction`-adjacent lint that
  fires on `assert!(true)` — a real comparison like this one does not trip it.
- Tests are **Go-style sibling files**: append to `lsn_test.rs` / `ids_test.rs` /
  `sink_meta_test.rs`, wired by the `#[cfg(test)] #[path = "…_test.rs"] mod tests;` line at the
  bottom of each module. Never add an inline `mod tests {}`.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it, and nothing here needs it.
