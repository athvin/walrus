# PR 18.9 — Stop swallowing errors into `Option` and deny `let_underscore_must_use`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** loader,pg-sink,pg-to-arrow

> **Phase:** 18 — Rust type safety · **Crates touched:** `loader`, `pg-to-arrow`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 18.8 · **Unlocks:** PR 18.10

Production has **27 `.ok()` calls** that flatten a `Result` into an `Option`, and two of them throw
away errors that decide whether the mirror is correct. `TransformSql::latest_truncate` collapses
*every* DuckDB failure into "there is no truncate" (`crates/loader/src/transform.rs:156-158`,
`.query_row(..).ok()` with the comment `// no rows → no truncate`): a missing column after a DDL
apply, a locked file, a corrupt page — all read back as `TruncateBoundary::none()`, and the MERGE
then runs against the wrong wipe boundary instead of failing loudly. `first_field_type` drops an
`emit_fields` error the same way (`crates/pg-to-arrow/src/descriptor.rs:144-148`), and its caller
falls back to typing the DuckDB column `VARCHAR` (`descriptor.rs:140`) — a wrong descriptor written
into `schema_registry` rather than a refusal. Separately, 16 production `let _ =` discards exist
with **no lint** forcing the decision to be explicit: five hide operational failures and eleven are
intentional formatting/type-state results. This PR converts the two real swallows, keeps the 25
legitimate `Option`-returning parsers, logs the five operational failures, names the eleven
intentional discards, and adds the gate so the next discard has to be argued for.

## Why — learning objectives

- **`Result` vs `Option` for fallible operations** — and how to tell a driver's "not found" apart
  from a real failure: `duckdb::OptionalExt::optional()` maps only
  `duckdb::Error::QueryReturnedNoRows` to `Ok(None)` and propagates everything else.
- **Why the loader's truncate boundary must never be silently absent** — the `(Ct, Lt)` tuple is
  what stops the transform from replaying rows the source already wiped.

**In scope**

- `latest_truncate`: `use duckdb::OptionalExt;` and replace `.ok()` with
  `.optional().duck_with(|| format!(..))?`, using the existing `DuckResultExt` helper so "no rows"
  stays `TruncateBoundary::none()` and any other DuckDB error preserves its typed source in the
  structured `LoaderError::Duck { op, source }` variant.
- `pg-to-arrow::descriptor`: `first_field_type -> Result<Option<DataType>, Error>`; `arrow_of`,
  `duckdb_of`, `emit_of`, `describe_column_with_labels`, `describe_column` and `describe_relation`
  all become fallible and propagate with `?`. `emit_of`'s `unwrap_or_default()` goes with them — it
  is the same swallow wearing a different combinator.
- `pg-sink::relcache::build_cached` maps the new error into the existing
  `RelationError::Schema { schema, table, source }` variant, exactly as `build_arrow` does.
- `let_underscore_must_use = "deny"` in `[workspace.lints.clippy]`, and all 16 production discards
  made explicit:
  - `crates/loader/src/phase_b.rs:84` and `crates/loader/src/compaction.rs:41` — the
    `execute_batch("ROLLBACK;")` on the error path logs at `warn!` if the rollback itself fails, and
    still returns the *original* error.
  - `crates/pg-sink/src/stream_txn.rs:316`, `:342`, `:383` — a failed speculative-file delete leaves
    an orphaned S3 object; log it at `warn!` with the key so it is greppable, then continue
    (best-effort deletion is the correct behaviour, silent deletion is not).
  - The eleven intentional non-operational discards in `loader/src/{health,ddl,duck}.rs` and
    `pg-sink/src/reload_export.rs` become descriptively named underscore-prefixed bindings. They
    remain deliberate no-ops (CAS miss, infallible `String` formatting, or compile-time type proof)
    without using the wildcard discard pattern the lint denies.
- Test-target carve-out: extend the existing `#![allow(clippy::unwrap_used, clippy::expect_used)]`
  header in the integration-test files that use `let _ =` with `clippy::let_underscore_must_use`,

  intentionally discard cleanup results"))]` to the crate roots whose sibling `*_test.rs` modules
  use it. The reason is required by the workspace's `allow_attributes_without_reason` deny.
- A `transform_test.rs` sibling case asserting a broken raw table surfaces `LoaderError::Duck`
  instead of `TruncateBoundary::none()`.

**Explicitly deferred** (do *not* build these here)

- **Conflict — `PendingSignal::from_tuple` returning `Option` is deliberate and documented.**
  `crates/pg-sink/src/reload_signal.rs:118-122` states it outright: "A malformed tuple returns
  `None` — the caller logs and drops it; it can never wedge the loop." Leave its three
  `.parse().ok()?` calls (`:135`, `:136`, `:137`) exactly as they are, and cite that comment in the
  PR body. A poison-pill signal row must not be able to stall the replication loop, which is
  precisely the case where `Option` beats `Result`.
- The remaining `.ok()` calls are genuine `Option`-returning parsers/conversions and are **not** converted:
  `crates/common/src/lsn.rs:50` and `:63` (`u32::from_str_radix` / `u64::from_str_radix` inside

  interval field scanner), `crates/pg-to-arrow/src/batch.rs:842` (`rfc3339_micros -> Option<i64>`),
  `crates/pg-sink/src/heartbeat.rs:111` and `crates/pg-sink/src/epoch.rs:90`. The current tree also

  `pg-sink/src/pgoutput/typmod.rs` (three), `pg-sink/src/replication.rs` (two),
  `pg-to-arrow/src/schema.rs` (three), and descriptor metadata extraction (two).
- No new error variants: `LoaderError::Duck` and `pg_to_arrow::Error` already carry everything
  needed. Do not retype `common::Error` or `loader::ConfigError`.
- No `.sql` template and no `.sqlx` cache entry changes.
- The `Tier::Two` arms of `arrow_of`/`duckdb_of` (`descriptor.rs:117`, `:127-137`) are pure `match`es
  on the type OID with no fallible call — they keep their current shape inside the new `Result`.

## Hints & gotchas

- **`clippy::let_underscore_must_use` fires in tests too, and there are ~128 `let _ =` sites across
  the test targets** (`let _ = std::fs::remove_dir_all(&dir);` is the common one — `io::Result` is
  `#[must_use]`). `[workspace.lints]` applies to *every* target of a member crate, so plan for it:
  extend the `#![allow(clippy::unwrap_used, clippy::expect_used)]` line that already sits at line 1
  of ~32 integration-test files, and add
  `#![cfg_attr(test, allow(clippy::let_underscore_must_use, reason = "unit tests intentionally
  discard cleanup results"))]` at the crate roots for the sibling `*_test.rs` modules. There is
  **no** `clippy.toml` knob for this lint — `allow-unwrap-in-tests`
  has no equivalent. Verify with `cargo clippy --all-targets`, not plain `cargo clippy`.
- **`optional()` is an extension trait**: `use duckdb::OptionalExt;` must be in scope or
  `.optional()` will not resolve. It maps *only* `Error::QueryReturnedNoRows`; every other
  `duckdb::Error` propagates — which is exactly the distinction this PR is buying.
- Making `describe_relation` fallible ripples into six test files
  (`crates/pg-sink/tests/reload_{recovery,export,metrics,ddl,pickup}.rs` and
  `crates/control/tests/schema_registry_descriptor.rs`) plus `relcache_test.rs` and
  `descriptor_test.rs`. Those are test targets, so `.expect("descriptors")` is fine there — the
  file-level allow already permits it.
- `build_arrow` runs before `describe_relation` in `build_cached` and already fails on any column
  whose `emit_fields` errors, so this conversion does not change runtime behaviour today. That is
  the point: the type now says what was previously only true by accident of call order.
- `stream_txn.rs:342` is inside a `for key in &doomed` loop and `:383` inside `for spill in staged`
  — both need the borrow of `key`/`spill.written.key` for the log line; take the `Path` reference
  before the `await`, not after.
- **New dependencies must clear `cargo deny`** (advisories + the 8-license allow-list + bans). This
  PR needs none — `duckdb::OptionalExt` ships with the pinned `duckdb = "=1.10504.0"`.
- `unwrap`/`expect` stay denied in production; `clippy::all` and `warnings` are already `deny`, so a
  newly-unused import or an unhandled `Result` will fail the build before clippy even speaks.
- `cargo test -p loader` builds bundled DuckDB (~20 min cold, ~3 min cached). Run
  `cargo clippy --all-targets -p pg-to-arrow -p pg-sink` first for a fast signal on the descriptor
  ripple, then the loader.
