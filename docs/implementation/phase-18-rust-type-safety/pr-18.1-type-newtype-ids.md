# PR 18.1 — Finish the residual SchemaVersionNo and ReloadId newtypes

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,control,loader,pg-sink,pg-to-arrow,e2e

> **Phase:** 18 — Rust type safety · **Crates touched:** `common`, `control`, `loader`, `pg-sink`,
> `pg-to-arrow`, `e2e` ·
> **Est. size:** L · **Depends on:** PR 17.5 · **Unlocks:** PR 18.2

PR 13.3 already introduces and migrates `EpochNo`. This residual task adds only `SchemaVersionNo` and `ReloadId`, then replaces their remaining bare-`i64` domain-ID sites without touching SQL text or the offline cache. The immediate predecessor has 46 explicitly named `schema_version: i64` / `reload_id: i64` annotations plus `Option<i64>`, `Cell<Option<i64>>`, `HashSet<i64>`, and `SchemaVersion::version` storage sites. Public model changes also require literal-construction call sites in `pg-to-arrow`, loader benches, and e2e to move with the defining crates.

## Why — learning objectives

- Prevent schema versions and reload ids from being interchanged with unrelated integers.
- Preserve transparent SQL and JSON boundary behavior while finishing the two deferred identifiers.

**In scope**

- Add `SchemaVersionNo(i64)` and `ReloadId(i64)` with the same value traits, `Display`, `From` pair, and feature-gated transparent sqlx support as the merged ids.
- Give `SchemaVersionNo` transparent serde so sink metadata remains a bare number.
- Re-export both and migrate every domain-typed production and test site in the allowlist.
- Migrate the complete current-tree caller closure of the public `SinkMeta`, `NewManifestFile`,
  `ManifestRow`, `RegistryRow`, reload-control, reload-waiter, and loader watermark APIs. This
  includes compile-only benchmark/e2e consumers even though the newtypes are defined elsewhere.
- Bind inner `i64` values and wrap decoded rows in Rust; keep all `.sql` and `.sqlx` bytes unchanged.
- Preserve `EpochNo` exactly as PR 13.3 left it.

**Explicitly deferred**

- No `EpochNo` edit, numeric counter newtype, `repr(transparent)` attribute, SQL text, or cache regeneration.
- `loader::ddl::SchemaVersion` remains the relation-shape struct; use `SchemaVersionNo` for the numeric id.
