# PR 18.1 — Finish the domain-ID newtypes: EpochNo, SchemaVersionNo, ReloadId

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 18 — Rust type safety · **Crates touched:** `common`, `control`, `loader`, `pg-sink` ·
> **Est. size:** L · **Depends on:** PR 17.5 · **Unlocks:** PR 18.2

PR 8.4a shipped `ManifestId(pub i64)` alone and said so out loud — `crates/common/src/ids.rs:5`
literally reads "`EpochNo`/`SchemaVersion`/`ReloadId` stay bare `i64` for now". This is the PR that
finishes it. **100 production sites still declare a bare `i64` domain id**: 61 `epoch: i64`, 24
`schema_version: i64`, 15 `reload_id: i64`, spread over `control` (42), `pg-sink` (41), `loader`
(13) and `common` (4). They are three *different* bigints that the control plane routinely passes
side by side in the same struct — `ManifestRow.epoch` at `manifest.rs:95` sits eight fields above
`ManifestRow.schema_version` at `:103`, and `ReloadRow.reload_id` at `reload.rs:99` sits directly
above `ReloadRow.epoch` at `:100`. Swapping any pair compiles cleanly today and silently reads the
wrong generation's state. After this merges the swap is a type error, and `ids.rs` stops apologising
for being unfinished.

## Why — learning objectives

- **The newtype pattern over primitives, with hand-written `sqlx` `Type`/`Encode`/`Decode`** —
  `common` deliberately does not enable sqlx's `macros` feature, so the DB integration is three
  small impls that delegate to `i64` (`ids.rs:37-66`), not a derive.
- **`epoch`, `schema_version` and `reload_id` are three different bigints that must never be
  swapped** — epoch namespaces *all* control state (architecture.md §1.8), `schema_version` keys
  the registry and the homogeneous-file rule, `reload_id` routes a single-table rebuild. A mix-up
  reads a live table's rows against a retired generation's watermark.

## Read first

- [`type-newtype-ids`](../../../.claude/skills/rust-skills/rules/type-newtype-ids.md) — take the
  derive set (`Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord`), the `From<i64>` /
  `From<Self> for i64` pair, and the `define_id!` macro sketch at the end. Ignore the `Display`
  suggestion of `"user:{id}"` — walrus's `ManifestId` prints the bare integer and the new ids must
  match it.
- `crates/common/src/ids.rs` (whole file, 70 lines) — this is the template. Copy `ManifestId`'s
  derives (`:11`), `Display` (`:14`), both `From` impls (`:20`, `:26`) and the `sqlx_support` module
  (`:37-66`) verbatim for each new type. Line 5 is the doc comment this PR must rewrite.
- `crates/control/src/manifest.rs:92-107` (`ManifestRow`) and `:110-123` (`NewManifestFile`) — the
  two structs that hold `epoch`, `schema_version` *and* `reload_id` at once.
- `crates/control/src/manifest.rs:265-278` — **read the comment at `:271-272`.** It records exactly
  how `ManifestId` binds: `query_file!` offline-checks the argument against the column's concrete
  `i64`, so a scalar bind passes the **inner value** (`id.0`). The new ids bind the same way.
- `crates/control/src/replication_state.rs:20-30` plus
  `crates/control/sql/postgres/queries/read_current_epoch.sql` — the `query_file_as!` trap. That SQL
  file already carries `created_lsn AS "created_lsn: Lsn"`, i.e. a newtype in a `query_file_as!`
  struct needs a **column override inside the `.sql`**. You may not edit `.sql` (see Hints).
- `crates/common/src/sink_meta.rs:110-175` — `SinkMeta.epoch` (`:123`) and `.schema_version`
  (`:127`) are part of a **cross-service JSON wire contract**, and `MetaConst` (`:154-161`) mirrors
  their types field-for-field for the amortized split serialization (PR 5.7).
- `crates/loader/src/duck.rs:287-296` and `:315-324` — the `duckdb::params![epoch]` /
  `params![reload_id]` binds; the loader stores these ids in `_walrus_meta` as a DuckDB `BIGINT`.
- `docs/architecture.md` §1.8 (epoch = one slot lifetime, namespaces all control state) and
  `docs/single-table-reload.md` (why `reload_id` is a bigserial, not a UUID).

  `Checkpoint`, `ReloadRow`, `DdlRow`), convert **that call** to `sqlx::query_file!` plus explicit

  unchanged, so the committed `.sqlx` entry stays valid.
- `crates/common/src/ids_test.rs`: round-trip cases per type mirroring the three existing
  `ManifestId` cases, plus one case proving `EpochNo` serializes as a bare JSON number.

**Explicitly deferred** (do *not* build these here)

- **No `.sql` and no `.sqlx` offline-cache edits.** The newtypes bind and decode as transparent
  `int8` exactly like `ManifestId` (`ids.rs:37-66`), so `query_file!` sees the same parameter types

- `chunk_no`, `xid`, `row_count`, `restart_count` and `beat_seq` stay bare integers. They are

- No `#[repr(transparent)]` and no layout assertions — that is PR 18.2, immediately after.
- No hex/octal formatters for the new ids — PR 18.3 deliberately restricts those to `Lsn`.

**Conflict to resolve explicitly** — `crates/loader/src/ddl.rs:27` already defines
`pub struct SchemaVersion { version: i64, relation: PgRelation }`, a *shape snapshot*, not a number.
Name the numeric newtype **`SchemaVersionNo`**. Do **not** shadow it, do **not** rename the loader

## Hints & gotchas

- **`query_file!` binds take `.0`, not the newtype.** The comment at
  `crates/control/src/manifest.rs:271` says it precisely: the macro offline-checks the argument
  against the column's concrete `i64`. `s.created_lsn as Lsn` works only because that column is
  `pg_lsn`, a type sqlx has no native mapping for; an `int8` column expects an `i64`.
- **`query_file_as!` is the real trap.** It matches columns to struct fields by name and needs the
  `col AS "col: Type"` override *inside the `.sql`* — which changes the query text, which
  invalidates the committed `.sqlx` cache, which needs a live Postgres to regenerate. There is **no
  Docker on this machine.** The eight `query_file_as!` call sites are
  `checkpoint.rs:33`, `reload.rs:170/470/511/522`, `ddl_manifest.rs:69`, `replication_state.rs:23`;
  convert the ones whose struct gains a newtype field to `query_file!` + explicit construction.
- `#[serde(transparent)]` is mandatory on `EpochNo`/`SchemaVersionNo`. `SinkMeta` is a
  **cross-service wire contract** (`sink_meta.rs:9-12`) and `MetaConst`/`MetaRow` guarantee
  byte-equivalence "by construction" only because they carry identical field names *and types*. A
  non-transparent newtype would emit `{"epoch":{"0":3}}` and silently break the loader.
- Add `serde_json` to `common`'s `[dev-dependencies]`? No need — it is already a regular dependency
  (`crates/common/Cargo.toml`), used by the amortized serializer.
- `ReloadId` needs no serde: it never crosses the wire. `ManifestId` has none either — match that.
- `duckdb::params![...]` needs the inner `i64` as well (`duck.rs:292`, `:320`); `duckdb::ToSql` is
  not implemented for a foreign newtype.
- Do the crates in dependency order — `common`, then `control`, then `loader`/`pg-sink` — and
  compile after each. Flipping all 100 sites at once produces an unreadable error wall.
- `unwrap()`/`expect()` are `deny` in production (`Cargo.toml:16-20`). `clippy.toml` re-allows them
  under `#[cfg(test)]`, so the sibling `*_test.rs` files may keep using `.unwrap()`.
- Tests are **Go-style sibling files**: append to `ids_test.rs`, wired by the
  `#[cfg(test)] #[path = "ids_test.rs"] mod tests;` at `ids.rs:68-70`. Never add an inline
  `mod tests {}`.
- `clippy::all` + `warnings` are already `deny` workspace-wide. Expect `clippy::from_over_into` and
  `clippy::elidable_lifetime_names` to have opinions about the sqlx impls — the latter is
  deliberately left to PR 18.10, so do not "fix" `impl<'q> Encode<'q, Postgres>` here.
