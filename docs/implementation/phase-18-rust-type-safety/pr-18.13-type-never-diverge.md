# PR 18.13 — Record and guard walrus's no-diverging-function rule

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 18 — Rust type safety · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 18.12 · **Unlocks:** PR 19.1

`type-never-diverge` asks for `-> !` on functions that never return, and its worked examples reach
for `std::process::exit(1)` and `panic!` to get there. walrus has **zero** of both: `grep -rn
--include='*.rs' -E '\->\s*!|process::exit' crates/ tests/` returns **0**, production carries no
`panic!`/`todo!` (the single `unimplemented!` is a `#[allow(dead_code)]` deferred-goal stub at
`backfill.rs:36`), and both binaries are `fn main() -> ExitCode` (`loader/src/main.rs:16`,
`pg-sink/src/main.rs:16`) that surface `common::ExitCode`'s documented `#[repr(i32)]` contract
(`error.rs:105-121`). That is not an accident: every long-running loop is `CancellationToken`-driven
(28 uses) and **must unwind** to flush Parquet, commit the watermarks, release the ownership lease
and `CHECKPOINT` the `.duckdb` file — `process::exit` skips destructors, so adopting the rule's
technique would convert a clean drain into a data-loss bug. This PR keeps the property at 0 and
makes it *enforced* rather than merely *true*: a `common` integration test that fails on any `-> !`
or `std::process::exit` under `crates/*/src`, plus an ADR recording why the technique is rejected.

## Why — learning objectives

- **The never type `!` and its stable stand-in** — `fn f() -> !` is stable since 1.41, but naming
  `!` as a *type argument* (`Result<(), !>`, `JoinHandle<!>`) is still nightly; `Infallible` is the
  stable substitute, and walrus has no target for it (`impl TryFrom` count is 0).
- **Divergence vs RAII** — a diverging exit path skips every `Drop`, which is exactly the guarantee
  walrus's SIGTERM drain, lease release and DuckDB `CHECKPOINT` depend on.
- **walrus's exit-code contract** — errors travel as values to `main`, the single place that maps
  them onto the `#[repr(i32)]` `ExitCode` enum runbooks grep for.
- **Guard-and-note as a first-class outcome** — when a corpus rule is structurally inapplicable, the
  deliverable is a regression gate plus written evidence, never a silent skip.

## Read first

- [`type-never-diverge`](../../../.claude/skills/rust-skills/rules/type-never-diverge.md) — take the
  never-type semantics and the **Stability Notes** section (`!` as a type argument is nightly-only,
  `Infallible` is the stable stand-in). Treat its `abort_with_error` / `panic_handler` examples as
  the thing this PR argues *against*, with evidence.
- `crates/loader/src/main.rs:16-45` and `crates/pg-sink/src/main.rs:16-53` — the two `fn main() ->
  ExitCode` shells; every failure returns a value, nothing exits the process from below `main`.
- `crates/common/src/error.rs:89-128` — `Error::exit_code()` and the `#[repr(i32)] enum ExitCode`
  whose numbers are a documented public contract, converted via `From<ExitCode> for
  std::process::ExitCode`.
- `crates/loader/src/shutdown.rs` (module doc) — the six-step ordered drain, and the
  signal-swallowing `loop { select! }` at `shutdown.rs:63` (the one genuinely non-returning
  construct in the tree — inside a spawned async block, not a function).
- `crates/loader/src/apply_loop.rs:17-33` — `loop { tokio::select! { _ = shutdown.cancelled() =>
  return drain(&ctx), … } }`: the loop *returns*, which is the whole point.
- `docs/architecture.md` → "Graceful shutdown (SIGTERM drain)" and `docs/walrus-loader.md` §8.5 —
  the drain requirement the ADR cites.
- `docs/implementation/notes/duckdb-lts-bump.md` — the house shape for a notes/ ADR: a title, a
  one-line status blockquote, what the rule expected, what is actually true, the decision.

## Scope

**In scope**

- New integration test `crates/common/tests/no_divergent_exit.rs` that resolves the repo root from
  `CARGO_MANIFEST_DIR`, walks every `*.rs` under `crates/*/src` (sibling `*_test.rs` files included
  — they compile into the crate), and fails listing `path:line` for any `-> !` return type or
  `std::process::exit` call. An `ALLOW_LIST: &[&str]` constant exists and is **empty** today.
- A second `#[test]` proving the scanner is not vacuous: planted source strings containing each
  construct are both detected.
- Needles built with `concat!` so the guard's own source does not contain the literal patterns and
  the repo-wide grep still reports 0 after this PR.
- New ADR `docs/implementation/notes/no-divergent-functions.md` recording the decision, the measured
  evidence, and the graceful-drain rationale.

**Explicitly deferred** (do *not* build these here)

- **No `Infallible` work.** The rule's other half has no target: no infallible conversion in the
  tree is currently mis-typed as fallible (`impl TryFrom` count is 0).
- **No production changes.** Not one file under `crates/*/src` is touched; this PR is a test plus a
  note.
- **No new `[workspace.lints]` entry.** `clippy::exit` (restriction) would catch only
  `std::process::exit`, not `-> !`, so it cannot replace the guard — and workspace-lint additions
  belong to the Phase 33 `lint-*` tickets, which own that file. One guard, one failure message.
- **No new dependency.** The walker is ~15 lines of `std::fs` recursion; `walkdir` would have to
  clear `cargo deny` for no benefit.
- Scan scope stays `crates/*/src`. The `tests/e2e` harness crate and `benches/` are out of scope for
  this guard (they are test scaffolding, not the drain path).

**The conflict — resolve it explicitly, do not apply the rule as written.** The rule's own "Good"
examples are walrus's anti-pattern: `fn abort_with_error(msg: &str) -> !` calling
`std::process::exit(1)`, and `must_get_config()` coercing an exit into a value. `std::process::exit`
runs no destructors, so on this codebase it would abandon an open DuckDB write transaction, skip the
`CHECKPOINT`/close that prevents a stale file lock, and leave the table-ownership lease held until
TTL expiry — blocking the replacement pod. **Adopt the guard, reject the technique**, and say so in
the note with the file:line evidence above. This is an archetype-**D** ticket: the deliverable is
enforcement plus a written decision, not a code change.

## Hints & gotchas

- **The guard must not match itself.** If you write the literal `-> !` or `process::exit` anywhere
  in `no_divergent_exit.rs` — including in a doc comment or a failure message — the task's probe
  (`grep … crates/ tests/`) stops printing 0 and the DoD fails. Build both needles with `concat!`
  and compose the failure text from those constants.
- **`dead_code` will mask your falsification.** `fn boom() -> ! { loop {} }` in `lsn.rs` trips
  `deny(warnings)` first, so the build errors instead of the guard failing. Use `pub fn` in a `pub`
  module (`crates/common/src/lsn.rs` is one) so the compile succeeds and you see the *guard* go red.
- **Whitespace-normalise before matching.** Compare against the line with ASCII whitespace stripped
  so `-> !`, `->!` and `->  !` all hit; skip lines whose trimmed start is `//` so a doc comment
  explaining the rule doesn't trip the gate. If you ever need such prose in `crates/*/src`, the fix
  is an `ALLOW_LIST` entry plus an ADR line — not loosening the matcher.
- **No `walkdir`.** Any new dependency has to clear `cargo deny` (advisories + the 8-license
  allow-list + bans) and the recursion is ~15 lines of `std::fs`. If PR 18.12's
  `no_deref_inheritance.rs` guard already factored a walker into a shared `mod` under
  `crates/common/tests/`, reuse it via `mod …;`; integration-test binaries do not share code
  otherwise, so duplicating the walker is acceptable — do not add a crate to avoid ~15 lines.
- **This one belongs in `tests/`, not a sibling `*_test.rs`.** walrus unit tests are Go-style
  siblings (`src/foo.rs` → `src/foo_test.rs`), but this scans the repo from `CARGO_MANIFEST_DIR` and
  must not compile into the library — an integration target is the right home. `clippy.toml`
  (`allow-unwrap-in-tests`/`allow-expect-in-tests`) re-allows `unwrap`/`expect` there, so the guard
  can read files directly; production code still cannot.
- **Don't try to type the one non-returning construct.** The signal-swallowing tail at
  `crates/loader/src/shutdown.rs:63` really never returns, but it is an `async move { … }` block
  handed to `tokio::spawn`, not a function — and per the rule's own Stability Notes you cannot name
  `!` as a type argument (`JoinHandle<!>`) on stable. Leave it exactly as it is; note it in the ADR
  as the one place divergence is *observed* and still correctly untyped.
- **Ordering matters in the note.** Reject the technique on evidence, not taste: `process::exit`
  skips `Drop`, and walrus's drain (`shutdown.rs`) releases the lease *after* the watermarks commit
  and `CHECKPOINT`s before closing the `.duckdb` file. Skipping either is the stale-lock /
  double-apply hazard the whole §8.5 sequence exists to prevent.
- Keep the diff to two new files. A "while I'm here" `clippy::exit` line in the root `Cargo.toml`
  changes a probe count that a Phase 33 ticket owns.
