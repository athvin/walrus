# PR 18.3 — Give Lsn the LowerHex, UpperHex, Octal and Binary formatters

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 18 — Rust type safety · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 18.2 · **Unlocks:** PR 18.4

`Lsn` is a `u64` newtype whose entire canonical rendering is hexadecimal: `Display` is
`write!(f, "{:016X}", self.0)` (`lsn.rs:92`), `Debug` is `Lsn({:016X})` (`lsn.rs:98`), and `FromStr`
parses both hex dialects (`lsn.rs:66-87`). And yet the repo has **zero** `LowerHex`, `UpperHex`,
`Octal` or `Binary` impls — so `format!("{lsn:x}")` or `{lsn:#018x}` is a *compile error* today, on
the one type in walrus where a hex format specifier is the obvious thing to reach for. API guideline
C-NUM-FMT says a numeric newtype should support every specifier its inner integer does. This PR adds
the four forwarding impls (four lines of body each) and, just as importantly, pins `Display` so
nobody "unifies" it with the now-available `UpperHex` and silently drops the zero padding the whole
ordering contract depends on.

## Why — learning objectives

- **The `std::fmt` trait family, and forwarding formatter flags to an inner primitive** —
  `fmt::LowerHex::fmt(&self.0, f)` hands the *whole* `Formatter` down, so `#`, width, `0`-fill and
  precision all reach `u64`'s implementation for free. `write!(f, "{:x}", self.0)` would silently
  drop every one of them.
- **Why walrus prints LSNs as zero-padded hex rather than decimal** — `lsn.rs:3-8` spells it out:
  the 16-hex padded form was chosen precisely so a **text** sort equals a **numeric** sort, which is
  the ordering contract the entire `(commit_lsn, lsn)` pipeline rides on.

  through the inner type's trait implementation so `#`, `0` and width are handled correctly*). The
  third bullet ("skip `Octal`/`Binary` if there is no domain reason") is what PR 18.1's ids rely on;
  here all four are wanted because an LSN *is* a WAL byte position with a meaningful bit pattern
  (high 32 bits = segment file, low 32 = offset).

- `crates/common/src/lsn.rs:66-87` — `FromStr`, which accepts `0/199BAC8` **and** bare 1-16 hex, in

  `round_trips_through_display_and_from_str`. These are the cases that must stay green untouched.
- `crates/common/src/sql.rs:9-13` — the tree's existing **doctest** style (a ```` ``` ```` fenced
  example inside a doc comment). There are only two doctests in the whole repo; adding one here is
  optional but welcome.

## Scope

**In scope**

- Four new impls in `crates/common/src/lsn.rs`, each a single forwarding line:
  `fmt::LowerHex`, `fmt::UpperHex`, `fmt::Octal`, `fmt::Binary` for `Lsn`.
- A doc line on each explaining that the flags forward, and that the **unpadded** default is
  intentional — `{lsn}` is the canonical padded form, `{lsn:X}` is the raw one.
- New cases in `crates/common/src/lsn_test.rs`:
  - `format!("{:x}", Lsn::new(0x019A_2B3C))` == `"19a2b3c"` (lowercase, unpadded).
  - `format!("{:#018X}", Lsn::new(0x019A_2B3C))` == `"0x00000000019A2B3C"` — proves `#`, width and
    zero-fill all reached the inner `u64`.
  - `{:o}` and `{:b}` on a small value.
  - A **Display pin**: `Lsn::new(0xDEAD_BEEF).to_string()` is still 16 chars and still uppercase,
    and `format!("{lsn}") != format!("{lsn:X}")` for a value with leading zeros.
- Optionally one doc example on the `Lsn` type showing `{lsn}` vs `{lsn:x}` side by side, in the
  `sql.rs:9-13` style.

**Explicitly deferred** (do *not* build these here)

- No hex formatters for `ManifestId`, `EpochNo`, `SchemaVersionNo` or `ReloadId`. Those are decimal
  Postgres bigints with no bit-pattern meaning; the rule explicitly allows skipping non-mask types,
  and `{:x}` on a manifest id would only ever be a typo.
- No `fmt::Pointer`, no `LowerExp`/`UpperExp` — `Lsn` is an integer position, not a float.
- No change to `FromStr`. It already accepts lowercase (`lsn_test.rs:31`), so `{:x}` output already
  parses back.

**Conflict to resolve explicitly** — `Display` **must stay** the zero-padded 16-uppercase-hex form.
`lsn.rs:3-8` documents that text sort == numeric sort is the ordering contract the whole
`(commit_lsn, lsn)` pipeline relies on, and `Serialize` (`lsn.rs:106`) emits *through* `Display`, so
the padded form is the on-disk JSON and the DuckDB `_walrus_lsn` text column. A forwarded `UpperHex`
is **unpadded** by default. Do **not** rewrite `Display` as `fmt::UpperHex::fmt(&self.0, f)` and do
**not** "simplify" it to reuse the new impl — keep a test pinning `to_string()` at exactly 16 chars.

## Skeleton

```rust
// crates/common/src/lsn.rs — immediately after the existing `impl fmt::Debug for Lsn` (:96-100).

/// Lowercase hex, **unpadded** by default — `format!("{lsn:x}")` → `19a2b3c`.
///
/// Forwards the whole [`Formatter`](fmt::Formatter) to the inner `u64`, so `#`, width, precision and
/// the `0` fill flag all behave exactly as they do on a bare integer: `{lsn:#018x}` yields
/// `0x00000000019a2b3c`. The canonical *walrus* rendering is still [`Display`](fmt::Display) — this
/// is the escape hatch for ad-hoc debugging and for matching Postgres' own `pg_lsn` casing.
impl fmt::LowerHex for Lsn {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        fmt::LowerHex::fmt(&self.0, f)
    }
}

/// Uppercase hex, unpadded by default. **Not** the same as [`Display`], which always pads to 16
/// digits — see the module doc: the padded form is the one whose text order equals numeric order.
impl fmt::UpperHex for Lsn {

}
```

```rust
#[test]
fn hex_specifiers_forward_to_the_inner_u64() {
    let lsn = Lsn::new(0x019A_2B3C);
    assert_eq!(format!("{lsn:x}"), "19a2b3c");
    assert_eq!(format!("{lsn:X}"), "19A2B3C");
    // `#`, width and zero-fill all reach u64's LowerHex/UpperHex — this is the case that would
    // fail if the impls used `write!(f, "{:x}", self.0)` instead of forwarding the Formatter.
    assert_eq!(format!("{lsn:#018X}"), "0x00000000019A2B3C");
    assert_eq!(format!("{lsn:#010x}"), "0x019a2b3c");
}

fn display_stays_padded_and_is_not_upper_hex() {
```

## Hints & gotchas

- **`{:#X}` prefixes with a lowercase `0x`, not `0X`.** Rust's alternate flag is `0x` for both hex
  cases, so the expected string is `"0x00000000019A2B3C"` — 18 characters, prefix included, because
  the width counts the prefix and the zero-fill is inserted *after* it.
- The four impls must **not** be `write!(f, "{:x}", self.0)`. That re-formats with a *fresh* default
  spec and throws away `#`, width, fill and precision — the `{lsn:#018X}` assertion exists precisely
  to catch it in review.
- `fmt` is already imported at `lsn.rs:10` (`use std::fmt;`). Do not add `use std::fmt::LowerHex;` —
  the qualified `fmt::LowerHex::fmt(…)` form matches the file's existing style and avoids shadowing
  the inherent `fmt` method names.
- `Serialize` (`lsn.rs:105-107`) uses `collect_str(self)`, which routes through `Display`. Adding
  `UpperHex` cannot change the JSON — but *editing* `Display` would change every persisted
  `commit_lsn` string in `_walrus_meta`, `<table>_raw` and the control tables at once. Leave it be.
- `{:b}` on a real LSN is 64 characters wide. Keep the binary/octal test values small (`Lsn::new(5)`)
  so the assertion stays readable.
- A doc example is a **doctest** and runs in CI. It must use the public path (`use common::Lsn;`) and
  only public API — `Lsn::new` and `as_u64` are `pub const fn` (`lsn.rs:26`, `:31`), so that is fine.
- `unwrap()`/`expect()` are `deny` in production; `clippy.toml` re-allows them under `#[cfg(test)]`,
  so the sibling `lsn_test.rs` may keep using `.unwrap()`. A **doctest** is compiled as its own
  crate against `common`'s public API and is *not* `cfg(test)` — but the workspace lints do not apply
  to doctests either, so `.unwrap()` inside one is fine. Prefer `assert_eq!` on infallible calls
  anyway.
- `clippy::all` + `warnings` are already `deny` workspace-wide and `common` declares
  `[lints] workspace = true`. Watch for `clippy::missing_trait_methods` (nursery, not enabled) — not
  a concern; but `clippy::use_self` **is** in the pedantic sweep and not yet denied, so match the
  file's existing `for Lsn` style rather than `for Self`.
- Tests are **Go-style sibling files**: append to `lsn_test.rs`, wired by the
  `#[cfg(test)] #[path = "lsn_test.rs"] mod tests;` at `lsn.rs:157-159`. Never add an inline
  `mod tests {}`.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it, and nothing here needs it.
