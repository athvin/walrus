# PR 18.12 — Guard the domain newtypes against `Deref` inheritance

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** evidence
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 18 — Rust type safety · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 18.11 · **Unlocks:** PR 18.13

Walrus's domain newtypes already expose the API-guideline shape — explicit accessors:
`Lsn::as_u64` (`crates/common/src/lsn.rs:31`), `From<ManifestId> for i64`
(`crates/common/src/ids.rs:26`), and `UtcTimestamp`'s parse/render pair
(`crates/common/src/sink_meta.rs:47`). The tree does have one legitimate `Deref`/`DerefMut` pair:
`pg-sink::reload_signal::SubscribeGuard` temporarily exposes its oneshot receiver while its `Drop`
impl unregisters the in-flight watermark subscription, exactly the rule's RAII-guard carve-out.
Nothing prevents a *domain* newtype from regressing, and the pressure to regress is about to go up:
after PRs 18.1 and 18.11 the tree carries arithmetic-shaped or string-shaped newtypes (`EpochNo`,
`SchemaVersionNo`, `ReloadId`, `ManifestId`, `Lsn`, `DuckTable<K>`) — exactly the types a future
contributor would `Deref` to `i64` or `str` "to make comparisons easier", silently undoing the whole
point of PR 8.4. This PR adds no production code. It adds a test that preserves the documented RAII
exception but fails the build if anyone writes `impl Deref for` a walrus domain type, plus a short
note recording the decision so the next reader knows it was deliberate.

## Why — learning objectives

- **Why `Deref` is for smart pointers, not OOP-style inheritance** (API guideline C-DEREF) — and
  how a `Deref` on a newtype re-opens every hole the newtype closed, silently, at method resolution.
- **The walrus newtype accessor convention** established in PR 8.4: `as_u64` / `From` / `as_str`,
  never transparent method inheritance.

## Read first

- [`type-deref-coercion`](../../../.claude/skills/rust-skills/rules/type-deref-coercion.md) — the
  `AdminUser` "Bad" example is the exact hazard, and the **Legitimate Uses** list is what your
  allow-list must be able to express (`Box`/`Rc`/`Arc`, owned→borrowed containers, RAII guards).
  Note its final bullet — "newtype wrappers where the entire semantic purpose is 'this is a `T`
  with additional invariants'" — and see the Scope note below on why walrus reads that narrowly.
- `crates/common/src/lsn.rs:21-34` — `Lsn::new` / `Lsn::as_u64`, the const accessor pair every
  walrus newtype copies.
- `crates/common/src/ids.rs:1-30` — `ManifestId`, its `Display`, and the two `From` impls that are
  the *entire* public conversion surface.
- `crates/common/src/sink_meta.rs:41-60` — `UtcTimestamp(jiff::Timestamp)`: a wrapper whose whole
  purpose is an invariant (always UTC `Z`). A `Deref` to `jiff::Timestamp` would hand callers every
  method that can produce a non-UTC value — the clearest concrete example for the note.
- `crates/pg-sink/src/reload_signal.rs:138-175` — `SubscribeGuard`'s existing RAII
  `Deref`/`DerefMut`, `Future`, and `Drop` impls; the guard must allow exactly this type with a reason,
  not allow every future implementation in the file.
- `crates/pg-to-arrow/tests/conformance.rs:1-10` — an existing integration test's file-level header,
  the shape yours copies.
- `docs/implementation/notes/duckdb-lts-bump.md` — the house style for a decision note: a `# Title`,
  a `> **Status:** …` blockquote, then the evidence.

**In scope**

- A new integration test `crates/common/tests/no_deref_inheritance.rs` that walks
  `crates/*/src/**/*.rs` from `CARGO_MANIFEST_DIR` (i.e. `crates/common/../..`), skips comment
  lines, and fails on any line whose trimmed form starts with `impl` and mentions `Deref` /
  `DerefMut` followed by ` for `.
- An explicit, documented `ALLOWED` list keyed by repo-relative path **and type name**, containing
  exactly `pg-sink/src/reload_signal.rs`'s `SubscribeGuard` with its RAII subscription-cleanup
  reason. The comment says what else could legitimately go in it (a genuine smart pointer or an
  owned→borrowed container) and what would not (any domain newtype). Keying the exception by type as
  well as file ensures a future unrelated `Deref` in `reload_signal.rs` still fails.
- A decision note at `docs/implementation/notes/rust-skills/type-deref-coercion.md`: what the guard forbids,
  the three accessor precedents it protects, the `UtcTimestamp` worked example, and how to add an
  allow-list entry if a real smart pointer ever appears.
- The test carries the current standard multiline file-level allow for `clippy::unwrap_used` and
  `clippy::expect_used`, with reason `"integration test — unwrap/expect fine in setup + helpers"`.

**Explicitly deferred** (do *not* build these here)

- **No production code changes at all.** No accessor is added, renamed or removed; no newtype gains
  or loses a trait impl. If `cargo clippy` reports anything in `crates/*/src`, you have changed
  something you should not have.
- No `AsRef<str>` / `Borrow` sweep. Those are different traits with different guidance, and walrus
  does not implement them on its newtypes today either — a separate ticket if ever wanted.
- No `syn`/`proc-macro` parsing and no `walkdir` dependency. The guard is a line scan over
  `std::fs::read_dir` recursion; a new dependency would have to clear `cargo deny` (advisories, the
  8-license allow-list, bans) for a twenty-line file walk.
- No CI-workflow change. `cargo test --workspace` already runs `crates/common/tests/*`, so the gate
  rides the existing job.
- The scan covers `crates/*/src` only. `tests/e2e/src` is a test-harness lib, not production, and is
  deliberately out of the guard's scope — say so in the note rather than silently omitting it.
- **The rule's "transparent wrapper" carve-out is read narrowly here.** `Lsn`, `ManifestId` and
  friends *are* transparent at the sqlx layer (PR 18.2 makes that `#[repr(transparent)]` and
  explicit), but transparency of *layout* is not a licence for transparency of *API*: the entire
  reason `EpochNo` and `SchemaVersionNo` exist is that they must **not** behave like the `i64` they
  wrap. Record that reading in the note; do not treat it as a reason to weaken the guard.

//! Guard: walrus newtypes expose explicit accessors (`Lsn::as_u64`, `From<ManifestId> for i64`,
//! `DuckTable::as_str`), never `Deref`. `Deref` is for smart pointers and owned→borrowed containers
//! (API guideline C-DEREF); using it on a domain newtype re-exposes every inner method through
//! method resolution and quietly undoes the type distinction the newtype was created to enforce.
//!
//! See `docs/implementation/notes/rust-skills/type-deref-coercion.md`.

use std::path::{Path, PathBuf};

The note at `docs/implementation/notes/rust-skills/type-deref-coercion.md` follows the house format used by
`duckdb-lts-bump.md` — a level-1 title, a `> **Status:** decided — …` blockquote, then evidence.
Its four sections, in order:

1. **"What the convention is"** — `Lsn::as_u64` (`lsn.rs:31`), `From<ManifestId> for i64`
   (`ids.rs:26`), `DuckTable::as_str` (PR 18.11): explicit accessors, nothing inherited.
2. **"Why `Deref` would break it"** — the `UtcTimestamp(jiff::Timestamp)` worked example: a `Deref`
   hands callers every `jiff::Timestamp` method, including the ones that can produce a non-UTC
   value — the exact invariant `sink_meta.rs:41-60` exists to guarantee.
3. **"Layout-transparent is not API-transparent"** — PR 18.2 makes these `#[repr(transparent)]`;
   that is a statement about bytes, not a licence to inherit the inner type's methods.
4. **"How to add an allow-list entry"** — record the existing `SubscribeGuard` exception, then
   explain that each entry needs a path, exact wrapper name, and one-line reason plus a sentence in
   the note proving the wrapper is a genuine smart pointer / owned container / RAII guard.

## Hints & gotchas

- **The guard must be able to fail.** A path bug that makes `rust_files` return an empty `Vec` would
  give you a permanently-green test that proves nothing. Assert a non-zero file count (the tree has
  ~189 `.rs` files, ~140 of them under `crates/*/src`) inside the test, and *actually run* the
  break-it-on-purpose step in the DoD before you open the PR.
- **`CARGO_MANIFEST_DIR` is the package dir, not the workspace root.** From `crates/common` you need
  two `parent()` hops to reach the repo root. `env!` (compile time) is right here; `std::env::var`
  (run time) also works but is one more failure mode.
- **Don't over-match.** `Deref` will appear in prose — this very note, module docs, and possibly a
  `// never Deref` comment someone adds later. Filter comment lines first, then require the line to
  *start* with `impl` and contain ` for `. A naive `contains("Deref")` scan will fail the build on a
  doc comment and get the guard deleted within a month.
- Matching `Deref` as a substring also catches `DerefMut` — that is intentional, and it means you do
  not need a second pattern.
- **No new dependency.** `walkdir`, `regex`, `syn`, `glob` would all need to clear `cargo deny`
  (advisories, 8-license allow-list, bans) to save fifteen lines of `read_dir` recursion. Not worth
  it; the rest of the workspace does the same.
- Integration tests live in the existing `crates/common/tests/` directory — that is the right home
  for a whole-tree guard. Sibling `*_test.rs` files are for unit tests of one module and could not
  reach outside the crate.
- `unwrap`/`expect` are denied in production but re-allowed in tests via the reason-bearing
  file-level header; keep the current multiline form so the workspace's
  `allow_attributes_without_reason` deny remains satisfied.
- This PR is a **gate**, not a cleanup: the production probe stays at the one legitimate two-impl
  RAII pair, while every unlisted wrapper is denied by construction. Say that in the PR body.
