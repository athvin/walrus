# PR 18.6 — Add a validated SqlIdent newtype and retire the duplicated identifier quoting

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,loader,pg-sink

> **Phase:** 18 — Rust type safety · **Crates touched:** `common`, `loader`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 18.5 · **Unlocks:** PR 18.7

`common::sql` ships `sql_literal` for single-quote escaping (`sql.rs:14`) but has no identifier
sibling — so double-quote escaping is re-implemented per crate: a private `fn ident` in `pg-sink`
(`preflight.rs:442-443`) and an inline `format!("\"{}\"", c.replace('"', "\"\""))` in the loader
(`duck.rs:176`). Two copies of the same three-line rule, in two crates, with nothing tying them
together. Worse, `TableDb::append_parquet` takes `table: &str` (`duck.rs:161`) and splices it into
the `append_parquet.sql` template unquoted (`duck.rs:184`), so **nothing at the type level says which
strings have already been through an escaper**. This PR adds one validated newtype in `common` whose
mere existence proves the escaping happened, and deletes both hand-rolled copies.

## Why — learning objectives

- **Parse, don't validate: a newtype whose existence proves the escaping already happened** — once
  you hold a `SqlIdent`, no caller needs to re-check, re-escape or wonder. The fallible constructor
  is the single boundary.
- **SQL identifier quoting vs string-literal quoting, and where walrus builds DuckDB DDL by hand** —
  a literal doubles `'` (`sql_literal`), an identifier doubles `"`. They are *different rules* for
  *different syntactic positions*, and the loader's DDL templates + the sink's publication
  management are the two places walrus writes SQL by string assembly.

**In scope**

- `crates/common/src/sql.rs` gains:
  - `pub struct SqlIdent(String)` — private inner field, so the only way to get one is `new`.
  - `pub fn SqlIdent::new(s: &str) -> Result<Self, IdentError>` rejecting **empty** and any
    **interior NUL** (`\0` terminates the identifier for the wire protocol and can smuggle past a
    naive escaper).
  - `impl fmt::Display for SqlIdent` rendering the quote-doubled `"…"` form, written as a
    character walk over the `Formatter` — **not** via `String::replace` (see Hints; the probe
    depends on it and the walk avoids an intermediate allocation).
  - `pub fn as_raw(&self) -> &str` returning the *unquoted* name, for callers that need to compare
    against a catalog value.
  - `#[derive(Debug, Clone, PartialEq, Eq, thiserror::Error)] pub enum IdentError { Empty,
    InteriorNul(String) }`.
- `crates/pg-sink/src/preflight.rs`: replace the hand-rolled `fn ident` (`:441-444`) with a fallible
  `SqlIdent::new(…)` helper that maps a rejection to `PreflightError::Query`; its three call sites
  propagate with `?`.
- `crates/loader/src/duck.rs`: `append_parquet`'s `quoted` list is built from `SqlIdent`, mapping a
  rejection to `LoaderError::Internal` without fabricating a DuckDB engine source.
- New cases in `crates/common/src/sql_test.rs` for `a"b` → `"a""b"`, the empty-string rejection, the
  NUL rejection, and `as_raw` round-tripping the original.

**Explicitly deferred** (do *not* build these here)

- Only pg-sink's `ident(..)` call sites and the loader's `columns_for` column list migrate. The
  remaining `format!("\"{…}\"", …)` interpolations in `crates/loader/src/ddl.rs`,
  `crates/loader/src/transform.rs` and `duck.rs::ensure_tables_planned` keep their current shape —
  migrating the nine DDL templates is a follow-up with its own review budget.
- `TableDb::append_parquet`'s `table: &str` parameter (`duck.rs:161`) stays a `&str` in this PR. It
  is substituted into `{table}` inside the template, and re-typing it correctly means touching every

- **No `.sql` template and no `.sqlx` cache entry is touched.** `SqlIdent` renders the exact same
  bytes the two hand-rolled escapers do today.
- `sql_literal` is unchanged. It is a `String` in, `String` out helper for a *different* syntactic
  position and does not gain a newtype here.

## Skeleton

```rust
// crates/common/src/sql.rs — after the existing `sql_literal` (:14-16).

use std::fmt::{self, Write as _};

/// Why a string cannot be a SQL identifier.
#[derive(Debug, Clone, PartialEq, Eq, thiserror::Error)]
pub enum IdentError {
    #[error("must not be empty")]
    Empty,
    /// A NUL terminates the identifier on the wire; an escaper that only doubles `"` would let it
    /// through and truncate the statement server-side.
    #[error("value {0:?} contains an interior NUL")]
    InteriorNul(String),
}

/// A **validated** SQL identifier: a table, column or publication name that has passed the
/// identifier rules once, at construction.
///
/// Holding a `SqlIdent` is the proof that quoting happened — there is no way to build one without
/// going through [`SqlIdent::new`], and `fmt::Display` always renders the quote-doubled
/// `"…"` form. Contrast [`sql_literal`], which escapes a *value* (`'` doubled) rather than a *name*.
///
/// ```
/// use common::sql::SqlIdent;
/// assert_eq!(SqlIdent::new("plain").unwrap().to_string(), "\"plain\"");
/// assert_eq!(SqlIdent::new("a\"b").unwrap().to_string(), "\"a\"\"b\"");
/// assert!(SqlIdent::new("").is_err());
/// ```
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct SqlIdent(String);

impl SqlIdent {
    /// Parse, don't validate: the only constructor.
    ///
    /// # Errors
    ///
    /// Returns [`IdentError::Empty`] for an empty name or [`IdentError::InteriorNul`] when the name
    /// contains a NUL byte.
    pub fn new(s: &str) -> Result<Self, IdentError> {
        if s.is_empty() {
            return Err(IdentError::Empty);
        }
        todo!("reject s.contains('\\0') with IdentError::InteriorNul(s.to_string()), else Ok(Self(s.to_string()))")
    }

    /// The **unquoted** name, for comparing against a catalog value.
    pub fn as_raw(&self) -> &str {
        &self.0
    }
}

impl fmt::Display for SqlIdent {
    /// The quoted form, doubling every interior `"` — `a"b` renders as `"a""b"`.
    ///
    /// Written as a character walk rather than `String::replace` so there is no intermediate
    /// allocation, and so the tree keeps exactly **zero** hand-rolled identifier escapers.
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_char('"')?;
        for ch in self.0.chars() {
            if ch == '"' {
                f.write_char('"')?;
            }
            f.write_char(ch)?;
        }
        f.write_char('"')
    }
}
```

## Hints & gotchas

- **Do not implement `Display` with `String::replace`.** The probe counts production lines that hold
  both `replace(` and an escaped `\"`; a `self.0.replace('"', "\"\"")` inside `sql.rs` would keep
  the count at 1 and fail the DoD. The character walk over the `Formatter` is both the passing form
  and the better one — no intermediate `String`.
- `use std::fmt::Write as _;` is required for `f.write_char(…)`. The `as _` import keeps the trait
  name out of scope so it cannot collide with `std::io::Write`.
- `SqlIdent`'s inner field must be **private** (`SqlIdent(String)`, not `SqlIdent(pub String)`).
  A public field lets a caller mint an unvalidated one and the whole guarantee evaporates. Contrast
  `ManifestId(pub i64)`, where every `i64` is a valid id — there is nothing to validate.
- The three `preflight.rs` call sites sit inside `format!` arguments. `SqlIdent` implements
  `Display`, so `{}` works directly — do **not** call `.to_string()` on it there.
- The record for this ticket estimated *five* `ident(..)` call sites; the tree actually has **three**
  (`preflight.rs:266`, `:290`, `:291`) plus the definition at `:442`. Migrate what is there and say
  so in the PR body rather than hunting for two that do not exist.
- `columns_for` returns `Arc<Vec<String>>` (`duck.rs:197`), and the closure inside `map` is now
  fallible — collect into `Result<Vec<_>, LoaderError>` and `?` it, rather than reaching for
  `unwrap()` (`unwrap_used` is `deny` in production).
- DuckDB and Postgres share the SQL-standard identifier rule (double quotes, doubled to escape), so
  one newtype legitimately serves both engines. Do **not** add engine-specific variants.
- `common` has no `sqlx` requirement here — `SqlIdent` is pure string handling, so it lives outside
  the `#[cfg(feature = "sqlx")]` modules and is available to every consumer.
- The doc example is a **doctest** and runs in CI (`cargo test -p common --doc`). Use the public
  path `common::sql::SqlIdent`; note `sql` is `pub mod sql;` in `lib.rs` but is not flat-re-exported,
  and this PR does not change that.
- `unwrap()`/`expect()` are `deny` in production; `clippy.toml` re-allows them under `#[cfg(test)]`,
  so the sibling `sql_test.rs` may keep using `.unwrap()`.
- Tests are **Go-style sibling files**: append to `sql_test.rs`, wired by the
  `#[cfg(test)] #[path = "sql_test.rs"] mod tests;` at `sql.rs:18-20`. Never add an inline
  `mod tests {}`.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. The rendered bytes are unchanged, so nothing needs regenerating.
