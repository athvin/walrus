# PR 18.11 — Tag DuckDB table names with `PhantomData` so mirror and raw cannot be swapped

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** loader

> **Phase:** 18 — Rust type safety · **Crates touched:** `loader` · **Est. size:** M ·
> **Depends on:** PR 18.10 · **Unlocks:** PR 18.12

The loader carries **two** DuckDB table names per source table — the mirror `<table>` (current row
per PK) and the CDC log `<table>_raw` (every change, verbatim) — as **one bare `String`**
(`TablePlan::table`, `crates/loader/src/plan.rs:52`), from which the raw name is re-derived by string
concatenation at roughly ten SQL-construction sites (`transform.rs:104`, `:151`, `:305`;
`phase_b.rs:63`; `ddl.rs:201`, `:208`, `:216`, `:223`, `:303`; `compaction.rs:95`). The two tables
have deliberately *asymmetric* semantics — `ddl.rs:1-19` spends a paragraph on it: the mirror is kept
at the exact current source shape while raw is an additive superset that never drops or re-casts —
so writing to the wrong one is a data-corruption bug. Today it is also a bug that compiles cleanly,
because both names are `String`. There is **zero `PhantomData` anywhere in the repo**. This PR
introduces a `DuckTable<K>` whose type parameter exists only at compile time, and adopts it in the
two hottest derivation sites so the mirror name and the raw name stop being the same type.

## Why — learning objectives

- **`PhantomData`, zero-sized type tags and variance** — a type parameter that appears in no field,
  costs nothing at runtime, and still makes two values non-interchangeable.
- **The loader's two-table model** — the verbatim `<table>_raw` CDC log versus the derived
  `<table>` mirror, and why `_raw` should be spelled in exactly one place.

**In scope**

- A new `crates/loader/src/table_name.rs` defining two zero-sized tags (`Mirror`, `Raw`) and
  `DuckTable<K> { name: String, _kind: PhantomData<K> }` with:
  - `DuckTable::<Mirror>::new(impl Into<String>)` — the only public constructor.
  - `DuckTable::<Mirror>::raw(&self) -> DuckTable<Raw>` — **the single place `_raw` is spelled**.
  - `as_str(&self) -> &str` on the generic impl, for interpolation into SQL.
- `pub mod table_name;` in `crates/loader/src/lib.rs`.
- `TransformSql.table` becomes `DuckTable<Mirror>`; the three `_raw` interpolations inside
  `transform.rs` (`:104`, `:151`, `:305`) go through `.raw()`. `TransformSql::table()` keeps its
  `-> &str` signature (it returns `self.table.as_str()`), so `compaction.rs` and the `tracing` call
  in `full_rebuild` compile untouched.
- `phase_b.rs:60-69` builds the scanned table name as
  `DuckTable::<Mirror>::new(&ctx.table).raw()` instead of `format!("{}_raw", ctx.table)`.
- A sibling `crates/loader/src/table_name_test.rs` asserting the tag is free
  (`size_of::<DuckTable<Raw>>() == size_of::<String>()`) and that
  `DuckTable::<Mirror>::new("t").raw().as_str() == "t_raw"`.

**Explicitly deferred** (do *not* build these here)

- `ddl.rs`'s nine DDL templates (`:201`, `:208`, `:216`, `:223`, `:286`, `:303`) and `duck.rs`'s
  `{table}` substitutions keep their current `&str` shape. Converting them touches every
  `AdditiveChange` / `DestructiveChange` arm and the `include_str!` templates' parameter names — a
  follow-up, not this PR.
- `compaction.rs:95`'s `format!("DELETE FROM \"{}_raw\" …", t.table())` stays as-is for the same
  reason. Note it in the PR body as the known remaining derivation site.
- `TablePlan::table` (`plan.rs:52`) stays a `String`. It is built from the registry and from
  `PgRelation::name`; retyping it would ripple into `duck.rs::ensure_tables_planned` and the DDL
  applier, which are explicitly out of scope above.
- **No `trybuild` compile-fail harness.** Proving "passing a `DuckTable<Raw>` where `DuckTable<Mirror>`
  is expected fails to compile" would need a new dev-dependency, and every new dependency must clear
  `cargo deny` (advisories + the 8-license allow-list + bans). The `size_of` assertion plus the
  `raw()` round-trip are the mechanical probe here.
- No `Deref<Target = str>` on `DuckTable<K>`. That would make a `DuckTable<Raw>` usable anywhere a
  `&str` is wanted and undo the entire point — and PR 18.12 adds the guard that forbids it.

## Skeleton

```rust
// crates/loader/src/table_name.rs — new
//! Type-tagged DuckDB table names. The loader owns two tables per source table with deliberately
//! asymmetric semantics (`crate::ddl` module doc): the mirror `<table>` is kept at the exact current
//! source shape, while `<table>_raw` is an additive superset that never drops or re-casts history.
//! Passing one where the other belongs corrupts data, so they are different types.

use std::marker::PhantomData;

/// The mirror `<table>` — current row per PK, exact current source shape.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Mirror;

/// The CDC log `<table>_raw` — every change verbatim, additive superset.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Raw;

/// A DuckDB table name tagged with which of the two tables it names.
///
/// `PhantomData<K>` stores nothing: `size_of::<DuckTable<K>>() == size_of::<String>()` for every
/// `K` (asserted in `table_name_test.rs`). The parameter exists purely so the compiler can tell a
/// mirror name from a raw name.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DuckTable<K> {
    name: String,
    _kind: PhantomData<K>,
}

impl<K> DuckTable<K> {
    /// The bare name, for interpolation into a quoted SQL identifier.
    pub fn as_str(&self) -> &str {
        &self.name
    }
}

impl DuckTable<Mirror> {
    pub fn new(name: impl Into<String>) -> Self {
        todo!("DuckTable { name: name.into(), _kind: PhantomData }")
    }

    /// This mirror's CDC log. **The only place the `_raw` suffix is spelled in the loader.**
    pub fn raw(&self) -> DuckTable<Raw> {
        todo!("DuckTable { name: format!(\"{}_raw\", self.name), _kind: PhantomData }")
    }
}
```

## Hints & gotchas

- **`#[derive(Clone)]` on `DuckTable<K>` adds an unwanted `K: Clone` bound.** The derive is
  conservative and bounds every parameter, even one that only appears inside `PhantomData`. `Mirror`
  and `Raw` are `Clone`, so it compiles — but if you ever tag with a non-`Clone` type it breaks.
  Either keep the tags `Copy + Clone` (simplest, and what the skeleton does) or hand-write `Clone`
  without the bound. This is the same "bounds only where needed" point PR 18.10 just locked in.
- **`PhantomData<K>` makes `DuckTable<K>` inherit `K`'s auto traits.** With unit-struct tags that is
  harmless (they are `Send + Sync`). If you prefer the bullet-proof form, use
  `PhantomData<fn() -> K>`: it is covariant, always `Send + Sync`, and expresses "produces a K"
  rather than "owns a K". Say which you chose and why in the module doc.
- The tags must be **`pub`**, or `DuckTable<Mirror>` in a public signature trips
  `private_interfaces` under `deny(warnings)`.
- **Do not change any rendered SQL.** `crates/loader/tests/transform.rs` and `phase_b.rs` assert on
  transform behaviour end to end; if a test starts failing, you changed a string, not a type. Diff
  the rendered output before and after if in doubt.
- `crates/loader/src/transform.rs:69` (`let table = &plan.table;`) and `:271` (`let t = &self.table;`)
  are used as `{table}` / `{t}` inline-format captures. Those become `table.as_str()` /
  `t.as_str()` bindings — inline format args need a `&str`, not a `DuckTable`, unless you also
  implement `Display` (don't: `as_str()` is the walrus accessor convention, and PR 18.12 is about to
  make "explicit accessors, never `Deref`" a tested rule).
- `unwrap`/`expect` are denied in production and `clippy::all` + `warnings` are already `deny`;
  a `PhantomData` field named `_kind` will not trip `dead_code`, but a differently-named one might —
  keep the leading underscore.
- Unit tests are **sibling files**, not inline `mod tests {}`; add the
  `#[cfg(test)] #[path = "table_name_test.rs"] mod tests;` footer to `table_name.rs`.
- `cargo test -p loader` builds bundled DuckDB (~20 min cold, ~3 min cached). The two new unit tests
  need no database: `cargo test -p loader --lib table_name` is the fast loop.
- No `.sql` template and no `.sqlx` cache entry changes here.
