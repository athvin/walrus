# PR 12.7 — Record the Miri decision and add a tripwire that forces it to be revisited

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 12 — Rust unsafe-code policy · **Crates touched:** none (CI script + `docs/`) ·
> **Est. size:** S · **Depends on:** PR 12.6 · **Unlocks:** PR 13.1

`unsafe-miri-ci` says "run `cargo miri test` for every crate that contains `unsafe` code". In
walrus that set is **empty** — 0 `unsafe` tokens across all 189 Rust files, and as of PR 12.1
`unsafe_code = "forbid"` makes it a compile error to grow one. The crates whose *dependencies*
carry unsafe are exactly the ones Miri cannot execute: `loader` and `pg-to-arrow` link bundled
DuckDB C++ through `libduckdb-sys 1.10504.0` (`Cargo.lock:2137`) and Miri cannot call foreign
functions; `pg-sink`/`control` drive real TCP and Postgres, with **131** `#[ignore]`d
compose-gated tests behind **135** `#[tokio::test]`s. Miri also needs nightly, while
`rust-toolchain.toml:4` pins `1.95.0` exactly and CI has a dedicated `msrv` job to keep it that
way. Today there are **0** mentions of "miri" anywhere in the repo — the decision is unrecorded,
and nothing notices if the premise changes. This PR closes both halves: an ADR that states the
rejection *and* the condition that flips it, plus a case in
`scripts/check-unsafe-invariants.sh` (built in PR 12.6) asserting the forbid is still in force
and still reaches all six members. Delete the forbid line and the `gates` job fails with a
message pointing at the ADR. Phase 12 closes with the unsafe posture both written down and
machine-enforced.

## Why — learning objectives

- **What Miri actually checks** — Stacked Borrows / Tree Borrows aliasing, pointer provenance and
  reads of uninitialized memory, by *interpreting* MIR — which is precisely why FFI calls and
  syscall-heavy suites are outside its reach, not merely slow.
- **Recording an engineering rejection as a tripwire** — a "no" is only durable if it names the
  condition under which it becomes a "yes", and something mechanical asserts that condition still
  holds. An ADR without a guard rots; a guard without an ADR is a mystery failure.

## Scope

**In scope**

- Create `docs/implementation/notes/miri-deferred.md` (the `notes/` directory goes from 2 files to
  3). It must record, with citations:
  1. the rule's precondition and the measured fact that it is empty (0 `unsafe` tokens; `forbid`
     since PR 12.1);
  2. the FFI wall — bundled DuckDB C++ via `libduckdb-sys` in `loader` and `pg-to-arrow`, which
     Miri cannot execute, and the 131 `#[ignore]`d compose/TCP tests it also cannot run;
  3. the toolchain cost — nightly plus a `cargo miri setup` sysroot build on every push, against a
     repo that pins one exact stable and has an `msrv` job guarding that pin;
  4. the **build-cost** argument, citing `Cargo.toml:71-77` (thin LTO adopted,
     `codegen-units = 1` rejected) and the `justfile` `bench` comment — the rejection is on
     measured grounds, not taste;
  5. the **re-evaluation trigger**: the first PR that needs `unsafe_code = "allow"` in any member,
     or the first first-party `unsafe extern` block, re-opens this decision — and at that point
     Miri runs scoped to that crate, not workspace-wide.
- Extend `scripts/check-unsafe-invariants.sh` (from PR 12.6) with a "the unsafe policy is still in
  force" case that asserts **both** halves of the PR 12.1 gate:
  - `unsafe_code = "forbid"` is present in `[workspace.lints.rust]` in the root `Cargo.toml`;
  - every workspace member still inherits it via `[lints]` / `workspace = true` — and the member
    list is **derived from `Cargo.toml`'s `members = [...]`**, so a crate added later cannot slip
    past the loop.

  Both failure messages must name `docs/implementation/notes/miri-deferred.md`.
- No `.github/workflows/ci.yml` change: PR 12.6 already added the script as a step in the `gates`
  job, and `scripts/**` is in the `changes` job's `code:` filter, so this PR's edit is enough to
  make CI actually execute the new case.

**Explicitly deferred** (do *not* build these here)

- **Any Miri job — not even a `workflow_dispatch`-only one.** A job that cannot be run green
  cannot be verified and will rot into a red badge nobody trusts. The artifact of this ticket is a
  written decision plus a guard, not a disabled workflow.
- `cargo careful`, `-Zsanitizer=address/thread`, `cargo-fuzz`. Same nightly + FFI constraints;
  each deserves its own evaluation if it is ever wanted.
- A `-p common`-only Miri run (the obvious "but `common` is pure Rust!" counter-argument).
  `common`'s config tests run inside `figment::Jail` (`crates/common/src/config_test.rs:19-25` —
  fresh temp CWD + scoped env) and `crates/common/src/metrics.rs:134-146` installs a process-wide
  Prometheus recorder; both need `-Zmiri-disable-isolation` and neither has been verified under
  Miri here. Record the idea in the ADR's trigger section; do not implement it on a guess.
- Any change to `Cargo.toml`, `rust-toolchain.toml`, or the lints themselves — PRs 12.1–12.4 own
  those, and this PR's guard exists to protect what they landed.

**Conflict to resolve explicitly.** `CONTEXT.md` §4 pre-decides archetype **D** for this rule, and
that verdict is honoured — but D here must not be written as "walrus has no unsafe, so skip". Two
extra obligations follow:

- The ADR must argue from the **FFI + nightly + build-cost** evidence above. "No unsafe today"
  alone is an argument that expires the moment someone adds unsafe — which is exactly why the
  tripwire exists.
- The ADR must cite the Phase-5 cost precedent (`Cargo.toml:71-77`, the `justfile` bench note) so
  a reader sees that walrus already declines compile-time-expensive wins on measured grounds. Do
  not claim a Miri run time you have not measured; argue from "a nightly toolchain install plus a
  `cargo miri setup` sysroot build on every push, on a repo that pins one exact stable".

## Skeleton

```bash
# scripts/check-unsafe-invariants.sh — appended by PR 12.7.
# The file already exists (PR 12.6) with `set -euo pipefail`, `cd "$(git rev-parse --show-toplevel)"`
# and a `fail()` helper. Reuse them; do not redefine.

ADR="docs/implementation/notes/miri-deferred.md"

echo "== unsafe policy still in force (PR 12.1 forbid + per-member inheritance) =="

# Half 1: the workspace lint table still forbids unsafe. `forbid` (not `deny`) is the point —
# it cannot be lifted by a local `#[allow(unsafe_code)]`, so anchor the pattern on "forbid".
grep -qE '^[[:space:]]*unsafe_code[[:space:]]*=[[:space:]]*"forbid"' Cargo.toml \
  || fail "Cargo.toml lost \`unsafe_code = \"forbid\"\` (PR 12.1). walrus runs no Miri job precisely
because the tree is unsafe-free — read $ADR before removing it."

# Half 2: every member still INHERITS it. `[workspace.lints]` reaches a crate only through that
# crate's own `[lints] workspace = true` (Cargo.toml:11 says so) — dropping those two lines is a
# silent opt-out that half 1 alone would not catch. Derive the member list from the manifest so a
# crate added in a later phase cannot evade the loop.
while IFS= read -r member; do
  [ -n "$member" ] || continue
  grep -A3 '^\[lints\]' "$member/Cargo.toml" \
    | grep -qE '^[[:space:]]*workspace[[:space:]]*=[[:space:]]*true' \
    || fail "$member/Cargo.toml no longer inherits \`[lints] workspace = true\`; the workspace
\`forbid(unsafe_code)\` does not reach it. See $ADR."
  echo "   ok: $member inherits [lints] workspace = true"
done < <(sed -nE 's/^members[[:space:]]*=[[:space:]]*\[([^]]*)\].*/\1/p' Cargo.toml \
           | tr ',' '\n' | tr -d '" ')
```

- `Why the precondition is empty` — 0 `unsafe` tokens across 189 files; PR 12.1's `forbid`; PRs
  12.2–12.4 pre-paying the Rust-2024 unsafe lints.
- `Why the crates that link unsafe are the ones Miri cannot run` — `libduckdb-sys 1.10504.0`
  (`Cargo.lock:2137`) bundled into `loader` (`Cargo.toml:23`) and `pg-to-arrow`
  (`Cargo.toml:30`, behind `conformance`); Miri cannot call foreign functions. Then `pg-sink` /
  `control`: real TCP + Postgres, 131 `#[ignore]`d compose-gated tests, 135 `#[tokio::test]`s.
- `Why nightly is a second, independent cost` — `rust-toolchain.toml:4` pins `1.95.0` exactly
  *with a written reason*, and CI's `msrv` job (`ci.yml:492`) exists so the pin and the declared
  MSRV never diverge. Cite `Cargo.toml:71-77` and the `justfile` `bench` note.
- `What walrus does instead` — `forbid` plus the 2024 unsafe lints (12.1–12.4), the Send/Sync

  Static, free, always-on.
- `Re-evaluation trigger` — flip the decision when **either** (a) any member needs
  `unsafe_code = "allow"` or a first-party `unsafe extern` block — then run Miri scoped to that
  crate's unit tests only, never `--workspace`; or (b) a dependency's unsafe is implicated in a
  real defect that static analysis missed. Also record the `-p common` idea and why it is
  unverified here.

## Hints & gotchas

- **`set -euo pipefail` turns a silent `grep` into a silent abort.** `grep -q` exits 1 when it
  finds nothing, and with `-e` that kills the script *before* your message prints. Always chain
  `grep -q … || fail "…"`. Same trap with `grep -c`: it exits 1 on zero matches, so
  `n=$(grep -c … file)` aborts — write `n=$(grep -c … file || true)`.
- **`forbid`, not `deny`, is the thing being guarded.** A `deny` can be lifted by a local
  `#[allow(unsafe_code)]`; `forbid` cannot. If the grep is written loosely enough to match
  `unsafe_code = "deny"` the guard silently weakens.
- **Half 2 is the non-obvious half.** `Cargo.toml:11` says it outright: the workspace lint table
  "only take[s] effect in a member once it declares `[lints] workspace = true`". A new crate added
  without those two lines compiles unsafe happily while half 1 still passes. That is why the
  member list is parsed out of `members = [...]` rather than hard-coded.
- **Avoid `mapfile`/`readarray`** in the member loop — they are bash 4+, and macOS still ships
  bash 3.2 at `/bin/bash`. The `while IFS= read -r … done < <(…)` form above works on both.
- **`sed -i` is not portable.** BSD/macOS needs `sed -i '' …`; GNU needs `sed -i …`. The tamper
  test in the transcript is the BSD form — and restore with `git checkout --`, never by
  re-editing.
- **Docs-only commits skip `gates`.** The `changes` classifier (`ci.yml:28-51`) lists `crates/**`,
  `scripts/**`, `Cargo.*`, `.github/**` … but *not* `docs/**`. If you land only the ADR, the
  `gates` job is skipped and the new guard never runs in CI. Ship the script change in the same
  PR — that is what makes `code: true`.
- **Do not "just add a `workflow_dispatch` Miri job to be safe".** It is explicitly deferred. An
  unrunnable job cannot be verified green in this PR, and a rotting workflow is worse than no
  workflow — it makes the next reader think Miri coverage exists.
- **The ADR is an argument, not an apology.** A note that says only "walrus has no unsafe" is
  worthless the day someone adds unsafe. The durable content is the FFI wall, the nightly/pin
  conflict, the build-cost precedent, and the named trigger.
- Do not add a dependency here (this PR adds none) — anything new must clear `cargo deny`'s
  advisories / 8-license allow-list / bans gate.
- No Rust changes, but the workspace must still be green: `clippy::all` + `warnings` are `deny`,
  and `unwrap`/`expect` are denied in production. Tests, if any were ever added, are **sibling
  `foo_test.rs` files** — never an inline `mod tests {}`.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine
  to regenerate it. Nothing in this PR should come near them.
