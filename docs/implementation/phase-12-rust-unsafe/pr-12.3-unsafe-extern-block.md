# PR 12.3 — Deny missing_unsafe_on_extern and document bundled DuckDB's FFI boundary

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** —

> **Phase:** 12 — Rust unsafe-code policy · **Crates touched:** *(workspace manifest only)* ·
> **Est. size:** S · **Depends on:** PR 12.2 · **Unlocks:** PR 12.4

walrus authors **zero `extern` blocks**
(`grep -rn --include='*.rs' -E '^\s*(unsafe )?extern' crates tests | wc -l` → `0`) — yet it very much
links native code. `crates/loader/Cargo.toml:23` and `crates/pg-to-arrow/Cargo.toml:30` both pull
`duckdb` with `features = ["bundled"]`, so `libduckdb-sys 1.10504.0` (`Cargo.lock:2137`) compiles
DuckDB's C++ from source and owns that engine's generated `extern "C"` declarations. Other
dependencies, including `ring` and `zstd-sys`, also own native boundaries; none is authored by
walrus. The principal explicitly configured native engine is therefore *vendored, not authored* —
and the rustc lint that would catch a
first-party bare `extern "C" { }` sneaking in, `missing_unsafe_on_extern`, is reported `allow` by
`rustc -W help` and is absent from `Cargo.toml`. One line closes it.

## Why — learning objectives

- **Rust 2024 `unsafe extern` blocks** — before 2024 an `extern "C" { }` block carried no `unsafe`
  keyword even though every item inside was unsafe to call. The block-level `unsafe` in 2024 asserts
  something specific: *"I certify these declarations faithfully describe the external ABI."* It does
  not, by itself, make calls safe.
- **Per-item `safe` / `unsafe`** — inside an `unsafe extern` block each item is annotated. Marking an
  item `safe` is a *promise* the compiler cannot check: if the item is actually unsafe to call, the
  `safe` annotation is itself unsound.
- **walrus's native surface** — `duckdb` with the `bundled` feature compiles the whole DuckDB engine
  from C++ inside `libduckdb-sys`. That is why loader/conformance CI builds are minutes long, and it
  is the reason an FFI lint is not hypothetical here even with zero first-party `extern` blocks.

## Hints & gotchas

- **`--all-features` is expensive here and you cannot skip it.** It enables `pg-to-arrow`'s
  `conformance` feature, which pulls the second copy of bundled DuckDB; a cold
  `cargo clippy --all-targets --all-features` can take ~20 minutes (CI is ~3 minutes warm through
  sccache). Budget for it — do not "verify" this PR with a feature-less clippy run.
- Do **not** touch `crates/*/Cargo.toml` or `Cargo.lock`. The `duckdb`/`arrow`/`parquet` versions are
  pinned with `=` on purpose (`Cargo.toml:103-112`): the `arrow.uuid` canonical-extension annotation
  that makes DuckDB read a native `UUID` is behaviour a minor bump could change.
- `missing_unsafe_on_extern` is part of `rust_2024_compatibility`. Enable **only** this lint; the
  group as a whole drags in drop-order and scoping changes that need behavioural review.
- The lint fires on the *declaration*, not the call site — and PR 12.1's `unsafe_code = "forbid"`
  will reject even the correctly-spelled `unsafe extern` form. Both are intended: first-party FFI in
  walrus is a deliberate, reviewed exception, not something a PR can add by accident.
- `crates/pg-to-arrow/src/**` compiles *without* `duckdb` by default; the crate's `conformance`
  tests are the only consumers. If you find yourself editing anything under `crates/`, you have left
  this ticket's scope.
- Do not create an ADR here. Phase 11 has already added Rust-skills notes under
  `docs/implementation/notes/`; the unsafe-policy ADR still belongs to PR 12.6/12.7.
- Keep the `Cargo.toml:17-19` comment style — every lint outside `clippy::all` explains why it needs
  no `priority`. This one is a **rustc** lint, so the reason is different (it is allow-by-default,
  and `warnings = "deny"` cannot reach an allow-level lint); say that, don't copy the clippy wording.
- No `.sql` / `.sqlx` changes (no Docker locally to regenerate the offline cache); no new dependency
  (each must clear `cargo deny`: advisories, the 8-license allow-list, bans).
