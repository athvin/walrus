# PR 12.6 — Guard against fake initialization and record why walrus never needs MaybeUninit

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 12 — Rust unsafe-code policy · **Crates touched:** *(scripts, CI, and a design note)* ·
> **Est. size:** M · **Depends on:** PR 12.5 · **Unlocks:** PR 12.7

This rule's entire *Good* section is unsafe code — `assume_init`, `set_len` — which PR 12.1 made a
workspace-wide compile error. And walrus's one genuine uninitialized-buffer site already gets the
performance benefit **safely**: `crates/pg-sink/src/replication.rs:102` allocates
`BytesMut::with_capacity(16 * 1024)` and fills it via `read_buf` at `:329`, which writes into
`bytes`' `UninitSlice` spare capacity behind a safe API. Measured: **0** uses of
`MaybeUninit` / `mem::uninitialized` / `mem::zeroed` / `assume_init` / `.set_len(` anywhere in
`crates` or `tests`, **0** `vec![0…]` scratch buffers, and all 15 `with_capacity` sites are
length-tracked collections. The two clippy lints for the bad forms (`uninit_vec`,
`uninit_assumed_init`) are **already deny-by-default**, so there is no lint left to promote. The
artifact of this PR is therefore a repo-invariant **guard script** wired into CI, plus an ADR
recording the encapsulation argument so the next reader does not re-litigate it.

## Why — learning objectives

- **The validity-invariant argument** — `mem::uninitialized()` is *immediate* UB for any type whose
  bit patterns are constrained (`bool`, `&T`, `char`, `NonZero*`, enums), and `mem::zeroed()` is UB
  for references and `NonZero*` too. `MaybeUninit<T>` is the only correct spelling because it never
  produces an invalid `T` at all — and `assume_init` is sound only once *every byte* is written.
- **Encapsulation beats adoption** — `bytes::BytesMut` + `AsyncReadExt::read_buf` hand you the
  uninitialized spare capacity as an `UninitSlice` behind a safe API. The right response to a rule
  whose technique is already provided safely by a dependency is a *guard plus a note*, not a rewrite.
- **walrus's replication read path** — `read_message` (`replication.rs:320-334`) is
  **cancellation-safe**: bytes already read stay in `rbuf` when the future is dropped, which is
  exactly why the sink can cancel a read mid-wait for the feedback timer and lose nothing.
- **How to write a `D` verdict honestly** — cite the evidence for *why the technique is unnecessary
  here*, name the lints that already cover the bad forms, and leave behind a mechanical tripwire so
  the claim cannot silently rot.

## Scope

**In scope**

- **Create `scripts/check-unsafe-invariants.sh`** — a grep-based repo-invariant guard, scoped to
  `crates/*/src` and `tests/*/src`, that exits non-zero (printing the offending `file:line`) if any
  of `MaybeUninit`, `mem::uninitialized`, `mem::zeroed`, `assume_init`, `.set_len(` appears in a
  `*.rs` file. House style per `scripts/k8s-validate.sh`.
- **Wire it into CI** as a step in the `gates` job of `.github/workflows/ci.yml`, placed
  *before* `cargo fmt --check` (`:93`) so the sub-second gate runs first — exactly the reasoning the
  comment at `:90-92` already records. `scripts/**` is already in the `changes` filter
  (`ci.yml:44`), so the job triggers on edits to the script itself.
- **Create `docs/implementation/notes/uninit-memory-is-encapsulated.md`** — the ADR. It must:
  - state the **D** verdict and the measured evidence (0 sites, 15 length-tracked `with_capacity`,
    0 `vec![0…]` scratch buffers);
  - explain the encapsulation: `BytesMut::with_capacity` + `read_buf` → `UninitSlice`, and the arrow
    builders' `with_capacity`, which reserve without ever exposing an uninitialized `T`;
  - state explicitly that `clippy::uninit_vec` and `clippy::uninit_assumed_init` are **already
    deny-by-default**, so this PR is *not* pretending to add them;
  - state that PR 12.1's `unsafe_code = "forbid"` already makes the rule's *Good* code a compile
    error, and that the guard exists to catch the forms that would appear *alongside* a deliberate
    forbid downgrade.

**Explicitly deferred** (do *not* build these here)

- **Rewriting any buffer code.** `replication.rs`, `batch.rs`, and `phase_a.rs` are read for evidence
  only; not one line changes.
- **A `bytes`-level benchmark.** No criterion bench, no measurement of `read_buf` vs a zeroed
  scratch buffer.
- **Extending the guard to the forbid-tripwire case** — asserting that `unsafe_code = "forbid"` is
  still present in `Cargo.toml` and that no member replaced `[lints] workspace = true` with its own
  table is **PR 12.7's** addition to this same script. Ship the uninit checks only.
- Any Rust change at all. This PR touches a shell script, a workflow, and a markdown note.

**Conflict with the corpus — resolve it this way.** CONTEXT.md §4 pre-decides **D** for this rule;
that verdict is honoured. But **D here must be argued from encapsulation evidence**
(`BytesMut`/`read_buf`, the arrow builders), *not* from "walrus has no unsafe" — the latter is
PR 12.1's argument and would make this ticket redundant. The ADR must also state that
`clippy::uninit_vec` and `clippy::uninit_assumed_init` are already deny-by-default, so the PR does
not claim credit for adding a lint that was never off.

## Skeleton

```bash
#!/usr/bin/env bash
# check-unsafe-invariants.sh — PR 12.6 repo-invariant guard. walrus never constructs a value from
# uninitialized memory: the one place that genuinely wants uninitialized spare capacity
# (crates/pg-sink/src/replication.rs:102/:329) gets it safely through `bytes::BytesMut` +
# `AsyncReadExt::read_buf`. This script fails the build if a fake-initialization form comes back.
# Rationale: docs/implementation/notes/uninit-memory-is-encapsulated.md
#
#   bash scripts/check-unsafe-invariants.sh
#
# Same command CI runs, so "green locally" predicts "green in CI".
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"

# Scoped to first-party Rust sources only. Vendored crates (libduckdb-sys, bytes, arrow) legitimately
# use these forms; auditing them is `cargo deny`'s job, not this script's.
SCOPE=(crates/*/src tests/*/src)

# The bad forms from the `unsafe-maybeuninit` rule. NOTE: this file lives in scripts/, which is NOT in
# SCOPE, so the pattern cannot match itself.
UNINIT_PATTERN='MaybeUninit|mem::uninitialized|mem::zeroed|assume_init|\.set_len\('

echo "== fake initialization (${UNINIT_PATTERN}) =="
if todo!("grep -rnE the pattern over *.rs under SCOPE; capture hits"); then
  echo "FAIL: uninitialized-memory construction found in first-party sources." >&2
  echo "      walrus gets uninitialized spare capacity safely via BytesMut + read_buf." >&2
  echo "      See docs/implementation/notes/uninit-memory-is-encapsulated.md" >&2
  todo!("print the offending file:line hits to stderr, then exit 1")
fi
echo "   0 sites"

echo "check-unsafe-invariants: PASS"
```

## Hints & gotchas

- **`grep -q` plus `set -e` is a trap.** With `set -euo pipefail`, a `grep` that finds nothing exits
  `1` and kills the script. Capture into a variable inside an `if`/`|| true` and test emptiness —
  do not let a *clean* tree look like a failure.
- **The script must not match itself.** It contains the very strings it hunts for. Keeping `SCOPE`
  to `crates/*/src` and `tests/*/src` (never `.` or `scripts/`) is what makes that safe — and the
  ADR is a `.md`, so a `*.rs`-only scan skips it too. Verify by running the script *after* writing
  it, not before.
- `crates/*/src` and `tests/*/src` are globs the shell expands; `tests/e2e/src/lib.rs` is the only
  match under `tests/`. Benches (`crates/*/benches`) and integration tests (`crates/*/tests`) are
  deliberately out of scope — the record fixed the scope at `src`; do not widen it here.
- `.set_len(` needs the backslash-escaped dot in an ERE, otherwise `.` matches any character and you
  will flag unrelated code. Keep the pattern in one shell variable so the echo, the grep, and the
  ADR cannot drift apart.
- **Do not "adopt" the rule.** `MaybeUninit` in walrus would be unsafe code, which PR 12.1 forbids.
  If you feel tempted to optimise `rbuf`, read `replication.rs:320-321` first: the retained-bytes
  behaviour is *cancellation safety*, a correctness property, not an allocation trick.
- `clippy::uninit_vec` and `clippy::uninit_assumed_init` are **deny-by-default** in clippy. Do not
  add them to `[workspace.lints.clippy]` and call it a delta — the ADR must say they were never off.
- The `gates` job is gated on `changes.outputs.code == 'true'`, and `scripts/**` is inside that
  filter (`ci.yml:44`), so a script-only PR still runs the job. A pure `docs/**` change would skip
  it — which is fine, because a docs-only change cannot introduce an uninit site.
- Make the script executable (`chmod +x`) *and* invoke it as `bash scripts/...` in CI, matching
  `k8s-validate.sh`'s treatment at `ci.yml:594`.
- No Rust changes means `cargo fmt`/`clippy`/`test` should be unchanged from `main` — run them
  anyway; `cargo test -p pg-sink` is the crate whose read path this ADR is about.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache (no Docker locally to
  regenerate it), and add no dependency — any new one must clear `cargo deny`.
