# PR 12.1 — Forbid unsafe code workspace-wide and require SAFETY comments if it ever returns

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** —

> **Phase:** 12 — Rust unsafe-code policy · **Crates touched:** *(workspace manifest only)* ·
> **Est. size:** S · **Depends on:** PR 11.17 · **Unlocks:** PR 12.2

walrus contains **zero unsafe Rust syntax sites** across all 196 Rust files
(`rg -n '\bunsafe\s*(\{|fn\b|trait\b|impl\b)|\bunsafe\s+extern\b' crates tests -g '*.rs'` has
zero hits) and zero `// SAFETY:` comments. A raw word search has two prose-only hits describing
unsafe DDL casts; neither is Rust unsafe syntax. Yet *nothing* stops the next PR from adding an
undocumented `unsafe` block. `Cargo.toml:12-13`
declares only `warnings = "deny"`, and `unsafe_code` is **allow**-by-default (`rustc -W help` reports
`unsafe-code  allow`), so `deny(warnings)` never reaches it: an allow-level lint that never fires
produces no warning to deny. All six members already inherit the workspace table via
`[lints] workspace = true`, so a **two-line** addition to `Cargo.toml` gates the entire tree at once —
`unsafe_code = "forbid"` makes an unsafe block a hard compile error, and
`clippy::undocumented_unsafe_blocks = "deny"` is the belt-and-braces that survives a future,
deliberate downgrade of that forbid in one crate.

## Why — learning objectives

- **rustc lint levels, and `forbid` vs `deny`** — `deny` is an error that a downstream `#[allow]`
  can still override; `forbid` is an error that **cannot** be overridden by any attribute in the
  crate being compiled. Denying `warnings` says nothing about lints whose level is `allow`.
- **How `[workspace.lints]` propagates** — the table in the root `Cargo.toml` only takes effect in a
  member once that member declares `[lints] workspace = true` (`crates/common/Cargo.toml:8-9`,
  `crates/loader/Cargo.toml:15-16`). All six already do, so one edit reaches six crates.
- **walrus's lint-as-policy convention** — safety posture lives in the manifest, not in per-file
  inner attributes. The tree has **zero** crate-level `#![deny(...)]`/`#![forbid(...)]` attributes
  today, and `Cargo.toml:10-11` states the convention in a written comment.

## Skeleton

```toml
# Cargo.toml — [workspace.lints.rust], joining the existing `warnings = "deny"`.
[workspace.lints.rust]
warnings = "deny"
# `unsafe_code` is ALLOW by default (`rustc -W help` → "unsafe-code  allow"), so `warnings = "deny"`
# above never reaches it — an allow-level lint emits no warning to deny. `forbid` (not `deny`) so no
# `#[allow(unsafe_code)]` anywhere in a member can re-open the door. walrus has 0 unsafe syntax sites; this
# keeps it that way. See docs/implementation/phase-12-rust-unsafe/pr-12.1-unsafe-safety-comment.md.
unsafe_code = "forbid"
```

```toml
# Cargo.toml — [workspace.lints.clippy], after `unwrap_used`/`expect_used`.
# Belt-and-braces for the day a crate deliberately steps outside the forbid above (it would replace
# `[lints] workspace = true` with its own table): every `unsafe {}` block must then carry a
# `// SAFETY:` comment. Like unwrap_used/expect_used this is `clippy::restriction`, NOT part of
# `clippy::all`, so there is no group-vs-lint `priority` to juggle.
undocumented_unsafe_blocks = "deny"
```

```rust
// NOT committed — the manual proof that the gate bites. Paste into any member's src/lib.rs,
// run `cargo check -p <crate>`, confirm the error, then delete it. (A committed compile-fail test
// would need a `trybuild` dev-dependency, which must clear `cargo deny` — out of scope for a
// two-line manifest change.)
fn _gate_probe() {
    // before this PR: compiles silently.
    // after:  error[E0133]: usage of an `unsafe` block
    //         note: the lint level is defined here / `#[forbid(unsafe_code)]` on by default
    let _ = unsafe { std::mem::transmute::<u32, i32>(1) };
}
```

## Hints & gotchas

- **`forbid` cannot be locally overridden — that is the feature and the footgun.** If a future
  in-crate macro expansion ever emits `unsafe` (none does today: `serde`, `thiserror`, `criterion`,
  and `tokio::main` all expand to safe code), no `#[allow(unsafe_code)]` will rescue it. The correct
  escape hatch is a *deliberate* per-crate `[lints]` table replacing `workspace = true` — which
  PR 12.7's guard is designed to catch. Do not pre-emptively weaken this to `deny`.
- `clippy::undocumented_unsafe_blocks` is a **restriction** lint, and `clippy::restriction` is not
  part of `clippy::all`. That is exactly why `unwrap_used`/`expect_used` at `Cargo.toml:20-22` need
  no `priority = -1` on `all` — keep that comment style and that reasoning.
- With `unsafe_code = "forbid"` in force the clippy lint can never actually fire. That is fine and
  intended: it is the second layer, and it costs nothing. Say so in the comment so a later reader
  does not "clean up" the apparently-dead line.
- Use `cargo clippy --all-targets --all-features` exactly as CI does (`.github/workflows/ci.yml:96`).
  `--all-features` turns on `pg-to-arrow`'s `conformance` feature, which compiles **bundled DuckDB
  from C++ source** — expect a multi-minute cold run locally; the warm run is fast.
- Benches (`harness = false`) and the e2e harness carry file-level `#[allow]`s for unwrap/expect —
  they do **not** carry any unsafe. `--all-targets` compiles them, so if one did, this PR would
  fail immediately; confirm the unsafe-syntax probe is empty across `crates` **and** `tests` before
  editing. Do not treat prose such as "unsafe DDL cast" as Rust unsafe syntax.
- Tests in walrus are **Go-style sibling files** (`src/foo.rs` → `src/foo_test.rs` wired by
  `#[cfg(test)] #[path = "foo_test.rs"] mod tests;`), not inline `mod tests {}`. Nothing in this PR
  needs a test file, but do not invent an inline one.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. No new dependency is needed here; any that you reach for must clear
  `cargo deny` (advisories, the 8-license allow-list, bans).
- `clippy::all` and `warnings` are already `deny` workspace-wide, so a lint added to `Cargo.toml`
  takes effect in every member with no per-crate edit.
