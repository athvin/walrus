# PR 25.3 — Narrow the streamed-txn survivor closure from &self to the aborted set

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 25 — Rust closures · **Crates touched:** `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 25.2 · **Unlocks:** PR 25.4

`crates/pg-sink/src/stream_txn.rs:88` is the **only** production closure in walrus that reaches
through `self`: `.filter(move |c| !self.aborted.contains(&c.sub_xid))`. A `move` closure truncates
its capture path at the `*self` deref, so it captures the whole `&StreamedTxn` rather than just the
`aborted: HashSet<u32>` field it actually reads. The consequence is visible three lines up — the
accessor is `#[cfg(test)]`-gated at :84, because `on_stream_commit` destructures the txn into owned
`changes` / `staged` / `aborted` and therefore cannot call it, and so re-inlines the identical
predicate at :398. The doc comment at :83 admits it verbatim: *"Commit materialisation inlines this
filter"*. After this PR the survivor rule is written **once**, `survivors()` is live production code
used by the commit path, and no production `move` closure captures `self`.

## Why — learning objectives

- **RFC 2229 disjoint closure capture (edition 2021)** — a closure captures the minimal *place* it
  uses (`config.threshold`, not `config`), but `move` still captures the whole named place, and
  `self.aborted` behind a reference truncates to `*self`. Binding the field to a local first is the
  fix the rule prescribes.
- **Duplication is the symptom, not the cost** — the over-broad capture is what forced the
  `#[cfg(test)]` gate, and the gate is what forced the copy-pasted predicate. Fixing the capture
  deletes both.
- **Streamed-transaction survivorship in logical decoding** — which buffered rows survive a
  `Stream Abort {sub != top}`, and why the spill side and the in-memory side apply the same rule to
  two different element types.

**In scope**

- Rewrite `StreamedTxn::survivors()` so it binds `let aborted = &self.aborted;` *before* the closure
  and filters on that local — narrowing the capture from `&StreamedTxn` to `&HashSet<u32>`.
- Drop the `#[cfg(test)]` gate at :84 and delete the "Commit materialisation inlines this filter"
  sentence, replacing it with the fact that the commit path now calls it.
- Restructure `on_stream_commit` so it stops destructuring the whole txn: bind `mut txn`, take the
  spills with `std::mem::take(&mut txn.staged)` for the publish loop, then iterate
  `txn.survivors()` for the materialise loop.
- Result: `aborted.contains(&c.sub_xid)` is written exactly **once**, inside `survivors()`.

**Explicitly deferred** (do *not* build these here)

- **Do not reorder `on_stream_commit`.** Spills are published *before* the in-memory survivors are
  materialised; that ordering is part of the commit-visibility contract. This is a capture fix, not
  a sequencing change.
- **Do not touch the spill-side check** `aborted.contains(&spill.sub_xid)` at :382. Its element type
  is `StagedSpill`, not `StreamedChange` — folding the two together would need a trait or a closure
  parameter and buys nothing.
- No change to sub-transaction abort semantics. `crates/pg-sink/tests/subtransaction_exclusion.rs`
  and `tests/e2e/tests/subtxn_abort.rs` must stay green **unchanged** — do not edit them to fit.
- Not a visibility change: `survivors()` stays private to the module (`fn`, not `pub fn`).
- Do not touch `on_stream_abort`'s `txn.staged.retain(|s| s.sub_xid != sub_xid)` at :336; it already
  captures only `sub_xid` (a `Copy` local).

## Hints & gotchas

- **`survivors()` must be reachable from production or the build breaks.** `[workspace.lints.rust]`
  sets `warnings = "deny"`, so an unused private fn is a hard error, not a warning. Removing
  `#[cfg(test)]` is only safe *because* `on_stream_commit` now calls it — do both edits in one commit.
- **You cannot destructure and still call the method.** `let StreamedTxn { changes, staged, aborted,
  .. } = txn;` partially moves `txn`. `std::mem::take(&mut txn.staged)` is the surgical alternative:
  it leaves an empty `Vec` behind and keeps `txn` whole.
- **`for spill in std::mem::take(&mut txn.staged)`** takes the mutable borrow, ends it, and yields
  owned `StagedSpill`s — so reading `txn.aborted` inside the loop body is fine. Writing
  `for spill in &mut txn.staged` would instead hold the mutable borrow across the read: no compile.
- **The materialise loop only borrows.** Check before you rewrite: the body reads `c.oid`, `c.op`,
  `c.lsn`, `c.sub_xid` and `&c.values`, so an iterator of `&StreamedChange` is exactly what it wants.
  Nothing there needs owned values.
- **Removing `move` entirely also compiles** — but do not. The rule's prescription is *bind the field
  to a local*, and keeping `move` on the narrowed local documents that the closure owns the `&HashSet`
  reference, not the txn. Match the rule.
- **The perl probe is deliberately crude.** It flags any production `move |…|` whose body mentions
  `self.`. Keep it at zero rather than "explaining" a hit; if a future PR genuinely needs one, that
  is a conversation, which is the point of the guard.
- **Count `survivor_count` calls, not tests.** Baseline `77b7695` has three calls across two tests;
  the new commit-path agreement test adds the fourth. The three baseline calls remain byte-identical.
- `unwrap`/`expect` are `deny` in production; `clippy.toml` re-allows them under `#[cfg(test)]`, so
  the sibling `stream_txn_test.rs` may use them freely.
- Unit tests are **Go-style sibling files**. `stream_txn_test.rs` already exists and is wired at the
  bottom of `stream_txn.rs` — add to it, never introduce an inline `mod tests { … }`.
- **Do not touch `.sql` files or the `.sqlx` offline cache.** No Docker locally to regenerate it;
  nothing in this PR is sqlx-adjacent, so any `.sqlx` churn means you edited the wrong thing.
