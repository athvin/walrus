# PR 25.5 — Replace redundant method-call closures with function paths and deny the lint

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 25 — Rust closures · **Crates touched:** `pg-to-arrow`, `pg-sink`, `loader` ·
> **Est. size:** M · **Depends on:** PR 25.4 · **Unlocks:** PR 26.1

The static side of `closure-static-vs-dyn`'s decision table is already walrus's default:
`Box<dyn Fn>` / `Arc<dyn Fn>` is **0** repo-wide, and all three callback parameters are generic
(`impl FnMut`, `R: FnMut`, `F: FnMut`). The one deliberate stored `dyn` callback is
`Arc<dyn Clock>` at 7 production sites — a single-method `Send + Sync` trait documented at
`crates/pg-sink/src/batch.rs:19-24` as existing *"for that test seam, not as dead generality
(audited PR 8.5, kept by design)"*. What is **not** gated is the cheapest static form:
`clippy::redundant_closure_for_method_calls` reports **7** deduped sites (pg-to-arrow 3, pg-sink 3,
loader 1) where a fresh anonymous closure type stands in for a zero-sized `fn` item that already
satisfies the `Fn` bound. This PR rewrites all 7 to bare function paths and denies the lint, so the
cheapest form is the enforced one. It also records — in a code comment, not a refactor — why the
`Clock` trait and arrow's `Box<dyn ArrayBuilder>` stay dynamic.

## Why — learning objectives

- **Function items vs closures** — every closure is a *distinct anonymous type*, so
  `.map(|u| u.into_bytes())` monomorphises one more instantiation per site, while
  `uuid::Uuid::into_bytes` is a zero-sized `fn` item usable at any `Fn`/`FnMut`/`FnOnce` bound.
- **Reading a method path as a function** — `fn is_nullable(&self) -> bool` is
  `fn(&Field) -> bool` as a path, which is exactly what `Iterator::all` wants when `Item = &Field`;
  auto-ref is what the closure was silently doing for you.
- **Where walrus deliberately pays for dynamic dispatch** — the injectable `Clock` test seam
  (`Arc<dyn Clock>`, 7 sites) and arrow's builder downcasts on the row-encode hot path
  (`Box<dyn ArrayBuilder>` / `&mut dyn ArrayBuilder`, 10 sites), which `[profile.release]
  lto = "thin"` was chosen to inline through.
- **Pedantic lints and lint groups** — `redundant_closure_for_method_calls` is `clippy::pedantic`,
  not in `clippy::all`, so it needs no `priority` juggling in `[workspace.lints.clippy]`.

## Scope

**Conflict — resolve it explicitly; do not apply the rule blind.**

1. **Phase 33 (`lint-*`, 13 PRs) also promotes clippy lints.** This promotion is closure-specific and
   lands **here**, together with its 7 fixes. Phase 33 must treat
   `redundant_closure_for_method_calls` as already-owned and must not re-add the key — a duplicate
   key in the `[workspace.lints.clippy]` table is a TOML parse error. Re-measure with
   `grep -n 'redundant_closure_for_method_calls' Cargo.toml` before adding it, and if an earlier
   phase got there first, keep only the fixes.
2. **The rule's decision table would send you to `Box<dyn Fn>` for the stored `Clock` callback.**
   walrus deliberately uses a named single-method trait instead: it is nameable, mockable, `Send +
   Sync`, and was audited and kept in PR 8.5. This ticket **records** that choice in a comment; it
   does **not** convert it, and a reviewer must reject any diff that does.

**In scope**

- Add `redundant_closure_for_method_calls = "deny"` to `[workspace.lints.clippy]` in `Cargo.toml`
  (pedantic, not in `clippy::all`, so no `priority`), with a one-line comment in the house style.
- Rewrite all 7 reported sites to bare function paths (list in *Files to create / modify*).
- Extend the `Clock` doc comment at `crates/pg-sink/src/batch.rs:19-24` with one sentence naming the
  alternative the rule suggests (`Box<dyn Fn() -> Instant>`) and why the named trait wins here.

**Explicitly deferred** (do *not* build these here)

- **Do not convert `Arc<dyn Clock>`** (7 production sites: `batch.rs:60/82`, `snapshot.rs:107`,
  `stream_txn.rs:99/109`, `consume.rs:409/420`).
- **Do not convert arrow's `Box<dyn ArrayBuilder>` / `&mut dyn ArrayBuilder`** (10 sites in
  `crates/pg-to-arrow/src/batch.rs`). That dispatch is arrow-rs's own API on the row-encode hot path
  and is precisely what thin LTO was selected to inline through (`Cargo.toml:70-76`).
- **Do not enable `clippy::pedantic` wholesale.** The committed evidence records 51 distinct
  pedantic/nursery lints over 1192 sites; turning the group on is Phase 33's problem, not a
  side effect of this PR.
- No new dependency, and no signature changes — every rewrite must be expression-local.
- Do not "fix" `map_err(|_| Error::ValueParse { … })` in `uuid_enum.rs:54-58` or any other closure
  that constructs a value; those are not method calls and the lint does not flag them.

/// Injectable clock so `max_fill` is testable without sleeping. Production uses [`SystemClock`]; the
/// single production impl is deliberate — the trait exists **for that test seam**, not as dead
/// generality (audited PR 8.5, kept by design).
///
/// `closure-static-vs-dyn` would point a *stored* callback at `Box<dyn Fn() -> Instant>`. A named,
/// object-safe trait is the better answer here: it is `Send + Sync` (the batchers cross tasks), it

pub trait Clock: Send + Sync {

## Hints & gotchas

- **Check what a method path resolves to before you paste it.** `Iterator::map` on `pk_cols.iter()`
  yields `&String`, so the path must be `String::as_str` (`fn(&String) -> &str`) — `str::as_str`
  does not exist and `AsRef::as_ref` would need a turbofish. When in doubt, let the compiler tell
  you: paste the path and read the "expected/found" diagnostic.
- **Trait methods need the trait path.** `to_string` lives on `ToString`, not on `u32`, so
  `ToString::to_string` is the spelling. Same shape as `Field::is_nullable`, which *is* inherent.
- **`clippy --fix` will do most of this**, but review every hunk: the lint occasionally suggests a
  path that changes auto-deref behaviour, and three of the seven sites are in test files where a
  wrong path still compiles but asserts something subtly different.
- **`--all-targets` matters.** Three of the seven sites are `*_test.rs` / `tests/*.rs`. A clippy run
  without `--all-targets` will look green while CI (which uses `--all-targets --all-features`) fails.
- **Re-measure the manifest before adding the key.** If Phase 33 (or any reordering) landed
  `redundant_closure_for_method_calls` first, adding it again is a TOML duplicate-key parse error
  that breaks the whole workspace, not a harmless repeat.
- **Do not touch the `Box<dyn ArrayBuilder>` downcasts.** They are arrow-rs's API surface, not a
  walrus design choice, and `crates/pg-to-arrow/src/batch.rs` is the hot per-value path — the place
  where a well-meaning "make it generic" rewrite costs the most and buys the least.
- **Do not touch `.sql` files or the `.sqlx` offline cache.** There is no Docker on this machine to
  regenerate the cache; `reload_export.rs` is sqlx-adjacent, so keep the edit to the `.iter().map(…)`
  expression and leave every query alone.
- `unwrap`/`expect` are `deny` in production; `clippy.toml` re-allows them under `#[cfg(test)]`, and
  integration tests under `tests/` carry the file-level `#![allow(…)]` header — leave those headers
  in place when you edit `pgoutput_vectors.rs` and `parquet_put.rs`.
- Unit tests are **Go-style sibling files** (`schema_test.rs` is one); never convert a site by
  introducing an inline `mod tests { … }`.
