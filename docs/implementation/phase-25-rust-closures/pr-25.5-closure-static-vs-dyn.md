# PR 25.5 — Replace redundant method-call closures with function paths and deny the lint

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common,pg-to-arrow

> **Phase:** 25 — Rust closures · **Crates touched:** `common`, `pg-to-arrow`, `pg-sink`, `loader` ·
> **Est. size:** M · **Depends on:** PR 25.4 · **Unlocks:** PR 26.1

At source parent `e24f365`, walrus already makes the rule's dispatch decision deliberately. No
production code stores a `Box<dyn Fn>` / `Arc<dyn Fn>`, and the authored three-spelling `FnMut`
census has collapsed to one declaration: `reload_signal::extract` accepts
`mut pred: impl FnMut(&T) -> bool`. The two repeated async callbacks became borrowing
`AsyncFnMut` bounds in PR 14.4, and PR 25.2 added a bounded `impl FnOnce` transaction seam. More
importantly, PR 19.5 removed all seven `Arc<dyn Clock>` owners: the sealed, `Debug` clock trait is
now carried as `C: Clock`, with a `deadline` convenience method and delegating `Arc<T>` / `&T`
implementations. Re-litigating that finished static-dispatch work would be regression, not scope.

The remaining live finding is narrower. A forced
`clippy::redundant_closure_for_method_calls` audit reports exactly **7** sites (pg-to-arrow 3,
pg-sink 3, loader 1) where a non-capturing closure only forwards its argument to a method. Both
forms are allocation-free and statically dispatched; the direct method item simply states the
callable identity without a redundant adapter. This PR rewrites those seven sites and denies the
pedantic lint so the policy remains enforced. Arrow's erased `ArrayBuilder` storage remains the
deliberate dynamic case: ten storage/signature declarations, plus PR 16.2's local typed slice view,
produce eleven textual matches in `batch.rs`.

## Why — learning objectives

- **Function items vs non-capturing closures** — both are zero-allocation static callables, but a
  closure introduces a distinct anonymous adapter type. `uuid::Uuid::into_bytes` states the method
  identity directly and is usable at any compatible `Fn`/`FnMut`/`FnOnce` bound.
- **Reading a method path as a function** — `fn is_nullable(&self) -> bool` is
  `fn(&Field) -> bool` as a path, which is exactly what `Iterator::all` wants when `Item = &Field`;
  auto-ref is what the closure was silently doing for you.
- **Where walrus deliberately pays for dynamic dispatch** — Arrow needs heterogeneous per-column
  builders, so `Vec<Box<dyn ArrayBuilder>>` and `&mut dyn ArrayBuilder` are honest erased-storage
  boundaries. The clock seam is the contrast: named trait, generic owner, static dispatch.
- **Do not turn an optimization rule into a benchmark claim** — `docs/benchmarks.md` records thin
  LTO as an honest null on the single-crate append-row microbench. It is kept for cross-crate release
  hygiene, not as proof that an `ArrayBuilder` vtable is free or that these seven rewrites are faster.
- **Pedantic lints and lint groups** — `redundant_closure_for_method_calls` is `clippy::pedantic`,
  not in `clippy::all`, so it needs no `priority` juggling in `[workspace.lints.clippy]`.

## Hints & gotchas

- **Check what a method path resolves to before you paste it.** `Iterator::map` on `pk_cols.iter()`
  yields `&String`, so the path must be `String::as_str` (`fn(&String) -> &str`) — `str::as_str`
  does not exist and `AsRef::as_ref` would need a turbofish. When in doubt, let the compiler tell
  you: paste the path and read the "expected/found" diagnostic.
- **Trait methods need the trait path.** `to_string` lives on `ToString`, not on `u32`, so
  `ToString::to_string` is the spelling. Same shape as `Field::is_nullable`, which *is* inherent.
- **`RecordBatch` is not imported in `parquet_put.rs`.** Use the fully qualified
  `arrow::record_batch::RecordBatch::num_rows` path so the seventh rewrite stays expression-local;
  do not add an otherwise-unneeded import merely to match the stale authored skeleton.
- **Rewrite the seven sites manually.** A workspace-wide `clippy --fix` can edit unrelated
  diagnostics and cross the task boundary. Three sites are test-only, so review their inferred item
  types rather than assuming every auto-deref suggestion is interchangeable.
- **`--all-targets` matters.** Three of the seven sites are `*_test.rs` / `tests/*.rs`. A clippy run
  without `--all-targets` will look green while CI (which uses `--all-targets --all-features`) fails.
- **The test-first failure is the missing policy, not changed conversion behavior.** The seven
  forwarding closures already produce the right bytes. Commit the exact manifest-count assertion,
  observe 0 vs 1, and leave it unchanged while adding the lint and expression rewrites.
- **Re-measure the manifest before adding the key.** The expected branch-point count is zero. A
  nonzero result means the baseline moved and requires another re-authoring pass; adding a duplicate
  is a TOML parse error, while silently omitting the promised policy would violate the outcome.
- **Do not touch the Arrow builder topology.** The stable census is ten storage/signature
  declarations, while a raw type-spelling scan prints eleven lines because PR 16.2 explicitly types
  a local mutable slice. Do not mistake that view for a new allocation or "fix" the count to ten.
- **Do not edit the clock explanation.** It already says `C: Clock` is statically dispatched and
  documents the seal, `Debug`, `deadline`, and wrapper impls. A `Box<dyn Fn>` comparison would now
  describe a baseline that PR 19.5 intentionally removed.
- **Do not touch `.sql` files or the `.sqlx` offline cache.** There is no Docker on this machine to
  regenerate the cache; `reload_export.rs` is sqlx-adjacent, so keep the edit to the `.iter().map(…)`
  expression and leave every query alone.
- `unwrap`/`expect` are `deny` in production; `clippy.toml` re-allows them under `#[cfg(test)]`, and
  integration tests under `tests/` carry the file-level `#![allow(…)]` header — leave those headers
  in place when you edit `pgoutput_vectors.rs` and `parquet_put.rs`.
- Unit tests are **Go-style sibling files** (`schema_test.rs` is one); never convert a site by
  introducing an inline `mod tests { … }`.
