# PR 25.2 — Add a FnOnce transaction seam to TableDb so rollback cannot be forgotten

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 25 — Rust closures · **Crates touched:** `loader` · **Est. size:** M ·
> **Depends on:** PR 25.1 · **Unlocks:** PR 25.3

Production has exactly three closure-typed parameters and every one is `FnMut` —
`pg-sink/src/reload_signal.rs:222` (`impl FnMut(&T) -> bool`), `reload.rs:71` (`R: FnMut() -> RFut`)
and `bootstrap.rs:150` (`F: FnMut() -> Fut`) — all correctly bounded at the weakest trait that
works. The **once-called** end of the hierarchy is unexercised: `FnOnce` appears **0** times in
production (its only occurrence in the whole tree is `crates/common/src/config_test.rs:24`).
Meanwhile the loader hand-rolls the same `BEGIN TRANSACTION;` / `ROLLBACK on error` / `COMMIT;`
discipline **twice** — `phase_b.rs:81/84/87` and `compaction.rs:38/41/56` — where forgetting the
`ROLLBACK` on some future third caller would leave a half-transformed mirror behind an open
transaction. This PR gives `TableDb` one `in_txn` seam bounded at `FnOnce`, because the body is
called exactly once and may consume its captures, and deletes both hand-rolled copies.

## Why — learning objectives

- **The `Fn` ⊇ `FnMut` ⊇ `FnOnce` hierarchy** — `FnOnce` is implemented by *every* closure, so it is
  the widest bound; picking it here is not laziness, it is the precise statement "this body runs once
  and may move what it captured".
- **RAII-by-closure** — wrapping a resource protocol (begin/commit/rollback) in a higher-order
  function is how you make the unhappy path unforgettable when there is no `Drop` guard available.
- **DuckDB transaction discipline in the loader** — Phase-B transform and the compaction full-rebuild
  must both roll back to an *intact* mirror; readers on another connection see the old table until
  `COMMIT`.
- **Bound placement** — `impl FnOnce(&Connection) -> Result<T, LoaderError>` in argument position
  (APIT) versus a named `F:` parameter, and why no `Send` bound belongs here.

## Read first

  take the trait/captures/calls table from it, plus the note that `FnMut` needs `mut f` at the call

- `crates/loader/src/compaction.rs:27-59` — `full_rebuild`. Same protocol, but the error arm is

- `crates/loader/src/compaction.rs:66-80` — `full_rebuild_abortable`, which needs

- `crates/pg-sink/src/reload_signal.rs:220-232`, `crates/pg-sink/src/reload.rs:64-73`,
  `crates/pg-sink/src/bootstrap.rs:146-152` — the three existing `FnMut` bounds. Read them to see

## Scope

**In scope**

- `TableDb::in_txn` in `crates/loader/src/duck.rs`: `BEGIN TRANSACTION;`, run the closure, then
  `COMMIT;` on `Ok` and best-effort `ROLLBACK;` on `Err`, propagating the body's error unchanged.
  Bounded `impl FnOnce(&duckdb::Connection) -> Result<T, LoaderError>`.
- Rewrite `run_phase_b` to `ctx.db.in_txn("transform", |conn| apply_transform(conn, &t, &after))?`.
- Rewrite `full_rebuild` / `full_rebuild_abortable` to take `&TableDb` instead of
  `&duckdb::Connection` (they need the seam) and to keep their cancel-to-`Ok(())` mapping on the
  *outside* of `in_txn`.
- Update the 5 call sites that pass `.conn()` today: `crates/loader/src/apply_loop.rs:99`,
  `crates/loader/tests/compaction.rs:90/122/138/207/223` and `crates/loader/tests/shutdown.rs:290`.
- Extend `crates/loader/src/duck_test.rs` with the seam's two contracts: a committing body persists,
  and an erroring body leaves the table exactly as it was.

**Explicitly deferred** (do *not* build these here)

- **Do not widen or narrow the three existing `FnMut` bounds.** They are already the weakest trait
  their bodies need — `retry_transient` and `lease_guarded_export` genuinely call `op`/`renew` in a
  loop. Changing them to `Fn` or `FnOnce` would be a regression in both directions.
- **No `Send` bound.** `duckdb::Connection` is `!Send` by design; the loader runs one per worker on a
  `LocalSet`. Adding `+ Send` would make the seam unusable at both call sites.
- Do not touch `control`'s sqlx transactions. They have their own `Transaction<'_, Postgres>` RAII
  type and no closure seam is needed.
- Compaction keeps its own `cancel.is_cancelled()` → `Ok(())` drain-abort mapping (PR 3.12) and its
  own `LoaderError::Duck(format!("full rebuild {}: …"))` message — both stay outside `in_txn`.
- No new `#[cfg(test)]`-only helper on `TableDb`; `in_txn` is production API used by production code.

```rust
// crates/loader/src/duck.rs — inside `impl TableDb`, next to `conn()`.

/// Run `f` inside one DuckDB transaction. `COMMIT;` on `Ok`, best-effort `ROLLBACK;` on `Err` —
/// so a caller cannot forget the unhappy path. `what` names the transaction in the begin/commit
/// error contexts (`"begin {what} txn"` / `"commit {what} txn"`), keeping PR 25.1's message shapes.
///
/// Bounded `FnOnce`: the body runs **exactly once** and may consume what it captured. That is the
/// weakest bound that works, so it accepts move-consuming closures too. No `Send` — the connection
/// is `!Send` and lives on one worker's `LocalSet`.
pub fn in_txn<T>(
    &self,
    what: &str,
    f: impl FnOnce(&duckdb::Connection) -> Result<T, LoaderError>,
) -> Result<T, LoaderError> {
    self.conn
        .execute_batch("BEGIN TRANSACTION;")
        .map_err(duck_err(|| format!("begin {what} txn")))?;
    match f(&self.conn) {
        Ok(value) => {
            todo!("COMMIT; mapped with duck_err(|| format!(\"commit {what} txn\")), then Ok(value)")
        }
        Err(e) => {
            todo!("best-effort `let _ = self.conn.execute_batch(\"ROLLBACK;\");` then Err(e)")
        }
    }
}
```

```rust
// crates/loader/src/compaction.rs — the signature moves from `&Connection` to `&TableDb` so the
// seam is reachable; the drain-abort mapping stays OUTSIDE the closure.
pub fn full_rebuild(
    db: &crate::duck::TableDb,
    t: &TransformSql,
    cancel: &CancellationToken,
) -> Result<(), LoaderError> {
    if cancel.is_cancelled() {
        return Ok(()); // shutting down — don't even start the heavy rewrite (PR 3.12)
    }
    let boundary = t.latest_truncate(db.conn(), &Lsn::ZERO)?;
    let rewrite = db.in_txn("rebuild", |conn| {
        conn.execute_batch(&t.render_rebuild(&boundary))
            .map_err(duck_err(|| format!("full rebuild {}", t.table())))
    });
    match rewrite {
        Ok(()) => Ok(()),
        // Interrupted by the drain (the watcher called `interrupt()`): `in_txn` already rolled back,
        // the old mirror is intact, and the rebuild re-runs next cycle. NOT an error.
        Err(_) if cancel.is_cancelled() => {
            todo!("tracing::info!(table = t.table(), \"full-rebuild aborted by drain (rolled back)\"); Ok(())")
        }
        Err(e) => Err(e),
    }
}
```

## Hints & gotchas

- **The `FnOnce` count is not 0 by the time you start.** PR 25.1 lands `duck_err`, whose return type
  already spells `impl FnOnce`. Re-measure before you claim a number: this ticket's contribution is
  the first `FnOnce` **bound on a parameter**, which the `impl FnOnce(&duckdb::Connection)` grep
  isolates cleanly.
- **`ROLLBACK` must stay best-effort.** `let _ = …execute_batch("ROLLBACK;")` — if the rollback
  itself fails you still owe the caller the *original* error, not the rollback's. Returning the
  rollback error would hide the real cause and break the `Quarantine`/`Duck` classification.
- **Do not swallow the body's error type.** `in_txn` returns the body's `LoaderError` untouched, so
  `apply_transform`'s `"transform {table}: …"` and the rebuild's `"full rebuild {table}: …"` keep
  reaching `main`'s exit-code mapping.
- **One accepted semantic widening:** with the cancel check now outside `in_txn`, a `COMMIT;` that
  fails *while cancelled* maps to `Ok(())` rather than `Err`. That is sound — a failed commit aborts
  the transaction, so the mirror is intact and the idempotent rebuild re-runs — but say so in the PR
  body and in a code comment rather than letting a reviewer discover it.
- **`full_rebuild` is public and used by integration tests.** Changing its first parameter is a
  breaking change *inside the workspace only* (walrus publishes nothing), but you must update
  `crates/loader/tests/compaction.rs` and `crates/loader/tests/shutdown.rs` in the same commit or the
  workspace will not build.
- **`latest_truncate` runs before `BEGIN`.** Keep it there; it is a read that does not need the
  transaction, and moving it inside the closure would change what the boundary resolution sees.
- **No `Send` bound, ever.** `duckdb::Connection` is `!Send`; the `RefCell` in `TableDb` documents
  the single-threaded-per-worker model. A stray `+ Send` will produce a confusing "cannot be sent
  between threads safely" error at both call sites.
- `unwrap`/`expect` are `deny` in production; `clippy.toml` re-allows them under `#[cfg(test)]`, so
  the sibling `duck_test.rs` may use them. Integration tests under `tests/` carry the file-level
  `#![allow(clippy::unwrap_used, clippy::expect_used)]` header instead.
- **Do not touch `.sql` files or the `.sqlx` offline cache.** No Docker locally to regenerate it; the
  DuckDB statements here are inline string literals, not sqlx queries.
