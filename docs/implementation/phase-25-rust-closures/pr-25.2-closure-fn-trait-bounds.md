# PR 25.2 — Add a FnOnce transaction seam to TableDb so rollback cannot be forgotten

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** loader

> **Phase:** 25 — Rust closures · **Crates touched:** `loader` · **Est. size:** M ·
> **Depends on:** PR 25.1 · **Unlocks:** PR 25.3

At baseline `bbd0bde`, production has **five logical closure-typed parameters** (six source
declarations because the `DuckResultExt::duck_with` trait signature is repeated by its impl):
`unknown_variant` and `duck_with` use `FnOnce`; `extract` uses `FnMut`; and `retry_transient` plus
`lease_guarded_export` use Rust 2024's borrowing `AsyncFnMut`. That inventory is the accumulated
result of PR 13.12 (`duck_with` and the direct, non-closure `duck_err` constructor), PR 14.4 (the two
`AsyncFnMut` conversions), and PR 24.4 (`unknown_variant`). PR 25.1 then landed docs-only evidence
that its proposed returned mapper was superseded by PR 13.12; it added no callback or Rust source.

The residual rule fit remains concrete and bounded. The loader hand-rolls the same
`BEGIN TRANSACTION;` / rollback-on-body-error / `COMMIT;` discipline **twice** — in
`run_phase_b` and `full_rebuild` — and both copies must preserve an intact mirror if their body
fails. This PR gives `TableDb` one `in_txn` seam bounded at `FnOnce`, because each transaction body
is called exactly once and may consume its captures, and deletes both hand-rolled copies. It does
not change any of the five existing callback contracts.

## Why — learning objectives

- **The `Fn` ⊇ `FnMut` ⊇ `FnOnce` hierarchy** — `FnOnce` is implemented by *every* closure, so it is
  the widest bound; picking it here is not laziness, it is the precise statement "this body runs once
  and may move what it captured".
- **RAII-by-closure** — wrapping a resource protocol (begin/commit/rollback) in a higher-order
  function is how you make the unhappy path unforgettable when there is no `Drop` guard available.
- **DuckDB transaction discipline in the loader** — Phase-B transform and the compaction full-rebuild
  must both roll back to an *intact* mirror; readers on another connection see the old table until
  `COMMIT`.
- **Bound placement** — `impl FnOnce(&Connection) -> Result<T, LoaderError>` in argument position
  (APIT) versus a named `F:` parameter, and why no `Send` bound belongs here.

**In scope**

- Rewrite `full_rebuild` / `full_rebuild_abortable` to take `&TableDb` instead of

  *outside* of `in_txn`. The cancellation guard must recognize only the rebuild-body error
  (`"full rebuild {table}"`); a coincident begin/commit failure must remain an error, as it is today.
- Update all seven calls that pass `.conn()` today: `crates/loader/src/apply_loop.rs:113`,
  `crates/loader/tests/compaction.rs:95/127/143/212/228`, and

- Extend `crates/loader/src/duck_test.rs` with the seam's three contracts: a committing body persists,

  transaction, and a body that actually consumes a moved capture compiles.

**Explicitly deferred** (do *not* build these here)

- **Do not alter any of the five existing callback contracts.** `retry_transient` and
  `lease_guarded_export` need borrowing `AsyncFnMut` because they await repeated calls; `extract`
  needs `FnMut`; `duck_with` and `unknown_variant` are already correctly `FnOnce`.
- **No `Send` bound.** The transaction body is invoked synchronously, exactly once, on the owning
  loader worker's `LocalSet`; no thread or task boundary requires `Send`. `TableDb` and
  `duckdb::Connection` are themselves `Send + !Sync`, but their shared references are not `Send`.
  Do not restate the obsolete claim that the owned connection is `!Send`.
- Do not touch `control`'s sqlx transactions. They have their own `Transaction<'_, Postgres>` RAII
  type and no closure seam is needed.
- Compaction keeps its own `cancel.is_cancelled()` → `Ok(())` drain-abort mapping (PR 3.12). The
  closure still constructs the direct body error with operation `"full rebuild {table}"` and the
  typed DuckDB source; `in_txn` rolls it back and returns it unchanged before compaction decides
  whether the interrupt is an intentional abort.
- Do not broaden that cancellation arm to swallow `begin rebuild txn` or `commit rebuild txn`
  errors merely because the token became cancelled at the same time.
- No new `#[cfg(test)]`-only helper on `TableDb`; `in_txn` is production API used by production code.

```rust
// crates/loader/src/duck.rs — inside `impl TableDb`, next to `conn()`.

/// Run `f` inside one DuckDB transaction. `COMMIT;` on `Ok`, best-effort `ROLLBACK;` on `Err` —
/// so a caller cannot forget the unhappy path. `what` names the transaction in the begin/commit
/// error contexts (`"begin {what} txn"` / `"commit {what} txn"`) and rollback warning, preserving
/// the current operation labels.
///
/// Bounded `FnOnce`: the body runs **exactly once** and may consume what it captured. That is the
/// weakest bound that works, so it accepts move-consuming closures too. No `Send`: the body is
/// invoked inline on the owning worker's `LocalSet` and never crosses a task or thread boundary.
pub fn in_txn<T>(
    &self,
    what: &str,
    f: impl FnOnce(&duckdb::Connection) -> Result<T, LoaderError>,
) -> Result<T, LoaderError> {
    self.conn
        .execute_batch("BEGIN TRANSACTION;")
        .duck_with(|| format!("begin {what} txn"))?;
    match f(&self.conn) {
        Ok(value) => {
            todo!("COMMIT; mapped with `.duck_with(|| format!(\"commit {what} txn\"))?`, then Ok(value)")
        }
        Err(e) => {
            todo!("attempt ROLLBACK; warn with `transaction = what` if it fails; then return the original e")
        }
    }
}
```

```rust
// crates/loader/src/compaction.rs — the signature moves from `&Connection` to `&TableDb` so the
// seam is reachable; the drain-abort mapping stays OUTSIDE the closure.
pub fn full_rebuild(
    db: &crate::duck::TableDb,
    t: &TransformSql,
    cancel: &CancellationToken,
) -> Result<(), LoaderError> {
    if cancel.is_cancelled() {
        return Ok(()); // shutting down — don't even start the heavy rewrite (PR 3.12)
    }
    let boundary = t.latest_truncate(db.conn(), &Lsn::ZERO)?;
    let rebuild_op = format!("full rebuild {}", t.table());
    let rewrite = db.in_txn("rebuild", |conn| {
        conn.execute_batch(&t.render_rebuild(&boundary))
            .map_err(|source| duck_err(rebuild_op.clone(), source))
    });
    match rewrite {
        Ok(()) => Ok(()),
        // Interrupted by the drain (the watcher called `interrupt()`): `in_txn` already rolled back,
        // the old mirror is intact, and the rebuild re-runs next cycle. NOT an error.
        Err(LoaderError::Duck { op, .. }) if cancel.is_cancelled() && op == rebuild_op => {
            todo!("tracing::info!(table = t.table(), \"full-rebuild aborted by drain (rolled back)\"); Ok(())")
        }
        Err(e) => Err(e),
    }
}
```

## Hints & gotchas

- **PR 25.1 added no Rust.** Its outcome was docs-only evidence that PR 13.12 superseded the proposed
  returned mapper. The current `duck_err(op, source)` is a direct constructor in
  `crates/loader/src/duck_ext.rs`, not an `impl FnOnce` return in `error.rs`. Use the existing
  `DuckResultExt::duck_with` for lazy begin/commit context.
- **`FnOnce` is already present.** The authored baseline has three production source declarations:
  `unknown_variant` once and the one logical `duck_with` contract twice (trait plus impl). This
  ticket adds the third logical `FnOnce` callback, isolated by
  `impl FnOnce(&duckdb::Connection)`, rather than the first production use of the trait.
- **Make the move-consuming test truly consuming.** A `move` closure that only evaluates `&sql`
  can still implement `Fn`; explicitly consume the owned capture (for example `drop(sql)` after the
  statement) so the compile test would reject an accidentally stricter bound.
- **`ROLLBACK` must stay best-effort and observable.** If rollback itself fails, warn with the typed
  DuckDB error and transaction context, then return the body's *original* error. Returning the
  rollback error would hide the real cause and break the existing error classification.
- **Do not swallow the body's error type.** `in_txn` returns the body's `LoaderError` untouched, so
  `apply_transform`'s `"transform {table}: …"` and the rebuild's `"full rebuild {table}: …"` keep
  reaching `main`'s exit-code mapping.
- **Do not use `Err(_) if cancel.is_cancelled()`.** Moving that broad guard outside `in_txn` would
  silently widen today's behavior by mapping coincident BEGIN and COMMIT failures to `Ok(())`.
  Recognize only the body error with operation `"full rebuild {table}"`; that is the error an
  `InterruptHandle` intentionally causes and the one the current code maps after rollback.
- **`full_rebuild` is public and used by integration tests.** Changing its first parameter is a
  breaking change *inside the workspace only* (walrus publishes nothing), but you must update
  `crates/loader/tests/compaction.rs` and `crates/loader/tests/shutdown.rs` in the same commit or the
  workspace will not build.
- **`latest_truncate` runs before `BEGIN`.** Keep it there; it is a read that does not need the
  transaction, and moving it inside the closure would change what the boundary resolution sees.
- **No `Send` bound.** The owned `duckdb::Connection` and `TableDb` are `Send + !Sync`; it is their
  shared references that are not `Send`. More importantly, `in_txn` calls its body inline, so no
  task/thread boundary asks the body to be `Send` at all.
- **There are seven external `.conn()` arguments, not five.** Five are in `tests/compaction.rs`, one
  is in `tests/shutdown.rs`, and one production call is in `apply_loop.rs`.
- `unwrap`/`expect` are `deny` in production; `clippy.toml` re-allows them under `#[cfg(test)]`, so
  the sibling `duck_test.rs` may use them. Integration tests under `tests/` carry the file-level
  `#![allow(clippy::unwrap_used, clippy::expect_used)]` header instead.
- **Do not touch `.sql` files or the `.sqlx` offline cache.** No Docker locally to regenerate it; the
  DuckDB statements here are inline string literals, not sqlx queries.
