# PR 25.1 — Return an impl FnOnce error mapper for the loader's DuckDB map_err closures

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 25 — Rust closures · **Crates touched:** `loader` · **Est. size:** M ·
> **Depends on:** PR 24.8 · **Unlocks:** PR 25.2

No function anywhere in walrus returns a closure: `-> impl Fn` / `FnMut` / `FnOnce` is **0**
repo-wide, and so is `Box<dyn Fn>` / `Arc<dyn Fn>` / `Rc<dyn Fn>`. Meanwhile the loader hand-writes
the identical `map_err(|e| LoaderError::Duck(format!("<ctx>: {e}")))` closure at **27** production
sites (`duck.rs` 16, `compaction.rs` 4, `ddl.rs` 3, `phase_b.rs` 3, `transform.rs` 1). This PR adds
one function — `duck_err(|| ctx) -> impl FnOnce(duckdb::Error) -> LoaderError` — and routes every
one of those sites through it. It is the motivated first use of return-position `impl Trait` for a
closure in this tree, and the *lazy* `impl FnOnce() -> impl Display` context keeps the happy path
allocation-free: 13 of the 27 contexts are static strings and 14 interpolate locals such as
`{table}` or `{uri}`, so today every one of them is a `format!` that only ever matters on failure.
The rendered message shape stays byte-identical, so nothing downstream (compose log assertions,
exit codes, the `common::Error` mapping) moves.

## Why — learning objectives

- **Return-position `impl FnOnce`** — how a higher-order function names an unnameable closure type
  with no `Box`, no vtable and no allocation, and why `FnOnce` is the right end of the hierarchy
  for something handed to `Result::map_err`.
- **RPIT lifetime capture in edition 2021** — `impl Trait` in return position captures every *type*
  parameter, and therefore any lifetime hidden inside one, which is exactly what lets
  `duck_err(|| format!("append {s3_uri} → {table}_raw"))` borrow locals from the caller's frame.
- **The `LoaderError::Duck` context convention** — `"<what failed>: {duckdb error}"`, and where
  DuckDB failures enter the terminal/transient taxonomy through
  `LoaderError::as_common()` → `common::Error::Internal` → `ExitCode`.

## Scope

**In scope**

- Add `duck_err` to `crates/loader/src/error.rs`: a generic, lazily-rendered context factory
  returning `impl FnOnce(duckdb::Error) -> LoaderError`.
- Rewrite all **27** grep-visible sites to `.map_err(duck_err(|| …))`, plus the 28th written as a
  multi-line block at `crates/loader/src/ddl.rs:277-279` — leaving the count at 0 for both spellings.
- A sibling `crates/loader/src/error_test.rs` (wired with the house
  `#[cfg(test)] #[path = "error_test.rs"] mod tests;` footer) proving the rendered message is
  `"<ctx>: <duckdb error>"`, that a borrowed local survives into the returned closure, and that the
  context closure is **not** invoked on the `Ok` path.

**Explicitly deferred** (do *not* build these here)

- The ~96 `map_err` sites in `control`, `pg-sink` and `pg-to-arrow`. They map into `anyhow` or
  `common::Error`, not `LoaderError::Duck`, and each has its own idiom — a different ticket.
- **No `Box<dyn Fn>` anywhere.** There is exactly one closure type here; boxing it would be the
  anti-pattern the rule exists to prevent.
- No error-variant, exit-code or message-text change. `LoaderError::Duck(format!("{ctx}: {e}"))` must
  render byte-for-byte what it renders today — the compose log assertions still match on those
  strings.
- Do not touch the `LoaderError::Quarantine` construction in `ddl.rs:291-298`. It is an
  `if let Err(e) = …` branch producing a *different* variant, not a `map_err`.

## Hints & gotchas

- **`map_err` takes `FnOnce`, so return `FnOnce`.** Do not "future-proof" with `Fn`: that would
  force the context closure to be re-callable and reject the `move`-consuming contexts you want.
  The rule's whole point is to bound at the weakest trait that works.
- **Make the context lazy or you have gained nothing.** `duck_err(format!("describe {uri}"))`
  (taking `D: Display` directly) would allocate a `String` on *every* successful call — 27 sites on
  the loader's hot Phase-A/Phase-B path. Take `C: FnOnce() -> D` so `format!` runs only on error.
- **`&'static str` and `String` both satisfy `D: Display`** — that is why `|| "configure S3"` and
  `|| format!("describe {uri}")` can share one signature without a `.to_string()` at 13 call sites.
- **Edition 2021 RPIT captures type parameters, not free lifetimes.** `C` is a type parameter, and
  the borrowed `uri`/`table` live *inside* `C`, so they are captured and the code compiles. If you
  ever try to write `duck_err(ctx: &str) -> impl FnOnce(...)` you will need an explicit `+ '_`.
- **There is a 28th site the grep misses.** `crates/loader/src/ddl.rs:277-279` is written as
  `map_err(|e| { LoaderError::Duck(format!(…)) })` across three lines. Convert it too; a probe that
  reads 0 while a copy survives is worse than no probe.
- **Do not touch `.sql` files or the `.sqlx` offline cache.** There is no Docker on this machine to
  regenerate the cache; this PR is Rust-side only, and the loader's DuckDB SQL is
  `include_str!`-ed templates anyway.
- **No new dependency.** `duck_err` is std + `duckdb` (already a direct dep). Anything new would have
  to clear `cargo deny`'s advisories, 8-license allow-list and bans.
- `unwrap`/`expect` are `deny` in production via `[workspace.lints]`; `clippy.toml` re-allows them
  under `#[cfg(test)]`, so the sibling `error_test.rs` may use them freely — integration tests under
  `tests/` may not without the file-level `#![allow(…)]` header.
- Unit tests are **Go-style sibling files**, never inline `mod tests { … }`. Copy the three-line
  footer from the bottom of `crates/loader/src/duck.rs` verbatim.
