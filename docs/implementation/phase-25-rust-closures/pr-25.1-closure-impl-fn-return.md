# PR 25.1 — Record why DuckResultExt supersedes a returned closure mapper

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** superseded by PR 13.12
>
> **Gates:** fmt,clippy,test · **Test packages:** loader

> **Phase:** 25 — Rust closures · **Crates touched:** none (docs evidence only) · **Est. size:** S ·
> **Depends on:** PR 24.8 · **Unlocks:** PR 25.2

The original audit expected `LoaderError::Duck(String)`, **27** grep-visible handwritten
`map_err` closures, one multiline closure, and no `duck_err`. That tree no longer exists. PR 10.3
first made `LoaderError::Duck` a typed struct variant, and PR 13.12 then centralized every DuckDB
result mapping behind `DuckResultExt::{duck, duck_with}` plus the rollback-sensitive direct
`duck_err(op, source)` path. At baseline `11742412b47325f52fdd7d770afbe7b036d27b0f`, the five
consumer modules contain **29** extension-method mappings (**13** `.duck`, **16** `.duck_with`), the
direct rebuild branch calls `duck_err` once, and none constructs `LoaderError::Duck` locally.

Returning `impl FnOnce(duckdb::Error) -> LoaderError` would now add a second context API without
removing a single closure. The earlier extension trait is the stronger final shape: constant and
lazy context stay distinct, the typed source has one constructor, and callers name the operation at
the `Result` itself. This task records that ownership and the condition under which a returned
closure would become appropriate; it does not recreate the obsolete baseline.

## Why — learning objectives

- **Apply return-position `impl Trait` only when a function must return a closure.** A single
  concrete closure can be returned as `impl FnOnce` without allocation or dynamic dispatch, but no
  current loader API has that requirement.
- **Recognize an earlier abstraction that already owns the seam.** `DuckResultExt<T>` is a local
  extension trait over `Result<T, duckdb::Error>`; its `duck_with` argument is already the weakest
  correct `FnOnce` bound and runs only on the error path.
- **Preserve typed error ownership.** PR 10.3 owns `LoaderError::Duck { op, source }`; PR 13.12 owns
  the single constructor, the consumer routing, the operation strings, and the regression tests.

## Hints & gotchas

- **Do not satisfy the rule by manufacturing a caller.** Return-position `impl FnOnce` is useful when
  an API actually returns a closure; it is not a quota. All motivating callers disappeared in PR
  13.12.
- **`duck_with` accepts a closure; it does not return one.** Its `impl FnOnce() -> String` still teaches
  the weakest callback bound and lazy error-path work, while the evidence note explains why that is
  the right abstraction here.
- **The current result-site count is 29, not PR 13.12's historical 28.** A later truncate-boundary
  query correctly joined the same extension API. Classify it as evidence that the abstraction scales,
  not as an uncovered closure to rewrite.
- **`compaction::full_rebuild` is deliberately different.** It must roll back and check cancellation
  before constructing the error, so its direct two-argument `duck_err` call remains outside
  `DuckResultExt`.
- **Ignore unrelated `map_err` closures.** `Internal`, `LsnParse`, `RegistryDecode`, and other typed
  mappings are not DuckDB context duplication and are outside this rule.
- Do not add a textual source guard merely to create executable work. The typed constructor, extension
  trait, and sibling tests already own the behavioral regression surface; the evidence task is the
  truthful completion.
