# PR 10.11 — Gate that every workspace member inherits the unwrap and expect denies

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 10 — Rust error handling · **Crates touched:** `common` (guard test only) ·
> **Est. size:** S · **Depends on:** PR 10.10 · **Unlocks:** PR 10.12

Production has **0 `.unwrap()`** and **1 `.expect(`** (the `#[expect]`-pinned recorder install from
PR 10.10), and `[workspace.lints.clippy]` denies `unwrap_used` and `expect_used` at `Cargo.toml:20-21`.
But the constraint that makes that deny *reach* anything is stated in prose only —
`Cargo.toml:11`: "NOTE: these only take effect in a member once it declares `[lints] workspace = true`".
All **6** members declare it today. Nothing fails if a seventh crate is added without it, and nothing
fails if the three-line `[lints]` block is deleted from `crates/loader/Cargo.toml`: `cargo clippy
--all-targets -- -D warnings` stays green while an entire crate silently drops out of
`deny(warnings)`, `clippy::all`, `unwrap_used` and `expect_used` at once. This PR makes the policy
itself testable.

## Why — learning objectives

- **Cargo `[workspace.lints]` inheritance and its opt-in failure mode** — a workspace lint table is
  a *default that must be requested*, not a rule that is imposed; the failure is silent and
  crate-wide, which is the worst combination.
- **Lint-as-policy** — if a rule matters, assert it, don't comment it. A four-line guard that reads
  the manifests beats a NOTE nobody re-reads when adding crate number seven.

## Read first

- [`err-no-unwrap-prod`](../../../.claude/skills/rust-skills/rules/err-no-unwrap-prod.md) — take the
  "Clippy Lints" section: the rule's own recommendation is `[lints.clippy] unwrap_used = "warn"`
  *per crate*. walrus centralises it instead, which is stronger — but only for members that opt in.
  That gap is this ticket.
- `Cargo.toml:1-21` — `[workspace] members = [...]` (line 3), the NOTE at line 11, and the
  `[workspace.lints.rust]` / `[workspace.lints.clippy]` tables. These are the four facts the guard
  asserts.
- `crates/common/Cargo.toml:8-9` — the canonical member-side opt-in, comment and all:
  `[lints]` / `workspace = true # inherit deny(warnings) + clippy::all from the workspace root`.
  Compare `crates/loader/Cargo.toml:15-16` and `tests/e2e/Cargo.toml:16-17`.
- `clippy.toml` — the two-line (three after PR 10.9) test carve-out. The guard must also prove the
  carve-out is still *scoped to tests*, since a blanket allow here would defeat the deny just as
  thoroughly as a missing `[lints]` block.

**In scope**

- One new std-only integration test, `crates/common/tests/workspace_lints_inherited.rs`, that:
  1. resolves the repo root from `env!("CARGO_MANIFEST_DIR")/../..`;
  2. parses `members = [ … ]` out of the root `Cargo.toml` (all 6 today, whatever the count
     tomorrow) — **the member list is the source of truth**, not a hard-coded array in the test;
  3. for each member, reads `<root>/<member>/Cargo.toml` and asserts it has a `[lints]` section
     whose body contains `workspace = true`;
  4. asserts the root table still says what it is supposed to say —
     `[workspace.lints.rust] warnings = "deny"` and `[workspace.lints.clippy] unwrap_used = "deny"`,
     `expect_used = "deny"`;
  5. asserts `clippy.toml` still scopes the carve-out to tests
     (`allow-unwrap-in-tests`/`allow-expect-in-tests` present and `true`, and no key that widens
     unwrap/expect beyond tests).
- Failure messages that name the offending member and tell the reader exactly what to paste back in.

**Conflict with the rule — resolve it explicitly, do NOT apply the rule blindly**

The rule says "avoid `unwrap()` in production; deny it with clippy". walrus did that in PRs 7.6 and
7.7 — the tree is clean and the lint exists. Re-fixing a solved problem would be a no-op PR, so this
ticket must add the **missing** piece instead: the deny is *opt-in per member* and *unguarded*. Do
not open this PR by grepping for `.unwrap()` and "cleaning" anything; production has none, and the
20 file-level test allows are legitimate.

**Explicitly deferred** (do *not* build these here)

- Do not narrow or remove the 20 file-level `#![allow(clippy::unwrap_used, clippy::expect_used)]`
  headers in integration tests and benches. They implement `clippy.toml`'s documented test
  carve-out for helper code that lives outside a `#[test]` fn.
- Do not add new restriction lints — PR 10.9 (`panic`/`todo`/`unimplemented`/`unreachable`) and
  PR 10.10 (`allow_attributes_without_reason`) already did that, and this PR must not stack more
  policy on top of the one it is gating.
- No new CI job or step. The guard runs inside the existing `cargo test --workspace`.
- No TOML parser dependency (see Hints).

// crates/common/tests/workspace_lints_inherited.rs
#![allow(
    clippy::unwrap_used,
    clippy::expect_used,
    reason = "integration test — unwrap/expect fine in setup + helpers"
)]
//! Guard for `err-no-unwrap-prod` (PR 10.11). `[workspace.lints]` is a default a member must
//! *request*: without `[lints] workspace = true` in its own manifest, a crate silently opts out of
//! `deny(warnings)`, `clippy::all`, `unwrap_used` and `expect_used` — and CI stays green. This test
//! is the thing that goes red instead.

use std::path::{Path, PathBuf};

/// Repo root, from this crate's manifest dir (`<root>/crates/common`).
fn repo_root() -> PathBuf {
    todo!("Path::new(env!(\"CARGO_MANIFEST_DIR\")).join(\"../..\") — canonicalize it")
}

/// Every path in the root manifest's `[workspace] members = [ … ]`, in declaration order.
/// Parsed, never hard-coded: crate number seven must be covered the day it is added.
fn workspace_members(root_manifest: &str) -> Vec<String> {
    todo!("scan from `members = [` to the matching `]`, collecting the quoted paths")
}

/// The body of `[section]` in `manifest`, up to the next `[` at column 0. `None` if absent.
fn section<'a>(manifest: &'a str, header: &str) -> Option<&'a str> {
    todo!()
}

#[test]
fn every_member_opts_into_the_workspace_lint_table() {
    let root = repo_root();
    let root_manifest = std::fs::read_to_string(root.join("Cargo.toml")).unwrap();
    let members = workspace_members(&root_manifest);
    assert!(members.len() >= 6, "member list parsed as {members:?} — the parser is broken");

    let mut missing: Vec<String> = Vec::new();
    for member in &members {
        let path = root.join(member).join("Cargo.toml");
        let manifest = std::fs::read_to_string(&path)
            .unwrap_or_else(|e| panic!("member {member} has no manifest at {}: {e}", path.display()));
        // NOTE: a bare `contains("workspace = true")` is WRONG — every `dep = { workspace = true }`
        // line matches. It has to be the `[lints]` section body.
        let opted_in = section(&manifest, "[lints]")
            .is_some_and(|body| body.contains("workspace = true"));
        if !opted_in {
            missing.push(member.clone());
        }
    }
    assert!(
        missing.is_empty(),
        "these workspace members do not inherit [workspace.lints] — add\n\n    [lints]\n    workspace = true\n\nto: {missing:?}"
    );
}

#[test]
fn the_workspace_lint_table_still_denies_unwrap_and_expect() {
    let root_manifest = std::fs::read_to_string(repo_root().join("Cargo.toml")).unwrap();
    let rust = section(&root_manifest, "[workspace.lints.rust]").expect("[workspace.lints.rust]");
    let clippy = section(&root_manifest, "[workspace.lints.clippy]").expect("[workspace.lints.clippy]");
    assert!(rust.contains(r#"warnings = "deny""#));
    assert!(clippy.contains(r#"unwrap_used = "deny""#));
    assert!(clippy.contains(r#"expect_used = "deny""#));
}

#[test]
fn the_clippy_carve_out_is_still_scoped_to_tests() {
    let cfg = std::fs::read_to_string(repo_root().join("clippy.toml")).unwrap();
    assert!(cfg.contains("allow-unwrap-in-tests = true"));
    assert!(cfg.contains("allow-expect-in-tests = true"));
    todo!("assert no key widens unwrap/expect beyond tests — every configured key must end in `-in-tests`");
}

## Hints & gotchas

- **`grep 'workspace = true'` is not the check.** Every inherited dependency
  (`thiserror = { workspace = true }`) and every inherited package field
  (`edition.workspace = true`) matches it. The guard must find the `[lints]` **section** and look
  inside its body only — that is the entire subtlety of this ticket.
- **Do not add `toml` as a dev-dependency to get "proper" parsing.** A new dep has to clear
  `cargo deny` (advisories + the 8-license allow-list + bans) and, more importantly, `common` is a
  library crate — PR 10.8's `[bans]` entry exists precisely to keep its dependency surface honest.
  Section-scanning `&str` is ~40 lines and has no supply chain.
- **`tests/e2e` is a member too** (`members` line 3 lists it as `"tests/e2e"`, and its package name
  is `e2e`). Join member paths onto the repo root, don't assume `crates/<name>`.
- Handle the members array on one line *and* wrapped across lines — today it is one long line with a
  trailing `#` comment, and rustfmt does not touch `Cargo.toml`, so the next person to add a crate
  may well reflow it.
- Integration tests under `tests/` are **not** covered by `clippy.toml`'s `allow-*-in-tests` for
  helper code, so keep the file-level allow header — and, post-PR 10.10, it needs `reason = "…"`.
- Give the assertion message the fix, not just the diagnosis. Someone will hit this while adding
  crate seven at 6pm; `add [lints] workspace = true to crates/foo` saves them the archaeology.
- This PR does not touch `.sql` or the `.sqlx` offline cache, and must not — there is no Docker
  locally to regenerate it.
