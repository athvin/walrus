# PR 10.10 — Turn the justified expect allow into an expect attribute with a reason

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 10 — Rust error handling · **Crates touched:** `common` · **Est. size:** M ·
> **Depends on:** PR 10.9 · **Unlocks:** PR 10.11

Production contains exactly **one** `expect(` — `crates/common/src/metrics.rs:147`, under an
`#[allow(clippy::expect_used)]` at line 144 with a five-line justification: `install_recorder` can
only fail when a *different* global recorder is already installed, and `OnceLock::get_or_init`
guarantees the closure runs at most once, so the panic is unreachable in practice. That is already
the rule's ideal shape but for two things. Its message,
`"install a global Prometheus recorder exactly once"`, reads like a request rather than the
prescribed `BUG:` marker; and `#[allow]` is silent forever — the day someone threads a `Result` out
of `init()` or drops the `OnceLock`, the attribute quietly stops applying and nobody finds out.
Tree-wide there are **71 `#[allow(...)]`/`#![allow(...)]` attributes** (7 in production) and **zero
`#[expect(...)]`**. This PR converts the sanctioned exception to `#[expect]`, gives every suppression
in the tree a machine-checked `reason =`, and pins the invariant the expect rests on with a test.

## Why — learning objectives

- **`#[expect]` vs `#[allow]`** — an expectation *fails when the lint stops firing*, so a
  suppression can no longer outlive the thing it was suppressing; `reason = "…"` turns the
  justification from a comment into part of the attribute the compiler prints back at you.
- **Why the recorder install is a bug-class invariant** — `metrics::init()` is install-once at
  process start, not a runtime condition; distinguishing "this cannot happen unless the program is
  wrong" from "this dependency might be down" is the same judgement `Error::is_terminal()` encodes.

**In scope**

  `#[expect(clippy::expect_used, reason = "…")]`, and the panic message becomes
  `"BUG: a second global Prometheus recorder was installed"`.
- `[workspace.lints.clippy]` gains `allow_attributes_without_reason = "deny"`.
- Every `#[allow(...)]` / `#![allow(...)]` under `crates/` and `tests/` gains `reason = "…"`. Where
  a trailing `//` comment already carries the justification, move that text into the `reason` and
  delete the comment — do not leave the same sentence in two places.
- `crates/common/src/metrics_test.rs`: a test asserting `init()` is idempotent — the exact invariant
  the `#[expect]` rests on. If that test can ever fail, the expect is wrong.

**Conflict with the rule — resolve it explicitly, do NOT apply the rule blindly**

The rule is written for a codebase that still has `expect()` sprinkled through it. walrus does not:
`unwrap_used` and `expect_used` have been `deny` since PR 7.7 and the tree was cleaned in PR 7.6, so
"remove the unjustified expects" is already done and re-doing it would be busywork. The missing
piece — and the whole content of this ticket — is that the **one sanctioned exception is unverified
and unstructured**: its justification is a comment, and `#[allow]` never fails. `#[expect]` makes
clippy fail if the lint ever stops firing there, and `allow_attributes_without_reason` makes every
*future* suppression state its case in a machine-readable field.

**Explicitly deferred** (do *not* build these here)

- **Do not deny `clippy::allow_attributes`** (the stricter allow-to-expect migration). Converting
  the 20 file-level `#![allow(clippy::unwrap_used, clippy::expect_used)]` headers in integration
  tests and benches to `#![expect(...)]` would break every file that happens to use only one of the
  two macros — an expectation that never fires is an error. Reason-only for now.
- Do not touch the panicking-macro denies from PR 10.9, and do not add further restriction lints.
- Do not change `metrics::init()`'s signature. Threading a `Result` out is not possible on stable
  (`OnceLock` has no `get_or_try_init`) and there is no recoverable path anyway — that argument is
  already written at `metrics.rs:139-143` and this PR preserves it, it does not relitigate it.

```toml
allow_attributes_without_reason = "deny"
```

```rust
// crates/common/src/metrics.rs:137-157
pub fn init() {
    HANDLE.get_or_init(|| {
        // Install-once at process init: `install_recorder` only errors if a *different* global
        // recorder is already set (a programming error, not a runtime condition), and `get_or_init`
        // guarantees this closure runs at most once — so the panic is unreachable in practice. `init`
        // is infallible by signature and called from `main`/scrape-test setup; threading a `Result`
        // out (stable `OnceLock` has no `get_or_try_init`) would ripple with no recoverable path.
        #[expect(
            clippy::expect_used,
            reason = "install-once invariant: OnceLock::get_or_init runs this closure at most once, \
                      so install_recorder can only fail if another global recorder exists — a bug"
        )]
        let handle = PrometheusBuilder::new()
            .install_recorder()
            .expect("BUG: a second global Prometheus recorder was installed");
        describe_all();
        zero_init_global();
        for flavor in ["reload", "resync"] {
            metrics::gauge!(names::RELOAD_ACTIVE, names::FLAVOR_LABEL => flavor).set(0.0);
        }
        handle
    });
}
```

## Hints & gotchas

- **`reason` inside a multi-lint `allow` is one trailing item**, not per lint:
  `#[allow(a, b, reason = "…")]`. Attribute-level `reason` has been stable since 1.81 and the MSRV
  is 1.95, so no `cfg_attr` gymnastics.
- **`#[expect]` errors when the lint does not fire.** That is the feature, and it is also the trap:
  it means the attribute must sit on the *narrowest* item that triggers the lint. Keep it on the
  `let handle = …` statement, exactly where the `#[allow]` sits today — hoisting it to `fn init` or
  the module would still fulfil today but would silently over-suppress.
- **`allow_attributes_without_reason` is not limited to production.** All 20 integration-test
  headers, the 3 bench headers and the e2e harness lib header are in scope. They are 24 copies of
  one sentence — do them with a single careful `sed`, then read the diff, then run `cargo fmt`
  (rustfmt reflows multi-line attributes and will make the diff noisy if you don't).
- **`cargo fmt` will rewrap the long `reason` strings.** Prefer a `\`-continued string literal (as
  in the Skeleton) over one 140-column line so the formatter and the 100-column convention agree.
- **The idempotency test shares a process with every other `common` unit test.** `HANDLE` is a
  process-global `OnceLock`, so `render_lists_every_series` may already have installed the recorder
  before your test runs, in any order. Assert *properties that hold either way* — "render is
  non-empty after init", "the series list survives a second init" — not "the first call installed
  it". Never `assert!(render().is_empty())` before calling `init()`.
- Do not "fix" the seven production `#[allow]`s by deleting them. `new_ret_no_self`,
  `too_many_arguments` and the two `dead_code` deferred-goal stubs are all deliberate; this PR
  documents them, it does not relitigate them.
- Nothing here touches `.sql` or the `.sqlx` cache, and no new dependency is added — so `cargo deny`
  has nothing new to chew on.
