# PR 10.6 — Close the exit-code downcast hole at the pg-sink app boundary

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 10 — Rust error handling · **Crates touched:** `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 10.5 · **Unlocks:** PR 10.7

`crates/pg-sink/src/main.rs:45-49` is the single `anyhow::Error → ExitCode` mapping in the binary
— the "context in the loop, exit code at `main`" idiom — but it only downcasts to
`common::Error`. pg-sink defines **10** thiserror enums (`batch`, `config`, `reload`, `ddl`,
`sink`, `manifest`, `relcache`, `preflight`, `heartbeat`, `pgoutput`) and only **2** of them
convert into `common::Error` (`config.rs:141`, `preflight.rs:88`) — both on the *bootstrap* path.
So a post-bootstrap `SinkError::Store` (an object-store outage during a flush) falls through to
`unwrap_or(Internal)` and exits **70** instead of **12/ObjectStore**: the runbook greps the wrong
code and the on-call reads "internal error" for a MinIO outage. After this PR a new
`pg_sink::exit` module walks the anyhow chain trying each typed error in turn, `main` calls it,
and every classified failure keeps its distinct, greppable status.

## Why — learning objectives

- **`anyhow::Error::downcast_ref` and `chain()`** — how a typed error survives underneath an
  `anyhow::Error`, and precisely which layers a downcast can see.
- **The typed-error-under-anyhow boundary** — libraries stay typed, the application carries them
  in `anyhow`, and exactly one function at the edge translates them back into a decision.
- **The walrus `ExitCode` contract** — distinct, stable, greppable statuses so a
  `CrashLoopBackOff` names its own cause without anyone reading a log line.

## Scope

**In scope**

- New module `crates/pg-sink/src/exit.rs` exporting
  `pub fn code_for(err: &anyhow::Error) -> common::ExitCode`, registered as `pub mod exit;` in
  `crates/pg-sink/src/lib.rs`. It tries `downcast_ref` for `common::Error` first (preserving
  today's behaviour), then each typed pg-sink error, then `control::ControlError`, and falls back
  to `ExitCode::Internal`.
- New `impl From<…> for common::Error` for at least `SinkError` (`Store` → `ObjectStore`,
  `Encode` → `Internal`), `ManifestError` (→ `ControlDb`) and `HeartbeatError` (→ `SourceDb`),
  taking the count of such impls in `crates/pg-sink/src` from 2 to ≥5.
- `main.rs` replaces its inline `downcast_ref::<common::Error>()…unwrap_or(Internal)` with
  `pg_sink::exit::code_for(&e)`. The `tracing::error!("walrus-pg-sink exiting: {e:#}")` line
  stays.
- New sibling test `crates/pg-sink/src/exit_test.rs` with one case per typed error:
  `SinkError::Store` → 12, `ManifestError` / `control::ControlError` → 11, `ConfigError` → 10,
  `PreflightError::NoPrimaryKey` → 14, `HeartbeatError` → 16, an unclassified `anyhow!("boom")` →
  70, and one case proving a *context-wrapped* typed error still classifies.

**Explicitly deferred** (do *not* build these here)

- Do **not** convert pg-sink's library modules off anyhow. The convention (CONTEXT §6) —
  thiserror in the library crates, anyhow in the application, context in the loop, exit code at
  `main` — stays.
- Do **not** change the loader, which already maps exhaustively via `LoaderError::exit_code`
  (`loader/src/error.rs:61`).
- Do **not** add or renumber `common::ExitCode` variants. Every pg-sink error maps onto an
  existing code.
- Do **not** write `impl From<control::ControlError> for common::Error` in pg-sink — both types
  are foreign to this crate, so the orphan rule forbids it. Classify `ControlError` inline inside
  `code_for` instead.
- Do **not** make `code_for` exhaustive over *every* enum in the crate on day one;
  `PreflightRejection` (`reload.rs:40`) is operator UX recorded on a `table_reload` row and never
  reaches `main`.

## Skeleton

```rust
// crates/pg-sink/src/exit.rs
//! The one place an `anyhow::Error` becomes a process exit status.

use common::ExitCode;

/// Recover the distinct exit code for a failure that reached `main`.
///
/// Tries the classified `common::Error` first (the bootstrap path), then each typed pg-sink error
/// that can escape the run loop, then the control crate's error. Anything unrecognised is
/// [`ExitCode::Internal`] — the same fallback `main` had, now with far fewer things falling into it.
pub fn code_for(err: &anyhow::Error) -> ExitCode {
    if let Some(e) = err.downcast_ref::<common::Error>() {
        return e.exit_code();
    }
    if let Some(e) = err.downcast_ref::<crate::sink::SinkError>() {
        todo!("common::Error::from(e-by-ref) .exit_code()  — Store => ObjectStore (12)");
    }
    if let Some(e) = err.downcast_ref::<crate::manifest::ManifestError>() {
        todo!("=> ExitCode::ControlDb (11)");
    }
    if let Some(e) = err.downcast_ref::<crate::config::ConfigError>() {
        todo!("=> ExitCode::Config (10)");
    }
    if let Some(e) = err.downcast_ref::<crate::preflight::PreflightError>() {
        todo!("=> Preflight (13) / KeylessTable (14) via the existing From impl");
    }
    if let Some(e) = err.downcast_ref::<crate::heartbeat::HeartbeatError>() {
        todo!("=> ExitCode::SourceDb (16)");
    }
    if let Some(_e) = err.downcast_ref::<control::ControlError>() {
        // Orphan rule: no `From` impl possible here, so classify inline.
        return ExitCode::ControlDb;
    }
    ExitCode::Internal
}
```

## Hints & gotchas

- **`downcast_ref` sees anyhow's own layers, not `#[source]` links.** A `control::ControlError`
  nested behind `ManifestError::Control(#[from] …)` is *not* independently downcastable — anyhow
  only unwinds the context layers it created plus the base error. So classify the **outermost**
  typed enum; that is why `ManifestError` needs its own arm even though it wraps `ControlError`.
- **The orphan rule blocks `impl From<control::ControlError> for common::Error` in pg-sink.**
  Both types are foreign. Classify inline in `code_for` (a `return ExitCode::ControlDb;`), or —
  if you want the impl — it belongs in the `control` crate, which is out of scope here.
- **`From<SinkError> for common::Error` consumes the error, but `code_for` only has `&`.** Either
  match on the reference inside `code_for` (cheapest), or give the enum a small
  `fn exit_code(&self)`; do not clone the error just to reuse the `From`.
- **Order matters.** Keep `common::Error` first so today's bootstrap behaviour is bit-for-bit
  preserved, and keep the `ExitCode::Internal` fallback last — this PR must never *remove* a
  classification.
- **`ExitCode` numbers are a public contract.** Runbooks and alerts grep them: never renumber,
  only append (and this PR appends nothing).
- **`unwrap`/`expect` are denied in production** by `[workspace.lints.clippy]`; `clippy.toml`
  re-allows them under `#[cfg(test)]`, so `exit_test.rs` may use them and `exit.rs` may not.
- **Tests are Go-style sibling files** — `exit.rs` gets
  `#[cfg(test)] #[path = "exit_test.rs"] mod tests;` at the bottom; never an inline
  `mod tests { … }`.
- **No new dependency is needed.** `anyhow`, `object_store`, `tokio-postgres` and `control` are
  already pg-sink dependencies; anything else would have to clear `cargo deny` in the
  `supply-chain` CI job.
