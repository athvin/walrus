# PR 10.5 — Add anyhow context to the contextless pg-sink await sites

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 10 — Rust error handling · **Crates touched:** `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 10.4 · **Unlocks:** PR 10.6

`pg-sink` is *the* anyhow crate — 94 `anyhow` references and 99 `.context(` / `.with_context(`
calls — but the context is unevenly applied: **86 bare `.await?` sites** remain, and three
modules that return `anyhow::Result` have **zero** context calls at all: `slot.rs` (3 bare
`.await?`), `reload.rs` (12) and `health.rs` (2). Today a failed `pg_replication_slots` query
inside `slot::read_slot` surfaces only the raw tokio-postgres message — no slot name, no
operation, nothing that tells an operator whether the sink failed to *read* a slot or to *create*
one. After this PR every `?` on a network or DB call in those three modules carries a context
line, and the top-level `{e:#}` in `main` reads as a sentence.

## Why — learning objectives

- **`anyhow::Context`** — `.context()` wraps an error with a message *and* keeps the original as
  the cause, so `{:#}` prints `"read slot walrus_slot: connection closed"`.
- **`context` vs `with_context`** — the first evaluates its argument eagerly (fine for a
  `&'static str`), the second is a closure so `format!` only allocates on the error path. Pick
  per call site.
- **Which walrus identifier belongs in which message** — `slot_name` for slot management,
  `reload_id` for the reload controller, the bind address for the health server. A context line
  without an identifier is barely better than none.

  (`tracing::error!("… {e:#}")`) and downcast to an exit code, so you can see what your messages
  will look like in `kubectl logs`.

## Scope

**In scope**

- `slot.rs`: add `use anyhow::Context as _;` and give all three `.await?` sites context that
  names the slot — read (`64`), verify-read (`95`), create (`122`). Use
  `with_context(|| format!(…))` since the slot name is runtime data. Target: ≥3 context calls.
- `reload.rs`: context on the control-pg and source-DB awaits — `pool.acquire()` (115, 552),
  `restart_for_ddl` (116), `ChunkExporter::connect` (175), `exporter.run()` (176),
  `complete_export` (180), `claim_requested` (326), `renew_lease` (462), `stuck_exporting` (538),
  `reload::fail` (553). Name the `reload_id` wherever one is in scope. Target: ≥6 context calls.
- `health.rs`: context on `axum::serve(…).await?` (162) and `TcpListener::bind(addr).await?`
  (172), the latter naming the address. Target: ≥2 context calls.
- Every message is lowercase-leading and unpunctuated, so it chains cleanly under `{:#}` — the
  convention PR 10.7 will guard.

**Explicitly deferred** (do *not* build these here)

- Do **not** add context inside `bootstrap.rs`. `run_shared` returns the typed `common::Error`,
  not `anyhow::Result` (see `bootstrap.rs:46`), so `.context()` does not apply — and it stays
  typed on purpose so `main` can recover its exit code by downcast.
- Do **not** touch the `loader` crate; it is thiserror-only and its context lives in variant
  payloads (PRs 10.3/10.4).
- Do **not** convert any of these three modules to a typed error enum. The convention (CONTEXT
  §6) is anyhow in the application crate, context in the loop, exit code at `main`.
- Do **not** attempt to reach all 86 bare `.await?` sites tree-wide — many are already inside a
  function whose *caller* adds the context, and blanket-wrapping would produce noise like
  `"failed to await: failed to await"`.

## Hints & gotchas

- **`use anyhow::Context as _;`** — importing the trait unnamed avoids colliding with any local
  `Context` type and keeps the import obviously trait-only. `warnings = "deny"` is
  workspace-wide, so an unused import will fail the build if you add it to a file you end up not
  editing.
- **`.context()` takes an eagerly-evaluated argument.** `.context(format!("… {slot}"))` allocates
  on every successful call. Use `.with_context(|| format!(…))` whenever the message interpolates.
- **`?` on a non-`std::error::Error` is fine here** — `anyhow::Context` is implemented for
  `Result<T, E: StdError>` *and* for `Option<T>`; if you hit a type error, the receiver is
  probably an `anyhow::Result` already, in which case `.context(…)` still works.
- **Do not context-wrap a call that already reports itself.** `reload.rs:192`'s
  `ok_or_else(|| anyhow! ("successor reload {new_id} vanished after restart"))` already names
  everything; adding an outer layer just doubles the sentence.
- **`reload.rs:462` is inside a renewal closure** returning `anyhow::Result<()>` from an
  `async move`; the captured `reload_id` is read from an `AtomicI64`, so bind it before the
  `format!`.
- **Lowercase, no trailing punctuation.** PR 10.7 adds a conformance test over `#[error("…")]`
  literals, and the same house style applies to context strings — write them right the first
  time.
- **`unwrap`/`expect` remain denied in production**, and tests stay in sibling `*_test.rs` files.
- **Any new dependency must clear `cargo deny`** (advisories + the 8-license allow-list) — but
  this PR needs none: `anyhow` is already a `pg-sink` dependency.
