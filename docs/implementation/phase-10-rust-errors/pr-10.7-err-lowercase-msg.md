# PR 10.7 — Guard the lowercase no-punctuation error-message convention

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 10 — Rust error handling · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 10.6 · **Unlocks:** PR 10.8

walrus already writes error messages the way `std` does. Across **67 production `#[error("…")]`
literals** in 15 modules, **zero** end in `.`, `!` or `?`, and only **two** start with a capital —
`"DuckDB: {0}"` (`loader/src/error.rs:13`) and `"DDL capture not installed: …"`
(`pg-sink/src/preflight.rs:77`) — both acronyms the rule explicitly permits. The same holds for the
99 `.context(` strings, whose uppercase cases are SQL/protocol tokens (`CREATE_REPLICATION_SLOT`,
`CopyDone`, `PUT`). What is missing is a *gate*: the convention lives only in prose, so the next
`#[error("Failed to open the slot.")]` lands green and the `{:#}` chain starts reading like
"reload failed.: Failed to open the slot.: connection refused". This PR turns the convention into a
plain `cargo test` that reads the tree and fails on the first violation.

## Why — learning objectives

- **Error-message composition** — lowercase, punctuation-free messages concatenate cleanly under
  `{:#}` / `source()` walking; capitals and full stops produce garbage mid-chain.
- **Source-scanning conformance tests** — a `#[test]` that reads `crates/*/src/**/*.rs` from
  `CARGO_MANIFEST_DIR/../..` gives a lint-grade gate with no Docker, no proc macro and no new crate.

## Read first

- [`err-lowercase-msg`](../../../.claude/skills/rust-skills/rules/err-lowercase-msg.md) — take the
  formatting table (`"failed to parse config"` not `"Failed to parse config."`) and the
  "When to Use Capitals" carve-out for acronyms; that carve-out is the allow-list you implement.
- `crates/common/src/error.rs` — the 9-variant house taxonomy; every message is the shape the gate
  must accept (`"invalid configuration: {0}"`, `"table {table} has no usable key (strict mode)"`).
- `crates/loader/src/error.rs:13` and `crates/pg-sink/src/preflight.rs:77` — the only two
  legitimately-uppercase messages in the tree; if your allow-list is wrong, these are what break.
- `crates/pg-sink/src/preflight.rs:60-82` — the **multi-line** `#[error(…)]` forms with `\`
  line-continuations. A naive one-line regex silently skips these.
- `crates/control/tests/checkpoint.rs:1` — the house header for an integration test
  (`#![allow(clippy::unwrap_used, clippy::expect_used)]` plus a one-line justification).

**In scope**

- A new integration test `crates/common/tests/error_message_style.rs`, std-only (no new
  dependency, nothing for `cargo deny` to chew on).
- It resolves the repo root from `env!("CARGO_MANIFEST_DIR")/../..`, walks `crates/*/src/**/*.rs`
  recursively (`crates/pg-sink/src/pgoutput/` is nested — a one-level glob misses it), and skips
  `*_test.rs` siblings.
- It extracts every `#[error("…")]` literal, skipping `#[error(transparent)]`, and joining
  `\`-continuations so a multi-line message is checked as one logical string.
- A message **fails** if it ends in `.`, `!` or `?`, or if its first character is uppercase and its
  first word is not on a short acronym allow-list (`DuckDB`, `DDL`, `LSN`, `JSON`, `TLS`, `S3`,
  `UTF-8`). Leading `{` (as in `#[error("{0}")]`) is fine.
- A self-test on the checker itself, so the gate is proven to reject `"Failed."` rather than merely
  proven to pass on a tree that already conforms.

**Explicitly deferred** (do *not* build these here)

- `.context("…")` / `.with_context(|| …)` / `bail!("…")` literals. All 99 are conformant today, but
  they need a smarter parser (interpolated `format!`, multi-argument macros) — a follow-up.
- **No production error message changes.** If the gate flags something, the correct fix is the
  allow-list, not a reworded message; the tree is already conformant and this PR must stay a pure
  addition. (PR 10.5 is where message *content* was last touched.)
- No `#[error]` scanning inside `tests/`, `benches/` or `tests/e2e` — production surface only.

//! Conformance gate for `err-lowercase-msg` (PR 10.7): every production `#[error("…")]` literal
//! starts lowercase (or with an allow-listed acronym) and carries no trailing sentence punctuation,
//! so `{:#}` chains read as one sentence. Pure source scanning — no Docker, no new dependency.

fn production_sources(root: &Path) -> Vec<PathBuf> {

}

/// Each `#[error("…")]` literal in `src`, as `(1-based line number, logical message)`.
/// `#[error(transparent)]` yields nothing; `\`-continuations are joined into one message.
fn error_literals(src: &str) -> Vec<(usize, String)> {
    todo!()
}

/// `Err(reason)` when `msg` breaks the convention; `Ok(())` otherwise.
fn check(msg: &str) -> Result<(), String> {
    todo!("trailing . ! ? => Err; uppercase first char whose first word is not in ACRONYM_ALLOW => Err")
}

#[test]
fn every_production_error_literal_follows_the_convention() {
    let root = repo_root();
    let mut violations: Vec<String> = Vec::new();
    for path in production_sources(&root) {
        let src = std::fs::read_to_string(&path).expect("read a production source file");
        for (line, msg) in error_literals(&src) {
            if let Err(why) = check(&msg) {
                violations.push(format!("{}:{line}: {why} — {msg:?}", path.display()));
            }
        }
    }
    assert!(
        violations.is_empty(),
        "err-lowercase-msg violations:\n{}",
        violations.join("\n")
    );
}

#[test]
fn the_gate_rejects_what_it_is_supposed_to_reject() {
    // Accepted: house style, interpolation-first, and the two real acronym messages.
    assert!(check("invalid configuration: {0}").is_ok());
    assert!(check("{0}").is_ok());
    assert!(check("DuckDB: {0}").is_ok());
    assert!(check("DDL capture not installed: {detail}").is_ok());
    // Rejected: the two failure modes the rule names.
    assert!(check("Failed to read config").is_err());
    assert!(check("failed to read config.").is_err());
    assert!(check("invalid JSON format!").is_err());
}

#[test]
fn the_extractor_sees_multi_line_and_skips_transparent() {
    let src = r#"
        #[error(transparent)]
        Config(#[from] ConfigError),
        #[error(
            "publication {p} missing table {s}.{t} \
             (fix: ALTER PUBLICATION {p} ADD TABLE {s}.{t})"
        )]
        PublicationGap { p: String, s: String, t: String },
    "#;
    let found = error_literals(src);
    assert_eq!(found.len(), 1, "transparent must not be extracted");
    assert!(found[0].1.starts_with("publication "));
    assert!(found[0].1.contains("ALTER PUBLICATION"), "continuation must be joined");
}

## Hints & gotchas

- **`#[error(...)]` is not always one line.** `pg-sink/src/preflight.rs` wraps two messages across
  lines with a trailing `\` inside the string literal. If your extractor is a per-line regex you
  will scan 65 of 67 messages and never know. Write the state machine: find `#[error(`, skip
  whitespace/newlines, require `"`, then read to the first unescaped `"`, collapsing `\<newline>`
  plus the following indentation.
- **Do not add `regex`.** A new dependency has to clear `cargo deny` (advisories + the 8-license
  allow-list + bans), and this is ~60 lines of `str` scanning. Same reason: no `walkdir` — hand-roll
  the recursion with `std::fs::read_dir`.
- **`CARGO_MANIFEST_DIR` is the only reliable anchor.** `cargo test` sets the CWD to the package
  root for integration tests, but do not rely on it — `env!("CARGO_MANIFEST_DIR")` is resolved at
  compile time and is exactly `<repo>/crates/common`.
- Integration tests under `tests/` are **not** covered by `clippy.toml`'s
  `allow-unwrap-in-tests`/`allow-expect-in-tests` — that is why all 20 existing ones carry a
  file-level `#![allow(clippy::unwrap_used, clippy::expect_used)]`. Copy the header verbatim,
  comment and all. (PR 10.10 will add `reason = "…"` to every such attribute; leaving it in the
  house shape now keeps that sweep mechanical.)
- Fail with **all** violations at once (collect into a `Vec`, assert empty), not on the first one.
  A gate that reports one problem per run is a gate people learn to hate.
- Keep the acronym list tight and comment why each entry is there. `LSN`, `JSON`, `TLS`, `S3` and
  `UTF-8` are forward-looking; `DuckDB` and `DDL` are the two the tree actually uses today.
- `#![deny(warnings)]` is inherited via `[lints] workspace = true`, so an unused helper in the test
  file is a hard error, not a warning. Delete scaffolding as you go.
