# PR 10.12 — Document every fallible public function with an Errors section

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,control,loader,pg-sink,pg-to-arrow

> **Phase:** 10 — Rust error handling · **Crates touched:** `common`, `control`, `pg-to-arrow`,
> `pg-sink`, `loader` · **Est. size:** L · **Depends on:** PR 10.11 · **Unlocks:** PR 11.1

walrus is a well-documented codebase by volume — **1736 `///` lines and 774 `//!` lines** — and it
has **literally zero `# Errors` sections**, against **201 `clippy::missing_errors_doc` sites**
(pg-sink 69, control 39, loader 34, pg-to-arrow 18, common 8, the rest in the e2e harness). That is
the second-largest pedantic lint in the whole clippy survey, behind only `doc_markdown`. The gap is
not cosmetic: `CommonConfig::load` (`common/src/config.rs:71`) and `ReplicaIdentity::from_wire`
(`common/src/pg_shape.rs:29`) both return `Result` under a paragraph of prose that never says what
can fail, so a caller deciding whether to retry has to read the body — even though this project
models terminal-vs-transient as *data* (`Error::is_terminal`) precisely so that decision can be
made from the type. This PR writes the missing sections against the real variants and then promotes
`missing_errors_doc` to `deny`, so the next fallible `pub fn` cannot land undocumented.

## Why — learning objectives

- **The rustdoc `# Errors` convention** — the standard section every Rust caller looks for, and
  intra-doc links to `Error::Config` that turn a prose list into navigable references to the
  actual variants.
- **walrus's failure taxonomy end-to-end** — writing 168 of these forces you to answer, per public
  entry point, which failures are terminal and which are transient. Doing it will surface at least
  one function whose declared error type does not match what it can actually produce.

## Read first

- [`err-doc-errors`](../../../.claude/skills/rust-skills/rules/err-doc-errors.md) — take the three
  "Error Section Format Options" (bullet list / `Returns [`Variant`] if …` / prose) and the
  "Linking to Error Variants" example. Pick per function; do not mechanise one shape onto all 168.
- `crates/common/src/error.rs:15-121` — the taxonomy every `# Errors` section in `common` links
  into, and the `is_terminal` / `exit_code` matches that tell you which sentence to write.
- `crates/common/src/config.rs:67-125` — `CommonConfig::load` and `CommonConfig::validate`: a
  figment extract layered under a bounds check, i.e. two *different* reasons to return
  `Error::Config`. The section has to distinguish them.
- `crates/common/src/pg_shape.rs:27-40` — `ReplicaIdentity::from_wire`, the smallest possible case
  (one variant, one condition). Write this one first to fix the house style.
- `crates/control/src/db.rs:6-40, 78-92` — `ControlError`'s six variants and the two public
  entry points (`connect`, `run_migrations`). After PRs 10.1-10.2 the variant a caller sees comes
  from `impl From<sqlx::Error>`, so the section must describe the *classification*, not the call.
- `crates/pg-to-arrow/src/error.rs:4-27` and `crates/pg-sink/src/config.rs:135-155` — the other two
  taxonomies you will be linking into.
- `Cargo.toml:15-21` — where the lint promotion goes, and why no `priority` is needed.

**In scope**

- One `# Errors` section on every fallible public item that `clippy::missing_errors_doc` reports in
  `common`, `control`, `pg-to-arrow`, `pg-sink` and `loader` — 168 sites.
- Each section names **concrete variants** with intra-doc links to `Error::Config` or
  `ControlError::CheckViolation` and the condition that produces them. "Returns an error if
  the operation fails" is a failed section; so is restating the signature.
- Where a function's errors are worth classifying, say so: "transient — the bootstrap retries this
  under the startup deadline" vs "terminal". That sentence is the thing an operator actually needs.
- `[workspace.lints.clippy]` gains `missing_errors_doc = "deny"` **in the final commit**, once the
  count is already 0.
- `tests/e2e` (~33 sites) takes a single crate-level allow rather than 33 sections:

  ```rust
  #![allow(
      clippy::missing_errors_doc,
      reason = "compose-gated harness, not a published API — every helper returns \
                anyhow::Result and its failure IS the test failure"
  )]
  ```

  It is a black-box test driver with no library consumers; document its
  ~10 real entry points in prose if you like, but do not let it double the size of this PR. State
  this decision in the PR body so it is a choice, not an omission.

**Explicitly deferred** (do *not* build these here)

- `# Panics` (1 site — `clippy::missing_panics_doc` at `common/src/metrics.rs:137`), `# Examples`,
  and doctests. Those are Phase 29 (`doc-*`). The tree has 2 doc code fences today and this PR adds
  none — a doctest is a compiled test, and 168 of them would change what `cargo test` costs.
- Do **not** enable `clippy::pedantic` wholesale. Exactly one lint is promoted here; the other 50
  pedantic/nursery lints (1192 sites — `doc_markdown` 203, `use_self` 145, `must_use_candidate` 109,
  …) belong to their own phases and would swamp the diff.
- **Do not re-classify any error while documenting it.** You will notice things — e.g.
  `ReplicaIdentity::from_wire` returns `Error::Internal` for a bad protocol byte, which is arguably
  a decode failure rather than an internal one. Write down what the code *does*, open a follow-up,
  and keep this PR documentation-plus-one-lint. A behaviour change hidden in a 168-file diff is
  unreviewable.
- No `.sql` or `.sqlx` cache changes (there is no Docker locally to regenerate the cache) and no
  new dependency.

## Hints & gotchas

- **Land it crate by crate, promote the lint last.** `common` (8) → `pg-to-arrow` (18) →
  `loader` (34) → `control` (39) → `pg-sink` (69). Flipping `missing_errors_doc` to `deny` in the
  first commit means every intermediate commit is red and `git bisect` becomes useless. If the
  reviewer prefers, split at the crate boundary into 10.12a-e — a merged `common`+`pg-to-arrow`
  slice is worth more than a stalled 168-file branch.
- **`--force-warn` is the enumeration tool.** `cargo clippy … -- --force-warn clippy::missing_errors_doc`
  lists the sites without changing the workspace lint table, so you can re-run it after every crate
  and watch the number fall.
- **Clippy does not validate intra-doc links; rustdoc does.** A link to `Error::Config` that does not
  resolve is a `rustdoc::broken_intra_doc_links` warning, invisible to `cargo clippy` and fatal
  under `warnings = "deny"` when someone finally runs `cargo doc`. Run `cargo doc --workspace
  --no-deps` yourself, per crate, as you go. Cross-crate links need the full path
  (`common::Error::Config`) and the crate must be a dependency — which it is, in all five.
- **`missing_errors_doc` only fires on items reachable from the crate root.** A `pub fn` in a
  private module does not count, and `pub(crate)` never does. Do not chase sites the lint does not
  report — and do not widen visibility to "fix" anything.
- The lint accepts the section on the item's own doc comment only; `#[doc = "…"]` built from a
  constant will not satisfy it, and neither will a section on the enclosing `impl`.
- **`# Errors` goes after the summary paragraph and before `# Examples`.** Keep the existing first
  paragraph intact — `too_long_first_doc_paragraph` already has 83 sites and this PR must not add to
  them by merging the error text into the opening line.
- Reuse the sentence the error variant's own doc comment already carries — `common::Error` and
  `ControlError` document terminal-vs-transient per variant (`error.rs:22-61`, `db.rs:9-39`). The
  `# Errors` section's job is to say *which* of those a given function can produce, not to reinvent
  the description.
- 168 doc edits will produce a very large diff. Keep the commits mechanical and per-crate, and never
  let a `rustfmt`-driven reflow of surrounding code sneak in — `cargo fmt` does not touch doc
  comments, so any non-`///` line in the diff is a red flag.
