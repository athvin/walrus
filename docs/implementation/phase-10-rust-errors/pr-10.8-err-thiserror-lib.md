# PR 10.8 — Ban anyhow from the pure library crates via cargo-deny

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test,deny · **Test packages:** —

> **Phase:** 10 — Rust error handling · **Crates touched:** — (repo-root `deny.toml` only) ·
> **Est. size:** S · **Depends on:** PR 10.7 · **Unlocks:** PR 10.9

walrus already splits libraries from applications exactly the way the rule prescribes: `common`,
`control` and `pg-to-arrow` carry **zero** `anyhow` in their manifests and **zero** `anyhow::`
references in their sources, expressing every failure through one of the tree's **16
`#[derive(thiserror::Error)]` enums**; `anyhow` is a direct dependency of exactly three packages —
`loader`, `pg-sink` and `e2e` — which `Cargo.lock` confirms are also its *only* dependents in the
whole graph. The split is a convention, not a constraint: `deny.toml`'s `[bans]` section (lines
50-56) has an empty `skip = []` and no `deny` list at all, so a future PR can add
`anyhow = { workspace = true }` to `crates/common/Cargo.toml`, start returning `anyhow::Result`
from `CommonConfig::load`, and erase the typed surface that `Error::is_terminal()` and the
`ExitCode` contract are built on — with CI fully green. This PR encodes the boundary as a
dependency-graph invariant that the always-on `supply-chain` job enforces on every push.

## Why — learning objectives

- **thiserror-for-libraries vs anyhow-for-applications** — why a matchable enum is the library
  contract and an erased `anyhow::Error` is the application's convenience, and why that split has to
  be *checked* rather than remembered.
- **`cargo-deny [bans].deny` + `wrappers` as an architecture test** — a dependency-graph assertion
  is a cheaper, harder-to-bypass boundary check than a grep or a code review habit.

- `crates/common/src/error.rs:20-61`, `crates/control/src/db.rs:6-40`,

  each one models terminal-vs-transient as *data* (`is_terminal`, `exit_code`), which is precisely

- `.github/workflows/ci.yml:468-485` — the always-on `supply-chain` job. `cargo deny check` runs all
  four families against `Cargo.lock` with no crate compilation, so this gate costs seconds and needs
  no DuckDB build.
- `CONTEXT` / `docs/implementation/README.md` "Conventions" — errors in libraries are `thiserror`
  enums; errors in binaries are `anyhow` with context, mapped to `ExitCode` at the top of `main`.

## Skeleton

The whole PR is this diff (archetype B — the "skeleton" is the config, and `cargo deny` is the
guard):

```diff
 [bans]
 # Start at "warn": the tree carries known duplicate majors (arrow 54 vs 58, rand 0.8 vs 0.10,
 # windows-sys generations, …) pulled by transitive deps. Tighten to "deny" in a follow-up once the
 # tree is de-duplicated — don't block this PR on tree hygiene (task Hints).
 multiple-versions = "warn"
 # Each future entry needs a justifying comment.
 skip = []
+# Architectural boundary (PR 10.8, rule `err-thiserror-lib`): libraries expose *matchable* errors,
+# applications erase them. `common`, `control` and `pg-to-arrow` are libraries — their failure
+# surface is 16 thiserror enums whose `is_terminal()` / `exit_code()` classification is modelled as
+# data (see crates/common/src/error.rs). Adding `anyhow` to one of them would erase that surface,
+# so only the three application packages may depend on it. If a fourth ever legitimately needs
+# anyhow, add it to `wrappers` in the SAME PR that adds the dependency — the list is the review.
+deny = [
+  { crate = "anyhow", wrappers = ["loader", "pg-sink", "e2e"] },
+]
```

The reviewable proof is the policy entry plus the existing positive gate:

```console
$ rg -n 'crate = "anyhow"|wrappers = \["loader", "pg-sink", "e2e"\]' deny.toml
$ cargo deny check bans
bans ok
```

## Hints & gotchas

- **`wrappers` means "may depend on it", not "is exempt from the ban".** cargo-deny still reports
  the crate as banned for anyone else; the three wrappers are simply allowed direct dependents.
  Verify the list first with `cargo tree -i anyhow` — it must print exactly `loader`, `pg-sink` and
  `e2e` before you write the entry, or the gate fails on main.
- **Use the modern `crate = "…"` PackageSpec key.** cargo-deny ≥0.14 replaced `{ name = "anyhow" }`
  with `{ crate = "anyhow" }`; the old key still parses but emits a deprecation the pinned
  `cargo-deny@0.19.9` will print into CI logs.
- `anyhow` is a **direct** dependency only. If a transitive dep ever pulls it, the ban fires with
  that crate named as the missing wrapper — which is informative, not a false positive: decide then
  whether to allow-list it, and comment why.
- Run the pinned version locally (`cargo install cargo-deny --version 0.19.9`) so a newer local
  cargo-deny doesn't disagree with CI about syntax.
- `deny.toml` is not Rust, so `cargo fmt` will not touch it. Match the surrounding comment style by
  hand: full sentences, ~100 columns, and a "drop this when …" clause where one applies.
- This PR must **not** modify `.sql` or the `.sqlx` offline cache (no Docker locally to regenerate
  it) and must not touch `Cargo.lock` — if `cargo deny` rewrote the lock file, something else went
  wrong.
