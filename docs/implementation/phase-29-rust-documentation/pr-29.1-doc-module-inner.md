# PR 29.1 — Give every module doc a one-line summary paragraph

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 29 — Rust documentation · **Crates touched:** `common`, `control`, `loader`, `pg-sink`,
> `pg-to-arrow` · **Est. size:** L · **Depends on:** PR 28.15 · **Unlocks:** PR 29.2

walrus does not have a *missing* module-doc problem: all **80** production files under `crates/*/src`
(excluding `*_test.rs`) already open with `//!`, 1247 inner-doc lines in total. What is broken is the
**shape**. `clippy::too_long_first_doc_paragraph` fires at **83 unique sites** (loader 24, pg-sink 23,
control 18, pg-to-arrow 10, common 7, e2e 1) because the first paragraph runs three to five lines
before the first blank `//!`. rustdoc puts *only that first paragraph* in the module index and in the
parent's item table, so today a reader scanning `common`'s index gets a wall of prose per entry
instead of a scannable one-line summary. This PR splits every one of those 83 first paragraphs into a
summary line plus a body, turns the lint on at `deny` in `[workspace.lints.clippy]` (it is unset
anywhere in the workspace today), and adds a `scripts/check-module-docs.sh` guard so the 80/80 `//!`
convention itself cannot silently regress.

## Why — learning objectives

- **rustdoc's summary-vs-body split** — everything before the first blank `//!`/`///` line is the
  *summary*; it is what the module index, the parent item table, and search results render. The rest
  is the body and only appears on the item's own page.
- **`//!` inner attributes on module files** — `//!` documents the *enclosing* item (the file's
  module), which is why it must be the first thing in the file, above the `use` block; `///`
  documents the item that follows it.
- **walrus module topology** — you will read all 80 production modules and write one sentence each
  saying what that module owns in the CDC pipeline. That is the point of the exercise as much as the
  lint is.

- `scripts/check-module-docs.sh` — assert every non-test file under `crates/*/src` has `//!` on line

**Explicitly deferred** (do *not* build these here)

- `# Examples` / `# Errors` / `# Panics` sections — PRs 29.8, 29.3 and 29.4 respectively. A summary

- Backticking or linking bare identifiers (`DuckDB`, `wal_sender`, `TupleData`) — that is

- Doc *content* in `*_test.rs`, `crates/*/tests/`, and `crates/*/benches/` — those files report zero

```bash
#!/usr/bin/env bash
# scripts/check-module-docs.sh — walrus module-doc guard (PR 29.1).
#
# clippy cannot express "line 1 of this file is an inner doc comment": `missing_docs` accepts a doc
# anywhere on the item and says nothing about placement, and `too_long_first_doc_paragraph` only
# fires on docs that already exist. Hence a grep gate. 80/80 production files pass today.
set -euo pipefail

missing=0
total=0
while IFS= read -r f; do
  # Go-style sibling unit-test files are `#[path]`-included into their parent module and therefore
  # cannot carry their own `//!` — skip them, and skip nothing else.
  case "$f" in *_test.rs) continue ;; esac
  total=$((total + 1))
  if [ "$(head -n 1 "$f" | cut -c1-3)" != '//!' ]; then
    echo "::error file=${f},line=1::module file must open with an inner doc comment"
    missing=$((missing + 1))
  fi
done < <(find crates/*/src -name '*.rs' | sort)

echo "module docs: $((total - missing))/${total} files open with an inner doc comment"
todo!("exit non-zero when `missing` > 0, and also fail if `total` is 0 (a broken find = a silent pass)")
```

## Hints & gotchas

- The lint's threshold is the **first paragraph**, not the first line: it fires when everything
  before the first blank doc line exceeds ~200 characters. Two short lines are fine; one 210-char
  line is not. The fix is always a blank `//!` / `///`, never truncation.
- `clippy::too_long_first_doc_paragraph` is **nursery** and default-`allow`. Confirm the group
  yourself before writing the Cargo.toml comment: `clippy-driver -W help | grep too-long-first-doc`.
  Because it is not in `clippy::all`, adding it beside `all = "deny"` does **not** trip
  `clippy::lint_groups_priority`, so no `priority = -1` is needed.
- Reproduce the baseline the way the evidence was gathered — `[workspace.lints] warnings = "deny"`
  turns a `-W` into an error and aborts the run, so you must use `--force-warn`:
  `cargo clippy --all-targets --all-features -- --force-warn clippy::nursery`. Dedupe by
  `(file, line, col)`; `--all-targets` checks each file once per target, so raw counts double.
- Work crate by crate (`cargo clippy -p control --all-targets …`) and commit per crate. 83 edits in
  one pass is where a "reworded" sentence sneaks in.
- `--all-features` enables the e2e `it` feature, and `tests/e2e` declares `[lints] workspace = true`,
  so the workspace lint reaches `tests/e2e/src/lib.rs`. That crate already carries a file-level
  `#![allow(clippy::unwrap_used, clippy::expect_used)]` at line 1 — resist the temptation to append
  this lint to it for one three-line paragraph.
- `//!` must precede any `use`, but it goes **after** a file-level `#![allow(...)]` — see
  `tests/e2e/src/lib.rs:1-2` for the ordering the compiler wants.
- Unit tests here are Go-style sibling files (`src/foo.rs` → `src/foo_test.rs`), not inline
  `mod tests {}`. They are `#[path]`-included, so they must **not** grow a `//!` — that is exactly
  the case the guard script skips.
- `clippy::all` and `warnings` are already `deny` at the workspace root and all six members declare
  `[lints] workspace = true`, so the new lint takes effect everywhere with no per-crate edit.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. No new dependency is needed here; anything you add must clear
  `cargo deny` (advisories, the 8-license allow-list, bans).
