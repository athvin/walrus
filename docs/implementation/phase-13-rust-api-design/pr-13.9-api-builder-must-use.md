# PR 13.9 — Make ignoring a builder method a compile error

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 13 — Rust API design · **Crates touched:** `pg-sink` ·
> **Est. size:** S · **Depends on:** PR 13.8 · **Unlocks:** PR 13.10

PR 13.8 gave walrus its first chained `-> Self` methods. Before it, the tree had none — which is
why clippy's `return_self_not_must_use` reported **0** sites among 1192 pedantic/nursery findings,
and why the whole production tree carried **0** `#[must_use]` before PR 13.2. A consuming builder
whose return value is dropped is the classic silent bug: `builder.epoch(e);` compiles, does nothing,
and the next `.build()` fails on a field you are certain you set — or worse, succeeds with a stale
one. This PR closes that: `DecodeLoopBuilder` becomes `#[must_use]` at the type level, every setter
carries a `#[must_use = "…"]` with a message, `return_self_not_must_use = "deny"` lands in
`[workspace.lints.clippy]`, and a ```compile_fail doctest pins the regression so the gate cannot be
quietly removed. `grep -c 'return_self_not_must_use' Cargo.toml` goes 0 → 1.

## Why — learning objectives

- **`#[must_use]` on a type vs on each method** — the type-level attribute is what actually makes
  `builder.epoch(7);` a `unused_must_use` warning (and therefore an error under the workspace's
  `warnings = "deny"`); the per-method attributes document intent and satisfy the rule.
- **`compile_fail` doctests as a lint regression test** — an ordinary `#[test]` cannot assert that
  something *fails to compile*; a doc fence can, and it runs under `cargo test`, not under
  `--all-targets`.
- **Why a silently-dropped decode-loop builder is invisible** — a sink whose `router` was never wired
  looks alive: it answers `/healthz`, answers keepalives, and simply never batches a row.

## Hints & gotchas

- **A bare `#[must_use]` on a setter is a build failure.** `clippy::double_must_use` fires on a
  message-less `#[must_use]` when the returned type is *already* `#[must_use]` — which it is, once
  the builder type is annotated. It is a `style` lint, so it is inside `clippy::all = "deny"`.
  Always write `#[must_use = "…"]`.
- Consequently, `clippy::return_self_not_must_use` will report **0** sites *after* this PR too: it
  does not fire on methods whose return type is already `#[must_use]`. That is fine and expected —
  the deny is a gate for the *next* builder someone writes on a non-`must_use` type. Do not chase
  a non-zero count.
- `unused_must_use` is a warn-by-default rustc lint. Inside a doctest the workspace's
  `warnings = "deny"` may or may not propagate, so put `#![deny(unused_must_use)]` as the first line
  **inside** the `compile_fail` fence. Without it the fence may compile and the doctest will fail
  with "expected compile error, but it compiled".
- A `compile_fail` doctest that fails for the *wrong* reason still passes, which is the classic trap.
  Sanity-check it once by changing `b.epoch(7);` to `let _ = b.epoch(7);` — the doctest must then
  fail (because the code now compiles). Restore afterwards.
- `cargo clippy --all-targets` does **not** run doctests, and neither does `cargo test
  --all-targets`. The fence only runs under `cargo test -p pg-sink` / `cargo test --workspace`
  (which includes `--doc` by default). Do not "verify" this PR with clippy alone.
- The doctest names the item through the *public* path `pg_sink::consume::DecodeLoop` — doctests
  compile as external crates. If `DecodeLoop::builder` is not `pub`, the fence will fail to compile
  for a reason that has nothing to do with `must_use`.
- `[workspace.lints]` only applies to a member that declares `[lints] workspace = true`; all six
  members already do, so `Cargo.toml` is the only manifest to touch.
- `unwrap`/`expect` are `deny` in production; nothing here needs them. Do not touch any `.sql` file
  or the `.sqlx` offline cache — there is no Docker locally to regenerate it.
