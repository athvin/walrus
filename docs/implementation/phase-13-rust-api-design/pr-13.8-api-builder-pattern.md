# PR 13.8 — Replace the 14-argument decode-loop signature with a builder

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 13 — Rust API design · **Crates touched:** `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 13.7 · **Unlocks:** PR 13.9

`run_decode_loop` takes **14 positional parameters** (`crates/pg-sink/src/consume.rs:31-45`) and
carries `#[allow(clippy::too_many_arguments)]` with a comment conceding the arity
(`consume.rs:28-30`); `BatchRouter::push` takes 8 with the same allow (`consume.rs:511`). Those two
are the **only** `too_many_arguments` allows in the whole tree, and the 13th parameter
(`_schema_version`) has been dead since PR 2.33 — the underscore is right there in the signature,
and `main.rs:174` still passes `SCHEMA_VERSION` into it. Not one chained builder exists anywhere:
clippy pedantic reported `return_self_not_must_use` at **0** sites across 1192 findings, and the sole
`*Builder` type walrus defines (`pg_to_arrow::BatchBuilder`, `batch.rs:73`) is a row accumulator, not
a configurator. After this PR the wiring reads as `DecodeLoop::builder().stream(…).router(…)…
.build()?.run().await`, the dead parameter is gone, and both `#[allow]`s are deleted while
`cargo clippy --all-targets --all-features -- -D warnings` stays green.

## Why — learning objectives

- **Consuming builders** — `fn field(mut self, v: T) -> Self` moves the builder through the chain;
  `build(self) -> Result<T, E>` is the single place a missing required field becomes an error.
- **Grouping intrinsic parameters into a context struct** — `BatchRouter::push`'s six provenance
  arguments are one concept (a decoded row's identity), not six knobs; a `RowSource` struct removes
  the arity without inventing a second builder.
- **The walrus decode-loop wiring** — stream, relation cache, batch router, Parquet sink, durability
  checkpoint, streamed-txn demux, DDL consumer, heartbeat, health state, control pool, epoch and the
  reload watermark waiters. Knowing *why* each one is there is what makes the builder readable.

## Scope

**In scope**

- `crates/pg-sink/src/consume.rs`: introduce `pub struct DecodeLoop<'a>` holding the 13 live
  parameters, `pub struct DecodeLoopBuilder<'a>` with `Option` fields and one consuming setter each,
  `DecodeLoop::builder()`, `DecodeLoopBuilder::build() -> Result<DecodeLoop<'a>, DecodeLoopError>`,
  and `DecodeLoop::run(self) -> anyhow::Result<()>` carrying today's loop body verbatim.
- Delete `pub async fn run_decode_loop` and its `#[allow(clippy::too_many_arguments)]`.
- **Drop the dead `_schema_version` parameter entirely** — it has ridden the cached shape since
  PR 2.33; the builder must not offer a setter for it.
- `crates/pg-sink/src/consume.rs`: replace `BatchRouter::push`'s six provenance arguments with a
  private `RowSource<'_>` struct (`oid`, `op`, `values`, `frame_lsn`, `xid`) so `push` becomes
  `(&mut self, cache, row)` and its `#[allow]` is deleted too. `route`'s now-unused
  `schema_version` parameter is renamed `_schema_version` (its arity is 5 — no allow needed).
- `crates/pg-sink/src/main.rs:161-177`: rewrite the call site as the builder chain.
- `crates/pg-sink/src/consume_test.rs`: **new** sibling test module asserting `build()` names the
  first missing required field.

**Explicitly deferred** (do *not* build these here)

- **No typestate on the builder.** Required fields stay a `build()`-time `Result`; compile-time
  required-field checking is exercised separately in PR 13.15 (`api-typestate`).
- **No `#[must_use]` anywhere.** Marking the builder type and its setters, and denying
  `clippy::return_self_not_must_use`, is PR 13.9 — this PR is the *shape* only.
- `BatchRouter::push` may keep its arity if the borrow split makes `RowSource` unnatural (the
  `values: &[TupleValue]` borrow is re-borrowed from the decoded `Message`) — **but the `#[allow]`
  must still go**, so find a grouping that works.
- No change to what the loop *does*: message ordering, sealing at commit boundaries, drain on
  cancel, and every `tracing` field stay byte-identical.

## Hints & gotchas

- **The lifetimes are the hard part.** Every borrow in `main` is a distinct local, so one `'a` on
  both the builder and `DecodeLoop` works — but the builder must *hold* the `&mut` (not re-borrow),
  which means the setters take `&'a mut T` and the builder is moved, never reused. That is exactly
  what a consuming builder gives you for free.
- `#[derive(Default)]` on `DecodeLoopBuilder<'a>` is fine: `Option<T>: Default` for every `T`, and
  the derive does not require `T: Default`. It *does* add an `'a` bound-free impl, so
  `DecodeLoop::builder()` in a unit test infers `'a` freely.
- `token: CancellationToken` is cheap to clone (an `Arc` inside) — take it **by value** in the
  setter, matching today's `token.clone()` at the call site. Do not add a lifetime for it.
- Deleting the 13th parameter means `BatchRouter::route`'s `schema_version` becomes unused. Rename
  it `_schema_version` rather than removing it: `route` is called from the loop body **and** from
  six integration tests under `crates/pg-sink/tests/`, and changing its arity is out of scope.
- `clippy::all` + `warnings` are `deny`, so a leftover `use` of a now-unused import in `main.rs`
  (e.g. the `SCHEMA_VERSION` const if nothing else reads it) fails CI. Check whether
  `establish_stream` still needs it before deleting.
- `unwrap`/`expect` are `deny` in production; the new `consume_test.rs` is `#[cfg(test)]`, where
  `clippy.toml` re-allows them.
- Unit tests are Go-style siblings — `consume.rs` → `consume_test.rs` with `#[cfg(test)]
  #[path = "consume_test.rs"] mod tests;` at the bottom of `consume.rs`. Never an inline
  `mod tests {}`.
- Do not touch any `.sql` file or the `.sqlx` offline cache — no Docker locally to regenerate it.
  The loop body's `sqlx::query_file!` calls move verbatim into `run`, which keeps the cache valid.
- Keep `run`'s body a pure move. Reviewing a 300-line relocation *plus* behaviour edits is how this
  PR turns into a regression; make the diff mechanical.
