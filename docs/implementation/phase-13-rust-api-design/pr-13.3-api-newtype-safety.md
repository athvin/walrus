# PR 13.3 — Introduce the EpochNo newtype (domain-ID newtypes, slice 2 of 4)

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,control,loader,pg-sink

> **Phase:** 13 — Rust API design · **Crates touched:** `common`, `control`, `loader`, `pg-sink` ·
> **Est. size:** L ·
> **Depends on:** PR 13.2 · **Unlocks:** PR 13.4

PR 8.4a shipped `ManifestId` as "slice 1 of 4", and `crates/common/src/ids.rs:5` records in writing
that `EpochNo` / `SchemaVersion` / `ReloadId` stay bare `i64` **for now**. They still are: `epoch:
i64` appears at **62** production sites, and the three names together at 100 (control 42, pg-sink 41,
loader 13, common 4). The same crate also carries `pub type TableId = u32` (`memory.rs:19`) — a bare
alias, not a newtype — colliding by name with `pub struct TableId { schema, table }`
(`preflight.rs:23`), and `InflightMeter::add(key: (TableId, u32))` is called as
`self.meter.add((oid, sub_xid), bytes)` (`stream_txn.rs:189`) where both halves are `u32` and
swapping them compiles clean. This PR closes slice 2: after it, an epoch is an `EpochNo` everywhere
and cannot be handed to a function that wanted a manifest id, a schema version, or a table OID.

## Why — learning objectives

- **The newtype pattern with orphan-safe trait impls** — `EpochNo` lives in `common`, so `common` is
  the only crate that may implement foreign traits (`sqlx::Type`, `serde::Serialize`) for it; every
  other crate consumes it through `From`/`.0`.
- **Transparent database encoding without derive macros** — `ManifestId` binds and decodes exactly
  as its inner `i64` via hand-written `Type`/`Encode`/`Decode` (`ids.rs:37-66`), deliberately
  avoiding `sqlx`'s `macros` feature. `EpochNo` copies that verbatim for runtime `.bind` calls.
  Offline `query_file!` parameters still have an exact generated `i64` input type, so those checked
  boundaries pass `epoch.0`; neither case requires regenerating the `.sqlx` cache.
- **walrus epoch semantics** — an epoch is a **generation counter** for the §1.8 total-restart
  contract (the sink bumps `replication_state.epoch` when the lifelong slot is lost, and every
  `.duckdb` built for the retired generation is wiped). It is not a row id, and it namespaces every
  control-plane table and every S3 key prefix.

**Conflict — read before you start**

There is **no Docker on this machine**, so the `.sqlx` offline cache *cannot* be regenerated.
Therefore:

- `EpochNo` **must** reuse the transparent-`int8` pattern already proven for `ManifestId`
  (hand-written `Type`/`Encode`/`Decode` over `i64`, `crates/common/src/ids.rs:37-66`). Runtime
  `.bind(epoch)` calls therefore stay plain `int8`; checked `query_file!` inputs use `epoch.0` to
  satisfy the offline macro's exact generated `i64` expression type. The committed query metadata
  stays valid in both cases.
- Do **not** edit any `.sql` file and do **not** edit anything under `.sqlx/**`. In particular, do not
  reach for an inline `as "epoch: EpochNo"` type override — that lives in the SQL text and would
  invalidate the cache. Convert at the Rust boundary instead: `epoch.0` into a checked query and
  `EpochNo(rec.epoch)` out, exactly as `manifest.rs:146` wraps a decoded `ManifestId`.
- `loader::ddl::SchemaVersion` (`ddl.rs:27`) is **already taken** by a shape-snapshot struct. The
  future `SchemaVersion` newtype will need that collision resolved first — which is precisely why
  this slice does `EpochNo` alone. Do not rename `loader::ddl::SchemaVersion` here.

## Skeleton

```rust
// crates/common/src/ids.rs

/// The control plane's **generation counter** (`replication_state.epoch`): bumped when the lifelong
/// replication slot is lost and a total restart opens a new generation (§1.8). It namespaces every
/// control-plane row and every S3 key prefix — it is *not* a row id, and it must never be confused
/// with a [`ManifestId`], a schema version, or a table OID.
#[derive(
    Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, serde::Serialize, serde::Deserialize,
)]
#[serde(transparent)] // bare JSON number — SinkMeta's provenance contract, byte-for-byte as before
pub struct EpochNo(pub i64);

impl std::fmt::Display for EpochNo {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "{}", self.0)
    }
}

impl From<i64> for EpochNo {
    fn from(v: i64) -> Self {
        EpochNo(v)
    }
}

impl From<EpochNo> for i64 {
    fn from(e: EpochNo) -> Self {
        e.0
    }
}

#[cfg(feature = "sqlx")]
mod sqlx_support {
    use super::{EpochNo, ManifestId};
    use sqlx::postgres::{PgArgumentBuffer, PgTypeInfo, PgValueRef};
    use sqlx::{Decode, Encode, Postgres, Type};

    // …existing ManifestId impls unchanged…

    impl Type<Postgres> for EpochNo {
        fn type_info() -> PgTypeInfo {
            <i64 as Type<Postgres>>::type_info()
        }
        fn compatible(ty: &PgTypeInfo) -> bool {
            <i64 as Type<Postgres>>::compatible(ty)
        }
    }

    impl<'q> Encode<'q, Postgres> for EpochNo {
        fn encode_by_ref(
            &self,
            buf: &mut PgArgumentBuffer,
        ) -> Result<sqlx::encode::IsNull, sqlx::error::BoxDynError> {
            <i64 as Encode<Postgres>>::encode_by_ref(&self.0, buf)
        }
    }

    impl<'r> Decode<'r, Postgres> for EpochNo {
        fn decode(value: PgValueRef<'r>) -> Result<Self, sqlx::error::BoxDynError> {
            Ok(EpochNo(<i64 as Decode<Postgres>>::decode(value)?))
        }
    }
}
```

## Hints & gotchas

- **`tracing` will break before the type checker does.** The shorthand field syntax
  `tracing::info!(epoch, "…")` (e.g. `crates/pg-sink/src/main.rs:104`) requires the value to
  implement `tracing::Value`, which `i64` does and `EpochNo` does not. Change those sites to
  `epoch = %epoch` (uses `Display`) or `epoch = epoch.0`. Do not implement `tracing::Value` for
  `EpochNo` — that is Phase 30's territory.
- `crates/loader/src/epoch.rs` compares generations (`built < control_epoch`). That is why `Ord` is
  in the derive bundle; drop it and the total-restart detection stops compiling.
- `LoaderError::EpochBumped { from, to }` has `#[error("epoch bumped {from} → {to} …")]` — thiserror
  formats through `Display`, which is exactly why `EpochNo` needs one. The rendered message must stay
  byte-identical (bare integers, no `EpochNo(…)` wrapper), so `Display` must **not** delegate to
  `Debug`.
- Array binds: a manual `Type` impl carries no `PgHasArrayType`, so `&[EpochNo]` will not bind. If a
  query needs an epoch array, convert at the call site (`&epochs.iter().map(|e| e.0).collect::<Vec<_>>()`)
  — the same note `ids.rs:35-36` already makes for `ManifestId`.
- DuckDB is a *second* foreign boundary with its own `ToSql`; `common` does not depend on `duckdb`,
  so orphan rules forbid the impl. Use `.0` at the bind site in `crates/loader/src/duck.rs`.
- The S3 key layout is epoch-prefixed (`<epoch>/<schema>/<table>/…`, `sink.rs`). `Display` prints the
  bare integer, so `format!("{epoch}/…")` produces the same keys as before — verify one key string
  in a test rather than assuming.
- Do **not** touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine
  to regenerate it. If a `query_file!` stops compiling, the fix is on the Rust side (wrap/unwrap),
  never in the SQL.
- `unwrap()` / `expect()` are `deny` in production; `clippy::all` and `warnings` are already `deny`.
  `clippy.toml` re-allows them under `#[cfg(test)]`, which is why `ids_test.rs` may use `.unwrap()`.
- Unit tests are Go-style siblings (`foo.rs` → `foo_test.rs`); `ids_test.rs` already exists and is
  wired via `#[cfg(test)] #[path = "ids_test.rs"] mod tests;`. Extend it — do not add an inline
  `#[cfg(test)] mod tests {}`.
