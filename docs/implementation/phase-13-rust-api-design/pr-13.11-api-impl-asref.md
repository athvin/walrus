# PR 13.11 — Take `impl AsRef<Path>` when opening a DuckDB table file

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** loader

> **Phase:** 13 — Rust API design · **Crates touched:** `loader` ·
> **Est. size:** S · **Depends on:** PR 13.10 · **Unlocks:** PR 13.12

`AsRef` appears **0** times in the production tree. `TableDb::open(path: &Path)`
(`crates/loader/src/duck.rs:46`) is the one place it obviously belongs: it has 22 call sites, and
**6 of them spell out `Path::new(":memory:")` purely to satisfy the signature** — four integration
tests (`transform.rs:665`, `ddl_additive.rs:41`, `ddl_destructive.rs:38`, `compaction.rs:36`) and two
bench setups (`benches/append.rs:120`, `:142`). `std::path::Path` is otherwise used in the loader
only to build the per-table file name at `bootstrap.rs:80`. After this PR the in-memory fixture reads
`TableDb::open(":memory:")`, the 15 `&PathBuf` call sites compile completely unchanged, and the
error message still names the path — because the body binds `path.as_ref()` before using it.

## Why — learning objectives

- **`AsRef<T>` vs `Into<T>` vs `&T`** — `AsRef` is a *cheap borrow*: no ownership transfer, no
  allocation, and the generic stays monomorphic. `Into` is for when you need to own the value (that
  was PR 13.10); `&T` is for a single concrete type.
- **Where the flexibility actually comes from** — std provides `AsRef<Path>` for `str`, `String`,
  `Path`, `PathBuf`, `OsStr` and `OsString`, so one signature absorbs all six caller shapes.
- **The loader's storage layout** — one `<table>.duckdb` file per owned table under `duckdb_dir`,
  opened read-write so DuckDB's file lock is the *second* ownership fence behind the control-plane
  lease; plus the `:memory:` fixture that six test/bench harnesses use to skip the filesystem
  entirely.

## Skeleton

```rust
// crates/loader/src/duck.rs — today: `pub fn open(path: &Path) -> Result<Self, LoaderError>`.
impl TableDb {
    /// Open (or create) the file read-write, taking DuckDB's file lock. A stale lock behind an
    /// expired lease has already been reclaimed by the caller; a *live* owner would make this fail.
    ///
    /// Accepts anything path-like: a `&Path`/`&PathBuf` from the bootstrap join, or the bare
    /// `":memory:"` literal the test and bench harnesses use.
    pub fn open(path: impl AsRef<Path>) -> Result<Self, LoaderError> {
        // Bind the borrow ONCE — `duckdb::Connection::open` is itself generic over `AsRef<Path>`,
        // but forwarding the generic directly would leave nothing to call `.display()` on in the
        // error arm, and the message must stay byte-identical.
        let path = path.as_ref();
        let conn = duckdb::Connection::open(path)
            .map_err(|e| LoaderError::Duck(format!("open {}: {e}", path.display())))?;
        Ok(TableDb {
            conn,
            parquet_cols: RefCell::new(HashMap::new()),
        })
    }
}
```

## Hints & gotchas

- **Do not forward the generic straight into `duckdb::Connection::open`.** It is itself
  `P: AsRef<Path>`, so `Connection::open(path)` compiles — and then `path` is moved and you cannot
  call `path.display()` in the `map_err` closure. Bind `let path = path.as_ref();` first.
- Most of the 22 call sites already pass `&PathBuf` or `&Path`. Both implement `AsRef<Path>`
  (`&T: AsRef<U>` where `T: AsRef<U>`), so **they must not need editing** — if one does, you changed
  more than the signature.
- Removing `Path::new(...)` from `benches/append.rs` orphans its `use std::path::Path;`. Benches are
  built by `cargo clippy --all-targets`, and `warnings = "deny"` makes an unused import a hard
  failure. The four integration tests spell it `std::path::Path::new(...)` inline, so they have no
  import to clean.
- `crates/loader/benches/append.rs` carries a file-level allow for `unwrap` (benches run
  `harness = false`); do not remove it while you are in the file.
- There are **two** `Path` types in play. `object_store::path::Path` is an S3 key, not a filesystem
  path, and it does *not* implement `AsRef<std::path::Path>`. A find-and-replace across the loader
  will break `bootstrap.rs:180`.
- `impl AsRef<Path>` makes `open` generic, so `TableDb::open` can no longer be used as a bare `fn`
  value. Nothing in the tree does that — confirm with `grep -rn 'TableDb::open[^(]' crates/`.
- `unwrap`/`expect` are `deny` in production but re-allowed in `#[cfg(test)]` and under
  `crates/loader/tests/` by `clippy.toml`.
- Unit tests are Go-style siblings (`duck.rs` → `duck_test.rs`); `duck_test.rs:64` already exercises
  `TableDb::open(&dir.join(...))` and must keep passing unmodified — that is your compile-time proof
  that `&PathBuf` still works.
- Do not touch any `.sql` file or the `.sqlx` offline cache; the DuckDB DDL templates under
  `crates/loader/sql/duckdb/templates/` are `include_str!`-ed and unaffected by this change.
