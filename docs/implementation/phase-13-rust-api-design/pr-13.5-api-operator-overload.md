# PR 13.5 — Give Lsn the arithmetic operators its call sites are hand-rolling

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 13 — Rust API design · **Crates touched:** `common`, `loader` · **Est. size:** M ·
> **Depends on:** PR 13.4 · **Unlocks:** PR 13.6

There is not one `std::ops` impl anywhere in the production tree (**0** grep hits), so every LSN
calculation unwraps to the primitive first and does the arithmetic there:
`head.as_u64().saturating_sub(raw_appended.as_u64())` (`phase_a.rs:329`), the same shape at
`phase_b.rs:47-48`, and `Lsn::new(transformed_lsn.as_u64().saturating_sub(retention_lsn_lag))`
(`compaction.rs:109`). WAL **byte distance between two LSNs** and **retreat an LSN by N bytes** are
exactly the two operations the API guidelines call natural on a numeric newtype. After this PR the
distance is spelled `a - b`, the retreat is a named `Lsn::saturating_sub_bytes`, and no call site
reaches through `as_u64()` to do LSN maths any more.

## Why — learning objectives

- **`std::ops` traits and associated `Output` types** — `Sub<Lsn> for Lsn` does *not* return `Lsn`:
  the difference of two positions is a **distance**, so `type Output = u64`. Picking the right
  `Output` is most of the design.
- **Impls for reference types** — the rule asks for the `&` forms alongside the owned ones so callers
  need not copy. `Lsn` is `Copy`, so this is about ergonomics at borrow sites, not allocation.
- **LSN algebra** — byte distance is meaningful; `Lsn + Lsn` is not (adding two WAL positions is
  nonsense). `Add<u64>` advances a position; `Mul` and `Index` have no meaning at all.
- **Retention floor vs replication lag** — both are "subtract bytes", but one is a deliberately
  saturating policy knob and the other is a guaranteed-ordered measurement. Only the second gets an
  operator.

- `crates/loader/src/phase_a.rs:324-331` — `raw_append_lag_bytes`. Read the doc comment carefully:
  "a frontier already at/after the head **saturates to 0 and never underflows**". This site is
  **not** guaranteed-ordered, and `crates/loader/src/phase_a_test.rs:21` asserts
  `raw_append_lag_bytes(Some(Lsn::new(100)), Lsn::new(300)) == 0`.
- `crates/loader/src/phase_b.rs:44-49` — the transform-lag metric. Here ordering **is** guaranteed:
  the control DB enforces `CHECK (transformed_lsn <= raw_appended_lsn)` (see
  `crates/loader/src/error.rs`'s `CorruptCheckpoint`, which exists precisely because the inverse is
  "impossible").
- `crates/loader/src/compaction.rs:106-110` — `retention_floor`, the deliberately-saturating knob.

## Scope

**In scope**

- Four `std::ops` impls on `Lsn`, all in `crates/common/src/lsn.rs`, all written **fully qualified**
  (`impl std::ops::Sub<Lsn> for Lsn`) so the probe can count them:
  - `Sub<Lsn> for Lsn` with `type Output = u64` — the WAL byte distance, defined for the ordered
    case only.
  - `Sub<&Lsn> for &Lsn` with `type Output = u64` — the reference form.
  - `Add<u64> for Lsn` with `type Output = Lsn` — advance a position by N bytes.
  - `AddAssign<u64> for Lsn` — the mandatory partner of `Add`.
- A named method `Lsn::saturating_sub_bytes(self, bytes: u64) -> Lsn` for the retreat-with-saturation
  case, replacing the body of `compaction::retention_floor`.
- Rewire the three call sites:
  - `phase_b.rs:47` → `cp.raw_appended_lsn - cp.transformed_lsn`.
  - `phase_a.rs:329` → an explicit ordered guard, `if head > raw_appended { head - raw_appended }
    else { 0 }`, so the saturation that used to hide inside `saturating_sub` is now *visible* and the
    operator is only reached in its defined domain.
  - `compaction.rs:109` → `transformed_lsn.saturating_sub_bytes(retention_lsn_lag)`.
- Unit cases in `crates/common/src/lsn_test.rs` for distance, the reference form, `Add`/`AddAssign`,
  and `saturating_sub_bytes` at and past zero.

**Explicitly deferred** (do *not* build these here)

- **No operators on `ManifestId` / `EpochNo`.** They are counters, not measures — the distance
  between two generations is not a quantity anyone wants.
- No `Sum` / `Product` impls.
- No change to `Lsn`'s serde or sqlx encoding, its `Display`/`Debug`, or its parsing.
- No `Deref`, `Index`, `Mul`, `Neg`, or `Sub<u64> for Lsn` (that last one is what
  `saturating_sub_bytes` deliberately replaces).

**Conflict — read before you start**

The rule's own decision table says an operator whose meaning depends on context *not captured by the
types* must stay a named method. **Saturation is that context.** Concretely:

- `-` is defined **only for the ordered case** (`lhs >= rhs`), which the `(commit_lsn, lsn)` ordering
  contract and the control DB's `CHECK (transformed_lsn <= raw_appended_lsn)` guarantee at
  `phase_b.rs:47`. Implement it as `checked_sub` with a `debug_assert!` on the invariant and a
  saturate-to-0 fallback, so a violated invariant is loud in tests and *safe* (never a wrapped
  2⁶⁴-ish number) in release.
- `retention_floor`'s subtraction is a **policy knob** that is meant to bottom out at zero — it keeps
  a named method (`saturating_sub_bytes`), because a reader seeing `lsn - lag` would not expect the
  clamp.
- `phase_a`'s lag metric is genuinely un-ordered (a frontier may sit past the head), so it gets an
  explicit `if`, not a silently-saturating operator.
- Do **not** add `Add<Lsn> for Lsn`, `Mul`, or `Index`. Adding two WAL positions is meaningless and
  the rule lists side-effect-free-but-surprising overloads as the failure mode.

## Skeleton

```rust
// crates/common/src/lsn.rs

impl Lsn {
    /// Retreat this position by `bytes`, **saturating at 0**.
    ///
    /// A named method, not `Sub<u64>`: the clamp is a policy decision (the retention floor must
    /// never go negative and must never wrap), and a reader seeing `lsn - lag` would not expect it.
    #[must_use = "returns the retreated position; it does not move anything"]
    pub const fn saturating_sub_bytes(self, bytes: u64) -> Self {
        Lsn(self.0.saturating_sub(bytes))
    }
}

/// WAL byte distance between two positions.
///
/// **Defined for the ordered case only** (`self >= rhs`) — which is what the `(commit_lsn, lsn)`
/// contract and the control DB's `CHECK (transformed_lsn <= raw_appended_lsn)` guarantee. A
/// violation is a bug: it trips a `debug_assert!` in tests and saturates to 0 in release rather than
/// wrapping. Callers whose inputs are genuinely unordered must branch first (see
/// `loader::phase_a::raw_append_lag_bytes`).
impl std::ops::Sub<Lsn> for Lsn {
    type Output = u64;

    fn sub(self, rhs: Lsn) -> u64 {
        debug_assert!(
            self.0 >= rhs.0,
            "Lsn subtraction is defined for the ordered case only"
        );
        todo!("self.0.saturating_sub(rhs.0)")
    }
}
```

```rust
// crates/loader/src/phase_a.rs
/// The raw-append backlog in LSN-bytes: how far the newest ready file's commit LSN leads the Phase-A
/// frontier. An empty queue (`None`) is 0; a frontier already at/after the head is 0 — the ordered
/// guard is explicit now, so `-` is only ever reached in its defined domain.
fn raw_append_lag_bytes(max_ready_lsn_end: Option<Lsn>, raw_appended: Lsn) -> u64 {
    max_ready_lsn_end.map_or(0, |head| {
        if head > raw_appended {
            head - raw_appended
        } else {
            0
        }
    })
}
```

```rust
// crates/loader/src/phase_b.rs — ordering is a DB invariant here, so the bare operator is correct.
common::metrics::set_transform_lag(

    cp.raw_appended_lsn - cp.transformed_lsn,
```

```rust
// crates/loader/src/compaction.rs
/// The retention floor for a table: `transformed_lsn - retention_lsn_lag`, saturating at 0. Always
/// `<= transformed_lsn`, so pruning below it can never drop a row the incremental transform reads.
#[must_use = "returns the computed floor; it does not prune anything by itself"]
pub fn retention_floor(transformed_lsn: Lsn, retention_lsn_lag: u64) -> Lsn {
    transformed_lsn.saturating_sub_bytes(retention_lsn_lag)
}
```

```rust
// crates/common/src/lsn_test.rs
#[test]
fn subtraction_is_the_byte_distance() {
    assert_eq!(Lsn::new(500) - Lsn::new(200), 300);
    assert_eq!(Lsn::new(200) - Lsn::new(200), 0);
    assert_eq!(&Lsn::new(500) - &Lsn::new(200), 300); // reference form
}

#[test]
fn addition_advances_a_position() {
    assert_eq!(Lsn::new(100) + 24, Lsn::new(124));
    let mut l = Lsn::new(100);
    l += 24;
    assert_eq!(l, Lsn::new(124));
}

#[test]
fn saturating_sub_bytes_bottoms_out_at_zero() {
    assert_eq!(Lsn::new(300).saturating_sub_bytes(100), Lsn::new(200));
    assert_eq!(Lsn::new(100).saturating_sub_bytes(300), Lsn::ZERO);
}
```

## Hints & gotchas

- Write the impls **fully qualified** (`impl std::ops::Sub<Lsn> for Lsn`), not via
  `use std::ops::Sub;`. The DoD probe counts `impl std::ops::` lines, and a single `use` line would
  make it read 1 instead of 4. It also reads better next to `impl fmt::Display for Lsn`.
- Do not blindly convert `phase_a.rs:329` to `head - raw_appended`. `phase_a_test.rs:21` deliberately
  passes a frontier *past* the head; without the explicit guard the `debug_assert!` fires and the
  test suite goes red. That test is the invariant, not an accident.
- `debug_assert!` is compiled out in release, so the release path must still be *safe* — use
  `saturating_sub` inside the impl, never a bare `-` on the inner `u64` (which wraps silently in
  release and would produce an absurd lag metric).
- `Sub<&Lsn> for &Lsn` gives you `&a - &b`. It does **not** give you `a - &b` or `&a - b`; those need
  their own impls and are not worth it for a `Copy` type. Do not add them.
- Implementing `Add` obliges you to implement `AddAssign` (the rule's Notes section). Do not ship one
  without the other.
- `const fn` and trait impls do not mix: `saturating_sub_bytes` can be `const`, the `std::ops` impls
  cannot. That asymmetry is expected.
- `#[must_use]` is now denied-by-candidate (PR 13.2), so the new pure methods need the attribute or
  clippy will fail the build.
- Do **not** touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine
  to regenerate it, and this PR needs neither.
- `unwrap()` / `expect()` are `deny` in production; `clippy::all` and `warnings` are already `deny`.
- Unit tests are Go-style siblings (`foo.rs` → `foo_test.rs`); extend `crates/common/src/lsn_test.rs`
  rather than adding an inline `#[cfg(test)] mod tests {}`.
