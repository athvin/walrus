# PR 13.10 — Accept `impl Into<String>` in the sink's owned-String constructors

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 13 — Rust API design · **Crates touched:** `pg-sink` ·
> **Est. size:** S · **Depends on:** PR 13.9 · **Unlocks:** PR 13.11

There are **zero** `impl Into<…>` parameters anywhere in the production tree, while 38 production
signatures and fields take an owned `String`. Four public constructors are the clean targets —
`BatchRouter::new` (`consume.rs:418`), `StreamDemux::new` (`stream_txn.rs:107`),
`Heartbeat::connect` (`heartbeat.rs:187`) and `Backfill::connect` (`snapshot.rs:113`) — all four
taking the same value, the sink instance tag, and all four storing it for the process lifetime.
Across their 17 call sites `main` pays `cfg.instance.clone()` four times (`main.rs:110`, `:118`,
`:127`, `:307`) and the integration harness pays `"test".to_string()`
(`crates/pg-sink/tests/batching.rs:83`). After this PR the four signatures read
`sink_instance: impl Into<String>`, the conversion happens once inside the constructor, and callers
pass whatever they already have.

## Why — learning objectives

- **`impl Trait` in argument position** — a generic parameter with an anonymous type; each distinct
  caller type monomorphises its own copy, which is why this belongs on wiring-time constructors and
  not on per-row functions.
- **Why `From` is implemented and `Into` is consumed** — the std blanket
  `impl<T, U: From<T>> Into<U> for T` means implementing `From` gives you `Into` for free; an API
  therefore *accepts* `Into` and never implements it.
- **Which walrus strings are configuration vs data** — the sink instance tag is read from config once
  at bootstrap and stamped into every row's `SinkMeta`; the per-row path is
  `BatchBuilder::append_row`, which must stay monomorphic and allocation-free.

**In scope**

- Change the instance-tag parameter to `impl Into<String>` on exactly four constructors:
  `BatchRouter::new`, `StreamDemux::new`, `Heartbeat::connect`, `Backfill::connect`.
- Convert **once**, at the top of each constructor body (`let sink_instance = sink_instance.into();`),
  never at each use.
- Update the four `main.rs` call sites to pass a borrow (`&cfg.instance`) instead of
  `cfg.instance.clone()`.
- Update `crates/pg-sink/tests/batching.rs:83` to pass `"test"` instead of `"test".to_string()`.
  The remaining 12 test call sites are multi-line; simplify them only where the diff is trivially
  obvious, and leave the rest compiling unchanged.

**Explicitly deferred** (do *not* build these here)

- **The other 34 owned-`String` parameters stay.** Most are enum-variant payloads
  (`LoaderError::Quarantine { table: String, .. }`, `ConfigError::Load(String)`), where `impl Into`
  is not even expressible — a struct/enum field cannot be `impl Trait`.
- **No `impl Into` on hot per-row paths.** The rule explicitly warns against it, and walrus's per-row
  path is `pg_to_arrow::BatchBuilder::append_row` — do not go near it.
- No new `From` impls. Adding `From` to walrus's own types is PR 13.4's ticket (`api-from-not-into`),
  already merged; this ticket only *consumes* the std blanket impl.
- No `impl AsRef<…>` anywhere — that is PR 13.11, and the distinction (own vs borrow) is the point.

## Hints & gotchas

- `&cfg.instance` is a `&String`, and `impl From<&String> for String` exists in std — so it satisfies
  `Into<String>` and allocates exactly the same single copy the old `.clone()` did. If you prefer the
  conversion to be obvious at the call site, write `cfg.instance.as_str()`; both compile.
- **This is not an allocation win.** The constructor still owns a `String`; what changes is that the
  caller no longer has to name the conversion. Say so in the PR body rather than claiming a perf
  improvement the benchmarks will not show.
- `impl Trait` in argument position means **no turbofish** at the call site. If any test needs to
  name the parameter type explicitly, switch that constructor to `fn new<S: Into<String>>(…)` — same
  semantics, nameable. Prefer `impl Into<String>` unless something actually breaks.
- `impl Trait` arguments also make the function generic, so it can no longer be coerced to a plain
  `fn` pointer. Nothing in the tree does that today — check with
  `grep -rn 'BatchRouter::new[^(]' crates/` before you assume.
- Two of the four are `async fn`. Adding a generic parameter to an `async fn` is fine, but it makes
  the returned future's type depend on it — do not try to store these futures in a
  `Vec<Pin<Box<dyn Future>>>` without boxing.
- The parameter is called `instance` on `Heartbeat`/`Backfill` and `sink_instance` on
  `BatchRouter`/`StreamDemux`. Keep the existing names — renaming them is `name-*` phase work
  (Phase 27), not this PR.
- `clippy::all` + `warnings` are already `deny`, so a now-redundant `use` or a leftover `.clone()`
  flagged by `redundant_clone` will fail the build.
- `unwrap`/`expect` are `deny` in production; the integration tests under `crates/pg-sink/tests/` are
  re-allowed by `clippy.toml`.
- Do not touch any `.sql` file or the `.sqlx` offline cache — no Docker locally to regenerate it.
  None of these four constructors carries a `query_file!`.
