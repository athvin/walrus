# PR 13.1 — Derive Debug on every public type and deny missing_debug_implementations

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,control,loader,pg-sink,pg-to-arrow,e2e

> **Phase:** 13 — Rust API design · **Crates touched:** `common`, `control`, `loader`, `pg-sink`,
> `pg-to-arrow`, `e2e` · **Est. size:** L ·
> **Depends on:** PR 12.7 · **Unlocks:** PR 13.2

**27** of the **124** `pub struct` / `pub enum` declarations in the production tree carry no `Debug`
at all — including `BatchBuilder`, `ReplicationStream`, `TableDb`, `BatchRouter`, `ParquetSink`,
`Heartbeat`, the e2e `Harness`, and every one of `loader::ddl`'s change enums. The tree has exactly
**one** hand-written `Debug` impl (`common::Lsn`, `lsn.rs:96`), and nothing in
`[workspace.lints.rust]` stops the 28th gap from landing. After this PR every public walrus type
formats under `{:?}` — so it can appear in a `tracing` field or an `anyhow` chain without a caller
having to re-derive it — and `missing_debug_implementations = "deny"` makes the next omission a
build failure rather than a review catch.

## Why — learning objectives

- **Derive macros vs hand-written trait impls** — `#[derive(Debug)]` requires *every* field to be
  `Debug`; where a field is a trait object over a foreign non-`Debug` trait, the fix is to change
  the bound or wrap the field, not to abandon the derive.
- **rustc lint groups in `[workspace.lints.rust]`** — `missing_debug_implementations` is an
  allow-by-default rustc lint (not clippy); promoting it to `deny` at the workspace root is what
  turns a one-time cleanup into a standing invariant across all six members.
- **Which walrus types cross a crate boundary** — `pg-to-arrow`'s builders, `pg-sink`'s routers and
  `loader`'s `TableDb` all surface in `tracing` fields and `anyhow` error chains, which is exactly
  where a missing `Debug` costs a debugging session.

**In scope**

- Add `#[derive(Debug)]` to the **26** production/e2e public types that lack it, keeping any existing
  derive list intact (e.g. `ParquetSink` becomes `#[derive(Clone, Debug)]`,
  `SchemaDiff` becomes `#[derive(Debug, Default)]`).
- Two structural unblockers, both required before the derives compile:
  - `pg_sink::batch::Clock` gains `std::fmt::Debug` as a supertrait
    (`pub trait Clock: Send + Sync + fmt::Debug`). `SystemClock` already derives it; the sibling
    `FakeClock` (`batch_test.rs:23`) needs `#[derive(Debug)]` added.
  - `pg_to_arrow::batch` gains a **private** `Builders(Vec<Box<dyn ArrayBuilder>>)` newtype with a
    hand-written `Debug` that prints arity, not contents. `BatchBuilder` then derives `Debug`
    normally. Keep the wrapper private and reach through `.0` internally — do **not** add a `Deref`
    impl (PR 13.5 owns the first `std::ops` impl in the tree and its probe counts them).
- Add `missing_debug_implementations = "deny"` to `[workspace.lints.rust]`.
- `common::Lsn` keeps its hand-written `impl fmt::Debug` — it is the one type whose `{:?}` form is a
  deliberate contract (`Lsn(<16-hex>)`), not a field dump.
- `control` needs **no code change**: it is already 100 % `Debug`-clean. It is listed as touched
  because the workspace lint now applies to it and must keep compiling.

**Explicitly deferred** (do *not* build these here)

- No audit of `Clone` / `PartialEq` / `Eq` / `Hash` / `Copy`. This ticket is `Debug` only; the rule's
  trait-bundle table is read for the `Debug` row and nothing else.
- No custom redacting `Debug` for `control_db_url` / `source_db_url` — secret hygiene in log output
  belongs to the `obs-` phase (Phase 30), and a redacting impl here would be a silent behaviour
  change nobody asked for.
- `Lsn`'s hand-written `Debug` is kept, **not** replaced by a derive.
- No `Display` impls, and no `#[derive(Debug)]` on private types that the lint does not reach.

## Hints & gotchas

- Start with the two blockers (`Clock`, `Builders`). Adding the workspace lint first just floods the
  build with 26 errors at once; land the derives, then flip the lint in the same commit.
- `missing_debug_implementations` is **reachability-based**: it fires on types exported from a
  library's public API. Types that only exist inside a `main.rs` may not trip it, which is exactly
  why the DoD keeps the perl scan as the belt-and-braces check — do not rely on the lint alone.
- If `cargo` rejects the lint table with a *lint group priority* error, write
  `warnings = { level = "deny", priority = -1 }` so the group is applied before the specific lint.
  Do not drop the group.
- A trait object cannot gain `Debug` after the fact: `Box<dyn ArrayBuilder + Debug>` is illegal
  (only auto traits may be added). Supertrait or wrapper — those are the only two moves.
- Adding a `Debug` supertrait to `Clock` is **not** the sealing work: PR 13.14 adds
  `private::Sealed`, and the two supertraits are orthogonal. Do not pre-empt it here.
- Unit tests are Go-style siblings (`foo.rs` → `foo_test.rs` via `#[cfg(test)] #[path = …] mod
  tests;`). `FakeClock` lives in `crates/pg-sink/src/batch_test.rs`; edit that file, never add an
  inline `#[cfg(test)] mod tests {}`.
- Do **not** touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine
  to regenerate it, and this PR needs neither.
- `unwrap()` / `expect()` are `deny` in production via `[workspace.lints.clippy]`; nothing here needs
  them. `clippy::all` and `warnings` are already `deny`.
- The e2e harness (`tests/e2e/src/lib.rs`) is a workspace member with `[lints] workspace = true`, so
  `Harness` must be derived too even though its tests are `#[ignore]`-gated behind `--features it`.
