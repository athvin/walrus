# PR 13.15 — Turn the snapshot-export handshake into a typestate

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test,integration · **Test packages:** pg-sink

> **Phase:** 13 — Rust API design · **Crates touched:** `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 13.14 · **Unlocks:** PR 13.16

`SnapshotConn` (`crates/pg-sink/src/snapshot.rs:42`) models its own state machine with
`exported: Option<ExportedSnapshot>` (:44) and enforces the ordering at **runtime**: `into_stream`
bails with `.context("create_slot_with_snapshot must run before streaming")` (:94). That is the
textbook shape the typestate pattern replaces — the handshake is *linear*
(`connect → CREATE_REPLICATION_SLOT … (SNAPSHOT 'export') → START_REPLICATION`), it is enforced by
Postgres itself, and getting it wrong is a bootstrap-time disaster, not a recoverable retry. There
is no `PhantomData` and no type-state parameter anywhere in the tree (0 hits). After this PR the
`Option` field and its `.context(…)` are both **deleted**: `SnapshotConn<NotExported>` is the only
state with `create_slot_with_snapshot`, `SnapshotConn<Exported>` is the only state with
`into_stream`, and calling them out of order is a compile error pinned by a `compile_fail` doctest.

## Why — learning objectives

- **Typestate with a generic parameter + `PhantomData`** — the state lives in the *type*, the
  markers are zero-sized, and `SnapshotConn<Exported>` has byte-identical layout to
  `SnapshotConn<NotExported>`: the check costs nothing at runtime because it happens at compile
  time.
- **Consuming transitions** — a transition takes `self` by value, so the old state is
  *unnameable* afterwards. You cannot accidentally keep a stale handle.
- **Deleting the `Option`, not just hiding it** — an `Option` field that is "always `Some` after
  step 2" is a state machine asking to be typed. The win is only real when the field and its
  runtime check both disappear.
- **The Postgres slot handshake** — `CREATE_REPLICATION_SLOT … (SNAPSHOT 'export')` must precede
  `START_REPLICATION` from `consistent_point`, and the exported snapshot dies the moment any other
  command runs on that connection. The type now says what the module doc has always said.

**Explicitly deferred** (do *not* build these here)

- `ReplicationStream`'s connect/stream states stay **runtime-checked**. It is the hand-rolled wire
  protocol (`replication.rs`), and re-typing it would touch the whole replication path,
  `ReplicationMessage`, the feedback loop, and every integration test. Cite it as the follow-on in
  the PR body; do not start it.
- No typestate on the `Backfill` session, on `TableBatcher`, or on the PR 13.8 decode-loop builder.
- No change to `ExportedSnapshot` (its fields, `Debug`/`Clone`, or the log line at
  `snapshot.rs:70-75`), to `Backfill`, or to any SQL string.

**Design decision to make explicitly (do not skip):** the states here are **zero-sized markers**
plus `PhantomData<S>`, and the `ExportedSnapshot` is *returned to the caller* rather than stashed
in the `Exported` state. That is the point of the exercise — the type parameter carries the
**state**, the caller carries the **value** — and it is what lets both the field and the runtime
check be deleted. It also matches the call sites, which already hold the snapshot in a local. The
alternative the rule shows (a data-carrying `struct Exported { snapshot: ExportedSnapshot }`) would
additionally prove the snapshot came from *this* connection, at the cost of the zero-sized-marker
lesson and of `PhantomData`. If you choose it anyway, say so in the PR body and justify it — do not
change it silently.

## Skeleton

```rust
// crates/pg-sink/src/snapshot.rs — replacing :42-101.

use std::marker::PhantomData;

/// State marker: the connection is open and idle; no slot has been created, so no snapshot is
/// exported. Zero-sized — it exists only in the type.
#[derive(Debug)]
pub struct NotExported;

/// State marker: `CREATE_REPLICATION_SLOT … (SNAPSHOT 'export')` has run on this connection, so it
/// is holding an exported snapshot and the only legal next command is `START_REPLICATION`.
#[derive(Debug)]
pub struct Exported;

/// Holds the slot-creating replication connection, which **must stay open + idle** so the exported
/// snapshot remains valid until every backfill session has attached to it.
///
/// The handshake order is a **typestate**: `create_slot_with_snapshot` is only callable on
/// `SnapshotConn<NotExported>` and `into_stream` only on `SnapshotConn<Exported>`, so streaming
/// before the slot exists is a compile error rather than a runtime `anyhow` context.
///
/// ```compile_fail
/// # async fn demo(dsn: &str, snap: &pg_sink::snapshot::ExportedSnapshot) -> anyhow::Result<()> {
/// let conn = pg_sink::snapshot::SnapshotConn::connect(dsn).await?;
/// // error[E0599]: no method named `into_stream` found for `SnapshotConn<NotExported>`
/// let _stream = conn.into_stream("walrus_slot", snap, "walrus_pub").await?;
/// # Ok(()) }
/// ```
#[derive(Debug)]
pub struct SnapshotConn<S = NotExported> {
    stream: ReplicationStream,
    _state: PhantomData<S>,
}

impl SnapshotConn<NotExported> {
    /// Open a replication connection and complete startup (no `START_REPLICATION` yet).
    pub async fn connect(dsn: &str) -> anyhow::Result<Self> {
        Ok(SnapshotConn {
            stream: ReplicationStream::connect(dsn)
                .await
                .context("open replication connection for snapshot export")?,
            _state: PhantomData,
        })
    }

    /// `CREATE_REPLICATION_SLOT <slot> LOGICAL pgoutput (SNAPSHOT 'export')`. **Consumes** the
    /// idle connection and hands back the exported state plus the snapshot itself — the connection
    /// now holds that snapshot, so do not run anything else on it until backfill is done.
    pub async fn create_slot_with_snapshot(
        mut self,
        slot: &str,
    ) -> anyhow::Result<(SnapshotConn<Exported>, ExportedSnapshot)> {
        let (consistent_point, snapshot_name) =
            self.stream.create_replication_slot_export(slot).await?;
        let snap = ExportedSnapshot {
            consistent_point,
            snapshot_name,
        };
        tracing::info!(
            slot,
            consistent_point = %snap.consistent_point,
            snapshot_name = %snap.snapshot_name,
            "created replication slot with exported snapshot"
        );
        let exported = todo!("SnapshotConn { stream: self.stream, _state: PhantomData }");
        Ok((exported, snap))
    }
}

impl SnapshotConn<Exported> {
    /// Hand off to streaming: `START_REPLICATION` from `consistent_point` (this ends the exported
    /// snapshot, which is safe once every backfill session has attached). Consumes the connection.
    ///
    /// No runtime check: reaching this method is proof the slot was created.
    pub async fn into_stream(
        mut self,
        slot: &str,
        snap: &ExportedSnapshot,
        publication: &str,
    ) -> anyhow::Result<ReplicationStream> {
        self.stream
            .start_streaming(slot, snap.consistent_point, publication)
            .await
            .context("hand off snapshot → streaming from consistent_point")?;
        Ok(self.stream)
    }
}
```

## Hints & gotchas

- **A consuming transition destroys the old value on failure.** `create_slot_with_snapshot(self)`
  drops the connection if `CREATE_REPLICATION_SLOT` errors. That is correct here — both call sites
  `?` straight out to a terminal bootstrap failure — but if you ever need a retry, the shape is
  `Result<SnapshotConn<Exported>, (SnapshotConn<NotExported>, anyhow::Error)>`. Do not add that
  now; note it in the PR body if a reviewer asks.
- Removing the `&mut` receiver means the `let mut snap = …` bindings at `main.rs:267` and
  `snapshot_backfill.rs:100` must lose their `mut`. `unused_mut` is a rustc warning and
  `[workspace.lints.rust]` denies `warnings` — so a leftover `mut` is a build failure, not a nit.
- `PhantomData<S>` inherits `S`'s auto traits. Keep the markers plain unit structs so
  `SnapshotConn<S>` stays `Send` — it is held across `.await` points in `main`'s bootstrap. Do
  **not** reach for `PhantomData<*const S>` or `PhantomData<fn() -> S>`; there is no variance
  problem to solve here.
- `#[derive(Debug)]` on a generic struct adds an `S: Debug` bound, so both markers must derive
  `Debug` too. (PR 13.1 already put `Debug` on every public type — do not regress that.)
- The default type parameter `<S = NotExported>` is a readability aid for signatures and doc
  links; method resolution does not need it, because `connect` lives in
  `impl SnapshotConn<NotExported>`.
- The `compile_fail` doctest must fail for the *right* reason. Verify by temporarily moving
  `into_stream` into a plain `impl<S> SnapshotConn<S>` block and watching the doctest go red, then
  put it back. A doctest with a typo passes forever.
- Doctests compile as an external crate, so the snippet needs `pg_sink::snapshot::…` paths; use a
  hidden `# async fn demo(…)` wrapper (lines prefixed `# ` are compiled but not rendered) so the
  fence stays readable.
- `snapshot_backfill.rs` is `#[ignore]`d and needs the compose stack (source PG + control PG +
  MinIO). `cargo clippy --all-targets` type-checks it, which is the gate that matters locally; run
  it with `-- --ignored` only if you have the stack up.
- `unwrap`/`expect` are denied in production by `[workspace.lints]` (`clippy.toml` re-allows them
  in tests). The whole point of this PR is to delete a runtime check — do not replace it with an
  `expect`.
- Do not touch any `.sql` file, the `.sqlx` offline cache, or `migrations/**` — there is no Docker
  on this machine to regenerate the cache, and nothing here needs it.
