# PR 13.7 — Pin the shipped configuration defaults with a golden test

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 13 — Rust API design · **Crates touched:** `common`, `loader`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 13.6 · **Unlocks:** PR 13.8

walrus's `Default` story is already idiomatic: 5 hand-written `impl Default` — all with genuinely
non-zero values, so `clippy::derivable_impls` inside the already-denied `clippy::all` stays silent —
plus 11 `#[derive(Default)]`, and the two `pub fn new()` constructors return `Arc<Self>`
(`loader/src/health.rs:32`, `pg-sink/src/health.rs:45`) so `clippy::new_without_default` never fires.
What is missing is a **gate**. All three service configs are `#[serde(deny_unknown_fields, default)]`,
which makes `Default` *the shipped default configuration* of the product — yet none of the 14
existing config unit tests (7 in `common`, 7 in `pg-sink`) asserts a single default value, and
`crates/loader/src/config.rs` has no test module at all. After this PR each of the three config
modules owns a `defaults_are_the_shipped_contract` case that pins every field, so silently changing
`max_fill` from 5s or `retention_lsn_lag` from 16 MiB turns a test red instead of shipping.

## Why — learning objectives

- **`Default` as an API contract** — with `#[serde(default)]`, every field a ConfigMap omits comes
  from `Default::default()`; the impl *is* the documented product behaviour, not a convenience.
- **Derive vs manual `Default`** — `#[derive(Default)]` uses each field type's own default; a
  non-zero default (`Duration::from_secs(5)`, `"us-east-1"`, `0.0.0.0:8080`) must be hand-written,
  which is exactly why these five impls can drift unnoticed.
- **The walrus sibling-test convention applied to a module that never had one** — `foo.rs` →
  `foo_test.rs` wired with `#[cfg(test)] #[path = "foo_test.rs"] mod tests;`, never an inline
  `mod tests {}`.

- [`api-default-impl`](../../../.claude/skills/rust-skills/rules/api-default-impl.md) — take the

  default the *required* string fields to `String::new()` so `validate()` can reject them at the

- `crates/common/src/config.rs:18-65` — `CommonConfig` / `ObjectStoreConfig` and their two manual

- `crates/loader/src/config.rs:11-64` — `LoaderConfig` and its manual `Default`. The file ends at
  the `From<ConfigError> for common::Error` impl (line 122) — there is no test module.
- `crates/pg-sink/src/config.rs:19-128` — `SinkConfig`'s 26 fields and its manual `Default`.
- `crates/common/src/telemetry.rs:37-55` — `TelemetryConfig`'s manual `Default`
  (`json: false`, `filter: DEFAULT_FILTER` = `"info"`), which all three configs embed.
- `crates/common/src/config_test.rs` and `crates/pg-sink/src/config_test.rs` — the existing style
  (a `valid()` helper plus one assertion per bound); your new case sits alongside them.

## Scope

**In scope**

- `crates/common/src/config_test.rs`: add `defaults_are_the_shipped_contract`, asserting every field
  of `CommonConfig::default()` **and** of the nested `ObjectStoreConfig::default()` /
  `TelemetryConfig::default()`.
- `crates/pg-sink/src/config_test.rs`: the same case for `SinkConfig::default()` — all 26 fields.
- `crates/loader/src/config_test.rs`: **new file**, the same case for `LoaderConfig::default()`.
- `crates/loader/src/config.rs`: append the three-line `#[cfg(test)] #[path = "config_test.rs"]
  mod tests;` wiring so the new sibling is actually compiled.
- Each new test carries a one-line comment saying *why* it exists: `#[serde(default)]` makes these
  values the shipped configuration, so a change here is a product change and must be deliberate.

**Explicitly deferred** (do *not* build these here)

- **No new `Default` impls for non-config types.** This ticket does not hunt for types that "should"
  have a `Default`; it gates the ones that already do.
- **Do not change any default value.** If a default looks wrong, the test still pins today's value —
  changing it is a separate, argued PR.
- No `..Default::default()` refactor of production code, and no change to `validate()`.
- No `PartialEq` derives on the config structs to enable whole-struct comparison — assert field by
  field so the failure message names the field that drifted.

```rust
// crates/loader/src/config_test.rs — NEW FILE.
use super::*;

/// `LoaderConfig` is `#[serde(deny_unknown_fields, default)]`, so `Default` *is* the shipped
/// loader configuration: any field a ConfigMap omits arrives from here. Changing a value below is
/// a product change — update this test deliberately, never to make it pass.
#[test]
fn defaults_are_the_shipped_contract() {
    let cfg = LoaderConfig::default();
    todo!("assert every field, one assertion per line, e.g.:");
    assert_eq!(cfg.control_db_url, ""); // required — empty so validate() rejects it at the edge
    assert_eq!(cfg.instance, "");
    assert_eq!(cfg.duckdb_dir, "");
    assert_eq!(cfg.lease_ttl, Duration::from_secs(30));
    assert_eq!(cfg.poll_interval, Duration::from_secs(5));
    assert_eq!(cfg.compaction_interval, Duration::from_secs(3600));
    assert_eq!(cfg.retention_lsn_lag, 16 << 20); // 16 MiB of WAL retained behind transformed_lsn
    assert_eq!(cfg.max_files_per_cycle, 32);
    assert_eq!(cfg.startup_deadline, Duration::from_secs(60));
    assert_eq!(cfg.health_addr, SocketAddr::from(([0, 0, 0, 0], 8080)));
    // nested
    assert_eq!(cfg.object_store.bucket, "");
    assert_eq!(cfg.object_store.endpoint, None);
    assert_eq!(cfg.object_store.region, "us-east-1");
    assert!(!cfg.telemetry.json);
    assert_eq!(cfg.telemetry.filter, "info");
}
```

## Hints & gotchas

- **PR 13.6 landed first and reshaped some `SinkConfig` fields.** The five `positive()`-checked knobs
  became `NonZeroU64` and the two backpressure ratios became a parsed band. Assert against whatever
  the types actually are after 13.6 — `cfg.max_rows.get() == 100_000`, and the band through its
  accessors — not against the pre-13.6 shape sketched in the Skeleton.
- Comparing `f64` with `assert_eq!` works today (`clippy::float_cmp` is pedantic, not in the denied
  `clippy::all`), but write `(x - 0.85).abs() < f64::EPSILON` so a future pedantic promotion in
  Phase 33 does not come back to this file.
- `use super::*` in a sibling test sees exactly what the parent module imported. `Duration`,
  `SocketAddr`, `ObjectStoreConfig` and `TelemetryConfig` are all in scope in all three config
  modules; the private `DEFAULT_FILTER` const in `crate::telemetry` is **not** — assert `"info"`.
- The config structs derive `Debug, Clone, Deserialize` but **not** `PartialEq`, so there is no
  whole-struct `assert_eq!`. That is the point: field-by-field assertions name the drift.
- `unwrap`/`expect` are `deny` in production but re-allowed under `#[cfg(test)]` by `clippy.toml` —
  these tests need neither anyway.
- Tests are Go-style siblings, never inline `mod tests {}`. The `#[path]` attribute is what makes
  `crates/loader/src/config_test.rs` compile; without it the file is dead weight and the probe
  passes while nothing runs. Check the test actually appears in `cargo test -p loader` output.
- `clippy::all` + `warnings` are already `deny`, so an unused import in the new test file fails CI.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine to
  regenerate it, and nothing here goes near SQL.
