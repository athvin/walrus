# PR 13.14 — Seal the Clock trait so the test seam cannot become an extension point

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 13 — Rust API design · **Crates touched:** `pg-sink` · **Est. size:** S ·
> **Depends on:** PR 13.13 · **Unlocks:** PR 13.15

`pub trait Clock: Send + Sync` (`crates/pg-sink/src/batch.rs:22`) is re-exported through
`pub mod batch` (`lib.rs:10`), so today any downstream crate can implement it — while its own doc
comment says the opposite: *"the single production impl is deliberate — the trait exists for that
test seam, not as dead generality (audited PR 8.5, kept by design)."* Its only two implementors are
`SystemClock` (`batch.rs:30`) and `FakeClock` in the sibling test module (`batch_test.rs:23`), both
inside `pg-sink`, so sealing costs exactly nothing and makes the doc comment enforced rather than
aspirational. There is no `mod private` / `trait Sealed` anywhere in the repo (0 hits). This PR adds
the idiom, seals both implementors, and pins it with the crate's first `compile_fail` doctest —
`cargo test -p pg-sink --doc` runs **0** doctests today.

## Why — learning objectives

- **The sealed-trait idiom** — a `pub trait Sealed` inside a *private* module is nameable only from
  inside the defining crate, so a supertrait bound on it makes the public trait usable everywhere
  and implementable nowhere else.
- **Supertrait bounds as capability tokens** — `Clock: private::Sealed + Send + Sync` composes: the
  `Send + Sync` bound (needed for `Arc<dyn Clock>`) and the seal are independent obligations.
- **`compile_fail` doctests as lint regression tests** — a doctest is compiled as an *external*
  crate, which is exactly the vantage point from which the seal must be observable.
- **Why an injectable clock is the seam that matters** — `max_fill` is a cadence trigger; without a
  fake clock the only way to test it is `sleep`, which makes the suite slow and flaky.

## Skeleton

```rust
// crates/pg-sink/src/batch.rs — replacing the trait declaration at :19-34.

/// The sealing token. `Sealed` is `pub` so no `private_bounds` warning fires, but `private` itself
/// is a private module, so the name is unreachable from outside `pg-sink` — which is exactly what
/// makes `Clock` unimplementable there.
mod private {
    pub trait Sealed {}
}

/// Injectable clock so `max_fill` is testable without sleeping. Production uses [`SystemClock`]; the
/// single production impl is deliberate — the trait exists **for that test seam**, not as dead
/// generality (audited PR 8.5, kept by design).
///
/// This trait is **sealed**: it can be called and stored (`Arc<dyn Clock>`) from anywhere, but only
/// `pg-sink` can implement it. That keeps "one production clock + one fake" a compile-time fact.
///
/// ```compile_fail
/// use std::time::Instant;
/// struct WallClock;
/// // error: the trait bound `WallClock: batch::private::Sealed` is not satisfied
/// impl pg_sink::batch::Clock for WallClock {
///     fn now(&self) -> Instant {
///         Instant::now()
///     }
/// }
/// ```
pub trait Clock: private::Sealed + Send + Sync {
    fn now(&self) -> Instant;
}

/// The wall clock.
#[derive(Debug, Default)]
pub struct SystemClock;

impl private::Sealed for SystemClock {}

impl Clock for SystemClock {
    fn now(&self) -> Instant {
        todo!("unchanged: Instant::now()")
    }
}
```

```rust
// crates/pg-sink/src/batch_test.rs — beside the existing `impl Clock for FakeClock` at :23.
// The file is included as a child module of `batch` (`#[cfg(test)] #[path = "batch_test.rs"] mod
// tests;`), so the parent's private `private` module IS in scope — `use super::*;` at :1 already
// brings it in. Spelling the path in full documents why this compiles at all.
impl super::private::Sealed for FakeClock {}

impl Clock for FakeClock {
    fn now(&self) -> Instant {
        todo!("unchanged: self.base + *self.offset.lock().unwrap()")
    }
}
```

## Hints & gotchas

- Write `pub trait Sealed {}` inside the private module, **not** `trait Sealed {}`. A nominally
  private trait in a public bound trips rustc's `private_bounds` lint, and `[workspace.lints.rust]`
  denies `warnings` — so the "obvious" spelling is a hard build failure. The `pub`-in-a-private-mod
  form is the canonical API-guidelines shape precisely because it is lint-clean.
- Keep `Sealed` **method-free**. The moment it has a method, or a `Self: Sized` bound, `Clock`
  stops being object-safe and all seven `Arc<dyn Clock>` sites break.
- Ordering in the supertrait list is cosmetic, but keep `private::Sealed` first so a reader hits the
  seal before the `Send + Sync` noise.
- `compile_fail` passes if the snippet fails to compile *for any reason* — a typo would make it
  green forever. Prove it is load-bearing by deleting the supertrait bound once and watching the
  doctest fail. You may optionally pin the error code (```` ```compile_fail,E0277 ````), but
  rustc error codes drift, so the delete-and-observe check is the real evidence.
- Doctests are compiled against the crate's **library** target as an external crate, so the snippet
  must say `pg_sink::batch::Clock` (underscore, not hyphen) and import `std::time::Instant` itself.
- `cargo test --workspace` runs doctests too; `cargo clippy` does not lint them. If the fence body
  needs `unwrap`, that is fine — but this one should not need any.
- The sibling `batch_test.rs` is a **child module** of `batch` via `#[cfg(test)] #[path = …] mod
  tests;` at `batch.rs:243-245`. That is why `FakeClock` can implement a private-module trait at
  all. Never convert it to an inline `mod tests {}`.
- Sealing restricts *implementing*, not *using*: the nine integration tests under
  `crates/pg-sink/tests/` construct `Arc::new(SystemClock)` from outside the crate and must not
  need a single edit. If any of them breaks, you have over-sealed.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — no Docker locally to
  regenerate it. Nothing here should need to.
