# PR 13.4 — Replace LoaderError::as_common with From, and give Lsn the From impls ManifestId already has

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,loader

> **Phase:** 13 — Rust API design · **Crates touched:** `common`, `loader` · **Est. size:** S ·
> **Depends on:** PR 13.3 · **Unlocks:** PR 13.5

The direct-implementation lint is already clean — **0** direct `Into` impls and **14** direct `From`
impls in production, and `clippy::from_over_into` is denied transitively through `clippy::all`.
(Three `impl Into<String>` parameter bounds are callers of the blanket impl, not trait
implementations.) What is *not* clean is the ad-hoc conversion hiding in plain sight:
`LoaderError::as_common(&self) -> common::Error` (`loader/src/error.rs:77`) is a hand-rolled `From`
wearing a different name, so `?` and `.into()` do not reach it and `exit_code` has to call it
explicitly (`error.rs:120`). Meanwhile `ManifestId` has
both `From<i64>` and `From<ManifestId> for i64` (`ids.rs:20`, `ids.rs:26`) while the flagship `Lsn`
newtype has **zero** `From` impls — only `Lsn::new` / `as_u64`. After this PR the loader's
crate-local taxonomy converts through the standard trait, `Lsn` matches its sibling newtype, and
`from_over_into` is named explicitly so the rule survives any future regrouping of `clippy::all`.

## Why — learning objectives

- **The std blanket impl** — `impl<T, U> Into<U> for T where U: From<T>` means implementing `From`
  gives you `Into` for free, and `?` works through `From` only. A method named `as_common` gives you
  neither.
- **`From` on a reference type** — `LoaderError::as_common` takes `&self` and must keep doing so
  (the caller still owns the error), so the impl is `From<&LoaderError> for common::Error`, not
  `From<LoaderError>`. Lifetimes make this a genuinely different impl from the owned one.
- **walrus error mapping** — crate-local taxonomy → `common::Error` → `ExitCode` at the top of
  `main`. Making the middle arrow a `From` is what lets the classification travel through `?`.

**In scope**

- Replace `LoaderError::as_common(&self) -> common::Error` with
  `impl From<&LoaderError> for common::Error`, moving the match body across **unchanged** — every arm
  and every rendered message stays byte-identical.
- `LoaderError::exit_code` becomes `common::Error::from(self).exit_code()`.
- Rewire both conversion paths: `LoaderError::exit_code` calls `common::Error::from(self)`, and
  `crates/loader/src/main.rs` maps its retained `&e` through `common::Error::from(&e)` before taking
  the exit code.
- Give `Lsn` the pair `ManifestId` already has: `impl From<u64> for Lsn` and
  `impl From<Lsn> for u64`. `Lsn::new` / `Lsn::as_u64` stay — they are `const`, which `From` cannot
  be, and `Lsn::ZERO` depends on `new`.
- Add `from_over_into = "deny"` to `[workspace.lints.clippy]` so the rule is named explicitly rather
  than inherited.
- Extend `crates/common/src/lsn_test.rs` with a round-trip case for the new pair.

**Explicitly deferred** (do *not* build these here)

- **No `TryFrom` work.** Fallible conversions are `conv-tryfrom-fallible`'s subject in Phase 20

- `ConfigError` and `PreflightError` already have `From` impls into `common::Error` and are

```rust
// crates/loader/src/error.rs

/// The classified terminal error `main` surfaces as an exit code.
///
/// Takes `&LoaderError` (not the owned error) because the caller keeps its error for logging; the
/// std blanket impl then gives `(&e).into()` for free, and `?` can cross the crate boundary.
impl From<&LoaderError> for common::Error {
    fn from(e: &LoaderError) -> Self {
        match e {
            LoaderError::Config(e) => common::Error::Config(e.0.clone()),
            LoaderError::Control(e) => common::Error::ControlDb(e.to_string()),
            LoaderError::Duck(m) => common::Error::Internal(format!("duckdb: {m}")),
            // …every remaining arm moved across verbatim — messages must stay byte-identical…
            LoaderError::Internal(m) => common::Error::Internal(m.clone()),
        }
    }
}

impl LoaderError {
    #[must_use = "the exit code must reach `main` — dropping it loses the failure class"]
    pub fn exit_code(&self) -> common::ExitCode {
        common::Error::from(self).exit_code()
    }
}
```

```rust
// crates/common/src/lsn.rs — mirror ManifestId's pair (ids.rs:20, ids.rs:26).

impl From<u64> for Lsn {
    /// Wrap a raw `u64` WAL position. [`Lsn::new`] stays for `const` contexts (`Lsn::ZERO`).
    fn from(raw: u64) -> Self {
        Lsn(raw)
    }
}

impl From<Lsn> for u64 {
    /// The raw `u64` WAL position. [`Lsn::as_u64`] stays for `const` contexts.
    fn from(lsn: Lsn) -> Self {
        lsn.0
    }
}
```

```rust
// crates/common/src/lsn_test.rs
#[test]
fn u64_round_trips_through_from() {
    let lsn = Lsn::from(0x0000_0000_019A_2B3C_u64);
    assert_eq!(lsn, Lsn::new(0x0000_0000_019A_2B3C));
    assert_eq!(u64::from(lsn), 0x0000_0000_019A_2B3C);
```

## Hints & gotchas

- **`from_over_into` is a member of `clippy::all`.** Listing both at priority 0 makes cargo fail with
  *"lint group `clippy::all` has the same priority (0) as `clippy::from_over_into`"*. Fix it by
  giving the group `priority = -1`, not by dropping either entry. (Contrast PR 13.2's
  `must_use_candidate`, which is `pedantic` and needs no such tweak.)
- `From<&LoaderError>` and a hypothetical `From<LoaderError>` are **different impls**. Only add the
  reference one — the owned one would be dead, and adding both invites `?` to silently pick whichever
  the inference finds.
- `From` cannot be `const`. That is exactly why `Lsn::new` / `Lsn::as_u64` stay: `Lsn::ZERO` is a
  `const` item built from `Lsn::new(0)` and would stop compiling without it.
- Do not delete `Lsn::new` "because `From` covers it" — `pub const fn new` is called from `const`
  contexts and from `Lsn::from_str`.
- Once `From<&LoaderError>` exists, `?` will start coercing in places it did not before. Resist
  rewriting `map_err` chains in this PR — that is `err-`-phase work and would make the byte-identical
  message check unverifiable.
- Do **not** touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine
  to regenerate it, and this PR needs neither.
- `unwrap()` / `expect()` are `deny` in production; `clippy::all` and `warnings` are already `deny`.
- Unit tests are Go-style siblings (`foo.rs` → `foo_test.rs`); extend `crates/common/src/lsn_test.rs`
  rather than adding an inline `#[cfg(test)] mod tests {}`.
