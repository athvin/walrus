# PR 13.6 — Parse the sink's backpressure and threshold knobs into types that cannot be invalid

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 13 — Rust API design · **Crates touched:** `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 13.5 · **Unlocks:** PR 13.7

`SinkConfig` exposes **25** `pub` fields plus a *public* `validate(&self)` (`config.rs:217`) that is
separate from construction — so `SinkConfig::default()` (`config.rs:98`), an entirely invalid config
with empty URLs, type-checks everywhere. The invariants then have to be re-stated downstream:
`Backpressure::new(activate_ratio: f64, resume_ratio: f64)` (`memory.rs:109`) accepts any two f64s,
and the hysteresis band `0 < resume < activate < 1` lives only in the 12-line runtime branch at
`config.rs:271-283`. Five more fields go through a `positive()` runtime helper (`config.rs:304`, 5
call sites) that `NonZeroU64` would make unrepresentable. `NonZero` already appears on **6**
production lines for unrelated `NonZeroU32` type-descriptor fields and conversions, while the five
target `SinkConfig` fields have **0** `NonZeroU64` declarations. After this PR the five thresholds cannot hold zero, the band cannot be built inverted,
and `Backpressure` cannot be constructed from two unrelated floats.

## Why — learning objectives

- **Make illegal states unrepresentable** — a `positive()` check you must remember to call is a
  weaker guarantee than a type that cannot hold zero. The check moves from a function you can forget
  into a constructor you cannot bypass.
- **Smart constructors returning `Result`** — `HysteresisBand::new(activate, resume)` is the single
  gate for the band invariant; every consumer downstream then works with a value that is correct by
  construction.
- **`NonZeroU64`'s niche optimisation** — `Option<NonZeroU64>` is the same size as `u64`, which is
  the standard-library proof that the zero-is-invalid encoding is free.
- **Why backpressure needs hysteresis** — pausing WAL intake at the same ratio you resume it at makes
  the pause-poll backstop flap around the ceiling; `0 < resume < activate < 1` is what stops that.
  And an invalid walrus config must be **terminal at the edge** — `ExitCode::Config`, never a panic
  three modules later.

**In scope**

- Two parsed newtypes in `crates/pg-sink/src/memory.rs`:
  - `Ratio(f64)` — an open-unit-interval ratio (`0.0 < r < 1.0`), constructed only through
    `Ratio::new` / `TryFrom<f64>`, with an `as_f64()` accessor.
  - `HysteresisBand { activate: Ratio, resume: Ratio }` — constructed only through
    `HysteresisBand::new(activate, resume)`, which enforces `resume < activate`. It carries an
    associated `DEFAULT` const holding the shipped `(0.85, 0.75)` pair.
- `Backpressure::new(band: HysteresisBand) -> Self` — the two-`f64` signature is gone.
- `SinkConfig`: the five `positive()` fields (`max_rows`, `max_bytes`, `max_inflight_bytes`,
  `max_concurrent_reloads`, `reload_chunk_rows`) become `std::num::NonZeroU64`; the two ratio fields
  become `Ratio`. Wire names, env names and the TOML/YAML shape are **unchanged** (a bare integer, a
  bare float).
- Delete the `positive()` helper and its five call sites; delete the 12-line band branch and replace
  it with a single `self.hysteresis_band()?;` inside `validate`.
- `SinkConfig::backpressure(&self)` becomes `-> Result<crate::memory::Backpressure, ConfigError>`,
  built from the parsed band.
- `crates/pg-sink/src/main.rs` (and any other consumer) calls `.get()` at the exact point the
  primitive is needed — `BatchTriggers`, `InflightMeter::new`, the reload semaphore, `chunk_rows`.
- Tests: the `max_rows = 0` and `max_concurrent_reloads = 0` sub-cases become *uncompilable* and are
  replaced by a serde-boundary case (a zero in the config source is rejected at parse time);
  `backpressure_ratios_must_form_a_hysteresis_band` moves to a constructor assertion on
  `HysteresisBand::new` in `crates/pg-sink/src/memory_test.rs`.

**Explicitly deferred** (do *not* build these here)

- The **26 `pub` fields stay public** and `SinkConfig::validate` **stays public**. Collapsing the
  serde struct into a private `RawSinkConfig` + accessor wrapper is a much larger change and is out
  of scope.
- `LoaderConfig` / `CommonConfig` keep their string-emptiness checks exactly as they are.
- `reload_max_restarts: i32` stays as it is — `0` is a legal, meaningful value (fail on the first
  mid-export DDL), so it is not a `NonZero` candidate.
- No `Duration` newtypes: the `duration_bound` helper and `MAX_DURATION` ceiling are untouched.
- No newtype for the string fields (`instance`, `slot_name`, …) — the emptiness check stays in
  `validate`.

**Conflict — read before you start**

The parsed newtypes need `Deserialize`. Implement it as **`TryFrom<f64>` on the newtype**, with a
hand-written `Deserialize for Ratio` that deserializes an `f64` and delegates to that `TryFrom`.
The struct-level `#[serde(try_from = "…")]` attribute — i.e. hanging a `try_from` on `SinkConfig`
itself — is owned by `serde-try-from-validate` in Phase 22 (`srd.try_from` is 0 today) and must
**not** be pre-empted here. `NonZeroU64` needs nothing: serde already rejects `0` for it.

// crates/pg-sink/src/config.rs
use crate::memory::{HysteresisBand, Ratio};
use std::num::NonZeroU64;

/// `NonZeroU64::new` returns `Option`, and `unwrap` is denied in production — so the shipped
/// defaults go through a `const fn` that matches instead. A literal that *is* zero would be a
/// compile-time-visible bug, not a silent `MIN`.
const fn nz(v: u64) -> NonZeroU64 {
    match NonZeroU64::new(v) {
        Some(n) => n,
        None => NonZeroU64::MIN,
    }
}

#[derive(Debug, Clone, Deserialize)]
#[serde(deny_unknown_fields, default)]
pub struct SinkConfig {
    // …unchanged fields…
    /// Row-count flush threshold.
    pub max_rows: NonZeroU64,
    /// Byte-size flush threshold.
    pub max_bytes: NonZeroU64,
    /// Back-pressure ceiling on aggregate in-flight buffered bytes (§1.3).
    pub max_inflight_bytes: NonZeroU64,
    /// Pause-poll backstop **activate** ratio of `max_inflight_bytes` (high band).

}

            max_inflight_bytes: nz(512 * 1024 * 1024),
            backpressure_activate_ratio: HysteresisBand::DEFAULT.activate(),
            backpressure_resume_ratio: HysteresisBand::DEFAULT.resume(),
            max_concurrent_reloads: nz(2),
            reload_chunk_rows: nz(10_000),
            // …every other field unchanged…
            ..todo!("keep the remaining fields exactly as they are today")
        }

}

impl SinkConfig {
    /// The parsed hysteresis band — the ONE place the cross-field invariant is decided.
    fn hysteresis_band(&self) -> Result<HysteresisBand, ConfigError> {
        HysteresisBand::new(
            self.backpressure_activate_ratio,
            self.backpressure_resume_ratio,

            field: "backpressure_activate_ratio",
            detail: e.to_string(),

    /// The validated backpressure hysteresis gate (PR 2.32).
    pub fn backpressure(&self) -> Result<crate::memory::Backpressure, ConfigError> {
        Ok(crate::memory::Backpressure::new(self.hysteresis_band()?))
    }

    pub fn validate(&self) -> Result<(), ConfigError> {

## Hints & gotchas

- `NonZeroU64::new` returns `Option`, and `unwrap`/`expect` are `deny` in production — that is why
  the `const fn nz` helper matches instead. Do not "simplify" it into
  `NonZeroU64::new(x).unwrap()`; clippy will fail the build.
- `Ratio::new` must reject `NaN`. `!(0.0 < raw && raw < 1.0)` handles it (every comparison with `NaN`
  is false), but write the test so a future refactor to `raw > 0.0 || …` cannot regress it silently.
- `f64` has no `Eq`/`Ord`, so `Ratio` derives `PartialEq`/`PartialOrd` only. Do not reach for
  `#[derive(Eq)]` — it will not compile, and a total order on ratios is not needed.
- Serde already rejects `0` for `NonZeroU64` with a clear message, so the "zero is invalid" contract
  is enforced at the *parse* boundary, before `validate` ever runs. That is the whole point of the
  rule; make sure the replacement test asserts it through `SinkConfig::load`-shaped parsing, not
  through `validate`.
- `max_inflight_bytes >= max_bytes` is a **cross-field** invariant that `NonZeroU64` does not cover.
  Keep that check in `validate`. `config_test.rs:57` does `cfg.max_inflight_bytes = cfg.max_bytes - 1`
  — that becomes `nz(cfg.max_bytes.get() - 1)` (or the test's own local helper).
- Call `.get()` at the point of use, not at the top of `main` — the whole value of the newtype is
  that it stays typed as far as possible. `max_concurrent_reloads` feeds
  `Semaphore::new(usize)`; `usize::try_from(cfg.max_concurrent_reloads.get())` is the honest
  conversion on a 32-bit target.
- `SinkConfig::backpressure` has no production call site today (only the definition). Changing it to
  return `Result` therefore breaks nothing — but do wire it into `validate` so the invariant is still
  checked at bootstrap.
- Do **not** touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine
  to regenerate it, and this PR needs neither.
- `clippy::all` and `warnings` are already `deny`, and `must_use_candidate` was promoted to `deny` in
  PR 13.2 — the new pure accessors (`as_f64`, `activate`, `resume`) need `#[must_use]`.
- Unit tests are Go-style siblings (`foo.rs` → `foo_test.rs`); `memory_test.rs` and `config_test.rs`
  both already exist and are wired via `#[cfg(test)] #[path = …] mod tests;`. Extend them — do not
  add an inline `#[cfg(test)] mod tests {}`.
