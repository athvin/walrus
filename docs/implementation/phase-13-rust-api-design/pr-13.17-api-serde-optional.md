# PR 13.17 — Record why serde stays a hard dependency and gate the feature seam that already exists

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** evidence
> **Gates:** fmt,clippy,test · **Test packages:** —

> **Phase:** 13 — Rust API design · **Crates touched:** *none — CI workflow + a design note* ·
> **Est. size:** S · **Depends on:** PR 13.16 · **Unlocks:** PR 14.1

`api-serde-optional` asks library crates to put serde behind a feature flag so downstream users do
not pay for it. walrus has no downstream users: all **6** workspace members are internal, pinned at
`version = "0.1.0"`; the only `[package] publish` key is e2e's explicit `publish = false`, and no
member carries registry metadata or has a consumer outside this repo. serde is also load-bearing
rather than incidental — `Lsn`'s ordering contract *is* its
hand-written `Serialize`/`Deserialize` (`crates/common/src/lsn.rs:100-116`), `SinkMeta` is the
per-row provenance JSON stamped into every Parquet file, and all three service configs are serde
structs. So the verdict is **reject, with the reasoning written down**. What this PR *does* buy is
real: `common` already implements the technique correctly for a different dependency
(`sqlx = ["dep:sqlx"]`, `crates/common/Cargo.toml`), and CI has **never once compiled that seam in
its off state** — `cargo test --workspace` unifies features so `common` always gets `sqlx`, and the
only other build is `--all-features`. This PR adds the one CI step that closes that hole.

## Why — learning objectives

- **Cargo features and `dep:` syntax** — `sqlx = ["dep:sqlx"]` names an *optional dependency*
  without leaking an implicit feature of the same name; that is what `common/Cargo.toml` already
  does.
- **Feature unification hides broken combinations** — within one cargo invocation, a package is
  compiled once with the *union* of every selected feature. `--workspace` therefore can never
  observe `common` without `sqlx`, and `--all-features` cannot either. Only building the package
  in isolation can.
- **Archetype D: rejecting a rule is an engineering act, not a shrug** — the deliverable is a note
  with the evidence and the trigger that would reverse the decision, plus a guard that makes the
  ticket buy something real anyway.
- **Which walrus types must serialize** — `Lsn` (the padded-hex form whose text sort equals its
  numeric sort), `SinkMeta` (per-row provenance), the three configs — and which need not.

  matches its second bullet ("domain heavily uses serde"), and fails its premise entirely (nothing
  is published). Take the `#[cfg_attr(feature = "serde", derive(…))]` mechanics as background for
  the note; do not apply them.

  ("Off by default so non-DB consumers of `common` don't pull sqlx; `control`/`loader` enable it"),
  and the `serde`/`serde_json` entries that are **not** optional. Note there is no `default`
  feature at all.
- `crates/common/src/lsn.rs:100-160` — the `Serialize`/`Deserialize` impls that encode the ordering
  contract, then `#[cfg(feature = "sqlx")] mod sqlx_support` at :120 — the seam this PR gates.
- `crates/common/src/ids.rs:35-66` — the second `#[cfg(feature = "sqlx")]` block (`ManifestId`'s
  transparent-int8 encoding). These two blocks are the entire off-state surface.
- `crates/common/src/config.rs:18-32` — `CommonConfig`, `#[serde(deny_unknown_fields, default)]`:
  serde is the config loader, not a convenience.
- `.github/workflows/ci.yml:53-104` — the `gates` job (`fmt · clippy · test`): the fmt step at
  :93, clippy at :96, `cargo test --workspace` at :99, `sccache stats` at :102. The new step goes
  in this job because it is the cheap, always-run one.

  "Why it does not apply here"

## Hints & gotchas

- **`--no-default-features` is not what does the work here.** `crates/common/Cargo.toml` declares
  no `default` feature, so the flag is a no-op *today*; the isolation of `-p common` is what turns
  `sqlx` off, because nothing in that sub-graph enables it. Say this plainly in the CI comment —
  a reviewer who thinks the flag is load-bearing will delete the wrong half later.
- Feature unification is per-invocation, not per-crate: `cargo test --workspace` compiles `common`
  **once**, with `sqlx` on, because `control` and `loader` ask for it. Resolver v2 (`Cargo.toml:2`)
  changes unification for build/dev/target deps only — it does not help here.
- Use `cargo check`, not `cargo build` or `cargo test`. The seam is a *compilation* concern, and
  `check` keeps the `gates` job cheap; `common` has no benches and only two lightweight integration
  test targets, so `--all-targets` means "lib + unit and integration test targets" and costs almost
  nothing.
- If the check fails, read the error before "fixing" it: a missing `#[cfg(feature = "sqlx")]` on a
  `use` line or a test helper is the likely cause, and the fix belongs in `crates/common/src/**`.
  Never fix it by making the feature non-optional or by adding it to a `default` list.
- sccache is enabled in the `gates` job (`RUSTC_WRAPPER`), so the extra step mostly hits cache —
  but it is a *different* feature set, hence a genuine first compile the first time it runs. Expect
  a one-off minute, not the ~20-minute cold DuckDB build (that is the loader's, not `common`'s).
- Put the step inside `gates`, not in a new job. A new job would need its own toolchain install,
  cache, and sccache wiring for a three-second check.
- The note is documentation, so this PR touches no Rust — but it still runs the full gate. Keep
  `cargo fmt --check` and clippy green out of habit; a stray edit under `crates/` would fail them.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache. (Different `.sqlx`: the
  offline **query** cache at the repo root, unrelated to `common`'s `sqlx` *feature* — but the
  no-Docker constraint stands either way.)
- Any new dependency — including a CI tool like `cargo hack` — must clear `cargo deny`
  (advisories, the 8-license allow-list, bans). That is exactly why the powerset matrix is deferred.
