# PR 21.3 — Assert walrus wire and exit-code invariants at compile time with const blocks

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 21 — Rust const & compile-time · **Crates touched:** `common`, `pg-sink` ·
> **Est. size:** S · **Depends on:** PR 21.2 · **Unlocks:** PR 21.4

On exact predecessor `30bd428`, walrus has **zero inline `const { }` blocks in production**. Four
constant relationships are still useful build-time gates, but two of the original audit's
implementation premises have already been retired. PR 18.7 removed the raw
`PHASE_BOOTSTRAPPING` / `PHASE_READY` sentinels in favour of `Phase { Bootstrapping = 0, Ready = 1
}` plus `AtomicPhase`; the invariant now is that those typed discriminants stay aligned with
`AtomicU8::default()`, `store`, and `TryFrom<u8>`. PR 17.3 replaced `code as u8` with checked
`u8::try_from(raw).unwrap_or(INTERNAL_EXIT_BYTE)` and added
`every_exit_code_variant_fits_a_u8`; there is no silent truncation to repair. The remaining
exit-code contract is the documented **`0..125`** range, and it should fail at compile time while
the checked fallback and runtime tests remain intact.

The other two authored findings still match exactly: `XID_PREFIXED = b"RYIUDTM"` is the sole
seven-tag pgoutput set whose members consume a streamed per-message xid, and
`MAX_STARTUP_DEADLINE` is the sole ceiling used by `CommonConfig::validate`. After this PR, one
inline const block at each of the four reliance sites turns these representation, wire, and bound
claims into compile errors with actionable messages.

## Why — learning objectives

- **Inline `const { }` blocks as anonymous compile-time expressions** — stable since Rust 1.79
  (walrus pins 1.95), usable at the exact site where an invariant matters, and distinct from a
  named `const ITEM`.
- **Compile-time assertions complement rather than replace runtime checks.** Constant relationships
  fail the build; dynamic config input still returns `Error::Config`, invalid atomic bytes still
  take the typed `TryFrom` error path, and process exit conversion stays checked.
- **Representation invariants evolve with the code.** The health check is no longer "two raw
  sentinels differ"; it is "the typed enum's explicit discriminants agree with the byte boundary."
- **An exhaustive enum match is a better census than a fixed-length array.** An
  `ALL_EXIT_CODES: [ExitCode; 10]` array would not become ill-typed merely because an eleventh enum
  variant was appended. The conversion instead matches every variant explicitly, while one const
  block asserts the range of every listed discriminant.
- **The pgoutput proto-v2 xid-prefix rule is a wire fact.** Exactly seven tags — Relation, Type,
  Insert, Update, Delete, Truncate, Message — carry a per-message xid inside a streamed block; a
  count drift changes how the same bytes are decoded.

```rust
// crates/common/src/error.rs — inside From<ExitCode> for std::process::ExitCode.

fn from(code: ExitCode) -> Self {
    // The public range is stricter than merely fitting u8: 125..=255 are shell-reserved too.
    // Keep all ten assertions in declaration order. If the repr cast needs the already-established
    // numeric-lint carve-out, scope it to this block and retain the reason.
    const {
        assert!(
            (ExitCode::Success as i32) >= 0 && (ExitCode::Success as i32) < 125,
            "ExitCode::Success must stay in 0..125 or the process status contract breaks"
        );
        assert!(
            (ExitCode::Config as i32) >= 0 && (ExitCode::Config as i32) < 125,
            "ExitCode::Config must stay in 0..125 or the process status contract breaks"
        );
        assert!(
            (ExitCode::ControlDb as i32) >= 0 && (ExitCode::ControlDb as i32) < 125,
            "ExitCode::ControlDb must stay in 0..125 or the process status contract breaks"
        );
        assert!(
            (ExitCode::ObjectStore as i32) >= 0 && (ExitCode::ObjectStore as i32) < 125,
            "ExitCode::ObjectStore must stay in 0..125 or the process status contract breaks"
        );
        assert!(
            (ExitCode::Preflight as i32) >= 0 && (ExitCode::Preflight as i32) < 125,
            "ExitCode::Preflight must stay in 0..125 or the process status contract breaks"
        );
        assert!(
            (ExitCode::KeylessTable as i32) >= 0 && (ExitCode::KeylessTable as i32) < 125,
            "ExitCode::KeylessTable must stay in 0..125 or the process status contract breaks"
        );
        assert!(
            (ExitCode::LeaseContended as i32) >= 0 && (ExitCode::LeaseContended as i32) < 125,
            "ExitCode::LeaseContended must stay in 0..125 or the process status contract breaks"
        );
        assert!(
            (ExitCode::SourceDb as i32) >= 0 && (ExitCode::SourceDb as i32) < 125,
            "ExitCode::SourceDb must stay in 0..125 or the process status contract breaks"
        );
        assert!(
            (ExitCode::Quarantine as i32) >= 0 && (ExitCode::Quarantine as i32) < 125,
            "ExitCode::Quarantine must stay in 0..125 or the process status contract breaks"
        );
        assert!(
            (ExitCode::Internal as i32) >= 0 && (ExitCode::Internal as i32) < 125,
            "ExitCode::Internal must stay in 0..125 or the process status contract breaks"
        );
    }

    // This is the compiler-enforced census: adding an ExitCode variant makes the match
    // non-exhaustive. Return each variant's repr, never a duplicated integer literal.
    #[allow(
        clippy::cast_possible_truncation,
        reason = "read the enum's explicit repr(i32) discriminants before checked narrowing"
    )]
    let raw = match code {
        ExitCode::Success => ExitCode::Success as i32,
        ExitCode::Config => ExitCode::Config as i32,
        ExitCode::ControlDb => ExitCode::ControlDb as i32,
        ExitCode::ObjectStore => ExitCode::ObjectStore as i32,
        ExitCode::Preflight => ExitCode::Preflight as i32,
        ExitCode::KeylessTable => ExitCode::KeylessTable as i32,
        ExitCode::LeaseContended => ExitCode::LeaseContended as i32,
        ExitCode::SourceDb => ExitCode::SourceDb as i32,
        ExitCode::Quarantine => ExitCode::Quarantine as i32,
        ExitCode::Internal => ExitCode::Internal as i32,
    };

    // PR 17.3's checked conversion stays; the const block makes its fallback unreachable for the
    // public range today without weakening the defensive boundary.
    std::process::ExitCode::from(u8::try_from(raw).unwrap_or(INTERNAL_EXIT_BYTE))
}
```

// crates/pg-sink/src/health.rs — at the top of Phase::try_from.

fn try_from(byte: u8) -> Result<Self, Self::Error> {
    const {
        assert!(
            Phase::Bootstrapping as u8 == 0,
            "Phase::Bootstrapping must stay byte 0 because AtomicPhase defaults to zero"
        );
        assert!(
            Phase::Ready as u8 == 1,
            "Phase::Ready must stay byte 1 so AtomicPhase store and decode agree"
        );
    }
    match byte {
        0 => Ok(Self::Bootstrapping),
        1 => Ok(Self::Ready),
        other => Err(InvalidPhase(other)),
    }
}

## Hints & gotchas

- **Do not resurrect obsolete implementation shapes.** `Phase`/`AtomicPhase` and checked exit-code
  narrowing are deliberate earlier-roadmap improvements. This PR adds compile-time assertions to
  them; it does not unwind them.
- **A fixed-size enum array is not exhaustive.** `[ExitCode; 10]` checks its own initializer length,
  not the number of enum variants. The explicit conversion match is what makes variant growth a
  compile error; the adjacent per-variant const assertions enforce the range.
- **Check the lower and upper exit bounds.** `< 125` alone accepts negative `repr(i32)` values,
  which the checked narrowing would map to `INTERNAL_EXIT_BYTE`. The public contract is `0..125`.
- **Panic messages in const evaluation cannot format runtime arguments.** Keep each message a
  string literal. The negative fixture should require E0080 and that exact message stem so a syntax
  error cannot masquerade as proof.
- `clippy::assertions_on_constants` is already denied. Keep conditions as comparisons/method calls;
  never suppress the lint. Any numeric-cast allowance stays statement-scoped with a reason.
- `Duration::is_zero` and `Duration::from_secs` are const-evaluable. Assert the ceiling constant,
  never `self.startup_deadline`.
- `XID_PREFIXED` is `&[u8]`; `.len()` is const-evaluable. Keep the block beside `parse_one`'s xid
  decision, not as a new module-level named assertion.
- The compile-fail helper must be std-only: a process-unique temp directory, the active `rustc`,
  `--edition=2024 --crate-type=lib`, captured stderr, and cleanup of only the directory it created.
  Do not add `trybuild`, edit the checkout, or run Cargo recursively from a test.
- Test code may use `unwrap`/`expect`; production may not. Existing sibling unit tests remain
  untouched, while the new integration target lives under `crates/common/tests/`.
- No SQL text is involved. If `.sql` or `.sqlx/` changes, the implementation has left scope.
