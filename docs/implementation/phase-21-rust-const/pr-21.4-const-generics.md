# PR 21.4 — Collapse the fixed-width big-endian readers with const generics

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 21 — Rust const & compile-time · **Crates touched:** `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 21.3 · **Unlocks:** PR 22.1

On exact predecessor `f2362b4`, walrus has zero Rust declarations containing `<const `, but the
reader baseline is no longer the pre-Phase-16 implementation this task originally described.
`crates/pg-sink/src/pgoutput/reader.rs` is **188 lines**, not 124. PR 16.2 (`520651b`) already
removed all three `try_into()` calls from `Reader::{int16,int32,int64}` and changed them to
`first_chunk::<2/4/8>()`, while making `need` return the checked `&'a [u8]`. PR 16.5 (`bf1b9f3`)
already collapsed every `DecodeError::UnexpectedEof` construction into one private free
`#[cold] #[inline(never)] eof` helper. The broad name appears 11 times because public docs describe
the error, but there is exactly **one struct-literal construction**. Undoing either earlier change
would be a regression, not const-generic cleanup.

The residual duplication is still real and bounded. The three numeric cursor readers repeat the
same `rest().first_chunk::<N>()` / `eof` / advance sequence. A private
`Reader::fixed<const N: usize>(&mut self) -> Result<&'a [u8; N], DecodeError>` can instead reuse the
exact head already returned by `need(N)?`, turn it into an array reference with one
`first_chunk::<N>()`, advance only after success, and leave the public readers as one-line
`from_be_bytes` adapters. Separately, `replication.rs` still has three `try_into()`-based free
readers (`read_lsn`, `read_i64`, `read_i32`) with three duplicated `anyhow!` messages. They have
**seven production call sites** — three `read_lsn`, two `read_i64`, and two `read_i32` — and can
share a second private width-generic helper without changing a caller. Those are the two genuine
const-generic declarations this PR adds.

## Why — learning objectives

- **Const generics parameterise a function over a value.** `N` is part of the array type, so one
  helper expresses the 2-, 4-, and 8-byte cases and rustc monomorphises only the widths used.
- **A const-generic use is not a const-generic declaration.** The existing
  `first_chunk::<2/4/8>()` turbofishes already pass const arguments to a standard-library method;
  this PR introduces walrus's first own `<const N: usize>` declarations and centralises the width.
- **Carry an existing bounds proof forward.** `need(N)?` returns exactly the checked borrowed head.
  `fixed` converts that head to `&[u8; N]`, so the public reader copies only the small array required
  by `from_be_bytes`; there is no allocation, new indexing, or new error taxonomy.
- **Refactors must respect prior optimization ownership.** The free cold `eof` helper keeps error
  construction out of hot reader bodies, and `need` keeps the slice proof introduced by PR 16.2.
- **The pgoutput / CopyBoth wire contract stays observable.** All fields remain big-endian; a short
  cursor read remains `DecodeError::UnexpectedEof { needed, offset, remaining }`, while a wrong-size
  replication window remains contextual `anyhow` with the reader name, expected width, and actual
  width.

fn fixed_width_borrows_and_advances() {

Then implement the two distinct private helper shapes:

```rust
// crates/pg-sink/src/pgoutput/reader.rs — inside impl Reader.

/// Borrow `N` bytes at the cursor, advancing only after a successful width proof.
fn fixed<const N: usize>(&mut self) -> Result<&'a [u8; N], DecodeError> {
    let head = self.need(N)?;
    // `need(N)` returned exactly N bytes, so None is unreachable. Keep it modelled rather than
    // using unwrap/expect, and keep error construction in PR 16.5's cold free helper.
    let Some(chunk) = head.first_chunk::<N>() else {
        return Err(eof(N, self.pos, self.remaining()));
    };
    self.pos += N;
    Ok(chunk)
}

pub fn int16(&mut self) -> Result<u16, DecodeError> {
    Ok(u16::from_be_bytes(*self.fixed()?))
}
// int32 / int64 retain their public signatures and use the same inferred-N shape.
```

```rust
// crates/pg-sink/src/replication.rs — next to read_lsn/read_i64/read_i32.

fn fixed<const N: usize>(b: &[u8], what: &str) -> anyhow::Result<[u8; N]> {
    b.try_into()
        .map_err(|_| anyhow!("{what}: expected {N} bytes, got {}", b.len()))
}

fn read_lsn(b: &[u8]) -> anyhow::Result<Lsn> {
    Ok(Lsn::new(u64::from_be_bytes(fixed(b, "read_lsn")?)))
}
// read_i64 / read_i32 retain their signatures and error labels in the same shape.
```

## Hints & gotchas

- `need(N)?` already returns **exactly** `N` bytes with lifetime `'a`; call
  `head.first_chunk::<N>()` on that slice. Do not regress to `self.buf[self.pos..self.pos + N]` or
  a reader-side `try_into()`.
- Return `&'a [u8; N]` from the cursor helper, not an owned array. The public `from_be_bytes`
  adapter dereferences the small borrowed array (`*self.fixed()?`), preserving PR 16.2's carried
  bounds proof and the public method's value result.
- Keep the free `eof(needed, pos, remaining)` call in the logically unreachable `None` arm. A
  `&self` EOF method would undo PR 16.5's code-layout choice and can introduce a conflicting borrow
  inside the helper; `unwrap`/`expect` are denied in production anyway.
- The reader has **11 textual references** to `DecodeError::UnexpectedEof` because its public docs
  describe failure behavior. Count the struct literal with the trailing `{` when checking actual
  constructors; do not edit docs merely to change the broad count.
- `N` is inferred for the public numeric readers from `u16/u32/i64::from_be_bytes`; the explicit
  turbofish belongs inside the helper's `first_chunk::<N>()` and in the direct unit tests.
- The two helpers intentionally share a name only within different modules. Reader returns a
  borrowed array and typed `DecodeError`; replication returns an owned array and contextual
  `anyhow::Error`. Do not force them into one abstraction.
- `clippy::uninlined_format_args` is denied through `clippy::all`: keep `{what}` and `{N}` inline in
  the replication message while `b.len()` remains the positional expression shown in the skeleton.
- Unit tests use Go-style sibling files wired by `#[path = "reader_test.rs"]` and
  `#[path = "replication_test.rs"]`. They are tracked and intentionally modified here; the golden
  integration file remains untouched.
- The seven production replication calls are three LSN windows, two server-clock windows, and two
  Int32 windows (startup auth and DataRow length). Do not repeat the stale count of six.
- Nothing in this task requires Docker, SQLx regeneration, or an external service.
