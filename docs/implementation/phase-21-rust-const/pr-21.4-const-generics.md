# PR 21.4 — Collapse the fixed-width big-endian readers with const generics

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 21 — Rust const & compile-time · **Crates touched:** `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 21.3 · **Unlocks:** PR 22.1

Zero const generics exist in walrus (`grep -rn '<const ' crates tests` → `0`), and the replication
wire path pays for it: the **same fixed-width big-endian read is hand-written six times**, differing
only in the width. `Reader::int16`/`int32`/`int64` (`pgoutput/reader.rs:53`/`:67`/`:82`) are three
copies of *bounds-check, slice, `try_into`, `map_err` into `UnexpectedEof`, advance* — three
`try_into()` calls and six `DecodeError::UnexpectedEof` constructions in a 124-line file — and
`read_lsn`/`read_i64`/`read_i32` (`replication.rs:500`/`:506`/`:512`) are three more, with
copy-pasted `anyhow!` strings. One `fn fixed<const N: usize>(&mut self) -> Result<[u8; N],
DecodeError>` turns all six into one-liners, because the blanket
`impl<T: Copy, const N: usize> TryFrom<&[T]> for [T; N]` already does the width-generic work — no
extra trait bound needed. The public `int16`/`int32`/`int64`/`lsn` names and signatures do not
move, and the 30 golden pgoutput vectors prove the decode is byte-for-byte unchanged.

## Why — learning objectives

- **Const generics `<const N: usize>` and monomorphisation over a *value*** — the compiler emits one
  specialised copy per distinct `N` (here: 2, 4, 8), so a width-generic helper costs exactly what
  the hand-written triplicate cost. `N` is usually **inferred** from the return type
  (`u16::from_be_bytes(self.fixed()?)` fixes `N = 2`), so call sites rarely need a turbofish.
- **The blanket `TryFrom<&[T]> for [T; N]` impl** — this is the std impl that makes a fixed-width
  slice read generic at all, and the reason no `where` clause is required.
- **The pgoutput / CopyBoth wire format** — `Int16`/`Int32`/`Int64` fields are big-endian, and every
  short read must be a *modelled* `DecodeError::UnexpectedEof`, never a panic. Deduplicating the
  reads must not weaken that: the bounds check happens before the conversion, and the impossible
  branch is still returned as data, not `unwrap`ped.

## Scope

**In scope**

- `crates/pg-sink/src/pgoutput/reader.rs`:
  - Add a **private** `const fn eof(&self, needed: usize) -> DecodeError` — the single place an
    `UnexpectedEof` is constructed for a fixed-width read (`offset: self.pos`,
    `remaining: self.remaining()`).
  - Add a **private** `fn fixed<const N: usize>(&mut self) -> Result<[u8; N], DecodeError>`:
    `need(N)?`, slice, `try_into`, advance `self.pos` by `N`.
  - Rewrite `int16`, `int32`, `int64` as one-liners over `fixed` + `from_be_bytes`. **Signatures,
    visibility, doc comments and error semantics unchanged.**
  - Rewrite `need` to build its error via `self.eof(n)`.
- `crates/pg-sink/src/replication.rs`:
  - Add a private `fn fixed<const N: usize>(b: &[u8], what: &str) -> anyhow::Result<[u8; N]>` with
    the one `anyhow!` message, parameterised by `N` and the caller's name.
  - Rewrite `read_lsn` / `read_i64` / `read_i32` as one-liners over it. Names and signatures
    unchanged (the sibling test calls `read_lsn`).
- Keep every existing test green with **no test edits**: `crates/pg-sink/tests/pgoutput_vectors.rs`
  (33 tests, 30 vectors) and `crates/pg-sink/src/replication_test.rs` are the proof that decoding is
  byte-identical.

**Explicitly deferred** (do *not* build these here)

- **No const-generic buffer *type*** and no change to `crates/pg-sink/src/batch.rs` sizing. Buffer
  shape is Phase 11 (`mem-*`) territory and gated on the committed criterion baseline.
- **Do not unify the two error taxonomies.** `reader.rs` keeps `DecodeError::UnexpectedEof`
  (library → `thiserror`); `replication.rs` keeps `anyhow!` (binary path → `anyhow` with context).
  That split is the walrus errors convention, not an accident.
- No `NonZero*`, no `PhantomData` (both still 0 in the tree; Phase 18 `type-*`).
- `take(&mut self, n: usize)` (`:113`) **stays runtime-sized** — its length comes off the wire, not
  from the type. Same for `string` (`:96`) and `byte1` (`:45`).
- No `.sql` / `.sqlx` edits, no new dependency, no change to `parse_one` or any message parser.

**Conflicts to resolve explicitly** — two:

1. **`Reader` is public API.** `pg_sink::pgoutput::Reader` is imported by
   `crates/pg-sink/tests/pgoutput_vectors.rs:9-11`, so the const-generic helper must sit *behind*
   the existing names. Do not change, rename or remove a public signature; `fixed` and `eof` are
   private (`fn`, no `pub`). If you find yourself editing the test's `use` line, you have broken the
   contract this PR is supposed to preserve.
2. **This lands under PR 21.1's `missing_const_for_fn = "deny"`.** `fixed` calls `try_into` — a
   trait method — so clippy will *not* ask for `const fn` there, and neither helper may be forced
   const. But `new`, `remaining`, `need` and the new `eof` are pure and **must** be `const fn`, or
   the lint fails the build. Write `eof` as `const fn` from the start.

## Skeleton

```rust
// crates/pg-sink/src/pgoutput/reader.rs — replacing :32-93. Public surface is untouched.

impl<'a> Reader<'a> {
    /// The one place a fixed-width read reports running off the end. `const fn` because PR 21.1's
    /// `missing_const_for_fn = "deny"` will demand it once `remaining` is const.
    const fn eof(&self, needed: usize) -> DecodeError {
        DecodeError::UnexpectedEof {
            needed,
            offset: self.pos,
            remaining: self.remaining(),
        }
    }

    /// Error unless at least `n` bytes remain.
    const fn need(&self, n: usize) -> Result<(), DecodeError> {
        if self.remaining() < n {
            Err(self.eof(n))
        } else {
            Ok(())
        }
    }

    /// `N` bytes at the cursor, bounds-checked, advancing by `N`.
    ///
    /// `N` is a const generic, so the compiler emits one specialised copy per width actually used
    /// (2, 4, 8) — identical codegen to the three hand-written versions this replaces. The blanket
    /// `impl<T: Copy, const N: usize> TryFrom<&[T]> for [T; N]` supplies the conversion; no extra
    /// bound is needed. NOT `const fn`: `try_into` is a trait call.
    fn fixed<const N: usize>(&mut self) -> Result<[u8; N], DecodeError> {
        self.need(N)?;
        let end = self.pos + N;
        // `need(N)` already proved the window is exactly N bytes, so this cannot fail — but
        // `unwrap`/`expect` are denied workspace-wide, so the impossible branch is modelled too.
        let arr: [u8; N] = match self.buf[self.pos..end].try_into() {
            Ok(a) => a,
            Err(_) => return Err(self.eof(N)),
        };
        self.pos = end;
        Ok(arr)
    }

    /// Big-endian `Int16`.
    pub fn int16(&mut self) -> Result<u16, DecodeError> {
        // N = 2 is INFERRED from `from_be_bytes`'s [u8; 2] parameter — no turbofish needed.
        Ok(u16::from_be_bytes(self.fixed()?))
    }

    /// Big-endian `Int32` (OID / xid).
    pub fn int32(&mut self) -> Result<u32, DecodeError> {
        todo!("Ok(u32::from_be_bytes(self.fixed()?))")
    }

    /// Big-endian `Int64` (the raw 8-byte field; LSN reads it as unsigned via [`Reader::lsn`],
    /// commit timestamps keep it as signed µs).
    pub fn int64(&mut self) -> Result<i64, DecodeError> {
        todo!("Ok(i64::from_be_bytes(self.fixed()?))")
    }

    // byte1 (:45), string (:96), take (:113), peek (:27) and lsn (:121) are UNCHANGED. `string`
    // keeps its own `UnexpectedEof` construction — a missing NUL terminator is not a fixed-width
    // read, and folding it into `eof` would blur two different failure stories.
}
```

/// `N` big-endian bytes out of an exact wire window. One message for all three callers.
fn fixed<const N: usize>(b: &[u8], what: &str) -> anyhow::Result<[u8; N]> {
    b.try_into()
        .map_err(|_| anyhow!("{what}: expected {N} bytes, got {}", b.len()))
}

fn read_lsn(b: &[u8]) -> anyhow::Result<Lsn> {
    Ok(Lsn::new(u64::from_be_bytes(fixed(b, "read_lsn")?)))

## Hints & gotchas

- **Let `N` be inferred.** `u16::from_be_bytes(self.fixed()?)` pins `N = 2` from the parameter type;
  a turbofish (`self.fixed::<2>()`) is legal but noisy. Only reach for it if inference genuinely
  cannot see the width.
- **Borrowck on the `match` scrutinee.** `self.buf` is a `&'a [u8]` *field that is `Copy`*, so
  `self.buf[a..b]` borrows from `'a`, not from `self` — `self.eof(N)` in the `Err` arm is fine. If
  your local rustc still complains, hoist the conversion first
  (`let conv: Result<[u8; N], _> = self.buf[self.pos..end].try_into();`) and match on `conv`.
- **Do not collapse `string()` into `eof`.** Its `needed: 1` means "a NUL terminator", not "one more
  byte of a fixed-width field", and the DoD's count of **3** depends on it keeping its own
  construction.
- **`byte1` stays as it is.** It reads a single byte with direct indexing and no `from_be_bytes`;
  routing it through `fixed::<1>()` would add an array round-trip for zero readability gain.
- **PR 21.1's lint is live.** `eof` must be `const fn` or `missing_const_for_fn` (now `deny`) fails
  the build. Conversely, do not try to force `fixed` const — `try_into` is a trait call and rustc
  will reject it; that is expected, not a problem to `#[allow]` around.
- **The golden vectors are the regression test, and they must not be edited.** 30 ported vectors,
  33 tests, pure CPU — run `cargo test -p pg-sink --test pgoutput_vectors` after every step. If a
  vector's expected line changes, you have altered the decode.
- `clippy::uninlined_format_args` is in `clippy::all` and therefore `deny`: write
  `anyhow!("{what}: expected {N} bytes, got {}", b.len())` — `{what}` and `{N}` inline (a const
  generic parameter is a valid value path), `b.len()` stays positional.
- Unit tests are **Go-style sibling files** (`replication.rs` → `replication_test.rs`, wired by a
  `#[cfg(test)] #[path = ...] mod tests;`). `reader.rs` has **no** sibling test — its coverage lives
  in the integration file `crates/pg-sink/tests/pgoutput_vectors.rs`. Do not invent
  `reader_test.rs` here.
- `unwrap`/`expect` are `deny` in production. The "cannot fail after `need(N)`" branch must return
  a modelled error, not `.unwrap()` — that is the whole reason `reader.rs` exists in this shape.
- The `.sqlx` offline cache **cannot be regenerated** (no Docker locally); nothing here touches a
  query, so `cargo sqlx prepare --check` must stay green untouched.
- Most `pg-sink` integration tests are `#[ignore]`d because they need compose; `pgoutput_vectors` is
  not one of them, so a plain `cargo test -p pg-sink` gives you real signal locally.
