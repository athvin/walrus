# PR 21.2 — Gate the const-vs-static storage-class policy and hoist the Postgres epoch constant

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 21 — Rust const & compile-time · **Crates touched:** `common`, `pg-sink` ·
> **Est. size:** S · **Depends on:** PR 21.1 · **Unlocks:** PR 21.3

walrus already picks the right storage class everywhere, which is exactly why this is an *enforce*
PR and not an *apply* one: an exact declaration-shape probe finds **159 `const` items in production
source paths** — 137 named items plus 22 anonymous compile-time assertions/proofs; 54 of the named
items are the `pg_catalog` OIDs in `crates/common/src/oids.rs` — and **exactly one production
`static`** —
`crates/common/src/metrics.rs:132`, a `OnceLock<PrometheusHandle>`, which is the rule's own
recommended shape for a single-writer global — **28 test-scope
`static … tokio::sync::Mutex::const_new(())`** serialisers that genuinely need `&'static`, and
**zero** `static mut`, zero `lazy_static!`, zero `once_cell`. Nothing stops that from regressing:
`clippy::non_std_lazy_statics` is pedantic/allow-by-default and absent from `Cargo.toml`, and no
rustc or clippy lint catches a `static mut` *declaration* at all. The one real placement smell is
duplication, not storage class: the Postgres-epoch magic number `946_684_800` is spelled out in
**five** places across three crates. After this merges there is one `PG_EPOCH_UNIX_SECS` in
`common`, a guard test that fails the build if a mutable or plain addressed global ever appears,
and a lint that rejects hand-rolled `lazy_static!`/`once_cell` globals before review has to.

## Why — learning objectives

- **`const` vs `static` vs `OnceLock`/`LazyLock`/atomics** — a `const` is *inlined at every use
  site* and has no address; a `static` is one address with a `&'static` lifetime. Small values,
  masks and magic numbers are `const`; large tables and anything needing `&'static T` are `static`;
  mutable global state is an atomic or a `OnceLock`/`LazyLock`, never `static mut` (referencing one
  is a hard error in edition 2024).
- **The Postgres epoch is a wire-protocol constant and must have exactly one home** — pgoutput
  commit timestamps and CopyBoth clocks are measured from 2000-01-01T00:00:00Z, i.e.
  946 684 800 seconds after the Unix epoch. Five independent spellings of one wire constant is a
  latent off-by-one-timezone bug, not a style nit.
- **Enforce beats apply when the tree is already correct** — the deliverable is a *gate* (a lint
  plus a guard test), not a refactor, and the gate has to be honest about what it actually covers.

// crates/common/src/sink_meta.rs — immediately after the `use` block at :16.

/// Postgres' own epoch, 2000-01-01T00:00:00Z, as seconds after the Unix epoch: 946_684_800.
///
/// pgoutput commit timestamps (proto §4) and the CopyBoth standby-status clock (§1.9) are both
/// measured from this instant, **not** the Unix epoch. Unix time has no leap seconds, so the offset
/// is exact and fixed. One definition, workspace-wide — never re-type the digits.
pub const PG_EPOCH_UNIX_SECS: i64 = 946_684_800;

/// The same instant in microseconds. Derived from [`PG_EPOCH_UNIX_SECS`] so the two can never drift.

            .ok_or_else(|| todo!("unchanged: the existing overflow Error::Internal"))?;
        todo!("rest of the body unchanged")
    }
}

## Hints & gotchas

- **The guard test must not match itself.** It lives under `crates/`, so a literal `"static mut"`
  in its own source would make both the test and the repo-wide grep probe report a hit. Build the
  needle with `concat!("static", " mut ")` and phrase the doc comment as "a mutable global" — never
  write the two words adjacently anywhere in that file.
- **No `walkdir`.** Every new dependency has to clear `cargo deny` (advisories + the 8-license
  allow-list + bans), and a 30-line `std::fs::read_dir` recursion is not worth that. Skip `target/`
  and `.git/` explicitly or the test will walk gigabytes.
- **Integration-test policy scanners carry a reasoned allow header.** `clippy.toml` scopes
  unwrap/expect allowances to tests, while the existing synchronous scanners also allow
  `clippy::disallowed_methods` with a reason (see
  `crates/common/tests/error_message_style.rs:1-8`). Match that established common-test convention.
- **Check the lint name against the pinned toolchain first.** If `non_std_lazy_statics` is unknown
  to clippy, `unknown_lints` fires and `warnings = "deny"` turns it into a hard error — you would
  break the whole workspace. Confirm with `cargo clippy -- -W help 2>&1 | grep lazy` before
  committing, and note the observed clippy version in the PR body.
- **Do not "fix" `metrics.rs:132`.** The `expect` inside `get_or_init` at `:151` has a deliberate
  reasoned `#[expect(clippy::expect_used)]` at `:144-149`. Adding `LazyLock` or
  threading a `Result` out of an infallible-by-signature `init()` is out of scope and would ripple.
- `crates/common/tests` already has **five** integration-test files. `storage_class_guard.rs` is the
  sixth target, so reuse their sorted recursive scan and in-memory synthetic-input patterns. Keep
  it fast (pure file I/O), deterministic, and unignored because it runs on every CI push.
- This PR touches no query, so the `.sqlx` offline cache must remain byte-identical and
  `cargo sqlx prepare --check` must stay green without regeneration.
- `sink_meta.rs` is a **cross-service JSON wire contract** (`sink_meta.rs:9-12`). Replacing a local
  constant with an identical imported one changes no bytes — but run
  `cargo test -p common sink_meta` and confirm `round_trips_a_known_commit_ts`
  (`sink_meta_test.rs:219`) and the amortized-meta cases still pass with unchanged expected strings.
- Unit tests are **Go-style sibling files**: `sink_meta_test.rs` is wired by the
  `#[cfg(test)] #[path = "sink_meta_test.rs"] mod tests;` at `sink_meta.rs:300-302`. Edit the
  sibling; never add an inline `mod tests {}`.
- `unwrap`/`expect` are `deny` in production and `clippy::all` + `warnings` are already `deny`
  workspace-wide, so the guard's parsing must be `Option`/`match`-driven, not `.unwrap()`-driven,
  in any helper you might later move out of the test target.
