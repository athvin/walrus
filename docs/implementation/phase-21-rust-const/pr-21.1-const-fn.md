# PR 21.1 — Make every eligible function a const fn and deny missing_const_for_fn

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 21 — Rust const & compile-time · **Crates touched:** `common`, `control`,
> `pg-to-arrow`, `pg-sink`, `loader`, `e2e` · **Est. size:** L · **Depends on:** PR 20.3 ·
> **Unlocks:** PR 21.2

At predecessor `6c7ebd9`, walrus contains **12** `const fn`, not two. Five are the `Lsn`
constructors/bit conversions/arithmetic in `crates/common/src/lsn.rs`; one is loader's
`nonzero_i64`; five are pg-sink's `nz`, `Ratio::as_f64`, `HysteresisBand::{activate,resume}` and
`Backpressure::new`; and one is pg-to-arrow's `Emit::width`. Against that exact tree, the pinned
1.95.0 Clippy pass

```text
cargo clippy --all-targets --all-features --message-format=short -- --cap-lints warn -W clippy::missing_const_for_fn
```

reports **73 unique residual sites**: common 4 (3 library + 1 integration test), control 5, loader
10 (9 library + 1 integration test), pg-to-arrow 9 (8 library + 1 bench), pg-sink 43 (41 library +
1 bench + 1 integration test), and e2e 2. Duplicate lib-test diagnostics are not counted twice.
This PR adds `const` to those compiler-proven sites, reruns Clippy to a fixed point, and denies the
nursery lint at the workspace root so future eligible functions cannot silently remain runtime-only.

The old error-classifier anchors are no longer eligible: PR 19.2 moved them into the shared
`FailureClass` trait. Stable Rust 1.95 does not support const trait methods or const trait impls, so
`Error::{is_terminal,exit_code}`, `ControlError::is_terminal`, `LoaderError::{is_terminal,exit_code}`
and the shared `is_transient` default must remain ordinary trait methods. That is a language boundary,
not a lint escape hatch.

## Why — learning objectives

- **`const fn` follows the compiler's const-evaluable subset, not a prose purity guess.** Primitive
  matches/arithmetic, field projection, references and mutation can be const; allocation, most trait
  calls, destructors and async cannot. The pinned Clippy diagnostic is the executable inventory.
- **Adding `const` widens an API without changing runtime behavior.** The 73 bodies remain byte-for-byte
  unchanged; only their signatures gain the keyword.
- **Const and traits are separate on stable Rust.** A pure `FailureClass` implementation is still not
  eligible while const trait methods remain unstable. Do not duplicate the classifiers as inherent
  methods just to increase the count.
- **Lint-as-policy.** `missing_const_for_fn` is a nursery lint outside `clippy::all`; the exact
  `rust-toolchain.toml` pin makes promoting it deterministic, and a genuine false positive receives
  a reasoned site-local allow rather than a workspace escape hatch.

## Hints & gotchas

- **Treat the 73 diagnostics as the first pass, then run to a fixed point.** Duplicate `lib test`
  warnings are the same source locations and do not increase the count.
- **Do not restore the old error skeleton.** PR 19.2 deliberately centralized classification in
  `FailureClass`; stable const traits are unavailable, and parallel inherent methods would create
  two sources of truth.
- **Checked Phase-17 conversions explain several former omissions.** A function can be pure at
  runtime yet non-const because `TryFrom::try_from` is a trait call. Do not replace checked
  conversions with `as` casts to satisfy this task.
- **The builder inventory is deliberately discontinuous.** Lines 463 and 475 onward are const;
  `token` at 469 is not. Moving a `CancellationToken` into an already-populated option may run its
  destructor, which stable const evaluation rejects.
- **`&mut self` and mutable locals are not automatic blockers.** The pinned MSRV permits mutable
  references in const functions; follow the diagnostic, not an obsolete pre-1.83 rule of thumb.
- Benches, integration tests, and e2e lib targets are covered by `--all-targets`; the seven
  non-library locations are part of the policy, not test-only exceptions.
- A site-local `#[allow(..., reason = "…")]` is an emergency hatch for an actual pinned-Clippy
  false positive. Never add this lint to the bench file-level allows or to `clippy.toml`.
