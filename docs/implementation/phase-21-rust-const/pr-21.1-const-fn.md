# PR 21.1 — Make every eligible function a const fn and deny missing_const_for_fn

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 21 — Rust const & compile-time · **Crates touched:** `common`, `control`,
> `pg-to-arrow`, `pg-sink`, `loader`, `e2e` · **Est. size:** L · **Depends on:** PR 20.3 ·
> **Unlocks:** PR 21.2

The whole workspace contains **exactly two `const fn`** — `Lsn::new` and `Lsn::as_u64`, at
`crates/common/src/lsn.rs:26` and `:31` — while clippy's nursery `missing_const_for_fn` finds **63
sites** that could be const today (pg-sink 34, pg-to-arrow 10, loader 7, control 6, common 4, plus 2
in `tests/e2e`). The lint is allow-by-default and absent from the workspace lint table
(`grep -c missing_const_for_fn Cargo.toml` → `0`), so nothing marks a pure classifier const:
`Error::is_terminal` (`error.rs:69`), `Error::exit_code` (`:90`),
`PgColumn::numeric_precision_scale` (`pg_shape.rs:60`), `ControlError::is_terminal` (`db.rs:46`) and
`Reader::new`/`Reader::remaining` (`reader.rs:17`/`:22`) are all pure, allocation-free, and
trivially const-evaluable. After this merges the 63 become 0, the lint is `deny` at the workspace
root beside `unwrap_used`/`expect_used`, and every future pure getter is const *by policy* rather
than by luck.

## Why — learning objectives

- **`const fn` and the const-evaluable subset of stable Rust** — arithmetic, bitwise ops, `as`
  casts, `match` on a reference, indexing, `while` loops and calls to other `const fn`s are all
  allowed; heap allocation, trait-method calls (`Default::default()`, `Into::into`, operators on
  non-primitives) and `async` are not. Marking a function `const` is a backwards-compatible
  addition — but it is a *promise*, so only make it where the body is genuinely pure.
- **The walrus error taxonomy is exactly the shape that should be compile-time evaluable** —
  `is_terminal`/`is_transient`/`exit_code` are pure classifiers over an exhaustive, no-`_`-arm
  match (`error.rs:69-102`). Nothing about them needs a running program.
- **Lint-as-policy, and how a nursery lint differs from a group member** — `missing_const_for_fn`
  is *not* in `clippy::all`, so it needs no `priority` juggling; it slots in beside the two
  restriction lints the workspace already denies.

## Hints & gotchas

- **Work outside-in and re-run clippy after every crate.** `const fn` only propagates in one
  direction: a caller can become const *after* its callee does. `common` first, then `control` /
  `pg-to-arrow`, then `pg-sink` / `loader` / `e2e`. Running clippy once and calling it done is the
  single most likely way to fail CI here.
- **`async fn` can never be `const fn`.** Most of `control` and `loader` is async, which is why
  their counts (6 and 7) are so much lower than pg-sink's 34 — do not go hunting for more.
- **Trait calls are the usual blocker**, and they hide: `Default::default()`, `.into()`,
  `.to_string()`, `PartialEq`/`PartialOrd` on non-primitives, `Iterator` adapters, and arithmetic
  operators on newtypes. Primitive `==`, `<`, `+`, `>>`, `&` and `as` are fine; `Option::is_some`,
  `Option::is_none`, `<[T]>::len`, `<[T]>::is_empty` and `Duration::as_secs` are `const fn` in std.
- `&mut self` receivers and mutable locals **are** allowed in `const fn` on this MSRV (1.95); the
  `const_mut_refs` restriction was lifted in 1.83. If clippy flags a `&mut self` method, take it.
- **`#[allow(..., reason = "…")]` is stable** since 1.81 — use it. A bare `#[allow]` with no reason
  will (rightly) get review pushback, and `#[allow(...)]` in production is already down to 7 sites
  tree-wide; do not casually grow that number.
- **Benches and tests are linted.** `cargo clippy --all-targets` covers `benches/decode.rs`,
  `benches/batch.rs`, `crates/loader/tests/ddl_additive.rs` and
  `crates/pg-sink/tests/pgoutput_vectors.rs`. Fix them in place. Note the bench crates already
  carry file-level `#![allow(clippy::unwrap_used, clippy::expect_used)]` headers — do **not** add
  `missing_const_for_fn` to those lists.
- Unit tests here are **Go-style sibling files** (`src/foo.rs` → `src/foo_test.rs`). This PR adds
  no tests, but if you touch one, edit the sibling — never introduce an inline `mod tests {}`.
- `unwrap`/`expect` are `deny` in production and `clippy::all` + `warnings` are already `deny`
  workspace-wide, so a `const fn` conversion that tempts you into `.unwrap()` in a const context is
  a signal to leave that function alone.
- The `.sqlx` offline cache **cannot be regenerated** — there is no Docker on this machine. Nothing
  in this PR should change a query, so if `cargo sqlx prepare --check` starts failing you have
  edited something you should not have.
- `missing_const_for_fn` is nursery, which means clippy's own authors expect occasional wrong
  suggestions. When you hit one, read the error the compiler gives after you add `const` — it names
  the exact non-const operation — and put that sentence in the `reason`.
