# PR 14.16 — Broadcast the current epoch over a watch channel instead of polling it per table

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** loader

> **Phase:** 14 — Rust async/await · **Crates touched:** `loader` ·
> **Est. size:** M · **Depends on:** PR 14.15 · **Unlocks:** PR 14.17

`watch` channels appear **0 times** in the repo, yet the loader has the textbook case for one. Every
apply loop re-reads the **same global scalar** from the control DB on **every** cycle just to notice
a generation bump: `control::read_current_epoch(&ctx.pool)` at `crates/loader/src/apply_loop.rs:40`
(plus the loop-start baseline at `:26`). With N owned tables that is N `SELECT`s per `poll_interval`
for one `i64` whose *history* is irrelevant — only its current value matters, which is exactly what
`watch` is for. After this merges a single epoch poller task owns a `watch::Sender<i64>`, each
`TableCtx` carries a `watch::Receiver<i64>`, and the §1.8 total-restart guard reads `*rx.borrow()`
— an in-memory load. Control-DB epoch queries per poll cycle drop from **N to 1**, and the guard
itself becomes a pure function a unit test can drive.

## Why — learning objectives

- **`watch` = latest-value-only fan-out** — `changed()` / `borrow()` semantics, why a slow observer
  *skips* rather than lags, and why `Ref` is a lock guard you must not hold.
- **walrus total-restart guard (§1.8)** — a loader running a retired epoch must exit loudly so the
  orchestrator restarts it into a rebuild; it must never rebuild a running generation in place.

**In scope**

- `crates/loader/src/epoch.rs` gains two items: `spawn_epoch_watch(pool, baseline, period, token)`
  returning `(watch::Receiver<i64>, JoinHandle<()>)`, and a small pure `advance(&tx, observed)`
  helper that publishes only a genuine forward move via `send_if_modified`.
- The poller's cadence is the existing `cfg.poll_interval` — the same effective freshness the
  per-table reads had, at 1 query per cycle instead of N. It exits on the shutdown token.
- `crates/loader/src/epoch.rs` also gains `fixed_epoch_watch(epoch)` — a receiver pinned to one
  value, for the eight test `TableCtx` literals and any single-generation harness.
- `TableCtx` gains `pub epoch_rx: tokio::sync::watch::Receiver<i64>`; `main.rs` clones the poller's
  receiver into each one.
- `apply_loop` loses both `read_current_epoch` calls. The baseline becomes
  `(*ctx.epoch_rx.borrow()).max(ctx.epoch)` — preserving the "observed MAX" semantics exactly — and
  the per-cycle guard becomes a call to a new pure `epoch_guard(observed, baseline, started_at)`.
- New sibling `crates/loader/src/apply_loop_test.rs` (the module has none today) driving a real
  `watch::channel`, plus `#[cfg(test)] #[path] mod tests;` wiring in `apply_loop.rs`.
- Update the eight integration-test `TableCtx` construction sites in the exact files listed below
  to pass `epoch::fixed_epoch_watch(epoch)`; do not widen this into a glob-driven test rewrite.

**Explicitly deferred** (do *not* build these here)

- **Do not** replace `LoaderState`'s health atomics with a watch. The `/healthz` handlers are
  pull-based and have no awaiter — a watch would add a notification nobody consumes.
- **Do not** make the poll cadence configurable. Reuse `cfg.poll_interval`; a second dial is
  unjustified until someone measures a reason for one.
- Do not change `LoaderError::EpochBumped`'s fields or `exit_code()`, and do not change what
  bootstrap does with the epoch (`crates/loader/src/bootstrap.rs:50`) — this is the *running* half
  only.
- Do not use the receiver's `changed()` anywhere in the apply loop: the guard is a poll-time check,
  not an event.

**Conflict — the `Ref` guard.** `watch::Receiver::borrow()` returns a `Ref`, which is a lock guard.
Holding one across an `.await` is exactly what PR 14.3's newly-denied `significant_drop_tightening`
and `await_holding_lock` catch, and clippy *will* fail CI on it. Copy the `i64` out in the same
statement (`let observed = *ctx.epoch_rx.borrow();`) and never bind the `Ref` itself. The receiver
being `Send` while the apply loops are `!Send` `LocalSet` tasks is fine — that direction never
constrains anything.

## Skeleton

```rust
// crates/loader/src/epoch.rs — new items below `rebuild_for_new_epoch`.

use std::time::Duration;
use tokio::sync::watch;
use tokio_util::sync::CancellationToken;

/// Poll the control plane's current epoch ONCE per `period` and publish it to every apply loop.
/// Replaces N per-table `read_current_epoch` queries per cycle with one. Runs on the runtime pool
/// (not the `LocalSet`) next to `lease::spawn_renewer`, and returns on the shutdown token.
///
/// A read error is logged and retried next tick — the epoch is a *guard*, not a correctness input:
/// failing to observe a bump for one cycle delays the loud exit, it never corrupts anything.
pub fn spawn_epoch_watch(
    pool: sqlx::PgPool,
    baseline: i64,
    period: Duration,
    token: CancellationToken,
) -> (watch::Receiver<i64>, tokio::task::JoinHandle<()>) {
    let (tx, rx) = watch::channel(baseline);
    let handle = tokio::spawn(async move {
        let mut tick = tokio::time::interval(period);
        tick.set_missed_tick_behavior(tokio::time::MissedTickBehavior::Skip);
        tick.tick().await; // swallow the immediate first tick — `baseline` was just read
        loop {
            tokio::select! {
                biased; // PR 14.1: SIGTERM beats the poll tick.
                _ = token.cancelled() => return,
                _ = tick.tick() => {}
            }
            match control::read_current_epoch(&pool).await {
                Ok(observed) => {
                    advance(&tx, observed.map(|s| s.epoch));
                }
                Err(e) => tracing::warn!(error = %e, "epoch watch read failed; retrying next tick"),
            }
            todo!("if tx.is_closed() { return; } — every apply loop is gone, stop querying");
        }
    });
    (rx, handle)
}

/// Publish `observed` iff it is a genuine FORWARD move; returns whether receivers were notified.
/// Epochs are monotonic by construction (`control::bump_epoch` is `MAX(epoch) + 1`), so a lower or
/// absent reading is a stale/failed read and must never walk the value backwards — doing so would
/// silently disarm the total-restart guard.
pub(crate) fn advance(tx: &watch::Sender<i64>, observed: Option<i64>) -> bool {
    todo!("None => false; Some(e) => tx.send_if_modified(|cur| e > *cur && { *cur = e; true })")
}

/// A receiver pinned to `epoch` forever. The sender is dropped immediately, which is safe because
/// `borrow()` keeps returning the last value after every sender is gone — only `changed()` would
/// error, and the apply loop never calls it. For harnesses and single-generation tests.
pub fn fixed_epoch_watch(epoch: i64) -> watch::Receiver<i64> {
    watch::channel(epoch).1
}
```

pub async fn apply_loop(ctx: TableCtx, shutdown: CancellationToken) -> Result<(), LoaderError> {
    // …tick / last_compaction unchanged…

    // The generation baseline: the highest epoch present as of loop start. In production this
    // equals `ctx.epoch` (bootstrap read the MAX), so the guard fires on ANY later bump; taking the
    // observed MAX (not `ctx.epoch`) means a shared test control-plane carrying unrelated higher
    // epochs doesn't trip it — only a genuine bump *while this loader runs* does. Now an in-memory
    // load off the watch instead of a per-worker SELECT.
    let baseline_epoch = (*ctx.epoch_rx.borrow()).max(ctx.epoch);

    loop {
        tokio::select! {
            biased;
            _ = shutdown.cancelled() => return drain(&ctx),
            _ = tick.tick() => {}
        }
        // Total-restart guard (§1.8): exit loudly so `main` cancels the token and the process
        // restarts into a full rebuild under the new epoch — never rebuild in place mid-run.
        // Deref-copy in ONE statement: a `watch::Ref` is a lock guard and must not survive to the
        // `.await`s below (PR 14.3 denies `significant_drop_tightening` / `await_holding_lock`).
        let observed = *ctx.epoch_rx.borrow();
        epoch_guard(observed, baseline_epoch, ctx.epoch)?;

        run_phase_a(&ctx).await?;
        // …rest of the cycle unchanged…
    }
}

## Hints & gotchas

- **`borrow()` returns a lock guard.** `let e = ctx.epoch_rx.borrow();` followed by any `.await` is
  a clippy failure under PR 14.3's denies and a genuine latency hazard. Always
  `let observed = *rx.borrow();` — one statement, `i64` copied out, guard gone.
- Do **not** use `borrow_and_update()` here. It marks the value seen, which only matters if you also
  call `changed()`; mixing the two invites a "guard fires one cycle late" bug that is invisible in
  tests.
- `send_if_modified` takes `&mut T` and returns whether to notify. Returning `true` without actually
  mutating wakes every receiver for nothing; returning `false` after mutating leaves observers
  reading a value they were never told about. Do exactly one.
- The poller must stop. It selects on the token, *and* should bail when `tx.is_closed()` — otherwise
  a loader whose workers all exited early keeps querying the control DB until SIGTERM.
- `tokio::spawn` (not `spawn_local`) for the poller: it must not share the `LocalSet`'s single
  thread, or the whole point — taking work *off* the per-table loops — is lost.
- `watch::channel` requires tokio's `sync` feature, which PR 14.14 added explicitly to
  `crates/loader/Cargo.toml`. If that PR is not in your tree yet, add it here.
- **Nine test call sites will break** the moment you add the field to `TableCtx`; that is expected
  and is why `fixed_epoch_watch` exists. `crates/loader/tests/shutdown.rs:133` is a shared helper —
  fix it once there, not at each of its callers.
- `fixed_epoch_watch` drops its sender on purpose. That is safe **only** because nothing calls
  `changed()`; if a future ticket adds a `changed()` await, this helper must change with it. Say so
  in its doc comment.
- Keep the `.max(ctx.epoch)` on the baseline. Dropping it looks like a simplification and quietly
  breaks the shared-control-plane test story the original comment at `apply_loop.rs:22-25` records.
- Tests are Go-style siblings, never inline `mod tests {}`; without the `#[path]` wiring the new file
  is dead weight and the probe passes while nothing runs.
- `clippy::all` + `warnings` are `deny`; `unwrap`/`expect` are `deny` in production (re-allowed under
  `#[cfg(test)]` by `clippy.toml`). No new dependency, so `cargo deny` is unaffected. Do not touch
  `.sql` or the `.sqlx` offline cache — there is no Docker on this machine to regenerate it.
