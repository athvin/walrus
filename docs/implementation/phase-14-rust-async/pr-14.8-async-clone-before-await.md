# PR 14.8 — Deny non-Send futures outside the loader and document the LocalSet exception

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** loader,pg-sink

> **Phase:** 14 — Rust async/await · **Crates touched:** `loader`, `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 14.7 · **Unlocks:** PR 14.9

`clippy::future_not_send` fires **16** times across the tree: **15 in `loader`** and one in
`pg-sink`'s test-only cancel-safety helper. Two are accidental and fixed here: the pg-sink helper
uses `Cell` across an await, and loader's `table_exists` test helper is `async` despite containing
no await. The remaining **14 loader findings** are intentional — `apply_loop.rs:23`,
`apply_loop.rs:100`, `bootstrap.rs:56` and friends — because the loader deliberately keeps a
`duckdb::Connection` (which owns a `RefCell`, `duck.rs:40`) alive across `.await` and runs its
workers on a `LocalSet` (`main.rs:121`, `main.rs:147`). Twelve are covered by the loader lib/bin
crate roots; two live in separate integration-test crates and need item-level loader exceptions.
After this PR a non-`Send` future anywhere outside that documented loader boundary is a CI failure.

## Why — learning objectives

- **A future's `Send`-ness is decided by what is held across `.await`** — not by the function
  signature. One `Rc`/`RefCell`/`MutexGuard` alive at a suspension point makes the whole generated
  state machine `!Send`, and `tokio::spawn` rejects it at the call site, often far away.
- **Per-crate lint escape hatches** — a source-level `#![allow]` overrides a manifest-level `deny`
  (this is the mechanism the ticket relies on), which is exactly why the exception is expressed in
  the crate that owns the constraint rather than by weakening the workspace gate.
- **walrus's loader concurrency model** — one worker per `.duckdb` file, pinned to a `LocalSet`
  because DuckDB's `Connection` is `!Send`. After the two accidental sites are fixed, the 14
  remaining lint sites are the *shape of the design*, not a backlog.

- `Cargo.toml:14-24` — `[workspace.lints.rust]` / `[workspace.lints.clippy]`, the single place a
  new gate belongs.
- `crates/loader/src/duck.rs:31-53` — `TableDb`, its `parquet_cols: RefCell<HashMap<…>>` and the

- `crates/loader/src/main.rs:104-152` — `LocalSet::new()`, `local.spawn_local(...)`, and the
  sequential drain. This is the code that makes `Send` unnecessary *and unattainable* in `loader`.
- `crates/loader/src/apply_loop.rs:17` (`pub async fn apply_loop`) and `:93` (`async fn compact`) —
  two of the 14 sites, one public, one private: proof the lint is not limited to the public API.
- `crates/loader/src/lib.rs:1-20` and `crates/loader/src/main.rs:1-14` — the two crate roots that
  will carry the `#![allow]`. The lib and the bin are **separate crates**; one allow does not cover
  the other.
- `crates/loader/tests/shutdown.rs:160` and `reload_resync.rs:219` — separate integration-test
  crates whose helpers genuinely hold `TableCtx` across awaits; each needs an item-level exception.
- `crates/loader/tests/bootstrap.rs:123` and `crates/pg-sink/src/consume_test.rs:18` — the two
  accidental findings to fix rather than allow.

**In scope**

- Add `future_not_send = "deny"` to `[workspace.lints.clippy]` in the root `Cargo.toml`, with a
  comment naming the loader exception so the next reader does not "fix" the allows.
- Add a crate-level `#![allow(clippy::future_not_send, reason = "...")]` to
  **`crates/loader/src/lib.rs`** and
  **`crates/loader/src/main.rs`**, each with a comment naming the concrete cause: `duckdb::Connection`
  is `!Send` (it owns a `RefCell`, `duck.rs:40`), the apply workers run on a `LocalSet`
  (`main.rs:106`/`:132`), and the parallelism model is one worker per `.duckdb` file.
- Add item-level `#[allow(clippy::future_not_send, reason = "...")]` attributes to only
  `run_until_drain` in `crates/loader/tests/shutdown.rs` and `seed_live_mirror` in
  `crates/loader/tests/reload_resync.rs`, naming the `TableCtx`/DuckDB `LocalSet` model.
- Make loader test helper `table_exists` synchronous and remove its three `.await`s; it performs no
  asynchronous work and should not receive an exception.
- Replace `Cell<u32>` with `AtomicU32` in `crates/pg-sink/src/consume_test.rs`, preserving the two
  cancel-safety tests while making their helper future `Send`.

**Explicitly deferred** (do *not* build these here)

- Does **not** try to make the loader's futures `Send`. Doing so means one runtime per `.duckdb`
  file — a real, recorded finding, but PR 14.18's subject, not this PR's.
- Does **not** add `static_assertions`, `trybuild`, or any other dependency. The gate is one
  manifest line plus two attributes.
- Does **not** touch `clippy.toml`'s `disallowed-methods` (PR 14.7 owns that file's ban list) and
  does **not** promote any other nursery lint.

**Conflict — do not apply the rule blindly.** A source-level `#![allow]` overrides a manifest
`deny` but **not** a `forbid`. That override is precisely the mechanism this ticket depends on, so
the workspace entry must be `"deny"`. Writing `"forbid"` would make the loader uncompilable and
there would be no way to express the exception locally.

## Skeleton

```toml
# Cargo.toml
[workspace.lints.clippy]
all = "deny"
unwrap_used = "deny"
expect_used = "deny"
# A future that is not `Send` cannot be `tokio::spawn`ed on the multi-thread runtime, and the failure
# surfaces at the spawn site, not at the offending `.await`. Deny it workspace-wide.
# `future_not_send` is `clippy::nursery`, NOT part of `clippy::all` — so no `priority` juggling.
# EXCEPTION, by design: `loader` holds a `!Send` `duckdb::Connection` (RefCell, duck.rs:40) across
# awaits and runs its workers on a `LocalSet` (main.rs:106/132). Both loader crate roots carry a
# documented `#![allow]`; a source-level allow overrides this deny (which is why it is not `forbid`).
future_not_send = "deny"
```

```rust
// crates/loader/src/lib.rs — first line of the crate root, above the //! docs is fine too.
// The loader's whole parallelism model is ONE worker per `.duckdb` file, pinned to a `LocalSet`
// (main.rs:106/132): `duckdb::Connection` owns a `RefCell` (duck.rs:40), so it is `!Send` and every
// future that holds a `TableDb` across an `.await` is `!Send` too. Nothing here is ever `tokio::spawn`ed
// — only `spawn_local` — so `Send` is neither required nor attainable. See PR 14.18's ADR before
// "fixing" this. The workspace-level `future_not_send = "deny"` still guards the other four crates.
#![allow(
    clippy::future_not_send,
    reason = "DuckDB TableDb futures are intentionally pinned to the loader LocalSet"
)]

//! `walrus-loader` — reads the sink's staged Parquet from S3 and materialises it into per-table DuckDB
//! files (`<table>` mirror + `<table>_raw` CDC log).
```

```rust
// crates/loader/src/main.rs — the BIN is a separate crate; the lib's allow does not reach it.
#![allow(
    clippy::future_not_send,
    reason = "the loader pipeline owns !Send DuckDB workers driven by a LocalSet"
)]

//! The `walrus-loader` binary — the pod lifecycle shell.
```

## Hints & gotchas

- `future_not_send` is `clippy::nursery`, **not** part of `clippy::all`. Adding it next to
  `all = "deny"` needs no `priority = -1` — same situation as `must_use_candidate` in PR 13.2.
- Nursery lints are less stable than `style`/`correctness`; a toolchain bump can change the site
  count. That is a feature here (the gate is what matters), but expect the loader allows to absorb
  any drift, and re-run the `--force-warn` census if CI ever reports a *new* crate.
- The lint fires on **private** async fns too (`apply_loop.rs:93` is `async fn compact`), so a
  `pub(crate)` helper in `pg-sink` is fully covered by the gate.
- The lib and the bin are separate crates. `crates/loader/src/main.rs` needs its own attribute, and
  each integration test is another crate; keep the two test-target exceptions item-scoped rather
  than suppressing the whole file.
- Inner attributes (`#![...]`) must precede items; they may sit above or below the `//!` module docs,
  but not after the first `pub mod`. `cargo fmt` will not move them for you.
- Do not "fix" the 14 intentional loader sites by cloning data before the await. The blocker is
  `duckdb::Connection: !Send` itself, which no `Arc`/clone dance changes — see PR 14.18.
- Do **not** touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine
  to regenerate it, and this PR needs neither.
- `unwrap()` / `expect()` stay `deny` in production; `clippy::all` and `warnings` are already `deny`.
- Unit tests are Go-style siblings (`foo.rs` → `foo_test.rs`), never inline `mod tests {}`. This PR
  adds no test file — its probe is the clippy gate itself.
