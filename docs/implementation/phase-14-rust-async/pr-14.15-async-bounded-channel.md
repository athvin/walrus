# PR 14.15 — Forbid unbounded channels and make the last one bounded

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 14 — Rust async/await · **Crates touched:** `pg-sink` ·
> **Est. size:** S · **Depends on:** PR 14.14 · **Unlocks:** PR 14.16

Production code contains **0 unbounded channels** — but only because, until PR 14.14, it contained
**0 channels at all**. That is conformance by absence, and nothing prevents the next one from being
unbounded. The single `unbounded_channel` in the repo lives in an integration-test harness:
`spawn_echo_resolver` at `crates/pg-sink/tests/reload_export.rs:122-131`, where a live replication
stream (a producer that runs as fast as Postgres can decode) feeds an assertion loop that reads
**one** LSN at `:358` — no backpressure, no cap, memory bounded only by how much traffic the test
generates. After this merges that harness is bounded at a documented capacity with an explicit
full-channel policy, and `clippy.toml`'s `disallowed-methods` names `unbounded_channel`, so
`clippy::disallowed_methods` — already `deny` via `clippy::all` at `Cargo.toml:16-17` — fails CI the
moment anyone reintroduces one, in production *or* in a test.

## Why — learning objectives

- **Backpressure as a design property** — a bounded capacity converts an OOM into a slowdown (or an
  explicit, visible drop); the number you choose is a statement about burst size, not a guess.
- **`clippy.toml` `disallowed-methods` as the enforcement arm** of an architectural rule — a
  zero-code gate that outlives the reviewer who wrote the rule down.

/// Watch-LSN queue depth. The overlap probe consumes exactly ONE LSN (the first commit that
/// touched `watch_table` while the export ran — see the `watch_rx.recv()` at the call site), so
/// anything past the first is diagnostic slack, not data. 64 is ~an order of magnitude more than
/// a reload test's watch-table commits and caps the harness at 64 × size_of::<Lsn>() instead of
/// "however many commits the source produced".
const WATCH_LSN_CAPACITY: usize = 64;

fn spawn_echo_resolver(
    slot: &'static str,
    waiters: Arc<WatermarkWaiters>,
    watch_table: &'static str,
    token: CancellationToken,

    tokio::task::JoinHandle<()>,
    tokio::sync::mpsc::Receiver<Lsn>, // was UnboundedReceiver<Lsn>
) {
    let (tx, rx) = tokio::sync::mpsc::channel(WATCH_LSN_CAPACITY);
    let handle = tokio::spawn(async move {
        todo!("body unchanged down to the Commit arm");
    });
    (handle, rx)
}

## Hints & gotchas

- **`clippy.toml` applies to test targets too.** That is the point here — an unbounded channel in a
  harness is still an unbounded channel — but it is also why PR 14.7 kept its fs ban narrow. Do not
  widen either list opportunistically.
- `disallowed-methods` entries are path-resolved. Use an isolated temporary Cargo fixture if that
  resolution needs direct falsification; the locked policy remains the constructor entry alone.
- `disallowed_methods` lives in `clippy::style ⊂ clippy::all`, which `Cargo.toml:16` already denies.
  Do **not** add a `disallowed_methods = "deny"` line to `[workspace.lints.clippy]` — it is
  redundant, and a duplicate entry there needs `priority` juggling that this repo has so far avoided.
- `mpsc::channel(0)` panics; `WATCH_LSN_CAPACITY` is a const so this cannot regress silently.
- `Sender::try_send` returns `Result<(), TrySendError<T>>` where the error **carries the value back**.
  `.is_err()` is enough here; if you match, remember `TrySendError::Closed` is the normal end-of-test
  case and must not fail the harness.
- Resist `send().await` in the resolver even though it looks more "correct". The resolver is also
  the echo resolver: parking it stalls watermark resolution and the exporter fails with
  `echo timeout` — a confusing, unrelated-looking failure. Say so in the comment you leave.
- `tokio::sync::mpsc::Receiver` and `UnboundedReceiver` have the same `recv()` shape, so the consumer
  at `:358` needs no edit — but the `let (resolver, mut watch_rx) = …` bindings at `:330` and `:455`
  do need the new type to infer, so build with `--all-targets` before you believe it.
- `clippy::all` + `warnings` are `deny`; `unwrap`/`expect` are `deny` in production and re-allowed in
  tests by `clippy.toml`. This PR adds no dependency, so `cargo deny` is unaffected. Do not touch
  `.sql` or the `.sqlx` offline cache — there is no Docker on this machine to regenerate it.
