# PR 14.10 — Size and name the tokio runtime from bounds-validated config

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,loader,pg-sink

> **Phase:** 14 — Rust async/await · **Crates touched:** `common`, `loader`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 14.9 · **Unlocks:** PR 14.11

Both binaries build their runtime with `Builder::new_multi_thread().enable_all().build()` and
nothing else — `crates/loader/src/main.rs:28-31` and `crates/pg-sink/src/main.rs:30-33`. Production
code uses `worker_threads`, `max_blocking_threads`, `thread_name` and
`std::thread::available_parallelism` a combined **0** times. The default sizing is actively wrong
for the loader, whose entire parallelism model is one `LocalSet` on the `block_on` thread
(`main.rs:106`, `:132`): every extra worker thread is a container CPU request the pod never spends.
And unnamed threads make `kubectl exec … top -H` and every flamegraph unreadable — you get
`tokio-runtime-worker` for both services and nothing else. After this PR each binary names its
threads, sizes its pools from `serde`-typed config, and rejects an out-of-range value as a terminal
`ExitCode::Config` before the runtime is ever built.

## Why — learning objectives

- **tokio `Builder` knobs** — `worker_threads` (async executor threads), `max_blocking_threads`
  (the `spawn_blocking` pool, default **512**), and `thread_name`. They are independent pools; the
  second one exists to absorb blocking work like `tokio::fs`.
- **`std::thread::available_parallelism()` over `num_cpus`** — stable since 1.59, in `std`, and it
  accounts for the cgroup CPU quota a container actually gets. `num_cpus` is unmaintained and reads
  the host.
- **walrus config discipline** — `serde`-typed, env/file, bounds-validated at the edge; an invalid
  value is a *terminal* error mapped to `ExitCode::Config` (10), never a panic three modules later.

## Hints & gotchas

- `available_parallelism()` returns `io::Result<NonZeroUsize>` — do **not** `unwrap()` it
  (`unwrap_used` is `deny` in production). `.map(NonZeroUsize::get).unwrap_or(1)` is the shape.
- `worker_threads(0)` **panics inside tokio's builder**. That is exactly why the bound is enforced
  in `validate()` — the config layer must make the panic unreachable, not catch it.
- Both config structs are `#[serde(deny_unknown_fields, default)]` with a hand-written `Default`
  impl. Adding a field to the struct without adding it to `Default` is a compile error; adding it to
  neither means `WALRUS_WORKER_THREADS` is *rejected* as an unknown field. Do both.
- PR 13.2 promoted `clippy::must_use_candidate` to `deny`, so a new pure `pub fn` such as
  `resolve_worker_threads` needs `#[must_use]` or clippy fails. `validate_worker_threads` returns
  `Result`, which is already `#[must_use]` — a second attribute there is `clippy::double_must_use`.
- Linux truncates a thread name to 15 bytes (`TASK_COMM_LEN`). `walrus-loader` (13) and
  `walrus-sink` (11) both fit; a longer name would silently truncate in `top -H`.
- tokio's `thread_name` applies to worker **and** blocking-pool threads, so the pod's thread list
  becomes uniformly greppable — that is the point of the change, not a side effect.
- Keep `enable_all()`. Dropping it to `enable_io().enable_time()` looks tidier and breaks
  `tokio::signal` (the shutdown handlers).
- Do **not** touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine
  to regenerate it, and this PR needs neither.
- Unit tests are Go-style siblings (`foo.rs` → `foo_test.rs`) declared with
  `#[cfg(test)] #[path = "foo_test.rs"] mod tests;` at the bottom of the module. Copy the
  declaration from `crates/pg-sink/src/config.rs:314-316`.
