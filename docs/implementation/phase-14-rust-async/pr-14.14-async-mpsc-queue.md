# PR 14.14 — Report loader worker failures over a bounded mpsc instead of mutating shared shutdown state

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 14 — Rust async/await · **Crates touched:** `loader` ·
> **Est. size:** M · **Depends on:** PR 14.13 · **Unlocks:** PR 14.15

Production code uses **0 mpsc channels**. The loader's per-table workers report failure by
*cancelling the shared shutdown token from inside the worker* (`crates/loader/src/main.rs:131-137`),
and that workaround's own six-line comment explains why it exists: without it the sequential
`for h in handles { h.await }` drain at `main.rs:143-152` blocks on a **healthy** worker — one that
only returns when the token is cancelled — and the loader deadlocks instead of dying. The cost is
that `main` learns exactly one bit, "someone failed": not which table, not why, and
indistinguishable from a real SIGTERM. Worse, the drain loop only `tracing::error!`s the error and
then falls through to `Ok(())`, so **a quarantined table exits the pod with status 0**. After this
merges a bounded `tokio::sync::mpsc` carries `{ schema, table, LoaderError }` from each worker to a
small supervisor that `main` awaits: the first failure is logged *with its table*, the token is
cancelled by the supervisor (not the worker), the drain still terminates, and `run()` returns that
worker's classified `LoaderError` so the pod exits with its real `ExitCode`.

## Why — learning objectives

- **Bounded `tokio::sync::mpsc` for task→supervisor reporting** — what capacity actually buys you,
  and `try_send` vs `send().await` when the producer must never park.
- **walrus loader supervision** — one worker per `.duckdb` file, and why a single failed worker must
  take the whole pod down rather than leave the rest limping.

## Scope

**In scope**

- A new `crates/loader/src/supervisor.rs` module (plus its sibling test file, wired into
  `crates/loader/src/lib.rs`) holding three items: the `WorkerFailure` message, a
  `failure_channel(workers)` constructor that sizes capacity from the worker count, and an
  `async fn supervise(...)` that races the failure receiver against the drain future.
- `main.rs`: build the channel before the spawn loop, clone a `Sender` into each worker, `drop` the
  original so the channel closes when the last worker exits, and hand the receiver + the existing
  sequential drain to `supervise` inside `local.run_until(...)`.
- The worker closure stops calling `worker_token.cancel()`; it reports the failure instead. The
  **supervisor** cancels the token — one writer of that decision, not N.
- `run()` returns the first failure's `LoaderError` **after** `lease::release_all` and the health
  server join, so a failing pod still releases its leases before it exits (a live lease would make
  the replacement hit `LeaseContended`).
- `report(&tx, failure)` uses `try_send`: a worker must never park on a supervisor that is busy
  awaiting a different worker. A full channel logs a `warn!` and drops — which capacity makes
  unreachable, and the warning proves it if the invariant ever breaks.
- Add `"sync"` to the loader's `tokio` feature list in `crates/loader/Cargo.toml` (see Hints — today
  it arrives only by accident).

**Explicitly deferred** (do *not* build these here)

- **Do not** move the apply loops off the `LocalSet`. They stay `!Send`, one per `.duckdb` file.
- **Do not** put a channel anywhere on the data path. The S3 PUT stays parked inline: architecture
  §1.5 requires PUT → manifest → checkpoint ordering, implemented as `flush_batch_keepalive`
  (`crates/pg-sink/src/consume.rs:346`). A queue there would break the durability invariant.
- No new error variant, no change to `exit_code()` mappings, no change to what `apply_loop` returns.
- Do not make the capacity configurable, and do not reach for `unbounded_channel` — PR 14.15 bans it
  outright and this ticket is the reason the ban has teeth.

**Conflict — capacity is load-bearing.** Capacity must be **>= the worker count**, so every worker
can deposit its failure without ever blocking on `send`. This is precisely the situation where an
unbounded channel is tempting; resist it. The bound is `owned.len()` (one message per worker,
maximum), and `.max(1)` because `mpsc::channel(0)` panics.

//! Worker→`main` failure reporting (PR 14.14). One worker per `.duckdb` file, and any one of them
//! failing must take the pod down — but the drain is sequential, so `main` cannot learn about a
//! failure by awaiting handles in order. A bounded `mpsc` carries the failure out of band; the
//! supervisor is the single place that decides to cancel the shutdown token.

pub fn report(tx: &mpsc::Sender<WorkerFailure>, failure: WorkerFailure) {

/// Race the failure stream against `drain`. The FIRST failure cancels `token` (which is what makes
/// the sequential drain inside `drain` finish — every healthy worker returns on cancellation) and is
/// the value returned; later failures are logged, not returned. Returns `None` on a clean drain.
pub async fn supervise<D>(
    mut rx: mpsc::Receiver<WorkerFailure>,
    token: &CancellationToken,
    drain: D,
) -> Option<WorkerFailure>
where
    D: std::future::Future<Output = ()>,
{
    tokio::pin!(drain);
    let mut first: Option<WorkerFailure> = None;
    loop {
        tokio::select! {
            biased; // PR 14.1: learn about the failure before declaring the drain finished.
            Some(f) = rx.recv() => {
                todo!("if first.is_none(): error! with table + error, token.cancel(), first = Some(f); \
                       else: error! `additional apply loop failed` (the exit code stays the first)");
            }
            () = &mut drain => return first,
        }
    }
}

// crates/loader/src/main.rs — replacing lines 104-152 (the LocalSet block) and 154-161 (the tail).

let local = tokio::task::LocalSet::new();
let (failures_tx, failures_rx) = loader::supervisor::failure_channel(keys.len());
let handles: Vec<_> = owned
    .into_iter()
    .map(|o| {
        // Captured BEFORE `o` moves into the ctx — the failure message must name its table.
        let (schema, table) = (o.schema.clone(), o.table.clone());
        let ctx = loader::phase_a::TableCtx { /* unchanged */ };
        let worker_token = token.clone();
        let tx = failures_tx.clone();
        // A failed worker no longer cancels the token itself: it REPORTS, and the supervisor
        // cancels. One writer of that decision, and `main` learns which table and why.
        local.spawn_local(async move {
            if let Err(error) = loader::apply_loop::apply_loop(ctx, worker_token).await {
                loader::supervisor::report(
                    &tx,
                    loader::supervisor::WorkerFailure { schema, table, error },
                );
            }
        })
    })
    .collect();
// `main` holds no sender, so `rx.recv()` yields `None` once the last worker exits.
drop(failures_tx);

let first_failure = local
    .run_until(loader::supervisor::supervise(failures_rx, &token, async {
        for h in handles {
            if let Err(e) = h.await {
                tracing::error!(error = %e, "apply worker panicked");
            }
        }
    }))
    .await;

tracing::info!("draining: releasing leases");
renewer.abort();
lease::release_all(&pool, epoch, &keys, &cfg.instance).await;
server
    .await
    .map_err(|e| LoaderError::Internal(format!("health server join: {e}")))?
    .map_err(|e| LoaderError::Internal(format!("health server: {e}")))?;
// Surface the worker's own classified error AFTER the leases are released, so a failing pod never
// dies holding a live lease (the replacement would hit LeaseContended).
if let Some(f) = first_failure {
    return Err(f.error);
}
Ok(())

## Hints & gotchas

- **`tokio/sync` currently reaches the loader by accident.** `crates/loader/Cargo.toml` asks for
  `["macros", "rt-multi-thread", "signal", "net", "time"]` — none of which enables `sync`. It
  compiles today only because `sqlx-core`'s `_rt-tokio` feature enables `tokio/sync` and cargo
  unifies features. Add `"sync"` explicitly; relying on another crate's feature set is exactly the
  kind of thing that breaks on a dependency bump.
- `mpsc::channel(0)` **panics** at runtime ("mpsc bounded channel requires buffer > 0"). The loader
  can legitimately own zero tables (an empty registry), so `.max(1)` is not defensive padding — it
  is required.
- `LoaderError` is **not `Clone`**. `WorkerFailure` must own it and be moved into the channel once;
  do not add a `#[derive(Clone)]` to make the plumbing easier.
- `mpsc::Receiver::recv()` **is** cancel-safe — no message is lost when a `select!` drops it — which
  is why it can be a bare branch here. Contrast PR 14.2's frame future.
- Drop the original `Sender` after cloning it into the workers. If `main` keeps one, `rx.recv()`
  never yields `None` and a future refactor that loops on `recv()` would hang forever.
- The worker closure runs under `spawn_local` on a `LocalSet`, so its future is `!Send` — that is
  fine: `mpsc::Sender<T>` is `Send + Sync` and works identically inside a `!Send` future. Do not
  "fix" this by trying to make the worker `Send`.
- Keep `biased;` in `supervise` with the `recv` arm first. Without it, a drain future that resolves
  in the same poll as an arriving failure can win the coin flip and the failure is lost — a
  once-in-a-thousand flake that is very hard to reproduce.
- `tokio::pin!(drain)` then `() = &mut drain` — polling the drain by value in a loop would restart
  it on every iteration and the sequential `h.await` would begin again from the first handle.
- Do not change `apply_loop`'s signature or return type. The worker closure adapts; the loop does
  not need to know a supervisor exists.
- Tests are Go-style siblings, never inline `mod tests {}`; without the `#[path]` wiring the new file
  is dead weight.
- `clippy::all` + `warnings` are `deny`, `unwrap`/`expect` are `deny` in production (re-allowed under
  `#[cfg(test)]` by `clippy.toml`). Any new dependency must clear `cargo deny` — this PR needs none.
  Do not touch `.sql` or the `.sqlx` offline cache; there is no Docker on this machine.
