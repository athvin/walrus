# PR 14.13 — Own the reload exporter tasks in a JoinSet instead of detaching them

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 14 — Rust async/await · **Crates touched:** `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 14.12 · **Unlocks:** PR 14.14

`ReloadController::spawn_exporter` fires `tokio::spawn` at `crates/pg-sink/src/reload.rs:424` and
throws the returned `JoinHandle` on the floor. Nothing owns the exporters after that. On SIGTERM the
controller's own loop returns immediately (`reload.rs:270-275`) while up to `max_concurrent_reloads`
exporters are mid-`PUT` or mid-manifest-write; nothing joins them, nothing bounds them, and a
**panicking** exporter is completely invisible — its only trace is the `OwnedSemaphorePermit`
silently dropping and a free permit reappearing next tick. `JoinSet` appears **0 times** in the
repo, and of the 12 production `tokio::spawn` calls, 5 are fully detached. After this merges the
controller owns a `JoinSet<()>`: every exporter's exit is *observed* (finished, panicked, or
aborted), shutdown drains the set under a bounded budget and then `abort_all()`s the stragglers, and
the `exporting` rows those stragglers leave behind are recovered exactly as designed — lease expiry
plus PR 6.9's `adopt_and_resume`.

## Why — learning objectives

- **Structured concurrency** — a `JoinSet` gives you as-completed results, abort-on-drop and panic
  visibility that a bare `tokio::spawn` throws away; a detached task is a task you cannot reason
  about.
- **walrus reload lifecycle** — `exporting` rows are recovered by lease expiry + startup adoption,
  which is *why* aborting an exporter is safe and hanging on one is not.

**In scope**

- Thread a `&mut tokio::task::JoinSet<()>` through the controller task: `spawn_exporter`, `tick` and
  `adopt_and_resume` all take it, and the set is created inside the `tokio::spawn` body at
  `reload.rs:260` so it lives exactly as long as the controller.
- `spawn_exporter` becomes `set.spawn(async move { … })` — the body is moved verbatim, not rewritten.
- Add a **join arm** to the controller's outer `select!` so a finished exporter is observed
  promptly, and a small `observe_exporter_end` helper that classifies the `JoinError` into
  finished / panicked / aborted and logs each at the right level (a panic is `error!`).
- Add a **bounded drain** on the cancellation paths (both the outer and the inner cancel arm): join
  the set under one `tokio::time::timeout`, and on expiry `abort_all()` + drain the aborted tasks.
  The budget is a module const in `reload.rs`, commented against the K8s grace budget.
- Restructure the outer `select!` into the *event-then-handle* shape (see Skeleton) — the join arm
  borrows `set` mutably for the whole `select!`, so the tick arm cannot also call
  `controller.tick(&mut set)` inside it. This is the sharp edge of the whole PR.
- New `reload_test.rs` cases over the two extracted helpers: a panicking task **is** observed as a
  panic, and the drain returns within its budget by aborting a task that never finishes.

**Explicitly deferred** (do *not* build these here)

- **Do not** convert the loader's `LocalSet` handles at `crates/loader/src/main.rs:107-152` to
  `JoinSet::spawn_local`. Those futures are `!Send` and that is a separate, riskier restructure —
  PR 14.14 reshapes that supervision path a different way.
- **Do not** touch the four `tokio_postgres` connection-driver spawns (`preflight.rs:115`,
  `heartbeat.rs:195`, `reload_export.rs:117`, `snapshot.rs:123`). Those must outlive their client by
  design; putting them in a set that aborts on drop would kill live connections.
- No change to the claim/preflight logic, the `Semaphore` cap, the lease renewal cadence, or the
  `ExporterEnd` variants.
- Do not make the drain budget configurable — PR 14.10 owns runtime/config sizing for this phase.

```rust
use tokio::task::{JoinError, JoinSet};

/// How long shutdown waits for in-flight exporters before aborting them. Deliberately a const, not
/// config: it is a slice of the K8s termination grace period, which the sink's WAL drain also draws
/// on (walrus-pg-sink.md §4.5). An exporter that cannot finish inside it is NOT lost — its row
/// stays `exporting` with a dying lease, which is exactly what PR 6.9's startup scan adopts.
const EXPORTER_DRAIN_BUDGET: Duration = Duration::from_secs(5);

/// How one exporter task left the set. Split out so a unit test can assert the classification
/// without standing up a controller.

    /// `exporting` and only lease expiry recovers it.
    Panicked,
    /// We aborted it (drain budget spent).
    Aborted,
}
```

```rust
// crates/pg-sink/src/reload.rs — the controller task body, replacing lines 260-295.
//
// THE BORROW: `set.join_next()` holds `&mut set` for the whole `select!`, so the tick arm cannot
// call `controller.tick(&mut set)` *inside* the same select. Produce a small event value, let the
// select end (releasing the borrow), then handle it. Same shape PR 14.2 used for the frame future.

/// What woke the controller loop. Carrying it out of the `select!` is what frees `&mut set`.
enum ControllerEvent {
    Cancelled,
    Joined(Result<(), JoinError>),
    Tick,
}

tokio::spawn(async move {
    let mut set: JoinSet<()> = JoinSet::new();
    if !token.is_cancelled() {
        controller.adopt_and_resume(&mut set).await;
    }
    let mut tick = tokio::time::interval(controller.cfg.poll_interval);
    tick.set_missed_tick_behavior(tokio::time::MissedTickBehavior::Skip);
    loop {
        let event = tokio::select! {
            biased; // PR 14.1: shutdown wins the race, deterministically.
            _ = token.cancelled() => ControllerEvent::Cancelled,
            // Disabled while the set is empty: `join_next()` on an empty set is `Ready(None)`.
            Some(joined) = set.join_next(), if !set.is_empty() => ControllerEvent::Joined(joined),
            _ = tick.tick() => ControllerEvent::Tick,
        }; // `set` borrow ends here.

        match event {
            ControllerEvent::Cancelled => {
                tracing::info!(exporters = set.len(), "reload controller cancelled; draining");
                drain_exporters(&mut set, EXPORTER_DRAIN_BUDGET).await;
                return;
            }
            ControllerEvent::Joined(joined) => {
                observe_exporter_end(joined);
            }
            ControllerEvent::Tick => {
                tokio::select! {
                    biased;
                    _ = token.cancelled() => {
                        tracing::info!("reload controller cancelled mid-tick");
                        drain_exporters(&mut set, EXPORTER_DRAIN_BUDGET).await;
                        return;
                    }
                    res = controller.tick(&mut set) => {
                        if let Err(e) = res {
                            tracing::warn!(error = %e, "reload controller tick failed; retrying next tick");
                        }
                    }
                }
            }
        }
    }
})
```

## Hints & gotchas

- **The borrow is the whole difficulty.** `set.join_next()` is a future that holds `&mut set` for as
  long as the `select!` lives. If you put `controller.tick(&mut set)` in a sibling arm, borrowck
  rejects it — and no amount of arm reordering helps. The `ControllerEvent` enum is not decoration;
  it is what ends the borrow before the handler runs.
- `JoinSet::join_next()` on an **empty** set resolves to `Ready(None)` immediately. In `select!` a
  non-matching pattern just disables that branch for this poll, so it is not a busy loop — but the
  `if !set.is_empty()` guard makes the intent obvious and avoids a needless poll.
- `join_next()` **is** cancel-safe (dropping it loses no completions — results stay in the set), so
  it is a legitimate bare `select!` branch. That is the exception, not the rule; PR 14.2 is about
  the futures that are not.
- `set.spawn(fut)` requires `fut: Send + 'static`, which the exporter body already satisfies (it is
  `tokio::spawn`ed today). Do not add `spawn_local` here — `ReloadController` is not on a `LocalSet`.
- `set.spawn` returns an `AbortHandle`. Ignore it deliberately; do not stash handles in a `Vec`
  alongside the set, which would re-create the problem this PR removes.
- **`abort_all()` does not wait.** It only requests cancellation; you must still drain with
  `while set.join_next().await.is_some() {}` or the tasks are merely detached again. An aborted task
  surfaces as `Err(e)` with `e.is_cancelled()`.
- Aborting an exporter is **safe by design**: the row stays `exporting` with a dying lease, and
  `adopt_and_resume` (`reload.rs:492`) re-acquires + resumes it from the chunk cursor on the next
  start. Say that in the log line so the operator does not chase a phantom.
- Do not `.await` the drain outside a timeout anywhere. `ReloadController::spawn`'s `JoinHandle` is
  awaited by the sink's shutdown path, so an unbounded join here becomes an unbounded pod shutdown.
- `#[tokio::test(start_paused = true)]` needs tokio's `test-util`, already a `pg-sink`
  dev-dependency. No new dependency, so `cargo deny` is unaffected.
- Tests are Go-style siblings — `reload_test.rs` is already wired via
  `#[cfg(test)] #[path = "reload_test.rs"] mod tests;` at the bottom of `reload.rs`. Never add an
  inline `mod tests {}`.
- `clippy::all` + `warnings` are `deny`; `unwrap`/`expect` are `deny` in production and re-allowed
  under `#[cfg(test)]` by `clippy.toml`. Do not touch `.sql` or the `.sqlx` offline cache — there is
  no Docker on this machine to regenerate it.
