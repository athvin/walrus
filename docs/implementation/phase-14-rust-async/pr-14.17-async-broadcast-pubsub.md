# PR 14.17 — Record why walrus has no broadcast channel and guard the decision

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** evidence
> **Gates:** fmt,clippy,test · **Test packages:** —

> **Phase:** 14 — Rust async/await · **Crates touched:** none (`clippy.toml` + `docs/`) ·
> **Est. size:** S · **Depends on:** PR 14.16 · **Unlocks:** PR 14.18

There are **0 `broadcast` references** in the entire repo, and that is not an oversight — the rule's
use case is already occupied. walrus's only one-to-many notification is **shutdown**, and it is
served by `tokio_util::sync::CancellationToken`: **28 production references** across both binaries,
consumed by **10 `select!` arms**, with a hierarchy via `child_token()` (`reload.rs:410`) and a
`DropGuard` RAII form (PR 14.6). `broadcast` would be strictly worse for that job — it demands
`T: Clone`, a ring-buffer capacity, and a `RecvError::Lagged` arm for a payload-free *edge* that can
never meaningfully lag. And neither data path has a multi-consumer event stream to justify one: the
replication socket has exactly **one** consumer (`run_decode_loop`) and each `.duckdb` file has
exactly **one** apply loop. This PR does not add a broadcast channel. It writes the decision down as
an ADR with the counts that support it, names the single condition that would reverse it, and puts a
`clippy.toml` guard in front of the constructor so the next person reaches the ADR before the crate.

## Why — learning objectives

- **Picking the fan-out primitive by delivery semantics** — `broadcast` (every subscriber sees every
  message) vs `watch` (latest value only) vs `mpsc` (one consumer, backpressure) vs
  `CancellationToken` (a one-shot, payload-free, hierarchical edge). Three of the four are now in
  the tree; knowing why the fourth is not is the same skill.
- **walrus shutdown topology** — one token, N observers, `child_token()` for scoped subtrees, and
  why a level-triggered edge beats a message queue for "stop".

place that *looks* like it (shutdown) is better served by a primitive the corpus does not cover. The
ADR must say this explicitly — that the rule was read, applied to the real tree, and declined with
evidence — and must never read as "not relevant".

## Hints & gotchas

- **"Not relevant" is a failed ADR.** Every claim in the note must carry the command that produced
  it or the `file:line` that shows it. A future reader will re-run those commands; if they do not
  reproduce, the note is worse than nothing.
- Count `CancellationToken` the same way the probe does (`crates/*/src`, excluding `*_test.rs`) so
  the number in the ADR matches what anyone re-running it sees. If the tree has moved since this
  ticket was written, **record the new number**, not the one quoted here.
- `broadcast::channel` is re-exported out of a private module. If direct path-resolution proof is
  needed, use a disposable Cargo fixture rather than a scratch call in tracked production source.
- `disallowed_methods` is in `clippy::style ⊂ clippy::all`, already `deny` at `Cargo.toml:16`. Do
  **not** add a lint entry to `[workspace.lints.clippy]`; the config alone arms it.
- `clippy.toml` applies to test targets too. Say so in the ADR: a test harness wanting a broadcast
  channel is a signal that the reversal condition may be approaching, not a reason for a quiet
  `#[allow]`.
- Do not "improve" `CancellationToken` while you are in here — no shutdown-reason payload, no
  wrapper type. That is a design change wearing a documentation PR's clothes.
- The metadata line says **no crates are touched**: if your diff contains a `crates/**/*.rs` change,
  the ticket has drifted. The `cargo test -p pg-sink` box is there because `clippy.toml` is
  repo-wide, so the gate must be proven against a real crate's targets.
- `clippy::all` + `warnings` are `deny`; `unwrap`/`expect` are `deny` in production. This PR adds no
  dependency, so `cargo deny` is unaffected. Do not touch `.sql` or the `.sqlx` offline cache —
  there is no Docker on this machine to regenerate it.
