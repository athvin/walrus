# PR 14.4 — Replace the two-generic Fn-returning-Future bounds with AsyncFnMut

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 14 — Rust async/await · **Crates touched:** `pg-sink` ·
> **Est. size:** S · **Depends on:** PR 14.3 · **Unlocks:** PR 14.5

Two production helpers use the pre-1.85 two-generic pattern *verbatim from the rule's Bad block*:
`retry_transient` (`crates/pg-sink/src/bootstrap.rs:148-152` — `F: FnMut() -> Fut, Fut:
Future<Output = Result<T, Error>>`) and `lease_guarded_export` (`crates/pg-sink/src/reload.rs:64-74`
— `R: FnMut() -> RFut, RFut: Future<Output = anyhow::Result<bool>>`). Zero `AsyncFn` / `AsyncFnMut`
/ `AsyncFnOnce` bounds exist anywhere in the tree, though MSRV is **1.95**, well past the 1.85
stabilisation. The cost is visible at the call sites: `bootstrap.rs:69-77` has to clone the `Arc`
object store and the instance name into an `async move` block on **every retry attempt**, purely
because the old bound cannot accept a closure whose future borrows from the environment. After this
merges both helpers take a single `AsyncFnMut` bound and the object-store and source-DB retries
borrow instead of cloning.

## Why — learning objectives

- **`AsyncFn` / `AsyncFnMut` / `AsyncFnOnce`** — one bound instead of two generics, and *why* the
  two-generic form structurally cannot accept an async closure that borrows across the call (the
  future's lifetime is not tied to the call).
- **walrus startup-deadline retry policy** — transient vs terminal via `common::Error::is_terminal`,
  with every attempt bounded so `startup_deadline` is honoured.

**In scope**

- `crates/pg-sink/src/bootstrap.rs`: `retry_transient<T, F>` with `F: AsyncFnMut() -> Result<T,
  Error>`; drop the `Fut` generic and the `std::future::Future` bound.
- `crates/pg-sink/src/reload.rs`: `lease_guarded_export<R, E>` with `R: AsyncFnMut() ->
  anyhow::Result<bool>`; drop the `RFut` generic. **Leave `E` exactly as it is.**
- Convert the two clone-dance call sites at `bootstrap.rs:69` and `bootstrap.rs:83` to `async ||`
  closures that borrow `object_store` / `cfg` directly, deleting the per-attempt `clone()`s. The
  control-DB site at `:49` becomes `async || { … }` too (a one-token change).
- Add `use std::ops::AsyncFnMut;` to both modules — the trait is not in the 2021 prelude.
- One new case in `crates/pg-sink/src/bootstrap_test.rs` that passes an `async ||` closure whose
  future **borrows** a local, proving the new capability. It must not compile against the old bound.

**Explicitly deferred** (do *not* build these here)

- **No other generic bound is converted.** This ticket touches exactly these two `where` clauses.
- **No new `async ||` closures beyond the three `retry_transient` call sites.** In particular, leave
  the production `renew` closure at `reload.rs:451-464` alone: it moves an owned `Arc`/`String` into
  a spawned task and has no borrow to shed here.
- **No change to retry or backoff semantics** — same attempt budget, same terminal-vs-transient
  branch, same `deadline` arithmetic.
- **No edition bump.** 2021 stays; the missing prelude entry is solved with an import.

**Conflict — do not blindly follow the rule.** The rule's Key Points say the traits "are brought in
scope automatically in the 2024 edition". walrus is edition 2021 (`Cargo.toml:6`), so add
`use std::ops::AsyncFnMut;` rather than bumping the edition — an edition bump is a separate,
whole-workspace change and is out of scope for this phase. And `E: Future<Output = …>` at
`reload.rs:73` is a plain future parameter, *not* a closure: converting it to `AsyncFnOnce` would
change the caller contract for no gain. Leave it.

/// The capability the old `F: FnMut() -> Fut, Fut: Future` bound could not express: the attempt
/// future BORROWS `label` from the enclosing scope while the closure also mutates `attempts`.
/// Under the two-generic form this is a lifetime error, because `Fut` is one fixed type that
/// cannot name the borrow created by each call.
#[tokio::test]
async fn retry_accepts_a_borrowing_async_closure() {
    let deadline = Instant::now() + Duration::from_secs(3600);
    let label = String::from("canary"); // borrowed, never cloned into the attempt
    let mut attempts = 0_u32;
    let out: Result<usize, Error> = retry_transient(deadline, "borrowing", async || {
        attempts += 1;
        todo!("first attempt transient, second returns Ok(label.len())");
    })
    .await;
    assert_eq!(out.unwrap(), 6);
    assert_eq!(attempts, 2);
}

## Hints & gotchas

- **The existing call sites keep compiling.** `AsyncFnMut` has a blanket impl for any
  `FnMut() -> Fut where Fut: Future`, so `|| async move { … }` still satisfies the new bound. That
  makes the migration low-risk — and it also means the grep probe, not the compiler, is what proves
  you actually converted the three call sites. Convert them.
- **`async ||` is stable in edition 2021** (Rust 1.85+); only the *prelude entry* for the traits is
  2024-only. `use std::ops::AsyncFnMut;` is the whole fix — do not reach for `edition = "2024"`.
- **The call future borrows the closure.** `AsyncFnMut::call` takes `&mut self`, so the future
  returned by `op()` holds a mutable borrow of `op` for as long as it lives — and a temporary in a
  `match` scrutinee lives until the end of the whole `match`. `retry_transient` is safe because no
  arm touches `op`; if you ever need a second call inside an arm, bind the result to a `let` first.
  (Same family of bug as PR 14.3's scrutinee fix.)
- Pick `AsyncFnMut`, not `AsyncFn`: both closures mutate captured state (`attempts`, the backoff
  bookkeeping in the tests, the `AtomicI64` reload id in production) and both are called repeatedly.
  `AsyncFnOnce` would be wrong — the helper loops.
- **Do not touch `E`.** `lease_guarded_export` pins `export` with `tokio::pin!` and polls
  `&mut export`; it is one future, awaited to completion at most once. An `AsyncFnOnce` bound would
  force every caller to wrap its export in a closure for nothing.
- The new test's `assert_eq!(out.unwrap(), 6)` relies on `"canary".len()`; `unwrap` is fine here
  because `clippy.toml` re-allows it under `#[cfg(test)]`, while production stays `deny`.
- `cargo deny` is unaffected — no new dependency; `AsyncFnMut` is std.
- Tests are Go-style siblings (`bootstrap_test.rs` is already wired at `bootstrap.rs:173-175`),
  never inline `mod tests {}`.
- `clippy::all` + `warnings` are already `deny`, so a now-unused import (e.g. a leftover
  `std::future::Future`) fails CI. Do not touch `.sql` or the `.sqlx` offline cache — there is no
  Docker on this machine to regenerate it.
