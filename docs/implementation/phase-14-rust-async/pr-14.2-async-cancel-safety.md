# PR 14.2 — Pin the replication frame future so a dropped select branch cannot tear a feedback write

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 14 — Rust async/await · **Crates touched:** `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 14.1 · **Unlocks:** PR 14.3

`ReplicationStream::next()` is used **bare** as a `tokio::select!` branch at
`crates/pg-sink/src/consume.rs:85`, and it is not cancel-safe. Its inner `read_message` *is* — bytes
accumulate in the `self.rbuf` field, documented at `replication.rs:320-321` — but `next()` also
calls `send_received_feedback` (`replication.rs:196` on the feedback deadline, `:294` on a
`reply_requested` keepalive), and that does `write_all` + `flush` straight onto the `TcpStream`. If
the `beat_check.tick()` arm fires while that write is parked, the branch future is dropped
mid-write and a **partial `'r'` standby-status frame** is left on the CopyBoth wire; the walsender
then reads the next frame's bytes as a continuation of the torn one. Only 2 `tokio::pin!` sites
exist in production today (`reload.rs:75`, `consume.rs:356`), and `flush_batch_keepalive`
(`consume.rs:346-368`) already proves the correct pattern. After this merges the decode loop pins
one `next()` future and polls `&mut fut` across select iterations, so a heartbeat tick parks the
frame future instead of destroying it — and every `pub async fn` reachable from a `select!` arm
states its cancel-safety in its own doc comment.

## Why — learning objectives

- **Cancel safety** — which futures lose state when `select!` drops them, and `tokio::pin!` +
  `&mut fut` as the fix that keeps one future alive across many loop iterations.
- **Postgres CopyBoth wire discipline** — a torn standby-status frame desyncs the walsender; the
  connection does not error, it silently misparses everything after it.

**In scope**

- Restructure `run_decode_loop`'s loop body into two phases so the frame future can be pinned:
  an inner block that owns `tokio::pin!(frame)` and `select!`s until it has an *event*, then a
  handler phase — outside that block, so the `&mut stream` borrow has ended — that does the work.
  This is the only way the pin can coexist with the cancel arm, which needs `stream` for the drain.
- Poll the pinned future as `res = &mut frame`, so a `beat_check.tick()` firing **parks** it rather
  than dropping it. `tokio::pin!` count goes 2 → 3.
- Add a `## Cancel safety` doc section to every `pub async fn` reachable from a `select!` branch or
  arm body, stating plainly whether dropping it loses state and what walrus does about it. At
  minimum: `ReplicationStream::next`, `::send_standby_status`, `::send_received_feedback`,
  `consume::flush_batch`, `consume::flush_batch_kind`, `shutdown::drain`,
  `heartbeat::Heartbeat::maybe_beat`.
- Extend the existing sibling `crates/pg-sink/src/consume_test.rs` with cases that drive a
  `select!` whose non-frame arm fires repeatedly while an accumulating future is in flight,
  asserting the pinned future's partial progress survives and that the recreate-every-iteration
  shape loses it. The existing `#[cfg(test)] #[path] mod tests;` wiring in `consume.rs` stays
  unchanged.
- Document the one **residual**: the cancellation arm still drops the frame future. Record it in
  `next()`'s `## Cancel safety` section, with the mitigation (the drain immediately sends a fresh
  complete standby frame and then `CopyDone`s) and the real fix that is out of scope (staging
  outbound bytes in a `wbuf` field, mirroring `rbuf`).

**Explicitly deferred** (do *not* build these here)

- **Do not touch `flush_batch_keepalive`** (`consume.rs:346-368`) — it is already correct and is the

- No change to what the drain does, to the heartbeat cadence, or to `feedback_budget()`.
- No new dependency (`futures`, `tokio-util::io`, `pin-project`) — `tokio::pin!` is enough.

## Skeleton

```rust
// crates/pg-sink/src/consume.rs — inside `run_decode_loop`, replacing the body of the loop at
// line 61. `stream: &mut ReplicationStream` is a parameter, so the pinned future borrows it and
// the borrow MUST end before the handler phase can call `drain(stream, …)` / `flush_sealed(…,
// stream, …)`. An inner block is what ends it.

/// What ended one pass of the frame race. Carrying the outcome out of the inner block is what
/// lets the pinned `next()` future be dropped *before* the handler phase touches `stream`.
enum FrameEvent {
    /// SIGTERM/SIGINT: run the ordered drain.
    Cancelled,
    /// A frame (or `None` = stream end), or the read error.
    Frame(anyhow::Result<Option<ReplicationMessage>>),
}

loop {
    let event = {
        // ONE `next()` future for this frame, pinned so a heartbeat tick parks it instead of
        // dropping it mid-`send_received_feedback` (a torn 'r' frame desyncs the walsender).
        let frame = stream.next();
        tokio::pin!(frame);
        loop {
            tokio::select! {
                biased; // PR 14.1: shutdown wins the race, deterministically.
                () = token.cancelled() => break FrameEvent::Cancelled,
                // Polled by &mut: NOT consumed, NOT dropped, when another arm wins.
                res = &mut frame => break FrameEvent::Frame(res),
                _ = beat_check.tick() => {
                    todo!("unchanged heartbeat body — touches `heartbeat`/`health`, never `stream`");
                }
            }
        }
    }; // `frame` dropped here → the `&mut stream` borrow ends.

    match event {
        FrameEvent::Cancelled => {
            todo!("unchanged: mark_terminating + crate::shutdown::drain(stream, …) + return Ok(())");
        }
        FrameEvent::Frame(frame) => match frame.context("read replication frame")? {
            None => {
                tracing::info!("replication stream ended");
                return Ok(());
            }
            Some(frame) => {
                todo!("unchanged: the whole existing Some(frame) handler, verbatim");
            }
        },
    }
}
```

```rust
// `ReplicationStream` owns a live `TcpStream` after a Postgres handshake, so it cannot be built in
// a unit test; the compose suite covers the real socket. What IS unit-testable — and what actually
// regressed — is the *shape*: a pinned branch future keeps its partial progress when a sibling arm
// wins, and a recreated one throws it away.
use std::time::Duration;

/// Stands in for `ReplicationStream::next()`: it makes progress in steps and only completes after
/// `steps` of them, exactly like a frame read interleaved with feedback writes.
async fn stepwise(progress: &std::cell::Cell<u32>, steps: u32) {
    for _ in 0..steps {
        tokio::time::sleep(Duration::from_millis(10)).await;
        progress.set(progress.get() + 1);
    }
}

#[tokio::test(start_paused = true)]
async fn pinned_branch_survives_other_arm_firing() {
    let progress = std::cell::Cell::new(0);
    let fut = stepwise(&progress, 5);
    tokio::pin!(fut);
    let mut ticker = tokio::time::interval(Duration::from_millis(3));
    let mut interruptions = 0_u32;

        tokio::select! {
            () = &mut fut => break,
            _ = ticker.tick() => interruptions += 1,
```

## Hints & gotchas

- **The borrow is the whole difficulty.** `stream.next()` takes `&mut *stream` for as long as the
  future lives, and futures carry a drop obligation, so NLL will not shorten it — the borrow lasts
  to the end of the enclosing *scope*, not the last use. That is why the pinned future must live in
  an inner block whose value is a small `FrameEvent` enum. Trying to `drop(frame)` inside a
  `select!` arm will not compile.
- `tokio::pin!(frame)` **shadows** `frame` with a `Pin<&mut _>`. In the arm write `res = &mut frame`
  — `&mut Pin<&mut F>` is a `Future` because `Pin<&mut F>: Future + Unpin`.
- **Never poll a completed future again.** Once the `res = &mut frame` arm fires you `break` out of
  the inner loop, so it is polled exactly once after completion — which is why the `break` must be
  in the arm, not after the `select!`.
- Keep `biased;` and PR 14.1's arm order: `token.cancelled()` first, then `beat_check.tick()`, then
  the frame arm. Reordering the frame arm ahead of the tick would let a busy stream starve the
  heartbeat check, which also refreshes `health.set_degraded(...)`.
- The heartbeat arm body must stay `stream`-free. It touches `heartbeat`, `health` and
  `last_activity` only — all distinct `&mut` parameters, so borrowck is happy with the pin. If you
  find yourself needing `stream` there, the restructure is wrong.
- Doc sections use `##` inside the doc comment (`/// ## Cancel safety`), which is what makes the
  probe `grep '# Cancel safety'` match. Keep the heading text verbatim so the count is stable.
- `#[tokio::test(start_paused = true)]` needs tokio's `test-util`, which `pg-sink` already has as a
  dev-dependency (used by the reload lease tests). No new dependency, so `cargo deny` is unaffected.
- The test uses `std::cell::Cell` deliberately: the assertion is about a `!Send` single-task future,
  which is exactly the decode loop's situation. Do not reach for `Arc<AtomicU32>`.
- Tests are Go-style siblings, never inline `mod tests {}`. Keep the existing `#[path]` wiring in
  `consume.rs`; otherwise additions to the sibling file would be dead weight.
- `clippy::all` + `warnings` are `deny`; `unwrap`/`expect` are `deny` in production (re-allowed
  under `#[cfg(test)]` by `clippy.toml`). Do not touch `.sql` or the `.sqlx` offline cache — there
  is no Docker on this machine to regenerate it.
