# PR 14.1 — Make shutdown win every select! race with biased

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** loader,pg-sink

> **Phase:** 14 — Rust async/await · **Crates touched:** `loader`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 13.17 · **Unlocks:** PR 14.2

walrus has 10 production `tokio::select!` blocks and exactly **one** of them
(`crates/pg-sink/src/consume.rs:360`) declares `biased;`. The other nine race a shutdown/cancel arm
against a timer or an I/O arm under tokio's default **random** branch selection, so a cancelled
token can lose to `tick.tick()` for an unbounded number of iterations — `apply_loop.rs:32` can run a
whole poll + Phase-A + Phase-B + compaction cycle *after* SIGTERM, inside the same Kubernetes grace
budget the drain needs. After this merges, every `select!` whose arms include a cancellation branch
declares `biased;` with that branch first, so the drain is entered on the first poll after
cancellation, deterministically, every time — and the single block whose arms are genuinely
equivalent (the loader's signal-swallow loop) keeps random selection with a comment saying why.

## Why — learning objectives

- **`tokio::select!` branch selection** — random by default (so no branch starves), deterministic
  top-to-bottom under `biased;`; a `select!` never guarantees fairness either way.
- **walrus drain ordering** — SIGTERM must beat the poll tick so the grace budget is spent draining,
  not applying; a lost race is not a hang, it is silently spent budget.

**In scope**

- Add `biased;` as the first statement inside **eight** `tokio::select!` blocks:
  `loader/src/shutdown.rs:55`, `loader/src/lease.rs:43`, `loader/src/apply_loop.rs:32`,
  `pg-sink/src/shutdown.rs:110`, `pg-sink/src/reload.rs:80`, `pg-sink/src/reload.rs:269`,
  `pg-sink/src/reload.rs:281`, `pg-sink/src/consume.rs:62`.
- **Reorder arms in exactly two of them.** In both signal installers the cancellation arm is
  currently *last*: move `_ = child.cancelled() => {}` to the top so an already-cancelled token
  (e.g. a bootstrap failure) exits the task without logging a spurious "SIGTERM received".
  The other six already list the cancellation arm first — those get `biased;` and nothing else.
- `loader/src/shutdown.rs:64` (the signal-swallow loop): **do not** add `biased;`. Its two arms
  (`term.recv()` / `int.recv()`) are equivalent — both log "ignored, drain in progress" — so random
  selection is correct. Add a one-line comment saying exactly that, so the next reader (and the
  probe) knows the omission is deliberate.
- A new sibling test module `crates/loader/src/shutdown_test.rs` with one deterministic case proving
  the property: a pre-cancelled token plus an already-elapsed `interval` must take the cancel arm on
  every one of N iterations under `biased;` (unbiased, it would take it ~half the time).

- **No new `select!` blocks**, and no change to `consume.rs:359` (already `biased;`, already

```rust
// crates/loader/src/shutdown_test.rs — NEW FILE.
use std::time::Duration;
use tokio_util::sync::CancellationToken;

/// The invariant `biased;` buys: when BOTH arms are ready, the cancellation arm wins every time.
/// Without `biased;` this is a coin flip per iteration, which is exactly how a cancelled loader
/// can run a whole extra apply cycle inside the grace budget.
#[tokio::test(start_paused = true)]
async fn biased_select_prefers_cancellation() {
    let token = CancellationToken::new();
    token.cancel();
    let mut tick = tokio::time::interval(Duration::from_millis(1));
    tick.tick().await; // consume the immediate first tick
    tokio::time::advance(Duration::from_millis(50)).await; // the interval is now ready too

    let mut cancels = 0_u32;
    for _ in 0..100 {
        todo!("run the biased select and count which arm fires");
        tokio::select! {
            biased;
            () = token.cancelled() => cancels += 1,
            _ = tick.tick() => {}
        }
    }
    assert_eq!(cancels, 100, "biased select must always take the cancellation arm");
}
```

## Hints & gotchas

- `biased;` must be the **first token inside the braces**, before any arm, and it takes a trailing
  semicolon. Putting it after an arm is a compile error, not a silent no-op.
- **Starvation is the reason `biased;` is not the default.** It is safe at all eight of these sites
  because the first arm is `CancellationToken::cancelled()`, which is `Pending` until the token is
  cancelled and `Ready` forever after — it can never starve a later arm during normal operation.
  Do not reflexively add `biased;` to a `select!` whose first arm is a hot channel or socket.
- **`consume.rs:62` — keep the existing order after the cancel arm.** `token.cancelled()` is already
  first; leave `beat_check.tick()` ahead of `frame = stream.next()`. Promoting the frame arm would
  let a busy stream starve the heartbeat tick, which is also what refreshes
  `health.set_degraded(...)`.
- **`reload.rs:80` costs something, and that is accepted.** With `token.cancelled()` first, an
  export that finished in the same poll as a cancellation is reported `Cancelled`, not `Finished`.
  That is safe by design: the row stays `exporting` and PR 6.9's `adopt_and_resume` picks it up on
  the next start — see the comment at `reload.rs:270-275`. Say so in the PR body.
- `reload.rs:281` is a `select!` **nested inside** an arm of the one at `:269`. Both need `biased;`;
  they are separate blocks, and rustfmt will indent the inner one further.
- `crates/loader/src/shutdown.rs` has no test module today — the `#[cfg(test)] #[path = "…"]
  mod tests;` wiring is what makes the new sibling compile. Without it the file is dead weight and
  `cargo test -p loader` will not mention the test. Check the name appears in the output.
- Tests are Go-style siblings, never inline `mod tests {}` — 47 modules in the tree, zero inline.
- `#[tokio::test(start_paused = true)]` needs tokio's `test-util` feature. `pg-sink` already has it
  as a dev-dependency; **`loader` does not** — add
  `tokio = { workspace = true, features = ["test-util"] }` to `crates/loader/Cargo.toml`'s
  `[dev-dependencies]` (it already lists a dev-only `tokio` entry for `io-util`, so extend that
  feature list rather than adding a second key). No new crate enters the dependency graph, so
  `cargo deny` is unaffected.
- `clippy::all` + `warnings` are already `deny`; an unused import in the new test file fails CI.
  `unwrap`/`expect` are `deny` in production but re-allowed under `#[cfg(test)]` by `clippy.toml`.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine to
  regenerate it, and nothing here goes near SQL.
