# PR 22.7 — Prove and guard the humantime duration form on every config Duration field

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 22 — Rust serde · **Crates touched:** `common`, `loader`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 22.6 · **Unlocks:** PR 22.8

walrus already *applies* this rule: all **12** `Duration` config fields carry
`#[serde(with = "humantime_serde")]` — `common` 1/1 (`config.rs:29`), `loader` 4/4
(`config.rs:24/:27/:32/:41`), `pg-sink` 7/7 (`config.rs:37/:40/:43/:48/:63/:72/:81`) — and the
newtype alternative the rule endorses is used for `Lsn` (`lsn.rs:102-116`) and `UtcTimestamp`
(`sink_meta.rs:91-103`). What is missing is **proof**: `grep -rn 'humantime' crates/*/src/*_test.rs
crates/*/tests` returns **2 lines**, both in `crates/common/src/config_test.rs` (`:57`, `:62`), and
`crates/loader/src/config_test.rs` **does not exist at all**. `crates/pg-sink/src/config_test.rs`
builds `SinkConfig` structurally (`valid()` at `:3-17`) and never parses a document, so deleting any
of those 11 attributes leaves `cargo test --workspace` green — the failure surfaces when a pod
restarts and figment refuses `WALRUS_POLL_INTERVAL: "5s"`
(`deploy/k8s/base/configmap.yaml:53`). After this merges, every one of the 12 fields is parsed
from a humantime document in a sibling test, and each of the three config modules carries a
source-scan guard asserting `count(": Duration,") == count("humantime_serde")` — 1/1, 4/4, 7/7 —
so a new `Duration` field that forgets the attribute fails a **unit** test in seconds instead of a
compose run in minutes.

## Why — learning objectives

- **`#[serde(with = ...)]` module contract vs a newtype with its own impls** — `with` points serde
  at a module exposing `serialize<S>(&T, S)` + `deserialize<'de, D>(D) -> Result<T, _>`; it changes
  the *wire* form without changing the *field* type. A newtype (walrus's `Lsn`, `UtcTimestamp`) owns
  the impls instead and is the better trade once the form repeats — here it would churn public field
  types across three crates, so the attribute stays and a guard replaces the type-level enforcement.
- **A source-scanning `include_str!` guard as a cheap mechanical gate** — an attribute convention
  has no compiler representation, so the only way to make it non-optional is to read the source back
  at compile time and count. `include_str!` resolves relative to the file containing the macro, runs
  at build time, and costs nothing at runtime.

## Scope

**In scope**

1. **New sibling test module for the loader.** Create `crates/loader/src/config_test.rs` and add
   `#[cfg(test)] #[path = "config_test.rs"] mod tests;` at the bottom of
   `crates/loader/src/config.rs`, mirroring `crates/common/src/config.rs:137-139`.
2. **Parse proof for all 12 fields.** A document-parsing test per crate that drives the real
   `load()` inside a `figment::Jail` and asserts each `Duration` field against a **non-default**
   value:
   - `common` — already covered 1/1 by `humantime_durations_parse` (`config_test.rs:62`). Leave it
     alone; this crate's delta is the guard in item 3.
   - `loader` — 4 fields, new test.
   - `pg-sink` — 7 fields, new test.
3. **Attribute guard per config module.** In each of the three sibling test files, a test that
   `include_str!`s its own `config.rs` and asserts
   `src.matches(": Duration,").count() == src.matches("humantime_serde").count()`, plus the expected
   literal (1, 4, 7) so that *adding* a `Duration` field is also a deliberate act.
4. **Dev-dependency for `Jail`.** `figment`'s `Jail` lives behind its `test` feature. `common`
   already has `figment = { workspace = true, features = ["test"] }` under `[dev-dependencies]`
   (`crates/common/Cargo.toml:38-40`); add the same line to `crates/loader/Cargo.toml` and
   `crates/pg-sink/Cargo.toml`. This is a feature flip on a crate already in the graph, not a new
   dependency — but still run `cargo deny check`.

**Explicitly deferred** (do *not* build these here)

- **No `HumanDuration` newtype.** The rule's Key Point 4 says a newtype beats 12 repeated
  attributes. Declined *here*: it would change the public field type of every duration knob across
  `common`, `loader` and `pg-sink`, touching `heartbeat_config()` (`pg-sink/src/config.rs:188-193`),
  the lease/poll call sites in `loader`, and every `Default` impl — a wide refactor hidden inside a
  test-coverage PR. The guard in item 3 buys the same regression safety for three lines of test.
- **No change to the hand-written `Lsn` / `UtcTimestamp` (de)serializers.** Their wire forms are
  already covered by `lsn_test.rs` and `sink_meta_test.rs`.
- **No new `Duration` field, no default change, no bound change.** If a test needs a value the
  current `validate()` rejects, change the *test literal*, never `validate()`.
- **No CI step.** The guard is a unit test, per the walrus preference for unit-level probes.
- **No `.sql` / `.sqlx` edits.** Nothing here touches a query.

fn every_duration_field_carries_humantime() {

        attrs, fields,
        "{fields} `Duration` fields but {attrs} `humantime_serde` attributes: every duration knob \
         is a humantime string in deploy/k8s/base/configmap.yaml"

## Hints & gotchas

- **`include_str!` resolves relative to the file containing the macro**, not the crate root and not
  the module's logical parent. The guard lives in `config_test.rs`, which sits beside `config.rs`,
  so the bare `include_str!("config.rs")` is correct — `"src/config.rs"` is not.
- **Do not make the guard walk the filesystem.** `std::fs::read_to_string("src/config.rs")` happens
  to work because `cargo test` sets CWD to the crate root, but it is a runtime dependency on the
  layout for something the compiler can settle. `include_str!` also means a stale path fails to
  *build*, not to *run*.
- **Needle discipline.** `": Duration,"` deliberately requires the trailing comma so it matches
  struct fields only — `const MAX_DURATION: Duration =` (`pg-sink/src/config.rs:16`,
  `common/src/config.rs:16`) and `d: Duration)` (`pg-sink/src/config.rs:288`) are excluded. It would
  also miss an `Option<Duration>` or `Vec<Duration>` field; none exists today, and the hard-coded
  field count (1/4/7) is what forces a future author to revisit the guard.
- **`figment::Jail` is behind the `test` feature and takes a process-wide lock**, chdir-ing into a
  temp directory for the closure. Never call `LoaderConfig::load()` / `SinkConfig::load()` from a
  test outside a jail: it reads the real environment and will flake under a parallel test binary.
- **You cannot reuse `common`'s `in_jail`** — it is `#[cfg(test)]`-private to that crate. Copy the
  seven lines into each sibling file; do not add a test helper to `common`'s public API for them.
- **Keep the `#[allow(clippy::result_large_err)]` on the copied helper.** `figment::Error` is large
  and `Jail::expect_with` forces it into the closure's return type; without the allow, workspace
  `clippy::all = deny` fails the build. `unwrap`/`expect` are fine in tests (`clippy.toml` sets
  `allow-unwrap-in-tests` / `allow-expect-in-tests`) but stay denied in production.
- **Pick literals that clear `validate()`.** `pg-sink` bounds every listed duration to
  `0 < d <= 1h`, requires `heartbeat_idle_after < heartbeat_roundtrip_deadline`, and rejects
  `reload_lease_ttl < 15s`. A test that trips a bound proves nothing about serde.
- **`backfill_statement_timeout` is the trap.** Its default is `Duration::ZERO` and the ConfigMap
  sets `"0s"`, so asserting `"0s"` cannot distinguish "humantime parsed it" from "the container
  default supplied it". Assert a non-zero literal; `"0s"` is legal and stays legal.
- humantime accepts `"250ms"`, `"45s"`, `"30m"`, `"1h"` and compound forms like `"1m 30s"`. It does
  **not** accept a bare integer — `WALRUS_MAX_FILL: "5"` is an error, which is exactly why every
  ConfigMap value is quoted with a unit.
- **Attribute count, not attribute placement.** Counting `"humantime_serde"` occurrences catches a
  deletion but not a misplacement (attribute on the wrong field). The parse tests in item 2 are what
  cover placement — that is why both halves are required, not either one alone.
- Tests are **Go-style sibling files** here (`src/foo.rs` → `src/foo_test.rs` via
  `#[cfg(test)] #[path = "foo_test.rs"] mod tests;`), 47 modules and zero inline `mod tests {}`.
  Adding the loader's hook makes 48.
- The `.sqlx` offline cache **cannot be regenerated** — there is no Docker on this machine. Nothing
  here touches a query, so a `cargo sqlx prepare --check` failure means you edited something you
  should not have.
