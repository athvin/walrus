# PR 22.6 — Lock the scalar wire representation of every serde enum with an exhaustive-match test

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 22 — Rust serde · **Crates touched:** `common` · **Est. size:** M ·
> **Depends on:** PR 22.5 · **Unlocks:** PR 22.7

All four serde-carrying enums in walrus are **unit-only** — `Op` and `Kind`
(`crates/common/src/sink_meta.rs:19`/`:35`), `ReplicaIdentity` (`crates/common/src/pg_shape.rs:16`)
and `Tier` (`crates/common/src/type_descriptor.rs:14`) — so serde's four tagging strategies all
collapse to "a JSON scalar" and the default external tagging is already the right answer. The one
data-carrying enum anywhere near the wire path, `TupleValue`, is deliberately **not** `Serialize`
(documented at `pg_shape.rs:99-100`). Nothing, however, *keeps* it that way: the day someone adds a
struct or tuple variant to `Op`, external tagging silently turns `"u"` into `{"u":{…}}` and the
loader's `json_extract_string(meta, '$.op')` starts returning NULL for every row — with no compile
error and no failing test. Coverage is also uneven: `Op`, `Kind` and `Tier` have wire-form tests
(`sink_meta_test.rs:21`, `:30`; `type_descriptor_test.rs:22`) while
`crates/common/src/pg_shape_test.rs` contains the string `serde` zero times on `main`. This PR turns
"they happen to be scalars" into a gate.

## Why — learning objectives

- **serde's four enum representations** — externally tagged (default), internally tagged
  (`tag = "…"`), adjacently tagged (`tag`/`content`), untagged — and *why a unit-only enum serializes
  as a bare scalar under all of them*. The representation only becomes visible when a variant carries
  data.
- **A compile-fail regression gate** — expressing the expected wire value through an **exhaustive
  `match` with no `_` arm** (the same convention `common::Error::is_terminal` uses) so that adding a
  variant, or giving an existing one a payload, is a compile error rather than a silent contract
  change.

**In scope**

- A new conformance test, `crates/common/tests/enum_wire_form.rs` — the walrus home for
  golden-vector/conformance suites — containing:
  - one `fn <enum>_wire(v: Enum) -> serde_json::Value` per enum, whose body is an **exhaustive match
    with no `_` arm** returning the expected scalar;
  - one shared `assert_scalar_wire` helper asserting the serialized value equals the expected scalar,
    **is** a `Value::String` or `Value::Number` (never an object or array), and round-trips back to
    the same variant;
  - four tests driving every variant of `Op` (4), `Kind` (3), `ReplicaIdentity` (4) and `Tier` (3)
    through it — 14 variants total.
- A **tagging guard** in the same file: `include_str!` the three serde-bearing modules
  (`../src/sink_meta.rs`, `../src/pg_shape.rs`, `../src/type_descriptor.rs`) and assert zero
  occurrences of `serde(tag`, `serde(content` and `serde(untagged`, so a future internal/adjacent/
  untagged attribute fails a test instead of quietly reshaping the document.
- A one-line comment above each of the four enums pointing at
  `crates/common/tests/enum_wire_form.rs`, so the gate is discoverable from the type.

**Explicitly deferred** (do *not* build these here)

- **No internal, adjacent or untagged tagging is introduced anywhere.** No data-carrying enum is
  serialized in walrus, so there is nothing for those strategies to fix. `TupleValue` stays
  **non-`Serialize`** — do not add a derive to it "so the test can cover it".
- **The `#[sqlx(rename_all)]` enums in `control` are out of scope.** `ReloadFlavor` and `ReloadStatus`
  (`reload.rs:27`/`:58`) are a *SQL* contract with their own `CHECK` constraints, and their drift
  guard already exists at `reload_test.rs:5`.
- No `#[non_exhaustive]` on any of these four enums. PR 13.16 deliberately left the data enums
  exhaustive precisely so out-of-crate matches like this one compile; do not undo that.
- No change to any enum's variants, wire strings, or attributes. This PR adds a gate; it changes no
  behaviour and must produce an empty diff on every `.json`/`.sql`/`.sqlx` artifact.

## Skeleton

```rust
// crates/common/tests/enum_wire_form.rs — new integration (conformance) test.
//
// Every serde-carrying enum in `common` is unit-only, so its JSON form is a bare scalar under ALL
// FOUR of serde's tagging strategies. This file freezes that: each expected value comes from an
// EXHAUSTIVE match with no `_` arm, so adding a variant — or giving one a payload — is a COMPILE
// ERROR here before it can become a silent wire-format change in production.

use common::{Kind, Op, ReplicaIdentity, Tier};
use serde::{de::DeserializeOwned, Serialize};
use serde_json::{json, Value};

/// Serialize, compare against the golden scalar, prove it is a scalar, and round-trip.
fn assert_scalar_wire<T>(value: T, expected: &Value)
where
    T: Serialize + DeserializeOwned + PartialEq + std::fmt::Debug + Copy,
{
    let v = serde_json::to_value(value).expect("serializes");
    assert_eq!(&v, expected, "wire form drifted for {value:?}");
    assert!(
        v.is_string() || v.is_number(),
        "must stay a JSON scalar — an object/array here means a variant gained a payload: {v}"
    );
    let back: T = serde_json::from_value(v).expect("round-trips");
    assert_eq!(back, value);
}

/// EXHAUSTIVE — no `_` arm. Keys documented in architecture.md §1.4.
fn op_wire(op: Op) -> Value {
    match op {
        Op::Insert => json!("i"),
        Op::Update => json!("u"),
        Op::Delete => json!("d"),
        Op::Truncate => json!("t"),
    }
}

#[test]
fn op_is_a_single_char_scalar() {
    for op in [Op::Insert, Op::Update, Op::Delete, Op::Truncate] {
        assert_scalar_wire(op, &op_wire(op));
    }
}

// … kind_wire (snapshot|stream|reload), replica_identity_wire (default|nothing|full|index —
//    lowercase after PR 22.4), tier_wire (json!(1)|json!(2)|json!(3)) follow the same shape …

fn tier_wire(t: Tier) -> Value {
    match t {
        Tier::One => todo!("json!(1) — a JSON NUMBER, not the string \"1\""),
        Tier::Two => todo!(),
        Tier::Three => todo!(),
    }
}

/// The serde-bearing modules, scanned as source text.
const SERDE_MODULES: [(&str, &str); 3] = [
    ("sink_meta.rs", include_str!("../src/sink_meta.rs")),
    ("pg_shape.rs", include_str!("../src/pg_shape.rs")),
    ("type_descriptor.rs", include_str!("../src/type_descriptor.rs")),
];

#[test]
fn no_enum_tagging_attribute_is_introduced() {
    // Internal/adjacent/untagged tagging would reshape a scalar into an object. walrus has no
    // data-carrying serde enum, so the correct count is zero — forever, until a PR argues otherwise.
    for (module, src) in SERDE_MODULES {
        for attr in ["serde(tag", "serde(content", "serde(untagged"] {
            todo!("assert !src.contains(attr), \"{module} introduced {attr}\"");
        }
    }
}
```

## Hints & gotchas

- **This is archetype B: the code is already right, the *gate* is what is missing.** Resist the urge
  to "improve" a representation while you are here. If a wire string looks wrong to you, that is a
  separate PR with a rollout plan (see PR 22.4 for what that costs).
- **`crates/common/tests/` does not exist yet — creating it is expected.** Integration tests are
  separate crates that link against the package's `[dependencies]` *and* `[dev-dependencies]`, so
  `serde`, `serde_json` and `common`'s own public API are all available with no `Cargo.toml` change.
  Import through the crate name (`use common::{Kind, Op, …}`), not `crate::`.
- **`include_str!` paths in an integration test are relative to that file**, hence `../src/…`. The
  guard reads source text, so it also fails if someone adds a tagging attribute inside a comment —
  that is acceptable noise for a three-line gate, and the failure message names the module.
- **The exhaustive match is the actual gate; the assertion is just the message.** Write the expected
  value inside a `match` on the variant, never as a parallel `&[(&str, Value)]` table — a table does
  not break when a variant is added.
- **`#[non_exhaustive]` would break this file.** The attribute is a no-op inside the defining crate
  but forces a `_` arm on *out-of-crate* matches, and an integration test is a different crate.
  PR 13.16 explicitly left `Op`, `Kind`, `TupleValue`, `Tier` and `ReplicaIdentity` exhaustive for
  this reason — if you find yourself adding `_ =>` to satisfy the compiler, something upstream
  regressed.
- **All four enums are `Copy`**, which is why the helper can take `T: Copy` by value and still compare
  against the original after the round trip. If a future enum is not `Copy`, take `&T` and clone
  inside the helper rather than dropping the round-trip assertion.
- **`Tier` numbers vs strings.** `serde_json::to_value(Tier::Two)` must equal `json!(2)`;
  `json!("2")` would pass a naive `assert_eq!(v.to_string(), "2")` — compare `Value`s, not strings.
- Unit tests are Go-style sibling files (`foo_test.rs`); **conformance/golden-vector suites live in
  `tests/`** (`pg-to-arrow/tests/conformance.rs`, `pg-sink/tests/pgoutput_vectors.rs` are the
  precedents). This file is the latter, so it belongs in `tests/`, not as a fifth `*_test.rs`.
- `unwrap`/`expect` are denied in production and re-allowed in tests by `clippy.toml`; `clippy::all`
  and `warnings` are already `deny` workspace-wide. Do not touch any `.sql` file or the committed
  `.sqlx` offline cache (no Docker locally), and add no dependency — anything new must clear
  `cargo deny`.
