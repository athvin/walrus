# PR 22.4 — Give `ReplicaIdentity` an explicit lowercase wire form with legacy aliases

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 22 — Rust serde · **Crates touched:** `common` · **Est. size:** M ·
> **Depends on:** PR 22.3 · **Unlocks:** PR 22.5

There is exactly **one** serde `rename_all` in the whole tree — `Kind` at
`crates/common/src/sink_meta.rs:34` (the other two `rename_all` hits are `#[sqlx(…)]` on
`control/src/reload.rs:27` and `:58`, a different attribute entirely). Three of the four
serde-carrying enums have a *deliberate* wire form: `Op` uses per-variant `i`/`u`/`d`/`t`, `Kind` is
lowercase, `Tier` is a hand-written integer. `ReplicaIdentity` (`crates/common/src/pg_shape.rs:15-25`)
has none — `grep -c 'serde(' crates/common/src/pg_shape.rs` is `0` — so Rust's PascalCase
(`"Default"`, `"Nothing"`, `"Full"`, `"Index"`) leaks by accident into the `schema_registry.columns`
jsonb the sink persists at `pg-sink/src/consume.rs:644` and seven call sites read back. No test and no
doc asserts that string today, which means it is a wire contract nobody has agreed to. This PR makes
it explicit and lowercase, and adds a per-variant `alias` so every row already in control Postgres
keeps parsing forever.

## Why — learning objectives

- **Container-level `rename_all` vs per-variant `rename`, plus `alias`** — `rename_all` sets both
  directions for every variant, a per-variant `rename` overrides it, and `alias` adds an *additional
  accepted* name on the **read side only**. That asymmetry is exactly what backward compatibility
  needs.
- **Evolving a wire form that is already persisted** — how to change a string that lives in a
  control-plane table without a migration: make readers accept both dialects first, then let writers
  start emitting the new one.

## Read first

- [`serde-rename-all`](../../../.claude/skills/rust-skills/rules/serde-rename-all.md) — take the case

  says nothing about `alias`; that is the walrus-specific addition this ticket requires.
- `crates/common/src/pg_shape.rs:14-41` — `ReplicaIdentity`, its four variants, and the byte-level

- `crates/common/src/pg_shape.rs:71-79` — `PgRelation`, whose `replica_identity` field is the only
  place the enum reaches JSON.
- `crates/common/src/sink_meta.rs:17-39` — `Op`'s four per-variant `#[serde(rename)]`s and `Kind`'s
  `rename_all = "lowercase"`: the two precedents this PR follows and extends.
- `crates/pg-sink/src/consume.rs:637-650` — `on_relation`, where
  `serde_json::to_value(&cached.relation)` becomes `RegistryRow.columns` and is upserted into

- The seven readers: `crates/loader/src/bootstrap.rs:61` and `:105`,
  `crates/loader/src/phase_a.rs:316`, `crates/loader/src/phase_b.rs:23`,

  `let rel: PgRelation = serde_json::from_value(row.columns)`.
- `crates/common/src/pg_shape_test.rs` — no test mentions serde today; this is where the new
  round-trip case goes.

**Conflict to resolve explicitly (do not apply the rule blindly):** this changes a form that is
**already persisted** in control Postgres. `schema_registry.columns` is jsonb and there is no
migration — existing rows keep their PascalCase strings until the relation is re-registered, and the
loader must keep reading them. Therefore:

1. **The per-variant `#[serde(alias = "…")]` for the legacy PascalCase is MANDATORY.** Shipping
   `rename_all` without the aliases turns every pre-existing registry row into an unparseable
   document and stalls the loader at bootstrap.
2. **State the rollout order in the PR body and in the code comment: readers before writers.** A new
   reader accepts both dialects; an old reader rejects lowercase. So the `walrus-loader` Deployment
   must be rolled **before** `walrus-pg-sink`. (`pg-sink` is both a writer and a reader of its own
   rows, so it is safe either way once it carries the alias.)

**In scope**

- `crates/common/src/pg_shape.rs`: `#[serde(rename_all = "lowercase")]` on `ReplicaIdentity`, plus
  `#[serde(alias = "Default")]` / `"Nothing"` / `"Full"` / `"Index"` on the corresponding variants.
- A doc comment on the enum recording (a) that the JSON string is a persisted control-plane contract,
  (b) that the aliases exist for pre-PR rows, and (c) the reader-before-writer rollout order.
- `crates/common/src/pg_shape_test.rs`: a new
  `replica_identity_wire_form_is_lowercase_and_accepts_legacy` test that asserts each variant
  serializes to its lowercase string, that each *lowercase* string deserializes back, and that each
  *legacy PascalCase* string still deserializes to the same variant.
- A round-trip case at the `PgRelation` level, so the assertion covers the document actually stored
  in `schema_registry.columns`, not just the bare enum.

**Explicitly deferred** (do *not* build these here)

- **`Op`'s four per-variant `#[serde(rename)]` attributes stay exactly as they are.** The
  `i`/`u`/`d`/`t` chars are documented in `architecture.md` §1.4 and are **not derivable from any
  `rename_all` case** — "rewriting them as `rename_all`" is impossible, and touching them would
  break the loader's `json_extract_string(meta, '$.op')`.
- **No struct field is renamed.** Every serde struct field in `common` already matches the documented
  snake_case JSON key 1:1, so a `rename_all = "snake_case"` would be a no-op that only adds risk.
- No change to `Kind`, `Tier`, or the two `#[sqlx(rename_all)]` enums in `control` (`ReloadFlavor`,
  `ReloadStatus`) — those are SQL `CHECK`-constrained and already guarded by
  `crates/control/src/reload_test.rs:5`.
- **No data migration and no `.sql` change.** Do not write an `UPDATE schema_registry SET columns =
  …` — the alias is the migration. `.sql` files and the `.sqlx` offline cache are frozen (no Docker
  locally).
- No change to the pgoutput byte parse. `'d'`/`'n'`/`'f'`/`'i'` is a *different* wire form and stays
  byte-based.

## Skeleton

```rust
// crates/common/src/pg_shape.rs — replacing the bare derive at :15-25.

/// Postgres `relreplident` — governs which old-image columns Update/Delete carry (proto §6).
///
/// **Two distinct wire forms.** The pgoutput byte (`'d'`/`'n'`/`'f'`/`'i'`) is handled by the
/// byte parse below and is unrelated to serde. The *serde* form is the string persisted inside
/// `schema_registry.columns` (jsonb), written once by `pg-sink::consume::on_relation` and read back
/// by seven call sites in `loader` and `pg-sink`.
///
/// Rows written before this PR carry Rust's accidental PascalCase; the per-variant `alias` keeps
/// them parseable forever, so no migration is needed. **Rollout order: upgrade the reader
/// (`walrus-loader`) before the writer (`walrus-pg-sink`)** — a new reader accepts both dialects, an
/// old reader rejects lowercase.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum ReplicaIdentity {
    /// `'d'` — the default: Update/Delete carry key columns only (`'K'`).
    #[serde(alias = "Default")]
    Default,
    /// `'n'` — nothing: Update/Delete carry no old image (unusable as a key source).
    #[serde(alias = "Nothing")]
    Nothing,
    /// `'f'` — full: Update/Delete carry the whole old row (`'O'`).
    #[serde(alias = "Full")]
    Full,
    /// `'i'` — a nominated unique index supplies the identity.
    #[serde(alias = "Index")]
    Index,
}
```

        "schema": "public",
        "name": "orders",
        "replica_identity": "Default",

## Hints & gotchas

- **`alias` is read-side only.** It adds an accepted input name; it never changes what serde *emits*.
  That is precisely why the pair (`rename_all` + `alias`) gives a one-way, migration-free cutover.
  Do not reach for `#[serde(rename)]` on a variant here — it would override `rename_all` and change
  the output.
- **Two wire forms, one type.** `ReplicaIdentity` is parsed from a pgoutput *byte* and serialized to a
  *string*. PR 20.1 replaced `ReplicaIdentity::from_wire` with `impl TryFrom<u8>`; whichever spelling
  is in the tree when you start, it is unrelated to serde. Do **not** "unify" them by making the JSON
  form the single chars — that is a different, larger contract change and it is not this ticket.
- **Rollout order is a deliverable, not a footnote.** Write it in the PR body: `walrus-loader` first,
  `walrus-pg-sink` second. If both roll simultaneously, an in-flight old loader can see a lowercase
  row and fail its bootstrap `serde_json::from_value` at `bootstrap.rs:61`.
- **`schema_registry` rows are never rewritten.** A relation's `columns` document is written once per
  `schema_version` at `on_relation`; historical versions keep PascalCase indefinitely. That is fine —
  the alias is permanent, not a deprecation window. Say so in the comment so nobody deletes it.
- **`"lowercase"` is not `"snake_case"`.** All four variants are single words here, so the two
  coincide — but pick `lowercase` to match `Kind`'s existing spelling and keep the grep uniform.
- **Do not add `deny_unknown_fields` to `PgRelation`/`PgColumn` while you are in the file.** PR 22.1
  deliberately scoped that guard to config; wire documents stay lenient.
- Tests are **sibling files** (`pg_shape_test.rs` via `#[cfg(test)] #[path = …] mod tests;`). `use
  super::*` gives you `PgRelation`, `PgColumn`, `ReplicaIdentity` and `TupleValue`; `serde_json` is a
  regular dependency of `common`, so it is in scope without a dev-dependency.
- `unwrap`/`expect` are denied in production and re-allowed in tests by `clippy.toml`; `clippy::all`
  and `warnings` are already `deny` workspace-wide. Do not touch any `.sql` file or the `.sqlx`
  offline cache (no Docker locally), and add no dependency — anything new must clear `cargo deny`.
