# PR 22.8 — Record why serde flatten is rejected and guard the wire structs against it

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** evidence
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 22 — Rust serde · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 22.7 · **Unlocks:** PR 23.1

`#[serde(flatten)]` appears **0 times** in walrus, and its one natural site is real: `SinkConfig`
(`pg-sink/src/config.rs`) and `LoaderConfig` (`loader/src/config.rs`) each re-declare the same
**five** fields as `CommonConfig` (`common/src/config.rs`) — `control_db_url`, `object_store`,
`telemetry`, `startup_deadline`, and `instance`. The tempting refactor is technically supported,
including with walrus's strict unknown-key policy. The pinned `serde_derive` 1.0.228 does **not**
emit a compile error for a flattened field in a `deny_unknown_fields` container: it buffers keys,
lets the nested struct claim its recognized fields, and has the outer container reject anything
left over. An executable fixture in this PR records that behavior so the evidence cannot regress
into the old, false incompatibility claim.

Walrus still declines the production refactor here. Flattening `CommonConfig` would replace five
public fields with a nested Rust field across both binaries, their constructors and tests, and it
would move responsibility for defaults, validation, and service-specific error mapping across
three config types. That is a broad API/validation migration for declaration de-duplication, not a
safe Serde-attribute cleanup. `SinkMeta` is not a performance-based counterexample either: the hot
path serializes its existing `MetaConst`/`MetaRow` projections, while the loader extracts JSON keys
in SQL rather than deserializing `SinkMeta`. This archetype-**D** ticket records those actual facts,
keeps production behavior unchanged, and adds a source guard over the five audited, struct-bearing
candidate modules in `common` so a future flatten proposal there has to reopen the decision
deliberately. (`ids.rs` and `lsn.rs` also implement Serde, but their scalar/newtype wire forms are
not flatten candidates and remain outside this policy guard.)

## Why — learning objectives

- **Verify dependency behavior from the pinned source, not a rule summary** — the local rule says
  flatten and `deny_unknown_fields` are incompatible, but `serde_derive` 1.0.228 explicitly
  reconciles them. Learn the generated control flow: direct outer fields are consumed first,
  flattened structs claim only recognized buffered keys, and the outer strict container errors on
  leftovers.
- **Separate wire compatibility from Rust API and validation ownership** — flatten would keep the
  flat file/env key shape, but it would make `common: CommonConfig` part of both service structs and
  force coordinated changes to field access, defaults, constructors, validation, and error mapping.
- **Write an evidence-backed ADR that declines a viable technique without inventing a blocker** —
  the note must distinguish “supported but not worth this migration today” from “cannot compile,”
  and name a concrete condition that would reopen the choice.

## Read first

- [`serde-flatten`](../../../.claude/skills/rust-skills/rules/serde-flatten.md) — read the whole rule,
  but treat its `deny_unknown_fields` caveat as the claim under audit, not as proof. Its buffering
  caveat is real for deserialization; applicability still depends on walrus's actual call paths.
- `Cargo.lock` entries for `serde`, `serde_core`, and `serde_derive` — all are pinned at **1.0.228**.
- The fetched `serde_derive-1.0.228/src/internals/check.rs:99-136` — `check_flatten` rejects tuple
  and newtype structs only; it contains no `deny_unknown_fields` rejection.
- The fetched `serde_derive-1.0.228/src/de/struct_.rs:224-230,276-285,327-360` — flattened input is
  collected, passed through `FlatMapDeserializer`, and then, when the outer container denies unknown
  fields, any unclaimed entry becomes an `unknown field` error.
- The fetched `serde-1.0.228/src/private/de.rs:3260-3274,3387-3446` — `FlatStructAccess` offers a
  flattened struct only the keys in its declared field list and leaves all other buffered entries
  for the outer check. Cite these crate/version/source locations in the note, never the local Cargo
  registry's machine-specific absolute path.
- `crates/common/src/config.rs` — `CommonConfig`, its five shared fields, defaults, `load`, and
  `validate`; also `ObjectStoreConfig`. Both config containers deny unknown fields.
- `crates/loader/src/config.rs` and `crates/pg-sink/src/config.rs` — the two copies, their public
  direct-field APIs, distinct `Default` implementations, service validators, and different error
  types. These are the real migration surface.
- `crates/common/src/config_test.rs::unknown_key_is_rejected` and both service `config_test.rs`
  siblings — existing proof that typoed config remains terminal, plus the constructors/default
  assertions a nested `common` field would have to migrate.
- `deploy/k8s/base/configmap.yaml:1-5` — the operator-facing strict-key contract. Flatten need not
  break this contract when the **outer** service config keeps `deny_unknown_fields`; the evidence
  fixture must prove that exact point.
- `crates/common/src/sink_meta.rs:179-315` and `crates/pg-to-arrow/src/batch.rs::append_meta` — the
  stable flat wire contract and the hand-maintained `MetaConst`/`MetaRow` split used by the hot
  serialization path. There is no nested `SinkMeta` component waiting to be exposed.
- `crates/loader/sql/duckdb/templates/append_parquet.sql` — production loader code extracts named
  JSON keys; it does not deserialize `SinkMeta` through Serde.
- `docs/architecture.md` §1.4 and `docs/benchmarks.md` “The meta-JSON cost (isolated) — the
  headline” plus “PR 5.7 — sink hot path” — the ≈576 ns/row number motivated split
  **serialization**. It is context, not evidence that flatten's deserialization buffering would
  regress the current hot path.
- `docs/implementation/notes/duckdb-lts-bump.md` — the house style: expected premise, verified
  reality, evidence, decision, and a go-forward clock.

## Scope

**Baseline precondition.** Before editing, verify all three Serde crates are pinned at 1.0.228;
the five named `common` modules contain no flatten attribute; `CommonConfig`, `LoaderConfig`, and
`SinkConfig` still expose the five shared fields directly; all five config containers
(`CommonConfig`, `ObjectStoreConfig`, `TelemetryConfig`, `LoaderConfig`, `SinkConfig`) still carry
`deny_unknown_fields`; the production loader still extracts sink-meta keys in SQL; and
`crates/common/src/lib_test.rs` does not exist. Inspect the pinned derive/runtime source above and
record the supported control flow before editing. Run the full **Verification commands** block
after implementation. The named symbols and allowed paths below are the complete task boundary.

**Baseline mismatch.** A different pinned Serde version, changed flatten count, missing direct
shared field, changed strict-container set, production `SinkMeta` deserialization path, existing
crate-wide guard, or other behavior-changing site is a task-contract mismatch: **STOP and request
re-authoring before editing.** A mismatch never licenses reviving the compile-error claim.

**In scope**

1. **The ADR** — `docs/implementation/notes/rust-skills/serde-flatten.md`, with file/source
   citations, covering: the rule's claim; what pinned Serde actually generates; the executable
   evidence fixture; the viable config candidate; the flat wire/env and strict-unknown behavior it
   can preserve; the Rust API, default, validation, and error-ownership migration walrus declines;
   why `SinkMeta` is not supported by the benchmark argument; what walrus keeps today; and explicit
   re-open conditions.
2. **The source guard and evidence fixture** — new `crates/common/src/lib_test.rs`, hooked from
   `lib.rs`. It scans the five audited struct-bearing candidate modules — `config.rs`,
   `telemetry.rs`, `sink_meta.rs`, `pg_shape.rs`, `type_descriptor.rs` — and rejects flatten syntax
   after removing whitespace, naming the offending module. `ids.rs` and `lsn.rs` are intentionally
   excluded because their scalar/newtype representations cannot use struct flattening. A synthetic
   source string proves the guard bites.
3. **Pinned-behavior evidence in the same test file** — small local inner/outer structs, both with
   `deny_unknown_fields`, with the inner field flattened. One test proves known flat keys compile
   and deserialize into the right owners; the same test proves an extra key is still rejected.
   The fixture is test-only and is deliberately excluded from the five production-module scan.
4. **A required decision pointer** on `CommonConfig` sending readers to the ADR. A guard assertion
   requires the note path in `config.rs`; this is the tests-first red seam and the only non-test
   crate edit beyond the `#[cfg(test)]` hook.

**Explicitly deferred** (do *not* build these here)

- **No config de-duplication in production.** Do not add `common: CommonConfig`, accessors,
  `Deref`, a macro, or another nesting/rename scheme. Do not change any file/env key or either
  ConfigMap.
- **No validation/default/error refactor.** Do not delegate service validation to
  `CommonConfig::validate`, translate its error, or alter any shipped default or terminal-error
  classification. Those decisions belong to a coordinated config migration if the ADR reopens.
- **No `SinkMeta` restructuring and no benchmark claim.** Do not add nested batch/row structs to
  its public representation, alter `MetaConst`/`MetaRow`, or claim the ≈576 ns/row serialization
  measurement proves a flatten deserialization regression.
- **No blanket edit to the curriculum rule.** This PR records the verified behavior of walrus's
  pin and guards walrus's decision; changing the shared rule requires its own rule audit.
- **No CI grep step, no `.sql` / `.sqlx` edits, and no new dependency.** The existing
  `serde_json` dependency is sufficient for the test fixture.

**Conflict to resolve explicitly — do NOT apply this rule in production.** The rule's blanket
incompatibility statement is false for the pinned stack. Do not manufacture a compile-fail fixture
or delete `deny_unknown_fields`. In Serde 1.0.228 the outer container buffers unmatched keys, the
flattened struct claims its declared subset, and outer `deny_unknown_fields` rejects leftovers.
That makes a config refactor viable, but not small: the nested Rust representation and ownership of
defaults/validation/errors would change across `common`, `loader`, and `pg-sink`. The deliverable is
the truthful decision record plus test-only evidence and a source guard — no production attribute.

```rust
// crates/common/src/lib_test.rs — NEW
//! Crate-wide serde policy guards and dependency-behavior evidence.

use serde::Deserialize;

const SERDE_MODULES: [(&str, &str); 5] = [
    ("config.rs", include_str!("config.rs")),
    ("telemetry.rs", include_str!("telemetry.rs")),
    ("sink_meta.rs", include_str!("sink_meta.rs")),
    ("pg_shape.rs", include_str!("pg_shape.rs")),
    ("type_descriptor.rs", include_str!("type_descriptor.rs")),
];

fn flatten_violation(name: &str, src: &str) -> Option<String> {
    // Removing whitespace catches standalone and combined attributes regardless of formatting.
    let compact: String = src.chars().filter(|ch| !ch.is_whitespace()).collect();
    let starts_attribute = compact.contains(concat!("serde(", "flatten"));
    let later_argument = compact.contains(concat!(",", "flatten"));
    (starts_attribute || later_argument)
        .then(|| format!("{name}: serde flatten needs the PR 22.8 decision reopened"))
}

#[test]
fn no_serde_flatten_in_common_wire_and_config_modules() {
    for (name, src) in SERDE_MODULES {
        assert_eq!(flatten_violation(name, src), None, "{name}");
    }
}

#[test]
fn no_serde_flatten_source_guard_rejects_a_combined_fixture() {
    let fixture = concat!("#[serde(default,", " flatten)] struct Candidate;");
    assert_eq!(
        flatten_violation("fixture/flatten.rs", fixture).as_deref(),
        Some("fixture/flatten.rs: serde flatten needs the PR 22.8 decision reopened")
    );
}

#[derive(Debug, Default, Deserialize)]
#[serde(deny_unknown_fields, default)]
struct StrictCommonFixture {
    shared: String,
}

#[derive(Debug, Default, Deserialize)]
#[serde(deny_unknown_fields, default)]
struct StrictServiceFixture {
    service_only: bool,
    #[serde(flatten)]
    common: StrictCommonFixture,
}

#[test]
fn no_serde_flatten_evidence_fixture_preserves_strict_unknown_keys() {
    let parsed: StrictServiceFixture =
        serde_json::from_str(r#"{"shared":"ok","service_only":true}"#).unwrap();
    assert_eq!(parsed.common.shared, "ok");
    assert!(parsed.service_only);
    assert!(serde_json::from_str::<StrictServiceFixture>(
        r#"{"shared":"ok","service_only":true,"nonsense":1}"#
    )
    .is_err());
}

#[test]
fn no_serde_flatten_decision_is_linked_from_the_natural_site() {
    assert!(include_str!("config.rs")
        .contains("docs/implementation/notes/rust-skills/serde-flatten.md"));
}
```

## Hints & gotchas

- **Do not write the old compile-fail fixture.** On Serde 1.0.228 it compiles. The outer derive's
  leftover-key check is explicit source support, not an accidental acceptance; the runtime fixture
  makes the strict behavior observable.
- **Outer strictness owns composite unknown keys.** `FlatStructAccess` offers the nested struct only
  recognized names. An unknown composite key survives for the outer container to reject, so keep
  `deny_unknown_fields` on the outer service fixture. The inner attribute still governs standalone
  `CommonConfig` deserialization.
- **The fixture's literal attribute is intentional and test-only.** Do not claim a repo-wide textual
  count of 0 after this PR. The enforceable invariant is 0 across the five explicitly scanned
  production modules; `lib_test.rs` is excluded because it contains the executable positive
  evidence.
- **Normalize whitespace before checking source.** Testing `serde(flatten` and `,flatten` against a
  compacted string catches `#[serde( flatten)]`, `#[serde(default, flatten)]`, and multiline forms.
  Assemble the synthetic source needle with `concat!` so it does not add a second literal attribute.
- **Keep the decision honest.** Flatten preserves the flat external key shape here. The cost is the
  nested Rust API and the coordinated ownership migration for defaults, validation, and errors; do
  not imply operators would necessarily see renamed `WALRUS_*` keys.
- **Keep the benchmark in its lane.** The ≈576 ns/row result measures full per-row serialization
  before PR 5.7's split. The loader's production SQL key extraction is not Serde deserialization,
  so no current hot-path regression has been measured for flatten.
- Unit tests are Go-style sibling files (`src/foo.rs` → `src/foo_test.rs` via
  `#[cfg(test)] #[path = "foo_test.rs"] mod tests;`). `lib.rs` → `lib_test.rs` follows the same
  convention; do not create a `tests/` integration target for this crate-wide guard.
- `unwrap`/`expect` are re-allowed in tests by `clippy.toml` but remain denied in production. Read
  both fixture fields so `#![deny(warnings)]` does not turn dead-code evidence into a failure.
- The `.sqlx` offline cache cannot be regenerated without the control stack. Nothing in this PR
  changes a query.
