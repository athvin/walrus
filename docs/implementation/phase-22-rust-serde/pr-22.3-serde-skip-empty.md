# PR 22.3 — Drop the empty `unchanged_toast` array from every row's sink-meta JSON

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 22 — Rust serde · **Crates touched:** `common` · **Est. size:** M ·
> **Depends on:** PR 22.2 · **Unlocks:** PR 22.4

`skip_serializing_if` and `serde(skip)` appear **zero** times anywhere in the repo. Meanwhile all five
production `SinkMeta` construction sites build an *empty* `unchanged_toast`
(`pg-sink/src/consume.rs:552`, `stream_txn.rs:264`, `stream_txn.rs:414`, `snapshot.rs:230`,
`reload_export.rs:459`) — unchanged-TOAST placeholders are the rare case, not the common one. So today
every single Parquet row embeds a dead `"unchanged_toast":[],` — 21 bytes of nothing on the path that
`sink_meta.rs:144` measures at **≈576 ns/row and ~91 % of `append_row`**. The read side already
tolerates the key's absence: the loader's transform reads it as
`COALESCE(json_extract_string(meta, '$.unchanged_toast'), '[]')`
(`crates/loader/src/transform.rs:98`). This PR pairs `skip_serializing_if` with the
`#[serde(default)]` PR 22.2 just added, so the key is emitted only when it carries information.

## Why — learning objectives

- **`skip_serializing_if` predicates** — any path resolving to `fn(&T) -> bool`, and *why it must be
  paired with `#[serde(default)]`*: an omitted key has to deserialize back to the same value, or you
  have built a document that your own reader rejects.
- **Keeping a hot per-row wire document lean** — meta serialization dominates the batcher, so the
  cheapest byte is the one never written. This is a measured optimisation on a measured hot path, not
  a guess.

## Scope

**Conflict to resolve explicitly (do not apply the rule blindly):** skipping a key on the way out is
only safe because **PR 22.2 already made the same field default on the way in**. An omitted key must
still deserialize, or the sink writes documents its own loader (and its own round-trip tests) cannot
read. **This PR must land after 22.2** — if `grep -c 'serde(default' crates/common/src/sink_meta.rs`
is not already `1`, stop and land 22.2 first.

**In scope**

- `crates/common/src/sink_meta.rs`: add `skip_serializing_if` to `SinkMeta::unchanged_toast`
  (`:135`), keeping the `default` from 22.2 in the same attribute.
- The **same** attribute on `MetaRow::unchanged_toast` (`:172`) — the amortized borrow struct. Without
  it the two serializers disagree and `amortized_meta_matches_full` fails; with it, the amortized
  path is what actually stops writing the bytes in production.
- Update the amortized-split comment (`:147-150`): the byte-equivalence argument now rests on the two
  structs carrying *identical serialization attributes*, not on there being none.
- `crates/common/src/sink_meta_test.rs`: a new test asserting that a `SinkMeta` with an empty
  `unchanged_toast` serializes to a document containing **no** `unchanged_toast` key, that the
  non-empty case still emits it, and that the skipped document round-trips back to an equal
  `SinkMeta`.

**Explicitly deferred** (do *not* build these here)

- **No `skip_serializing_if = "Option::is_none"` on `TypeMeta`'s four `Option` fields or on
  `TypeDescriptor::recombine`.** `walrus-pg-sink.md` §2.6 documents the *explicit-null* descriptor
  form, and `crates/common/src/type_descriptor_test.rs:70` / `:89` assert
  `v["recombine"] == Value::Null` and `v["bit_length"] == Value::Null`. Changing that shape is a
  separate, docs-touching decision.
- No `#[serde(skip)]` anywhere — every `SinkMeta` field is part of the wire contract.
- No other `SinkMeta` field gains a skip predicate; `batch_id`, `commit_lsn` and friends are required
  identity keys, and PR 18.8 already recorded that they must not become optional or skipped.
- No change to `crates/loader/src/transform.rs`, to any `.sql` file, or to the `.sqlx` offline cache —
  the read side is already correct.
- No new criterion baseline claim in `docs/benchmarks.md`. If you want the number, measure it; do not
  assert an improvement you have not run.

    /// Skipped when empty — which is the overwhelmingly common case (all five production

// crates/common/src/sink_meta.rs — the amortized per-row borrow struct at :165-174.
// MetaRow MUST carry the identical serialization attribute, or the spliced `{const,row}` document
// stops matching `to_string(SinkMeta)` and `amortized_meta_matches_full` fails.

/// The per-row subset of [`SinkMeta`].
#[derive(Serialize)]
struct MetaRow<'a> {
    op: &'a Op,
    lsn: &'a Lsn,
    commit_lsn: &'a Lsn,
    commit_ts: &'a UtcTimestamp,
    xid: u32,
    #[serde(skip_serializing_if = "<[String]>::is_empty")]

    sink_processed_at: &'a UtcTimestamp,

fn empty_unchanged_toast_is_omitted_from_the_wire() {

    // Empty -> the key is gone entirely (not `[]`, not `null`).
    let empty = SinkMeta { unchanged_toast: Vec::new(), ..base.clone() };
    let json = serde_json::to_string(&empty).unwrap();

## Hints & gotchas

- **Predicate typing is the sharp edge.** serde generates `if !predicate(&self.field)`, so the
  predicate receives `&FieldType`. `Vec::is_empty` typechecks for `Vec<String>` but **not** for
  `MetaRow`'s `&'a [String]`, and not for `Box<[String]>` if PR 11.11 has already frozen the field.
  `<[String]>::is_empty` works for all three via deref coercion — use it in both places and you never
  have to revisit this when the field's container type changes.
- **Mirror the attribute on both structs or the test suite tells you immediately.**
  `amortized_meta_matches_full` compares the spliced `{const,row}` document against
  `to_string(SinkMeta)`; skipping on one side only makes them differ for exactly the empty case,
  which that test already covers.
- **`object_inner` (`:176-180`) is still safe.** It strips the first and last byte of each fragment.
  `MetaRow` keeps six unconditional fields, so it can never serialize to `{}` and the
  `saturating_sub` path is not newly reachable. Do not "simplify" it.
- **Do not `skip` the whole field.** `#[serde(skip)]` would drop it on the way *in* as well, which
  would break `meta_round_trips_exact_keys` and silently discard real TOAST placeholders.
- **`serde_json::to_string` field count is handled by the derive** — you do not need to adjust any
  `serialize_struct` length by hand; that is only a concern for a hand-written `Serialize` impl.
- **The loader needs no change.** `transform.rs:98` already `COALESCE`s a missing key to `'[]'`, and
  `crates/loader/tests/transform.rs:463` builds its own meta fixtures as literal JSON, so they are
  unaffected. Resist the urge to "tidy" the SQL: `.sql` files and the `.sqlx` offline cache are frozen
  (no Docker on this machine to regenerate them).
- Tests are **sibling files** (`sink_meta_test.rs`, `batch_test.rs`), not inline `mod tests {}`.
  `unwrap`/`expect` are denied in production and re-allowed there by `clippy.toml`; `clippy::all` and
  `warnings` are already `deny` workspace-wide.
- No new dependency is needed — anything new would have to clear `cargo deny` (advisories, the
  8-license allow-list, bans), which is a bad trade for two attributes.
