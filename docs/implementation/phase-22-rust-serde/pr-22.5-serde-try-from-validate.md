# PR 22.5 — Replace `Tier`'s hand-written deserializer with `serde(try_from)` and `serde(into)`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 22 — Rust serde · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 22.4 · **Unlocks:** PR 22.6

`serde(try_from` and `serde(into` are used **zero** times in the repo. `Tier`
(`crates/common/src/type_descriptor.rs:13-21`) hand-rolls **18 lines** of `Serialize` +
`Deserialize` (`:33-50`) whose entire job is to map `1|2|3` and reject everything else. The
validation is correct — but it is *locked inside the serde impls*, so no non-serde caller can reach
it: there is no way to ask "is 4 a valid tier?" without routing through `serde_json`. This PR moves
that logic into `TryFrom<u8>`/`From<Tier> for u8` and lets `#[serde(try_from = "u8", into = "u8")]`
generate both impls, which is the parse-don't-validate shape the rest of `common` already uses for
fallible conversions (PR 20.1's `TryFrom<u8> for ReplicaIdentity`). `Tier` is `Copy`, so `into`'s
`Clone` requirement costs nothing, and the §2.6 descriptor JSON keeps emitting the bare integer.

## Why — learning objectives

- **`#[serde(try_from = …, into = …)]` replaces the whole derived impl** — serde deserializes the
  *raw* type first, then calls your `TryFrom`; on the way out it calls `From`. You write one
  conversion and get both directions, with no `Serializer`/`Deserializer` boilerplate.
- **Parse-don't-validate at the deserialization boundary** — an invalid `Tier` is never constructed,
  and the same check is now reachable from ordinary Rust (`Tier::try_from(4u8)`), not just from a
  deserializer.

## Skeleton

```rust
// crates/common/src/type_descriptor.rs — the head of the file.

use serde::{Deserialize, Serialize};   // `Deserializer` / `Serializer` are no longer referenced

/// The three-tier mapping model (walrus-pg-sink.md §2.2). Serializes as the **integer** `1 | 2 | 3`
/// to match the `"tier": 2` form in the §2.6 descriptor JSON (not the string `"2"`).
///
/// The `1|2|3` validation lives in `TryFrom<u8>`, so it is reachable from ordinary code
/// (`Tier::try_from(n)?`) and not only from a deserializer; `#[serde(try_from, into)]` routes serde
/// through the same conversion, which is why an invalid `Tier` can never be constructed.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(try_from = "u8", into = "u8")]
pub enum Tier {
    /// Native 1:1 (Parquet-native logical type survives unchanged).
    One,
    /// Structural decomposition (one source column → several emitted columns / a nested type).
    Two,
    /// Canonical-text carrier (carried as VARCHAR, cast + metadata re-applied on load).
    Three,
}

impl TryFrom<u8> for Tier {
    type Error = crate::Error;

    fn try_from(n: u8) -> std::result::Result<Self, Self::Error> {
        // Same wording the hand-written deserializer produced — operators grep for this string.
        todo!("1 => One, 2 => Two, 3 => Three, other => Error::Internal(\"invalid tier {other}, expected 1, 2, or 3\")")
    }
}

impl From<Tier> for u8 {
    fn from(t: Tier) -> u8 {
        todo!("the match `as_int` used to hold: One => 1, Two => 2, Three => 3")
    }
}

// `fn as_int`, `impl Serialize for Tier` and `impl<'de> Deserialize<'de> for Tier` are all deleted.
```

```rust
// crates/common/src/type_descriptor_test.rs — new case. `tier_serializes_as_integer` (:21-30)
// stays byte-for-byte unchanged; this one proves the check escaped the serde impls.

#[test]
fn tier_validation_is_callable_outside_serde() {
    assert_eq!(Tier::try_from(1u8).unwrap(), Tier::One);
    assert_eq!(Tier::try_from(2u8).unwrap(), Tier::Two);
    assert_eq!(Tier::try_from(3u8).unwrap(), Tier::Three);

    // The rejection path is now ordinary Rust — no serde_json round trip needed.
    for bad in [0u8, 4u8, 255u8] {
        let err = todo!("Tier::try_from(bad).unwrap_err()");
        assert!(
            err.to_string().contains("invalid tier"),
            "message is the operator-grepped one: {err}"
        );
    }

    // And the serialize direction goes through the same conversion.
    assert_eq!(u8::from(Tier::Three), 3);
}
```

## Hints & gotchas

- **You still need `#[derive(Serialize, Deserialize)]`.** `try_from`/`into` do not stand alone — they
  tell the *derive* to route through your conversions instead of generating field-by-field code. A
  common first mistake is deleting the derive along with the manual impls, which leaves `Tier`
  un-serializable and breaks `TypeDescriptor`.
- **The `TryFrom` error type only needs `Display`**, because serde wraps it in
  `de::Error::custom(...)`. `crate::Error` is a `thiserror` enum, so it Displays — and using it keeps
  `Tier` inside the walrus taxonomy instead of introducing a bare `String` error. `Error::Internal` is
  the right variant: a bad tier in a persisted descriptor is an internal inconsistency, not a config
  problem.
- **`"2"` and `4` are rejected by two different mechanisms after this change** — the string fails
  while serde is deserializing the raw `u8` (before your code runs), and `4` fails in `TryFrom`.
  Both are still `is_err()`, which is all `tier_serializes_as_integer` asserts, but the *message*
  differs. Do not tighten that test to assert on the message text.
- **`into = "u8"` needs `Clone`.** `Tier` derives `Copy, Clone`, so it is free — but `From<Tier> for
  u8` must take `Tier` **by value**, not by reference, or the attribute will not resolve.
- **Delete `as_int` rather than leaving it.** It becomes dead code the moment `impl Serialize` goes,
  and `[workspace.lints.rust] warnings = "deny"` turns `dead_code` into a build failure. Same for the
  now-unused `Serializer`/`Deserializer` imports.
- **Do not chase the "same trick" onto `Lsn`/`UtcTimestamp`.** Their `collect_str` serialize path
  writes directly into the output buffer; `into = "String"` would add four heap allocations per row on
  the hottest path in the sink. The deferred list is not a to-do list.
- Tests are **sibling files** (`type_descriptor_test.rs`), not inline `mod tests {}`; `use super::*`
  gives you `Tier`, `TypeDescriptor`, `TypeMeta` and `serde_json`. `unwrap`/`expect` are denied in
  production and re-allowed in tests by `clippy.toml`; `clippy::all` and `warnings` are already
  `deny` workspace-wide.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. `schema_registry.descriptors` is jsonb and the emitted form is unchanged,
  so nothing downstream needs a migration. Add no dependency; anything new must clear `cargo deny`.
