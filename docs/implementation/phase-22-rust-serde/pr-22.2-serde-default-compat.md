# PR 22.2 — Make the sink-meta wire contract survive a mixed-version rollout with `serde(default)`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 22 — Rust serde · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 22.1 · **Unlocks:** PR 22.3

Container-level `#[serde(default)]` is on all five config structs, but **zero** of `SinkMeta`'s 15
fields carry it (`grep -c 'serde(default' crates/common/src/sink_meta.rs` ⇒ `0`). `SinkMeta` is the
cross-service wire contract (`architecture.md` §1.4): `pg-sink` writes it into every Parquet row's
`walrus_pg_sink_meta` column and `walrus-loader` reads it back — and the two are **separate
Deployments that roll independently**. Its own doc comment
(`crates/common/src/sink_meta.rs:108-109`) guards exactly one direction of that: unknown keys are
tolerated so a *newer* sink can add a field. The opposite direction is unguarded — a payload from an
*older* sink that predates a field is a hard `missing field` error on the newer loader, which turns a
routine rollout into a stalled Phase-A append. This PR closes that half for the one field where
defaulting is safe: `unchanged_toast`, the only non-identity, list-valued field on the struct.

## Why — learning objectives

- **Field-level vs container-level `#[serde(default)]`** — field-level fills exactly one key from
  `Default::default()` and leaves every other field required; container-level makes *all* of them
  optional and hides typos. Plus `default = "path"` for the case where `Default` is the wrong value.
- **CDC rolling-upgrade compatibility** — deciding, field by field, which wire keys may default
  silently and which must fail loudly. Defaulting an *ordering* key is not forward compatibility, it
  is silent data corruption.

- `crates/common/src/sink_meta.rs:142-215` — the PR 5.7 amortized `{const,row}` split. Note the

- `crates/common/src/sink_meta_test.rs:4-19` — `DOCS_EXAMPLE`, the §1.4 block as a real JSON document,
  and `:39-57` `meta_round_trips_exact_keys`, the test that must keep passing unedited.
- `docs/architecture.md` §1.4 (line 464 onward) — the canonical meta document and the sentence that
  `commit_lsn` is *the* progress/order key.
- `crates/common/src/config.rs:20` and `crates/common/src/telemetry.rs:39` — the container-level
  `#[serde(default)]` precedent, and the contrast: those structs *have* a `Default`; `SinkMeta`
  deliberately does not.

## Scope

**In scope**

- `crates/common/src/sink_meta.rs`: `#[serde(default)]` on **`unchanged_toast` only** (`:135`), with a
  comment recording the rolling-upgrade reason and the fact that it is a per-field, not per-container,
  decision.
- Reword the `:108-109` doc comment so it states **both** directions of the compatibility contract:
  unknown keys are ignored (newer sink → older loader) *and* a missing `unchanged_toast` defaults to
  empty (older sink → newer loader).
- Reword the `:148-149` amortized-split comment: the byte-equivalence argument now rests on "no
  *serialization-affecting* serde attributes on `SinkMeta`", which `default` is not.
- `crates/common/src/sink_meta_test.rs`: a new `meta_without_unchanged_toast_defaults_to_empty` test
  that parses the §1.4 example **minus** the `unchanged_toast` key and asserts the field comes back
  empty, plus a negative control proving a missing *identity* key is still a hard error.

**Explicitly deferred** (do *not* build these here)

- **No container-level `#[serde(default)]` on `SinkMeta`.** It has no `Default` impl, and adding one
  would be the wrong tool anyway — see the next bullet.
- **`op`, `lsn`, `commit_lsn`, `commit_ts`, `xid`, `epoch`, `schema_version`, `batch_id`,
  `source_schema`, `source_table`, `kind`, `sink_instance`, `sink_processed_at` stay required.**
  Defaulting an ordering key would silently substitute `Lsn::ZERO` for a real commit position and
  corrupt the `(commit_lsn, lsn)` contract the loader watermarks on; a missing identity field must
  stay a loud, terminal parse error.
- **No serialization change.** `#[serde(default)]` affects deserialization only; every row still
  emits `"unchanged_toast":[]` after this PR. Omitting it on the way out is PR 22.3's job and must
  not be smuggled in here — the two attributes are paired deliberately, in that order.
- No `deny_unknown_fields` on `SinkMeta` (that leniency is the documented cross-service property, and
  PR 22.1 already scoped the guard to config).
- No change to any `SinkMeta` construction site, to `MetaConst`/`MetaRow`, to `.sql`, or to the
  `.sqlx` offline cache.

## Hints & gotchas

- **`#[serde(default)]` is deserialize-only.** It has zero effect on `to_string`. If you find yourself
  editing an assertion about the *emitted* JSON, you have wandered into PR 22.3.
- **`Vec<String>`'s `Default` is the empty vec**, so bare `#[serde(default)]` is enough — no
  `default = "path"` function is needed. If an earlier phase has already frozen the field to
  `Box<[String]>` (PR 11.11 puts that in scope), `Box<[T]>: Default` too, so the attribute is
  unchanged either way.
- **Do not reach for container-level `default`.** `SinkMeta` has no `Default`, deriving one would
  invent an `Op` and an `Lsn` out of nothing, and the rule's own Caveats warn that container-level
  `default` masks field-name typos — exactly the failure mode PR 22.1 just spent a PR eliminating.
- **The amortized split is the thing most likely to break.** `MetaConst`/`MetaRow` (`:152-174`) are
  `Serialize`-only borrow structs; they need no `default`. `amortized_meta_matches_full` compares the
  spliced `{const,row}` document against `to_string(SinkMeta)` — a *serialization* attribute on one
  side and not the other would break it, which is why 22.3 has to touch both structs and this PR
  touches neither.
- **`Lsn` and `UtcTimestamp` have hand-written (de)serializers** (`lsn.rs:102/110`,
  `sink_meta.rs:91/103`). A field-level `default` interacts with neither; leave them alone.
- Tests are **sibling files** (`sink_meta_test.rs` via `#[cfg(test)] #[path = …] mod tests;`), not
  inline `mod tests {}`. `use super::*` already brings `Lsn`, `Op`, `Kind` and `serde_json` into scope
  there.
- `unwrap`/`expect` are denied in production and re-allowed in tests by `clippy.toml`; `clippy::all`
  and `warnings` are already `deny` workspace-wide.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. The loader side needs no change: `transform.rs:98` already reads the key
  through `COALESCE(…, '[]')`. Add no dependency; anything new must clear `cargo deny`.
