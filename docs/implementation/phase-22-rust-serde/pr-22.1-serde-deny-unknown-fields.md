# PR 22.1 — Close the last config typo hole with `deny_unknown_fields` on `TelemetryConfig`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common

> **Phase:** 22 — Rust serde · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 21.4 · **Unlocks:** PR 22.2

walrus has **five** `Deserialize` config containers — `CommonConfig`, `ObjectStoreConfig`,
`TelemetryConfig`, `LoaderConfig`, `SinkConfig` — and exactly **four** `#[serde(deny_unknown_fields)]`
attribute sites. The odd one out is `TelemetryConfig` (`crates/common/src/telemetry.rs:38-40`), which
carries only `#[serde(default)]`. `deny_unknown_fields` **does not propagate into a nested struct**,
so the guard on `CommonConfig` stops at the `telemetry` key and never inspects what is inside it. The
consequence is live: `WALRUS_TELEMETRY__JSN=true` — a one-character typo of the real ConfigMap key
`WALRUS_TELEMETRY__JSON` at `deploy/k8s/base/configmap.yaml:42` — is silently discarded, `json` keeps
its `false` default, and the pod ships pretty-printed logs into a JSON log pipeline for as long as
nobody notices. After this PR the fifth container has the same guard as the other four and that typo
is a terminal `Error::Config` at bootstrap, exactly like `WALRUS_NONSENSE` already is.

## Why — learning objectives

- **serde container attributes** — `deny_unknown_fields` is a property of *one* struct's
  `Deserialize` impl; it inspects only the keys that struct itself consumes, so it does **not**
  recurse into a nested struct field. Each container needs its own.
- **The walrus config contract** — invalid or typo'd config is a terminal error *at the edge*
  (bootstrap step 1), never a silent default that surfaces three modules later as "why are my logs not
  JSON?".

- `crates/common/src/config.rs:67-104` — `CommonConfig::load()`: an optional `WALRUS_CONFIG` file

  nesting separator, which is why `WALRUS_TELEMETRY__JSN` lands as `telemetry.jsn`.
- `crates/common/src/config_test.rs:19-29` and `:74-88` — the `in_jail` helper and
  `unknown_key_is_rejected`, the test this PR mirrors one level down.
- `crates/loader/src/config.rs:11-12` and `crates/pg-sink/src/config.rs:19-20` — the other two
  containers already carrying the guard; both embed `TelemetryConfig`, so both inherit the hole today.
- `deploy/k8s/base/configmap.yaml:42` (and `:68`) — the real `WALRUS_TELEMETRY__JSON: "true"` keys the
  typo shadows.

## Skeleton

```rust
// crates/common/src/telemetry.rs — replacing the attribute at :39.

/// How to render logs. `json` on in the cluster, off (pretty) for local dev.
///
/// `default` makes an omitted key legal (this struct's `Default` is the shipped configuration);
/// `deny_unknown_fields` makes a *present but misspelled* key fatal. `deny_unknown_fields` on
/// `CommonConfig` does NOT recurse into this struct, so the guard has to be declared here too.
#[derive(Debug, Clone, Deserialize)]
#[serde(deny_unknown_fields, default)]
pub struct TelemetryConfig {
    pub json: bool,
    pub filter: String,
}
```

// crates/common/src/telemetry_test.rs — new cases. `use super::*` brings in `TelemetryConfig` and
// `init_tracing` but NOT `CommonConfig`/`Error`, which live in sibling modules.

use crate::{CommonConfig, Error};

/// Hermetic env for a config load — the same shape as `config_test.rs`'s `in_jail`.
#[allow(clippy::result_large_err)]
fn in_jail(body: impl FnOnce(&mut figment::Jail)) {
    figment::Jail::expect_with(|jail| {
        body(jail);
        Ok(())
    });
}

#[test]
fn unknown_telemetry_key_is_rejected() {
    in_jail(|jail| {
        jail.set_env("WALRUS_CONTROL_DB_URL", "postgres://x/y");
        jail.set_env("WALRUS_INSTANCE", "i");
        jail.set_env("WALRUS_OBJECT_STORE__BUCKET", "b");
        // A one-character typo of the real ConfigMap key (configmap.yaml:42).
        jail.set_env("WALRUS_TELEMETRY__JSN", "true");

        let err: Error = todo!("CommonConfig::load().expect_err(\"typo'd nested key must fail\")");
        assert!(
            matches!(err, Error::Config(_)) && err.is_terminal(),
            "a typo'd telemetry key must be a terminal Config error: {err:?}"
        );
    });
}

#[test]
fn correctly_spelled_telemetry_key_still_loads() {
    in_jail(|jail| {
        jail.set_env("WALRUS_CONTROL_DB_URL", "postgres://x/y");
        jail.set_env("WALRUS_INSTANCE", "i");
        jail.set_env("WALRUS_OBJECT_STORE__BUCKET", "b");
        jail.set_env("WALRUS_TELEMETRY__JSON", "true");

        let cfg: CommonConfig = todo!("CommonConfig::load().expect(\"valid config should load\")");
        assert!(cfg.telemetry.json, "the real key must still take effect");
    });

## Hints & gotchas

- **`deny_unknown_fields` does not recurse.** This is the whole ticket. `CommonConfig`'s guard sees
  the key `telemetry` and hands the *value* to `TelemetryConfig::deserialize`, which — until this
  PR — is happy to ignore `jsn`. If you are tempted to "fix it once at the top", there is no such
  attribute.
- **`default` and `deny_unknown_fields` are not in tension.** `default` governs *absent* keys,
  `deny_unknown_fields` governs *unrecognised* keys. Keep both, in that order, matching the other four
  containers so a grep for the attribute string finds five identical spellings.
- **figment lowercases env keys and splits on `__`.** `WALRUS_TELEMETRY__JSN` becomes `telemetry.jsn`,
  which is why a *nested* guard is what catches it. `WALRUS_CONFIG` is already excluded via
  `.ignore(&["config", "CONFIG"])` at `config.rs:93-97` — do not remove that, or the file selector
  itself becomes an unknown key.
- **`use super::*` in a sibling test file only imports that module.** `telemetry_test.rs` sees
  `TelemetryConfig`, `init_tracing`, `build_env_filter`, `DEFAULT_FILTER` and `EnvFilter` — not
  `CommonConfig` or `Error`. Add `use crate::{CommonConfig, Error};` explicitly.
- **`figment::Jail` is dev-only and already available**: `crates/common/Cargo.toml` enables
  `figment`'s `test` feature under `[dev-dependencies]`. Copy `config_test.rs`'s
  `#[allow(clippy::result_large_err)]` onto the helper — `figment::Error` is large and the workspace
  denies `warnings`.
- **Tests are Go-style sibling files.** `telemetry.rs` already ends with
  `#[cfg(test)] #[path = "telemetry_test.rs"] mod tests;` — do not add an inline `mod tests {}`.
- `unwrap`/`expect` are denied in production by `[workspace.lints.clippy]` but re-allowed in tests by
  `clippy.toml`; `clippy::all` and `warnings` are already `deny` workspace-wide.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. Nothing here needs to. Any new dependency would have to clear
  `cargo deny` (advisories, the 8-license allow-list, bans); none is needed.
