# PR 11.13 — Bench-gate SmallVec for the usually-tiny key-column vectors

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `loader` *(bench target only)* ·
> **Est. size:** M · **Depends on:** PR 11.12 · **Unlocks:** PR 11.14

walrus has **no direct `smallvec` dependency** (`grep -rn 'smallvec' crates/*/Cargo.toml Cargo.toml`
→ 0), and the rule that says it should is in direct tension with two *other* rules from the same
corpus — `anti-premature-optimize` and `perf-profile-first`. The candidate is real but small:
`PgRelation::key_columns()` (`crates/common/src/pg_shape.rs:84`) heap-allocates a `Vec<&str>` that
holds **one** element for most tables, and `TransformSql` re-derives the same shape twice per render
(`pk_names()` / `non_key_names()`, `transform.rs:128-141`) on **every Phase-B poll, per table**
(default 1 s). What makes this a decision rather than a patch is the scale mismatch: the committed
loader baseline is **29.3 ms** (10k rows, K=1), **98.9 ms** (100k) and **473.9 ms** (1M) per
transform cycle — milliseconds of DuckDB work wrapped around a handful of nanoseconds of Rust
`collect()`. After this PR that intuition is a **measured number** in an ADR, a criterion bench that
isolates it lives beside the existing loader benches, and the dependency is added **only** if the
median actually moved. This is also the ADR template PRs 11.14–11.17 reuse.

## Why — learning objectives

- **Inline vs spilled storage** — `SmallVec<[T; N]>` keeps up to `N` elements in the struct itself
  and only heap-allocates past `N`; the price is a wider type and a branch on every access, so it is
  a trade, not a free win.
- **A benchmark must gate a dependency** — walrus's "measure, don't guess" rule from Phase 5:
  `docs/benchmarks.md` records *declined* optimisations (the TOAST back-scan rewrite, thin LTO's
  null result) with the same weight as adopted ones. A null result is a valid, publishable
  outcome.

## Scope

**In scope**

- Create `docs/implementation/notes/mem-smallvec-decision.md` — the ADR. It must state the rule, the
  candidate sites with `file:line`, the measurement, the decision, and the revisit trigger.
- Add an isolated criterion group to `crates/loader/benches/transform.rs` measuring the
  **Rust-side** cost only: `PgRelation::key_columns()` for a 1-key and a 3-key relation, and one
  whole `TransformSql::render(&Lsn::ZERO, &TruncateBoundary::none())` call. No DuckDB in the timed
  loop.
- Put the two scales side by side in the ADR: the isolated median (ns) against the committed
  `loader/transform` cycle medians (29.3 ms / 98.9 ms / 473.9 ms at K=1).
- Append a **"PR 11.13"** subsection to `docs/benchmarks.md`'s History with the measured number —
  whichever way the decision goes.
- **Only if** the criterion median moves outside its confidence interval: add `smallvec` to
  `[workspace.dependencies]` with a justifying comment, wire it into the consuming crate, re-run
  `cargo deny check`, and record the before/after delta. Otherwise the dependency count stays 0.

**Explicitly deferred** (do *not* build these here)

- Adding the dependency speculatively "because the rule says so". The dep count moving 0 → 1 without
  a number in `docs/benchmarks.md` is a failed ticket.
- `Vec<TupleValue>` (the per-row tuple). Its length is the table's column count — unbounded by any
  protocol constant — so it is not a small-vector candidate. PR 11.14 makes that argument formally.
- Re-shaping `key_columns()`'s return type in the public `common` API (e.g. to an iterator). That is
  an API-design change, not a memory one; leave it to Phase 13.
- Five different ADR shapes. The template written here is **reused verbatim** by PRs 11.14–11.17.

**The conflict, and how to resolve it** — CONTEXT §4 lists `mem-smallvec` as a known conflict:
adding a small-vector dependency contradicts `anti-premature-optimize` and `perf-profile-first`,
rules from this same corpus. **Do not apply the rule blindly.** The resolution is bench-gated: adopt
only if the committed criterion baseline moves; otherwise record the measurement and decline. One
nuance the ADR must state explicitly: `smallvec`, `arrayvec`, `tinyvec` and `bumpalo` are **already
in `Cargo.lock` transitively** (`smallvec` via the sqlx/tokio side, `bumpalo` via
`wasm-bindgen-macro-support` and `zopfli`), all under MIT/Apache-2.0 — so the `cargo deny` license
gate is *pre-cleared* and cannot be used as the reason to decline. The decision rests purely on the
number.

## Skeleton

```rust
// crates/loader/benches/transform.rs — new group, appended next to bench_mirror_size.
// The file already carries `#![allow(clippy::unwrap_used, clippy::expect_used)]` (bench, not test-cfg)
// and imports common::{Lsn, PgColumn, PgRelation, ReplicaIdentity} + loader::transform::*.

use loader::transform::TruncateBoundary;
use std::hint::black_box;

/// `orders(region, id, status, note)` with a 2-column composite PK — the "N > 1" key shape, so the
/// bench covers both the single-key common case and the inline-capacity-2 case.
fn composite_rel() -> PgRelation {
    todo!("mirror orders_rel(), but mark region+id as is_key = true")
}

/// The Rust-side cost ONLY: no DuckDB, no seeding. This is the number the ADR weighs against the
/// PR 5.5 cycle medians (29.3 ms / 98.9 ms / 473.9 ms at K=1).
fn bench_key_columns(c: &mut Criterion) {
    let single = orders_rel();
    let composite = composite_rel();
    let t = TransformSql::from_relation(&single);
    let mut g = c.benchmark_group("loader/keycols");
    g.bench_function("key_columns/k1", |b| {
        b.iter(|| black_box(black_box(&single).key_columns()));
    });
    g.bench_function("key_columns/k2", |b| {
        b.iter(|| black_box(black_box(&composite).key_columns()));
    });
    // The whole render — pk_names() + non_key_names() + every format!/join around them. The upper
    // bound on what removing the two key Vecs could possibly buy.
    g.bench_function("render", |b| {
        b.iter(|| black_box(t.render(black_box(&Lsn::ZERO), &TruncateBoundary::none())));
    });
    g.finish();
}

criterion_group!(
    benches,
    bench_transform_scaling,
    bench_toast_backscan,
    bench_mirror_size,
    bench_key_columns
);
criterion_main!(benches);
```

## Hints & gotchas

- **`just bench` does not run this bench.** The recipe is `cargo bench -p pg-sink -p pg-to-arrow`
  (justfile:35-36) — the loader benches are run explicitly: `cargo bench -p loader --bench
  transform`. Filter with `-- loader/keycols` so you don't sit through the 1M-row grid.
- **Benches are never a CI gate** (shared runners are too noisy); CI only *compile-checks* them via
  `clippy --all-targets`. So a bench that doesn't compile fails CI even though it never runs — and a
  bench median is only meaningful on a quiet machine, compared as a **delta**, not against the
  recorded absolute numbers from a different machine.
- `black_box` both the input and the result, or LLVM will hoist a pure `collect()` straight out of
  the loop and hand you a fake win.
- Bench files carry a file-level `#![allow(clippy::unwrap_used, clippy::expect_used)]` (they are
  `harness = false`, so `clippy.toml`'s test-cfg re-allow does not reach them). The existing header
  in `transform.rs:1` already covers your additions — don't add a second one.
- **Any new dependency must clear all four `cargo deny` families**, not just licenses: advisories
  (RUSTSEC), the 8-entry SPDX allow-list, bans (duplicate majors are `warn` today), and sources
  (crates.io only). Run `cargo deny check` locally before you commit a manifest change.
- A `SmallVec<[&str; 2]>` is **wider** than `Vec<&str>` and is stored inline — for a value that is
  immediately `join`ed into a `String` and dropped, the allocation you removed may cost more in
  moves than it saved. Say so in the ADR if the number says so.
- `TransformSql::render` returns a fresh `String` and performs ~10 `format!`/`join` allocations of
  its own (`transform.rs:178-250`). If `render` is nanoseconds against a millisecond cycle, the key
  vectors inside it cannot be the thing to fix — that ratio *is* the ADR's argument.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker locally to
  regenerate it. The DuckDB template `sql/duckdb/templates/transform.sql` is frozen here.
- If the PR ends up docs-only (the likely path), the CI `changes` classifier marks the diff
  `code: false` and the compile-heavy jobs skip — that is expected, not a broken run.
