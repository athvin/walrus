# PR 11.6 — Reuse scratch buffers in the Arrow append and commit-promotion loops

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `pg-to-arrow`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 11.5 · **Unlocks:** PR 11.7

`BatchBuilder` already proves this pattern in-repo: `meta_buf: String` (`batch.rs:82`) is cleared and
refilled per row (`batch.rs:169`, landed in PR 5.7) and that change alone took `append_row` from
634 ns/row to 460 ns/row on `narrow_int4`. But **three date/time parsers still `format!` a throwaway
`String` per cell** inside that same `append_row` — `crates/pg-to-arrow/src/batch.rs:857`, `:863`,
`:869` — so a `timestamp`-heavy row pays one allocation per temporal column on a path benchmarked at
460-837 ns/row. Separately, `TableBatcher::on_commit` (`crates/pg-sink/src/batch.rs:134`)
`mem::take`s `pending`, which resets its capacity to **0** on every commit, so the open-txn buffer
regrows from scratch for every transaction. After this PR both loops reuse their allocation: the
parsers borrow a `ts_buf` cleared like `meta_buf`, and `pending` keeps its capacity across commits,
guarded by a new sibling test that fails on `main` today.

## Why — learning objectives

- **`clear()` keeps capacity; `mem::take` does not** — `Vec::clear`/`String::clear` reset the length
  and keep the buffer; `mem::take` swaps in a brand-new `Vec::new()` with capacity 0 and drops the
  old allocation with the values.
- **The sink's two-stage buffering** — open-txn `pending` → committed Arrow `BatchBuilder` → sealed
  Parquet. `pending` is refilled and emptied once per transaction, which is exactly the shape a
  reused allocation is for.

## Scope

**In scope**

- `BatchBuilder` gains `ts_buf: String` next to `meta_buf`, initialised `String::new()` in
  `BatchBuilder::new` and documented the same way.
- Thread `scratch: &mut String` from `append_row` through `append_value`, `append_range`,
  `append_multirange` and `append_struct_bound` into `parse_date_days`, `parse_time_micros` and
  `parse_timestamp_micros`; each parser does `scratch.clear()` then builds its RFC-3339 candidate
  with `push_str`/`push` and calls `rfc3339_micros(scratch)`.
- `crates/pg-sink/src/batch.rs`: `on_commit` uses `self.pending.drain(..)` instead of
  `std::mem::take(&mut self.pending)`, so the buffer survives the commit with its capacity.
- A new sibling test in `crates/pg-sink/src/batch_test.rs` asserting `pending.capacity()` is
  unchanged (and non-zero) after `on_commit` — it must fail on `main`.
- `parse_timestamptz_micros` (line 873) allocates via `replacen` rather than `format!`; converting
  it to the same scratch buffer is welcome for consistency but is not required by the probe.

**Explicitly deferred** (do *not* build these here)

- Do **not** rework `seal()`'s `std::mem::replace(&mut self.builder, BatchBuilder::new(&…)?)`
  (`crates/pg-sink/src/batch.rs:165`). Reusing Arrow builders across seals needs `finish()` to stop
  consuming `self` — an arrow-rs-shaped change, out of scope.
- No change to parsed values, error messages or `Error::ValueParse` payloads. Same micros, same
  `Date32` days, same `value_err(col, s, dt)` text — `s` must still be the **original** cell text,
  not the scratch contents.
- No `thread_local!` scratch (the tree has zero, and PR 11.17 records why walrus keeps it that way)
  and no arena.
- No new dependency.

```rust
// crates/pg-to-arrow/src/batch.rs
pub struct BatchBuilder {
    schema: SchemaRef,
    builders: Vec<Box<dyn ArrayBuilder>>,
    plan: Vec<Emit>,
    meta: StringBuilder,
    rows: usize,
    meta_const: Option<String>,
    /// Reused scratch for assembling each row's `{const,row}` meta JSON (PR 5.7).
    meta_buf: String,
    /// Reused scratch for the RFC-3339 candidate the temporal parsers hand to `jiff` (PR 11.6) —
    /// cleared and refilled per cell, exactly like `meta_buf`.
    ts_buf: String,
}

impl BatchBuilder {
    pub fn append_row(&mut self, values: &[TupleValue], meta: &SinkMeta) -> Result<(), Error> {
        todo!("length check + `let fields = self.schema.fields().clone();` unchanged");
        for (emit, value) in self.plan.iter().zip(values) {
            match emit {
                // `self.builders` and `self.ts_buf` are DISJOINT fields, so both &mut borrows are legal.
                Emit::Scalar => {
                    append_value(self.builders[bi].as_mut(), &fields[bi], value, &mut self.ts_buf)?;
                    bi += 1;
                }
                Emit::Range => {
                    append_range(&mut self.builders[bi..bi + 5], &fields[bi..bi + 5], value, &mut self.ts_buf)?;
                    bi += 5;
                }
                Emit::Multirange => {
                    append_multirange(self.builders[bi].as_mut(), &fields[bi], value, &mut self.ts_buf)?;
                    bi += 1;
                }
                _ => todo!("Interval / Timetz / Geometric arms unchanged — no temporal text parsing"),
            }
        }
        self.append_meta(meta)?;
        self.rows += 1;
        Ok(())
    }
}

/// `"2024-01-02"` → days since 1970-01-01. `scratch` is cleared and reused (PR 11.6).
fn parse_date_days(s: &str, col: &str, scratch: &mut String) -> Result<i32, Error> {
    scratch.clear();
    scratch.push_str(s);
    scratch.push_str("T00:00:00Z");
    let micros = rfc3339_micros(scratch).ok_or_else(|| value_err(col, s, "Date32"))?;
    i32::try_from(micros / 86_400_000_000).map_err(|_| value_err(col, s, "Date32"))
}

/// `"03:04:05.678901"` → micros since midnight.
fn parse_time_micros(s: &str, col: &str, scratch: &mut String) -> Result<i64, Error> {
    scratch.clear();
    scratch.push_str("1970-01-01T");
    scratch.push_str(s);
    scratch.push('Z');
    rfc3339_micros(scratch).ok_or_else(|| value_err(col, s, "Time64"))
}

/// `"2024-01-02 03:04:05.678901"` (no offset) → micros since epoch, treated as UTC.
fn parse_timestamp_micros(s: &str, col: &str, scratch: &mut String) -> Result<i64, Error> {
    scratch.clear();
    scratch.push_str(s);
    // `replacen(' ', "T", 1)` replaced only the FIRST space — keep that exact semantics.
    if let Some(i) = scratch.find(' ') {
        scratch.replace_range(i..i + 1, "T");
    }
    scratch.push('Z');
    rfc3339_micros(scratch).ok_or_else(|| value_err(col, s, "Timestamp"))
}
```

```rust
// crates/pg-sink/src/batch.rs — TableBatcher::on_commit
pub fn on_commit(&mut self, commit_lsn: Lsn, commit_ts: UtcTimestamp) -> Result<(), BatchError> {
    todo!("empty check / opened_at / first_commit_lsn / last_commit_lsn unchanged");
    // `drain(..)` empties `pending` but KEEPS its capacity, so the next transaction refills the
    // same allocation. `mem::take` swapped in a fresh Vec and threw the buffer away every commit.
    for (mut meta, values) in self.pending.drain(..) {
        meta.commit_lsn = commit_lsn;
        meta.commit_ts = commit_ts;
        meta.batch_id.clone_from(&self.batch_id); // PR 11.3
        self.builder.append_row(&values, &meta)?;
        self.committed_rows += 1;
    }
    self.committed_bytes += std::mem::take(&mut self.pending_bytes);
    Ok(())
}
```

## Hints & gotchas

- `self.builders[bi].as_mut()` and `&mut self.ts_buf` are **disjoint field** borrows, so passing
  both in one call compiles. If borrowck still objects (e.g. after a later refactor), the escape
  hatch is `let mut scratch = std::mem::take(&mut self.ts_buf); … ; self.ts_buf = scratch;` — but
  try the direct form first.
- `for … in self.pending.drain(..)` borrows only the `pending` field, while the body mutably borrows
  `self.builder` and reads `self.batch_id` — again disjoint, so it compiles. Same fallback applies
  (take → iterate → `clear()` → put the buffer back) if it does not.
- An early `?` inside the drain loop drops the `Drain`, which discards the remaining pending rows —
  identical to today's `mem::take` behaviour on error. Do not "fix" it; just do not change it.
- `replacen(' ', "T", 1)` replaces only the **first** space. `str::replace` replaces all. Use
  `find(' ')` + `replace_range(i..i + 1, "T")` to keep the exact semantics; ASCII space is one byte,
  so the range is always on a char boundary.
- Keep passing the **original** `s` to `value_err(col, s, dt)`. Handing it `scratch` would change
  every `ValueParse` message and break the conformance assertions.
- `rfc3339_micros` takes `&str`; `&*scratch` / `scratch.as_str()` both work — you cannot pass
  `&mut String` where `&str` is expected without a deref.
- `unwrap`/`expect` are `deny` in production but re-allowed under `#[cfg(test)]` by `clippy.toml`,
  so the new sibling test may use them freely.
- Unit tests are Go-style siblings (`batch.rs` → `batch_test.rs` via
  `#[cfg(test)] #[path = "batch_test.rs"] mod tests;`). The wiring already exists in
  `crates/pg-sink/src/batch.rs:243-245` — add the test to the existing file, do **not** create an
  inline `mod tests {}`.
- Do not touch `.sql` files or the `.sqlx` offline cache — no Docker locally to regenerate it.
- Any new dependency would have to clear `cargo deny` (advisories + the 8-licence allow-list +
  bans). This PR needs none — that is the point.
