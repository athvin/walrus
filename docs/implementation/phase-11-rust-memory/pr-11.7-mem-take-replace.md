# PR 11.7 — Move rows out of the streamed-txn buffers with mem::take instead of cloning

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** loader,pg-sink

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `pg-sink`, `loader` ·
> **Est. size:** M · **Depends on:** PR 11.6 · **Unlocks:** PR 11.8

Production already reaches for `mem::take`/`mem::replace` correctly in four places
(`pg-sink/src/batch.rs:134`, `:141`, `:165`, `consume.rs:191`), but the two places that most need it
still avoid ownership the expensive way. `crates/pg-sink/src/stream_txn.rs:230-237` opens
`let mut take = Vec::new();` and then **deep-clones every matching `StreamedChange`** —
`take.push(c.clone())` at `:233`, each clone copying a whole `Vec<TupleValue>` — inside a `retain`,
on the memory-pressure spill path, i.e. exactly when the process is already short of memory.
`crates/pg-sink/src/reload_signal.rs:222` hand-rolls `extract` with `Vec::remove(i)` in a loop, an
O(n²) memmove. `stream_txn.rs` holds **18** `.clone()` occurrences, the second-highest of any
production file. After this PR the spill path performs **zero** deep clones, `extract` is linear,
and `clippy::redundant_clone` is denied in `[workspace.lints.clippy]` so the pattern cannot come
back.

## Why — learning objectives

- **`std::mem::take` / `std::mem::replace`** — how to move a value out from behind a `&mut` without
  cloning, and how to partition a `Vec` into "taken" and "kept" halves with no allocation of copies.
- **walrus streamed-transaction spill** — per-sub-xid files, so an aborted savepoint's already
  spilled object drops cleanly without contaminating the survivors (proto §8/§9).

## Skeleton

```rust
// crates/pg-sink/src/stream_txn.rs — inside `spill_if_over_ceiling`, replacing lines 224-240.
let (begin, rows) = {
    let Some(txn) = self.open.get_mut(&top) else {
        // `top` was just derived from `self.open`'s own keys, so this is unreachable;
        // skip this speculative-spill iteration rather than panic.
        continue;
    };
    // Move the buffer out (leaving an empty Vec), split it in commit order, put the
    // survivors back. `partition` preserves the relative order of both halves.
    let (rows, keep): (Vec<StreamedChange>, Vec<StreamedChange>) =
        std::mem::take(&mut txn.changes)
            .into_iter()
            .partition(|c| c.oid == oid && c.sub_xid == sub_xid);
    txn.changes = keep;
    (txn.begin_lsn, rows)
};
```

```rust
// crates/pg-sink/src/reload_signal.rs — replacing the O(n^2) `Vec::remove` loop at :222.
/// Drain every element matching `pred` out of `v`, preserving order.
fn extract<T>(v: &mut Vec<T>, mut pred: impl FnMut(&T) -> bool) -> Vec<T> {
    let (out, keep) = std::mem::take(v).into_iter().partition(|t| pred(t));
    *v = keep;
    out
}
```

## Hints & gotchas

- **Order is load-bearing.** `txn.changes` is "buffered changes **in commit order**" (the field's
  own doc). `Iterator::partition` preserves relative order within each half — `retain` did too, so
  this is a like-for-like swap. Do not reach for `HashSet`/`sort_by` shortcuts.
- `std::mem::take` needs `T: Default`; `Vec<StreamedChange>` has one, so `take` leaves an empty
  `Vec` (which does **not** allocate) and you assign the survivors straight back over it.
- `Vec::extract_if(.., pred)` (stable since 1.87, and MSRV is 1.95) is the std alternative for
  `reload_signal::extract` and avoids even the take-and-reassign. Its closure takes `&mut T`, so
  wrap the predicate: `v.extract_if(.., |t| pred(t)).collect()`. Either shape satisfies the DoD.
- `redundant_clone` is a **nursery** lint with known false positives and MIR-dependent results —
  run `cargo clippy --all-targets --all-features` (not just the lib target) before you trust the
  count, and fix rather than `#[allow]`.
- `#[derive(Clone)]` on `StreamedChange` stays: `Message`'s payloads are still cloned into it at
  `stream_txn.rs:162/168/174`. Removing the derive is out of scope.
- `unwrap`/`expect` are denied in production by `[workspace.lints.clippy]`; the `let … else
  { continue; }` guards already in `spill_if_over_ceiling` exist for that reason — keep them.
- Tests are **sibling files** (`stream_txn.rs` → `stream_txn_test.rs` via
  `#[cfg(test)] #[path = "stream_txn_test.rs"] mod tests;`), never an inline `mod tests {}`.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker on this machine to
  regenerate it.
