# PR 11.11 — Freeze the never-grown collections into Box<[T]> and Arc<[T]>

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,loader

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `loader`, `common` ·
> **Est. size:** M · **Depends on:** PR 11.10 · **Unlocks:** PR 11.12

The tree contains **zero** `Box<[T]>`, **zero** `Box<str>` and **zero** `Arc<[T]>`. Two remaining
collections are still `Vec`s advertising a growth capability they never use and are provably
frozen after construction: `TablePlan.raw_cols` / `mirror_cols`
(`crates/loader/src/plan.rs:51` — built once per Phase-B cycle, never pushed to afterwards),
and `SinkMeta.unchanged_toast` (`crates/common/src/sink_meta.rs:135` — one per row). The Parquet
column cache is already frozen as `Rc<[String]>`, the appropriate non-atomic owner because
`TableDb` is single-threaded. Measured with rustc on a 64-bit target, `TablePlan` goes 72 B → 48 B
with `Box<[T]>` + `Box<str>`.

## Why — learning objectives

- **`Vec<T>` is 3 words, `Box<[T]>` is 2; `Arc<Vec<T>>` is one hop more than `Arc<[T]>`** — the
  capacity field and the extra heap header are pure overhead once a collection stops growing, and
  the type is the documentation.
- **walrus's homogeneous-file rule** — a `schema_version`'s Parquet column list is *immutable* (the
  sink cuts a fresh file at every DDL bump, walrus-pg-sink §3.5), which is why the loader's existing
  `Rc<[String]>` DESCRIBE cache stays frozen and unchanged.

**In scope**

- `TablePlan`: `table: Box<str>`, `raw_cols: Box<[RawCol]>`, `mirror_cols: Box<[MirrorCol]>`. Build
  through `Vec` inside `tier1` / `from_registry` / `plan_column` exactly as today, then
  `.into_boxed_slice()` / `.into_boxed_str()` once at construction.
- `SinkMeta.unchanged_toast: Box<[String]>`. Every current construction site passes `vec![]`, so
  those sites become `Box::default()`; the two constructors that forward a `Vec<String>` freeze it
  with `.into_boxed_slice()`. The serialized JSON (`[]`) is byte-identical.
- A new PR 11.2-style const assertion for `TablePlan` (48 B on a 64-bit target), so the freeze is
  ratcheted rather than merely applied.

**Explicitly deferred** (do *not* build these here)

- `CachedRelation.descriptors` (`crates/pg-sink/src/relcache.rs:23`). That type sits behind an `Arc`

- `TransformSql`'s own fields — only the one `plan.table.clone()` call site changes, to
  `plan.table.to_string()`. Do not cascade the freeze into the SQL renderer in this PR.
- `TableDb.parquet_cols` — it is already `Rc<[String]>`, which has the frozen two-word slice shape
  without atomic refcount overhead. Do not churn it to `Arc<[String]>`.
- Any `Vec` that is genuinely appended to after construction (`StreamedTxn.changes`,
  `PendingSignals.pending`, `TableBatcher.pending`).

**Conflict to resolve explicitly** — `PgRelation.columns` looks like the same shape and is **not**

- `PgRelation` is serde-round-tripped through the `schema_registry` JSON contract, read back by

  `.sql` files and the `.sqlx` offline cache are frozen (no Docker locally to regenerate them) and
  the cross-service wire contract is out of scope for a memory-layout PR.
- **Required resolution:** leave `PgRelation.columns: Vec<PgColumn>` exactly as it is, and say why

## Skeleton

// crates/loader/src/plan.rs
/// The full plan for one table: the raw emit columns and the mirror columns.
/// Both lists are built once and never pushed to afterwards, so they are frozen into
/// boxed slices — 2 words each instead of 3, and the type states the invariant.
#[derive(Debug, Clone)]
pub struct TablePlan {
    pub table: Box<str>,
    pub raw_cols: Box<[RawCol]>,
    pub mirror_cols: Box<[MirrorCol]>,
}

impl TablePlan {
    pub fn tier1(rel: &PgRelation) -> Self {
        let mut raw_cols = Vec::with_capacity(rel.columns.len());   // PR 11.1
        let mut mirror_cols = Vec::with_capacity(rel.columns.len()); // PR 11.1
        // … unchanged push loop …
        TablePlan {
            table: rel.name.as_str().into(),
            raw_cols: raw_cols.into_boxed_slice(),
            mirror_cols: mirror_cols.into_boxed_slice(),
        }
    }
}

#[cfg(target_pointer_width = "64")]
const _: () = assert!(
    size_of::<TablePlan>() == 48,
    "TablePlan is rebuilt every Phase-B poll; keep its lists frozen"
);

## Hints & gotchas

- **Freeze at the boundary, build with a `Vec`.** `Box<[T]>` has no `push`. Keep `plan_column`'s
  `&mut Vec<RawCol>` / `&mut Vec<MirrorCol>` signature and call `.into_boxed_slice()` exactly once,
  in the struct literal. Pair it with PR 11.1's `Vec::with_capacity(rel.columns.len())` so
  `into_boxed_slice` does not have to `shrink_to_fit` (a realloc + memcpy when capacity > len).
- `&plan.table` is `&Box<str>` and deref-coerces to `&str` at any `&str` parameter (e.g.
  `String::replace`'s `to:` argument) and in `format!`. The one site that does *not* coerce is
  `transform.rs:123`, `TransformSql { table: plan.table.clone(), … }` — that field is a `String`, so
  use `plan.table.to_string()`.
- `Rc<[String]>` already supports `.iter()`, indexing and `len()`; leave the loader cache path
  untouched.
- serde: `Box<[T]>` implements both `Serialize` and `Deserialize` and produces the identical JSON
  array. `Box<[T]>: Default` gives you the empty case (`Box::default()`), so `vec![]` sites are a
  one-token edit.
- `clippy::all` + `warnings` are `deny`, so a leftover `.to_vec()` or an unused `use` fails CI
  immediately.
- Tests are sibling files (`duck.rs` → `duck_test.rs`, `sink_meta.rs` → `sink_meta_test.rs`); also
  fix the `unchanged_toast: vec![]` occurrences under `tests/` and `benches/`.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker locally to
  regenerate it. That constraint is exactly why `PgRelation` stays a `Vec`.
