# PR 11.9 — Right-size the decoder error offsets and give TypeMeta NonZero niches

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,pg-sink

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `pg-sink`, `common` ·
> **Est. size:** M · **Depends on:** PR 11.8 · **Unlocks:** PR 11.10

`DecodeError::UnexpectedEof` carries **three `usize`** (`crates/pg-sink/src/pgoutput/error.rs:8`),
which makes `DecodeError` 32 B and therefore `Result<u8, DecodeError>` 32 B — the return type of
`Reader::byte1`, i.e. of *every single-byte read in the decoder*. But a pgoutput message length is an
`Int32` on the wire (`reader.int32()`, and the TupleData column count is `reader.int16()` at
`pgoutput/mod.rs:211`), so `u32` is exact for all three fields and takes `DecodeError` to 24 B, where
the floor is `std::str::Utf8Error` (16 B), not walrus's own fields. Separately `TypeMeta`
(`crates/common/src/type_descriptor.rs:55`) holds three `Option<u32>` at 8 B each; `bit_length` and
`char_length` are **structurally non-zero** — `bit(0)` and `varchar(0)` are not legal Postgres types
— so `Option<NonZeroU32>` is 4 B and `TypeMeta` goes 48 B → 40 B. The tree contains **zero**
`NonZero*` types today; this PR introduces the first two and makes the type system carry the domain
bound instead of a comment.

## Why — learning objectives

- **Niche optimisation** — `Option<NonZeroU32>` is 4 bytes where `Option<u32>` is 8, because the
  `None` discriminant reuses the forbidden zero bit-pattern. Same idea that already makes
  `Option<Vec<T>>` the size of `Vec<T>`.
- **Wire widths as the domain bound** — a pgoutput `Int16` column count and `Int32` length are the
  protocol's own limits; picking the Rust integer that matches them turns "this can't overflow" from
  a comment into a type.

**In scope**

- Narrow `DecodeError::UnexpectedEof`'s `needed` / `offset` / `remaining` from `usize` to `u32`, and
  `DecodeError::TrailingBytes::unconsumed` likewise (same `Int32` wire bound; keeps the taxonomy
  consistent even though it does not move the size).
- Add one small private helper in `reader.rs` for the `usize → u32` conversion; it must be
  **infallible and non-panicking** (`u32::try_from(n).unwrap_or(u32::MAX)`), because an error path
  must never be able to fail harder than the error it is reporting.
- Change `TypeMeta::bit_length` and `TypeMeta::char_length` to `Option<NonZeroU32>`; update
  `pg_to_arrow::descriptor::meta_of` to build them with `NonZeroU32::new(…)` and tighten its guards
  so an out-of-domain modifier yields `None` rather than `Some(0)`.
- Update the PR 11.2 const assertions for `DecodeError` and `TypeMeta` to the values the compiler
  reports on **this** merge commit.

**Explicitly deferred** (do *not* build these here)

- The 104 `as` numeric casts across the tree — that is Phase 17 (`num-`). This PR adds no new bare
  `as` cast; it uses `try_from` + `unwrap_or`.
- Any change to `TypeMeta`'s serde shape. `Option<NonZeroU32>` serializes byte-identically to
  `Option<u32>`; the existing `type_descriptor` round-trip tests (which assert
  `"bit_length": null` etc.) must pass unchanged.
- `money_fraction_digits` stays `Option<u32>`: **zero is a legal value** (JPY and other
  `lc_monetary` locales have 0 fractional digits), so a `NonZero` niche would silently erase a real
  case. Say so in a comment next to the field.

**Conflict to resolve explicitly** — do **not** apply the rule blindly to every integer:

- The 128 `i64` struct fields in production are Postgres `bigint` columns (`epoch`,
  `schema_version`, `reload_id`, `chunk_no`, `manifest_id`). Narrowing them would break the
  control-plane wire/SQL contract. **Out of scope, permanently.**
- `common::ExitCode` is a documented `#[repr(i32)]` public contract. **Never narrow it.**
- Only **wire-bounded** (`Int16`/`Int32`) and **domain-bounded** (`bit(n)` / `char(n)`) values are
  in scope here.

## Skeleton

```rust
// crates/pg-sink/src/pgoutput/error.rs
#[derive(Debug, thiserror::Error)]
pub enum DecodeError {
    /// Widths are `u32`, not `usize`: a pgoutput message length is an `Int32` on the wire
    /// (proto §4), so `u32` is exact and `Result<u8, DecodeError>` stays small on the
    /// per-byte read path.
    #[error("unexpected end of message: needed {needed}B at offset {offset}, {remaining} left")]
    UnexpectedEof { needed: u32, offset: u32, remaining: u32 },
    // … unchanged variants …
    #[error("{unconsumed} trailing bytes after a complete message")]
    TrailingBytes { unconsumed: u32 },
}

// PR 11.2's ratchet, re-baselined by this PR.
#[cfg(target_pointer_width = "64")]
const _: () = assert!(
    size_of::<DecodeError>() == 24,
    "DecodeError is on the per-byte decode path; keep it small"
);
```

```rust
// crates/pg-sink/src/pgoutput/reader.rs
/// A pgoutput frame is `Int32`-bounded, so this never truncates in practice; saturating
/// (rather than `unwrap`) keeps the ERROR path infallible — `unwrap`/`expect` are denied.
fn u32c(n: usize) -> u32 {
    u32::try_from(n).unwrap_or(u32::MAX)
}

impl<'a> Reader<'a> {
    fn need(&self, n: usize) -> Result<(), DecodeError> {
        if self.remaining() < n {
            Err(DecodeError::UnexpectedEof {
                needed: u32c(n),
                offset: u32c(self.pos),
                remaining: u32c(self.remaining()),
            })
        } else {
            Ok(())
        }
    }
    // … int16 / int32 / int64 / string construct UnexpectedEof the same way …
}
```

use std::num::NonZeroU32;

#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
pub struct TypeMeta {
    /// Ordered label set for an `enum`.
    pub enum_labels: Option<Vec<String>>,

## Hints & gotchas

- **The assertion numbers are the compiler's, not this ticket's.** The 24 B / 40 B figures above are
  modelled. If `cargo build` rejects the `const _: () = assert!(…)`, read the real size out of the
  error message and use it — never bend the type to fit a guessed number.
- `std::str::Utf8Error` (16 B) is `DecodeError`'s floor. Do not try to shrink past it by boxing the
  UTF-8 variant: that trades a cold heap allocation for 8 stack bytes on an error type.
- Deserializing a JSON `0` into `Option<NonZeroU32>` is now an **error** ("invalid value: integer
  `0`, expected a nonzero u32") rather than `Some(0)`. That is the intended tightening — no walrus
  writer can emit 0 (the `meta_of` guards see to it) — but say so in the field doc so a future
  reader does not treat it as a bug.
- `col.type_modifier` is `i32` and can be `-1`; the guards must run **before** the conversion, and
  the conversion itself must not use a bare `as` (Phase 17 will clean those up — do not add more).
- `clippy::all` + `warnings` are already `deny` at the workspace level, so a now-unused `usize`
  import or an unreachable branch fails CI immediately.
- Tests are sibling files (`type_descriptor.rs` → `type_descriptor_test.rs`, `descriptor.rs` →
  `descriptor_test.rs`); update the existing `assert_eq!(d.meta.char_length, Some(5))` style
  expectations to `NonZeroU32::new(5)` rather than adding new inline test modules.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker locally to
  regenerate it. `TypeMeta` reaches Postgres only as JSON inside `schema_registry.descriptors`,
  which is unchanged.
