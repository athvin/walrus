# PR 11.10 — Box the oversized pg-to-arrow error variants

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-to-arrow

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `pg-to-arrow` ·
> **Est. size:** M · **Depends on:** PR 11.9 · **Unlocks:** PR 11.11

`pg_to_arrow::Error::ValueParse` (`crates/pg-to-arrow/src/error.rs:14`) carries **three inline
`String`s** — 72 B of payload — while its next-largest walrus-defined sibling (`EmptyRelation`,
`Downcast`) carries 24 B. An enum is as large as its largest variant, and this one is the error half
of the `Result` that `BatchBuilder::append_row` returns **for every row** (benchmarked in PR 5.7 at
460–837 ns/row). Modelled with rustc on a 64-bit target the walrus-defined variants alone make
`Error` 72 B; boxing `ValueParse`'s payload drops it to 32 B. `clippy::large_enum_variant` is
already denied via `clippy::all`, but its default 200-byte threshold never fires here and
`clippy.toml` (2 lines, unwrap/expect only) sets none. This PR boxes the cold payload, tightens the
threshold so a future variant cannot quietly repeat the mistake, and re-baselines the PR 11.2 size
assertion.

## Why — learning objectives

- **An enum is as large as its largest variant** — `Box` moves a cold, rarely-constructed payload to
  the heap so the hot success path stops paying for it in every `Result`.
- **Why the per-row `Result<(), Error>` size matters** — `append_row` is the sink's inner loop; the
  `Ok` case never touches the payload, but it is memcpy'd through every `?` on the way out.

**In scope**

- Introduce a `ValueParseDetail` struct holding the three `String`s, and change the variant to
  `ValueParse(Box<ValueParseDetail>)`. Keep the `#[error(…)]` message **byte-identical** — the
  existing tests and logs match on it.
- Add an `Error::value_parse(column, value, data_type)` constructor so the twelve call sites stay
  one-liners instead of each spelling out `Box::new(ValueParseDetail { … })`.
- Update the one pattern match in `crates/pg-to-arrow/src/batch_test.rs:168`
  (`Error::ValueParse { column, .. }`) to the boxed shape.
- Add `enum-variant-size-threshold = 64` to `clippy.toml`.
- Lower the PR 11.2 const assertion for `pg_to_arrow::Error` to whatever the compiler reports after
  the change.

**Explicitly deferred** (do *not* build these here)

- Restructuring `pgoutput::Message` (88 B modelled, dominated by the inline `PgRelation`). It is
  `#[non_exhaustive]` and matched exhaustively in three crates; that is a separate, larger change.
- Boxing any other walrus error type (`common::Error`, `LoaderError`, `DecodeError`, `BatchError`) —
  none of them sits on a per-row `Result`.

**Conflict to resolve explicitly** — the rule says "box the large variant", but two of these
variants are not walrus's to shrink:

- `Arrow(#[from] arrow::error::ArrowError)` and `Parquet(#[from] parquet::errors::ParquetError)`
  wrap foreign types whose sizes walrus does not control and whose exact size is pinned by the
  `=54.3.1` version pin.
- **Required resolution:** after boxing `ValueParse`, read the PR 11.2 assertion failure to see what
  actually dominates. If a foreign error does, box **it** too (`Arrow(Box<ArrowError>)`) and keep
  the ergonomic conversion by writing the `impl From<ArrowError> for Error` **by hand** — do *not*
  raise `enum-variant-size-threshold` to fit them, and do *not* delete the `?`-friendly conversion.

## Hints & gotchas

- **`enum-variant-size-threshold` is a *difference* threshold**, not an absolute size: clippy fires
  when `largest - second_largest` exceeds it. So the lint may well stay silent both before and after
  your change — the **PR 11.2 const assertion**, not clippy, is what proves the boxing worked. The
  clippy.toml line is the regression ratchet.
- Lowering the threshold is workspace-wide. Run `cargo clippy --all-targets --all-features` before
  and after and diff the output; if `pgoutput::Message` trips, do **not** restructure it (it is the
  explicit defer) — pick the tightest threshold that still catches `Error`, or add a narrowly-scoped
  `#[allow(clippy::large_enum_variant)]` on `Message` with a one-line comment pointing at this
  ticket.
- Keep the `#[error(…)]` text identical. `thiserror` lets you reach into a tuple field with
  `.0.column`; use that rather than restating the message.
- `Box<T>` in an error variant is fine for `std::error::Error`: `Debug` and `Display` both forward,
  and `Error` here derives `Debug` and gets `Display` from `thiserror`.
- The `#[from]` attribute generates `impl From<ArrowError> for Error`. If you box a foreign variant
  you must **drop `#[from]` and hand-write the impl** (`Error::Arrow(Box::new(e))`), or every `?` on
  an arrow call stops compiling.
- `unwrap`/`expect` are denied in production; the constructor takes `impl Into<String>` so no call
  site needs a fallible conversion.
- Tests are sibling files (`batch.rs` → `batch_test.rs`); the only test edit needed is the one
  pattern match — do not add an inline `mod tests {}`.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker locally to
  regenerate it. This PR is pure Rust.
