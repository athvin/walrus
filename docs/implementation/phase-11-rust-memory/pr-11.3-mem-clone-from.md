# PR 11.3 — Reuse the destination allocation with `clone_from` and deny `assigning_clones`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `loader`, `pg-sink` ·
> **Est. size:** S · **Depends on:** PR 11.2 · **Unlocks:** PR 11.4

Exactly **two** production sites assign a fresh clone over a live `String`:
`crates/loader/src/ddl.rs:226` (`cur = to.clone();`, inside the DDL-apply loop) and
`crates/pg-sink/src/batch.rs:137` (`meta.batch_id = self.batch_id.clone();`, inside the per-row
`on_commit` promotion loop). Clippy's pedantic `assigning_clones` reports one of them today, and
`[workspace.lints.clippy]` currently denies only `all`, `unwrap_used` and `expect_used` — so nothing
stops the next `x = y.clone()` from landing in a hot loop. This PR converts both to `clone_from` and
promotes `assigning_clones` to `deny`, which is the part that actually holds: the two conversions
are small, the gate is permanent.

Be honest in the PR body about the size of the win. At `ddl.rs:226` the destination `cur` is a live
`String` (opened at `ddl.rs:191` with `table.to_string()`), so `clone_from` genuinely reuses its
buffer. At `batch.rs:137` the destination is *always* a freshly-empty `String` — every `SinkMeta`
is constructed with `batch_id: String::new()` (`consume.rs:547`, `snapshot.rs:225`,
`reload_export.rs:454`, `stream_txn.rs:259` and `:409`) — so `clone_from` there buys idiom and lint
conformance, not an avoided allocation. Removing *that* allocation means `Arc<str>`, which is PR
5.7's documented defer and is re-measured in PR 11.16.

## Why — learning objectives

- **`Clone::clone_from` vs drop-then-allocate** — `x = y.clone()` frees `x`'s buffer and allocates a
  new one; `x.clone_from(&y)` calls `clear()` + `push_str` and keeps the buffer when capacity
  allows.
- **The sink's commit-boundary promotion loop** — `TableBatcher::on_commit` walks every pending row
  of the just-committed transaction, stamps `commit_lsn`/`commit_ts`/`batch_id`, and pushes it into
  the Arrow `BatchBuilder`. Anything per-iteration there is per-row.

## Scope

**In scope**

- `crates/loader/src/ddl.rs:226`: `cur = to.clone();` → `cur.clone_from(to);`.
- `crates/pg-sink/src/batch.rs:137`: `meta.batch_id = self.batch_id.clone();` →
  `meta.batch_id.clone_from(&self.batch_id);`.
- `Cargo.toml`: add `assigning_clones = "deny"` to `[workspace.lints.clippy]`, with a one-line
  comment saying it is pedantic (so outside `all`) and needs no `priority`.
- A short comment at `batch.rs:137` recording that the destination is always empty today and that
  `Arc<str>` (PR 11.16) is the real fix — so the next reader does not assume an allocation was
  removed.

**Explicitly deferred** (do *not* build these here)

- **Do not** change `batch_id` to `Arc<str>`. That is PR 5.7's recorded defer
  (`docs/benchmarks.md`, PR 5.7 item 3) and is re-measured in PR 11.16; it ripples through every
  `SinkMeta` construction site.
- Do not touch the other **172** production `.clone()` calls. `mem-take-replace` (PR 11.7) and
  `own-*` (Phase 9) own those.
- No change to what the emitted DuckDB DDL or the Parquet meta JSON contain — this is a
  reassignment-shape change only.

## Skeleton

```toml
# Cargo.toml
[workspace.lints.clippy]
all = "deny"
unwrap_used = "deny"
expect_used = "deny"
# `x = y.clone()` drops the destination's buffer before allocating a new one; `clone_from` reuses
# it. Pedantic (not in `all`), so — like unwrap_used/expect_used above — no `priority` juggling.
assigning_clones = "deny"
```

```rust
// crates/loader/src/ddl.rs — inside apply_additive's `for ch in changes` match.
AdditiveChange::RenameTable { from, to } => {
    todo!("push the three ALTER/DROP VIEW statements as today");
    // `cur` is a live String opened at ddl.rs:191 — reuse its buffer instead of dropping it.
    cur.clone_from(to);
    structural = true;
}
```

```rust
// crates/pg-sink/src/batch.rs — inside TableBatcher::on_commit's per-row loop.
for (mut meta, values) in std::mem::take(&mut self.pending) {
    meta.commit_lsn = commit_lsn;
    meta.commit_ts = commit_ts;
    // NOTE: every SinkMeta is built with `batch_id: String::new()`, so this destination has no
    // capacity to reuse — `clone_from` here is idiom + lint conformance. Removing the allocation
    // outright means `batch_id: Arc<str>` (PR 5.7 defer, re-measured in PR 11.16).
    meta.batch_id.clone_from(&self.batch_id);
    self.builder.append_row(&values, &meta)?;
    self.committed_rows += 1;
}
```

## Hints & gotchas

- `[workspace.lints]` only applies to a member crate that declares `[lints] workspace = true` — all
  six members already do, so nothing else needs editing.
- Promoting a lint to `deny` runs it over `--all-targets`, i.e. **tests and benches too**. Today no
  test matches the pattern, but re-run the clippy line after the Cargo.toml edit before assuming it
  is clean.
- In the `RenameTable` arm, `to` is already a `&String` from the match pattern, so it is
  `cur.clone_from(to)` — **not** `cur.clone_from(&to)`, which would be a `&&String` and fail to
  compile.
- `meta.batch_id.clone_from(&self.batch_id)` borrows `self.batch_id` immutably while `meta` is a
  local moved out of `pending` — disjoint from `self.builder`, so borrowck is happy. If you later
  reshape the loop (PR 11.6), keep those two field borrows disjoint.
- `unwrap`/`expect` are `deny` in production; nothing here needs them. `clippy::all` and `warnings`
  are already `deny`, so a stray unused import will fail the build.
- Do not modify any `.sql` file or the `.sqlx` offline cache — no Docker locally to regenerate it,
  and neither site touches SQL text bindings.
- Unit tests are Go-style siblings (`batch.rs` → `batch_test.rs`); the loader's DDL coverage lives
  in the integration test `crates/loader/tests/ddl_additive.rs`. Do not add inline test modules.
