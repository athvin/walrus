# PR 11.5 — Cache the per-table metric label instead of formatting it every poll

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** common,loader,pg-sink

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `loader`, `pg-sink`, `common` ·
> **Est. size:** M · **Depends on:** PR 11.4 · **Unlocks:** PR 11.6

Four production call sites build a metric label with `&format!("{}.{}", schema, table)` for a value
that is **constant for the life of the object**. Two of them fire on every loader poll — default
1 s, per owned table: `phase_a.rs:82` (`set_raw_append_lag`) and `phase_b.rs:45`
(`set_transform_lag`). The other two fire per reload chunk: `reload_export.rs:328` and `:421`. The
`common::metrics` helpers then allocate a **second** time (`table.to_string()` at `metrics.rs:376`,
`:389`, `:422`, `:428`), so every metric update costs two heap allocations for a string that never
changes. The allocation-free idiom is already used one line above one of them —
`format_args!` at `reload.rs:352`. After this PR the label is computed **once** at construction and
stored next to `schema`/`table`, the four `format!`s are gone, and the recorded label values are
byte-identical.

## Why — learning objectives

- **`format_args!` vs `format!`, and hoisting a loop-invariant allocation** — `format_args!` builds
  a borrowed `Arguments<'_>` with no heap allocation (what `tracing` already uses at
  `phase_a.rs:102` and `reload.rs:352`); `format!` always allocates. When the value is
  loop-invariant, the right answer is neither — compute it once and store it.
- **walrus metric cardinality** — the `table` label is `schema.table` and is bounded by the tables a
  pod owns, which is exactly why it is safe (and cheap) to precompute one `String` per worker rather
  than one per poll.

## Hints & gotchas

- Field order matters in `ChunkExporter::connect`: build `series` from `rel.schema`/`rel.name`
  **before** `rel` is moved into the struct literal, or you get a use-after-move. Putting the
  `series:` line above `rel:` in the literal is the simplest fix.
- Adding a public field to `TableCtx` breaks every struct literal at compile time — that is the
  point, and it is 9 files. Let the compiler drive it; do not add `..Default::default()`.
- In the tests, the literal value can just be `series: "public.demo".to_string()` (or built from the
  same `schema`/`table` locals) — keep it consistent with what the test's other fields say, because
  `metrics_scrape.rs` asserts on the rendered label.
- `format_args!` cannot be stored in a local and then used later (the temporary it borrows dies at
  the end of the statement). It is fine *inside* a `tracing` macro — which is why
  `phase_a.rs:102`'s `table = %format_args!(...)` stays as it is — but it is not the tool for a
  struct field.
- `unwrap`/`expect` are denied in production; nothing here needs them. `clippy::all` and `warnings`
  are already `deny`, so a now-unused `ctx.schema`/`ctx.table` read is fine (both fields are still
  used elsewhere) but a stale import is not.
- Do not touch `.sql` files or the `.sqlx` offline cache — no Docker locally to regenerate it.
- Unit tests are Go-style siblings (`phase_a.rs` → `phase_a_test.rs`); the loader's `TableCtx`
  fixtures live in `crates/loader/tests/*.rs`. Do not add inline `#[cfg(test)] mod tests {}`.
