# PR 11.12 — Stop copying every text cell twice in the pgoutput decoder

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `pg-sink` ·
> **Est. size:** L · **Depends on:** PR 11.11 · **Unlocks:** PR 11.13

Every `'t'` (text) cell that walrus decodes is copied **twice**: `Reader::take` does
`Bytes::copy_from_slice` (`crates/pg-sink/src/pgoutput/reader.rs:115`), and then
`crates/pg-sink/src/pgoutput/mod.rs:222` does `std::str::from_utf8(&bytes)?.to_string()` — a second
heap allocation and a second memcpy of the same bytes, immediately discarding the first. Since
pgoutput ships **every** value as text (proto §5), this is the per-cell cost on the decoder's inner
loop. It is also the exact allocation walrus's own committed baseline names as dominant —
`docs/benchmarks.md:57`: *"the per-cell `String` allocation in the `'t'` branch dominates … First
optimisation target for PR 5.7"* — and it was never taken, because PR 5.7 spent its budget on
meta-JSON amortization instead. Recorded baseline to beat: `parse_tuple` **236 ns/row**
(`narrow_int4`), **1 822 ns/row** (`wide30`), **710 ns/row** (`text_heavy`). After this PR the
cursor grows one borrowing primitive, the `'t'` arm allocates exactly once, and the benchmark table
gains an after-column.

## Why — learning objectives

- **Borrowing from an input buffer with a lifetime-parameterised cursor** — `Reader<'a>` already
  holds `buf: &'a [u8]`, so it can hand out `&'a str` that outlives the `&mut self` borrow;
  validating UTF-8 on the borrowed slice avoids materialising an intermediate owned copy.
- **pgoutput TupleData framing** — `Int16` column count, then a one-byte format tag per column, and
  why walrus keeps `Null` (`'n'`) distinct from `UnchangedToast` (`'u'`): the loader's TOAST
  back-scan (PR 3.6) depends on that difference surviving from wire to `<table>_raw`.

## Read first

- [`mem-zero-copy`](../../.claude/skills/rust-skills/rules/mem-zero-copy.md) — take the

  `memchr`: adding a dependency for a `position(|&b| b == 0)` over a short name would have to clear

- `crates/pg-sink/src/pgoutput/reader.rs` — the whole file (124 lines). `need()` (`:32`) is the
  single bounds check every primitive funnels through; `take` (`:113`) and `string` (`:96`) are the
  two that copy.
- `crates/pg-sink/src/pgoutput/mod.rs:205-233` — `parse_tuple`, the four format-tag arms. Note that
  `'b'` (binary) genuinely needs an owned `Bytes`, and so does the `'M'` message content at `:374`.
- `crates/common/src/pg_shape.rs:91-110` — `TupleValue`'s doc: `Text(String)` is a public,
  cross-crate type; `Null` vs `UnchangedToast` must never collapse.
- `crates/pg-sink/benches/decode.rs` — especially `TableShape::TextHeavy` at `:43` ("10 × ~200-byte
  text columns — allocation-bound (the `'t'`-branch `String` per cell)"), built specifically to
  expose this.
- `docs/benchmarks.md` — the "Methodology", the `parse_tuple` baseline rows, and the "History"
  section's before/after table format (PR 5.7's is the template to copy).

## Scope

**In scope**

- Add a borrowing primitive to `Reader<'a>`:
  `pub fn slice(&mut self, n: usize) -> Result<&'a [u8], DecodeError>` — bounds-checked through the
  existing `need()`, advancing `pos`, returning a borrow into `buf` with no copy.
- Add `pub fn str(&mut self, n: usize) -> Result<&'a str, DecodeError>` on top of it, validating
  UTF-8 on the borrowed slice (`DecodeError` already has `Utf8(#[from] std::str::Utf8Error)`, so
  `?` converts).
- Rewrite the `'t'` arm of `parse_tuple` (`mod.rs:217-223`) to `reader.str(len)?.to_string()` —
  **one** allocation, down from two.
- Re-express `Reader::take` in terms of `slice` so the cursor has exactly one bounds-checked read
  primitive and no second copy path (`Bytes::from(self.slice(n)?.to_vec())`). The `'b'` arm and the
  `'M'` content read keep owned `Bytes` and are otherwise untouched.
- Re-run `cargo bench -p pg-sink --bench decode` on a quiet machine and add an after-column to the
  `pgoutput/parse_tuple` rows in `docs/benchmarks.md`, in the "History" section's existing format.

**Explicitly deferred** (do *not* build these here)

- Changing `TupleValue::Text(String)` into a `Bytes`/`Cow` variant. That ripples into `pg-to-arrow`,
  the loader's TOAST resolution and the golden vectors. **One** copy is removed here; the public
  `common::TupleValue` shape is untouched.
- The `'b'` (binary) arm: it keeps `Bytes` as-is. `Bytes` is already the zero-copy-friendly owner and
  the value must outlive the frame.
- `Reader::string()` (the NUL-terminated relation/column-name reader). Re-expressing it on top of
  `slice` is a welcome tidy but is not required by the probe — those strings are per-*relation*, not
  per-cell.

## Skeleton

```rust
// crates/pg-sink/src/pgoutput/reader.rs
impl<'a> Reader<'a> {
    /// Borrow the next `n` bytes **without copying**, advancing the cursor. The lifetime is the
    /// buffer's (`'a`), not the borrow of `self`, so the result outlives this call.
    pub fn slice(&mut self, n: usize) -> Result<&'a [u8], DecodeError> {
        self.need(n)?;
        let out = &self.buf[self.pos..self.pos + n];
        self.pos += n;
        Ok(out)
    }

    /// Borrow the next `n` bytes as UTF-8 — validated **on the borrowed slice**, so a text cell is
    /// materialised at most once, by the caller that actually needs ownership.
    pub fn str(&mut self, n: usize) -> Result<&'a str, DecodeError> {
        Ok(std::str::from_utf8(self.slice(n)?)?)
    }

    /// Copy `n` bytes into an owned `Bytes` (TOAST-safe value copies from PR 2.4, and the `'M'`
    /// message content). Built on `slice` so the cursor has exactly one read primitive.
    pub fn take(&mut self, n: usize) -> Result<Bytes, DecodeError> {
        Ok(Bytes::from(self.slice(n)?.to_vec()))
    }
}
```

```rust
// crates/pg-sink/src/pgoutput/mod.rs — parse_tuple's 't' arm (was :217-223)
```

## Hints & gotchas

- **The lifetime is the point.** `slice` must return `&'a [u8]`, not `&[u8]`. `self.buf: &'a [u8]`
  is `Copy`, so reborrowing it out of `&mut self` is sound and lets the returned `&'a str` outlive
  the cursor borrow. If you write `-> Result<&[u8], _>` the elided lifetime binds to `&mut self` and
  the `'t'` arm stops compiling.
- `std::str::from_utf8` returns `Result<&str, Utf8Error>` and `DecodeError` already has
  `Utf8(#[from] std::str::Utf8Error)`, so plain `?` converts. Do **not** introduce
  `from_utf8_unchecked` — walrus has zero `unsafe` in production and this PR must not be the first.
- `Bytes::from(vec)` and `Bytes::copy_from_slice(s)` are equivalent (the latter is `s.to_vec().into()`
  internally). Routing `take` through `slice` is not a micro-optimisation — it makes "the cursor has
  exactly one bounds-checked read primitive" mechanically checkable by the grep in the probe.
- **Benches are never a CI gate** (shared runners are too noisy) — CI only compile-checks them via
  `clippy --all-targets`. Run `just bench` locally on a quiet machine and compare *deltas*, not
  absolute numbers against the recorded table's machine.
- `parse_stream` allocates a `Vec<Message>` whose final length is genuinely unknown — leave it
  alone; PR 11.1 already documented it as out of scope for pre-sizing.
- `TupleValue::Text(String)` stays. The temptation to make it `Cow<'a, str>` is exactly the
  deferred item: it would put a lifetime on a type that crosses three crates and is stored in
  `StreamedChange` past the frame's life.
- `unwrap`/`expect` are denied in production, and `clippy::all` + `warnings` are `deny` — a
  now-unused `use bytes::Bytes;` or an unread local will fail CI.
- Tests are **sibling files**: wire the new `reader_test.rs` from `reader.rs` with
  `#[cfg(test)] #[path = "reader_test.rs"] mod tests;`, never an inline `mod tests {}`.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker locally to
  regenerate it. This PR is decoder-only.
