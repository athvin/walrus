# PR 11.16 — Re-measure the deferred SinkMeta string-layout win

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `common`, `pg-sink`
> *(only if the measurement adopts branch (b))* · **Est. size:** M ·
> **Depends on:** PR 11.15 · **Unlocks:** PR 11.17

walrus already made this decision once and wrote it down. `docs/benchmarks.md:237` (PR 5.7, item
3): *"`TableBatcher::push` still `to_vec()`s the decoded values, and `on_commit` clones `batch_id`
per row … `batch_id → Arc<str>` ripples through every `SinkMeta` construction site. **Deferred**:
PR 5.6's e2e ranking shows the sink is not the system bottleneck (the loader is; sink `inflight`
stays 0 at 6–7 k rows/s)."* The shape is still there: `SinkMeta`
(`crates/common/src/sink_meta.rs:111`) carries **four `String`s plus a `Vec<String>` per row**, of
which `batch_id` (`:125`), `source_schema` (`:129`), `source_table` (`:131`) and `sink_instance`
(`:137`) are **batch-constant**, and it is constructed at five production sites. What has changed
since PR 5.7 is the rest of this phase: PR 11.3 replaces the per-row `meta.batch_id =
self.batch_id.clone()` (`pg-sink/src/batch.rs:137`) with `clone_from`, which reuses the
destination allocation — i.e. it already removes most of what `Arc<str>` was going to remove. So
this ticket re-measures against a *moved* baseline and then either re-affirms the defer with a
number or takes the std-only `Arc<str>` half. `compact_str`, `smartstring` and `ecow` are absent
from `Cargo.lock`; `Arc<str>` has **0 uses** in the tree. Either way the compact-string dependency
count stays 0.

## Why — learning objectives

- **Inline/small-string layouts vs `Arc<str>` sharing** — `CompactString` keeps ≤23 bytes in the
  24-byte struct (no heap for short strings); `Arc<str>` keeps one heap copy and makes *clone* O(1).
  They solve different problems: walrus's strings are batch-**constant and cloned**, not short and
  numerous, so sharing is the relevant idiom and it needs no crate.
- **Read the project's own benchmark history before re-litigating a deferred optimisation** —
  `docs/benchmarks.md` records *why* PR 5.7 declined this, with the e2e evidence. A re-open must
  either beat that evidence or restate it with a fresh number.

## Scope

**In scope**

- Create `docs/implementation/notes/mem-compact-string-decision.md` from PR 11.13's template.
- Re-run the sink hot-path bench on the **current** tree (i.e. after PRs 11.3 and 11.6 landed):
  `cargo bench -p pg-to-arrow --bench batch` and record the `append_row` medians against the PR 5.7
  after-column (narrow_int4 460, wide30 814, text_heavy 616, tier2_fanout 837 ns/row).
- Land exactly **one** of two outcomes, and say which in the ADR's Status line:
  - **(a) Re-affirm the defer** — record the fresh number, restate the PR 5.6 system-level evidence,
    and note that PR 11.3's `clone_from` already reclaimed the per-row allocation.
  - **(b) Adopt the std-only `Arc<str>` half** — batch-constant fields become `Arc<str>`, no new
    dependency, no `cargo deny` exposure, and the measured delta is appended to
    `docs/benchmarks.md`. Only take this if the number justifies it *and* the serde cost below is
    paid consciously.
- Append a **"PR 11.16"** subsection to `docs/benchmarks.md`'s History either way — an honest null
  is a result, exactly as PR 5.7 item 2 and PR 5.8 item 2 recorded theirs.
- The ADR must price branch (b) explicitly: `Arc<str>` is only `Serialize`/`Deserialize` when
  serde's **`rc` feature** is enabled, so branch (b) is not free — it changes
  `crates/common/Cargo.toml` and puts a feature flag under a wire-contract type. Weigh that
  against a saving on a component the e2e ranking says is not the limiter.

**Explicitly deferred** (do *not* build these here)

- Restructuring `SinkMeta`'s serde output. The JSON keys and value shapes are a cross-service wire
  contract (architecture.md §1.4) and the amortized `{const,row}` splice from PR 5.7 must stay
  **byte-equivalent** — `amortized_meta_matches_full` is the test that proves it and it must pass
  unchanged.
- Adding `compact_str`, `smartstring` or `ecow`. None is in `Cargo.lock`; all three are new
  supply-chain surface for a component that is not the bottleneck. The count stays 0 in both
  branches.
- The other half of PR 5.7's item 3 — the ownership-taking `push` that would stop `to_vec()`ing the
  decoded values. That cascades into the sink's decode loop (`route` borrows `&Message`) and is an
  ownership change, not a string-layout one; leave it to Phase 9's `own-` work.
- Touching `unchanged_toast: Vec<String>` (`:135`). It is per-row and genuinely varying — the one
  string collection in `SinkMeta` that is *not* batch-constant.

**The conflict, and how to resolve it** — CONTEXT §4 bench-gates `mem-compact-string`. The
walrus-specific resolution is **stronger than "measure it"**, and the ADR must say so: PR 5.6's
e2e run shows the sink is provably not the system bottleneck (`walrus_sink_inflight_bytes` 0,
`spill_total` 0, at 6 250–6 886 rows/s, while the loader's lag climbs to 1.72–11.4 MB), so a
sink-side string-layout win is **low-leverage regardless of what the micro-benchmark says**. If
anything is taken at all, prefer std `Arc<str>` over a new crate. Do not apply the rule blindly.

## Hints & gotchas

- **`Arc<str>` is not serde-serializable by default.** serde implements `Serialize`/`Deserialize`
  for `Arc<T>` only under its **`rc`** feature, and the docs warn that deserialization does
  **not** preserve sharing (each `Arc` deserializes into its own allocation). Branch (b) therefore
  edits `crates/common/Cargo.toml`, not just the struct — price it in the ADR before you write any
  code.
- **Do not re-order `SinkMeta`'s fields.** The doc comment at `sink_meta.rs:107` says field order
  and keys are a cross-service wire contract; the loader reads them back by key, but the amortized
  `{const,row}` splice's byte-equivalence argument leans on the borrow structs carrying *identical
  field names and types*.
- `MetaConst<'a>` and `MetaRow<'a>` already hold `&'a str` / `&'a [String]` — the serialization path
  never owned those strings. That is why branch (b) changes construction sites and clone cost, and
  **not** the emitted JSON.
- **Measure after PR 11.3, not before.** `clone_from` reuses the destination `String`'s
  allocation, so the per-row `batch_id` cost on today's `main` is a memcpy, not a malloc. Quoting
  PR 5.7's numbers as if nothing changed would be the ADR's one fatal error.
- **Benches are never a CI gate** (shared runners are too noisy); CI only compile-checks them via
  `clippy --all-targets`. Run `just bench` (it covers `pg-sink` + `pg-to-arrow`) on a quiet machine
  and compare **deltas**, not absolutes against another machine's table.
- `stream_txn.rs:259` constructs `batch_id: String::new()` deliberately — spilled rows get their id
  when the spill batcher opens. Under branch (b) that becomes an empty `Arc<str>`; do not "fix" it
  into a real id.
- New deps must clear all four `cargo deny` families and the 8-id SPDX allow-list — which is exactly
  why the std-only `Arc<str>` is the preferred half if anything is taken at all.
- `unwrap`/`expect` are denied in production and `clippy::all` + `warnings` are `deny`; note that
  `Arc<str>` construction is `Arc::from("…")` / `.into()`, never `Arc::new(str)`.
- Tests are **sibling files** (`sink_meta_test.rs`, `batch_test.rs`), not inline `mod tests {}` —
  extend those if branch (b) needs coverage.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker locally to
  regenerate it. `SinkMeta` is serialized into a Parquet column, not into SQL, so nothing here
  requires it.
