# PR 11.2 — Ratchet the sizes of the per-row hot types with const assertions

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `common`, `pg-sink`, `pg-to-arrow` ·
> **Est. size:** S · **Depends on:** PR 11.1 · **Unlocks:** PR 11.3

`grep -rn 'size_of' crates/ tests/` returns **0** — there is not a single size assertion anywhere in
walrus. Every type walrus instantiates once per row or once per column is therefore completely
unguarded: modelled with rustc on a 64-bit target, `TupleValue` is 40 B, `PgColumn` 40 B,
`PgRelation` 80 B, `pgoutput::Message` 88 B, `DecodeError` 32 B and `pg_to_arrow::Error` ≥ 72 B.
Adding one `String` to any of them costs 24 B per instance and is **invisible in review** today.
After this PR each of those types carries a `const _: () = assert!(size_of::<T>() == N, "…")` next
to its definition, so growth becomes a compile error with a message that says why the size matters —
and the rest of Phase 11 (11.9 narrowing, 11.10 boxing, 11.11 `Box<[T]>`, 11.15's ThinVec
measurement) has a hard number to move.

## Why — learning objectives

- **Const-evaluated assertions** — `const _: () = assert!(…)` runs at compile time with no runtime
  cost, no test to run, and no new dependency; `#[cfg(target_pointer_width = "64")]` keeps it honest
  on a hypothetical 32-bit build instead of hard-coding a pointer width.
- **Which walrus types are per-row vs per-table** — `TupleValue`, `pgoutput::Message`, `SinkMeta`
  and `StreamedChange` are constructed for every decoded row; `TablePlan` and `PgRelation` are
  per-table. Only the first group earns a byte-level ratchet.

## Scope

**In scope**

- One `const _: () = assert!(size_of::<T>() == N, "…")` per type, placed immediately below the type
  definition, each gated `#[cfg(target_pointer_width = "64")]`.
- Cover at minimum: `common::TupleValue`, `common::PgColumn`, `common::PgRelation`,
  `pg_sink::pgoutput::Message`, `pg_sink::pgoutput::DecodeError`, `pg_to_arrow::Error`.
  `pg_sink::stream_txn::StreamedChange` is a welcome seventh.
- Each assertion's message states **why** the size is guarded (per row / per column / per
  single-byte read), not just the number.
- A one-paragraph doc comment on each guarded type pointing at the assertion, so the next person to
  add a field reads *why* before they hit the compile error.

**Explicitly deferred** (do *not* build these here)

- No field reordering and no `#[repr(...)]` changes — this PR only **observes and freezes** the
  current layout. Shrinking is 11.9 (`NonZero`/narrower integers), 11.10 (boxing the big variant)
  and 11.11 (`Box<[T]>`).
- No `static_assertions` dependency. The built-in `const _: () = assert!(…)` form is enough and adds
  nothing that must clear `cargo deny`'s advisory/licence/bans gates.
- The asserted numbers are **whatever the compiler reports on the merge commit**, not the modelled
  numbers quoted in this ticket. Measure, then write the number down.
- No runtime `#[test] fn sizes()` — a const assertion already fails the build; a test would only
  fail later and duplicate the guard.

## Skeleton

```rust
// crates/common/src/pg_shape.rs — directly under each definition.

/// One column value inside a TupleData (proto §5).
///
/// # Size
///
/// Constructed once per column per decoded row; the const assertion below freezes its width so a
/// new variant or a widened payload has to be an explicit decision (PR 11.2).
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum TupleValue {
    Null,
    UnchangedToast,
    Text(String),
    Binary(Bytes),
}

#[cfg(target_pointer_width = "64")]
const _: () = assert!(
    size_of::<TupleValue>() == 40,
    "TupleValue is built once per column per row — grow it only on purpose (PR 11.2)"
);
```

```rust
// crates/pg-sink/src/pgoutput/error.rs
#[cfg(target_pointer_width = "64")]
const _: () = assert!(
    size_of::<DecodeError>() == 32,
    "DecodeError sets the size of Result<u8, DecodeError> for every single-byte decoder read \
     (PR 11.2; narrowed in PR 11.9)"
);
```

```rust
// crates/pg-to-arrow/src/error.rs
#[cfg(target_pointer_width = "64")]
const _: () = assert!(
    size_of::<Error>() == 72,
    "Error is the Err half of append_row's per-row Result (PR 11.2; boxed down in PR 11.10)"
);
```

To discover the real `N` without guessing, drop this in temporarily — the compiler error names the
actual size, then delete it:

```rust
const _: [(); 0] = [(); size_of::<TupleValue>()];
// error[E0308]: expected `[(); 0]`, found `[(); 40]`   <-- 40 is the answer
```

## Hints & gotchas

- `size_of` is in the std prelude since Rust 1.80 and the MSRV is **1.95**, so no
  `use std::mem::size_of;` is needed — adding one would trip `unused_imports` under
  `warnings = "deny"`.
- Do **not** guess `N`. Use `const _: [(); 0] = [(); size_of::<T>()];`, read the size out of the
  `E0308` message, then write the real assertion. `cargo build -p <crate>` is enough — const
  assertions fire during compilation, not during `cargo test`.
- `pg_to_arrow::Error` inlines `arrow::error::ArrowError` and `parquet::errors::ParquetError`. Those
  crates are pinned to **exactly** `=54.3.1` in the workspace `Cargo.toml`, so the number is stable
  — but say in the message that an arrow/parquet bump may legitimately move it, and that PR 11.10
  is where the variant gets boxed.
- `pgoutput::Message` is `#[non_exhaustive]` and matched exhaustively in three crates. The assertion
  does not change that; it just makes the next variant's cost visible.
- Assertions must be **module-level items**, not inside a function. `const _: () = …` in an `impl`
  block is also fine, but next to the type reads best.
- Unit tests here are Go-style siblings (`pg_shape.rs` → `pg_shape_test.rs`). This PR adds **no**
  test — the guard is a compile-time item. Do not add an inline `#[cfg(test)] mod tests {}`.
- CI builds on 64-bit targets only, so the `cfg` gate never suppresses the guard in practice; it is
  there so a future 32-bit cross-build does not fail for a false reason.
- Do not touch any `.sql` file or the `.sqlx` offline cache (no Docker locally to regenerate it).
