# PR 11.4 — Write DDL SQL into the buffer instead of formatting a throwaway `String`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `loader`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 11.3 · **Unlocks:** PR 11.5

There are **9** `push_str(&format!(...))` sites in the repo — 8 in production (loader 6, pg-sink 2)
plus 1 in an integration test — and every one of them allocates a temporary `String` purely to copy
it into a buffer that is already being built. Clippy's restriction lint `format_push_string` reports
the same set. `crates/loader/src/ddl.rs:190` is the worst of them: it opens the batch buffer with
`String::new()` and then push-formats once per additive change, so an N-column `ADD COLUMN` batch
costs N throwaway allocations *plus* the buffer's own doubling ladder. After this PR every site
writes through `std::fmt::Write` into a buffer opened with `String::with_capacity`, the emitted SQL
is byte-for-byte identical (asserted by the existing `ddl_additive` / `ddl_destructive` /
`reload_export_test` suites), and `format_push_string = "deny"` keeps the pattern out.

## Why — learning objectives

- **`std::fmt::Write` vs `std::io::Write`** — `write!` picks its trait from the target type;
  `String` implements the `fmt` one, `Vec<u8>`/`File` the `io` one. Importing the wrong trait is the
  usual first compile error.
- **How the loader assembles additive-DDL batches for DuckDB** — the mirror `<table>` takes the
  exact shape while `<table>_raw` is an additive superset, so each change emits a *pair* of `ALTER`
  statements into one `execute_batch` string; getting that string byte-identical is the whole test
  surface.

## Scope

**In scope**

- `apply_additive`: `use std::fmt::Write as _;`, open `sql` with `String::with_capacity(...)` sized
  from `changes.len()`, and convert all six `push_str(&format!(...))` to `write!(&mut sql, ...)`.
- `continuation_sql`: same treatment for both sites; the `format!` that *creates* `sql` at line 514
  stays a `format!` (it is the initial value, not an append).
- `fmt_bytes` in `crates/pg-sink/tests/pgoutput_vectors.rs`: `write!(&mut s, "\\x{byte:02x}")`.
- `Cargo.toml`: add `format_push_string = "deny"` to `[workspace.lints.clippy]` with a comment
  noting it is a restriction lint (outside `all`), so no `priority` is needed.
- Byte-identical output. If any assertion in the DDL or reload-export tests has to change, the
  refactor is wrong.

**Explicitly deferred** (do *not* build these here)

- **No `.sql` file and no `.sqlx` offline-cache change.** There is no Docker on this machine to
  regenerate the cache. Only Rust-side string assembly changes here — the DuckDB DDL text and the
  reload-export SELECT text stay the same bytes.
- Do not convert `format!` calls that *produce* a returned `String` (e.g. `user_view_sql`,
  `ddl.rs:233`'s `lit`, `reload_export.rs:511/513`'s `map(...).collect()`); they have no existing
  buffer to write into. `mem-avoid-format` (PR 11.5) covers the label case; the rest stays.
- No SQL restructuring: same statements, same order, same quoting, same trailing `;`.
- Do not introduce a `String`-returning helper that hides the buffer — the point is to write into
  the caller's buffer.

## Skeleton

```rust
// crates/loader/src/ddl.rs
use std::fmt::Write as _;

pub fn apply_additive(
    conn: &duckdb::Connection,
    table: &str,
    changes: &[AdditiveChange],
) -> Result<(), LoaderError> {
    // Each change emits a mirror + a _raw statement, ~120 B together; one reservation for the batch.
    let mut sql = String::with_capacity(changes.len() * 128);
    let mut cur = table.to_string();
    let mut structural = false;
    for ch in changes {
        match ch {
            AdditiveChange::AddColumn(c) => {
                let ty = duck_type(c.type_oid);
                let name = &c.name;
                // `String`'s fmt::Write is infallible; `unwrap`/`expect` are denied workspace-wide
                // (PR 7.7), so discard the Ok(()) explicitly.
                let _ = write!(
                    &mut sql,
                    "ALTER TABLE \"{cur}\" ADD COLUMN IF NOT EXISTS \"{name}\" {ty}; \
                     ALTER TABLE \"{cur}_raw\" ADD COLUMN IF NOT EXISTS \"{name}\" {ty};"
                );
                structural = true;
            }
            AdditiveChange::RenameColumn { .. } => todo!("same shape"),
            AdditiveChange::WidenColumn { .. } => todo!("same shape"),
            AdditiveChange::RenameTable { .. } => todo!("same shape; keeps cur.clone_from(to)"),
            AdditiveChange::Comment { target, text } => todo!("two write! arms"),
        }
    }
    if structural {
        sql.push_str(&user_view_sql(&cur)); // returns an owned String — unchanged
    }
    if sql.is_empty() {
        return Ok(());
    }
    conn.execute_batch(&sql)
        .map_err(|e| LoaderError::Duck(format!("apply additive DDL to {table}: {e}")))
}
```

## Hints & gotchas

- Import the trait as `use std::fmt::Write as _;`. Without the `as _` you will collide with
  `std::io::Write` if a file already imports it; without the import at all you get
  "cannot write into `String`".
- `write!` returns `fmt::Result`, which is `#[must_use]`. `unwrap()`/`expect()` are **denied**
  workspace-wide (PR 7.7), so use `let _ = write!(...);` and say in a comment that `String`'s
  `fmt::Write` is infallible. Do **not** add an `#[allow(clippy::unwrap_used)]` to dodge this.
- Multi-line string continuations (`"… \` + newline + spaces) collapse leading whitespace exactly as
  they do today — keep the continuation backslashes where they are or the emitted SQL changes and
  the golden assertions fail.
- Inline format args (`{cur}`, `{name}`, `{limit}`) work in `write!` exactly as in `format!`; keep
  them, because `clippy::uninlined_format_args` is part of the denied set via pedantic-adjacent
  cleanups in Phase 33 and rewriting to positional args would regress.
- `key_cols.join(", ")` still allocates a `String` per call — that is a `format!`-free `Vec::join`
  and is out of scope here; do not try to fold it into the `write!`.
- The `Comment` arm's `lit` is built with `format!("'{}'", …)` and is a *value*, not an append —
  leave it.
- Do not touch `.sql` files or `.sqlx/` (no Docker locally to regenerate the offline cache).
- Unit tests are Go-style siblings (`reload_export.rs` → `reload_export_test.rs`); the loader DDL
  proof lives in `crates/loader/tests/`. Do not add inline `#[cfg(test)] mod tests {}`.
