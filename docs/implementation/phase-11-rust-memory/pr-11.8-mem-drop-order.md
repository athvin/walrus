# PR 11.8 — Tighten guard lifetimes and deny significant-drop lints

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 11 — Rust memory optimization · **Crates touched:** `pg-sink`, `loader` ·
> **Est. size:** M · **Depends on:** PR 11.7 · **Unlocks:** PR 11.9

`crates/pg-sink/src/reload_signal.rs:80` matches directly on `self.waiters.lock().remove(…)`, so the
`parking_lot::MutexGuard` is the **scrutinee temporary** and stays alive through the whole `match` —
across `tx.send(echo)` and two `tracing` events in the arms. Clippy's nursery reports
`significant_drop_in_scrutinee` at exactly this one site. `crates/loader/src/duck.rs:198` has the
same shape with a `RefCell` borrow held in an `if let` scrutinee while the matching `borrow_mut()`
sits three lines below at `:203` — safe today *only* because that `if let` has no `else` arm, i.e.
one added arm turns a compile-time-invisible change into a runtime `already borrowed` panic.
Production holds 5 `Mutex`es and 1 `RefCell`, zero crate-level drop-order guards, and
`[workspace.lints.clippy]` (`Cargo.toml:15`) denies neither significant-drop lint. After this PR
both sites bind their guard to a `let` that ends before the arm bodies, and the two lints are
`deny` so the shape cannot return.

## Why — learning objectives

- **Temporary lifetime in `match`/`if let` scrutinees** — a temporary created in the scrutinee lives
  until the end of the *whole* expression, not the end of the scrutinee; locals, by contrast, drop
  in reverse declaration order.
- **Why holding a lock across a `tracing` event or a channel send is a latency hazard** — the sink's
  echo path resolves a reload watermark while the decode loop is the only writer; every microsecond
  under the lock is a microsecond the exporter's subscribe can block.

## Read first

  table and the "prefer explicit `drop(x)`" guidance. **Skip** the `ManuallyDrop` section: it needs
  `unsafe`, and walrus has zero `unsafe` in production (see Scope).
- `crates/pg-sink/src/reload_signal.rs` — the module doc's two handshake rules, then `resolve`
  (`:67-99`). The cross-check log at `:71-78` runs *before* the lock is taken; keep it that way.
- `crates/loader/src/duck.rs:31-53` and `:195-212` — the `parquet_cols` `RefCell` field doc (why it
  is `RefCell` at all: DuckDB's `Connection` is `!Send`, one per apply worker on a `LocalSet`) and
  `columns_for`.
- `crates/loader/src/phase_a.rs:36-68` and `:248`/`:270` — the two `parking_lot::Mutex` fields on
  `TableCtx` and `pause_began`; useful as the *counter-examples* (statement-scoped guards that are
  already fine).
- `Cargo.toml:10-22` — the lint-as-policy block these two new lints join.

## Scope

**In scope**

- `reload_signal.rs:80`: bind the `remove` result to a `let` so the guard drops at the end of that
  statement, then `match` the binding. Behaviour, logs and metrics identical.
- `duck.rs:197-206`: lift the `RefCell` borrow out of the `if let` scrutinee — take the borrow, map
  to an owned `Arc` clone, drop the borrow, *then* branch. This also removes the latent
  borrow/borrow_mut hazard at `:203`.
- Add `significant_drop_in_scrutinee = "deny"` and `significant_drop_tightening = "deny"` to
  `[workspace.lints.clippy]` in `Cargo.toml`, and fix any further sites they surface.
- A short `// NOTE:` comment at each fixed site saying *why* the binding exists (the rule's
  "add a comment when the ordering is non-obvious" guidance) — otherwise the next reader
  "simplifies" it back.

**Explicitly deferred** (do *not* build these here)

- Reordering any struct's fields. `TableDb`'s declaration order (`conn`, then `parquet_cols`) is
  already correct: the cache holds only `Arc<Vec<String>>`, nothing that must outlive the
  connection, so the current order is fine and churning it would be noise.
- Introducing `ManuallyDrop` anywhere. It requires `unsafe` to drop through, and walrus has zero
  `unsafe` in production; the rule's example does not apply here.
- Converting `LoaderState::last_poll_completed_at` or `TableCtx`'s two mutexes to another primitive
  — their guards are already statement-scoped.

## Skeleton

```rust
// crates/pg-sink/src/reload_signal.rs — replacing the `match self.waiters.lock().remove(..)` at :80.
// NOTE: drop order matters — the guard is bound to a `let` so it is released at the end of THIS
// statement, not held across `tx.send(echo)` and the tracing events in the arms below.
let waiter = self.waiters.lock().remove(&(reload_id, chunk_no));
match waiter {
    Some(tx) => {
        if tx.send(echo).is_err() {
            tracing::debug!(reload_id, chunk_no, "echo resolved after waiter gave up");
        } else {
            tracing::info!(/* … unchanged … */);
        }
    }
    None => tracing::debug!(reload_id, chunk_no, "echo with no subscriber; dropped"),
}
```

```rust
// crates/loader/src/duck.rs — `columns_for` (:197), with the RefCell borrow lifted out of the
// `if let` scrutinee so it cannot overlap the `borrow_mut()` below.
fn columns_for(&self, uri: &str, schema_version: i64) -> Result<Arc<Vec<String>>, LoaderError> {
    // NOTE: drop order matters — the shared borrow ends with this statement, so the
    // `borrow_mut()` on the miss path can never overlap it (an added `else` arm would
    // otherwise panic at runtime, invisibly to the compiler).
    let hit = self.parquet_cols.borrow().get(&schema_version).map(Arc::clone);
    if let Some(cols) = hit {
        return Ok(cols);
    }
    let cols = Arc::new(self.parquet_columns(uri)?);
    self.parquet_cols
        .borrow_mut()
        .insert(schema_version, Arc::clone(&cols));
    Ok(cols)
}
```

```toml
# Cargo.toml — [workspace.lints.clippy], joining `all` / `unwrap_used` / `expect_used`.

# PR 11.8 made both sites explicit; denying keeps them that way.
significant_drop_in_scrutinee = "deny"
significant_drop_tightening = "deny"
```

## Hints & gotchas

- **The fix is a `let`, not a `drop()`.** `let x = expr_that_locks();` ends every temporary created
  inside `expr` at the semicolon. An explicit `drop(guard)` is only needed when you also want the
  *value* the guard protects.
- `significant_drop_tightening` is chattier than its sibling and may flag guards that are held
  legitimately (e.g. `phase_a::pause_began`, which reads *and writes* through one guard). Where the
  guard is genuinely required for the whole body, keep it and say so in the comment — do not split a
  read-modify-write into two lock acquisitions, which would be a real race.
- Both lints are **nursery**: they must be named individually in `[workspace.lints.clippy]`
  (`clippy::nursery` as a group is *not* enabled, and enabling it wholesale is out of scope).
- `parking_lot::MutexGuard` has no poisoning, so there is no `unwrap()` here to trip
  `clippy::unwrap_used` — keep it that way (`parking_lot` was promoted to a direct dep in PR 7.6
  precisely for this).
- `RefCell` is single-thread interior mutability: an overlapping `borrow()`/`borrow_mut()` is a
  **runtime panic**, not a compile error. That is the whole point of the `duck.rs` half of this PR.
- `Arc::clone(&x)` (not `x.clone()`) at the cache hit — it makes the cheap refcount bump obvious and
  keeps PR 11.7's `redundant_clone` deny happy.
- Tests are sibling files (`duck.rs` → `duck_test.rs`); do not add an inline `mod tests {}`.
- Do not touch any `.sql` file or the `.sqlx` offline cache — there is no Docker locally to
  regenerate it.
