# PR 19.6 — Lock in Clock's dyn compatibility with a compile-time guard and a Self: Sized gate

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 19 — Rust traits & generics · **Crates touched:** `pg-sink` · **Est. size:** S ·
> **Depends on:** PR 19.5 · **Unlocks:** PR 20.1

`Clock` is dyn-compatible today only *by accident of use*: the 7 `Arc<dyn Clock>` sites are the only
thing that makes the compiler check it — and PR 19.5 deleted all of them. There is no explicit guard
anywhere: `grep -rn -e 'Self: Sized' -e 'Box<dyn Clock>' crates/ tests/` returns **0**, and after
19.5 `grep -rn 'dyn Clock' crates/ tests/` also returns 0, so *nothing checks dyn compatibility at
all*. A contributor could add `fn sleep_until<D: Into<Duration>>(&self, d: D)` to the trait and
silently make it non-dyn-compatible; the breakage would surface much later, at some future `dyn` use
site, far from the edit that caused it. This PR restores the check on purpose: a `const _` assertion
next to the trait, a defaulted generic convenience method correctly gated `where Self: Sized`, and a
`Vec<Box<dyn Clock>>` test case — **0 → ≥ 2** matching sites, with an E0038 compile failure as the
regression gate.

## Why — learning objectives

- **Rust dyn-compatibility rules** — a method is vtable-dispatchable only if it has no generic type
  parameters, does not take or return bare `Self` by value, and is not an associated const. Break
  one and the *whole trait* stops being usable as `dyn Trait`.
- **`where Self: Sized` vtable gating** — the escape hatch: a gated method is excluded from the
  vtable, so the trait stays dyn-compatible while concrete callers still get the convenience method.
  This is how `std::io::Read::bytes` and friends coexist with `dyn Read`.
- **Const-item compile-time assertions** — `const _: fn(&dyn Clock) -> Instant = |c| c.now();`
  costs nothing at runtime, needs no dependency, and turns "someone might break this later" into a
  build error at the line that breaks it.
- **Keeping a test seam usable after production went static** — production dispatches `Clock`
  statically (PR 19.5), but an integration harness that wants to run the same assertions over
  several clocks still needs a heterogeneous collection. That is a legitimate `dyn` and it should
  keep compiling.

## Skeleton

```rust
// crates/pg-sink/src/batch.rs — the trait gains ONE defaulted, generic, gated method.

pub trait Clock: Send + Sync {
    /// REQUIRED and dispatchable: no generics, no bare `Self`, so it rides the vtable.
    fn now(&self) -> Instant;

    /// DEFAULTED convenience: the instant `after` from now — the `max_fill` cadence expressed as
    /// a deadline instead of an elapsed comparison. `None` if the clock is so close to `Instant`'s
    /// ceiling that the deadline would overflow (never panics — `checked_add`, not `+`).
    ///
    /// Generic, therefore **not dispatchable**; `where Self: Sized` keeps it out of the vtable so
    /// `Clock` stays usable as `dyn Clock`. Callers with a concrete clock get it for free.
    fn deadline<D: Into<Duration>>(&self, after: D) -> Option<Instant>
    where
        Self: Sized,
    {
        todo!("self.now().checked_add(after.into())")
    }
}

/// Dyn-compatibility guard. `Clock` has no production `dyn` use since PR 19.5, so nothing else
/// forces the compiler to check it; this const does, for free, at this line. Adding an **ungated**
/// generic method (or a bare-`Self` return, or an associated const) to `Clock` breaks the build
/// here with `error[E0038]` — which is exactly the intent.
const _: fn(&dyn Clock) -> std::time::Instant = |c| c.now();
```

## Hints & gotchas

- **Order matters.** This ticket assumes PR 19.5 already removed the 7 production `Arc<dyn Clock>`
  sites. If they are still there the probe reads 7, not 0, and the ticket has no before-state.
- `const _: fn(&dyn Clock) -> Instant = |c| c.now();` works because a **non-capturing** closure
  coerces to a function pointer in a const item. Keep it non-capturing; a capturing closure will not
  coerce.
- Naming `dyn Clock` *anywhere* is what triggers the E0038 check — the const is just the cheapest,
  most self-documenting place to name it. Do not "simplify" it to a comment.
- `const _` is anonymous, so it is never dead-code-warned and needs no `#[allow]`. Do not give it a
  name; a named const would be an unused item under `warnings = deny`.
- Use `checked_add`, not `Instant + Duration`. The `+` impl **panics** on overflow, and walrus
  production is panic-free by policy (zero `unwrap`, zero `panic!`, `unwrap_used`/`expect_used`
  denied by `[workspace.lints]`).
- `where Self: Sized` must be on the **method**, not on the trait. On the trait it would make
  `dyn Clock` impossible outright, which is the opposite of the goal.
- `Box::new(FakeClock::new())` is a `Box<Arc<FakeClock>>` — double indirection, and that is fine for
  a test. It relies on PR 19.4's `impl<T: Clock + ?Sized> Clock for Arc<T>`; leave the comment that
  says so.
- Unit tests are **Go-style sibling files** (`batch.rs` → `batch_test.rs` via
  `#[cfg(test)] #[path = "batch_test.rs"] mod tests;`), never an inline `mod tests {}`.
  `clippy.toml` re-allows `unwrap`/`expect` there; production still denies them.
- `clippy::all` + `warnings` are already `deny` workspace-wide, so an unused `Duration` import or an
  unreachable gated method is a hard error, not a warning.
- Any new dependency must clear `cargo deny` (advisories, the 8-license allow-list, bans) — which is
  precisely why `trybuild` is deferred. Do not touch any `.sql` file or the committed `.sqlx`
  offline cache.
