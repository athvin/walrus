# PR 19.1 — Give ArrowNumBuilder an associated Val type instead of a generic parameter

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-to-arrow

> **Phase:** 19 — Rust traits & generics · **Crates touched:** `pg-to-arrow` · **Est. size:** M ·
> **Depends on:** PR 18.13 · **Unlocks:** PR 19.2

`trait ArrowNumBuilder<T>` (`crates/pg-to-arrow/src/batch.rs:747`) is generic over the value type,
but **every one of its 5 impls** — generated by the `num_builder!` macro at `:763`–`:767` for
`Int16Builder`/`Int32Builder`/`Int64Builder`/`Float32Builder`/`Float64Builder` — binds exactly one
`T`. The parameter therefore buys nothing and costs a redundant second turbofish argument at all
**5 call sites** (`batch.rs:281`–`:285`, e.g. `append_num::<Int32Builder, i32>`) plus a duplicated
bound `B: ArrayBuilder + ArrowNumBuilder<T>, T: FromStr` at `:723`–`:724`. This is the rule's
textbook "one output per implementor" case: after this PR the trait carries `type Val: FromStr`,
`grep -c 'append_num::<[A-Za-z0-9]*Builder, '` drops **5 → 0**, and `grep -c 'ArrowNumBuilder<'`
drops **3 → 0**, with the Tier-1 golden vectors byte-identical.

## Why — learning objectives

- **Associated types vs generic trait parameters** — an associated type is part of the implementing
  type's *identity*: one `Val` per builder, so no caller ever names it. A generic parameter exists
  to allow *many simultaneous* impls on one type (`Add<f64>` and `Add<Vec2>` for `Vec2`); nothing
  here wants that.
- **`Self::Assoc` in a bound** — constraining `type Val: std::str::FromStr` **at the trait
  declaration** means `append_num` no longer repeats `T: FromStr`; `s.parse::<B::Val>()` just works.
- **Declarative-macro impl generation** — `num_builder!($b, $t)` moves the value type from the impl
  header (`impl ArrowNumBuilder<$t> for $b`) into the body (`type Val = $t;`); the macro shrinks and
  the five expansions stay one line each.
- **The pg-to-arrow Tier-1 text-format value path** — how a pgoutput `TupleValue::Text` becomes a
  typed Arrow column: `append_value` matches on the Arrow `DataType`, downcasts the erased
  `&mut dyn ArrayBuilder`, and parses the canonical Postgres text.

**In scope**

- Rewrite the trait as `trait ArrowNumBuilder { type Val: std::str::FromStr; … }` with `append_val`
  taking `Self::Val`.
- Rewrite `num_builder!` to emit `type Val = $t;` instead of `impl ArrowNumBuilder<$t>`. The five
  invocations at `:763`–`:767` keep their `($builder, $ty)` argument shape.
- Drop the `T` parameter from `append_num`, leaving `B: ArrayBuilder + ArrowNumBuilder`, and parse
  with `s.parse::<B::Val>()`.
- Update all 5 call sites in `append_value` to the single-argument turbofish
  `append_num::<Int32Builder>(…)`.
- Keep the error attribution identical: a parse failure still produces
  `Error::ValueParse { column, value, data_type }` with the same three fields.

**Explicitly deferred** (do *not* build these here)

- The `downcast!` macro (`batch.rs:250`) and every other append helper — `Decimal128Builder`,
  `StringBuilder`, `BinaryBuilder`, `Date32Builder`, `Time64MicrosecondBuilder`,
  `TimestampMicrosecondBuilder`, `FixedSizeBinaryBuilder`, and the Tier-2 range/geometric fan-outs.
  They do not go through `ArrowNumBuilder` and are out of scope.
- Erasing the `B: ArrayBuilder` downcast parameter. `Box<dyn ArrayBuilder>` per column is arrow-rs's

- Any `.sql` file or the `.sqlx` offline cache — this PR touches neither.
- Making the trait or `append_num` `pub`. Both are crate-private and stay that way.

## Skeleton

```rust
// crates/pg-to-arrow/src/batch.rs:746 — the trait, with the value type as an ASSOCIATED type.

/// Tiny bridge so `append_num` can be generic over the numeric builders. Each Arrow numeric
/// builder accepts exactly ONE Rust scalar, so the value type is an associated type — callers
/// never name it. `FromStr` is required here (not at every use site) because pgoutput ships
/// canonical text.
trait ArrowNumBuilder {
    /// The one scalar this builder appends.
    type Val: std::str::FromStr;

    fn append_val(&mut self, v: Self::Val);
    fn append_null_val(&mut self);
}

macro_rules! num_builder {
    ($b:ty, $t:ty) => {
        impl ArrowNumBuilder for $b {
            type Val = $t;
            fn append_val(&mut self, v: Self::Val) {
                todo!("self.append_value(v)")
            }
            fn append_null_val(&mut self) {
                todo!("self.append_null()")
            }
        }
    };
}
// Unchanged — the five invocations keep their (builder, scalar) shape.
num_builder!(Int16Builder, i16);
num_builder!(Int32Builder, i32);
num_builder!(Int64Builder, i64);
num_builder!(Float32Builder, f32);
num_builder!(Float64Builder, f64);
```

```rust
// crates/pg-to-arrow/src/batch.rs:715 — one type parameter instead of two, one bound instead of two.

/// Append a parsed number to a `FromStr` builder, attributing a failure to the column.
fn append_num<B>(
    builder: &mut dyn ArrayBuilder,
    value: &TupleValue,
    col: &str,
    dt: &DataType,
    is_null: bool,
) -> Result<(), Error>
where
    B: ArrayBuilder + ArrowNumBuilder,
{
    let b = builder
        .as_any_mut()
        .downcast_mut::<B>()
        .ok_or_else(|| Error::Downcast {
            column: col.to_string(),
        })?;
    if is_null {
        b.append_null_val();
    } else {
        let s = text(value, col, dt)?;
        // `B::Val: FromStr` comes from the trait declaration — no bound repeated here.
        let parsed = todo!("s.parse::<B::Val>() mapped to Error::ValueParse { column, value, data_type }");
        b.append_val(parsed);
    }
    Ok(())
}
```

## Hints & gotchas

- **The bound must live on the associated type, not on `append_num`.** Writing
  `type Val;` and then `where B::Val: FromStr` on the function works, but it re-creates the noise
  the rule is about. Put `: std::str::FromStr` in the trait declaration.
- `s.parse::<B::Val>()` needs the turbofish because `parsed`'s type is otherwise unconstrained; keep
  the existing `.map_err(|_| …)` — `<B::Val as FromStr>::Err` has no `Debug`/`Display` bound and you
  do not want to add one.
- `append_val` must take `Self::Val`, not `T`. Inside the macro body write `v: Self::Val` (or `$t` —
  both expand identically); `Self::Val` reads better and proves the point.
- `unwrap`/`expect` are **denied** in production by `[workspace.lints]`; the parse stays
  `.map_err(…)?`. `clippy.toml` re-allows them in `*_test.rs` only.
- Unit tests are **Go-style sibling files** (`batch.rs` → `batch_test.rs` via
  `#[cfg(test)] #[path = "batch_test.rs"] mod tests;`), never an inline `mod tests {}`. You should
  not need to touch either test file — if you do, the refactor changed observable behaviour.
- `clippy::all` and `warnings` are already `deny` at the workspace level and every member declares
  `[lints] workspace = true`, so a stray unused type parameter is a hard error, not a warning.
- No new dependency is needed. Any dep you add must clear `cargo deny` (advisories, the 8-license
  allow-list, bans) — a bad trade for a signature cleanup.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache; there is no Docker on this
  machine to regenerate it.
