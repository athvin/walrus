# PR 19.4 — Blanket-impl Clock for Arc<T> and &T so shared clocks satisfy a Clock bound

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 19 — Rust traits & generics · **Crates touched:** `pg-sink` · **Est. size:** S ·
> **Depends on:** PR 19.3 · **Unlocks:** PR 19.5

The tree has **two type-generic impls in production**: `grep -rEn '^impl<[A-Z]' crates/*/src` minus
`*_test.rs` returns the loader's `DuckResultExt<T>` and `DuckTable<K>` impls. It also has ten
lifetime-only generic headers (4 × `impl<'de> Deserialize`, 6 × `impl<'a>`). Meanwhile `Clock`
(`crates/pg-sink/src/batch.rs:44`) is **always** held behind an `Arc` — 23
`Arc::new(SystemClock)` sites in the workspace (1 production, 22 in tests), and the test fake's constructor
(`batch_test.rs:15`) itself returns `Arc<Self>`. Without `impl<T: Clock + ?Sized> Clock for Arc<T>`
none of those handles can satisfy a `C: Clock` bound — which is exactly why the standard library
writes `impl<R: Read + ?Sized> Read for &mut R`. Because `Clock` is sealed, each wrapper also needs
a local `private::Sealed` marker impl before its delegating `Clock` impl is legal. This PR adds those
four wrapper impls (**2 → 6**) plus a compile-proof test; it changes no field type and no signature,
and it is what makes PR 19.5's static-dispatch conversion a mechanical rename instead of a 23-site
rewrite.

## Why — learning objectives

- **Blanket / delegating impls** — `impl<T: Clock> Clock for Arc<T>` extends a whole class of types
  (every smart-pointer wrapper around a clock) in one item, rather than one impl per concrete
  clock. This is the mechanism behind `ToString for T: Display` and `Read for &mut R`.
- **`?Sized` bounds** — without `+ ?Sized` the impl silently excludes `Arc<dyn Clock>`, because the
  implicit `Sized` bound on a type parameter rejects an unsized `dyn`. That single token is the
  difference between "works for the code we have" and "works for the code we have *today*".
- **Coherence forbids overlapping impls** — a blanket `impl<T: Clock> Clock for T` would collide
  with `impl Clock for SystemClock` (E0119); stable Rust has no specialization. Targeting the
  *wrapper* types (`Arc<T>`, `&T`) is precisely how you get the reuse without the overlap.
- **The injectable-clock test seam** — how `FakeClock` lets `TableBatcher::should_flush` prove the
  `max_fill` cadence trigger without a real `sleep`, and why that seam is the trait's whole reason
  to exist.

**Conflict — read before applying the rule.** Blanket impls and per-type impls **cannot overlap**
(E0119; stable Rust has no specialization). `impl Clock for SystemClock` at `batch.rs:54` must stay,
so the new impls must target only the wrapper types `Arc<T>` and `&T` — **never** a bare
`impl<T: …> Clock for T`. The existing private seal must remain in force, so implement
`private::Sealed` only for the two wrapper shapes too. If you write the bare `Clock` form the build breaks immediately with
"conflicting implementations of trait `Clock` for type `SystemClock`".

## Skeleton

```rust
// crates/pg-sink/src/batch.rs — immediately after `impl Clock for SystemClock` (:54-58).

/// Delegating impls so a **shared** or **borrowed** clock still satisfies a `C: Clock` bound —
/// the std pattern (`impl<R: Read + ?Sized> Read for &mut R`). Every walrus clock is held behind
/// an `Arc` (the batchers share one), so without these the generic form is unusable.
///
/// `?Sized` is load-bearing: it keeps `Arc<dyn Clock>` covered. Both Clock impls target the *wrapper*
/// type — a bare `impl<T: Clock> Clock for T` would collide with `impl Clock for SystemClock`
/// (E0119: no specialization on stable).
impl<T: Clock + ?Sized> private::Sealed for std::sync::Arc<T> {}

impl<T: Clock + ?Sized> Clock for std::sync::Arc<T> {
    fn now(&self) -> Instant {
        todo!("(**self).now()")
    }
}

impl<T: Clock + ?Sized> private::Sealed for &T {}

impl<T: Clock + ?Sized> Clock for &T {
    fn now(&self) -> Instant {
        todo!("(**self).now()")
    }
}
```

## Hints & gotchas

- **`?Sized` is not optional.** Every type parameter has an implicit `Sized` bound; drop `?Sized`
  and `Arc<dyn Clock>` (which still exists in 7 places until PR 19.5) stops satisfying the impl,
  and PR 19.6's `Box<dyn Clock>` case would never compile.
- `Clock: Send + Sync`, so the compiler checks the supertraits on the new impls too. They hold:
  `T: Clock` ⇒ `T: Send + Sync`, and `Arc<T>`/`&T` are `Send + Sync` exactly when `T` is.
- Write the body as `(**self).now()` for `Arc<T>` — `self` is `&Arc<T>`, so one deref reaches the
  `Arc` and the second the `T`. Plain `self.now()` inside the impl is **infinite recursion**;
  clippy's `unconditional_recursion` will catch it, but write it right the first time.
- Use the same `(**self).now()` body for `&T`: the method receiver is `&&T`, so both dereferences
  are needed to delegate to `T` rather than recurse through the new reference impl.
- Do not add `impl<T: Clock> Clock for T`. E0119 fires against `impl Clock for SystemClock`, and
  the error text points at the blanket impl, not the specific one, which reads confusingly.
- `FakeClock::new()` already returns `Arc<Self>` (`batch_test.rs:15`) — leave it alone. The point of
  the new test is that the `Arc` wrapper is now transparent to a bound.
- Unit tests are **Go-style sibling files** (`batch.rs` → `batch_test.rs` via
  `#[cfg(test)] #[path = "batch_test.rs"] mod tests;` at `batch.rs:243-245`), never an inline
  `mod tests {}`. `clippy.toml` re-allows `unwrap`/`expect` there; production still denies both.
- `clippy::all` + `warnings` are already `deny` workspace-wide, so an unused generic parameter or a
  stray `mut` is a hard error, not a warning.
- No new dependency is needed; anything added must clear `cargo deny` (advisories, 8-license
  allow-list, bans). Do not touch any `.sql` file or the committed `.sqlx` cache.
