# PR 19.3 — Complete the orphan-rule newtypes with repr(transparent) and round-trip accessors

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 19 — Rust traits & generics · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 19.2 · **Unlocks:** PR 19.4

`UtcTimestamp(jiff::Timestamp)` (`crates/common/src/sink_meta.rs:47`) is a textbook orphan-rule
wrapper — a foreign type carrying foreign traits `Serialize` (`:91`) and `Deserialize` (`:98`) —
but it is incomplete against the rule's key points: the tree has **zero `#[repr(transparent)]`**
(`grep -rn 'repr(transparent)' crates/ tests/ | wc -l` → **0**), and `UtcTimestamp` exposes no
`Display`, no `From<jiff::Timestamp>`, and no `inner()`/`into_inner()`, so the wrapped instant is
unreachable outside serde. Worse, `Lsn(u64)` (`lsn.rs:19`) and `ManifestId(pub i64)` (`ids.rs:12`)
hand-write sqlx `Type`/`Encode`/`Decode` impls that **explicitly rely on layout** — `ids.rs:33`
literally calls it "the transparent-newtype trick" — without asserting it anywhere. After this PR
the count is **0 → 3**, the layout claim is a compile-time attribute plus a `size_of` test, and
`UtcTimestamp` round-trips through `From`/`into_inner` with a `Display` that is byte-identical to
what `Serialize` emits.

## Why — learning objectives

- **The orphan rule** — `impl Serialize for jiff::Timestamp` is rejected (E0117: both are foreign);
  wrapping in a local newtype makes the impl legal because the *type* is now local. That is the
  only reason `UtcTimestamp` exists.
- **`#[repr(transparent)]`** — guarantees the wrapper has the same size, alignment and ABI as its
  single non-ZST field. It is what makes "encode exactly as the inner `i64`" a *language*
  guarantee rather than a comment.
- **`From` / `into_inner` round-tripping** — the rule's ergonomics point: a newtype that you can
  only put values *into* is a one-way trap. `From<Inner> for Wrapper` + `From<Wrapper> for Inner`
  (or `into_inner()`) makes the wrapper free to adopt.
- **walrus's UTC-`Z`-only datetime invariant** — every walrus-stamped datetime is UTC RFC-3339 with
  a `Z` suffix, and the `walrus_pg_sink_meta` JSON is a cross-service wire contract the loader
  parses back verbatim.

## Scope

**In scope**

- Add `#[repr(transparent)]` to exactly three newtypes: `Lsn` (`lsn.rs:19`), `UtcTimestamp`
  (`sink_meta.rs:47`), `ManifestId` (`ids.rs:12`), each with a one-line comment saying *why* (the
  hand-written sqlx `Encode`/`Decode` and the serde adapter depend on the inner value's identity).
- `UtcTimestamp` gains:
  - `impl fmt::Display` delegating to the inner `jiff::Timestamp`'s `Display`,
  - `impl From<jiff::Timestamp> for UtcTimestamp` (infallible — a `jiff::Timestamp` is *already* a
    UTC instant with no offset to lose),
  - `impl From<UtcTimestamp> for jiff::Timestamp`,
  - `inner(&self) -> &jiff::Timestamp` and `into_inner(self) -> jiff::Timestamp`.
- Sibling-test assertions:
  - `sink_meta_test.rs` — `size_of::<UtcTimestamp>() == size_of::<jiff::Timestamp>()`; a
    `UtcTimestamp → jiff::Timestamp → UtcTimestamp` round-trip through the new `From`/`into_inner`;
    and **`Display` agrees with `Serialize`** (see the conflict note below).
  - `ids_test.rs` — `size_of::<ManifestId>() == size_of::<i64>()`.
  - `lsn_test.rs` — `size_of::<Lsn>() == size_of::<u64>()`.

**Explicitly deferred** (do *not* build these here)

- Sealing `ManifestId(pub i64)`'s public field behind `new()`/`get()`. That is `api-newtype-safety`
  in Phase 13; changing it here would touch every `ManifestId(…)` construction site.
- Replacing the **12** `#[serde(with = "humantime_serde")]` `Duration` escape hatches with a local
  `HumanDuration` newtype. Measure it and decline in the PR body: `humantime_serde` is an
  idiomatic serde *adapter* on a `std` type walrus fully controls — a newtype would buy nothing and
  cost a `.0` at every config read.
- Any `.sql` file or the `.sqlx` offline cache. The sqlx `Type`/`Encode`/`Decode` impls for `Lsn`
  and `ManifestId` are hand-written **Rust** — this PR does not regenerate anything.
- `#[repr(transparent)]` on any other type. Only these three have a layout-dependent claim to
  assert.

**Conflict — read before applying the rule.** The rule says "implement `Display`", but walrus has a
harder constraint: `Display for UtcTimestamp` **must emit exactly what `Serialize` emits** — jiff's
RFC-3339 `Z` form. The JSON keys and value shapes in `walrus_pg_sink_meta` are a cross-service wire
contract (`sink_meta.rs:9-12`, architecture.md §1.4), so a second, independently-written formatter
is a latent divergence. Delegate to the inner value's `Display` (which is exactly what
`Serialize`'s `collect_str(&self.0)` already does) and **assert the two agree in the test** rather
than writing formatting logic twice. Note also that `Lsn`'s `Display` is *not* its inner value's —
do not "harmonise" it; the padded 16-hex form is the ordering contract.

## Hints & gotchas

- `#[repr(transparent)]` requires **exactly one** field of non-zero size (the rest must be ZSTs).
  All three qualify. If you later add a second real field, the attribute becomes a compile error —
  that is the point.
- The attribute must go on the `struct`, and it composes with `#[derive(...)]` in any order;
  `rustfmt` will place it above the derives.
- `sink_meta.rs` does not currently import `std::fmt`. Add `use std::fmt;` (the file uses
  `serde::{…}` today) or fully qualify — `cargo fmt --check` and the `warnings = deny` lint will
  catch an unused import if you overshoot.
- Do **not** implement `Deref<Target = jiff::Timestamp>` as a shortcut for `inner()`. Deref on a
  newtype leaks the whole inner API and re-opens exactly the "caller emits a non-UTC form" hole the
  wrapper closes.
- `Lsn::Display` renders **padded 16-hex**, not the inner `u64` — its transparency claim is about
  *layout* (sqlx binding), not about text. Do not add a `Display`-agrees-with-inner assertion for
  `Lsn`; that would be false and wrong.
- `assert_eq!(size_of::<A>(), size_of::<B>())` is a *runtime* check in a sibling test. That is
  deliberate and cheap; a `const` assertion is not needed here and `static_assertions` would be a
  new dependency that must clear `cargo deny` (advisories, 8-license allow-list, bans).
- `unwrap`/`expect` are denied in production but re-allowed in `*_test.rs` by `clippy.toml`, so the
  `parse_rfc3339("…").unwrap()` in the new tests is fine — in `sink_meta.rs` itself it would not be.
- Unit tests are **Go-style sibling files** (`sink_meta.rs` → `sink_meta_test.rs`), never an inline
  `mod tests {}`. All three test files already exist; just add cases.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it, and nothing here needs it.
