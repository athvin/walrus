# PR 19.5 — Dispatch the sink clock statically and document why the remaining dyn stays dyn

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 19 — Rust traits & generics · **Crates touched:** `pg-sink` · **Est. size:** L ·
> **Depends on:** PR 19.4 · **Unlocks:** PR 19.6

The broad `dyn Clock` probe has exactly **8 production-source hits and 0 test sites**: seven are
executable field/parameter types and the eighth is PR 19.4's `?Sized` documentation. `Clock` still
has only one concrete production implementation (`SystemClock`) and one test fake — the rule's Bad
case, *"unnecessary boxing when only one concrete type is used"*, sitting on a per-row hot path
(`should_flush` runs at every commit boundary). Four structs carry the vtable: `TableBatcher`
(`batch.rs:109`), `BatchRouter` (`consume.rs:667`), `Backfill` (`snapshot.rs:151`, which hardcodes
`Arc::new(SystemClock)` at `:189`) and `StreamDemux` (`stream_txn.rs:109`). This PR threads a `C`
type parameter through all four and through the current `DecodeLoop` wiring, taking the broad
`dyn Clock` count **8 → 0** and executable type sites **7 → 0**. By contrast the other **22** `dyn`
executable uses are *correct* and stay:
`Arc<dyn ObjectStore>` (the backend is chosen from config at runtime) and `Box<dyn ArrayBuilder>`
(one heterogeneous builder per column) — this PR records a decision table saying so, so the next
reader does not "clean them up" too.

## Why — learning objectives

- **Monomorphisation vs vtable dispatch** — a generic `C: Clock` gets one specialised copy per
  concrete clock the binary actually uses (exactly one, in production), inlinable to nothing;
  `Arc<dyn Clock>` is a fat pointer with an indirect call per `now()`. The trade is binary size,
  which is negligible at one instantiation.
- **Threading a generic parameter through owning structs** — the mechanical part: the field type,
  the struct header, every `impl` block, and every free function that *names* the struct. Getting
  the bound placement right (`impl<C: Clock>`, not on the struct) is the idiomatic form.
- **`impl Trait` in argument position** — already used 20+ times in `control` as
  `impl PgExecutor<'_>`; it is the same monomorphisation as a named `C`, and it is what you reach
  for when the parameter appears exactly once.
- **The pg-sink batching hot path** — per-table batchers, commit-boundary sealing, and the
  `max_fill` cadence trigger: the only thing the clock is *for*.

## Hints & gotchas

- **Do this in dependency order or you will fight the compiler:** `TableBatcher` first, then
  `BatchRouter` and `StreamDemux` (both hold or create batchers), then `Backfill`, then
  `DecodeLoop`/`DecodeLoopBuilder`, then `shutdown::drain`. `main.rs` must compile unchanged.
- **Bounds belong on the `impl`, not the `struct`.** `pub struct TableBatcher<C>` + `impl<C: Clock>
  TableBatcher<C>` means every *other* place that merely names the type
  (`HashMap<u32, TableBatcher<C>>`, a `&mut BatchRouter<C>` parameter) does not have to repeat the
  bound. Putting `C: Clock` in the struct header forces the repetition everywhere.
- `BatchRouter`, `StreamDemux` and `Backfill` need `C: Clone` because they hand a clock to each new
  `TableBatcher` (`consume.rs:796`, `stream_txn.rs:237` and `:431`, `snapshot.rs:221`).
  `Arc<SystemClock>` is `Clone`; that is the whole reason PR 19.4 blanket-impls `Arc<T>` rather than
  `Box<T>`.
- `Backfill::connect` must stay in an `impl Backfill<Arc<SystemClock>>` block (**not** a defaulted
  type parameter). Rust does not use type-parameter defaults for inference in an expression path, so
  `Backfill::connect(…)` at `main.rs:312` resolves only because that inherent impl pins `C`.
- The old `run_decode_loop` free function has been replaced by `DecodeLoop` and its builder. Thread
  one `C` through both references: `main.rs` passes `Arc::new(SystemClock)` to router and demux, so
  two clock parameters would be noise.
- Deriving `Default` for a generic builder can introduce an unnecessary `C: Default` bound. Preserve
  the existing public `Default` capability with a manual all-`None` implementation, and name
  `C = Arc<SystemClock>` explicitly only in the empty-builder unit regression where no setter can
  otherwise infer it.
- The 25 files under `crates/pg-sink/tests/` are **integration** tests: they see only the public
  API, so any type you make generic must stay `pub` with a `pub` constructor. Several are
  compose-gated behind the `integration` feature — run
  `cargo clippy --all-targets --all-features` to compile them all.
- Do not "simplify" `Arc<CachedRelation>` or `Arc<dyn ObjectStore>` while you are in there. The
  first is real sharing; the second is the decision table's dynamic row.
- `unwrap`/`expect` are denied in production by `[workspace.lints]`; `clippy::all` + `warnings` are
  `deny` workspace-wide, so an unconstrained or unused `C` is a hard error.
- No new dependency is needed; anything added must clear `cargo deny` (advisories, 8-license
  allow-list, bans). Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is
  no Docker on this machine to regenerate it.
