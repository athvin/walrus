# PR 15.1 — Replace SeqCst with the weakest correct ordering on the health and reload atomics

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 15 — Rust concurrency · **Crates touched:** `loader`, `pg-sink` · **Est. size:** M ·
> **Depends on:** PR 14.18 · **Unlocks:** PR 15.2

Production Rust today carries **17 `Ordering::SeqCst` sites** (`loader/src/health.rs` 6,
`pg-sink/src/health.rs` 8, `pg-sink/src/reload.rs` 3), **2 `Ordering::Relaxed`**, and **zero**
`Acquire`/`Release`/`AcqRel`. Every one of those SeqCst sites is either an independent boolean/`u8`
latch read by an axum probe handler or a single-variable publish/observe handoff — none of them
needs a single total order *across multiple atomics*, which is the only thing SeqCst actually buys.
After this PR every atomic operation in the tree states the weakest ordering that is still correct,
each with a one-line comment naming the operation it pairs with, so the next reader can check the
reasoning instead of inheriting a blanket default.

## Why — learning objectives

- **The C11 memory model in Rust** — `Relaxed` vs an `Acquire`/`Release` pair vs the (rare) case
  where `SeqCst` is genuinely required.
- **Kubernetes probe semantics** — why the loader/sink readiness latches are independent flags
  rather than a coordinated protocol, and what that buys you at the atomic level.

## Read first

- [`conc-atomic-ordering`](../../../.claude/skills/rust-skills/rules/conc-atomic-ordering.md) — take
  the four-row ordering table and the rule's central test: `SeqCst` is only justified when you need
  *one global order observed by all threads across multiple atomic variables*. Ignore the `loom`
  section — loom is deliberately out of scope here (see **Scope**).
- `crates/loader/src/health.rs:20-80` — `LoaderState`: `ready` + `quarantined` (`AtomicBool`) plus
  the `parking_lot::Mutex<Option<Instant>>` progress stamp. Read the module doc: `/ready` is
  deliberately *not* gated on lag, and `quarantined` is a latch with exactly one exit.
- `crates/pg-sink/src/health.rs:22-92` — `HealthState`: `phase` (`AtomicU8`, `PHASE_BOOTSTRAPPING` /
  `PHASE_READY`), `terminating`, `degraded`, `live`. The doc comment on `set_degraded` is the key
  fact: `degraded` is *reported, never gating*.
- `crates/pg-sink/src/reload.rs:158-201` (`export_with_ddl_restarts`) and
  `crates/pg-sink/src/reload.rs:405-485` (`spawn_exporter`) — the `Arc<AtomicI64>` reload-id shared
  between the export loop (which repoints it on a DDL restart, line 191) and the lease-renewal
  closure (which reads it, line 454). Also read `lease_guarded_export` at line 64.
- `crates/pg-sink/src/reload_signal.rs:69,103` — the two `Ordering::Relaxed` sites that already
  exist (a violation counter). They are the reference for "counter ⇒ Relaxed" and are **not**
  changed by this PR.

Rewrite all 17 production `Ordering::SeqCst` arguments to the mapping below. Every changed line gets

## Skeleton

The change is mechanical, so the skeleton is the target shape rather than `todo!()` bodies; the
`todo!()` markers sit on the two decisions you actually have to make and defend.

```rust
// crates/loader/src/health.rs

impl LoaderState {
    /// Bootstrap finished: leases held + files open → `/startup` and `/ready` answer 200.
    pub fn mark_ready(&self) {
        // Release: publishes everything bootstrap did (leases, open .duckdb files, first
        // stamp_poll) to any handler that observes `ready == true` via the Acquire loads below.
        self.ready.store(true, Ordering::Release);
    }

    pub fn is_started(&self) -> bool {
        self.ready.load(Ordering::Acquire) // pairs with mark_ready's Release store
    }

    pub fn is_ready(&self) -> bool {
        // Two independent atomics read back-to-back: a probe answer is a snapshot, not a
        // protocol, so no single total order across them is required (that is the SeqCst case).
        self.ready.load(Ordering::Acquire) && !self.is_quarantined()
    }

    pub fn quarantine(&self) {
        todo!("Release store + a comment naming what a reader that sees `true` must also see")
    }

    pub fn clear_quarantine(&self) {
        self.quarantined.store(false, Ordering::Release); // publishes the completed PR 6.7 rebuild
    }

    pub fn is_quarantined(&self) -> bool {
        self.quarantined.load(Ordering::Acquire) // pairs with both stores above
    }
}
```

```rust
// crates/pg-sink/src/health.rs

impl HealthState {
    pub fn mark_ready(&self) {
        self.phase.store(PHASE_READY, Ordering::Release); // publishes bootstrap completion
    }

    pub fn mark_terminating(&self) {
        self.terminating.store(true, Ordering::Release); // publishes "SIGTERM seen; loop draining"
    }

    /// High lag / stale heartbeat → surfaced on readiness+health, **never** a liveness kill.
    pub fn set_degraded(&self, degraded: bool) {
        // Relaxed: report-only. Nothing is gated on it and no other write is published through it.
        self.degraded.store(degraded, Ordering::Relaxed);
    }

    pub fn set_live(&self, live: bool) {
        self.live.store(live, Ordering::Relaxed); // independent deadlock latch; no payload
    }

    pub fn phase(&self) -> Phase {
        match self.phase.load(Ordering::Acquire) { // pairs with mark_ready
            PHASE_READY => Phase::Ready,
            _ => Phase::Bootstrapping,
        }
    }

    pub fn is_ready(&self) -> bool {
        self.phase() == Phase::Ready && !self.terminating.load(Ordering::Acquire)
    }

    pub fn is_live(&self) -> bool {
        self.live.load(Ordering::Relaxed)
    }

    pub fn is_degraded(&self) -> bool {
        self.degraded.load(Ordering::Relaxed)
    }
}
```

## Hints & gotchas

- **The `Arc<AtomicI64>` handoff is currently intra-task, and you should say so.**
  `lease_guarded_export` (`reload.rs:64-94`) drives the export future and the renewal closure in one
  `tokio::select!` inside a *single* task, so the store at `:191` and the load at `:454` never
  actually run concurrently — the `.await` boundary already establishes happens-before even if tokio
  migrates the task between worker threads. `Release`/`Acquire` here documents the *intended*
  contract (single-variable publish/observe) and stays correct the day someone moves renewal to its
  own `tokio::spawn`. Put that sentence in the code comment; do not claim a race that isn't there.
- **`Relaxed` is a legitimate answer, but it owes a comment.** If you convince yourself that a latch
  publishes nothing (`degraded`, `live` — and arguably `terminating`), `Relaxed` is the weakest
  *correct* choice and the rule is satisfied. The DoD only requires the Acquire/Release-family count
  to stay **≥ 12**, which the `ready` / `quarantined` / `phase` / reload-id pairs already deliver.
  What is *not* acceptable is an ordering without a stated reason.
- **`is_ready()` reads two atomics — resist the urge to keep SeqCst there.** SeqCst would buy a
  single total order across `ready` and `quarantined`, and nothing in the design needs one: an HTTP
  probe answer is a point-in-time snapshot, and both flags are already documented as independent.
- **Never weaken to `Relaxed` on a store whose *purpose* is to make earlier writes visible.**
  `mark_ready` is the canonical example: bootstrap opened files and stamped a `parking_lot::Mutex`
  before it; a `Relaxed` store would leave a reader entitled to see `ready == true` with none of it.
- `parking_lot::Mutex` (used for `last_poll_completed_at`) already provides
  `Acquire`/`Release` internally — do not add atomics around it.
- `clippy::all` + `warnings` are already `deny` at the workspace level, and `unwrap`/`expect` are
  denied in production; this PR touches neither, but a stray `use std::sync::atomic::Ordering::*`
  would trip the enabled-by-default lints. Keep the existing `Ordering::` qualified form.
- Unit tests here are **sibling files** (`health.rs` → `health_test.rs` via
  `#[cfg(test)] #[path = "health_test.rs"] mod tests;`), never inline `mod tests {}`.
- No `.sql` file or the `.sqlx` offline cache is involved — there is no Docker on this machine to
  regenerate the cache, so do not let a refactor drift into `control/sql/**`.
