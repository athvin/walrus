# PR 15.2 — Reuse a thread-local scratch buffer in the Arrow temporal parse path

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 15 — Rust concurrency · **Crates touched:** `pg-to-arrow` · **Est. size:** M ·
> **Depends on:** PR 15.1 · **Unlocks:** PR 15.3

There are **0 `thread_local!` declarations and 0 `static mut` items** anywhere in the repo, so the
rule's anti-pattern (`static mut` + `unsafe`) does not exist here — but the *technique* is genuinely
motivated. `pg-to-arrow` is a pure sync library (no tokio dependency; `Cargo.toml` lists
arrow/parquet/jiff/hex/uuid and nothing async), and its four temporal free functions allocate a
throwaway `String` per cell at `batch.rs:857, 863, 868, 869, 874` — **5 allocation sites** — for
exactly one reason: they are free functions with no `&mut self` on which to hang a buffer. The paths
that *do* have one already use the struct-field pattern (`BatchBuilder::meta_buf`, `batch.rs:82`).
`docs/benchmarks.md` names the per-cell `String` allocation as the dominant decode cost. After this
PR a single `thread_local! { RefCell<String> }` serves all four parsers, and the bench suite finally
has a `temporal` shape so the claim is a number instead of an assertion.

## Why — learning objectives

- **`thread_local!` + `RefCell` + `with_borrow_mut`** — and why a per-thread scratch buffer is safe
  only inside a fully synchronous call, with no `.await` between borrow and release.
- **Arrow batch building** — per-cell text→typed parsing is the CDC hot path, and allocation
  dominates it for wide and text-heavy shapes.

## Scope

**In scope**

1. Declare exactly one `thread_local!` in `crates/pg-to-arrow/src/batch.rs`: a
   `RefCell<String>` scratch, pre-sized for the longest canonical Postgres temporal literal, with a
   doc comment stating *why it is safe here* (pure sync crate, no `.await` can straddle the borrow).
2. Rewrite all four temporal parsers to normalise into that buffer instead of allocating. The
   `rfc3339_micros(&str) -> Option<i64>` call shape stays exactly as it is.
3. Add a fifth bench shape `Shape::Temporal` (`date` + `time` + `timestamp` + `timestamptz`) to
   `crates/pg-to-arrow/benches/batch.rs`, widening `SHAPES` to `[Shape; 5]`.
4. Add sibling unit tests in `crates/pg-to-arrow/src/batch_test.rs` proving the buffer is cleared
   between calls and that interleaving the four parsers on one thread produces correct results.
5. Record the measurement in `docs/benchmarks.md`: a `temporal` row in the Arrow baseline table and
   a `### PR 15.2` subsection under `## History` with the before/after medians.

**Conflict — read this before you start.** CONTEXT §4's bench-gated resolution
(`anti-premature-optimize` + `perf-profile-first`, rules from this same corpus) applies **in spirit
even though no dependency is added**: the existing pg-to-arrow bench shapes contain no date or
timestamp column at all (`benches/batch.rs:61-95`), so the temporal path is currently *unmeasured*.
The required order of work is therefore:

1. Land the `temporal` bench shape **first** and run it against the current, allocating parsers.
   Record that median — it is the baseline.
2. Then apply the `thread_local!` rewrite and re-run.
3. **If the median does not move, keep the `thread_local!` anyway** — practising the technique is the
   point of this ticket — but write the honest measurement into `docs/benchmarks.md`. Do *not* claim
   a win the numbers do not show. "No measurable delta at 1 000 rows/iteration" is a legitimate,
   publishable result and is exactly what `perf-profile-first` asks you to say out loud.

**Explicitly deferred** (do *not* build these here)

- **Do not rewrite the parsers onto jiff's `civil::Date` / `civil::Time` APIs.** That would remove
  the allocation a completely different way and skip the technique this ticket exists to teach. Keep
  the `rfc3339_micros` call shape.
- **No thread-locals in `pg-sink` or `loader`.** Both hold state across `.await` points, where a
  per-worker-thread buffer is the wrong tool (tokio may migrate a task between threads at any await,
  so the buffer you resume with is not the one you started with).
- **Do not touch `BatchBuilder::meta_buf`** (`batch.rs:82`) — the struct-field scratch is already
  correct and is not a thread-local candidate.
- No `loom`, no `criterion` config change, no new dependency of any kind.

// crates/pg-to-arrow/src/batch.rs — near the other temporal helpers (~line 839).

use std::cell::RefCell;

thread_local! {
    /// Reused scratch for normalising canonical Postgres temporal text into RFC-3339 before
    /// [`rfc3339_micros`]. Safe as a thread-local because `pg-to-arrow` is a **pure sync** library
    /// (no tokio dependency): every borrow begins and ends inside one call, so it can never
    /// straddle an `.await` and be resumed on a different worker thread.
    ///
    /// Capacity covers the longest literal we ever build (`timestamptz` with micros + `+HH:MM`).
    static TEMPORAL_BUF: RefCell<String> = RefCell::new(String::with_capacity(40));
}

/// Micros since the Unix epoch for an RFC-3339 string. (Unchanged.)
fn rfc3339_micros(s: &str) -> Option<i64> {
    s.parse::<jiff::Timestamp>().ok().map(|t| t.as_microsecond())
}

/// `"2024-01-02"` → days since 1970-01-01.
fn parse_date_days(s: &str, col: &str) -> Result<i32, Error> {
    let micros = TEMPORAL_BUF
        .with_borrow_mut(|buf| {
            buf.clear();
            todo!("push `s`, then the literal \"T00:00:00Z\"; return rfc3339_micros(buf)")
        })
        .ok_or_else(|| value_err(col, s, "Date32"))?;
    i32::try_from(micros / 86_400_000_000).map_err(|_| value_err(col, s, "Date32"))
}

/// `"03:04:05.678901"` → micros since midnight.
fn parse_time_micros(s: &str, col: &str) -> Result<i64, Error> {
    TEMPORAL_BUF
        .with_borrow_mut(|buf| {
            buf.clear();
            todo!("push \"1970-01-01T\", then `s`, then 'Z'; return rfc3339_micros(buf)")
        })
        .ok_or_else(|| value_err(col, s, "Time64"))
}

/// `"2024-01-02 03:04:05.678901"` (no offset) → micros since epoch, treated as UTC.
fn parse_timestamp_micros(s: &str, col: &str) -> Result<i64, Error> {
    TEMPORAL_BUF
        .with_borrow_mut(|buf| {
            buf.clear();
            // The old body was `s.replacen(' ', "T", 1)` — one allocation. `split_once(' ')`
            // gives you the same first-space-only semantics with no allocation at all.
            todo!("split_once(' ') → push date, 'T', time; fall back to `s` when there is no space")
        })
        .ok_or_else(|| value_err(col, s, "Timestamp"))
}

/// Canonical Postgres `timestamptz` (`"…+00"`, already UTC upstream) → micros since epoch.
fn parse_timestamptz_micros(s: &str, col: &str) -> Result<i64, Error> {
    TEMPORAL_BUF
        .with_borrow_mut(|buf| {
            buf.clear();
            // Same space→`T` normalisation, then the offset fixup the old body did in place:
            // Postgres prints whole-hour offsets as `+HH`; jiff wants `+HH:MM`.
            todo!("normalise into `buf`; if the offset after 'T' is 3 chars, push \":00\"")
        })
        .ok_or_else(|| value_err(col, s, "TimestampTz"))
}

## Hints & gotchas

- **Never nest two borrows of the same thread-local.** `RefCell::borrow_mut` *panics* on a second
  overlapping borrow, and no clippy lint catches it (`unwrap_used`/`expect_used` do not cover
  `RefCell`). Concretely: do not call one temporal parser from inside another parser's
  `with_borrow_mut` closure, and do not call `value_err(...)` on the buffer *inside* the closure —
  build the error from `s` **outside**, exactly as the skeleton does with `.ok_or_else(...)` after
  `with_borrow_mut` returns.
- **`buf.clear()` is the whole contract.** `String::clear` truncates but keeps capacity, which is the
  entire point — the allocation is amortised to one per thread for the process lifetime. Forget it
  once and every subsequent parse in that thread silently sees a concatenated literal.
- **`with_borrow_mut` needs Rust ≥ 1.73** — walrus's MSRV is 1.95, so it is available. Prefer it over
  the older `with(|c| c.borrow_mut())` form, per the rule's *Key Points*.
- **Do not try to prove per-thread isolation with `std::thread`.** PR 15.4 lands a CI guard that
  fails on `std::thread::` anywhere under `crates/*/src` — **including sibling `*_test.rs` files**,
  because they live under `src/`. `pg-to-arrow` has no tokio dependency either. Test *correctness and
  reuse* single-threaded; thread isolation is a property of `thread_local!` itself, not something
  this crate needs to re-verify.
- **Benches are never a CI gate** (`docs/benchmarks.md` says so — shared runners are too noisy). CI
  only compile-checks bench targets via `clippy --all-targets`, so the `Shape::Temporal` arm must
  compile clean even though nobody runs it in CI. Run the numbers yourself on a quiet machine.
- The bench file opens with `#![allow(clippy::unwrap_used, clippy::expect_used)]` because
  `harness = false` targets are not `cfg(test)`. Production code in `batch.rs` gets **no** such
  allowance — `unwrap`/`expect` are denied there by `[workspace.lints]`.
- `oids::DATE` / `TIME` / `TIMESTAMP` / `TIMESTAMPTZ` are `1082 / 1083 / 1114 / 1184` in
  `crates/common/src/oids.rs:15-18`, re-exported as `pg_to_arrow::oids` (which is how the bench
  already imports them).
- Any new dependency would have to clear `cargo deny` (advisories, the 8-license allow-list, bans) —
  another reason this ticket adds none.
- Tests are **sibling files**, not inline `mod tests {}`: `batch.rs` already ends with
  `#[cfg(test)] #[path = "batch_test.rs"] mod tests;`, and `batch_test.rs` starts with
  `use super::*;`, so the private parsers are directly in scope.
