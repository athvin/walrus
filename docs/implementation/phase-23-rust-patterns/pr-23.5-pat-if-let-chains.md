# PR 23.5 — Move the workspace to edition 2024 and collapse nested if-let into let chains

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test,sqlx,msrv · **Test packages:** loader,pg-to-arrow

> **Phase:** 23 — Rust pattern matching · **Crates touched:** `common`, `control`, `loader`,
> `pg-sink`, `pg-to-arrow` · **Est. size:** L · **Depends on:** PR 23.4 · **Unlocks:** PR 24.1

If-let chains need the **2024 edition**, and `Cargo.toml:6` pins `edition = "2021"` for all six
members through `edition.workspace = true` — which is why `&& let` appears **0 times** anywhere in
the tree. The motivation is real: **5 production sites** nest an `if` or `if let` directly inside an
`if let` with no `else` (`control/src/db.rs:65`, `loader/src/apply_loop.rs:40`,
`pg-sink/src/consume.rs:573`, `pg-to-arrow/src/batch.rs:484` and `:876`). The migration risk is
measurably low: **0** `unsafe` blocks, **0** `static mut`, **0** `#[no_mangle]`/`#[export_name]`,
**0** bare `gen` identifiers, and `rust-toolchain.toml:4` pins `1.95.0` while edition 2024 only
needs 1.85. After this PR the workspace is on edition 2024 and the already-denied
`clippy::collapsible_if` — style, i.e. inside the `clippy::all` that `Cargo.toml:16` denies — starts
*requiring* the chains rather than merely allowing them.

## Why — learning objectives

- **If-let chains** — `&&`-joined `let` bindings interleaved with boolean guards, short-circuit
  evaluation left-to-right, later links using earlier bindings, and the fact that **availability is
  gated by the edition, not by the MSRV**: 1.95.0 can compile them, but only under edition 2024.
- **Edition migration mechanics on a real workspace** — `edition.workspace = true` inheritance from
  `[workspace.package]`, the `resolver` field on a virtual manifest, the
  `rust_2024_compatibility` lint group, and the `cargo fix --edition` → bump → rebuild order.
- **When *not* to chain** — a nest whose body mutates a value the chain conditions borrow, and any
  `if let` that has an `else`, stay as they are. `let … else` (PR 23.1) remains the tool for early
  return; chains are for a positive body behind several preconditions.

fn multirange_elem_type(field: &Field) -> Result<DataType, Error> {
    if let DataType::List(item) = field.data_type()
        && let DataType::Struct(fs) = item.data_type()
    {
        return Ok(fs[0].data_type().clone());
    }
    Err(Error::Downcast {

    })
}

    if let sqlx::Error::Database(db) = &e
        && db.code().as_deref() == Some("23514")

        return ControlError::CheckViolation(db.message().to_string());
    }
    ControlError::Connect(e)
}

```rust
// crates/pg-sink/src/consume.rs:562-579 — `cut_table`. The second link CALLS A METHOD on the
// binding produced by the first, which is exactly what chains are for; confirm borrowck agrees
// before committing to it (`batcher` is bound `mut` and `drain_committed` takes `&mut self`).
pub fn cut_table(
    &mut self,
    cache: &RelationCache,
    schema: &str,
    table: &str,
) -> anyhow::Result<Vec<SealedBatch>> {
    let Some(oid) = cache.oid_for(schema, table) else {
        return Ok(Vec::new()); // never buffered this table yet — nothing to cut (PR 23.1)
    };
    let mut sealed = Vec::new();
    if let Some(mut batcher) = self.batchers.remove(&oid)
        && let Some(batch) = todo!("batcher.drain_committed().context(\"cut table on DDL bump\")?")
    {
        sealed.push(batch);
    }
    Ok(sealed)
}
```

```rust
// crates/pg-to-arrow/src/batch.rs:872-884 — the triple nest. TRY this; if borrowck rejects it
// because the body mutates `n` while the chain indexes it, revert to the nest and keep the comment.
fn parse_timestamptz_micros(s: &str, col: &str) -> Result<i64, Error> {
    let mut n = s.replacen(' ', "T", 1);
    // Postgres prints whole-hour offsets as `+HH`; jiff wants `+HH:MM`.
    if let Some(t) = n.find('T')
        && let Some(sign) = n[t..].rfind(['+', '-'])
        && n[t + sign..].len() == 3
    {
        n.push_str(":00");
    }
    rfc3339_micros(&n).ok_or_else(|| value_err(col, s, "TimestampTz"))
}
```

## Hints & gotchas

- **Order of operations.** `cargo fix --edition` migrates *from* the current edition, so run it
  while `Cargo.toml` still says `2021`; only then flip the field. Doing it the other way round gives
  you a wall of hard errors instead of automated fixes.
- **`cargo fmt` will reformat more than you changed.** rustfmt's `style_edition` follows the crate
  edition, and the 2024 style edition changes things like `use`-statement sorting. Commit that pass
  on its own so the reviewable diff stays the four chains. If it is genuinely unreviewable, a
  `rustfmt.toml` with `style_edition = "2021"` is the escape hatch — but prefer taking the reformat.
- **The three migration lints that can change behaviour here** are `if_let_rescope` (an `if let`
  scrutinee's temporaries now drop *before* the `else` block), `tail_expr_drop_order` (temporaries
  in a tail expression drop before locals) and `rust_2024_incompatible_pat` (match-ergonomics
  binding modes). walrus holds `parking_lot` guards and `sqlx` pool/connection guards across
  expressions, so read every `cargo fix` edit in `control/` and `loader/` by hand rather than
  trusting the tool.
- Declarative macros are affected too: the `expr` fragment specifier matches more in edition 2024.
  `crates/pg-to-arrow/src/batch.rs:250-259` defines the `downcast!` macro — check it still expands
  identically.
- **`--all-targets` means test files count.** Once the edition flips, `clippy::collapsible_if` may
  report nests in `*_test.rs` and `tests/*.rs` beyond the 5 production sites. Fix them the same way;
  do not `#[allow]` them.
- **`cargo test -p loader` cold-builds the bundled DuckDB C++** (~20 min cold, ~3 min warm). Warm
  your local target dir *before* the edition flip, and be patient with CI on this PR — poll, do not
  assume a hang. The e2e `reload_quarantine` test is separately known-flaky (bootstrap race); a
  rerun of the failed job is the right response, not a revert.
- `tests/e2e` also inherits `edition.workspace = true`, so it moves too even though it is not in
  this ticket's crate list. Its lib carries a file-level `unwrap`/`expect` allow; that is unrelated
  and stays.
- Chains short-circuit left to right, and later links may use earlier bindings — but a binding from
  a chain is **only** in scope inside the `if` body, never in an `else`. If you find yourself
  wanting the binding in the `else`, you wanted `let … else` (PR 23.1) or a `match`.
- `unwrap`/`expect` stay denied in production; `clippy::all` + `warnings` are already `deny`; unit
  tests are Go-style sibling `*_test.rs` files. None of that changes with the edition.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — no Docker locally, and the
  edition does not invalidate it. Any new dependency would still have to clear `cargo deny`; this
  PR needs none.
