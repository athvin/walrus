# PR 23.5 — Move the workspace to edition 2024 and collapse nested if-let into let chains

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test,sqlx,msrv · **Test packages:** common,control,pg-sink,pg-to-arrow

> **Phase:** 23 — Rust pattern matching · **Crates touched:** workspace-wide (all six members) ·
> **Est. size:** L · **Depends on:** PR 23.4 · **Unlocks:** PR 24.1

**Authored baseline:** `1a9cdeb`.

If-let chains require the **2024 edition** and Rust **1.88 or newer**. The workspace root still
declares `edition = "2021"`, all **6** members inherit it through `edition.workspace = true`, and
`&& let` appears exactly **0** times under `crates/` and `tests/`. Four production nests are the
bounded rule sites: `ControlError::from_sqlx`, `BatchRouter::cut_table`,
`multirange_elem_type`, and `parse_timestamptz_micros`. The last two are both in
`crates/pg-to-arrow/src/batch.rs`; `multirange_elem_type` is now a three-level nest because it
also proves the struct has a first bound field.

The previously-authored fifth site in `loader/src/apply_loop.rs` no longer exists. PR 14.16
deliberately replaced its per-table `read_current_epoch` query with one shared epoch poller,
`TableCtx::epoch_rx`, and the pure `epoch_guard`. Reintroducing the old `if let Some(state)` would
be a behavior and query-topology regression, not a pattern cleanup. The migration risk remains
measurably low: the first-party Rust tree has **0** unsafe blocks/items, **0** `static mut`, **0**
`#[no_mangle]`/`#[export_name]`/`#[link_section]`, and **0** bare `gen` tokens. The declared MSRV is
`1.95`, the pinned toolchain is `1.95.0`, and both clear the chain feature's 1.88 floor (the 2024
edition itself was released with 1.85).

## Why — learning objectives

- **If-let chains** — `&&`-joined pattern bindings and boolean guards evaluate left-to-right;
  later clauses may use earlier bindings, and bindings exist only in the positive body.
- **Edition and feature floors are separate** — edition 2024 is available from Rust 1.85, while
  if-let chains stabilized in Rust 1.88; walrus's synchronized 1.95 MSRV/toolchain clears both.
- **Edition migration mechanics on a real workspace** — `edition.workspace = true` inheritance,
  the explicit resolver on a virtual manifest, the `rust_2024_compatibility` lint group, and the
  `cargo fix --edition` → manifest bump → rebuild order.
- **When not to chain** — `let … else` (PR 23.1) remains the early-return tool, and unrelated nests
  stay untouched unless edition-2024 clippy reports them under this task's all-targets gate.

```rust
// crates/pg-to-arrow/src/batch.rs — preserve the current empty-Struct check.
fn multirange_elem_type(field: &Field) -> Result<DataType, Error> {
    if let DataType::List(item) = field.data_type()
        && let DataType::Struct(fs) = item.data_type()
        && let Some(bound) = fs.first()
    {
        return Ok(bound.data_type().clone());
    }
    Err(Error::Downcast {
        column: field.name().clone(),
    })
}
```

```rust
// crates/pg-to-arrow/src/batch.rs — preserve checked byte-boundary arithmetic.
fn parse_timestamptz_micros(s: &str, col: &str) -> Result<i64, Error> {
    let mut n = s.replacen(' ', "T", 1);
    if let Some(t) = n.find('T')
        && let Some(sign) = n.get(t..).and_then(|suffix| suffix.rfind(['+', '-']))
        && t.checked_add(sign)
            .and_then(|start| n.get(start..))
            .is_some_and(|offset| offset.len() == 3)
    {
        n.push_str(":00");
    }
    rfc3339_micros(&n).ok_or_else(|| Error::value_parse(col, s, "TimestampTz"))
}
```

## Hints & gotchas

- **Do not conflate floors.** Rust 1.85 introduced edition 2024; if-let chains stabilized in Rust
  1.88. Walrus's actual declared/pinned build floor is 1.95/1.95.0 and remains unchanged.
- **Order of operations.** `cargo fix --edition` migrates from the current edition, so run it while
  `Cargo.toml` still says 2021; only then change the edition.
- **Review migration semantics.** `if_let_rescope` can rewrite an `if let` to retain 2021 temporary
  drop timing; `tail_expr_drop_order` warns without an automatic semantics-preserving rewrite; and
  `rust_2024_incompatible_pat` makes binding modes explicit. Treat generated edits as review input.
- **Rustfmt can be broad.** The style edition follows the crate edition. Keep the formatting pass
  isolated; if its diff is genuinely unreviewable, `style_edition = "2021"` is a documented escape
  hatch, but prefer accepting and reviewing the 2024 style.
- **Macro hygiene still matters.** `crates/pg-to-arrow/src/batch.rs:327` defines `downcast!` with
  `expr` fragments; confirm its exercised expansions remain equivalent after the edition bump.
- **All targets means tests.** Fix additional clippy-reported collapsible nests, but do not turn a
  broad text scan into authorization to refactor unrelated branches proactively.
- The baseline's `multirange_elem_type` uses `fs.first()` and timestamptz parsing uses `get` plus
  `checked_add`; both are prior safety improvements. The older `fs[0]` / `n[t + sign..]` skeleton
  is forbidden regression material.
- Full workspace validation still builds bundled DuckDB and can be slow. Preserve a healthy run.
- `tests/e2e` is the sixth member and inherits the edition even though it is not a production crate.
- Do not touch SQL, `.sqlx`, dependencies, resolver selection, loader epoch topology, or roadmap
  bookkeeping.
