# PR 23.2 — Collapse boolean matches into if/matches! and deny clippy::match_bool

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink,pg-to-arrow

> **Phase:** 23 — Rust pattern matching · **Crates touched:** `pg-to-arrow`, `pg-sink` ·
> **Est. size:** S · **Depends on:** PR 23.1 · **Unlocks:** PR 23.3

`matches!` is already idiomatic in walrus — **15 production uses** (the original 12-site census plus
the three predicates added by PR 18.7 in `crates/loader/src/health.rs:100,108,129`), including the one
at `crates/pg-to-arrow/src/batch.rs:349` that computes the very `is_null` flag this PR is about — and
`clippy::match_like_matches_macro` is a *style* lint already denied through `clippy::all`. What
survives is the shape that style lint does **not** cover: **6 `match is_null { true => …, false =>
… }` blocks**, all of them in `crates/pg-to-arrow/src/batch.rs` (:354, :366, :373, :389, :396,
:403), which are the tree's only `clippy::match_bool` sites; plus one hand-found site at
`crates/pg-sink/src/heartbeat.rs:172`, a `match (a, b) { (Some(_), Some(sent)) => <bool expr>, _ =>
false }` that is a `matches!`-with-guard written the long way. After this PR the six become the
plain `if is_null { … } else { … }` that the sibling helper `append_num` (`batch.rs:854`) already
uses, and `clippy::match_bool` keeps them that way.

## Why — learning objectives

- **`matches!` with `|` alternation and an `if` guard** — and why `match_bool` is a *style* smell,
  not a correctness one: `match` on a two-valued scrutinee buys you nothing the language's own `if`
  does not already give, and it hides the asymmetry between the two branches.
- **The `is_null` fast path in the Arrow batch builder** — `TupleValue::Null` and
  `TupleValue::UnchangedToast` collapse to *one* `append_null()` here, but they must stay distinct
  upstream (`crates/common/src/pg_shape.rs:130-141`); this PR must not blur that.
- **Lint-group membership as a design decision** — `match_like_matches_macro` is style (already
  denied via `clippy::all`); `match_bool` is pedantic and has to be named explicitly. Knowing which
  group a lint lives in is how you predict whether it is already on.

**Conflict — read before applying the rule**

`clippy::match_bool` is a **pedantic** lint, so it is *not* inside the already-denied `clippy::all`.
Add it as a plain named key with **no `priority` juggling** — the same reasoning the existing
`unwrap_used`/`expect_used` comment at `Cargo.toml:58-60` already spells out for restriction lints.
Do **not** reach for `clippy::pedantic = "deny"` wholesale: the measured pedantic/nursery run
in the authored force-warn inventory reports **1192 unique sites across 51 lints**, so enabling the
group here would turn a 7-site PR into an unreviewable one. One named lint, one PR.

```rust
// crates/pg-to-arrow/src/batch.rs — `append_value`. `is_null` is computed once at :349 with the
// `matches!` this rule is about; the six arms below just have to branch on it like `append_num` does.
fn append_value(
    builder: &mut dyn ArrayBuilder,
    field: &Field,
    value: &TupleValue,
    scratch: &mut String,
) -> Result<(), Error> {
    let col: &str = field.name();
    let dt = field.data_type();
    // Unchanged — NULL and unchanged-TOAST both append a null on the validity bitmap.
    let is_null = matches!(value, TupleValue::Null | TupleValue::UnchangedToast);

    match dt {
        DataType::Boolean => {
            let b = downcast!(builder, BooleanBuilder, col);
            if is_null {
                b.append_null();
            } else {
                b.append_value(parse_bool(text(value, col, dt)?, col)?);
            }
        }
        // …Int16/Int32/Int64/Float32/Float64 delegate to `append_num` and are already `if is_null`…
        DataType::Decimal128(_, scale) => {
            let b = downcast!(builder, Decimal128Builder, col);
            todo!("same if/else, calling parse_decimal(text(value, col, dt)?, *scale, col)?");
        }
        // …Utf8 (:373), Date32 (:389), Time64 (:396) and Timestamp (:403) get the same treatment.
        // Timestamp keeps its inner `if tz.is_some() { … } else { … }` exactly as it is today.
        _ => {
            return Err(Error::Downcast {
                column: col.to_string(),
            })
        }
    }
    Ok(())
}
```

## Hints & gotchas

- **`match_bool` is pedantic; `match_like_matches_macro` is style.** The second is already denied
  through `clippy::all`, which is exactly why nothing in the tree spells `match x { A => true, _ =>
  false }` any more — and exactly why the six `match is_null` blocks survived. Neither lint is in
  `clippy::all` *and* pedantic, so there is no `priority = -1` to add.
- **Do not "simplify" `is_null` itself.** Collapsing `Null` and `UnchangedToast` into one variant
  would break the loader's unchanged-TOAST back-scan (PR 3.6). The collapse is legal *here only*,
  at the Arrow validity bitmap, and the comment at `batch.rs:347-348` says so — keep it.
- `append_value` is per-column-per-row hot. The rewrite must be behaviour-identical: same
  `?`-propagation order, same `text(value, col, dt)?` call sites, no extra allocation. `cargo bench
  --bench batch` (criterion, `harness = false`) exists if you want to prove it, but it is not a DoD
  item.
- Watch the `Timestamp` arm (:401-415): its `false` branch has a *body*, not just an expression
  (`let s = …; let micros = if tz.is_some() { … } else { … }; b.append_value(micros);`). Move the
  whole body into the `else` block unchanged; do not flatten the inner `if`.
- `heartbeat.rs`'s `degraded` takes `self.pending_seq` and `self.last_beat` by value — both are
  `Option<…>` of `Copy` types, so the tuple in the `matches!` scrutinee is a copy, not a borrow. No
  lifetime problem, and the guard can call `self.cfg.roundtrip_deadline` freely.
- `unwrap`/`expect` are denied in production; `clippy::all` + `warnings` are already `deny`; unit
  tests live in sibling `*_test.rs` files, not inline `mod tests {}`.
- No new dependency here. If you add one anyway it must clear `cargo deny` (advisories, the
  8-license allow-list, bans).
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker locally
  to regenerate it.
