# PR 23.1 — Replace diverging match-binds with let-else in the reload controller and DSN parser

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 23 — Rust pattern matching · **Crates touched:** `pg-sink` · **Est. size:** S ·
> **Depends on:** PR 22.8 · **Unlocks:** PR 23.2

walrus already writes `let … else` **14 times** in production, so the idiom is not new here — but
`pg-sink` still spells the same shape the long way. There are **17** `let x = match …` statements
under `crates/pg-sink/src` (tests excluded), and **6 of them have a purely diverging second arm**
(`continue`, `return`, `bail!`). Clippy proves two of those mechanically —
`crates/pg-sink/src/reload.rs:381` and `:513`, the two `try_acquire_owned()` permit binds whose
`Err(_)` arm discards the error — but `clippy::manual_let_else` is **not enabled**:
`[workspace.lints.clippy]` at `Cargo.toml:15-22` carries only `all`, `unwrap_used` and
`expect_used`. This PR converts all 6 diverging sites and turns the lint on, so the long form
cannot come back on the next reload PR.

## Why — learning objectives

- **`let … else` and divergence** — the `else` block must `return` / `continue` / `break` / `bail!`,
  the compiler enforces it, and the binding lives *after* the statement (never inside `else`).
- **The reload controller's claim/permit lifecycle** — a lost semaphore permit must leave the row
  `exporting` so lease expiry + PR 6.9 adoption recover it; that is why these two sites `continue`
  and must never become `return`.
- **Why `manual_let_else` only flags 2 of the 6** — `let … else` throws the non-matching value away,
  so any arm that *logs the error* (`Err(e) => { warn!(error = %e, …) }`) is invisible to the lint.
  `Result::inspect_err` (stable since 1.76) is the bridge: log first, destructure second.

**Explicitly deferred** (do *not* build these here)

- The **29 other** `let x = match …` sites whose arms are genuine multi-way dispatch — e.g.
  `crates/pg-sink/src/pgoutput/mod.rs:214` and `crates/pg-sink/src/consume.rs:94`. A `match` that
  computes different values per arm is not a let-else candidate; do not "simplify" it.
- Any `?`-propagating `match`. CONTEXT § 6 keeps `?` as *the* propagation tool; `let … else` is only
  for divergence that is **not** an error return.
- Any `.sql` file or the committed `.sqlx` offline cache — untouched, and untouchable locally.

## Hints & gotchas

- **`let … else` cannot bind the failure value.** That is the whole reason four of these six sites
  are invisible to `clippy::manual_let_else`. Do not "fix" it by dropping the log line — move the
  log into `.inspect_err(|e| …)` so the operator breadcrumb survives byte-for-byte. `inspect_err`
  is stable since 1.76 and the toolchain is pinned to 1.95.0, so no MSRV question arises.
- **`continue` vs `return` in `tick()` is a correctness invariant, not style.** Re-read the doc
  comment at `reload.rs:302-307`: after `claim_requested`, every row in `claimed` is already
  `exporting`. A `return` in the per-row loop strands the remaining rows with a lease and no
  exporter. Keep `continue`; only the *pre-loop* `connect_source` failure returns, and it releases
  every claim first.
- `manual_let_else` is **pedantic**, so it is not inside the already-denied `clippy::all`. Add it as
  a plain named key — no `priority = -1` on `all`. This is exactly the reasoning already written
  down for `unwrap_used`/`expect_used` at `Cargo.toml:17-19`; keep that comment style.
- `unwrap()`/`expect()` are denied workspace-wide in production. `Option::unwrap_or` (used for the
  DSN port default) is a *different* method and is not flagged — leave it alone.
- The `else` block of a `let … else` inside an `async fn` may `.await` (the `release_row` loop
  does). It just has to diverge on every path.
- Unit tests are **Go-style sibling files** — `replication_test.rs` is wired in at
  `crates/pg-sink/src/replication.rs:555-557` via `#[cfg(test)] #[path = "replication_test.rs"] mod
  tests;`. Do not add an inline `mod tests {}`.
- `clippy::all` and `warnings` are already `deny` at the workspace level and all six members declare
  `[lints] workspace = true`, so the new key takes effect everywhere with no per-crate edit.
- No new dependency is needed. Anything you reach for must clear `cargo deny` (advisories, the
  8-license allow-list, bans) — a bad trade for a six-site refactor.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache; there is no Docker on this
  machine to regenerate it.
