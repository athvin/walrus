# PR 23.3 — Match TupleValue and Tier exhaustively instead of falling through a wildcard

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-to-arrow

> **Phase:** 23 — Rust pattern matching · **Crates touched:** `pg-to-arrow`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 23.2 · **Unlocks:** PR 23.4

Production carries **54 wildcard `_ =>` arms**. Classified by scrutinee, only **6** of them sit on a
walrus-owned enum: 4 on `common::TupleValue` (`crates/pg-to-arrow/src/batch.rs:309`, `:373`, `:405`,
`:612`) and 2 on `common::Tier` (`crates/pg-to-arrow/src/descriptor.rs:118`, `:138`). The other 48
match `u32` OIDs, `&str`, `Option`, byte literals or arrow's `DataType`, where a catch-all is
required and correct. The worst of the six is `batch.rs:309`:
`_ => unreachable!("is_null covers Null/UnchangedToast")` — a **panic path in production
guarded only by a comment**, in a tree that otherwise has zero `panic!`/`unwrap`. This PR
converts those 6 arms to explicit variants, pins each rewritten function with
`#[deny(clippy::wildcard_enum_match_arm)]`, and denies
`clippy::match_wildcard_for_single_variants` workspace-wide (2 sites, both in
`crates/pg-sink/tests/reload_recovery.rs`), so `TupleValue` and `Tier` can never gain a variant
that silently falls through.

## Why — learning objectives

- **Exhaustiveness as a compile-time checklist** — `|` alternation instead of `_`, so adding a
  variant to an enum you own becomes a build failure at every unhandled site rather than a silent
  runtime no-op. `#[non_exhaustive]` binds *downstream* crates, not the defining crate.
- **Why `TupleValue::Null` and `TupleValue::UnchangedToast` must never collapse** — the loader
  back-scans `<table>_raw` to resolve an unchanged-TOAST placeholder
  (`crates/common/src/pg_shape.rs:93-100`, PR 3.6). They may share one Arrow *null* at the validity
  bitmap; they may not share one *variant*.
- **`unreachable!` is a promise, not a proof** — replacing it with real arms removes the only panic
  path in `append_value` and lets the compiler check the claim the comment was making.
- **Restriction vs pedantic lint placement** — a lint that would fire on every `Option` match cannot
  go in `[workspace.lints]`; it goes on the specific items whose scrutinee you own.

            return Err(Error::Downcast {

## Hints & gotchas

- **Lint levels nest, and an `#[allow]` on a statement covers everything inside it.** The narrow
  allow on `append_value`'s `match dt` statement therefore also covers the nested bytea `match
  value`. That is why the DoD asserts the nested match by *inspection and grep count* as well —
  after this PR there is no `_` between `batch.rs:300` and `:312` at all.
- **Attributes on statements are stable; attributes on arbitrary expressions are not.** `match dt {
  … }` in `append_value` is an expression *statement* (it is followed by `Ok(())`), so `#[allow(…)]`
  attaches cleanly. If you restructure it into a tail expression the attribute stops compiling.
- **`#[non_exhaustive]` binds downstream crates, not the defining one.** `pgoutput::Message` is
  defined in `pg-sink` and matched in `pg-sink`, so the compiler would *let* you write an exhaustive
  match — do not. The marker exists because PRs 2.2–2.8 kept adding variants and the three dispatch
  sites are deliberately "handle what I know, ignore the rest".
- `unreachable!` counts as a panic. Production has zero `panic!`/`unwrap`/`expect` (one
  `expect` with a local `#[allow]`, one `unimplemented!` behind `#[allow(dead_code)]`), and this
  PR takes the count down further. Do not swap one panic macro for another.
- `crates/pg-sink/tests/reload_recovery.rs` is a compose-gated `#[ignore]` integration test, but
  `cargo clippy --all-targets` still compiles it — which is exactly how
  `match_wildcard_for_single_variants` reaches those two arms. Its file-level
  `#![allow(clippy::unwrap_used, clippy::expect_used)]` does not cover the new lint.
- Preserve the panic *messages* when you name the variant: the test's value on failure is the
  message. `RunOutcome::SchemaChanged { new_version }` gives you a better one than `{other:?}`.
- `descriptor.rs:130` and `:133` are `_ if RangeFamily::from_…(col.type_oid).is_some() =>` guards on
  a `u32`, not on an enum. They are not in scope and `wildcard_enum_match_arm` does not see them.
- Unit tests are Go-style sibling files (`batch_test.rs` is wired in at `batch.rs:886-888`); do not
  add an inline `mod tests {}`. `clippy.toml` re-allows `unwrap`/`expect` under `#[cfg(test)]`.
- `clippy::all` + `warnings` are already `deny` workspace-wide; adding a key to `Cargo.toml` reaches
  every member because all six declare `[lints] workspace = true`.
- No new dependency; anything new must clear `cargo deny`. Do not touch `.sql` or the `.sqlx` cache.
