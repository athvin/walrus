# PR 16.6 — Mark the Arrow value-parse error constructor `#[cold]`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-to-arrow

> **Phase:** 16 — Rust compiler optimization · **Crates touched:** `pg-to-arrow` ·
> **Est. size:** M · **Depends on:** PR 16.5 · **Unlocks:** PR 16.7

`pg-to-arrow` constructs `Error::ValueParse { column, value, data_type }` at **12 production sites**
— eight in `crates/pg-to-arrow/src/batch.rs` (`:161, 736, 773, 785, 796, 827, 832, 847`) and one
each in `geometric.rs:102`, `range.rs:85`, `tier2.rs:82`, `uuid_enum.rs:54`. Every one of them
allocates **three `String`s** via `to_string()` / `format!` *inline*, inside the per-cell append
helpers that the **460 ns/row `append_row`** bench measures (`docs/benchmarks.md` § History → PR
5.7). Zero `#[cold]` attributes exist repo-wide, so none of that construction code is kept out of
the hot path today: on a well-formed row — which is every row — the CPU carries the struct setup and
three allocation call sequences through its instruction cache and never executes them. This PR
funnels all twelve through one
`#[cold] fn value_parse(column: &str, value: &str, data_type: &str) -> Error` in
`crates/pg-to-arrow/src/error.rs`. The `Display` output is unchanged, so `cargo test -p pg-to-arrow`
proves it.

## Why — learning objectives

- **`#[cold]` as a code-placement hint** — it moves the function to a separate section, biases the
  branch layout toward the non-cold path, and stops the compiler inlining it into hot callers. A
  constructor that allocates three `String`s is exactly what you want *out* of a per-cell loop.
- **walrus's error taxonomy** — `ValueParse` is a **terminal**, per-cell type error carrying
  column / value / data-type context (`crates/pg-to-arrow/src/error.rs:13-18`). It is loud on
  purpose: PR 2.11's conformance tests exist to catch a "wrong-but-compiling" field, so the payload
  must survive this refactor byte for byte.

**In scope**

  `#[cold] pub(crate) fn value_parse(column: &str, value: &str, data_type: &str) -> Error`, doing
  the three `to_string()`s itself so they leave the callers' bodies too.
- Rewrite all 12 production construction sites as calls to it. The four domain helpers
  (`geo_err`, `range_err`, `parse_err`, `parse_uuid_bytes`'s closure) stay where they are and become
  one-line delegates — they carry meaningful defaults (`column: "geometric"`, `column: "range"`, …)
  that should not be inlined away into every call site.
- `batch.rs`'s local `value_err` (`:846`) is now identical to `value_parse` — delete it and call
  `value_parse` directly from its four callers.

**Explicitly deferred** (do *not* build these here)

- No `#[inline(never)]` pairing. PR 16.5 owns that attribute (on the decoder's `eof`); `#[cold]`
  alone already discourages inlining, and adding both here would blur which ticket's probe moved.
- No change to `Error`'s shape: same variants, same field names and order, same `#[error(...)]`
  messages, same `#[from]` conversions.
- No `#[cold]` on `loader` or `control` error paths — they are not on a benchmarked hot path, so
  marking them would be guessing (`perf-profile-first`, Phase 31).
- No touching the *other* `Error` variants' construction sites (`NotTier1`, `Downcast`,
  `RowLenMismatch`, `EmptyRelation`) — `Downcast` in particular is built by the `downcast!` macro at
  `batch.rs:250-259` and by PR 16.2's slice-pattern `else` arms.
- No allocation removal. Turning `ValueParse`'s three `String`s into `Box<str>` / `Cow` is a
  Phase-11 `mem-*` question, not this one.

## Skeleton

```rust
// crates/pg-to-arrow/src/error.rs

/// Build the per-cell `ValueParse` error.
///
/// `#[cold]` because this is the branch a well-formed row never takes, and it is expensive: three
/// `String` allocations. Keeping them **here** (rather than in the caller's body) is the point —
/// `append_row` runs this code path's setup once per cell per row on the 460 ns/row hot path
/// (docs/benchmarks.md § History → PR 5.7) and executes it approximately never. The `Display`
/// output is identical to the struct literal it replaces; `crates/pg-to-arrow/tests/conformance.rs`
/// and the sibling `*_test.rs` files pin that.
#[cold]
pub(crate) fn value_parse(column: &str, value: &str, data_type: &str) -> Error {
    Error::ValueParse {
        column: column.to_string(),
        value: value.to_string(),
        data_type: data_type.to_string(),
    }
}
```

## Hints & gotchas

- **`#[cold]` is a hint about frequency, not about correctness.** `value_parse` still returns a
  normal `Error`; nothing about the terminal/transient classification or the exit-code contract in
  `common::Error` changes.
- Keep the argument order `(column, value, data_type)`. It matches both the variant's field order
  and the deleted `value_err(col, s, dt)`, so the twelve rewrites are mechanical — and a transposed
  `value`/`data_type` pair still *compiles* (all three are `&str`). Read each site.
- `Error::ValueParse`'s message uses `{value:?}`, the `Debug` of a `String`, so the rendered text is
  quoted and escaped. Since `value_parse` still stores a `String`, the output is identical — but if
  you ever change the field type, that formatting changes with it.
- `batch.rs:773` passes `format!("{other:?}")` (the `TupleValue`'s Debug) as the *value*, and
  `batch.rs:736`/`:773` pass `dt.to_string()` (an arrow `DataType`'s Display) as the *data type*.
  Both temporaries must outlive the call — bind them if the borrow checker complains rather than
  restructuring the error.
- `pub(crate)`, not `pub`. `pg-to-arrow`'s public surface is `Error` itself; widening it with a
  constructor is a Phase-13 `api-*` decision.
- Sibling unit tests (`batch_test.rs`, `geometric_test.rs`, `range_test.rs`, `tier2_test.rs`,
  `uuid_enum_test.rs`) **match** on `Error::ValueParse { .. }` rather than construct it — matching
  is unaffected. Do not rewrite them; if one constructs the variant, leave it (the probe excludes
  `*_test.rs`).
- `batch.rs` carries `#![deny(clippy::indexing_slicing)]` from PR 16.2 and pulls its unit tests in
  with `#[cfg(test)] #[path = "batch_test.rs"] mod tests;` at the bottom — keep both intact.
- `unwrap`/`expect` are `deny` in production and `clippy::all` + `warnings` are already `deny`
  workspace-wide, so a half-finished rewrite fails loudly rather than warning.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it.
- Benches are never a CI gate. If you re-run `cargo bench -p pg-to-arrow --bench batch`, expect a
  small or null delta on `append_row` — the win here is instruction-cache footprint, which these
  micro-benches barely stress. Record whatever you measure in `docs/benchmarks.md` § History, null
  included.
