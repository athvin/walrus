# PR 16.6 — Mark the Arrow value-parse error constructor `#[cold]`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-to-arrow

> **Phase:** 16 — Rust compiler optimization · **Crates touched:** `pg-to-arrow` ·
> **Est. size:** S · **Depends on:** PR 16.5 · **Unlocks:** PR 16.7

PR 11.10 already funnels the **12 production constructor families** through
`Error::value_parse`: eight references in `crates/pg-to-arrow/src/batch.rs` and one each in
`geometric.rs`, `range.rs`, `tier2.rs`, and `uuid_enum.rs`. It also boxed `ValueParseDetail`, so the
hot `Error` result is 32 B while the cold payload owns the three diagnostic strings. The remaining
gap is code placement: that shared public constructor at `error.rs:49-59` has no `#[cold]`, so its
box and string-conversion setup is not explicitly marked as the branch a well-formed row never
takes. PR 16.5 introduced the repository's first `#[cold]` on decoder EOF; this PR adds the second
to `Error::value_parse` and removes `batch.rs`'s redundant one-line `value_err` shim. The public
generic signature and `Display` output remain unchanged, so `cargo test -p pg-to-arrow` proves the
behavior.

## Why — learning objectives

- **`#[cold]` as a code-placement hint** — it moves the function to a separate section, biases the
  branch layout toward the non-cold path, and stops the compiler inlining it into hot callers. A
  constructor that allocates three `String`s is exactly what you want *out* of a per-cell loop.
- **walrus's error taxonomy** — `ValueParse` is a **terminal**, per-cell type error carrying
  column / value / data-type context (`crates/pg-to-arrow/src/error.rs:23-24`). It is loud on
  purpose: PR 2.11's conformance tests exist to catch a "wrong-but-compiling" field, so the payload
  must survive this refactor byte for byte.

## Skeleton

```rust
// crates/pg-to-arrow/src/error.rs
impl Error {
    /// Build a boxed parse error without exposing its storage choice to call sites.
    ///
    /// Cold because a valid cell never constructs it; callers and tests pin the public generic
    /// API and byte-identical Display output introduced by PR 11.10.
    #[cold]
    pub fn value_parse(
        column: impl Into<String>,
        value: impl Into<String>,
        data_type: impl Into<String>,
    ) -> Self {
        Self::ValueParse(Box::new(ValueParseDetail {
            column: column.into(),
            value: value.into(),
            data_type: data_type.into(),
        }))
    }
}
```

## Hints & gotchas

- **`#[cold]` is a hint about frequency, not about correctness.** `value_parse` still returns a
  normal `Error`; nothing about its payload or callers' error handling changes.
- Keep the argument order `(column, value, data_type)`. It matches both the variant's field order
  and the deleted `value_err(col, s, dt)`, so the seven rewrites are mechanical — and a transposed
  `value`/`data_type` pair still compiles. Read each site.
- `Error::ValueParse`'s message uses `{value:?}`, the `Debug` of a `String`, so the rendered text is
  quoted and escaped. Since `value_parse` still stores a `String`, the output is identical — but if
  you ever change the field type, that formatting changes with it.
- `batch.rs:885` passes `format!("{other:?}")` (the `TupleValue`'s Debug) as the *value*, and
  `batch.rs:852`/`:885` pass `dt.to_string()` (an Arrow `DataType`'s Display) as the data type.
  Those existing owned arguments move through `impl Into<String>`; do not replace them with a
  narrower borrowed-only signature.
- Keep `value_parse` public. PR 11.10 exposed this associated constructor with a generic
  `impl Into<String>` API; 16.6 changes code placement, not public surface.
- Sibling unit tests (`batch_test.rs`, `geometric_test.rs`, `range_test.rs`, `tier2_test.rs`,
  `uuid_enum_test.rs`) match on `Error::ValueParse(detail)` rather than construct it — matching
  is unaffected. Do not rewrite them; if one constructs the variant, leave it (the probe excludes
  `*_test.rs`).
- `batch.rs` carries `#![deny(clippy::indexing_slicing)]` from PR 16.2 and pulls its unit tests in
  with `#[cfg(test)] #[path = "batch_test.rs"] mod tests;` at the bottom — keep both intact.
- `unwrap`/`expect` are `deny` in production and `clippy::all` + `warnings` are already `deny`
  workspace-wide, so a half-finished rewrite fails loudly rather than warning.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it.
- Benches are never a CI gate. If you re-run `cargo bench -p pg-to-arrow --bench batch`, expect a
  small or null delta on `append_row` — the win here is instruction-cache footprint, which these
  micro-benches barely stress. Record whatever you measure in `docs/benchmarks.md` § History, null
  included.
