# PR 16.1 — Gate the release LTO profile and fix the stale bench-profile note

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 16 — Rust compiler optimization · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 15.4 · **Unlocks:** PR 16.2

walrus already satisfies this rule: `[profile.release] lto = "thin"` sits at `Cargo.toml:76-77`,
chosen and measured in PR 5.7 (an honest null on the micro-benches — −0.8 % to +1 %, mixed sign —
kept because the sink/loader binaries span crates: decode → batch → arrow → parquet). What is
missing is anything that stops it from silently going away. `grep -c 'profile.release\|lto'
.github/workflows/ci.yml` = **0**, there is no `.cargo/config.toml`, and
`grep -rn 'RUSTFLAGS\|rustflags'` across `*.toml` / `*.yml` / `Dockerfile*` = **0** — a one-line
manifest edit would delete the decision with nothing failing. This PR adds the first
build-configuration guard test in the tree (`crates/common/tests/build_profile.rs`, which
`include_str!`s the workspace manifest and asserts the `lto` key is still declared), and repairs
`docs/benchmarks.md:12`, which still tells readers the bench profile has "LTO off" — flatly
contradicting `Cargo.toml:75` ("the bench inherits `release` so the numbers count") and quietly
invalidating every delta Phase 16 is about to record.

## Why — learning objectives

- **Cargo profile inheritance and `include_str!` as a compile-time configuration guard** — the
  `bench` profile inherits `release`, so a `[profile.release]` key is a *benchmark* setting too;
  and a test can read the manifest that built it because `include_str!` resolves at compile time.
- **Why walrus's multi-crate binaries are the case cross-crate inlining actually pays for** —
  `pg-sink` walks `pgoutput` decode → `pg-to-arrow` batch → `arrow` → `parquet`, four crates deep
  per row, which is exactly the boundary a single-crate micro-bench cannot see.

## Scope

**In scope**

- New integration test `crates/common/tests/build_profile.rs` that `include_str!`s
  `../../../Cargo.toml`, isolates the `[profile.release]` table, and fails if `lto` is absent or
  set to `false`/`"off"`.
- Fix `docs/benchmarks.md:12`: "LTO off" → "LTO thin (inherited from release, PR 5.7)".
- A short doc comment on the test naming PR 5.7 as the decision it is guarding, so the next reader
  finds the rationale instead of deleting the assertion.

**Explicitly deferred** (do *not* build these here)

- Raising `lto = "thin"` to `"fat"`.
- Adding `codegen-units`, `panic`, `strip`, `opt-level`, or `debug` keys to any profile.
- Touching `deploy/docker/Dockerfile.pg-sink` or `deploy/docker/Dockerfile.loader`.

**Conflict — the rule's bundled profile must NOT be applied blindly.** `opt-lto-release`'s
"Complete Optimized Profile" snippet ships `lto = "fat"`, `codegen-units = 1`, `panic = "abort"`
and `strip = true` together. Adopt **only the LTO clause**:

- `codegen-units = 1` is rejected *in writing* at `Cargo.toml:71-75` — "a bad trade for a project
  whose Phase-5 north star is *cutting* CI/Docker build time (PRs 5.1-5.3)". PR 16.9 turns that
  rejection into an ADR; do not pre-empt or reverse it here.
- `panic = "abort"` breaks `#[should_panic]` and the e2e harness, so walrus takes only the safe
  subset of the release-profile advice (see `perf-release-profile`, Phase 31).
- `lto = "fat"` roughly doubles link time against the same Phase-5 build-time budget, for a gain
  PR 5.7 already measured as within noise on these benches.

## Hints & gotchas

- `include_str!("../../../Cargo.toml")` is resolved **relative to the source file**, so from
  `crates/common/tests/build_profile.rs` three `../` land on the workspace root. Get this wrong and
  it is a compile error, not a silent pass — which is the point.
- Parse the manifest by hand. Adding `toml` as a dev-dependency to read four lines is not worth a
  `cargo deny` review (advisories, the 8-license allow-list, bans) and drags a parser into
  `common`'s dev tree.
- `Cargo.toml:73` contains the word `codegen-units` **inside a comment**. A naive
  `manifest.contains("codegen-units")` would make PR 16.9's guard permanently green-by-accident.
  Skip comment lines from the start; write the helper so 16.9 can reuse it.
- `clippy.toml` sets `allow-unwrap-in-tests` / `allow-expect-in-tests`, which covers `#[test]`
  functions in `tests/`. Free functions in the same file are *not* always covered — keep helpers
  returning `Option`/`bool` and do the `expect` inside the `#[test]` body.
- `clippy::all` and `warnings` are already `deny` workspace-wide and `common` declares
  `[lints] workspace = true`, so the new test target is linted like production code under
  `--all-targets`.
- Tests in walrus are Go-style sibling `foo_test.rs` files for **unit** tests. This one is
  deliberately an **integration** test under `tests/` — it tests the build configuration, not a
  module, and it has no `src/` sibling to attach to.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it.
- Re-running the benches is **not** required here (PR 16.3 does that). CI never gates on criterion
  numbers; it only compile-checks the bench targets via `clippy --all-targets`.
