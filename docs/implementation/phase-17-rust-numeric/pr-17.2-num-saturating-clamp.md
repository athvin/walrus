# PR 17.2 — Bound the bootstrap backoff and the lease renew interval with clamp instead of one-sided min/max

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** loader,pg-sink

> **Phase:** 17 — Rust numeric safety · **Crates touched:** `pg-sink`, `loader` ·
> **Est. size:** S · **Depends on:** PR 17.1 · **Unlocks:** PR 17.3

Production has exactly **one** `clamp(` call — `attempt_budget` at
`crates/pg-sink/src/bootstrap.rs:42` — against twelve `.min(` / `.max(` sites.
Two of those twelve are hand-rolled one-sided bounds where
a two-sided `clamp` is the correct shape, and both hide a real defect. `bootstrap.rs:167` writes
`backoff = (backoff * 2).min(Duration::from_secs(5))`: `impl Mul<u32> for Duration` **panics** on
overflow, so the doubling needs `saturating_mul` before any bound is applied.
`crates/loader/src/lease.rs:41` writes `tokio::time::interval((ttl / 3).max(Duration::from_secs(1)))`
— and `LoaderConfig::validate` only rejects `lease_ttl.is_zero()` (`crates/loader/src/config.rs:107`),
so a configured `lease_ttl` of 1s produces a renew tick **at or past** the TTL: the lease lapses
before it is renewed and a second loader can claim the table's DuckDB file, straight through the
ownership fence (loader §8.1). This PR extracts both expressions into named, unit-testable helpers
built on `saturating_mul` + `clamp`, and establishes the clamp precondition at the config boundary
where walrus already rejects invalid config.

## Why — learning objectives

- **`Ord::clamp` vs a `min`/`max` chain, `Duration::saturating_mul` vs the panicking `Mul<u32>`, and
  the `min > max` clamp precondition** — clamp is not a drop-in for `.max(x)`; it carries a
  precondition you must be able to *prove*, not hope for.
- **Lease renewal must tick strictly inside the TTL** or a second loader can claim the table's DuckDB
  file — the walrus ownership fence (loader §8.1). A numeric bound here is a correctness fence, not
  a tuning knob.

**In scope**

- `crates/pg-sink/src/bootstrap.rs`: two `const`s (`INITIAL_BACKOFF: Duration = 200ms`,
  `MAX_BACKOFF: Duration = 5s`) plus a private `fn next_backoff(cur: Duration) -> Duration` built on
  `saturating_mul(2)` + `clamp(INITIAL_BACKOFF, MAX_BACKOFF)`. `retry_transient` calls it.
- `crates/loader/src/lease.rs`: a private `fn renew_interval(ttl: Duration) -> Duration` returning
  `(ttl / 3).clamp(MIN_RENEW_INTERVAL, ttl)`, with `MIN_RENEW_INTERVAL: Duration = 1s`.
  `spawn_renewer` calls it.
- `crates/loader/src/config.rs`: `validate` rejects `lease_ttl < 3 * MIN_RENEW_INTERVAL` (3s) as a
  terminal `ConfigError`, replacing the `is_zero()` check (which it subsumes). The error message
  must name the reason — renewal ticks at TTL/3 and must land inside the TTL.
- New sibling tests: append lease-TTL validation cases to the existing, already-wired
  `crates/loader/src/config_test.rs`; create `crates/loader/src/lease_test.rs` and wire it with the
  Go-style `#[cfg(test)] #[path = "lease_test.rs"] mod tests;` line; append new cases to
  `crates/pg-sink/src/bootstrap_test.rs`.

**Explicitly deferred** (do *not* build these here)

- The monotonic-watermark `.max()` calls — `crates/pg-sink/src/checkpoint.rs:51`,
  `crates/pg-sink/src/replication.rs:251/275/291`, `crates/loader/src/phase_a.rs:201`. Those are LSN
  high-water marks ("never regress"), not bounds; `.max()` is exactly right and a `clamp` there would
  be wrong.
- A shared `common::backoff` module. `next_backoff` stays private to `pg-sink::bootstrap`; there is
  one caller and no second one is planned in this phase.
- `bootstrap.rs:164`'s `backoff.min(deadline.saturating_duration_since(now))`. That is "do not sleep
  past the deadline", a one-sided cap with no lower bound — leave it.
- Any change to the *values* (200 ms / 5 s / TTL⁄3). This PR changes the shape and the validation
  floor, not the tuning.

**Conflict — the rule must NOT be applied blindly.** `Ord::clamp` **panics when `min > max`**, so
naively rewriting `lease.rs:41` as `(ttl / 3).clamp(MIN_RENEW_INTERVAL, ttl)` *is itself a panic* for
any `ttl < MIN_RENEW_INTERVAL` — trading a lapsed lease for a crashed loader. The required
resolution, in this order:

1. Tighten `LoaderConfig::validate` to reject `lease_ttl < 3s` as a **terminal config error**. This
   is the walrus convention (`docs/architecture.md` — invalid config is rejected, never silently
   clamped) and it is what makes `MIN_RENEW_INTERVAL <= ttl` *provable* at the boundary.
2. Only then clamp the **derived runtime value** (`ttl / 3`), never the configured input.
3. `next_backoff`'s bounds are two `const`s in the same file, so `INITIAL_BACKOFF <= MAX_BACKOFF`
   is readable at a glance — state that in its doc comment so a later edit cannot invert them
   silently.

/// First retry pause, and the floor `next_backoff` clamps up to.
const INITIAL_BACKOFF: Duration = Duration::from_millis(200);
/// Ceiling for the exponential retry pause. `INITIAL_BACKOFF <= MAX_BACKOFF` is the `clamp`
/// precondition — keep these two lines adjacent so an edit cannot invert them unnoticed.
const MAX_BACKOFF: Duration = Duration::from_secs(5);

///

/// `clamp` then pins the result into `[INITIAL_BACKOFF, MAX_BACKOFF]`. Replaces the one-sided
/// `(backoff * 2).min(Duration::from_secs(5))`.
fn next_backoff(cur: Duration) -> Duration {
    todo!("cur.saturating_mul(2).clamp(INITIAL_BACKOFF, MAX_BACKOFF)")
}

async fn retry_transient<T, F, Fut>(deadline: Instant, what: &str, mut op: F) -> Result<T, Error>
where
    F: FnMut() -> Fut,
    Fut: std::future::Future<Output = Result<T, Error>>,
{
    let mut backoff = INITIAL_BACKOFF;
    loop {
        match op().await {
            Ok(value) => return Ok(value),
            Err(e) if e.is_terminal() => return Err(e),
            Err(e) => {
                let now = Instant::now();
                if now >= deadline {
                    tracing::error!("{what} still unavailable at startup deadline: {e}");
                    return Err(e);
                }
                // unchanged: a deadline cap, not a bound — leave the `.min(` alone.
                let wait = backoff.min(deadline.saturating_duration_since(now));
                tracing::warn!("{what} unavailable (transient), retrying in {wait:?}: {e}");
                tokio::time::sleep(wait).await;
                backoff = next_backoff(backoff); // was: (backoff * 2).min(Duration::from_secs(5))
            }
        }
    }
}

## Hints & gotchas

- **`Duration * 2` panics; `Duration::saturating_mul(2)` does not.** `saturating_mul` takes a `u32`,
  matching `impl Mul<u32> for Duration` — no cast needed.
- **Do not clamp the configured `lease_ttl` itself.** Clamping user input silently repairs a
  misconfiguration and hides it forever; walrus rejects it (see `pg-sink`'s `reload_lease_ttl >= 15s`
  check for the house style). Clamp only the derived `ttl / 3`.
- The `debug_assert!` inside `renew_interval` documents the precondition and costs nothing in
  release. It is *not* a substitute for the config check — if you only add the assert, release builds
  still panic inside `clamp`.
- `Duration::ZERO` into `tokio::time::interval` **panics** ("`period` must be non-zero"). The 3 s
  floor plus `MIN_RENEW_INTERVAL` makes that unreachable; keep both.
- The test files are **Go-style siblings**, not inline `mod tests {}`. `config_test.rs` is already
  wired; add `#[cfg(test)] #[path = "lease_test.rs"] mod tests;` at the bottom of `lease.rs` or the
  new file silently never compiles — and a test that never runs looks exactly like a passing one.
- `crates/loader/src/config.rs` does not import `Duration` at the point you need `MIN_LEASE_TTL`?
  It does — `lease_ttl: Duration` is already a field. No new `use` should be necessary.
- `clippy::all` + `warnings` are `deny` workspace-wide. Expect `clippy::manual_clamp` to *stop*
  firing after this change, not start; if clippy suggests `unnecessary_min_or_max` anywhere you did
  not touch, leave it — that is PR 17.3's neighbourhood at most.
- `unwrap`/`expect` are `deny` in production but re-allowed under `#[cfg(test)]` by `clippy.toml`,
  so `expect_err(...)` in the sibling tests is fine.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. `control::renew_lease`'s signature is unchanged by this PR.
