# PR 17.1 — Make integer overflow explicit in the interval parser and the in-flight meter

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink,pg-to-arrow

> **Phase:** 17 — Rust numeric safety · **Crates touched:** `pg-to-arrow`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 16.12 · **Unlocks:** PR 17.2

Production carries 15 `checked_`/`saturating_`/`wrapping_`/`overflowing_` call sites, but only 7 of
them are integer arithmetic — the other 8 are `Instant::saturating_duration_since`. The two places
that most need explicit overflow handling have **none**. `crates/pg-to-arrow/src/tier2.rs` parses
untrusted Postgres `interval` and `timetz` *text* with twelve lines of raw `+`, `*` and unary `-` on
`i64` and scores `grep -c 'checked_' = 0`: `hms_to_micros` computes
`(h * 3600 + m * 60 + sec) * 1_000_000 + frac_micros` (`tier2.rs:103`) and `parse_interval`
accumulates `n * 3_600_000_000` per `hours` token (`tier2.rs:153`), so an interval anywhere near
Postgres' own ceiling (~2 562 047 788 hours) blows `i64` long before Postgres would reject it —
which means **panic in debug, silent wrap in release**, on the CDC decode path, from a value an
untrusted upstream table can hold. `crates/pg-sink/src/memory.rs` does the same on the process-wide
byte meter: `self.total += bytes` (`:42`) and `self.total -= bytes` (`:48`), zero checked or
saturating calls in the file, so a double `release` underflows `u64` to ~1.8e19 and pins
`over_ceiling()` at `true` forever. This PR folds every one of those into a typed `Error::ValueParse`
rejection or a saturating gauge, and pins the behaviour with tests that run in **both** debug and
`--release`.

## Why — learning objectives

- **`checked_add`/`checked_mul`/`checked_neg` returning `Option`** — and folding `None` into a typed
  error with `.ok_or_else(err)?` instead of letting debug panic and release wrap.
- **Postgres `interval` is three independent fields (months, days, micros) and its text form is
  attacker-shaped input on the CDC path** — a decode-side panic takes down the sink, so overflow has
  to be a modelled `ValueParse` rejection, not a crash.

## Read first

- [`num-overflow-explicit`](../../../.claude/skills/rust-skills/rules/num-overflow-explicit.md) —
  take the four-family table (`checked_*` → `Option`, `saturating_*` → `T`, `wrapping_*` → `T`,
  `overflowing_*` → `(T, bool)`) and the "use when" column. This ticket needs exactly two of them:
  `checked_*` for the parser (overflow is a caller-visible error) and `saturating_*` for the meter
  (clamping at the type's bound is the correct gauge behaviour).
- `crates/pg-to-arrow/src/tier2.rs:89-112` — `hms_to_micros` and `signed_time_to_micros`. Both
  already return `Option<i64>`, so `checked_*` threads through with `?` and no signature change.
- `crates/pg-to-arrow/src/tier2.rs:114-168` — `parse_interval`. Note that it *already* narrows the
  final months/days with `i32::try_from(...).map_err(|_| err())?` (`:165-166`): the failure shape
  this PR needs is already established in the function — extend it to the accumulators.
- `crates/pg-to-arrow/src/tier2.rs:170-188` — `parse_timetz`; `sign * (oh * 3600 + om * 60 + os)`
  at `:187` is `i32` arithmetic on parsed text, the same class of bug one type narrower.
- `crates/pg-to-arrow/src/error.rs:14-18` — the `Error::ValueParse { column, value, data_type }`
  variant, and `tier2.rs:79-86` (`parse_err`) which builds it. Overflow reuses this variant; do
  **not** add a new one.
- `crates/pg-sink/src/memory.rs:30-71` — `InflightMeter::{new, add, release, total, over_ceiling}`.
  `over_ceiling()` is what gates the shed ladder in `decide` (`:86-97`), so a wrapped `total` is a
  stuck backstop, not a cosmetic wrong number.
- `crates/loader/src/compaction.rs:106-110` — `retention_floor`'s
  `transformed_lsn.as_u64().saturating_sub(retention_lsn_lag)`. This is the existing in-tree
  precedent for "saturate a monotone counter at the type bound and document why"; copy its shape and
  its doc-comment habit.

**In scope**

- `crates/pg-to-arrow/src/tier2.rs`: replace every raw `+`, `*` and unary `-` on `i64`/`i32` in
  `hms_to_micros`, `signed_time_to_micros`, `parse_interval` and `parse_timetz` with the `checked_*`
  form, folding `None` into `Option`-return (the two private helpers) or
  `.ok_or_else(err)?` → `Error::ValueParse` (the two `pub fn` parsers).
- The `ago` negation block (`tier2.rs:160-164`) becomes `checked_neg` — `i64::MIN.checked_neg()` is
  `None`, which is the one input where unary `-` panics outright.
- `crates/pg-sink/src/memory.rs`: `InflightMeter::add` uses `saturating_add` on both the per-stream
  entry and `self.total`; `InflightMeter::release` uses `saturating_sub`. Document *why* saturation
  (not `checked_`) is right for a gauge: the meter's job is to say "we are over", and `u64::MAX` says
  that correctly, whereas an `Err` would have to be swallowed by a caller that has nothing to do
  with it.
- New sibling test cases in `crates/pg-to-arrow/src/tier2_test.rs` and
  `crates/pg-sink/src/memory_test.rs` covering the overflow boundary in both directions.

- The ~40 other `+=` / `i += 1` cursor increments in `crates/pg-to-arrow/src/range.rs`,

// crates/pg-to-arrow/src/tier2.rs

/// Parse a `HH:MM:SS[.ffffff]` clock (no sign) into microseconds. Fractional seconds are padded /
/// truncated to microsecond resolution. Returns `None` on a malformed clock **or** on i64 overflow
/// — `'2562047788015216 hours'` is a syntactically valid clock that no i64 can hold.
fn hms_to_micros(body: &str) -> Option<i64> {
    let mut it = body.split(':');
    let h: i64 = it.next()?.parse().ok()?;
    let m: i64 = it.next()?.parse().ok()?;
    let s = it.next().unwrap_or("0");
    if it.next().is_some() {
        return None;
    }
    let (sec, frac) = s.split_once('.').unwrap_or((s, ""));
    let sec: i64 = sec.parse().ok()?;
    let frac_digits: String = frac.chars().chain(std::iter::repeat('0')).take(6).collect();
    let frac_micros: i64 = frac_digits.parse().ok()?;
    // was: Some((h * 3600 + m * 60 + sec) * 1_000_000 + frac_micros)
    todo!("h.checked_mul(3600)? + m.checked_mul(60)? + sec, then checked_mul(1_000_000)? \
           and checked_add(frac_micros) — every step `?`-folds into the existing None path")
}

/// A signed `[-]HH:MM:SS[.ffffff]` time token (the negative sign applies to the whole clock).
/// `None` when the magnitude is `i64::MIN`-adjacent: unary `-` on `i64::MIN` panics.
fn signed_time_to_micros(tok: &str) -> Option<i64> {
    match tok.strip_prefix('-') {
        // was: hms_to_micros(body).map(|us| -us)
        Some(body) => hms_to_micros(body).and_then(i64::checked_neg),
        None => hms_to_micros(tok),
    }
}

/// Parse canonical interval text (`"1 year 2 mons 3 days 04:05:06.5"`) into `(months, days, micros)`.
///
/// Overflow of any accumulator is an `Error::ValueParse`, not a panic: this text arrives from the
/// source database on the decode path, so a wrapped `micros` is a silently-corrupt CDC row and a
/// panic is a dead sink.
pub fn parse_interval(text: &str) -> Result<(i32, i32, i64), Error> {
    let err = || parse_err("interval", text);
    let mut months: i64 = 0;
    let mut days: i64 = 0;
    let mut micros: i64 = 0;
    let mut ago = false;

    let toks: Vec<&str> = text.split_whitespace().collect();
    let mut i = 0;
    while i < toks.len() {
        let tok = toks[i];
        if tok.contains(':') {
            // was: micros += signed_time_to_micros(tok).ok_or_else(err)?;
            micros = micros
                .checked_add(signed_time_to_micros(tok).ok_or_else(err)?)
                .ok_or_else(err)?;
            i += 1;
            continue;
        }
        if tok == "@" {
            i += 1;
            continue;
        }
        if tok == "ago" {
            ago = true;
            i += 1;
            continue;
        }
        let n: i64 = tok.parse().map_err(|_| err())?;
        let unit = toks.get(i + 1).ok_or_else(err)?;
        match *unit {
            // was: months += n * 12   /   micros += n * 3_600_000_000   /   …
            "year" | "years" | "yr" | "yrs" => {
                todo!("months = months.checked_add(n.checked_mul(12).ok_or_else(err)?).ok_or_else(err)?")
            }
            "mon" | "mons" | "month" | "months" => todo!("checked_add(n)"),
            "day" | "days" => todo!("days.checked_add(n)"),
            "hour" | "hours" | "hr" | "hrs" => todo!("checked_mul(3_600_000_000) then checked_add"),
            "min" | "mins" | "minute" | "minutes" => todo!("checked_mul(60_000_000) then checked_add"),
            "sec" | "secs" | "second" | "seconds" => todo!("checked_mul(1_000_000) then checked_add"),
            _ => return Err(err()),
        }
        i += 2;
    }
    if ago {
        // was: months = -months; days = -days; micros = -micros;
        months = months.checked_neg().ok_or_else(err)?;
        days = days.checked_neg().ok_or_else(err)?;
        micros = micros.checked_neg().ok_or_else(err)?;
    }
    // unchanged — the narrowing that already exists (tier2.rs:165-166)
    let months = i32::try_from(months).map_err(|_| err())?;
    let days = i32::try_from(days).map_err(|_| err())?;
    Ok((months, days, micros))
}

// crates/pg-sink/src/memory.rs

impl InflightMeter {
    /// Account `bytes` more buffered for `(table, xid)`.
    ///
    /// Saturating, not checked: this is a **gauge** whose only consumer is `over_ceiling()`. If the
    /// sum ever reached `u64::MAX` the honest answer is still "over the ceiling", and there is no
    /// caller in the shed ladder (`decide`) that could act on an `Err`. Compare
    /// `loader::compaction::retention_floor`, which saturates for the same reason.
    pub fn add(&mut self, key: (TableId, u32), bytes: u64) {
        let e = self.by_stream.entry(key).or_insert(0);
        *e = todo!("e.saturating_add(bytes)");
        self.total = todo!("self.total.saturating_add(bytes)");
    }

    /// Drop all accounting for `(table, xid)` (its buffer was flushed or spilled).
    ///
    /// `saturating_sub` guards the double-release path: a plain `-=` underflows `u64` to ~1.8e19,
    /// which pins `over_ceiling()` at `true` and leaves the sink pause-polling forever.
    pub fn release(&mut self, key: (TableId, u32)) {
        if let Some(bytes) = self.by_stream.remove(&key) {
            self.total = todo!("self.total.saturating_sub(bytes)");
        }
    }
}

## Hints & gotchas

- **Run the release test.** In debug, `h * 3600` already panics on overflow, so a debug-only suite
  cannot tell "explicitly rejected" from "panicked". `cargo test --release` is the discriminator and
  belongs in the DoD, not in a comment.
- `hms_to_micros` and `signed_time_to_micros` return `Option<i64>` **already**. Do not widen them to
  `Result` — `checked_*` returns `Option`, so `?` composes for free and the two `pub fn` callers keep
  doing the `ok_or_else(err)?` translation they already do.
- `err` in `parse_interval` is `let err = || parse_err("interval", text);` — a closure, so it is
  `ok_or_else(err)`, never `ok_or(err())` (that would build the `String`s on every success).
- Watch the `ago` block: `-i64::MIN` is the *only* unary-minus panic on `i64`, and `micros` can
  legitimately reach large magnitudes from a `720:00:00`-style clock. `checked_neg` costs nothing.
- `clippy::all` and `warnings` are `deny` workspace-wide (`Cargo.toml:12-17`) and both crates declare
  `[lints] workspace = true`. `clippy::checked_conversions` / `manual_checked_sub` may fire on a
  hand-rolled `if a > b { a - b }` — use the stdlib method and it stays quiet.
- `unwrap()`/`expect()` are `deny` in production (`unwrap_used`, `expect_used`). `clippy.toml`
  re-allows them under `#[cfg(test)]`, so the sibling `*_test.rs` files may keep using `.unwrap()`.
- Tests are **Go-style sibling files**: append to the existing `tier2_test.rs` / `memory_test.rs`,
  wired by the `#[cfg(test)] #[path = "…_test.rs"] mod tests;` lines already at the bottom of each
  module. Never add an inline `mod tests {}`.
- `memory_test.rs:44-45` reaches into the private field (`empty.total = 1;`) — that works because the
  sibling test is a child module. Keep it working: do not make `total` inaccessible.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. Nothing in this PR needs to.
