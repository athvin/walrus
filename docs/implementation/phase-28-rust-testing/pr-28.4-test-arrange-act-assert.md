# PR 28.4 — Split the multi-concern unit tests into labelled Arrange/Act/Assert sections

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 28 — Rust testing · **Crates touched:** `common`, `pg-to-arrow`, `pg-sink` ·
> **Est. size:** M · **Depends on:** PR 28.3 · **Unlocks:** PR 28.5

Not one of the 47 sibling test files carries an explicit Arrange/Act/Assert marker — a strict grep
returns **0**. Most of the 211 unit tests are implicitly AAA and small, but **three** pack several
concerns into one function: `orders_relation_maps_to_expected_tier1_schema`
(`crates/pg-to-arrow/src/schema_test.rs:34` — **10** bare `assert_eq!`s over 16 lines),
`type_descriptor_round_trips_the_docs_example` (`crates/common/src/type_descriptor_test.rs:33` —
**9** asserts covering two distinct behaviours: the field-by-field decode *and* the JSON
re-serialisation), and `maps_written_object_to_a_stream_ready_row`
(`crates/pg-sink/src/manifest_test.rs:6` — **8**). When the fifth of ten bare `assert_eq!`s fires,
the test name tells you nothing about which field drifted. This PR splits those three into
single-behaviour tests, labels the sections, and — because the split needs a second `to_ready_row`
case — closes a real coverage gap: the `reload_id` parameter is exercised only with `None` today.

## Why — learning objectives

- **One behaviour per test, and why a bare `assert_eq!` needs either a message or a smaller test** —
  ten unlabelled asserts in one function is a diagnosis you have to reconstruct by reading source.
  The fix is either a smaller test (preferred) or `assert_eq!(a, b, "what this pins")`. Note the
  counterexample: `standby_status_frame_layout` has 7 asserts and must **not** be split — one Act,
  seven views of the same artefact.
- **The walrus Tier-1 Arrow schema contract and the §2.6 `TypeDescriptor` round-trip these tests
  pin** — `build_schema` maps `numeric(10,2)` → `Decimal128(10,2)` and `timestamptz` →
  `Timestamp(Microsecond, "UTC")`, then appends `walrus_pg_sink_meta` as the last field; the
  descriptor is what lets the loader rebuild a Tier-2 column. Splitting the tests forces you to name
  which half of each contract you are pinning.

## Scope

**In scope** — four modules, three splits, AAA labels:

| file | today | after |
|---|---|---|
| `crates/pg-to-arrow/src/schema_test.rs:34` | 1 test, 10 asserts | 2 tests: field identity/order + per-column Tier-1 types |
| `crates/common/src/type_descriptor_test.rs:33` | 1 test, 9 asserts | 2 tests: decode field-by-field + re-serialise |
| `crates/pg-sink/src/manifest_test.rs:6` | 1 test, 8 asserts | 2 tests: stream row mapping + `reload_id` passthrough |
| `crates/pg-sink/src/replication_test.rs:11` | 1 test, 7 asserts | 1 test, AAA-labelled (**not** split) |

- Every touched test gets literal `// Arrange`, `// Act`, `// Assert` comment lines (the grep the
  probe uses is anchored: `^[[:space:]]*// (Arrange|Act|Assert)`).
- The new `manifest_test.rs` case is real new coverage: `to_ready_row`'s `reload_id` argument is
  passed `Some(_)` for the first time, with `kind: FileKind::Reload`.
- Where a split would otherwise duplicate an existing test, *move* the assertion rather than copy it
  (see the `tier` integer assertion versus `tier_serializes_as_integer`).

**Explicitly deferred** (do *not* build these here)

- Do **not** add AAA comments to the other ~200 sibling-test functions. Only these four modules.
  A tree-wide comment sweep is noise in `git blame` and buys nothing the three splits do not.
- Do **not** touch the 45 integration-test files under `crates/*/tests` or the 12 under
  `tests/e2e/tests`. Their "Arrange" is a compose stack, and consolidating that setup is **PR 28.6**.
- No production-code change. `build_schema`, `to_ready_row` and `build_standby_status` keep their
  signatures and behaviour exactly.
- Do not add an assertion-message sweep (`assert_eq!(a, b, "…")`) across the tree — inside the four
  touched modules only, and only where the split still leaves an ambiguous assert.

fn docs_example_descriptor_reserializes_to_the_same_json() {
    // Arrange
    let d: TypeDescriptor = serde_json::from_str(DOCS_DESCRIPTOR).unwrap();

    // Act — order-independent comparison through serde_json::Value.
    let reserialized: serde_json::Value =
        serde_json::from_str(&serde_json::to_string(&d).unwrap()).unwrap();

    // Assert
    let expected: serde_json::Value = serde_json::from_str(DOCS_DESCRIPTOR).unwrap();
    assert_eq!(reserialized, expected);
    // `tier` is the integer 2, not the string "2" — the codec half of `tier_serializes_as_integer`
    // (:21), asserted here on a *whole descriptor* rather than on the bare enum.
    assert_eq!(reserialized["tier"], serde_json::json!(2));

## Hints & gotchas

- **The probe's grep is anchored and exact.** `^[[:space:]]*// (Arrange|Act|Assert)( .*)?$` matches
  `    // Arrange` and `    // Assert — the Tier-1 mapping`, but **not** `// arrange`,
  `//Arrange`, or a trailing `// Act` on a code line. Write the markers on their own line, capital
  first letter, one space after `//`.
- **Do not chase a marker count.** Twelve is a floor that falls out of four modules × three sections;
  padding a passing test with `// Arrange` over an empty section is exactly the noise the *Explicitly
  deferred* section forbids.
- `assert_eq!(names, ["id", …])` compares `Vec<&str>` with an array — that works via
  `PartialEq<[&str; 5]> for Vec<&str>`. If the types fight you, compare against
  `&["id", …][..]` or collect into `Vec<String>`; do not fall back to five separate asserts.
- `Field::name()` returns `&String`, not `&str` — `.as_str()` in the map, or compare
  `&["id".to_string(), …]`.
- `FileKind` is a re-export: `pub use control::ManifestKind as FileKind;`
  (`crates/pg-sink/src/sink.rs:29`), with variants `Snapshot | Stream | Spill | Reload`. The
  `use crate::sink::FileKind;` on line 2 of `manifest_test.rs` stays — see PR 28.2's deferred list.
- `to_ready_row` is **private** (`fn`, not `pub fn`). That is precisely why this test is a sibling
  unit test and not an integration test — `crates/pg-sink/tests/manifest_insert.rs` can only reach
  `record_ready_with_reload`, and it needs compose.
- `unwrap()`/`expect()` are allowed in test code (`clippy.toml` sets `allow-unwrap-in-tests`), so the
  existing `.parse().unwrap()` calls stay. Do not "fix" them.
- The three splits each add a test, so PR 28.3's name gate runs on the new names — keep them ≥ 2
  words and never `test_`-prefixed.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache. Add no dependency — anything
  new must clear `cargo deny`.
