# PR 28.2 — Enforce `use super::` as the first line of every sibling test module

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 28 — Rust testing · **Crates touched:** none (repo tooling: `scripts/`) ·
> **Est. size:** S · **Depends on:** PR 28.1 · **Unlocks:** PR 28.3

All **47** sibling test files already open with `use super::` on **line 1** — 46 with the glob
`use super::*;` and one, `crates/loader/src/phase_a_test.rs:1`, with the explicit
`use super::{pause_began, raw_append_lag_bytes};` that the rule's own "Selective Imports" section
blesses. Seven supplementary `use crate::…` lines sit on line 2 or 3 of six files, so the road back
to fully-qualified absolute imports is open and nothing is standing on it. This PR adds one more
function to `scripts/test-hygiene.sh` (landed in PR 28.1) turning the convention into a
machine-checked invariant: line 1 of every `*_test.rs` under `crates/*/src` must start with
`use super::`. Zero Rust files change.

## Why — learning objectives

- **Module-path resolution: `super::` vs `crate::`** — a sibling test file is compiled as a *child*
  of the module under test, so `super::*` glob-imports its parent's items, private ones included,
  and keeps working when the module is renamed or moved. `crate::…` is absolute: it hard-codes the
  module's location, and it can only reach items whose visibility extends to the *importing*
  module — which is exactly why `crates/pg-sink/src/manifest_test.rs:2` can say
  `use crate::sink::FileKind;` (`FileKind` is `pub`) but could not say it for a private item of
  `sink`.
- **Turning an existing convention into a machine-checked invariant** — the difference between a
  sentence in a README (that decays) and a `grep` in CI (that does not). This is a *Enforce* ticket:
  the tree is already 47/47 conformant; the deliverable is the gate, not a refactor.

## Scope

**In scope**

- One new function in `scripts/test-hygiene.sh` — `check_first_line_use_super` — asserting that
  **line 1** of every `crates/**/src/**/*_test.rs` matches `^use super::`.
- The failure message distinguishes the two ways to break it: *missing* (`use super::` appears
  nowhere) versus *demoted* (`use super::` is present but not on line 1).
- The summary line grows a second clause, e.g. `47/47 sibling test modules paired · 47/47 open with

**Explicitly deferred** (do *not* build these here)

- Do **not** rewrite `crates/loader/src/phase_a_test.rs:1` from `use super::{pause_began,
  raw_append_lag_bytes};` to a glob. The rule permits selective parent imports and the explicit form
  documents which two private helpers the module pins.
- Do **not** touch the seven supplementary `use crate::…` lines
  (`crates/pg-to-arrow/src/tier3_test.rs:2`, `crates/pg-to-arrow/src/parquet_test.rs:2-3`,

- No check on import *ordering* beyond line 1, and no check on `crates/*/tests/**` — integration
  test files have no parent module and must use the crate's public path.

## Skeleton

```bash
# scripts/test-hygiene.sh — new function, called from the same list as PR 28.1's three checks.

# Check 4 (PR 28.2) — line 1 of every sibling test file imports its parent module.
# Both forms are legal: the glob `use super::*;` (46 files) and the selective
# `use super::{a, b};` (crates/loader/src/phase_a_test.rs). What is NOT legal is reaching the
# parent through an absolute `crate::` path, or burying `use super::` under another import.
check_first_line_use_super() {
    local t first
    while IFS= read -r t; do
        first=$(head -1 "$t")
        case "$first" in
            "use super::"*) ;;                      # conformant — glob or selective
            *) todo "if the file contains a 'use super::' line at all → 'must be line 1, found at
                     line N'; otherwise → 'missing: add use super::*; as line 1'" ;;
        esac
    done < <(todo "find crates -path '*/src/*' -name '*_test.rs'")
}
```

## Hints & gotchas

- **The rule overstates one thing; do not repeat it in the ADR.** Its "Bad" block claims a
  `use crate::…` path "can't access private items". In Rust a *descendant* module may name an
  ancestor's private items by any path, so `use crate::my_module::private_fn;` compiles from
  `my_module::tests`. The honest arguments for `super::` are refactor-robustness (rename the module,
  the test file needs no edit), relative depth (`pgoutput::typmod_test.rs` would otherwise need
  `use crate::pgoutput::typmod::*;`), and reach — an absolute path can only name items visible from
  the importing module, which is why `manifest_test.rs` can pull `crate::sink::FileKind` only
  because it is `pub`.
- `head -1` on an empty file yields the empty string, which correctly fails the `use super::` match —
  but under `set -euo pipefail` a `head` on a *missing* file aborts the script. PR 28.1's check 2
  already guarantees each `*_test.rs` has a parent; it does not guarantee readability. Guard with
  `[ -r "$t" ]`.
- Do not use `grep -q '^use super::' "$t"` — that passes when the import is on line 30. The whole
  point is *line 1*, so compare `head -1` exactly.
- Bash `case` with the `"use super::"*` pattern is cheaper and safer than a regex here (no escaping
  of `::`, no locale surprises). If you prefer `grep -E`, remember `^use super::` needs no escape but
  `super::\*` does.
- Keep the failure text actionable and *both-formed*: a contributor who wrote `use crate::foo::*;`
  needs to be told to write `use super::*;`, and one who put the import second needs to be told to
  move it up. One generic message for both wastes the gate.
- `scripts/**` is in the `changes` job's `code:` filter, so this PR runs the full heavy CI suite even
  though no Rust changes. Expect a normal-length run.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache. Add no dependency — anything
  new must clear `cargo deny`.
