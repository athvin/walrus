# PR 28.1 — Guard sibling unit-test module wiring

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** —

> **Phase:** 28 — Rust testing · **Crates touched:** none (repo tooling: `scripts/`, `justfile`,
> `.github/workflows/ci.yml`) · **Est. size:** M ·
> **Depends on:** PR 27.16 · **Unlocks:** PR 28.2

walrus deliberately moved every unit-test module out of inline `#[cfg(test)] mod tests {}` into
Go-style siblings during PRs 7.1–7.3. Today the tree has **47** `*_test.rs` files, **47** matching
`#[cfg(test)] #[path = "…_test.rs"] mod tests;` declarations, and **zero** inline `mod tests {`
blocks under `crates/*/src` — the rule's *intent* (test code compiled only under `cfg(test)`, with
access to private items) is fully satisfied; only its placement differs. What does not exist is any
gate: nothing stops a new module from regressing to the inline form, and nothing catches a
`foo_test.rs` that no `foo.rs` declares (it would silently never run). This PR lands
`scripts/test-hygiene.sh` — the repo-hygiene gate that PRs 28.2, 28.3 and 28.15 extend — wires it
into the CI `gates` job as the cheapest step, and records the deviation as an ADR so the next reader
of the corpus rule does not "fix" the tree back.

## Why — learning objectives

- **`#[cfg(test)]` + `#[path]` module wiring** — what a unit test can reach that an integration test
  cannot: `foo_test.rs` is compiled *as a child module of* `foo`, so `use super::*` sees private
  items; a file under `crates/*/tests/` is a separate crate and sees only the `pub` surface.
- **walrus's Go-style sibling-test convention** — why the roadmap adopted it over inline modules
  (production file stays the production file; `wc -l src/duck.rs` means something), and why that is a
  *placement* change, not a semantic one.

## Read first

- [`test-cfg-test-module`](../../../.claude/skills/rust-skills/rules/test-cfg-test-module.md) — take
  the *reason* (`#[cfg(test)]` keeps test code out of release builds; the tests module is a child of
  the module under test, so it reaches private items) and notice that its "Bad" example is a
  `tests/my_module_test.rs` at the **crate root** — a different crate — not a sibling wired by
  `#[path]`. That distinction is the whole ADR.
- `crates/common/src/lsn.rs:157-159` — the canonical three-line footer:
  `#[cfg(test)]` / `#[path = "lsn_test.rs"]` / `mod tests;`. Every one of the 47 looks like this.
- `crates/pg-sink/src/pgoutput/typmod.rs:22-24` — the same footer one directory deep
  (`crates/pg-sink/src/pgoutput/`), which is why the script must walk subdirectories, not just
  `crates/*/src/*.rs`.
- `crates/loader/src/duck.rs:209` — `#[cfg(test)] pub fn cached_schema_versions(&self)`: a
  *production* item gated on `cfg(test)` as a test probe. The guard must not mistake this for a test
  module.
- `crates/loader/src/duck.rs:404-406` — the footer again, at the end of a 400-line module.
- `scripts/k8s-validate.sh` — the house style for a repo gate: `set -euo pipefail`, `cd "$(git
  rev-parse --show-toplevel)"`, a header comment naming the PR, section `echo`s, and a final
  `PASS` line. Copy that shape.
- `.github/workflows/ci.yml:53-100` — the `gates` job. Note `needs.changes.outputs.code` and that
  `scripts/**` is already in the `changes` filter (`ci.yml:38-50`), so touching the script re-runs
  the job.

## Scope

**Audited baseline precondition:** Re-run the task probes after every predecessor merges.

**Baseline mismatch:** If the audited finding no longer holds—including because the required postcondition is already satisfied—stop and re-author this ticket before selection. This change task does not authorize a substitute refactor, a no-op completion, or an evidence-only PR.

**In scope**

- New `scripts/test-hygiene.sh` with three checks:
  1. **no inline test modules** — `#[cfg(test)]` immediately followed by `mod tests {` anywhere
     under `crates/*/src`;
  2. **every sibling is declared** — for each `crates/**/src/**/*_test.rs`, the parent
     `<stem>.rs` exists *and* contains `#[path = "<basename>"]`;
  3. **every declaration resolves** — for each `#[path = "…_test.rs"]` under `crates/*/src`, the
     named file exists next to the declaring file.
- The script accepts `TEST_HYGIENE_ROOT` (default `crates`) and a `--self-test` mode that creates
  isolated temporary fixtures for all three failure cases. It never edits a tracked Rust file.
- The script prints `47/47 sibling test modules paired` and exits `0` on today's tree; it exits `1`
  with a per-violation line otherwise.
- A `hygiene` recipe in the `justfile` so "green locally" is the same command CI runs.
- A CI step in the **`gates`** job, placed immediately after `actions/checkout@v4` — it is a
  sub-second grep and must fail before the ~20-minute bundled-DuckDB build starts.
- An ADR at `docs/implementation/notes/sibling-unit-tests.md` recording the deviation, its evidence
  (47/47/0), and what would reverse it.

**Explicitly deferred** (do *not* build these here)

- `clippy::tests_outside_test_module` stays untouched. It may well fire on the 58 top-level `#[test]`
  functions in `crates/*/tests/*.rs` (integration tests, where it is a false positive) — evaluating
  and configuring it is **Phase 33**'s `lint-*` work, not this ticket's.
- The `use super::` first-line check is **PR 28.2**; the test-function-name check is **PR 28.3**; the
  lock-free tripwire is **PR 28.15**. All three extend *this* script — leave clean seams (one
  function per check, one call site each), but do not write them here.
- Do not touch `tests/e2e` or `crates/*/tests/**` — those are integration crates by design and have
  no parent module to be a sibling of.

**Conflict — resolve it explicitly, do not apply the rule blindly.**
CONTEXT §4 pre-decides this rule: the corpus asks for inline `#[cfg(test)] mod tests {}`; walrus
moved all 47 modules to sibling `*_test.rs` in PRs 7.1–7.3. The required resolution is a **documented
deviation plus a guard asserting the sibling pattern**. This PR must **not** revert a single module
to the inline form, and must not add an inline module anywhere. The ADR is what makes the deviation
reviewable; the script is what makes it durable.

## Skeleton

```bash
#!/usr/bin/env bash
# scripts/test-hygiene.sh — PR 28.1 unit-test convention gate. walrus keeps unit tests in Go-style
# SIBLING files (src/foo.rs → src/foo_test.rs, wired by `#[cfg(test)] #[path] mod tests;`), not in
# inline `#[cfg(test)] mod tests {}` blocks — see docs/implementation/notes/sibling-unit-tests.md.
# This is the same command CI runs, so "green locally" predicts "green in CI".
#
#   bash scripts/test-hygiene.sh
#
# Exits 0 with a one-line summary, or 1 listing every violation.
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"

fail=0
bad() { fail=1; printf '  FAIL: %s\n' "$*"; }

# Check 1 — no inline `#[cfg(test)] mod tests {` under crates/*/src.
# NOTE: `#[cfg(test)]` on a *function* (crates/loader/src/duck.rs:209) is legitimate; only the
# two-line attribute-then-`mod tests {` sequence is a violation, so match on the `mod` line.
check_no_inline_modules() {
    todo "grep -rn --include='*.rs' 'mod tests {' crates/*/src → every hit is a violation"
}

# Check 2 — every sibling *_test.rs is declared by its parent with #[path].
# Walks subdirectories too (crates/pg-sink/src/pgoutput/typmod_test.rs).
check_siblings_declared() {
    todo "for t in crates/*/src/**/*_test.rs: parent=\${t%_test.rs}.rs must exist AND contain
          '#[path = \"'\$(basename \$t)'\"]' — else 'orphan test file, nothing declares it'"
}

# Check 3 — every #[path = "..._test.rs"] declaration resolves to a real file next to the declarer.
check_declarations_resolve() {
    todo "parse the #[path = \"…\"] value out of each declaring file; the sibling must exist"
}

echo "== unit-test hygiene (crates/*/src) =="
check_no_inline_modules
check_siblings_declared
check_declarations_resolve

paired=$(todo "count of *_test.rs files"); declared=$(todo "count of #[path] declarations")
[ "$fail" -eq 0 ] || { echo "test-hygiene: FAIL"; exit 1; }
echo "$paired/$declared sibling test modules paired"
echo "test-hygiene: PASS"
```

## Hints & gotchas

- **`#[cfg(test)]` is not the marker — `mod tests {` is.** `crates/loader/src/duck.rs:209` gates a
  *production* method on `cfg(test)`, and every one of the 47 footers has `#[cfg(test)]` on its own
  line. Grep for the `mod tests {` line, then (optionally) look back one or two lines for the
  attribute. Do not grep for `#[cfg(test)]` and count hits.
- **Walk subdirectories.** `crates/*/src/*_test.rs` finds 43 of the 47 — the `pgoutput` module has
  four (`typmod_test.rs`, and friends) one level down. Use `find crates -name '*_test.rs'` or
  `**` with `shopt -s globstar`; the repo's other scripts use plain `find`.
- `set -euo pipefail` plus `grep`'s exit-1-on-no-match is the classic footgun: a bare
  `count=$(grep -c … )` **aborts the script** when the count is legitimately zero. Use
  `grep -c … || true`, or `|| :`, on every counting grep.
- Make the failure message actionable: print `file:line` and name the fix ("use a sibling
  `foo_test.rs`"), plus the ADR path. A gate nobody can act on gets `#[allow]`ed away.
- `.github/**` and `scripts/**` are both in the `changes` job's `code:` filter
  (`.github/workflows/ci.yml:38-50`), so this PR is *not* docs-only and the heavy jobs will run.
  Budget for a full CI cycle.
- Keep the three checks as three shell functions with a shared `bad()` accumulator, and let the
  script report **all** violations before exiting rather than dying on the first — 28.2, 28.3 and
  28.15 each bolt one more function onto the same list.
- `chmod +x scripts/test-hygiene.sh` and commit the mode bit, matching the other four scripts; but
  invoke it as `bash scripts/…` in CI and the justfile the way `k8s-validate.sh` is invoked, so the
  bit is not load-bearing.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache (there is no Docker on this
  machine to regenerate it). Add no dependency — anything new must clear `cargo deny`.
