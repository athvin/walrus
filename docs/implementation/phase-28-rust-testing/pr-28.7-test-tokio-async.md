The tree has **135** `#[tokio::test]` functions: 115 on the bare attribute, 18 carrying
`flavor = "multi_thread", worker_threads = 4` (all compose/e2e), and exactly **2** on
`start_paused = true` (`crates/pg-sink/src/reload_test.rs:17,40`). One hermetic async test still
burns wall-clock to get its answer: `cap_of_two_schedules_third_request_only_after_a_permit_frees`
(`crates/pg-sink/src/reload_test.rs:68`) calls `tokio::time::sleep(Duration::from_millis(50))`
twice — at lines 89 and 104 — purely to give three spawned tasks time to reach the semaphore. That
is 100 ms of scheduler-dependent latency inside every `cargo test --workspace`, and a flake waiting
for a loaded CI runner: nothing in the test *requires* 50 ms, it just hopes 50 ms is enough. After
this PR the test runs on Tokio's virtual clock, so the same two `sleep` calls advance time instantly
and the assertion pins the **scheduling shape** (cap of two, third waits, third runs when a permit
frees) rather than a timing guess. `tokio`'s `test-util` feature is already a pg-sink dev-dependency
(`crates/pg-sink/Cargo.toml:60`) — it is what the two existing `start_paused` tests use — so no
dependency changes.

## Why — learning objectives

- **Tokio test runtime flavors and `start_paused` virtual time** — how the auto-advance-when-idle
  rule turns a `sleep` into a zero-cost "let every other task make progress" barrier, and why it
  only works on a single-threaded runtime.
- **The reload controller's semaphore cap** — `docs/single-table-reload.md` §5 caps concurrent
  exports at `max_concurrent_reloads`; permits live *inside* the exporter tasks, so what the test
  must pin is the scheduling shape, not how many milliseconds a spawn takes.

**The rule's factual error — do not copy it**

The rule file says, verbatim:

```rust
// Multi-threaded runtime (default)
#[tokio::test]
async fn test_default_runtime() {
    // Uses multi-thread runtime
}
```

That is **wrong**. `#[tokio::test]` defaults to `flavor = "current_thread"`; `multi_thread` is
opt-in, which is exactly why all 18 multi-threaded tests in this tree spell it out. The correction
matters here rather than being pedantry: `start_paused = true` **requires a current-thread runtime**
and panics on `multi_thread`, so it composes with the bare attribute only *because* the default is
single-threaded. Write the correction into the task's PR body and (one line) next to the attribute.

- The **18 `flavor = "multi_thread", worker_threads = 4`** attributes in the e2e/compose tests are

## Skeleton

```rust
// crates/pg-sink/src/reload_test.rs — the only edit, at line 68.

// `start_paused` puts this test on Tokio's VIRTUAL clock. The runtime auto-advances time whenever
// every task is idle, so the two barriers below cost 0 ms of wall clock and no longer depend on a
// loaded CI runner scheduling three spawned tasks inside 50 ms. NOTE: `start_paused` requires the
// current-thread flavor — which IS `#[tokio::test]`'s default, despite what the rule file claims.
#[tokio::test(start_paused = true)]
async fn cap_of_two_schedules_third_request_only_after_a_permit_frees() {
    // The scheduling shape `tick` relies on: permits live inside the exporter tasks, so a
    // third export starts only when one of the first two releases its permit.
    let semaphore = Arc::new(Semaphore::new(2));
    let started: Vec<Arc<AtomicUsize>> = (0..3).map(|_| Arc::new(AtomicUsize::new(0))).collect();
    let mut releases = Vec::new();
    let mut handles = Vec::new();
    for flag in &started {
        // …unchanged: spawn three tasks that acquire_owned(), set their flag, then park on `rx`
        // while HOLDING the permit.
        todo!()
    }

    // Barrier 1 — not a delay. Under paused time the clock jumps the moment the three spawned
    // tasks are parked, so this is "let every other task run to its next await point", for free.
    tokio::time::sleep(Duration::from_millis(50)).await;
    let started_count = || todo!(); // unchanged closure
    assert_eq!(started_count(), 2, "cap of two holds; the third waits");

    // Free exactly ONE permit …
    todo!();

    // Barrier 2 — same reasoning: the released task drops its permit, the parked third task wakes,
    // and only then does the clock advance past this sleep.
    tokio::time::sleep(Duration::from_millis(50)).await;
    assert_eq!(started_count(), 3, "the third started once a permit freed");

    // …unchanged: drain the remaining oneshots, join the handles, assert permits returned.
    todo!()
}
```

If you prefer the explicit form over the auto-advancing sleep, the barrier becomes:

```rust
// Yield until every spawned task has reached its next await point. On a current-thread runtime one
// `yield_now` only guarantees ONE trip through the ready queue, and barrier 2 needs two hops
// (released task wakes -> drops permit -> third task wakes), so loop rather than yielding once.
for _ in 0..8 {
    tokio::task::yield_now().await;
}
```

## Hints & gotchas

- **`start_paused = true` panics on `flavor = "multi_thread"`.** Virtual time is a property of the
  single-threaded timer driver. If you also add a flavor, the test dies at startup with a runtime
  builder panic — leave the flavor off and take the `current_thread` default.
- **Auto-advance only fires when *every* task is idle.** If any task is busy-looping or in a
  `std::thread::sleep`, the clock never jumps and the test hangs forever instead of failing. That is
  why the three spawned tasks must park on their `oneshot` receivers (they already do) rather than
  spin.
- **`std::time::Instant` is not paused.** Only `tokio::time` is virtual. Do not add an
  `Instant::now()` duration assertion to "prove" the speedup — measure it with the libtest
  `finished in` line instead.
- **One `yield_now()` is not a barrier.** On a current-thread runtime it hands control back exactly
  once. Barrier 2 needs at least two hops (the released task must wake, drop its permit, and only
  then does the third task's `acquire_owned` complete). If you go the `yield_now` route, loop.
- **`.unwrap()` here is fine.** `clippy.toml` sets `allow-unwrap-in-tests = true` /
  `allow-expect-in-tests = true`, and this file is a `#[cfg(test)]` sibling module — the workspace
  `unwrap_used`/`expect_used` denies do not reach it. Do not "improve" the existing unwraps.
- **Unit tests here are sibling files, not inline modules.** `reload_test.rs` is wired by
  `#[cfg(test)] #[path = "reload_test.rs"] mod tests;` at the bottom of `reload.rs`; do not create a
  `mod tests {}` block (PR 28.1 guards this).
- **`clippy::all` and `warnings` are already `deny`.** An unused `Duration` import after a
  `yield_now` rewrite will fail CI, not warn.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it. No new dependency, so nothing new for `cargo deny` to clear.
