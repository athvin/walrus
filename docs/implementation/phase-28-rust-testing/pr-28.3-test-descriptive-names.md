# PR 28.3 — Reject placeholder names in sibling unit tests

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** —

> **Phase:** 28 — Rust testing · **Crates touched:** none (repo tooling: `scripts/`) ·
> **Est. size:** S · **Depends on:** PR 28.2 · **Unlocks:** PR 28.4

The tree carries **432** test functions and **zero** of them is named `test_*`, `test1`, `it_works`
or `test_function`. The shortest name is `begin_decodes` (13 characters) and only **2** of the 432
have fewer than three underscore-separated words. Naming here is already exemplary —
`rolled_back_savepoint_never_materializes`, `cap_of_two_schedules_third_request_only_after_a_permit_frees`,
`equal_lsn_end_snapshot_files_all_land` — and it is enforced by absolutely nothing. This PR adds the
third check to `scripts/test-hygiene.sh`: a `#[test]` / `#[tokio::test]` function may not be prefixed
`test_`, may not be a single word, and may not be one of the classic placeholders. It exits `0` on
all 432 names today and fails CI the first time someone commits `#[test] fn test_it() {}`.

## Why — learning objectives

- **Test names as executable documentation** — libtest prints one line per failure and nothing else:
  `test cap_of_two_schedules_third_request_only_after_a_permit_frees ... FAILED` has to carry the
  whole diagnosis on its own. `test_reload ... FAILED` sends you reading source.
- **Writing a repo-hygiene gate that parses Rust attributes with grep/perl** — an attribute macro or
  a proc macro would be the "real" way and costs a dependency plus a compile; a 20-line forward scan
  over `#[…]` lines is exact here because the tree has exactly one intervening attribute form.

## Read first

- [`test-descriptive-names`](../../../.claude/skills/rust-skills/rules/test-descriptive-names.md) —
  take the "Bad" list (`test1`, `test_parse`, `it_works`, `test_function`) as the literal blocklist
  seed, and the three naming patterns (`function_condition_expected_result`,
  `scenario_expectation`, `when_given_then`) as *guidance the gate deliberately does not enforce*.
- `crates/common/src/lsn_test.rs:4` — `parses_x_slash_y_form`: `scenario_expectation`, three words,
  no `test_` prefix. The median shape.
- `crates/pg-to-arrow/src/tier2_test.rs:14` — `interval_1_month_ne_30_days_ne_720_hours`: digits and
  an operator abbreviation inside the name. The regex must accept `[a-z0-9_]`, not `[a-z_]`.
- `tests/e2e/tests/subtxn_abort.rs:12-14` — `#[tokio::test(flavor = "multi_thread", worker_threads =
  4)]` then `#[ignore = "…"]` then `async fn rolled_back_savepoint_never_materializes()`. This is
  the two-line-gap case; the parser must skip intervening attributes.
- `crates/pg-sink/src/reload_test.rs:68-69` — the longest name in the tree
  (`cap_of_two_schedules_third_request_only_after_a_permit_frees`) on a bare `#[tokio::test]`.
- `scripts/test-hygiene.sh` (PRs 28.1, 28.2) — the accumulator and function-per-check structure.

**In scope**

- A `check_test_fn_names` function in `scripts/test-hygiene.sh` covering **both** `crates/**` and
  `tests/**` (unlike checks 1–4, which are `crates/*/src`-only — integration and e2e test names are
  exactly the ones a failing CI log shows you).
- The mechanical floor, and only the floor. A name fails if it:
  - starts with `test_` (or is exactly `test`);
  - contains fewer than two `_`-separated words (`begin_decodes` = 2 words, passes);
  - is in the blocklist `it_works`, `works`, `basic`, `smoke`.
- Attribute parsing: from a line matching `^\s*#\[(tokio::)?test[\](]`, scan forward over further
  `#[…]` lines to the first `^\s*(pub )?(async )?fn <name>` and take `<name>`.
- The summary line grows a clause: `432/432 test names describe a behaviour`.
- Extend `--self-test` with isolated fixtures for the rejected placeholder-name family and accepted
  behavior-describing names. Do not append temporary functions to tracked Rust files.

**Explicitly deferred** (do *not* build these here)

- **Rename nothing.** All 432 names already pass; a rename in this PR is scope creep and churns
  `git blame` on test files four other Phase-28 tickets are about to touch.
- No enforcement of a specific naming *grammar* — `fn_condition_result` versus
  `scenario_expectation` is a style choice the tree makes per module, and a gate that picks one would
  fail ~half the suite.
- No maximum length, no vocabulary check, no `#[should_panic]`-specific naming (PR 28.10 adds the

- Do not extend the check to `#[bench]` (there are none — criterion benches use `harness = false`)

## Skeleton

```bash
# scripts/test-hygiene.sh — check 5 (PR 28.3). Covers crates/** AND tests/** (unlike checks 1-4).

# Blocklist: the rule's own "Bad" names, plus the two placeholders `cargo new`-era code grows.
TEST_NAME_BLOCKLIST='it_works works basic smoke'

# From `#[test]` / `#[tokio::test]` / `#[tokio::test(flavor = "…", worker_threads = 4)]`, skip any
# further attribute lines (only `#[ignore = "…"]` occurs today, 97 times) and take the fn name.
check_test_fn_names() {
    todo 'perl -0777 -ne  (or awk) over every *.rs under crates/ tests/:
            match  ^[ \t]*#\[(tokio::)?test[\](]
            then   skip lines matching ^[ \t]*#\[
            then   capture ^[ \t]*(pub )?(async )?fn ([a-z0-9_]+)
          For each captured NAME, fail when:
            NAME == test            || NAME starts with "test_"
            || NAME has no "_"      (fewer than two words)
            || NAME in $TEST_NAME_BLOCKLIST
          Report as  file:line  NAME  reason.'
}
```

## Hints & gotchas

- **The gap is 1 or 2 lines, never more.** Of the 432 attribute sites, 335 are followed directly by
  the `fn`, and 97 have exactly one `#[ignore = "…"]` in between. A `grep -A3` heuristic works today,
  but write the scan as "skip lines starting with `#[`" so PR 28.10's `#[should_panic(expected =
  …)]` and PR 28.7's `#[tokio::test(start_paused = true)]` do not break it.
- Match the attribute as `#[(tokio::)?test` followed by `]` **or** `(` — `#[tokio::test(flavor =
  "multi_thread", worker_threads = 4)]` (18 sites) and `#[tokio::test(start_paused = true)]` (2
  sites) both exist. A plain `#\[test\]$` anchor silently skips 135 async tests.
- Do **not** match `#[test` as a prefix without the boundary: it would also hit a hypothetical
  `#[test_case(...)]`. Anchor on `test` followed by `]` or `(`.
- `set -euo pipefail` + `grep -c` returning 1 on zero matches will abort the script. Every counting
  grep needs `|| true`.
- `begin_decodes` / `commit_decodes` are the tightest constraint in the tree. They are honest names
  (the pgoutput `Begin` and `Commit` messages decode), so the floor is "at least one underscore",
  not "at least two".
- **Anticipate PR 28.12.** `proptest!` blocks put `#[test]` *inside* a macro invocation with unusual
  indentation. Leading whitespace is already allowed by the `^[ \t]*` anchor — keep it; do not anchor
  at column 0.
- Emit `file:line` in every failure. A name-only message ("`test_it` is bad") in a 432-test tree is
  not actionable.
- `scripts/**` is in the `changes` job's `code:` filter, so the full heavy CI suite runs on this PR
  despite zero Rust changes.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache. Add no dependency — anything
  new must clear `cargo deny`.
