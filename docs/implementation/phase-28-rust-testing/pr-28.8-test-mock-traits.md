# PR 28.8 — Add hermetic object-store success and failure tests

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink,loader

> **Phase:** 28 — Rust testing · **Crates touched:** `pg-sink`, `loader` · **Est. size:** M ·
> **Depends on:** PR 28.7 · **Unlocks:** PR 28.9

walrus already has the seam this rule asks for and does not use it. `ParquetSink` holds an
`Arc<dyn ObjectStore>` (`crates/pg-sink/src/sink.rs:49`) and the loader's `verify_s3_read` takes
`&dyn ObjectStore` (`crates/loader/src/bootstrap.rs:179`) — textbook dynamic-dispatch injection
points — yet `object_store::memory::InMemory` appears at exactly **2** sites in the whole tree
(`crates/pg-sink/src/sink_test.rs:5`, `crates/pg-sink/src/stream_txn_test.rs:60`) and neither one
ever calls `put`, `delete` or `head`; both only build object *keys*. Every real S3 assertion is
therefore `#[ignore]`d behind compose MinIO — 3 of them in `crates/pg-sink/tests/parquet_put.rs`
alone, part of the 97 `#[ignore]` attributes across 432 tests. After this PR the Parquet write path,
the speculative-object delete, and the store-error mapping all have hermetic coverage that runs in
`cargo test -p pg-sink --lib` with no Docker, and the loader's three-armed `verify_s3_read` match
gets its first test at all.

## Why — learning objectives

- **Static vs dynamic dispatch for test doubles** — `Arc<dyn Trait>` seams, and the fake / stub /
  mock distinction: `InMemory` is a *fake* (a real working implementation), `FailingStore` is a
  *stub* (canned failure), and neither one needs an expectation DSL.
- **The walrus staging contract** — `<epoch>/<schema>/<table>/<lsn_end>-<uuid>.parquet` with
  `lsn_end` as zero-padded 16-hex, and the durable-before-manifest ordering that makes
  `ParquetSink::put` return only after `AsyncArrowWriter::close()` completes the multipart upload.

**In scope**

1. **Widen the `sink_test.rs` helper** so a test can hold the store *and* the sink: keep a
   `sink()`-shaped convenience, add `fn mem() -> Arc<InMemory>` and a `fn sink_over(store) ->
   ParquetSink`, so assertions can `head`/`get` the object the sink just wrote.
2. **Hermetic Parquet round-trip.** Port `sealed()` (relation + `SinkMeta` + one row through
   `BatchBuilder`) into the sibling test module and assert, with no Docker: `put_with_kind` returns
   a `WrittenObject` whose `key` starts `<epoch>/public/orders/`, contains the 16-hex `lsn_end` and
   ends `.parquet`; `s3_uri` is `s3://<bucket>/<key>`; `kind` is what you passed; and
   `store.head(&written.key)` reports non-zero bytes — i.e. `put` really did return only after the
   multipart completed.
3. **Speculative-object delete.** `ParquetSink::delete(&written.key)` succeeds and a following
   `store.head(&key)` is `Err(object_store::Error::NotFound { .. })`. This is the PR 2.30 abort path
   (a streamed txn's spilled file with no manifest row) and it has never been exercised.
4. **A deliberately-failing store.** Add a `FailingStore` stub implementing `ObjectStore` (all 8
   required methods; delegate `list`/`list_with_delimiter` to an inner `InMemory` so you are not
   inventing a stream, and return `object_store::Error::Generic` from the rest). Build a
   `ParquetSink` over it and assert `put(...)` is an `Err` — then **assert the variant it actually
   is and write a comment explaining why**. It may well be `SinkError::Encode` rather than
   `SinkError::Store`, because a multipart failure travels back through `AsyncArrowWriter` and
   `put_with_kind` maps every writer error with `|e| SinkError::Encode(e.to_string())`. If that is
   what you find, that finding *is* the deliverable — pin it, do not force the assertion to the
   variant you expected. Also assert the cheap direct mapping:
   `sink.delete(&absent_key)` on `InMemory` yields `Err(SinkError::Store(_))` via the `#[from]`.
5. **Loader: cover `verify_s3_read`'s reachable arm.** Create the sibling
   `crates/loader/src/bootstrap_test.rs`, wire it with
   `#[cfg(test)] #[path = "bootstrap_test.rs"] mod tests;` at the bottom of `bootstrap.rs`, and
   assert that an empty `InMemory` returns `Ok(())` — a `NotFound` on the `__walrus_loader_probe__`
   key means "reachable, key absent", which is the whole point of that arm.
6. **Two dev-dependencies, zero new crates.** `FailingStore` needs `async-trait` (the trait is
   declared `#[async_trait]` and `object_store` does not re-export it) and `futures-core` (to *name*
   `BoxStream` in `list`'s signature). Both are already in `Cargo.lock` — `async-trait 0.1.89`,
   `futures-core 0.3.32` — pulled transitively by `object_store`/`sqlx`, so promoting them to
   declared dev-dependencies adds **no** crate to the graph. Pin them in
   `[workspace.dependencies]` with a justifying comment, exactly as `parking_lot` was promoted.

**Explicitly deferred** (do *not* build these here)

- **No `#[ignore]` is removed.** The three MinIO tests in `crates/pg-sink/tests/parquet_put.rs` also
  assert against real S3 keys and the control plane; hermetic coverage is added *alongside* them,
  not instead of them.
- **No new trait is extracted** over `sqlx::PgPool`, `duckdb::Connection` or
  `tokio_postgres::Client`. Those are concrete foreign structs and are exactly why 97 tests are
  compose-gated — that is PR 28.9's subject, not a refactor to attempt here.
- **The loader's `Err(other)` arm stays uncovered.** It needs the same `FailingStore`, and
  duplicating a 60-line `ObjectStore` impl into a second crate to reach one `map_err` is a bad
  trade. Note it in the test file; promote the stub to shared test support only if a third crate
  ever needs it.
- No change to `ParquetSink`, `verify_s3_read`, or any other production signature. The seams already
  exist; this PR only uses them.

// ---- the stub -----------------------------------------------------------------------------------
/// Always fails the object-facing operations; delegates only the two listing methods so we never
/// hand-roll a `BoxStream`. `object_store::ObjectStore` has 8 methods with no default body —
/// everything else (`put`, `get`, `head`, `rename`, …) routes through these.
#[derive(Debug, Default)]
struct FailingStore(InMemory);

impl std::fmt::Display for FailingStore {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "FailingStore")
    }
}

fn boom() -> object_store::Error {
    object_store::Error::Generic { store: "FailingStore", source: "injected failure".into() }
}

#[async_trait::async_trait]
impl ObjectStore for FailingStore {
    async fn put_opts(&self, _: &Path, _: PutPayload, _: PutOptions) -> object_store::Result<PutResult> { Err(boom()) }
    async fn put_multipart_opts(&self, _: &Path, _: PutMultipartOpts) -> object_store::Result<Box<dyn MultipartUpload>> { Err(boom()) }
    async fn get_opts(&self, _: &Path, _: GetOptions) -> object_store::Result<GetResult> { Err(boom()) }
    async fn delete(&self, _: &Path) -> object_store::Result<()> { Err(boom()) }
    fn list(&self, prefix: Option<&Path>) -> futures_core::stream::BoxStream<'_, object_store::Result<ObjectMeta>> {
        self.0.list(prefix)
    }
    async fn list_with_delimiter(&self, prefix: Option<&Path>) -> object_store::Result<ListResult> {
        self.0.list_with_delimiter(prefix).await
    }
    async fn copy(&self, _: &Path, _: &Path) -> object_store::Result<()> { Err(boom()) }
    async fn copy_if_not_exists(&self, _: &Path, _: &Path) -> object_store::Result<()> { Err(boom()) }
}

## Hints & gotchas

- **`InMemory` is a fake, not a mock.** It really stores bytes, so `head` after `put` is a genuine
  durability assertion — that is the whole reason this seam is worth using instead of an expectation
  DSL. Do not add assertions about *how many times* the store was called; that is mock thinking and
  PR 28.9 explains why walrus rejects it.
- **Implementing `ObjectStore` is 8 methods, not 2.** `put`, `get`, `head`, `rename`,
  `rename_if_not_exists`, `get_range`, `get_ranges`, `delete_stream` and `list_with_offset` all have
  default bodies that route through the required ones — which is exactly why failing `get_opts` is
  enough to make `head` fail. Read the trait first; the compiler's "not all trait items implemented"
  error is a long one.
- **`futures-core`, not `futures`.** You only need the `BoxStream` type alias. Pulling the whole
  `futures` facade for a type alias is the kind of dev-dep bloat `cargo deny` review will ask about.
- **`object_store::Error::Generic { store, source }`** takes `store: &'static str` and a
  `Box<dyn Error + Send + Sync>`; `"injected failure".into()` satisfies the second.
- **The Parquet fixture is not optional.** `SealedBatch.record_batch` must come from a real
  `BatchBuilder::new(&orders())` + `append_row(...)` + `finish()`, or `AsyncArrowWriter` has nothing
  meaningful to encode. Port `orders()` / `meta()` / `sealed()` from
  `crates/pg-sink/tests/parquet_put.rs:33-95` rather than hand-building a `RecordBatch`.
- **These are `#[tokio::test]`s.** `put`/`delete`/`head` are all `async`. The default flavor is
  `current_thread` (see PR 28.7) and that is fine here — no timer is involved.
- **Unit tests are sibling files.** `sink_test.rs` and the new `bootstrap_test.rs` are wired with
  `#[cfg(test)] #[path = "..."] mod tests;`; never write an inline `mod tests {}` (PR 28.1 guards
  it). `bootstrap.rs` has no such declaration today — you are adding the 48th.
- **`.unwrap()` is legal in these files** (`clippy.toml` sets `allow-unwrap-in-tests`), but
  `unwrap`/`expect` remain denied in production — do not "simplify" `verify_s3_read` or
  `put_with_kind` while you are in there.
- **`clippy::all` + `warnings` are already `deny`.** An unused import from the wide `object_store::`
  use list will fail CI outright. Import exactly the types the stub's signatures name.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it.
