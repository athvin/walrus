# PR 28.15 — Record why loom does not apply, with a tripwire if that changes

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 28 — Rust testing · **Crates touched:** none (script + docs only) ·
> **Est. size:** S · **Depends on:** PR 28.14 · **Unlocks:** PR 29.1

loom model-checks **hand-rolled lock-free algorithms** — it replaces `std::sync::atomic`,
`std::sync::Mutex`, `std::thread` and `std::cell` with instrumented equivalents and enumerates the C11
interleavings. walrus has none of that: **0** `compare_exchange`, **0** `fetch_update`, **0**
`AtomicPtr`, **0** `UnsafeCell`, **0** `unsafe` tokens, **0** `std::thread::spawn` and **0**
`spawn_blocking` across all 189 Rust files. All 18 `Atomic*` sites are independent flags and one
counter — `LoaderState::{ready, quarantined}` (`crates/loader/src/health.rs:22,26`),
`HealthState::{phase, terminating, degraded, live}` (`crates/pg-sink/src/health.rs:36-39`),
`crosscheck_violations` (`reload_signal.rs:48`, `Relaxed`) and the `Arc<AtomicI64>` reload-id handoff
(`reload.rs:162`) — with **no data published through a second location**, so there is no
Acquire/Release protocol to verify. The real concurrency is tokio tasks, `CancellationToken` (28
sites), `parking_lot::Mutex` (5) and Postgres transactions, none of which loom models. This PR writes
that down as an ADR and installs a tripwire that fails the build the day the premise stops holding.

## Why — learning objectives

- **What loom actually proves** — exhaustive C11 interleavings for lock-free code under
  `loom::model(|| …)`, why the closure must stay tiny (combinatorial explosion), and why an async,
  I/O-bound pipeline built on tokio + a database sits entirely outside that model.
- **Tripwire guards over comments** — a decision recorded in prose rots silently; a decision recorded
  as a failing check tells the person who invalidates it, at the moment they do, and points them at
  the document that explains what to do next.

## Read first

- [`test-loom-concurrency`](../../../.claude/skills/rust-skills/rules/test-loom-concurrency.md) — read
  the "Good" example and the Key Points list. The load-bearing sentence is *"loom replaces
  `std::sync::atomic`, `std::sync::Mutex`, `std::thread`, and `std::cell` with instrumented
  equivalents"* — that list is precisely the set of things walrus does not build on.
- `crates/loader/src/health.rs:12-60` — `LoaderState`: two `AtomicBool` latches (`ready`,
  `quarantined`) read/written with `SeqCst`, plus a `parking_lot::Mutex<Option<Instant>>`. Nothing is
  published *through* the flags; each is its own answer.
- `crates/pg-sink/src/health.rs:18-52` — `HealthState`: `AtomicU8` phase + three `AtomicBool`s, same
  shape, with the doc comment explaining *why* atomics (a lock-free probe path), not *what* protocol.
- `crates/pg-sink/src/reload_signal.rs:48,66-70` — the tree's only `fetch_add`, a `Relaxed` violation
  counter feeding a metric. A counter with no companion load is the textbook legitimate `Relaxed`.
- `crates/pg-sink/src/reload.rs:162,191,468` — the `Arc<AtomicI64> current_reload_id` handoff between
  the exporter body and the lease-renewal closure: `store(SeqCst)` before the next await,
  `load(SeqCst)` in the renewal tick. Single value, no companion data — still not a publication
  protocol.
- `docs/implementation/phase-12-rust-unsafe/pr-12.1-unsafe-safety-comment.md` — the PR that adds
  `unsafe_code = "forbid"` to `[workspace.lints.rust]`. It lands *before* this one and already covers
  the `unsafe` / `UnsafeCell` half; this ticket must not duplicate it.
- `scripts/test-hygiene.sh` as it exists after PRs 28.1-28.3 — the script this PR extends, and the CI
  `gates` step that runs it.
- `docs/implementation/notes/duckdb-lts-bump.md` — the house ADR format: a `# Title (PR n.m)` heading,
  a `> **Status:**` blockquote verdict, "what was expected" vs "what is actually true", evidence, and
  the condition that would reopen it.

## Scope

**In scope**

- Extend `scripts/test-hygiene.sh` (from PR 28.1) with a **lock-free tripwire**: any occurrence of
  `compare_exchange`, `compare_and_swap`, `fetch_update` or `AtomicPtr` under `crates/*/src` fails the
  script with a message naming `docs/implementation/notes/loom-not-applicable.md`.
- Write that ADR: what loom is for, the measured evidence that walrus has no lock-free code, what the
  tree actually uses for concurrency, and the **explicit reversal condition**.
- Confirm the tripwire fires: inject one `compare_exchange` locally, watch the script exit 1, remove
  it.

**Explicitly deferred** (do *not* build these here)

- No `loom` dev-dependency and no `#[cfg(loom)]` shims. There is nothing to model; adding the cfg
  scaffolding "for later" would be dead code that never compiles under CI.
- No change to any `Ordering::SeqCst` choice. Whether those flags could relax to `Acquire`/`Release`
  is `conc-atomic-ordering`'s question in Phase 15 — and answering it here would *create* the
  publication protocol this ticket documents the absence of.
- No `RUSTFLAGS="--cfg loom"` CI job, no new workflow step (the `gates` job already runs
  `scripts/test-hygiene.sh` as of PR 28.1 — verify that step exists; only add it if it does not).

**Conflict — resolved here, do not apply the rule blindly.** CONTEXT §4 groups loom with the
zero-`unsafe` family, so the archetype is **D**: a documented, evidence-backed decline, not an
adoption. There is also an **overlap to avoid**: PR 12.1 (`unsafe-safety-comment`) adds
`unsafe_code = "forbid"` to `[workspace.lints.rust]`, which already makes `unsafe` and any real use of
`UnsafeCell` a compile error. This ticket therefore keeps its regex to the **atomic primitives only**
(`compare_exchange` / `compare_and_swap` / `fetch_update` / `AtomicPtr`) and *cross-references* PR 12.1
for the `unsafe`/`UnsafeCell` half rather than re-checking it. Both halves still fail the CI `gates`
job — one via the compiler, one via the script — which is what the probe requires.

## Skeleton

```bash
# scripts/test-hygiene.sh — a new check appended alongside the sibling-test / use-super / test-name
# checks from PRs 28.1-28.3. Reuse the script's existing failure helper and counter verbatim (the
# names below are illustrative — match the script as it actually exists).

# --- Check 4: lock-free tripwire (PR 28.15) -----------------------------------------------------
# walrus builds no hand-rolled lock-free structure: every Atomic* site is an independent flag or
# counter, so there is no Acquire/Release publication protocol and nothing for `loom` to model.
# The day that stops being true, this fails and sends the author to the ADR.
# `unsafe` / `UnsafeCell` are NOT re-checked here — `[workspace.lints.rust] unsafe_code = "forbid"`
# (PR 12.1) already makes them a compile error.
check_no_lockfree_primitives() {
    local hits
    hits=$(grep -rnE --include='*.rs' \
        'compare_exchange|compare_and_swap|fetch_update|AtomicPtr' crates/*/src || true)
    if [ -n "$hits" ]; then
        printf '%s\n' "$hits"
        fail "lock-free primitive introduced — walrus has none today. Read \
docs/implementation/notes/loom-not-applicable.md: if this really is a hand-rolled lock-free \
structure or an Acquire/Release publication protocol, the loom decision is REVERSED and that \
document must be updated in the same PR."
    else
        ok "no lock-free primitives (compare_exchange / compare_and_swap / fetch_update / AtomicPtr)"
    fi
}

check_no_lockfree_primitives
```

```markdown
# loom evaluation — not applicable (PR 28.15)

> **Status:** evaluated — declined, with a tripwire. walrus has no hand-rolled lock-free code for
> loom to model. `scripts/test-hygiene.sh` fails if that changes.

## What loom is for
… `loom::model(|| …)` enumerates C11 interleavings for lock-free algorithms; it substitutes
`std::sync::atomic`, `std::sync::Mutex`, `std::thread`, `std::cell`. Quote the rule's Key Points.

## What walrus actually has          <!-- the measured evidence, with file:line anchors -->
| primitive | count | where |
|---|---|---|
| `compare_exchange` / `compare_and_swap` / `fetch_update` / `AtomicPtr` | 0 | — |
| `unsafe` / `UnsafeCell` | 0 | forbidden workspace-wide (PR 12.1) |
| `std::thread::spawn` / `spawn_blocking` | 0 | — |
| `Atomic*` flags & counters | 18 | health.rs ×2 + ×4, reload_signal.rs:48, reload.rs:162 |
| `CancellationToken` | 28 | shutdown/cancellation across sink + loader |
| `parking_lot::Mutex` | 5 | health state, reload waiters |

… then: each atomic answers one question and publishes no companion data, so there is no
Acquire/Release pair to verify; the real coordination is tokio task scheduling, cancellation tokens,
a non-poisoning mutex, and Postgres transactions — none of which loom instruments.

## Why not adopt it anyway
… a `loom` dev-dep plus `#[cfg(loom)]` shims on code with nothing to prove is dead scaffolding that
CI never compiles; it would also have to be kept in sync with every atomic touched.

## Reversal condition                <!-- the whole point of the document -->
Adopt loom the moment either is true:
1. walrus hand-rolls a lock-free structure (a queue, a slot map, a refcount, an intrusive list); or
2. an atomic starts **publishing** data written elsewhere — i.e. a `Release` store paired with an
   `Acquire` load whose correctness depends on the ordering, rather than an independent flag.
The tripwire in `scripts/test-hygiene.sh` fires on the primitives that make (1) or (2) possible.

## See also
`conc-atomic-ordering` (Phase 15) owns the separate question of whether today's `SeqCst` flags could
relax; PR 12.1 owns the `unsafe` half.
```

## Hints & gotchas

- **Do not widen the regex.** `Atomic` alone matches all 18 legitimate sites and would fail on a clean
  tree; `fetch_` alone matches the legal `fetch_add` counter at `reload_signal.rs:69`. The four
  listed tokens are the ones that only appear in hand-rolled lock-free code. Test the pattern against
  the current tree *before* wiring it in — a tripwire that is red on main is worse than no tripwire.
- **`grep` exits 1 on no match**, which under `set -e` (or a pipeline) kills the script on the *good*
  path. Terminate with `|| true` and branch on whether the captured output is empty, exactly as the
  skeleton does.
- **This is an ADR, not an essay.** The reversal condition is the only part a future reader must act
  on; put it under its own heading and make it testable ("a Release store paired with an Acquire load
  whose correctness depends on the ordering"), never "if concurrency gets complicated".
- **Do not add `loom` to `Cargo.toml` "so it is ready".** Every new dependency must clear
  `cargo deny` (advisories, 8-license allow-list, bans), and a dep nothing imports is pure cost. The
  ADR's job is to make adding it later a five-minute decision, not to pre-pay for it.
- The `#[cfg(loom)]` pattern in the rule file requires the production type to *import* from `loom::`
  under the cfg. That is an intrusive change to `health.rs` for code with no invariant to check —
  which is exactly the trade this ADR declines.
- `unwrap`/`expect` are denied in production and `clippy::all` + `warnings` are already `deny`
  workspace-wide; this PR adds no Rust, so nothing here interacts with them. Unit tests in walrus are
  sibling `foo_test.rs` files, never inline `mod tests {}` — the script you are editing is what
  enforces that.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache — there is no Docker on this
  machine to regenerate it.
