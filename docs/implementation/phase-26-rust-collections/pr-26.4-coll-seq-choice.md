# PR 26.4 — Drain pending reload signals in one pass and deny LinkedList workspace-wide

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-sink

> **Phase:** 26 — Rust collections · **Crates touched:** `pg-sink` · **Est. size:** S ·
> **Depends on:** PR 26.3 · **Unlocks:** PR 27.1

At baseline `72daa7e`, `PendingSignals` already drains in linear time and preserves order.
PR 11.7 implementation commit `af31538` introduced
`std::mem::take(v).into_iter().partition(...)` (`reload_signal.rs:295-300`). That predecessor owns
the current algorithm and its complexity/order guarantees; this task must not claim or recreate it.

One residual sequence-choice refinement remains. `mem::take` transfers the pending buffer's backing
allocation into `IntoIter`; `partition` then builds fresh `out` and `keep` vectors (allocating for
each non-empty half), the old allocation is freed, and `keep` is assigned back to the long-lived
buffer. The helper therefore
throws away `PendingSignals.pending`'s reusable capacity on every drain. Rust 1.95's
`v.extract_if(.., |t| pred(t)).collect()` performs the same front-to-back predicate drain while
retaining `v`'s allocation and capacity; only the returned drained vector may allocate.
It also leaves `v` valid if the predicate panics, whereas the current take-first implementation
leaves `v` empty while its moved elements unwind and drop. Separately, the workspace has no
`linkedlist` lint entry. Adding `linkedlist = "deny"` closes Phase 26 with a durable guard against
the sequence type the rule says to avoid.

## Why — learning objectives

- **Refine an already-correct algorithm without stealing predecessor credit** — PR 11.7 made the
  drain linear and order-preserving. PR 26.4 keeps those properties and removes survivor-buffer
  reallocation; it is not another complexity fix.
- **`Vec::extract_if` as an allocation-preserving partition** — it removes and yields matches in
  one front-to-back traversal while compacting retained elements inside the original allocation.
  `retain` cannot return the removed signals, and `partition` cannot reuse the borrowed vector.
- **Panic behaviour is part of a reusable helper's contract** — on predicate panic, matches yielded
  before the panic have been removed, earlier non-matches stay, and the panicking element plus the
  unvisited tail remain in their original order. The vector stays valid with its capacity intact.
- **`Vec` is still the right container** — the buffer is drained by three different predicates,
  never as a FIFO. A deque would not improve scattered predicate removal.
- **A lint makes a container decision durable** — `clippy::linkedlist` is pedantic and outside
  `clippy::all`, so one named workspace deny adds regression protection without changing the group
  priority.
- **The reload echo handshake** — a decoded `walrus.reload_signal` insert remains buffered until
  `Commit`, `Stream Commit`, or `Stream Abort` supplies its fate. That is why order and precise
  predicate membership are load-bearing.

```rust
// crates/pg-sink/src/reload_signal.rs:295-300

/// Drain every element matching `pred` out of `v`, preserving both halves' relative order and
/// retaining `v`'s allocation for the next reload-signal transaction.
///
/// PR 11.7 made this linear with `mem::take` + `partition`; `extract_if` keeps that complexity and
/// ordering while avoiding a fresh survivor buffer. `Vec` remains correct because callers drain by
/// predicate, never from the front of a queue.
fn extract<T>(v: &mut Vec<T>, mut pred: impl FnMut(&T) -> bool) -> Vec<T> {
    v.extract_if(.., |t| pred(t)).collect()
}
```

```rust
// crates/pg-sink/src/reload_signal_test.rs — sibling module can call private `extract`.

#[test]
fn extract_preserves_capacity_and_both_relative_orders() {
    let mut values = Vec::with_capacity(64);
    values.extend([1, 2, 3, 4, 5, 6]);
    let capacity = values.capacity();

    let drained = extract(&mut values, |value| value % 2 == 0);

    assert_eq!(drained, [2, 4, 6]);
    assert_eq!(values, [1, 3, 5]);
    assert_eq!(values.capacity(), capacity);
}

#[test]
fn extract_all_matches_leaves_reusable_capacity() {
    let mut values = Vec::with_capacity(64);
    values.extend([1, 2, 3]);
    let capacity = values.capacity();

    assert_eq!(extract(&mut values, |_| true), [1, 2, 3]);
    assert!(values.is_empty());
    assert_eq!(values.capacity(), capacity);
}

#[test]
fn extract_predicate_panic_keeps_capacity_and_unvisited_tail() {
    let mut values = Vec::with_capacity(64);
    values.extend([1, 2, 3, 4, 5, 6]);
    let capacity = values.capacity();

    let result = std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| {
        let _drained = extract(&mut values, |value| {
            assert_ne!(*value, 4, "predicate panic seam");
            value % 2 == 0
        });
    }));

    assert!(result.is_err());
    assert_eq!(values, [1, 3, 4, 5, 6]);
    assert_eq!(values.capacity(), capacity);
}
```

## Hints & gotchas

- Rust 1.95's signature is
  `Vec::extract_if<F, R>(&mut self, range: R, filter: F)` with
  `F: FnMut(&mut T) -> bool` and `R: RangeBounds<usize>`; it has been stable since 1.87. The full
  range is `..`, so the call is `extract_if(.., filter)`, not `extract_if(filter)`.
- Preserve the helper's `FnMut(&T)` signature from PR 11.7. The adapter `|t| pred(t)` reborrows the
  method's `&mut T` as `&T`; passing `pred` directly would require a different closure bound and
  unnecessarily permit mutation.
- `ExtractIf` is lazy. `.collect()` is load-bearing because it drives the full range and builds the
  drained result. Dropping an unconsumed iterator would leave unvisited elements untouched.
- `extract_if` compacts survivors in the original allocation and never changes the vector's
  capacity. The returned `Vec<T>` still allocates as needed; the win is removal of the fresh
  survivor allocation and preservation of the long-lived pending buffer.
- On predicate panic, `ExtractIf::drop` closes holes and restores a valid length. The element whose
  predicate panicked was not yielded, so it and the unvisited tail remain; the partial `collect`
  output is dropped during unwind. Keep the caught-panic test exact.
- The capacity tests deliberately start with capacity 64 and only a few elements. The old
  `partition` survivor cannot accidentally satisfy that capacity assertion through ordinary growth.
- `clippy::linkedlist` is pedantic, not part of `clippy::all`. The current `all` entry already uses
  `{ level = "deny", priority = -1 }`; add a plain named deny and do not rewrite the table.
- Test code may use `unwrap`/`expect` under the repository's existing test carve-out. Do not add a
  production allow or change `clippy.toml`.
- Tests remain in the sibling `reload_signal_test.rs`, not an inline module. No SQL changes or
  offline-cache regeneration are involved.
