# PR 26.4 — Drain pending reload signals in one pass and deny LinkedList workspace-wide

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 26 — Rust collections · **Crates touched:** `pg-sink` · **Est. size:** S ·
> **Depends on:** PR 26.3 · **Unlocks:** PR 27.1

`PendingSignals` buffers reload echo candidates in `pending: Vec<PendingSignal>`
(`reload_signal.rs:152`) and drains them through a hand-rolled helper whose body is this rule's Bad
example verbatim: `while i < v.len() { if pred(&v[i]) { out.push(v.remove(i)) } else { i += 1 } }`
(`reload_signal.rs:222-233`). `Vec::remove` shifts every later element, so a drain that matches *m*
of *n* buffered signals is O(n·m) — and it is the **only** `.remove(i)` in the whole production tree
(measured: **1**). One `extract_if(.., pred).collect()` makes it a single O(n) pass that still
preserves order and still yields the removed elements. Separately, `VecDeque`, `LinkedList` and
`extract_if` each appear **0** times anywhere and `clippy::linkedlist` is absent from `Cargo.toml`,
so the container-choice invariant PRs 26.1–26.3 established has no permanent gate. This is the
phase-closing ticket: it fixes the last sequence-shaped defect and adds the lint that keeps it fixed.

## Why — learning objectives

- **`extract_if` vs `retain` vs a `remove(i)` loop** — `retain` keeps elements but *discards* the
  removed ones; `remove(i)` in a loop yields them but is quadratic; `Vec::extract_if` is the one that
  does both in a single O(n) pass, preserving relative order in the drained output and the remainder.
- **`Vec` is still the right container here** — the rule's headline fix for a `remove` loop is
  `VecDeque`, and it is the wrong answer for this call site. Being able to say *why* a rule's Good
  example does not apply, and fix the actual defect instead, is the point of the ticket.
- **A lint is how a design decision survives** — `clippy::linkedlist` costs zero fixes today, so
  adding it is pure regression protection for the container reasoning this phase spent four PRs on.
- **The reload echo handshake** — a decoded `walrus.reload_signal` insert is buffered from its
  `Insert` message until its transaction's `Commit` / `Stream Abort` decides whether its **commit
  LSN** becomes the chunk's low watermark `L_i`. That is why the buffer is drained *by predicate*.

## Scope

**In scope**

- Rewrite `extract` (`reload_signal.rs:222-233`) as a single `v.extract_if(.., pred).collect()` pass.
  Changing its bound from `impl FnMut(&T) -> bool` to `impl FnMut(&mut T) -> bool` is the cleanest
  way to match `extract_if`'s signature; all three call sites pass closures whose parameter type is
  inferred, so they do not change.
- Add a short comment above `extract` recording that `VecDeque` was evaluated and declined, and why
  (see the conflict below) — so the next reader with this rule in hand does not "fix" it.
- Add `linkedlist = "deny"` under `[workspace.lints.clippy]` in the root `Cargo.toml`, with a comment
  in the house style (what it buys, why no `priority` is needed) referencing this phase.
- New `reload_signal_test.rs` cases for `extract`'s semantics through the public API: order is
  preserved among both drained and retained signals; only matching signals are removed; a buffer of
  a few thousand signals drains correctly in one call; and `is_empty()` is true afterwards when the
  predicate matched everything.
- Keep the three drain call sites' **predicates and behaviour** byte-for-byte equivalent —
  `on_commit`, `on_stream_commit` and `on_stream_abort` must resolve/drop exactly the same signals as
  they do today, in the same order.

**Explicitly deferred** (do *not* build these here)

- **Add no `VecDeque` anywhere.** There is no FIFO or sliding-window site in the tree
  (`grep -rn --include='*.rs' 'VecDeque' crates tests` ⇒ 0 today and after), and inventing one to
  satisfy the rule's Good example would be a regression.
- **Promote only `clippy::linkedlist`.** Leave every other pedantic collection lint
  (`clippy::implicit_clone`, `clippy::iter_without_into_iter`, …) alone — CONTEXT's clippy evidence
  counts 51 pedantic/nursery lints across 1192 sites, and lint promotion is Phase 33's job.
- **Do not convert `BatchAccumulator.pending`** (`batch.rs:64`). It is sealed wholesale at commit, not
  drained by predicate, so `Vec` is already the right answer under this rule.
- Do not touch `memory.rs` or `stream_txn.rs` — PRs 26.2 and 26.3 own those, and this ticket lands
  after they have settled.
- No `.sql` file and no `.sqlx` offline-cache changes.

**Conflict — resolve explicitly, do NOT apply the rule blindly.** The rule's Good answer for a
`Vec`-remove loop is `VecDeque`, and it does not fit. `PendingSignals` drains **by predicate**, not
from the front: `on_commit` takes every signal with `xid.is_none()`, `on_stream_commit` every signal
with `xid.is_some()`, and `on_stream_abort` those matching a sub-xid — `reload_signal.rs:163`, `:179`,
`:202`. Matching elements are scattered through the buffer, so `pop_front` answers the wrong
question and a ring buffer buys exactly nothing; worse, `VecDeque`'s two-segment layout makes a
predicate drain *harder*, not easier. **Required resolution:** keep `Vec`, fix the algorithm with
`extract_if`, and record the `VecDeque` evaluation-and-decline in a comment at the call site. A PR
that swaps the container instead of fixing the drain fails this ticket.

## Hints & gotchas

- **`Vec::extract_if` takes a range as its first argument**, unlike the `HashMap`/`HashSet` versions:
  `v.extract_if(.., pred)`, not `v.extract_if(pred)`. Forgetting `..` is the single most likely
  compile error in this PR.
- **`ExtractIf` is lazy and `#[must_use]`.** Elements are removed only as the iterator advances — if
  you drop it half-consumed, the unvisited tail stays in the `Vec`. `.collect()` drives it to
  completion, which is exactly the semantics the three callers rely on. Never write
  `let _ = v.extract_if(..)`.
- **The closure takes `&mut T`, not `&T`.** Changing `extract`'s bound to
  `impl FnMut(&mut T) -> bool` is cleaner than wrapping (`|x| pred(x)` compiles via reborrow, but
  clippy will look at it twice and it buys nothing). All three call sites infer the parameter type,
  so they stay as they are.
- **MSRV: `Vec::extract_if` stabilised in Rust 1.87.** `rust-toolchain.toml` pins `1.95.0` and
  `Cargo.toml:8` declares `rust-version = "1.95"`, so this is safe — but the CI `msrv` job is what
  proves it; do not lower either pin.
- **`clippy::linkedlist` is `pedantic`, so it is not in `all`** — exactly like `unwrap_used` /
  `expect_used` two lines above it. That is why no `priority = -1` is needed on `all`. If you ever add
  a lint that *is* in `all`, you would need the priority dance; say so in the comment so the next
  person does not cargo-cult it.
- **`[workspace.lints]` only applies where the member opts in.** All six member crates already
  declare `[lints] workspace = true` (CONTEXT §2), so the new lint reaches the whole tree with no
  per-crate edit — verify rather than assume, and do not add `#![deny(clippy::linkedlist)]` anywhere.
- **Order preservation is the behavioural contract, not a nicety.** `extract_if` visits front-to-back
  and preserves relative order in both the yielded elements and the remainder — same as the old loop.
  The interleaved test case exists so a future "optimisation" (e.g. `swap_remove`) cannot slip past.
- **`PendingSignal` is `Copy`**, so nothing here needs a `clone` and the drained `Vec<PendingSignal>`
  is cheap. Do not add `.cloned()`.
- **`unwrap`/`expect` are `deny` in production**; the sibling test file may use `.unwrap()` freely
  (`clippy.toml` re-allows it under `#[cfg(test)]`), which the existing fixtures already do.
- **`clippy::all` + `warnings` are `deny` workspace-wide.** Removing the `mut` from `pred` (it is no
  longer needed once the closure is passed straight through) will otherwise fail the build on
  `unused_mut`.
- **Tests are a sibling file** (`#[cfg(test)] #[path = "reload_signal_test.rs"] mod tests;`) — add
  the new cases there, not in an inline `mod tests {}`.
- **No `.sqlx` regeneration is possible locally** (no Docker), and none is needed: this PR touches no
  SQL. Adding a dependency would need to clear `cargo deny`; this PR adds none.
