# PR 24.3 — Type the `string_enum!` arms with `:meta`/`:vis`/`:literal` and gate `:tt` slurping

> **Gates:** fmt,clippy,test · **Test packages:** common,control

> **Phase:** 24 — Rust macros · **Crates touched:** `common`, `control` · **Est. size:** M ·
> **Depends on:** PR 24.2 · **Unlocks:** PR 24.4

walrus captures precisely today — `grep -rn ':tt' crates tests` returns **0**, and every arm in the
tree names a real syntactic category (`$b:ty, $t:ty` in `num_builder!` at `batch.rs:751`, and PR
24.2's `$name:ident` / `$variant:ident` / `$text:literal`). That is conformance by luck, not by
construction: nothing in CI stops the next contributor from writing `($($tt:tt)*)` and re-parsing by
hand. This PR installs the gate — a `gates`-job step that fails on any unmarked `:tt` capture — and
spends the gate on real work at the same time. `reload.rs`'s two enums are the tree's remaining
hand-written string-enum pairs (`as_str` + `FromStr` at `:35/:43` and `:69/:80`, 7 variants, 14
literals), and they cannot adopt `string_enum!` until its arm can carry
`#[derive(Debug, Clone, Copy, PartialEq, Eq, sqlx::Type)]` and `#[sqlx(rename_all = …)]`
(`:26-27`, `:57-58`) through the expansion. Widening the matcher to `$(#[$attr:meta])* $vis:vis enum
$name:ident { $variant:ident => $text:literal }` does exactly that — and does it without `common`
gaining a single new dependency.

## Why — learning objectives

- **Fragment specifiers and follow-set restrictions** — `:meta`, `:vis`, `:literal`, `:ident`, and
  why `$(,)?` is the right way to accept a trailing comma instead of duplicating the arm. `:vis` is
  the specifier that can legally match *nothing*, so one arm covers `pub`, `pub(crate)` and private.
- **Attributes pass through as caller tokens** — `$(#[$attr:meta])*` re-emits the caller's tokens,
  which resolve in the *caller's* namespace. That is why `control` can hand `sqlx::Type` to a macro
  defined in `common` even though `common` does not enable sqlx's `macros` feature.
- **Keeping a DB text contract honest through codegen** — `#[sqlx(rename_all = "snake_case")]` and
  the `=> "export_complete"` literal are two independent spellings of the same string; the
  `table_reload` CHECK constraint is the third. All three must keep agreeing.

## Skeleton

```rust
// crates/common/src/string_enum.rs — the widened matcher.

#[macro_export]
macro_rules! string_enum {
    (
        // `:meta` captures a whole attribute body, so `#[derive(..)]`, `#[sqlx(rename_all = "..")]`
        // and desugared `///` doc comments all match — and are re-emitted as the CALLER's tokens,
        // resolving in the caller's namespace (this is what lets `control` pass `sqlx::Type`).
        $(#[$attr:meta])*
        // `:vis` is the one specifier that legally matches nothing, so `pub`, `pub(crate)` and a
        // private enum all take this single arm.
        $vis:vis enum $name:ident {
            // `:literal` (not `:expr`) — the persisted strings must be literals, so `1 + 1` or
            // `stringify!(x)` is rejected at the call site instead of expanding into a match arm.
            // `$(,)?` accepts an optional trailing comma without a second arm.
            $($variant:ident => $text:literal),* $(,)?
        }
    ) => {
        $(#[$attr])*
        $vis enum $name {
            $($variant,)*
        }

        impl $name {
            /// The exact string persisted in the control DB.
            $vis fn as_str(self) -> &'static str {
                match self {
                    $($name::$variant => $text,)*
                }
            }
        }

        impl ::std::str::FromStr for $name {
            type Err = ::std::string::String;

            fn from_str(s: &str) -> ::std::result::Result<Self, Self::Err> {
                match s {
                    $($text => Ok($name::$variant),)*
                    other => Err(todo!("uniform message — PR 24.4 routes this through $crate::")),
                }
            }
        }
    };
}
```

## Hints & gotchas

- **`sqlx::Type` resolves at the call site, not the definition site.** `$(#[$attr:meta])*` re-emits
  the caller's tokens verbatim, so the path `sqlx::Type` is looked up in `control` — which enables
  sqlx's `macros` feature (`crates/control/Cargo.toml`). `common`'s optional `sqlx` dependency has
  only `runtime-tokio` + `postgres` and must stay that way; this ticket adds **no** feature to
  `common`.
- **`rename_all` and the `=>` literal are independent spellings.** `#[sqlx(rename_all = "snake_case")]`
  derives `"export_complete"` from the variant name; the macro's `=> "export_complete"` is typed by
  hand; the CHECK constraint is a third copy in SQL. The unit tests cover `as_str`/`FromStr`; the
  *sqlx decode* direction is only exercised by the compose-gated integration tests
  (`cargo test -p control --features integration`, and the loader's `reload_*` suites). If you change
  a variant name, all three move together.
- **Column overrides bypass sqlx's type check.** `flavor AS "flavor: ReloadFlavor"` tells sqlx to
  trust you and call `Decode` directly, which is why a `text` column decodes into a derived unit
  enum at all. It also means a mismatch here fails at *runtime*, in an integration test, not at
  compile time — treat the seven strings as load-bearing.
- **Follow-set restrictions bit nobody here, and that is by design.** `:literal` and `:ident` have no
  follow-set restriction, so `=>` and `,` are legal after them. Had you reached for `$text:expr`,
  the `,` separator would still be legal — but `string_enum! { … A => 1 + 1 }` would then compile
  into a nonsense match arm. That is the whole reason to prefer `:literal`.
- **`$vis` on an inherent method.** `$vis fn as_str(self)` expands to `pub fn` for a `pub enum` and
  to a bare `fn` when `$vis` matched nothing — no extra arm needed, and no `unreachable_pub`
  surprise on a private enum.
- **The order of `$(#[$attr:meta])*` and `$vis:vis` is fixed.** Attributes come before visibility in
  real Rust items, so the matcher must list them in that order; a caller writing
  `pub #[derive(Debug)] enum …` is invalid Rust and will (correctly) not match.
- **Update PR 24.2's invocations in the same commit.** Widening the arm removes the hard-coded
  derive, so `manifest.rs` must regain `#[derive(Debug, Clone, Copy, PartialEq, Eq)]` and `pub enum`
  or `control` will not compile.
- **The guard is line-based.** `tt-fallback-ok` must sit on the *same physical line* as the `:tt`
  capture. In PR 24.6 that means a trailing `// tt-fallback-ok` after the arm's opening brace.
- `.github/**` is in the ci `changes` filter (`ci.yml:51`), so this workflow-only edit still triggers
  the compile-heavy `gates` job — you will get a real signal on the PR.
- Tests are Go-style sibling files; `unwrap`/`expect` are denied in production and re-allowed in
  tests by `clippy.toml`; `clippy::all` and `warnings` are already `deny`. Any new dependency would
  have to clear `cargo deny` — none is added here. Do not touch any `.sql` file or the committed
  `.sqlx` offline cache; there is no Docker on this machine to regenerate it.
