# PR 24.3 — Type the `string_enum!` arms with `:meta`/`:vis`/`:literal` and gate `:tt` slurping

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common,control

> **Phase:** 24 — Rust macros · **Crates touched:** `common`, `control` · **Est. size:** M ·
> **Depends on:** PR 24.2 · **Unlocks:** PR 24.4

PR 24.2 has landed the exported `string_enum!` with a deliberately typed rejection contract:
besides `$name:ident` / `$variant:ident` / `$text:literal`, its arm captures `$error:path` and
`$column:literal`, generates `type Err = $error`, and constructs the error from the exact column
and rejected input. The two manifest invocations therefore still return `ParseEnumError`, and all
eight `manifest_test.rs` field assertions remain data-level acceptance. This PR widens that arm;
it must preserve those captures rather than reverting the generated `FromStr` to `String`.

The remaining work is real. `reload.rs` still hand-writes two string-enum pairs (`as_str` +
`FromStr`, 7 variants and 14 mapping literals) because `string_enum!` cannot yet carry
`#[derive(..., sqlx::Type)]`, `#[sqlx(rename_all = ...)]`, or a caller-selected visibility.
`$(#[$attr:meta])* $vis:vis enum $name:ident` unlocks that conversion while leaving the typed
`error = ParseEnumError; column = ...;` input inside each invocation. The repository also has no
enforcement against a future raw token-tree capture. A naive text count is no longer truthful:
`rg -n ':tt' crates tests --glob '*.rs'` returns **1**, solely because PR 24.1's deferred
`num_builder!` comment says its arms are “never `:tt`”; there are **0 actual `$name:tt` captures**.
This PR adds a capture-aware, comment-ignoring checker with a fixture self-test, then wires it into
the `gates` job.

The first exact gate at implementation commit `8a68736` found one test-fixture-only consequence:
Clippy's `wrong_self_convention` rejects generated `as_str(self)` for private `Bare` because its
deliberately attribute-free invocation does not derive `Copy`. The macro API and empty-attributes
proof are both binding. The narrow continuation therefore makes only `Bare` manually `Copy` and
canonically `Clone`; it neither suppresses the lint nor rewrites the red test or generated method.

## Why — learning objectives

- **Fragment specifiers are an input contract** — `:meta`, `:vis`, `:path`, `:ident`, and
  `:literal` describe the syntax the macro accepts; a raw `:tt` capture postpones validation and
  degrades diagnostics. The existing typed `$error:path` / `$column:literal` captures are part of
  that same contract and stay intact.
- **Follow-set restrictions and trailing commas** — after `:expr`, `:ty`, `:pat`, and a few other
  fragments only a limited token set may follow. `$(,)?` accepts one trailing comma without a
  duplicate arm, while `:literal` rejects `1 + 1` and `stringify!(x)` at the call site.
- **Attributes pass through as caller tokens** — `$(#[$attr:meta])*` re-emits the caller's tokens,
  which resolve in the caller's namespace. Thus `control` can hand `sqlx::Type` to a macro defined
  in `common` without enabling sqlx's derive feature in `common`.
- **Guards must recognize syntax, not prose** — a repository invariant about metavariable
  captures cannot count comments or string contents. Its negative control belongs in an isolated
  self-test, not in a tracked Rust file that is later reverted.
- **DB text and error contracts survive code generation** — the macro's variant literals,
  sqlx's `rename_all`, the `table_reload` CHECK constraints, and `ParseEnumError { column, input }`
  are independent pieces that must keep agreeing.

```rust
// crates/common/src/string_enum.rs — widen the matcher without dropping the PR 24.2 error inputs.

#[macro_export]
macro_rules! string_enum {
    (
        // `:meta` captures complete attribute bodies, including desugared `///` docs and caller
        // derives. They are re-emitted as caller tokens, so `sqlx::Type` resolves in `control`.
        $(#[$attr:meta])*
        // `:vis` alone may match nothing; one arm covers `pub`, `pub(crate)`, and private enums.
        $vis:vis enum $name:ident {
            // `:path` preserves the caller's typed error; the column and persisted values are
            // `:literal` because expressions/macros are intentionally rejected at the call site.
            error = $error:path;
            column = $column:literal;
            // `:ident` matches enum variant names. `$(,)?` admits one trailing comma.
            $($variant:ident => $text:literal),* $(,)?
        }
    ) => {
        $(#[$attr])*
        $vis enum $name {
            $($variant,)*
        }

        impl $name {
            /// The exact string persisted in the control DB.
            #[must_use]
            $vis const fn as_str(self) -> &'static str {
                match self {
                    $($name::$variant => $text,)*
                }
            }
        }

        impl ::std::str::FromStr for $name {
            type Err = $error;

            fn from_str(s: &str) -> ::std::result::Result<Self, Self::Err> {
                match s {
                    $($text => Ok($name::$variant),)*
                    other => Err(<$error>::new($column, other)),
                }
            }
        }
    };
}
```

## Hints & gotchas

- **Do not copy the pre-24.2 skeleton.** `$error:path` and `$column:literal` are not incidental
  matcher syntax: PRs 18.5/20.2 made rejection column/input structured behavior, and PR 24.2 kept
  it through code generation. Every one of the four production invocations supplies both inputs.
- **`sqlx::Type` resolves at the call site.** `$(#[$attr:meta])*` re-emits caller tokens, so
  `sqlx::Type` is resolved in `control`, which enables sqlx's macro feature. Do not add that feature
  or any dependency to `common`.
- **`rename_all`, the variant literal, and the CHECK value are separate spellings.** A query column
  override tells sqlx to decode directly, so a disagreement may be a runtime integration failure.
  Keep all seven values and both query/SQL files byte-identical. Literal-count proofs must classify
  the two additional runtime diagnostics: `complete_export` reports expected `"exporting"`, while
  `complete` reports expected `"export_complete"`; neither belongs to the mapping boilerplate this
  macro removes.
- **A plain grep for `:tt` is the wrong invariant.** It already counts the deferred `batch.rs`
  ownership comment. Match `$metavariable : tt` in lexically active Rust code, retain line numbers,
  and leave that comment untouched.
- **Rust block comments nest.** The comment masker must track block depth. It must also avoid
  treating `//` or `/*` inside ordinary/raw string literals as comments; self-test those cases so a
  future checker edit cannot silently weaken the gate.
- **The exemption is narrow.** `tt-fallback-ok` must be on the same physical line as the capture.
  PR 24.6 can write its catch-all capture and marker together; a nearby blanket marker must not
  exempt a file, macro, or later line.
- **`$vis` on the inherent method preserves today's public API.** The three production enums are
  explicitly `pub`, so `as_str` remains `pub const fn`; the private test enum gets a private method.
- **`as_str(self)` and the empty attribute matcher are both intentional.** `wrong_self_convention`
  accepts this by-value `as_` receiver for `Copy` types. Do not change it to `&self`, add a derive
  attribute to `Bare`, or suppress the lint; make only the fieldless test enum manually `Copy`.
- **The manual impl shape is canonical and safe.** `impl Copy for Bare {}` is the required empty
  marker impl, and `Clone::clone` returning `*self` satisfies Clippy's all-group
  `non_canonical_clone_impl`. It performs no allocation, has no unsafe code or drop state, and the
  pinned toolchain leaves the separate pedantic `expl_impl_clone_on_copy` lint disabled. Keep the
  two impls test-local and immediately beside `Bare`.
- **Attributes precede visibility in Rust item syntax.** The matcher must list
  `$(#[$attr:meta])*` before `$vis:vis enum`. Doc comments arrive as `#[doc = ...]` and pass through
  the same repetition as derive/sqlx attributes.
- **The tests-first failure is at the old matcher.** Do not weaken or partially duplicate the arm
  to manufacture another failure. Commit `5f0d002` already records the complete intended call
  syntax and the old arm rejecting it. The additive manual impl follow-up leaves that historical
  proof and both test bodies unchanged.
- Tests stay in Go-style sibling files. Production denies unwrap/expect; test code permits them.
  The checker uses only Bash + Python standard library and needs no Cargo dependency.
- Do not touch SQL or `.sqlx`; the persisted/query text is unchanged and there is no regeneration
  work in this task.
