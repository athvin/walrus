# PR 24.4 — Route the `string_enum!` error path through a `$crate::` path

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common,control

> **Phase:** 24 — Rust macros · **Crates touched:** `common`, `control` · **Est. size:** S ·
> **Depends on:** PR 24.3 · **Unlocks:** PR 24.5

PRs 24.2 and 24.3 have landed one exported `string_enum!` in `common` and four production
invocations in `control`. Its generated rejection contract is deliberately typed: the invocation
captures `$error:path` and `$column:literal`, the expansion declares `type Err = $error`, and its
fallback constructs `<$error>::new($column, other)`. For all four production invocations that means
`ParseEnumError { column, input }`, which then reaches `ControlError::Decode(#[from]
ParseEnumError)`. Those fields and that typed payload are established behavior, not a seam for this
hygiene exercise.

The remaining hygiene gap is still real: `$crate` occurs zero times in Rust source. The macro is
defined in `common` but expands in `control`, so a future bare `crate::unknown_variant(..)` call
inside the expansion would resolve against `control` and fail with E0425 at the invocation. This PR
adds a small generic constructor adapter at `common`'s crate root and reaches it as
`$crate::unknown_variant(..)`. The helper forwards the exact captured column and rejected input to
the captured error constructor; it neither formats a `String` nor changes the invocation API,
`ParseEnumError`, or `ControlError`.

## Why — learning objectives

- **`$crate` vs `crate::`** — `$crate` names the crate that defined the macro even when expansion
  happens in another crate. A bare `crate::` item path is resolved in the caller after expansion.
- **Hygiene has separate boundaries** — the generated `other` binding is hygienic, the caller's
  `$error` / `$column` / `$name` tokens intentionally resolve at the invocation, and only the
  defining-crate helper path needs `$crate`.
- **Macro mechanics do not erase domain errors** — a generic defining-crate helper can exercise the
  correct path while returning the caller-selected error type with its exact structured context.

## Skeleton

```rust
// crates/common/src/string_enum.rs

/// Construct the caller-selected error for an unknown `string_enum!` value.
///
/// Generated code reaches this adapter through `$crate::unknown_variant`, so the item resolves in
/// `common` even when the macro expands in another crate. The adapter deliberately preserves the
/// caller's error taxonomy: it forwards the exact column and input to `make_error` and returns `E`.
#[must_use]
pub fn unknown_variant<E>(
    column: &'static str,
    input: &str,
    make_error: impl FnOnce(&'static str, &str) -> E,
) -> E {
    make_error(column, input)
}
```

```rust
// crates/common/src/string_enum.rs — only the fallback construction changes.

                    other => Err($crate::unknown_variant($column, other, <$error>::new)),
```

## Hints & gotchas

- **The constructor is a caller token.** `<$error>::new` resolves where the invocation lives; the
  generated call then passes that function item into a helper reached through the defining
  crate. Do not try to make `common` name `control::ParseEnumError`.
- **The helper is generic over the returned error.** The test uses private `TestParseError::new` and
  production uses public `ParseEnumError::new`; both satisfy the same `FnOnce(&'static str, &str)
  -> E` shape without a new trait or dependency.
- **Do not add an accepted-value list.** `ParseEnumError` deliberately stores the exact database
  column and rejected input. Adding accepted strings or replacing it with a formatted `String`
  changes the contract and belongs to no task in this seam.
- **Hygiene covers bindings, not item paths.** The macro-introduced `other` cannot capture a caller
  binding, but `crate::unknown_variant` would still point at `control`; that is why only the helper
  path uses `$crate`.
- **Do not hide the helper yet.** PR 24.5's baseline is the plain root re-export and its task is to
  move the same item behind `#[doc(hidden)] pub mod __private`.
- Tests are Go-style sibling files. `unwrap`/`expect` are test-only, Clippy and warnings are denied
  workspace-wide, and no dependency is required. Keep all SQL and `.sqlx` files byte-identical.
