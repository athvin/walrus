# PR 24.4 — Route the `string_enum!` error path through a `$crate::` path

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Phase:** 24 — Rust macros · **Crates touched:** `common`, `control` · **Est. size:** S ·
> **Depends on:** PR 24.3 · **Unlocks:** PR 24.5

`$crate` occurs **0 times** in the walrus tree — unsurprising while every macro was file-local, and
now a live hazard: `string_enum!` is defined in `common` and invoked from `control`, so the first
bare `crate::` path anyone writes inside its expansion will resolve against the *caller's* crate and
fail with `error[E0425]: cannot find function … in the crate root`, pointing at the invocation rather
than at the bug. The expansion needs a walrus item for a real reason. On `main` today each of the
four hand-written `from_str` bodies invents its own message —
`Err(format!("unknown manifest kind: {other}"))` at `manifest.rs:51` and `:82`, `reload.rs:50` and
`:90` — and **none of them lists the accepted values**, so an operator staring at
`control-plane decode: unknown reload status: exporting_` has to open the source to learn what was
expected. PRs 24.2/24.3 already collapsed those four into one inline `format!` inside the macro; this
PR moves that construction into `common::unknown_variant`, reaches it through `$crate::`, and makes
the message name the type and list every legal string.

## Why — learning objectives

- **`$crate` vs `crate::`** — `$crate` expands to the *defining* crate (to `::common` at a foreign
  call site, to `crate` inside `common` itself) and keeps working through re-exports. `crate::` is
  resolved after expansion, in the caller's namespace, which is why it silently breaks the moment a
  macro leaves its home crate.
- **What hygiene does and does not cover** — `macro_rules!` protects *local bindings* (the
  `other =>` binding the generated match introduces cannot collide with a caller's `other`), but it
  never resolves item paths for you. Two different mechanisms, one commonly conflated.
- **One rejection message for every control-plane decode site** — the same shape whether a bad string
  came out of `file_manifest.kind`, `.status`, `table_reload.flavor` or `.status`.

## Scope

**In scope**

- Add to `crates/common/src/string_enum.rs`:
  `pub fn unknown_variant(type_name: &str, got: &str, accepted: &[&str]) -> String`, producing one
  uniform message that names the Rust type, quotes the offending value, and lists every accepted
  string.
- Re-export it from `crates/common/src/lib.rs` so it is reachable at the crate root:
  `pub use string_enum::unknown_variant;` (the module itself stays private).
- Change the macro's fallback arm to
  `other => Err($crate::unknown_variant(stringify!($name), other, &[$($text),*]))` — the accepted
  list is built from the *same* `$text` literals as the match arms, so it can never go stale.
- A `crates/common/src/string_enum_test.rs` case asserting the message contains the type name and
  **every** accepted variant (iterate the list; do not assert one hard-coded sentence).
- A one-line comment on the `$crate::` call recording why it is not `crate::`, with the E0425 the
  wrong form produces.

**Explicitly deferred** (do *not* build these here)

- **`type Err = String` stays.** `macro-rules-hygiene` is not the ticket that types this error, and
  Phase 34's `anti-stringly-typed` may later want a real error enum. Resolution for this PR: keep
  `type Err = String` — `manifest.rs:193/:198` feeds it directly into `ControlError::Decode(String)`,
  so changing it here would ripple into `control`'s error taxonomy for no hygiene benefit. Moving
  only the *construction* behind a `$crate::`-reachable helper leaves the later typed-error ticket
  exactly **one** function to change.
- No change to `ControlError`, no new error enum, no `is_terminal()`/`exit_code()` edit.
- No hygiene work on local bindings — the macro introduces no `let`, and the `other` binding is
  already hygienic by construction.
- The helper stays a plain `pub fn` at `common`'s root for one PR. **PR 24.5** moves it behind
  `#[doc(hidden)] pub mod __private`; do not pre-empt that here or 24.5 has no probe.
- No `.sql` / `.sqlx` change, no new dependency.

        impl ::std::str::FromStr for $name {
            // Stays `String`: control/src/manifest.rs:193 feeds it straight into
            // ControlError::Decode(String). Typing it is Phase 34's `anti-stringly-typed`, and this
            // helper is the single place that ticket will have to touch.
            type Err = ::std::string::String;

            fn from_str(s: &str) -> ::std::result::Result<Self, Self::Err> {
                match s {
                    $($text => Ok($name::$variant),)*

                    // the same name at the call site. `$crate` is what makes the *path* work there.
                    other => Err($crate::unknown_variant(
                        stringify!($name),
                        other,
                        &[$($text),*],
                    )),
                }
            }
        }

## Hints & gotchas

- **`$crate` is not a variable you can build paths from at runtime.** It is substituted during
  expansion: `::common` at a foreign call site, `crate` inside `common` itself (which is why the
  sibling unit test can call `crate::unknown_variant` directly and exercise the same item).
- **Hygiene covers bindings, not paths.** The `other` in `other => Err(…)` is macro-introduced and
  cannot be captured by, or capture, a caller binding named `other`. `$name`/`$variant`/`$text` are
  caller tokens by design and deliberately are *not* hygienic — that is how the caller's enum name
  ends up in `stringify!($name)`.
- **`&[$($text),*]` is a `&[&'static str]`**, so `accepted.join(", ")` works directly and the array
  is built at each call — on the error path only. Do not try to hoist it into a `const`: `$text`
  lives in the caller's crate and the array's length differs per enum.
- **`stringify!($name)` gives the Rust type name, not the DB column.** `"unknown ManifestKind …"` is
  intentional: the operator reading `control-plane decode: unknown ManifestKind "spil"; expected one
  of: snapshot, stream, spill, reload` gets both the code location and the legal set in one line.
- **No test asserts the old message text** — verify with
  `grep -rn 'unknown manifest\|unknown reload' crates tests` before you change it, then say so in the
  PR body.
- **Do not move the helper into `__private` yet.** PR 24.5's entire probe is
  `grep -rn '__private' crates | wc -l` going 0 → ≥1 and `unknown_variant` disappearing from
  `cargo doc`'s item index. Landing it here erases that ticket.
- **`pub use` out of a private module is fine.** `mod string_enum;` stays private; re-exporting a
  `pub fn` from it at the crate root is ordinary Rust and keeps the module boundary intact.
- Tests are Go-style sibling files; `unwrap`/`expect` are denied in production and re-allowed in
  tests by `clippy.toml` (so `expect_err` in the test is fine); `clippy::all` and `warnings` are
  already `deny` workspace-wide. Any new dependency would have to clear `cargo deny` — none is
  needed. Do not touch any `.sql` file or the committed `.sqlx` offline cache; there is no Docker on
  this machine to regenerate it.
