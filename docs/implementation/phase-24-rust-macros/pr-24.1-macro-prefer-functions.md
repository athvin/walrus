# PR 24.1 — Replace the `downcast!` macro with a generic downcast helper in pg-to-arrow

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** pg-to-arrow

> **Phase:** 24 — Rust macros · **Crates touched:** `pg-to-arrow` · **Est. size:** M ·
> **Depends on:** PR 23.5 · **Unlocks:** PR 24.2

**Re-authored baseline:** `87fecbc`.

`crates/pg-to-arrow/src/batch.rs` has exactly **two** `macro_rules!`. The production tree has one
other macro, `typed_reload_row!` in `crates/control/src/reload.rs`, added by PR 18.1; it is outside
this task's allowlist and stays unchanged. Of the two macros in `batch.rs`, one earns its keep:
`num_builder!` (`:885`) writes the same `impl ArrowNumBuilder for $b` block, including its
associated `type Val = $t`, for five unrelated Arrow builder types — a trait impl across an open
set, which is the one job a function cannot do. The other does not. `downcast!`
(`:327`, **20 call sites**) expands to a fixed
`as_any_mut().downcast_mut::<$ty>().ok_or_else(…)?` shape with a fixed arity and no DSL — precisely
what `fn downcast<'a, T: ArrayBuilder>(&'a mut dyn ArrayBuilder, &str) -> Result<&'a mut T, Error>`
expresses. The file already contains both useful comparison shapes: generic `struct_field` at
`:700` and the monomorphic `bool_builder` at `:711`. After this PR the former macro sites are 20
ordinary generic calls that `rust-analyzer` can jump into and rustc can report against by type, one
`macro_rules!` remains in `batch.rs`, and a comment next to it records *why* it is the survivor.

## Why — learning objectives

- **Generic functions vs `macro_rules!` token substitution** — a turbofish type parameter and a
  `$ty:ty` fragment fill the same hole, but only the first is type-checked once at definition,
  navigable, and reportable in a sane error message.
- **Reborrowing through `dyn Trait`** — returning `&'a mut T` out of a `&'a mut dyn ArrayBuilder`,
  and handing a `Box<dyn ArrayBuilder>` slice element to it with `.as_mut()` without widening the
  borrow region NLL already computes.
- **The pg-to-arrow fan-out** — `TupleValue` → typed Arrow `ArrayBuilder`, covering Tier-1 scalars,
  the Tier-2 interval/timetz/range multi-builder spreads, and the nested geometric shapes.

**In scope**

- Add `fn downcast<'a, T: ArrayBuilder>(builder: &'a mut dyn ArrayBuilder, col: &str) -> Result<&'a
  mut T, Error>` to `batch.rs`, next to `struct_field` (`:700`), with a doc comment.
- Convert all **20** `downcast!(…)` call sites to `downcast::<T>(…)?`. The `?` moves from inside the
  macro to the call site — that is the only visible change at each site.
- Delete `macro_rules! downcast` (`:327-336`).
- Fold `bool_builder` (`:711-721`) into the new helper: its four syntactic call sites (`:555`,

  hand-written duplicate of the new generic next to it would be the same duplication in a
  different costume.

  place in the file that constructs `Error::Downcast` from an `as_any_mut` failure.

## Hints & gotchas

- **The `?` moves outward.** `downcast!` expanded to an expression that already contained `?`, so
  today's call sites read `let b = downcast!(builder, BooleanBuilder, col);` with no visible
  fallibility. The function returns `Result`, so every one of the 20 sites gains an explicit `?`.
  That is the readability win, not a cost — the early return is now where the reader can see it.
- **`T: ArrayBuilder` is enough.** arrow declares `pub trait ArrayBuilder: Any + Send + Sync`, and
  `Any` implies `'static`, so you do **not** need `T: 'static` or `T: Any` on the helper.
  `struct_field` at `:700` already proves the bound works.
- **Each destructured interval/timetz builder is a `Box`, not a `&mut dyn`.** Write
  `months_builder.as_mut()` (and the corresponding named builder). Do not reach for
  `&mut *months_builder` or `months_builder.as_any_mut()` — `as_mut()` is already the idiom at all
  five macro sites. The borrow region is identical to the macro's, so the sequential
  `months`/`days`/`micros` pattern in `append_interval` keeps compiling unchanged.
- **`ListBuilder<StructBuilder>` in turbofish position.** `downcast!(builder, ListBuilder<StructBuilder>, col)`
  worked because `:ty` captured the whole generic type; `downcast::<ListBuilder<StructBuilder>>(…)`
  is the direct translation. No `<` / `>` escaping problem — you are past the token layer now.
- **Convert, then delete.** Keep `macro_rules! downcast` in place while you convert the 20 sites
  (`cargo check -p pg-to-arrow` after each function), then delete it. Deleting first turns one
  logical change into 20 simultaneous compile errors.
- **Do not "improve" `Error::Downcast`.** It is `Downcast { column: String }` and the `to_string()`
  allocation happens only on the error path, inside `ok_or_else`. Keep it that way; `common::Error`
  taxonomy work is a Phase 10 concern.
- **`num_builder!` invocations must stay below the definition.** `macro_rules!` is textually scoped
  inside its crate: the five `num_builder!(…)` lines at `:899-903` only resolve because they follow
  `:885`. If you move code around, preserve that order.
- Tests are Go-style sibling files — `batch.rs` already ends with
  `#[cfg(test)] #[path = "batch_test.rs"] mod tests;` at `:1012-1014`. Do not add an inline
  `mod tests {}`.
- `unwrap`/`expect` are denied in production by `[workspace.lints.clippy]` and re-allowed in tests by
  `clippy.toml`; `clippy::all` and `warnings` are already `deny` workspace-wide. Any new dependency
  would have to clear `cargo deny` (advisories, the 8-license allow-list, bans) — none is needed.
- Do not touch any `.sql` file or the committed `.sqlx` offline cache; there is no Docker on this
  machine to regenerate it, and nothing here needs it.
