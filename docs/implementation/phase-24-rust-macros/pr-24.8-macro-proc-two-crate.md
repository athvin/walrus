# PR 24.8 — Guard the workspace against an unjustified proc-macro plus facade crate split

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test,deny · **Test packages:** —

> **Phase:** 24 — Rust macros · **Crates touched:** none (CI + docs only) · **Est. size:** S ·
> **Depends on:** PR 24.7 · **Unlocks:** PR 25.1

At the audited Phase-24 baseline, the workspace still has exactly **6** members and **7** manifests
(root plus the six members). No manifest declares a `proc-macro` library, no member is published,
and `tests/e2e/Cargo.toml:7` is the only place that says so explicitly with `publish = false`.
`common` already supplies the workspace-facing facade: its ordinary API is 13 public modules and
25 root-reexported items, its exported `string_enum!` macro resolves helpers through the
`#[doc(hidden)] pub mod __private` namespace, and all five other workspace packages depend on it by
path.

The old ticket's newtype premise is no longer true. Phase 18 has already landed transparent
`ManifestId`, `EpochNo`, `SchemaVersionNo`, and `ReloadId` types, complete with conversions and
hand-written SQLx delegation. They are evidence *against* adding a derive crate: their implementation
needs no inspection of an already-declared type's fields, and any future consolidation can take
identifiers and attributes as declarative-macro input. The rest of the authored macro census is
equally accounted for by the three existing `macro_rules!` definitions: `string_enum!`,
`typed_reload_row!`, and `num_builder!`. There is still no derive-shaped, type-definition-inspection
problem to justify a host-compiled proc-macro crate. This PR therefore adds no seventh member. It
extends PR 24.7's guard with two workspace-shape invariants and its decision note with the two-crate
analysis, making a future `walrus-derive` an explicit reviewed decision.

## Why — learning objectives

- **Why the split is forced, not stylistic** — a crate with `[lib] proc-macro = true` compiles for
  the *host* and can export only procedural macros: no ordinary trait, type, or function. A library
  that wants both a derive and runtime API items needs a proc-macro implementation crate plus a
  facade.
- **The `::mycrate::__private::` call convention** — generated code runs in the *caller's* crate, so
  it must name helpers through the facade. That is the procedural counterpart to the `$crate`
  hygiene and hidden `__private` namespace PRs 24.4/24.5 already use for `string_enum!`.
- **A current-tree candidate census, not a hypothetical one** — walrus's three declarative macros
  and four transparent integer IDs are already implemented. None needs a derive to inspect fields or
  types from an existing definition.
- **walrus's workspace shape** — 6 path-only members inherit `edition` / `license` / `rust-version`,
  none is published, and all move in one lockstep workspace. There is no external consumer or
  facade/implementation version skew to hide.

## Skeleton

```bash
# scripts/proc-macro-guard.sh — preserve check_direct and MANIFESTS from PR 24.7. The new functions
# take explicit inputs so --self-test never points them at the real checkout.

EXPECTED_MEMBERS=6

check_proc_macro_setting() {
  local declared
  declared=$(grep -nEH -- '^[[:space:]]*proc-macro[[:space:]]*=' "$@" || true)
  if [ -n "$declared" ]; then
    echo "::error::a workspace manifest declares a proc-macro library setting — read docs/implementation/notes/rust-skills/macro-proc-syn-quote.md (§ The two-crate split) before adding one"
    echo "$declared"
    return 1
  fi
  echo "ok: no workspace manifest declares a proc-macro library setting"
}

check_workspace_member_count() {
  local workspace_root=$1 actual
  actual=$(cd "$workspace_root" && cargo metadata --no-deps --format-version 1 --locked --offline \
    | python3 -c 'import json,sys; print(len(json.load(sys.stdin)["packages"]))')
  if [ "$actual" != "$EXPECTED_MEMBERS" ]; then
    echo "::error::workspace member count is $actual, expected $EXPECTED_MEMBERS — if deliberate, update the guard and two-crate decision together"
    return 1
  fi
  echo "ok: workspace resolves to $actual packages (expected $EXPECTED_MEMBERS)"
}

# --check, after invariant 1:
check_proc_macro_setting "${MANIFESTS[@]}"
check_workspace_member_count "$PWD"

# Capture each expected non-zero result, assert its ::error:: text + fixture path/count, and finish
# with the existing single "proc-macro-guard self-test: PASS" line.
```

## Hints & gotchas

- **Audit current types, not the old deferred note.** Phase 18 already landed `EpochNo`,
  `SchemaVersionNo`, and `ReloadId`; `ManifestId` predates them. The decision note must discuss their
  existing manual implementations and must not promise to create or migrate them.
- **Audit definitions and invocations separately.** The tree has three `macro_rules!` definitions.
  Their current invocation counts are 7 (`string_enum!`), 4 (`typed_reload_row!`), and 5
  (`num_builder!`). None changes in this docs/guard task.
- **`common` has two module counts worth distinguishing.** It exposes 13 ordinary domain modules
  plus a separate doc-hidden public `__private` implementation namespace. Its nine `pub use`
  statements re-export 25 items; the exported macro is additional.
- **Keep metadata read-only.** `--no-deps` keeps the output dependency-free; `--offline` prevents a
  network fallback; `--locked` turns any lockfile rewrite need into a failure. The seven-member
  negative control therefore needs its own complete temporary `Cargo.lock`.
- **Hard-coding `EXPECTED_MEMBERS=6` is the feature.** A future member must change this guard and the
  decision note together. Do not weaken the comparison to `>= 6`.
- **Whitespace variants matter.** `proc-macro=true`, `proc-macro = true`, and an indented key are
  valid TOML. Match an anchored key with flexible whitespace; do not grep a bare substring, because
  comments and the decision-note path legitimately contain `proc-macro`.
- **Do not inspect `Cargo.lock` for proc-macro dependencies.** Required transitive crates such as
  `serde_derive`, `sqlx-macros`, and `thiserror-impl` remain legal. PR 24.7's direct-manifest guard is
  unchanged.
- **Do not confuse the split with `__private`.** PR 24.5 already adopted the correct hidden-helper
  convention for declarative expansions. This task declines only an unneeded proc-macro crate; it
  does not reject the facade-path principle.
- **Publication wording must stay precise.** No member is published, but only
  `tests/e2e/Cargo.toml:7` states `publish = false`; the other manifests omit the key.
- No dependency is introduced. A real derive crate would need its own reviewed `syn`/`quote`/
  `proc-macro2` dependency decision and then the two-crate split this rule requires.
- This PR touches no Rust, but its exact fmt, Clippy, workspace-test, and cargo-deny gates still run.
