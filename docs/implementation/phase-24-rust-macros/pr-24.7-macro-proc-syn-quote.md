# PR 24.7 — Record why walrus takes no direct syn/quote/proc-macro2 dependency

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** evidence
>
> **Gates:** fmt,clippy,test,deny · **Test packages:** —

> **Phase:** 24 — Rust macros · **Crates touched:** none (CI + docs only) · **Est. size:** S ·
> **Depends on:** PR 24.6 · **Unlocks:** PR 24.8

`syn`, `quote` and `proc-macro2` appear **0 times** as direct dependencies across all **7** workspace
manifests (root + 5 crates + `tests/e2e`) — while the tree already compiles **19** distinct
proc-macro crates transitively and carries **two `syn` majors** in `Cargo.lock` (1.0.109 and 2.0.118),
pulled by `serde_derive`, `thiserror-impl`, `sqlx-macros`, `async-trait` and friends. That gap is the
whole point of this ticket: walrus happily *consumes* derives, but authors none, and every codegen
need it actually has is met by `macro_rules!` — the four control string enums PRs 24.2–24.6 build, and
the hand-written transparent-`int8` sqlx blocks at `ids.rs:37-66` / `lsn.rs:120-155` that
`ids.rs:33-36` explicitly chose over a derive. The cost of the other path is already documented
in-repo: `deny.toml:12-17` carries a permanent RUSTSEC exception for `paste`, an *unmaintained*
transitive proc-macro. This PR does not adopt the rule — it turns "we didn't happen to add syn" into
"we decided not to, and CI holds the line", via one manifest guard and one note that names the single
condition that would reopen the decision.

## Why — learning objectives

- **What the trio actually buys** — `syn` (typed AST), `quote` (quasi-quoting), `proc-macro2`
  (span-aware tokens usable outside the compiler, so macro logic is unit-testable) — and their price:
  a **host** compile that blocks every downstream crate, paid on every clean build and in every
  Docker layer.
- **Transitive ≠ direct** — a proc-macro you inherit through `serde_derive` is a cost you already
  accepted with `serde`; a direct dependency is a *new* commitment to author, review, and maintain
  compile-time code, plus its own advisory surface (`RUSTSEC-2024-0436` on `paste` is the in-repo
  example).
- **walrus's supply-chain gate** — `cargo deny`'s four families (advisories, the 8-license allow-list,
  bans, sources) and why the audited `ignore` list is the right place to record a *justified*
  exception rather than a place to hide one.

neither iterate a struct's fields nor read its types.

**In scope**

- `scripts/proc-macro-guard.sh` (new): `--check` fails if any workspace manifest declares `syn`, `quote`, or
  `proc-macro2` as a **direct** dependency, in any form cargo accepts — `syn = "2"`,
  `syn.workspace = true`, `syn = { version = "2", features = [...] }`, or a `[dependencies.syn]` /
  `[dev-dependencies.syn]` / `[build-dependencies.syn]` table header. `--self-test` runs the same
  matcher over temporary manifests containing each rejected form; it never edits the workspace.
- `.github/workflows/ci.yml`: one step in the **`supply-chain`** job that runs the script.
- `docs/implementation/notes/rust-skills/macro-proc-syn-quote.md` (new): the decision note. PR 24.8 extends this
  same file with the two-crate section — write it so a second section slots in cleanly.

**Explicitly deferred** (do *not* build these here)

- **No proc-macro crate**, now or speculatively. There is no `walrus-derive` member (PR 24.8 guards
  that explicitly).
- **No dev-only `syn`** "just for tests" — a dev-dependency is still a direct dependency, still costs
  a host compile on `cargo test`, and would trip this very guard.
- **No `cargo deny [bans]` entry for `syn`.** Banning it outright would break `serde_derive`,
  `thiserror-impl`, `sqlx-macros` and `async-trait`, all of which are required transitive deps. The
  guard therefore checks **manifests**, never the lockfile. Do not touch `deny.toml`.
- No change to `[advisories].ignore` — `RUSTSEC-2024-0436` is *cited* by the note, not modified.
- No `crates/**` file is touched at all, and no `.sql` file or `.sqlx` cache entry.

## Skeleton

```bash
#!/usr/bin/env bash
# proc-macro-guard.sh — PR 24.7 workspace-shape gate. walrus authors no procedural macros: every
# codegen need is met by `macro_rules!` (crates/common/src/string_enum.rs, and the hand-written
# transparent-int8 sqlx blocks in ids.rs / lsn.rs). Rationale + the one condition that reopens the
# decision: docs/implementation/notes/rust-skills/macro-proc-syn-quote.md.
#
#   bash scripts/proc-macro-guard.sh --check
#   bash scripts/proc-macro-guard.sh --self-test
#
# Checks MANIFESTS, never Cargo.lock — transitive proc-macros (serde_derive, thiserror-impl,
# sqlx-macros, async-trait, …) are required and must keep resolving.
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"

MANIFESTS=(Cargo.toml crates/*/Cargo.toml tests/e2e/Cargo.toml)

# Put invariant 1 in `check_direct MANIFEST...`. `--check` passes MANIFESTS; `--self-test` creates
# a `mktemp -d` directory, installs an EXIT trap scoped to that exact directory, and passes four
# fixture manifests (plain, workspace, inline-table, and dependency-table declarations) to the
# same function. Unknown/missing modes print usage and exit 2.

# Invariant 1: no direct syn / quote / proc-macro2 dependency, in any declaration form.
#   syn = "2"                      -> `^\s*syn\s*=`
#   syn.workspace = true           -> `^\s*syn\s*\.`
#   [dev-dependencies.proc-macro2] -> the table-header alternative below
# NOTE: grep exits 1 when it matches nothing, which is the SUCCESS case here — `|| true` keeps
# `set -e` from killing the script on a clean tree.
direct=$(grep -nE '^[[:space:]]*(syn|quote|proc-macro2)[[:space:]]*[.=]|^[[:space:]]*\[[^]]*dependencies\.(syn|quote|proc-macro2)\]' \
  "${MANIFESTS[@]}" || true)

if [ -n "$direct" ]; then
  echo "::error::direct syn/quote/proc-macro2 dependency declared in a workspace manifest — walrus authors no proc-macros (docs/implementation/notes/rust-skills/macro-proc-syn-quote.md)"
  echo "$direct"
  exit 1
fi

echo "ok: 0 direct syn/quote/proc-macro2 dependencies across ${#MANIFESTS[@]} manifests (transitive copies are expected and fine)"
```

## Hints & gotchas

- **`grep` exits 1 when it finds nothing, and that is your success path.** Under `set -euo pipefail`
  a bare `hits=$(grep …)` aborts the script on a *clean* tree — the guard would then "pass" only by
  never running its check on CI's `set -e` shell, or fail outright. Use `|| true` and test the
  captured string. This is the single most likely bug in this PR.
- **`grep -c` over multiple files prints one count per file**, which is why the probe pipes through
  `paste -sd+ - | bc` to sum 7 lines. The script itself should use `grep -n` and inspect the text, so
  the error message can name the offending `file:line`.
- **Match the whole declaration space, not just `syn = `.** `syn.workspace = true`,
  `[dependencies.syn]`, and `[build-dependencies.quote]` are all real cargo spellings. A guard that
  only catches one of them is worse than no guard, because it reads as protection.
- **Anchor the pattern.** An unanchored `syn` matches the word inside a comment ("…the syn/quote
  trio…") — including the comment you are about to write in `Cargo.toml`. Anchor at `^` with optional
  leading whitespace, and re-run the guard after editing any manifest comment.
- **Never ban `syn` in `deny.toml`.** `serde_derive`, `thiserror-impl`, `sqlx-macros` and
  `async-trait` all need it; a `[bans]` entry would fail the `supply-chain` job on `main`. The
  distinction this whole ticket rests on is *manifest* vs *lockfile*.
- **Put the step in `supply-chain`, not `gates`.** `gates` carries `if: needs.changes.outputs.code ==
  'true'`, so a docs-only PR skips it — and a manifest guard that skips on some PRs is a guard with a
  hole. `supply-chain` has no `needs:` and costs seconds.
- **`cargo deny` is not a substitute.** It checks the resolved lockfile; every proc-macro in the tree
  passes it today. Only a manifest check can express "we don't author macros".
- **Write the note like `duckdb-lts-bump.md`, not like a shrug.** "Not relevant" is a rejected
  answer; a measurement plus a reopening trigger is the accepted one. A D ticket's whole product is
  the argument.
- No new dependency is involved, so nothing here needs to clear `cargo deny`'s advisories / 8-license
  allow-list / bans — which is exactly the property the note is protecting.
- This PR touches no Rust, so `cargo fmt --check` and `clippy` are unchanged-green by construction;
  run them anyway before pushing, because CI will.
