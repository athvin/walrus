# PR 24.6 — Give `string_enum!` a `compile_error!` fallback arm instead of a token-soup diagnostic

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common,control

> **Phase:** 24 — Rust macros · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 24.5 · **Unlocks:** PR 24.7

`compile_error!` occurs **0 times** in walrus and no workspace member is a proc-macro crate, so this
rule's literal subject — a spanned `syn::Error` returned instead of a panic — has no site here. Its
principle does: *a macro must never fail with an opaque, location-free message*. Today a malformed
`string_enum!` invocation falls off the end of the matcher and rustc reports
`error: no rules expected ManifestKind` with a `note: while trying to match keyword enum`
pointing into `crates/common/src/string_enum.rs` — a message about the macro's internals, delivered
to someone who was editing a control-plane enum table. A trailing catch-all arm whose entire body is
`compile_error!("…")` replaces that with one sentence naming the expected shape, anchored on the
caller's invocation. It is the declarative-macro analogue of `Error::new_spanned`, it costs three
lines, and it is the only half of this rule walrus can actually buy.

## Why — learning objectives

- **`compile_error!` as the declarative-macro analogue of a spanned `syn::Error`** — and its ceiling:
  `macro_rules!` cannot attach a `Span`, so the error covers the whole invocation and can never point
  at the one offending token. That gap is exactly what a proc macro buys, and exactly what PRs
  24.7/24.8 decline.
- **Catch-all arm ordering** — `macro_rules!` tries arms top to bottom and takes the first that
  matches, so `($($bad:tt)*)` must be **last** or it shadows every real arm. This is also the one
  place a `:tt` slurp is correct: the arm never re-parses what it captured, it only reports.
- **Failing at compile time rather than decode time** — a mistyped control-plane variant table
  currently survives to runtime and surfaces as a `ControlError::Decode` (or a `CHECK` violation)
  against a live control-pg; a fallback arm moves that to `cargo check`.

## Skeleton

```rust
// crates/common/src/string_enum.rs — appended AFTER the real arm, never before it.

#[macro_export]
macro_rules! string_enum {
    (
        $(#[$attr:meta])*
        $vis:vis enum $name:ident {
            $($variant:ident => $text:literal),* $(,)?
        }
    ) => { /* unchanged — the real arm */ };

    // Fallback arm. MUST stay last: `macro_rules!` takes the first arm that matches, so moving this
    // up would shadow every real invocation. This is the one place a `:tt` slurp is correct — the
    // capture is never re-parsed, it exists only so a malformed invocation produces ONE located
    // error instead of rustc's "no rules expected <token>" note pointing into this file.
    //
    // Limit worth knowing: `macro_rules!` cannot attach a `Span`, so the error covers the whole
    // invocation and cannot underline the offending token. That is what a proc-macro's
    // `syn::Error::new_spanned` buys, and PRs 24.7/24.8 decline that dependency on purpose.
    ($($bad:tt)*) => { // tt-fallback-ok — the PR 24.3 gates guard exempts this line
        compile_error!(concat!(
            "string_enum! expects `#[attrs] <vis> enum Name { Variant => \"db_string\", ... }`; ",
            "every variant needs a `=> \"literal\"` giving the exact persisted string"
        ));
    };
}
```

```rust
// crates/common/src/string_enum_test.rs — every optional piece at once. If the fallback arm is ever
// reordered above the real arm, this stops compiling with the fallback's own message, which is the
// arm-ordering guard (no trybuild required).

string_enum! {
    /// Doc comment (a `#[doc = ".."]` meta), an explicit derive list, an explicit visibility,
    /// and a trailing comma in the variant table — all of it must take the FIRST arm.
    #[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
    pub enum AllOptions {
        First  => "first",
        Second => "second",
    }
}

#[test]
fn every_optional_piece_takes_the_real_arm() {
    assert_eq!(AllOptions::Second.as_str(), "second");
    assert_eq!("first".parse::<AllOptions>(), Ok(AllOptions::First));
}
```

## Hints & gotchas

- **Order is the whole implementation.** `macro_rules!` takes the first arm that matches and
  `($($bad:tt)*)` matches literally anything. Put it last. If you put it first, *every* invocation in
  `control` expands to `compile_error!` and the build tells you immediately — which is precisely why
  no extra test is needed for arm ordering.
- **The fallback replaces the item.** When it fires, the enum is never generated, so you also get a
  cascade of `cannot find type ManifestKind in this scope` errors from every use site. Read the
  *first* error; the rest are consequences.
- **`compile_error!` takes a string literal, not a runtime value.** Use `concat!` to assemble a long
  message across source lines; `format!` is not available at expansion time. Escape the inner quotes
  (`\"db_string\"`) so the message shows the literal the caller must type.
- **`compile_error!` is legal in item position**, which is what this expansion needs — the real arm
  emits items (an `enum` plus two `impl`s), so the fallback must be item-position-legal too.
- **Shape mistakes fall through; that is verified, not assumed.** A missing `enum` keyword, a missing
  `=>`, a bare ident where a `:literal` is expected, and a malformed `#[derive Debug]` attribute all
  fail to *match* and reach the fallback arm. What the fallback cannot recover from is an outright
  lexer error (unbalanced delimiters, an unterminated string) — that fails before any arm is tried.
  Say so in the arm's comment rather than over-promising.
- **rustc's wording drifts between releases.** The "before" message's exact phrasing (`no rules
  expected …` vs `no rules expected the token …`) has changed across versions; the repo pins
  `1.95.0` in `rust-toolchain.toml`, so run the hand-check with the pinned toolchain and paste what
  *it* says. What must not change is the shape of the improvement: the note stops pointing into
  `common` and the error starts pointing at the caller.
- **Keep the guard green.** PR 24.3's `gates` step greps for `:tt` and subtracts lines containing
  `tt-fallback-ok`. The marker has to be on the same line as the capture — a comment on the line
  above will not do.
- Tests are Go-style sibling files; `unwrap`/`expect` are denied in production and re-allowed in
  tests by `clippy.toml`; `clippy::all` and `warnings` are already `deny` workspace-wide. Any new
  dependency (including `trybuild`) would have to clear `cargo deny` (advisories, the 8-license
  allow-list, bans) — none is added. Do not touch any `.sql` file or the committed `.sqlx` offline
  cache; there is no Docker on this machine to regenerate it.
