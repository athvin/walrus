# PR 24.5 — Hide the macro's runtime helper behind `#[doc(hidden)] pub mod __private`

> **Status:** 📋 Planned <!-- flip to "✅ Done — <PR url>" when it merges -->

> **Readiness:** audited · **Outcome:** change
>
> **Gates:** fmt,clippy,test · **Test packages:** common,control

> **Phase:** 24 — Rust macros · **Crates touched:** `common` · **Est. size:** S ·
> **Depends on:** PR 24.4 · **Unlocks:** PR 24.6

`#[doc(hidden)]` appears **0 times** in the walrus tree and there is no `__private` module anywhere,
while `common` is the crate everything else stands on: 11 `pub mod`s and 8 root `pub use` lines
exporting 19 names (`lib.rs:4-23`), consumed by `control`, `pg-sink`, `pg-to-arrow`, `loader` and the
`tests/e2e` harness. PR 24.4 added a nineteenth-plus-one: `unknown_variant` **has** to be `pub`,
because `string_enum!`'s expansion reaches it as `$crate::unknown_variant(..)` from inside `control`
— and being `pub` at the crate root is indistinguishable, to a reader and to `cargo doc`, from a
deliberate part of `common`'s API. It is not: it is a formatting detail of one macro, and the moment
Phase 34's `anti-stringly-typed` ticket wants to change its signature, a "public function of
`common`" is what stands in the way. This PR applies the serde/thiserror convention — one
`#[doc(hidden)] pub mod __private` re-export, the macro's path lengthened by one segment — so the
item stays reachable from generated code and disappears from `common`'s documented surface.

## Why — learning objectives

- **`#[doc(hidden)] pub mod __private`** — the ecosystem convention (serde, thiserror, and every
  derive crate) for items that must be `pub` so macro call sites can name them, but that carry no
  stability promise. Visibility keeps them reachable; the attribute and the `__` prefix carry the
  "not API" signal.
- **Keeping a foundation crate's surface honest** — four crates plus the e2e harness compile against
  `common`; every accidental `pub` there is a promise someone will eventually rely on.

## Read first

- [`macro-private-helpers`](../../../.claude/skills/rust-skills/rules/macro-private-helpers.md) —
  take the Good example's exact shape (`#[doc(hidden)] pub mod __private { pub use … }` plus a
  private `mod` holding the real item) and the Key Points: name it `__private`, always pair with

  re-export list".

///
/// Everything here must be `pub` so an expansion in another crate can name it as
/// `$crate::__private::…`, and `#[doc(hidden)]` keeps it out of `cargo doc`. Nothing outside

## Hints & gotchas

- **Hiding is a convention, not a visibility change.** `__private` must be `pub` or the expansion
  cannot name it from `control`; `#[doc(hidden)]` only removes it from rendered docs. If you make the
  module `pub(crate)` the cross-crate expansion stops compiling — that failure is the whole reason
  the pattern exists.
- **`$crate::__private::…` is a crate-root path**, so the module must be declared in `lib.rs`, not
  nested inside `string_enum.rs`. The *function* can stay in the private `string_enum` module; only
  the re-export moves.
- **`grep` the doc index, not the whole `target/doc` tree.** `all.html` is rustdoc's "all items"
  page; other generated files (search index, source listings) still contain the identifier, so a
  broad `grep -r unknown_variant target/doc` will not go to 0 and is the wrong probe.
- **`cargo doc` needs the same feature set you build with.** `common`'s `sqlx` feature is optional;
  `--no-deps` on the default feature set is enough for this probe and is what the DoD pins.
- **Do not add `#[doc(hidden)]` anywhere else.** The count going 0 → 1 is the signal; sprinkling the
  attribute on unrelated items makes the next reviewer wonder what else is secretly not-API.
- **Name it exactly `__private`** (two leading underscores). The ecosystem reads that prefix as "do
  not touch"; `_private`, `internal`, or `private_` do not carry the same signal.
- Tests are Go-style sibling files; `unwrap`/`expect` are denied in production and re-allowed in
  tests by `clippy.toml`; `clippy::all` and `warnings` are already `deny` workspace-wide. Any new
  dependency would have to clear `cargo deny` (advisories, the 8-license allow-list, bans) — none is
  needed. Do not touch any `.sql` file or the committed `.sqlx` offline cache; there is no Docker on
  this machine to regenerate it.
