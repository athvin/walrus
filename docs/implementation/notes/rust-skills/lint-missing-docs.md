# `missing_docs` is one manifest line away, and the line is not the work

> **Status:** partially applied — the one exported surface whose documentation already existed
> elsewhere in its own file was documented (23 items in `crates/common`); the lint entry itself is
> deferred. `warnings = "deny"` makes `warn` and `deny` the same diagnostic here, so the entry is a
> hard build failure until the whole exported surface is documented — and 13 of those items are enum
> variants that no call site can reach. This note is the inventory that sweep needs.

## What the rule asks for

`lint-missing-docs` asks for `missing_docs` in the workspace lint table (`warn`, escalating to
`deny` once the tree is clean) and a `///` on every exported item: modules, structs, struct fields,
enums, enum variants, functions, traits and trait methods. Its stated payoff is that "for libraries,
documentation IS the user interface."

## What is enabled today

`missing_docs` appears in no manifest and in no source file: the only hits repo-wide are the rule
itself, its roadmap ticket, and the ticket generator. All six members inherit the table (`[lints]
workspace = true` in each of `crates/{common,control,loader,pg-sink,pg-to-arrow}/Cargo.toml` and
`tests/e2e/Cargo.toml`), so one entry under `[workspace.lints.rust]` (`Cargo.toml:22`) would reach
every crate at once.

Two thirds of the rule's substance is already enforced, which is why the gap below has the shape it
does:

- `clippy::missing_errors_doc = "deny"` (`Cargo.toml:260`) fires on an exported `Result`-returning
  function even when it carries no doc comment at all, so **every exported fallible function already
  has a doc comment** with an `# Errors` section. The gap is structurally confined to infallible
  functions, constants, fields and variants.
- `clippy::missing_safety_doc` / `unnecessary_safety_doc` police the other doc section, and
  `unsafe_code = "forbid"` leaves them no live site.
- Every module, crate root, bench and integration test already carries a `//!` block, by convention
  rather than by lint.

## What this pass changed

Documentation was added where the file already contained the authoritative text, so the doc is
transcription rather than invention:

- `crates/common/src/metrics.rs` — the 14 sink and 7 loader series-name constants. `describe_all()`
  in the same file already registers a one-line description and unit for each; the reload block
  (PR 6.11) had already been documented in that style, and the sink/loader blocks had not. A metric
  name is a value contract (a rename breaks the committed dashboard), so the constant is exactly
  where the description belongs.
- `crates/common/src/metrics.rs` — `dec_reload_active`, whose semantics were documented on
  `inc_reload_active` directly above it as a pair; it now carries a one-line pointer so it is not a
  blank row in the rendered item list.
- `crates/common/src/failure_class.rs` — `pub trait FailureClass`, the one item in a 44-line
  module doc's file with no `///` of its own (all three of its methods have one).

That is 23 items. It flips no lint on; it removes the two places where an undocumented item sat
inside a block whose siblings were documented.

## The measured gap

Method: `pub` items and named `pub` fields under `crates/*/src`, counting totals with a single-line
search and *documented* ones by pairing a `///` line (plus any single-line attributes) with the item
below it. Undocumented = total − documented, which avoids the undercount a "preceding line is not a
doc" search suffers on runs of consecutive undocumented items. The result is an upper bound: it
counts items in private structs and private modules that `missing_docs` never reaches, and it counts
an item as undocumented when a *multi-line* attribute separates it from its doc comment (measured:
one, `memory.rs`'s `Backpressure`).

| Surface | Count |
|---|---|
| `pub fn` / `const` / `struct` / `enum` / `trait` | 657 total, 545 documented — **112 undocumented** |
| Named `pub` fields | 270 total, 121 documented — **149 undocumented** |
| Enum variants generated by `string_enum!` | **13**, none reachable from a call site (below) |

Where the 112 sit — 54 of them are one table:

- `crates/common/src/oids.rs` — 54 of 54. Every `pg_catalog` base-type OID. The constant's *name* is
  the Postgres type name and the section comments carry the tier/decomposition story, so this block
  is the one place where the rule's payoff is weakest per line and its cost highest.
- `crates/pg-sink/src/consume.rs` — 14, the `DecodeLoopBuilder` setters, each carrying a
  `#[must_use = "builder methods return the modified builder — chain or assign"]` and nothing else.
- `crates/pg-sink/src/memory.rs` — 10: `InflightMeter::new`/`total`/`ceiling`/`is_over_ceiling`,
  `Ratio::as_f64`, `HysteresisBand::activate`/`resume`, `Backpressure::new`/`is_paused`.
- `crates/pg-sink/src/health.rs` 5, `crates/loader/src/health.rs` 4, `pg-sink/src/relcache.rs` 4,
  `pg-sink/src/checkpoint.rs` 3, then a tail of 1–2 each in `batch.rs`, `reload_signal.rs`,
  `ids.rs`, `sql.rs`, `telemetry.rs`, `preflight.rs`, `ddl.rs`, `duck_ext.rs`, `loader/config.rs`,
  and `pg-to-arrow`'s `range.rs` / `batch.rs`.

Every one of those is an accessor, a constructor, or a builder setter — the shapes for which the
rule's own "What to Document" table has the least to say, and for which a `///` would restate the
signature. That is a judgement worth making deliberately in one sweep, not incidentally.

The field gap is concentrated in the control-plane row mirrors (`control/src/manifest.rs` 20,
`control/src/reload.rs` 8, `schema_registry.rs` 4, `ddl_manifest.rs` 3) and the sink/loader
handle structs (`pg-sink/src/batch.rs` 10, `sink.rs` 9, `preflight.rs` 6; `loader/src/bootstrap.rs`
8, `duck.rs` 5, `phase_a.rs` 5). Both config structs are already fully documented
(`pg-sink/src/config.rs` 26/26, `loader/src/config.rs` 12/13), as is `common/src/sink_meta.rs`
(14/14) — so the pattern is not "walrus does not document fields", it is "the row mirrors inherit
their meaning from the SQL columns they name".

`tests/e2e` is the member that would pass today. It is also the member whose crate-level allow
already exempts it from this family (`clippy::missing_errors_doc`, `must_use_candidate` at
`tests/e2e/src/lib.rs:1-11`, reason "compose-gated e2e harness, not a published API"), so enabling
`missing_docs` means deciding whether that reason extends to it.

`common::__private` (`crates/common/src/lib.rs:68-76`) is the one `pub` surface a sweep must **not**
document: it is `#[doc(hidden)]` with a stability paragraph saying exactly that.

## The blocker a sweep cannot grep its way past

Four production enums are generated by `string_enum!`, and the macro's matcher
(`crates/common/src/string_enum.rs:75-87`) captures attributes **only** for the enum:

```rust
$(#[$attr:meta])*
$vis:vis enum $name:ident {
    error = $error:path;
    column = $column:literal;
    $($variant:ident => $text:literal),* $(,)?
}
```

There is no fragment in front of `$variant` and the expansion emits `$($variant,)*` bare, so no call
site can attach a `///` to a variant: `ManifestKind` (4) and `ManifestStatus` (2) in
`crates/control/src/manifest.rs`, `ReloadFlavor` (2) and `ReloadStatus` (5) in
`crates/control/src/reload.rs`. Whether `missing_docs` fires on those spans at all — they expand
from another crate's macro — is not something a static search settles; either way the entry cannot
be landed blind. Making them documentable means changing the grammar of an exported macro (adding
`$(#[$vattr:meta])*` before `$variant`) and re-proving it against the fragment-specifier and hygiene
guards, which is a change with its own PR-sized argument.

## Why there is no gradual path here

The rule's own answer to a gap this size is its "Gradual Adoption" section: `warn` first, `deny`
after cleanup. That path is closed in this workspace. `warnings = "deny"` (`Cargo.toml:23`) turns any
lint sitting at `warn` into a denial — the manifest already states this for a different lint three
lines below. So `missing_docs = "warn"` and `missing_docs = "deny"` produce the same red build here,
and the entry can only land together with the sweep, in one PR.

## What enabling it takes

For whoever lands it, in this order:

1. Extend the `string_enum!` matcher to capture per-variant attributes, and document the 13 variants
   at their call sites.
2. Document the `oids.rs` table (54) — decide there whether the value or the name is the contract.
3. Document the ~58 remaining accessors/constructors/builder setters and the ~149 named fields.
4. Decide whether `tests/e2e` documents its items or joins its existing file-level allow.
5. Add `missing_docs = "deny"` to `[workspace.lints.rust]` and a case in
   `crates/common/tests/workspace_lints_inherited.rs`, which is what notices if the entry is later
   dropped.
6. Prove it with a build, not with `cargo test`: `cargo clippy --workspace --all-targets` and
   `RUSTDOCFLAGS='-D missing_docs' cargo doc --workspace --no-deps`.

## What would reverse this note

- Any member becoming publishable. `publish = false` (`Cargo.toml:18`) plus no `cargo doc` in CI is
  what removes crates.io and docs.rs from the rule's three rendering targets; a published crate needs
  the lint on the day it publishes.
- The sweep landing. This note then stops being a deferral and becomes the record of what it covered.
- A new crate joining the workspace. It inherits the lint table and starts empty, so it can carry
  `#![deny(missing_docs)]` at its own root from its first commit without waiting for the tree.
